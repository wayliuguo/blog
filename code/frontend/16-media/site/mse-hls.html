MediaSource Extensions（MSE）流式播放原理

核心问题：浏览器原生 <video src="..."> 只能播放"整段、自带解码能力"的文件，不认 HLS（m3u8+TS 分片）或 FLV 分片。MSE 让 JS 把分片数据 appendBuffer 进 SourceBuffer，浏览器则退化为纯"解封装 + 解码 + 渲染"引擎。这就是 hls.js / flv.js 能在浏览器里播协议流的底层来源。

数据流

网络分片→ fetch() 拉取→ appendBuffer(ArrayBuffer)→ SourceBuffer→ <video> 解码渲染

受控样例说明

真实播放需要合法、已切片、连"首帧即为 IDR 关键帧"的 fMP4 分片数据。为在零依赖、离线环境演示 MSE 的工作机理，下面的样例不造假流，而是展示标准接入代码骨架（可对照第一章的 MSE 概念）： 

const ms = new MediaSource();
video.src = URL.createObjectURL(ms);
const codec = 'video/mp4; codecs="avc1.42E01E,mp4a.40.2"';
ms.addEventListener('sourceopen', () => {
  const sb = ms.addSourceBuffer(codec);
  fetch('seg-0.m4s').then(r=>r.arrayBuffer()).then(buf=>{
    sb.appendBuffer(buf);          // 把分片喂给浏览器
    sb.addEventListener('updateend', () => { /* 继续拉下一片，并做 Buffer 水位管理 */ });
  });
});
点击按钮检测浏览器对 MediaSource / addSourceBuffer 的支持。结果与说明会在下方展示，页面文字始终可见。

原理一句话：MSE 把"数据从哪来、何时喂"的控制权交给 JS——浏览器只做解封装、解码、渲染。想真正在线看到画面，需要接入 hls.js 等把 TS/FLV 转成 fMP4 的库并使用真实流地址。
