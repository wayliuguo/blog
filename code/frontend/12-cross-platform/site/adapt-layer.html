01 · 一套 DSL → 多平台适配层

跨端的核心是"一次编写，多端运行"。真实工程里 Taro/uni-app 就是编译器：开发者写一份业务，编译器按目标平台产出各自产物。这里我们把「编译 / 适配层」这层思想压到最小——输入一条统一的 DSL（领域专用描述，比如一次 setData 更新），由适配层分发给不同"平台"生成各自结构。

适配层只认统一 DSL，把 DSL 映射成该平台的原语：Web 操作 DOM，小程序走 setData，RN 生虚拟节点树，Flutter 生成 Widget 描述。

原理一句话：适配层的本质是把「统一 DSL」翻译成「各端原语」。业务代码永远只用一套 DSL，新增平台 = 新增一个适配器，而不是改业务。这正是 Taro/uni-app 与 RN 适配层的共同骨架。
