WebAssembly：为何快、编译链路与最小 wat 示例

WebAssembly（Wasm）是一种可移植、体积紧凑的字节码格式，代码在下载时被 AOT 编译成机器码，因而接近原生速度。它不与 JS 竞争，而是负责 JS 之外的重计算。

一、为什么 Wasm 比 JS 快（对照）

维度 JavaScript WebAssembly
执行方式 解释执行 + JIT AOT 编译为机器码，接近原生
类型 动态类型 静态类型（i32 / f32 / f64 等）
适用 DOM、事件、UI 交互 CPU 密集计算、图形、编解码
体积 较大 二进制小，加载快

二、编译链路：源码 → .wat → .wasm → 运行

源文件(.rs / .c / .cpp) → clang / rustc → .wat（人类可读文本） ↔ .wasm（二进制字节码）→ 浏览器实例化执行

JavaScript 侧用 WebAssembly.instantiateStreaming() 把 .wasm 以流式方式编译并实例化，得到可调用对象。

三、一个最小 add 的 wat 文本格式

下面这段是"加法函数"的人类可读文本（等价于一个导出 add 的模块，把两个 i32 相加并返回）：

(module
  (func $add (param $a i32) (param $b i32) (result i32)
    local.get $a
    local.get $b
    i32.add)
  (export "add" (func $add)))
原理一句话：把它用 wat2wasm 转成二进制 .wasm 后，浏览器会把函数体一次性编译成机器码，之后每次调用都接近原生——这就是 Wasm 相比逐行解释、动态内联的 JS 更快的原因。JS 负责 UI，Wasm 负责重计算，二者协同。
