Service Worker：生命周期与缓存策略

Service Worker 是运行在主线程之外的网络代理，通过 install（预缓存）、activate（清理旧版本）、fetch（拦截请求）三个钩子接管离线缓存。本页在同目录注册精简版 sw.js，下面给出注册结果与说明，unreg 按钮用于反注册以观察变化。

尚未注册（提示：请在 localhost 打开以保证安全来源）。

生命周期状态流转

registered(已登记) → installing(安装中, 触发 install) → activated(激活, 触发 activate) → 接管 fetch

注册后浏览器异步执行：先 install 预缓存常用资源，随后 activate 清理旧版本缓存并 clients.claim() 接管页面，之后页面请求会进入 fetch 事件走缓存策略。

常见缓存策略对比

策略 读取顺序 适用场景 优点 / 缺点
Cache First 缓存→网络 静态资源、图片 快，但更新滞后
Network First 网络→缓存 需新鲜度的 API 数据新，弱网慢
Stale-While-Revalidate 缓存→网络后台更新 列表、应用壳 快且渐次更新
Network Only 仅网络 实时性强的写入 无法离线

sw.js 核心片段（本演示所用）

self.addEventListener("install", (e) => {
  e.waitUntil(caches.open("v1").then((c) => c.addAll(["/pwa-sw.html"])));
  self.skipWaiting();
});
self.addEventListener("activate", (e) => {
  e.waitUntil(清理旧缓存后 self.clients.claim());
});
self.addEventListener("fetch", (e) => {
  e.respondWith(caches.match(e.request) || fetch(e.request).then(回填缓存));
});
