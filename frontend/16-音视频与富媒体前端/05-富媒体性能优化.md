# 富媒体性能优化

> 级别：高级

按本书四层推进：

- **入门使用**：会选图片格式、写 `<picture>` / `srcset`、加 `loading="lazy"`，理解宽高预留避免 CLS；
- **进阶**：分清 `preload` / `prefetch` / `preconnect`，掌握视频 `preload` 三档策略；
- **实战**：掌握视频秒开、弱网降级、帧率 / 卡顿监控与无障碍降级的成套工程实践；
- **最小实现掌握原理**：到 `code/frontend/16-media` 打开 `audio-viz.html`，用 `AnalyserNode` 把实时声音画成频谱，亲手走一遍"采集 → 分析 → 渲染"这条富媒体渲染链的最小闭环。

一堆图片和视频是网页体积的大头，也是用户体感"快慢糊"的直接来源。本章系统性介绍图片优化、懒加载/预加载、视频秒开、弱网降级、性能监控与无障碍，把"富媒体优化"从零散技巧上升到一套可量化、可监控、可降级的工程实践。

## 一、图片优化

### 1. 图片格式选型与对比

| 格式 | 压缩 | 透明 | 动画 | Safari 支持 | 适用 |
| --- | --- | --- | --- | --- | --- |
| JPEG | 有损 | 否 | 否 | ✅ | 照片、一般内容图 |
| PNG | 无损 | ✅ | 否 | ✅ | 简单图形、透明 |
| WebP | 有损/无损 | ✅ | 部分 | 现代✅ | 通用默认 |
| AVIF | 有损/无损 | ✅ | ✅ | 较新✅ | 高质量+小体积 |
| GIF | — | ✅ | ✅ | ✅ | 小动图（体积大） |

**体积/质量经验**：AVIF ≈ WebP ≈ HEIC < JPEG < PNG < GIF（动图越新越省）。示例 500KB 的 JPEG 转 WebP 约 300KB，转 AVIF 约 150KB。

### 2. `<picture>` + 自适应图片

```html
<picture>
  <source srcset="hero.avif" type="image/avif" />
  <source srcset="hero.webp" type="image/webp" />
  <img src="hero.jpg" alt="hero" width="800" height="450" loading="lazy" />
</picture>
```

加上 `srcset` + `sizes` 让浏览器按**视口宽度 + DPR** 选图：

```html
<img
  srcset="img-320.jpg 320w, img-640.jpg 640w, img-1280.jpg 1280w"
  sizes="(max-width: 600px) 320px, 1280px"
  src="img-1280.jpg"
  alt="响应式图"
/>
```

> `width`/`height` 一定要写，浏览器能预留空间、避免 CLS（布局偏移）。现代浏览器支持 `content-visibility` 进一步跳过屏外渲染。

### 3. 懒加载 idle/得分 与占位

```html
<img src="a.jpg" loading="lazy" decoding="async" />
```

不支持的浏览器用 `IntersectionObserver` 兜底：

```js
const observer = new IntersectionObserver(entries => {
  entries.forEach(e => {
    if (!e.isIntersecting) return;
    const img = e.target;
    img.src = img.dataset.src;      // 真正发起加载
    observer.unobserve(img);
  });
});
document.querySelectorAll('img[data-src]').forEach(i => observer.observe(i));
```

**占位策略**：模糊 LQIP（低质量小图 + 渐hidden）、CSS 底色 + `background` 撑高、骨架屏。核心是"图没到也让页面不跳动"。

### 4. 雪碧图 vs 图标方案

| 方案 | 体积 | 维护 | 使用 |
| --- | --- | --- | --- |
| SVG Sprite | 小 | 好 | 图标常用 |
| CSS Sprite | 中 | 一般 | 老式图片精灵 |
| IconFont | 极小 | 中 | 简单图标集 |
| Lazy SVG/Sprite | — | — | 现代 SVG 组件化 |

## 二、懒加载与预加载

### 1. 三者的对比

| 关键词 | 时机 | 用途 |
| --- | --- | --- |
| `loading="lazy"` | 进入视口时 | 屏外图片延时加载 |
| `rel="preload"` | 解析阶段即拉 | 提前拿关键资源 |
| `rel="prefetch"` | 空闲时 | 预取下个页面资源 |
| `rel="preconnect"`/`dns-prefetch` | 提前建连 | 减少关键请求握手 |

### 2. 预加载关键资源

```html
<link rel="preload" as="image" href="hero.jpg" />
<link rel="preload" as="video" href="intro.mp4" type="video/mp4" />
<link rel="preconnect" href="https://cdn.example.com" crossorigin />
```

**注意**：`preload` 关键资源要配合 SSR/首屏路径，否则反而抢占带宽。`prefetch` 对链路下的 CDN 大体积文件尤其有用（浏览器空闲再取）。

### 3. 视频预加载策略

| preload 值 | 行为 | 适用 |
| --- | --- | --- |
| `none` | 不预加载元数据 | 短页少视频 |
| `metadata` | 只拉文件头/时长 | 列表页有多个 video |
| `auto` | 尽力预加载整段 | 单视频内容页首屏 |

## 三、视频首帧与秒开优化

视频秒开是富媒体体验的重中之重，分"文件级、网络级、解析级"三层：

### 1. 文件与编码层

- **moov 前置**：`-movflags +faststart` 让 MP4 元数据在前，才能"边下边播"。
- **小分片 + 关键帧对齐**：HLS 分片 2-6s、GOP 变小，见流的首帧更早。
- **多档位编码**：首屏给低档，看到帧后再升高档。

### 2. 网络层

- `preload="auto"` + 首帧从容解析即起播放。
- CDN 边缘缓存 + 与图片同源以便复用 HTTP/2 连接。
- 首片段预热：进入路由前 `fetch(seg0.m4s)` 预热。

### 3. 解析与渲染层

- **首帧加载控**：MSE `appendBuffer` 后 `video.play()`，用 `loadeddata`/`playing` 事件做切换。
- **封面图兜底**：视频未出帧时先显示 poster 或第一帧截图，避免黑屏。
- **渲染管线**：`decoding="async"` + `disablePictureInPicture` 可选，硬解优先。

### 4. 秒开指标

常用：

```text
首帧时间（First Frame）＝ 播放器初始化 + 网络拉首片 + 解封装 + 解码器首帧就绪
```

用 PerformanceObserver / video events 上报 `playing` 到的时间，配合 SIT 埋点判断是网络、解码还是本地问题。

## 四、弱网降级

弱网降级的目标是"**音频不断、画面降档、不白屏**"，而不是直接失败。

### 1. 降级维度

| 层级 | 降级手段 |
| --- | --- |
| 码率 | 多码率 ABR 自动切换低档 |
| 分辨率 | 切 360p/480p |
| 帧率 | 降 fps（如 30→20） |
| 质量 | 关闭 HDR/高动态范围、降低画质档 |
| 传输 | WebRTC 降 Simulcast 层、丢帧保护 |

### 2. 兜底回退

- **图片**：大图失败 → 落低清占位 → 文案提示。
- **视频**：首片失败 → 尝试重新拉取 → 尝试切换协议（hls→flv）→ 显示错误+推荐降档入口。
- **播前检测**：先用 `fetch` 拉一段极小探测包估算带宽，再决定初始档位，避免"一上来就带宽不足卡顿"。

```js
// 弱网探测初始化档位
async function pickStartBitrate() {
  const ctrl = new AbortController();
  const t0 = performance.now();
  const res = await fetch('/tiny-probe.bin', { signal: ctrl.signal });
  await res.body.cancel();
  const bw = 8 /*MB*/ * 8 * 1000 / (performance.now() - t0); // 粗估 kbps
  return bw > 3000 ? 1080 : bw > 1000 ? 720 : 480;
}
```

## 五、帧率与卡顿监控

### 1. 视频层监控指标

从 `getVideoPlaybackQuality()` 与 MSE 事件拿：

```js
const q = video.getVideoPlaybackQuality();
{
  droppedVideoFrames: q.droppedVideoFrames,      // 解码后丢弃帧
  totalVideoFrames: q.totalVideoFrames,
  videoDecodedFrames: q.videoDecodedFrames,      // 实际解码帧
}
const fps = q.videoDecodedFrames / elapsed;       // 实测帧率
const dropRate = q.droppedVideoFrames / q.totalVideoFrames;
```

### 2. rAF 全屏 FPS

用途：非视频动画页面也测流畅度：

```js
let frames = 0, last = performance.now();
function loop(t) {
  frames++;
  if (t - last >= 1000) {
    report({ fps: Math.round(frames * 1000 / (t - last)), time: t });
    frames = 0; last = t;
  }
  requestAnimationFrame(loop);
}
requestAnimationFrame(loop);
```

### 3. 卡顿判定阈值

| 指标 | 告警阈值 | 含义 |
| --- | --- | --- |
| droppedVideoFrames 占比 | > 5% | 解码/渲染跟不上 |
| buffered 长时间为空 | 持续 >2s | 断流/卡顿 |
| 实测 FPS | 低于标称的 60% | 掉帧严重 |
| 多次 `waiting` 事件 | 30s 内 >3 次 | 网络不稳 |

把这些打成埋点，进入监控平台（如 Web Vitals 扩展 + 自接日志），按 `视频卡顿率 = waiting 次数 / 播放时长` 做行业对标。

## 六、富媒体对性能指标的影响

| 指标 | 富媒体影响 |
| --- | --- |
| LCP | 首屏视频封面/大图最易成为 LCP，变慢 |
| CLS | 无预留宽高、无占位的图/视频导致布局跳 |
| INP | 解码在主线程、懒加载回调密集会卡交互 |
| TTI | 多个多媒体 preload 抢占带宽拖慢可交互 |
| INP 卡 | 低端机软解视频 -> 主线程忙 |

**关联动作**：为所有图片/视频写 `width/height`，用 `content-visibility`、`will-change` 谨慎（否则更耗资源）、把解码尽量交给浏览器（不主动阻塞主线程）。

## 七、无障碍与降级

### 1. 富媒体无障碍要点

| 场景 | 做法 |
| --- | --- |
| 图片 | 必填有意义的 `alt`（装饰图用 `alt=""`） |
| 视频 | 提供字幕 `<track kind="captions">`、音频解说轨 |
| 画中画/弹窗 | `aria-label`、键盘可操作、焦点管理 |
| 动效 | `prefers-reduced-motion` 禁用大动画 |
| 弹幕 | 关闭按钮+不遮挡字幕；减少高频闪烁 |

```html
<video controls>
  <track kind="captions" src="captions.vtt" srclang="zh" label="中文字幕" default />
</video>
<a href="transcript.html">查看文字稿</a>
```

### 2. 降级与兜底

- 不支持 AVIF/WebP 用 `<picture>` 落 JPEG。
- 不支持 MSE 的低版本浏览器：HLS 用原生 iOS / FLV 原生（Safari FLV 弱）→ 无法播放时给可下载 MP4 链接。
- 把"能否播放"作为一等反馈告知用户（若见不到则避免一直 loading）。

## 最小实现：声音实时画成频谱

到 `code/frontend/16-media` 打开 `audio-viz.html`，它把富媒体里"采集 → 分析 → 渲染"的最小闭环跑通：点按钮后生成一个合成振荡器音（无需任何音频文件），`MediaStreamAudioSourceNode` 把它接进 `AnalyserNode`，用 `getByteFrequencyData` 拿到各频段能量，再每个动画帧画到 `<canvas>` 上。

- 这正是本章"富媒体对性能指标影响"里渲染管线的直观样例：数据在音频线程被分析，画面由 `requestAnimationFrame` 逐帧绘制。
- 把 `getByteFrequencyData` 换成视频帧数组，就理解了 `getVideoPlaybackQuality` 与帧率监控背后的"逐帧取数据 + 上报"思路。

原理一句话：`AnalyserNode` 是声音的"示波探针"，把实时音频能量喂给 canvas 逐帧绘制，就得到一条数据驱动的富媒体渲染链路——优化与监控都建立在这条采集 → 分析 → 渲染的管道上。
