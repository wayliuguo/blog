# 模块总结 · 前端框架-React

## 知识主线

六篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 React 核心概念（界面怎么描述、组件怎么写）
        │  组件会写了，但数据一变界面怎么跟着变、副作用放哪？
        ▼
02 React Hooks（状态与副作用）  ★主轴
        │  组件多了、页面多了，怎么在页面之间切换？
        ▼
03 React 路由（URL ↔ 组件）
        │  跨组件、跨页面共享的数据越来越多，放哪统一管？
        ▼
04 React 状态管理（全局状态）
        │  项目变大，怎么让组件不出错、可维护？
        ▼
05 React 使用 TS（类型约束）
        │  组件逻辑清楚了，样式怎么写、怎么隔离？
        ▼
06 React 使用 CSS（样式方案）
```

本模块的主轴是 **Hooks**：01 讲 React 的基础单元——用 JSX 声明界面、用组件组织 UI（props 单向数据流）；02 讲让组件"活"起来的机制——useState/useEffect/useRef/useMemo/useCallback 与自定义 Hook，这也是现代 React 函数组件的心跳；03 讲组件之间的跳转（react-router-dom），04 讲组件之间共享数据的集中管理（Context/useReducer/Redux/MobX/Zustand），05/06 讲用 TypeScript 与 CSS 方案把组件写得更规范、更好看。六篇合起来覆盖了"用 React 写出一个可维护的 SPA"的完整路线。

## 分篇知识点

### 01-React 核心概念

- **React 一切皆组件**：组件输入 props、返回 JSX；JSX 是 JS 语法扩展，只能有一个根节点（用 `<></>` Fragment）、标签必须闭合、`className` 替代 `class`、`style` 必须传驼峰 JS 对象
- **标签首字母规则**：小写开头视为 HTML 原生元素，大写开头渲染组件，`<input/>` 与 `<Input/>` 含义完全不同
- **JSX 表达式**：`{xxx}` 中 number/string/array 直接渲染，null/undefined/boolean 渲染为空，对象不能作子元素；判断用 `&&` / 三元 / 函数封装，循环用 `map` 且必须给唯一稳定的 `key`（不用 index、不用随机数）以优化 VDOM diff
- **事件绑定**：`onXxx` 合成事件 + 事件委托；传引用而非调用（`onClick={handleClick}`）；this 指向用 bind / 箭头函数 / 箭头函数执行三种方案
- **props 单向数据流**：子组件只读不能改；默认值用 defaultProps，类型校验从 prop-types 演进到 TypeScript；JSX 默认防 XSS，确需渲染 HTML 才用 `dangerouslySetInnerHTML`
- **与 Vue 模板的理念对比**：React 主张"JS 能实现的都交给 JS、不重复定义指令"，Vue 自定义 `v-if`/`v-for` 等指令更好上手——这是两代框架设计思路的分水岭

### 02-React Hooks

- **Hooks 让函数组件具备状态与副作用能力**：`useState` 返回 `[当前值, 更新函数]`，更新是异步的；核心是**不可变数据**——浅对比引用地址，直接改 state 不触发重渲染，对象更新要用扩展运算符创建新对象（或用 immer 的 `produce`）
- **useEffect 是三个生命周期的合一**：回调在挂载/更新/卸载时执行，依赖数组 `[]` 仅挂载执行一次、有依赖则依赖变化时执行、不传则每次渲染后执行；返回的函数是卸载清理（解绑事件防内存泄漏）；React 18 开发环境会执行两次以暴露问题
- **useRef**：返回可变对象 `.current`，值变化不触发重渲染，用于绑定 DOM 与保存不驱动 UI 的共享数据
- **useMemo / useCallback**：分别缓存计算结果与函数引用，依赖不变则不重建，用于性能优化（但官方强调"不要把它当成语义上的保证"）
- **自定义 Hook 是逻辑复用的正解**：对比 Class 高阶组件（HOC）的嵌套地狱与 props 透传，自定义 Hook 直接回到组件内部，保持组件树扁平；成熟后沉淀为 ahooks / react-use 这类第三方库
- **三条规则与闭包陷阱**：`useXxx` 命名、只能在组件/Hook 内调用、每次渲染按相同顺序调用（不能放 if/循环里）；异步回调里读 state 可能拿到旧值（闭包陷阱），用 useRef 同步最新值解决

### 03-React 路由

- **路由本质**：不刷新页面实现 URL ↔ 内容对应——"把 URL 变成状态 + 按状态渲染对应组件"；hash 路由（`#/about`）兼容性最好不触发请求，History 路由（pushState/popstate）更美观但刷新需服务端回落入口页否则 404
- **V5 vs V6 关键差异**：`<Switch>` 需手动排序（否则 `/product/new` 会先匹配到 `/product/:id`），V6 的 `<Routes>` 按路径优先级自动选最具体匹配；路由组件 props 从自动注入（history/location/match）改为 useParams/useLocation/useNavigate 等 Hook
- **传参三种方式**：params（拼路径，须在 Route 声明 `:id`）、search（URL 查询串，无需声明）、state（不在 URL 体现）；V6 对应 useParams / useSearchParams / useLocation
- **编程式导航**：V6 统一用 `useNavigate()`（支持字符串路径或 `{ pathname, search, state }` 对象），`Link`/`NavLink` 是声明式导航，NavLink 带 active 激活状态
- **路由守卫**：React Router 无内建守卫，用"条件渲染 + 自定义 Hook"（如 `RequireAuth` 未登录 `navigate('/login', { replace: true })`）实现权限校验，逻辑收敛到路由配置层
- **懒加载与代码分割**：`React.lazy(() => import(...))` + `<Suspense fallback>` 按路由拆包，首屏只加载访问到的页面

### 04-React 状态管理

- **为何需要**：状态提升靠 props 层层透传，链路长、跨页面共享无法实现；状态管理 = **单一数据源 + 发布订阅**（集中存一份数据，变了通知订阅方重渲染）
- **Context**：`createContext` + `Provider` 注入 + `useContext` 读取，跨层级传值（类似 Vue 的 provide/inject）；适合主题/语言这类低频全局数据，高频更新会让所有消费者重渲染
- **useReducer**：`useState` 的替代与"简化版 Redux"，四个概念 state / action（`{type}`）/ reducer（纯函数、不可变）/ dispatch；局限是没模块化、需结合 Context 才能跨组件
- **Redux**：把 useReducer 思想推广到全局，**单向数据流**（dispatch(action) → reducer 算新 state → 派发给订阅组件重渲染）；store 可拆分模块、DevTools 可回放每一步 dispatch；RTK 用 `configureStore` + `createSlice` 配合 TS 样板更少；reducer 必须不可变
- **MobX 与 Zustand**：MobX 声明式直接改数据（state/action/derivation，computed 惰性求值），像 Vue；Zustand 极简（`create` 即得 Hook、无需 Provider、支持选择器避免多余重渲染）
- **选型**：简单页用 useState/Context；大型复杂要规范可预测用 Redux；偏好声明式用 MobX；中小项目轻量少样板用 Zustand；无论哪种都牢记**不可变数据**与**单一数据源**

### 05-React 使用 TS

- **组件类型定义**：函数组件用 `FC<IProps>`（自动补全 props/children），类组件用 `React.Component<P, S>` / `PureComponent<P, S>`，P 为 props、S 为 state
- **事件与 ref 泛型**：事件对象/处理函数/DOM 标签都有内置泛型类型（`MouseEvent<HTMLDivElement>`、`ChangeEventHandler<HTMLInputElement>`、`useRef<HTMLInputElement>(null)`），泛型参数传绑定元素类型，ref 取值需判空（`current?.focus()`）
- **泛型组件**：props 类型由调用方传入（`<FunctionTs<IProps> name='well' />`）；`.tsx` 中箭头函数泛型 `<P>` 与 JSX 解析歧义，定义泛型组件推荐用 `function` 声明
- **hooks 泛型**：useState/useRef/useContext/useReducer 均支持泛型声明类型；封装自定义 hooks 时同时导出入参（inProps）与返回值（outProps）类型，把逻辑与类型解耦
- **type vs interface**：两者都能定义 props 类型，用哪个都行，选一种保持一致即可；"类型即文档"——编译期就拦住传错形状的错误

### 06-React 使用 CSS

- **普通 CSS**：内联 style 必须是驼峰 JS 对象（不能是字符串）、尽量少用；`className` 对应 HTML 的 class，动态拼接用 classnames / clsx（对象、数组写法可读性好）
- **CSS Module**：`xxx.module.css` 自动给类名加唯一后缀实现隔离，解决组件化下类名重复覆盖；可结合 classnames（用 `[styles['x']]` 中括号取值）与 Sass（`.module.scss`），CRA 原生支持
- **CSS-in-JS**：在 JS 里写 CSS（styled-components 用带样式的标签模板、styled-jsx 用 `<style jsx>`），编译后生成真实 class——**不是内联 style**；动态样式最强，适合组件库与高度动态场景
- **Tailwind**：Utility-first 原子化方案，用 `text-3xl font-bold` 这类工具类堆叠样式，效率高、风格统一
- **选型**：小项目普通 CSS + className；中大型要隔离用 CSS Module；高度动态用 CSS-in-JS；追求效率统一用 Tailwind
