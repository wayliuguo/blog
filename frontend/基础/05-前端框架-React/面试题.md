## 2. 重点题精答（五步法）

### Q1：JSX 的本质？

- **结论**：JSX 是 `React.createElement` 的语法糖，产出 React 元素（普通对象）。
- **原理**：`<div className="x">hi</div>` → `createElement('div', { className: 'x' }, 'hi')` → `{ type, props, children }`。
- **场景**：理解"JSX 里为什么不能用 if/for 直接写"（表达式求值）；自定义组件首字母大写（type 是函数）。
- **边界**：JSX 不是模板字符串，不执行任意代码，注入安全由转义保证。
- **追问**：React 元素与 DOM 节点的区别？→ 元素是描述对象，DOM 是浏览器节点。

### Q2：Hooks 的规则与原理？

- **结论**：只在顶层调用、只在函数组件调用；Hooks 按调用顺序存储状态。
- **原理**：React 用链表/数组按顺序保存每个 hook 的状态，条件调用会错位。
- **场景**：`useState` 多次调用各占一个槽位；自定义 Hook 复用逻辑。
- **边界**：依赖数组需要稳定引用；`useEffect` 依赖空数组 + 引用外部变量 = 闭包陷阱。
- **追问**：为什么依赖数组里写了 setState 相关的函数没事？→ setter 是稳定的。

### Q3：`useEffect` 与 `useLayoutEffect`？

- **结论**：useEffect 异步（绘制后）执行，useLayoutEffect 同步（绘制前）执行。
- **原理**：useLayoutEffect 在浏览器 paint 前同步运行，用于避免闪烁；useEffect 不阻塞渲染。
- **场景**：测量 DOM、需要同步布局时用 useLayoutEffect；请求数据、订阅用 useEffect。
- **边界**：useLayoutEffect 在服务端渲染会警告；多数场景 useEffect 即可。
- **追问**：为什么大部分场景用 useEffect？→ 不阻塞渲染，性能更好。

### Q4：虚拟 DOM 与 diff？

- **结论**：虚拟 DOM 是 UI 描述，diff 对比新旧元素树，最小化真实 DOM 变更。
- **原理**：同层 diff（不跨层）、`key` 识别节点身份、`type` 不同直接重建。
- **场景**：列表增删用稳定 `key`（id）避免错位渲染；index 作 key 在中间插入时状态错乱。
- **边界**：diff 只是策略，大规模列表仍需虚拟滚动/`memo`。
- **追问**：React 为什么不直接操作 DOM？→ 可声明式、可控更新范围、跨平台（同构渲染）。

### Q5：Hooks 闭包陷阱？

- **结论**：事件回调/effect 捕获了旧渲染的变量，读到的 state 是旧的。
- **原理**：每次渲染都是独立的闭包；依赖数组不更新，回调不重新创建。
- **场景**：`setInterval` 里读 state 拿到旧值 → 用 `useRef` 保存最新值或用函数式更新。
- **边界**：函数式更新（`setCount(c => c+1)`）解决"基于旧值的更新"但不解决"读取"。
- **追问**：为什么每次渲染都是独立闭包？→ state 是常量，重新渲染 = 新作用域 + 新值。

### Q6：React 19 的新特性？

- **结论**：Actions（表单动作）、`use()`（读 Promise/Context）、React Compiler（自动 memo）。
- **原理**：Actions 让表单提交自动管理 pending 状态与错误；`use()` 可在条件中调用读资源；编译器自动做记忆化。
- **场景**：管理后台表单提交用 Actions 简化 pending/error 处理。
- **边界**：新特性需配套 React 19 生态（Router 7 / antd 兼容）。
- **追问**：React Compiler 解决了什么？→ 自动 memo，替代手写 useMemo/useCallback。

## 3. 追问链

1. "`useMemo` 是不是越多越好？" → 不是，缓存也有开销；仅当计算昂贵或依赖引用稳定需要时用。
2. "Context 会触发整棵子树重渲染，怎么优化？" → 拆 Context、用 memo、或用状态管理库的 selector。
3. "受控与非受控怎么选？" → 需要校验/联动用受控；纯展示输入用非受控（ref）。
4. "为什么 key 不要用 index？" → 中间插入/删除时组件状态错位复用。

## 4. 场景设计题

**场景：管理后台有个可拖拽排序 + 实时搜索 + 分页的审核列表，怎么设计才能不卡？**
- 答题骨架：数据分页 + 搜索防抖 → 列表项 memo（纯展示项）→ 拖拽用 dnd-kit（变更最小化，只更新排序字段）→ 大量行虚拟滚动 → 状态收敛（列表数据与服务端同步，本地只存拖拽态）→ 性能度量（用 DevTools/React Profiler 定位重渲染）。
- 加分点：简历管理后台正是"React 19 + dnd-kit 拖拽排序"，可讲"拖拽只改排序字段 + 提交后刷新"的最小变更设计。
