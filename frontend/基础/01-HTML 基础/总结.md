# 模块总结 · HTML 基础

## 知识主线

两篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 HTML 语义化与结构（骨架怎么搭、结构怎么被机器读懂）  ★主轴
        │  页面搭好了只能看不能填，怎么把用户的输入收回来、发出去？
        ▼
02 表单与标签（输入怎么收集、校验、编码与提交）
```

本模块的主轴是**语义化**：01 建立"结构即含义"——语义化标签让 HTML 被解析成的 DOM 树对爬虫（SEO）与读屏器（无障碍）可读，这是整章的地基；02 的表单本质也是标签语义的一部分，`label`/`type`/`name` 的语义让表单既能被浏览器正确收集数据、也能被读屏器朗读，`required`/`pattern` 则把校验也"语义化"成浏览器原生能力。两篇合起来回答一件事：网页是什么结构，以及它怎么与用户交互。

## 分篇知识点

### 01-HTML 语义化与结构

- **文档骨架三件套**：`<!DOCTYPE html>`（声明 HTML5、让浏览器走标准模式，去掉可能进怪异模式）+ `<head>`（`title`/`meta`/`description`）+ `<body>`；`meta name="viewport"` 是移动端布局的关键
- **语义化 = 用含义贴切的标签描述内容**：核心价值是让爬虫与读屏器读懂结构树；用一堆 `<div>` 堆页面只会被读成无意义容器。`header/nav/main`（每页一个）`/article/section/aside/footer` 各司其职
- **进阶语义标签**：`figure + figcaption`（图注跟图走）、`time[datetime]`（机器可读时间利于 SEO）、`address`、`details + summary`（默认收起）
- **响应式图片**：`srcset` 的 `600w/1200w` 告诉浏览器图片真实宽度、由它按屏幕选择；`picture + source media` 按媒体条件换源，最后一个 `<img>` 必填作兜底
- **全局属性**：`id` 页面唯一、`class` 可空格分隔多个、`data-*` 供 JS 用 `dataset` 读取、`hidden` 隐藏
- **原理**：HTML 被解析成 DOM 树，任何框架、JS（`querySelector`）、爬虫本质都是在这棵树上找节点；`alt` 参与图片搜索与无障碍

### 02-表单与标签

- **提交三件套**：`action`（发往哪）+ `method`（get 拼 URL 适合搜索 / post 放请求体）+ 控件 `name`——**没有 `name` 的控件不会被提交**，是最常见的坑
- **控件速查**：`email/number/date` 自带格式校验；多行用 `textarea`；单选/复选/下拉用 `radio/checkbox/select`；`label for=id` 让点文字也能聚焦/选中控件，同时服务读屏器
- **原生约束校验**：`required/pattern/min/max` 不写 JS 也能拦，底层是浏览器的 Constraint Validation（`validity`/`checkValidity`/`setCustomValidity`），`:valid/:invalid` 伪类可定制样式
- **编码与上传**：普通 post 用 `application/x-www-form-urlencoded`（`a=1&b=2`）；上传文件必须把 `enctype` 设为 `multipart/form-data`，否则文件传不上去
- **FormData**：一次拿全表单（含文件），`Object.fromEntries(data)` 转对象，替代逐个 `getElementById`
- **`preventDefault()` 的本质**：掐断浏览器默认提交流程（收集 → 编码 → 跳转/刷新）把控制权交给 JS；`novalidate + checkValidity()` 是"仍用原生校验但自定义展示"的常用组合
