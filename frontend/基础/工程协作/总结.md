# 模块总结 · 工程协作

## 知识主线

本模块只有一篇正文，讲 Git 作为团队协作基石要会的两件事：**管好历史**（撤销回退、分支协作）与**跨仓库同步**（Gitee/GitHub 镜像、Monorepo 多包）。它属于"工具使用"能力，是进阶里「代码规范与质量门禁」「CI/CD 自动化」能落地的协作底座——没有一致的提交与分支约定，门禁和流水线也无从谈起。

## 分篇知识点

### 01-Git 与协作

- **常用命令速览**
  - 基础操作：`git init` / `add` / `commit` / `status` / `log`（含 `--oneline` / `--graph`）
  - 撤销回退：`git reset`（改写历史）vs `git revert`（新建反做提交，不改写历史）
- **撤销与回退提交**
  - `reset` 三种模式：`--soft` 只移动 HEAD（改动留暂存区）、`--mixed`（默认，更新暂存区）、`--hard` 工作区与暂存区都重置（未提交改动全丢，慎用）
  - `reset` 会改写历史：已推远程共享分支不要 `--force`，否则影响他人；此时用 `revert`
  - `revert commitId`：新建相反提交抵消目标提交，原历史不变，适合已推送场景；vim 小抄 `:wq` / `:q!`、普通/插入/命令三模式
- **远程仓库管理**
  - `git remote -v` 看关联；`remote rm` + `remote add` 换源；`push -u origin main` 首次指定上游
- **工作流与分支协作**
  - 功能分支流程：`checkout -b feature/xxx` → 开发提交 → 推远程发 PR/MR → 评审合入 → 其他人 `pull` 同步
  - 分支管理：`branch -vv`（看远程关联）、`merge`、`pull --rebase`（变基合并，历史更线性）
  - 合并冲突：冲突文件标 `both modified`，在 `<<<<<<<` / `=======` / `>>>>>>>` 区手动选留，解决后 `add` + `commit`；提前 pull、提交粒度单一可减少冲突
- **Gitee / GitHub 镜像同步**
  - 配置：Gitee「管理 → 仓库镜像管理 → 添加镜像」，选 Push 方向、填目标仓库与私人令牌（令牌需含 `repo` 权限）
  - 触发：提交到 Gitee 自动同步，最短间隔 5 分钟；Push 方向自动同步分支/标签/提交
- **Monorepo 与 pnpm（速览）**
  - 单仓库多模块：相同依赖提升到顶层只装一次省磁盘、工程配置一致；代价是无项目级权限管控、仓库体积大
  - pnpm：`workspace:` 协议在子包间互链，避免手写 `npm link`；完整工程化见[前端工程化 / Monorepo 工程化](../../进阶/前端工程化/Monorepo工程化.md)
