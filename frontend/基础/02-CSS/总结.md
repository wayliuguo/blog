# 模块总结 · CSS

## 知识主线

六篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 CSS 基础与选择器（怎么命中元素、冲突时听谁的）
        │  会"化妆"了，元素该怎么摆、多栏页面怎么排？
        ▼
02 布局（Flex/Grid 怎么排、经典布局怎么做）  ★主轴
        │  桌面排好了，手机/平板怎么办？一套代码怎么多端适用？
        ▼
03 响应式与移动端（断点、vw/rem 适配、移动端坑）
        │  静态布局完成，状态变化怎么表达才流畅不卡？
        ▼
04 动画与变换（transform/transition/animation 与合成层）
        │  页面变多了、人变多了，类名怎么命名才不冲突、好维护？
        ▼
05 BEM 与 CSS 规范（命名方法论与工程化选型）
        │  各点都会了，怎么放进一个真实页面串成闭环？
        ▼
06 综合实战（响应式卡片落地页收口）
```

本模块的主轴是**布局**：01 的层叠/盒模型/BFC 决定每个元素"怎么画"，02 的 Flex/Grid 决定"怎么排"，03 的媒体查询与 vw/rem 决定"多端怎么变"，04 的 transform 让布局动起来时走合成层不卡，05 的 BEM 是布局类名的组织规范，06 把它们全部放进一张真实页面收口。

## 分篇知识点

### 01-CSS 基础与选择器

- **层叠四层判定**：`!important` > 来源 > 优先级权重 > 源码顺序；权重近似"内联 > ID > 类/伪类/属性 > 标签/伪元素"四位数比较、不产生进位，同权重看源码顺序后者覆盖前者
- **选择器**：类选择器是 BEM 等规范的基础；属性选择器 `^=`/`$=`/`*=`/`~=`；伪类改状态（`:hover`/`:nth-child`）、伪元素造元素（`::before`/`::after`）；组合器空格/`>`/`+`/`~`
- **盒模型**：`box-sizing: border-box` 让设定的 width 即最终宽度（content 被压缩），标准 `content-box` 下 padding/border 会撑爆宽度；项目建议全局 `*{box-sizing:border-box}`
- **margin 两个坑**：垂直相邻 margin 合并取较大值（不是相加）；父子 margin 塌陷可用父级 padding/border、`overflow: hidden`、`display: flow-root` 解决
- **单位**：`em` 相对当前字体且会嵌套累积、`rem` 相对根元素（移动端适配主角）、`vw/vh` 直接跟视口挂钩；继承上文字类属性可继承、盒子类属性不继承
- **BFC**：一块独立渲染区域，触发方式（overflow/flex/grid/absolute/float），三类用途：清除浮动包住子元素、防父子 margin 塌陷、两列自适应不被浮动覆盖

### 02-布局

- **文档流与定位**：块级自上而下、行内从左到右；`absolute` 相对最近的非 static 祖先且脱离文档流、`relative` 仍占位可偏移、`sticky` 滚动吸附
- **float**：脱离文档流但文本环绕；父元素高度塌陷用 BFC 或 `::after + clear: both` 清除，现代布局已被 Flex/Grid 取代
- **Flex 一维**：主轴由 `flex-direction` 决定，`justify-content` 控主轴对齐、`align-items` 控交叉轴；`flex: 1` 均分剩余空间、`flex: 0 0 200px` 固定不缩放
- **Grid 二维**：`grid-template-columns` + `fr` 比例单位 + `repeat()`；`grid-template-areas` 命名区域直接摆页面骨架；`grid-column: 1/3` 跨列
- **经典布局**：两栏/三栏用 Flex"固定 + 自适应"；圣杯/双飞翼核心是"中间 DOM 靠前 + 两侧固定 + 中间自适应"，现代用 Grid 一行即可实现
- **居中与选型**：居中优先 Flex（> transform > margin:auto）；页面骨架用 Grid、局部行列用 Flex、图文环绕才用 float

### 03-响应式与移动端

- **viewport**：`width=device-width` 是核心，要分清布局视口/视觉视口/理想视口；`viewport-fit=cover` 配合 `env(safe-area-inset-*)` 适配刘海屏
- **媒体查询**：按设备特征换样式；**Mobile First** = 默认写移动端、用 `min-width` 向上递进，大屏只覆盖小屏样式；断点不必死守
- **适配方案四选**：百分比（等比/字体不便）、Flex（现代主力）、rem/flexible（动态改根字号全站等比缩放，需 JS 且字体有坑）、vw（1vw = 视口 1%，无 JS 是当前主流，极端大屏需 max-width 兜底）
- **dpr**：物理像素/逻辑像素；高清屏要 @2x/@3x 图，canvas 按 `1/dpr` 设物理宽高再 `ctx.scale(dpr, dpr)`
- **移动端坑**：300ms 点击延迟（设 `width=device-width` 即可消除）、点击穿透、1px 边框（`transform: scale(0.5)` 最常用）、点击高亮清理、iOS 安全区
- **实践建议**：布局用 Flex + Grid、尺寸缩放用 vw、图标用 iconfont/SVG、borders 用 scale 0.5

### 04-动画与变换

- **三套能力分工**：`transform` 管几何变换（translate/scale/rotate/skew，2D/3D）且不改变文档流占位；`transition` 是"被动"的、属性值改变才触发；`animation` 是"主动"执行的多关键帧序列
- **transform 细节**：translate 百分比相对元素自身（`translate(-50%,-50%)` 是居中技巧）；`transform-origin` 决定变换原点（开门效果）；3D 需 `perspective` + `transform-style: preserve-3d`
- **transition 限制**：只能过渡可插值的数值型属性，`display`/`auto` 无法过渡（高度展开用 `max-height` 技巧）；四个子属性 property/duration/timing-function/delay
- **animation 与 @keyframes**：百分比对应时间轴；`animation-fill-mode` 的 none/forwards/backwards/both——入场动画用 `both` 避免闪跳；`animation-play-state` 可暂停
- **性能铁律**：只动画 `transform` 和 `opacity`——它们跳过 layout/paint 直接走合成（composite）跑 GPU；`will-change` 可提前提升合成层但要按需添加、用完即移除
- **CSS vs JS 动画**：简单过渡/入场/无限循环优先 CSS；需要暂停/seek/物理模拟/滚动手势联动用 JS（WAAPI `element.animate()`）

### 05-BEM 与 CSS 规范

- **命名规范的价值**：为类名附加可预测信息（属于谁、什么角色、什么状态），解决命名冲突、无从定位、覆写成本高三大维护难题
- **BEM 三段式**：`block__element--modifier`——块（可复用组件）/`__` 元素（块内组成部分）/`--` 修饰符（状态或变体）；块内元素不写父级链（`card__title` 而非 `card__header__title`）
- **关键约定**：修饰符不单独存在、必须挂基础类做增量覆盖；命名描述"是什么"而非"长什么样"（`card--primary` 而非 `card--red`）；JS 钩子用 `data-*` 与样式类名解耦
- **Sass 写法**：用 `&` 嵌套让 BEM 更紧凑（`&__title`/`&--modifier`）；超小一次性样式与已引入 Tailwind 的项目不必追求完整 BEM
- **工程化四选一**：普通全局 CSS（零构建但易冲突）、CSS Module/scoped（哈希类名组件级隔离，React/Vue 主流）、CSS-in-JS（运行时生成、动态主题强、有开销）、Tailwind 原子化（工具类按需生成、快但 HTML 可读性下降）
- **选型**：看项目规模/团队熟悉度/构建链；务实做法是混合——主体 CSS Module 或 Tailwind，复杂业务组件用 BEM 承载语义

### 06-综合实战

- **能力对应表**：BEM 命名（05）+ Grid/Flex（02）+ 媒体查询 Mobile First（03）+ transform/animation（04）串成一张"产品特性卡片落地页"
- **Mobile First 写法**：默认 `grid-template-columns: 1fr`，`min-width: 600px` 两列、`min-width: 900px` 三列，大屏只覆盖列数、不动小屏样式
- **动效**：入场用 `animation ... both` 保留末帧避免闪跳；悬停用 `transform: translateY(-4px)` + box-shadow，走合成层流畅不卡
- **验收四查**：断点自适应不溢出、悬停平滑、入场浮现、类名遵循 `block__element--modifier` 改一处不影响他处

## 代码与自测入口

配套代码项目：`./code`，启动 `node server.js` 后打开 `http://localhost:5175/`（零依赖，无需 `npm install`）。代表性 demo：

- `box-sizing.html`：content-box vs border-box 实际占位对比，亲眼看 padding 是否"撑爆"设定宽度；
- `specificity.html`：四种选择器命中同一元素，验证"权重 + 源码顺序"；
- `bfc.html`：触发与不触发 BFC 的包裹差异，验证防父子 margin 塌陷；
- `flex-grid.html`：切换 `flex:1`/`flex-basis` 看剩余空间分配，对比 Grid 的 `1fr` 与 `grid-template-areas`；
- `responsive.html`：缩放窗口观察媒体查询断点与 vw 动态变化；
- `animation.html`：对比只动 transform 与动 width 的帧率，理解合成层；
- `bem-card.html`：增删 `--modifier` 看 BEM 增量覆盖；
- `project/index.html`：综合实战——响应式卡片落地页（BEM + Grid + 媒体查询 + 入场动画）。
