# 模块总结 · CSS

## 知识主线

六篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 CSS 基础与选择器（怎么命中元素、冲突时听谁的）
        │  会"化妆"了，元素该怎么摆、多栏页面怎么排？
        ▼
02 布局（Flex/Grid 怎么排、经典布局怎么做）  ★主轴
        │  桌面排好了，手机/平板怎么办？一套代码怎么多端适用？
        ▼
03 响应式与移动端（断点、vw/rem 适配、移动端坑）
        │  静态布局完成，状态变化怎么表达才流畅不卡？
        ▼
04 动画与变换（transform/transition/animation 与合成层）
        │  页面变多了、人变多了，类名怎么命名才不冲突、好维护？
        ▼
05 BEM 与 CSS 规范（命名方法论与工程化选型）
        │  各点都会了，怎么放进一个真实页面串成闭环？
        ▼
06 综合实战（响应式卡片落地页收口）
```

本模块的主轴是**布局**：01 的层叠/盒模型/BFC 决定每个元素"怎么画"，02 的 Flex/Grid 决定"怎么排"，03 的媒体查询与 vw/rem 决定"多端怎么变"，04 的 transform 让布局动起来时走合成层不卡，05 的 BEM 是布局类名的组织规范，06 把它们全部放进一张真实页面收口。

## 分篇知识点

### 01-CSS 基础与选择器

- **CSS 引入方式**
  - **行内样式**：写在标签 `style` 属性上，优先级最高（除 `!important` 外），结构与样式耦合、不推荐生产使用
  - **内嵌 `<style>`**：写在 `<head>` 的 `<style>` 标签里，适合单页测试、邮件模板等少量样式
  - **外链 `<link>`**：引入独立 `.css` 文件，样式与结构分离、可缓存可复用，**最推荐**
  - **`@import`**：CSS 文件内引入其他 CSS，会阻塞渲染且多一次 HTTP 请求，生产环境尽量避免
- **层叠四层判定**
  - **`!important`**：带 `!important` 的声明最优先，但会破坏可维护性，慎用
  - **来源**：用户 `!important` > 作者 `!important` > 作者普通样式 > 用户普通样式 > 浏览器默认样式
  - **优先级权重**：近似"内联 > ID > 类/伪类/属性 > 标签/伪元素"四位数比较、不产生进位
  - **源码顺序**：权重相同时，后出现的声明覆盖先出现的
- **选择器**
  - **基本选择器**：标签（命中面宽）、类（BEM 等规范的基础，推荐优先）、ID（权重过高且不可复用）、通配 `*`（重置用）
  - **属性选择器**：`[type="submit"]` 精确匹配，`^=` 以…开头、`$=` 以…结尾、`*=` 包含、`~=` 匹配空格分隔的单词
  - **伪类 vs 伪元素**：伪类改状态（`:hover`/`:nth-child`，单冒号）、伪元素造元素（`::before`/`::after`，双冒号）
  - **组合器**：空格（后代）、`>`（子）、`+`（相邻兄弟）、`~`（通用兄弟）
- **盒模型**
  - **四部分**：`content`（由 `width`/`height` 决定）、`padding`（内容与边框的距离）、`border`（边框）、`margin`（外边距，不占盒子尺寸）
  - **`content-box`（标准）**：`width` 只算 content，padding/border 会撑爆宽度
  - **`border-box`（怪异/IE）**：设定的 `width` 即最终宽度、content 被压缩，项目建议全局 `*{box-sizing:border-box}`
- **margin 两个坑**
  - **margin 合并**：垂直方向相邻的两个 margin 不相加、取较大值（水平方向不合并）
  - **父子 margin 塌陷**：块级父元素无 padding/border 且未触发 BFC 时，子元素 `margin-top` 冲出父元素
  - **解决方式**：父级 padding/border、`overflow: hidden`、`display: flow-root`
- **单位**
  - **`px`**：绝对单位，固定最直观，屏幕端最常用
  - **`em`**：相对当前元素字体大小，会嵌套累积，适合局部组件内部
  - **`rem`**：相对根元素 `<html>` 字体，全局统一，移动端适配主角
  - **`vw` / `vh`**：直接跟视口挂钩（`1vw` = 视口宽 1%），全屏/半屏布局方便，注意移动端 `100vh` 受地址栏影响可能偏大
  - **`%`**：宽高百分比相对父元素内容区
- **继承**
  - **可继承**：文字类属性（`color`/`font-size`/`font-family`/`line-height`/`text-align` 等）
  - **不可继承**：盒子类属性（`width`/`height`/`margin`/`padding`/`border`/`position`/`display` 等）
  - **控制关键字**：`inherit` 强制继承、`initial` 用浏览器默认值、`unset` 可继承属性=inherit 否则=initial
  - **应用**：在 `body` 或 `:root` 上统一设置字体/颜色，子孙自动继承
- **BFC**
  - **是什么**：块格式化上下文，页面上一块独立渲染区域，内部与外部布局互不干扰
  - **触发方式**：`overflow: hidden`（常用）/ `display: flow-root` / `flex` / `grid` / `absolute` / `fixed` / `sticky` / `float`
  - **清除浮动包住子元素**：子元素 float 后父元素高度塌陷，开 BFC 可重新包住
  - **防父子 margin 塌陷**：开 BFC 后子元素外边距不再溢出到父元素外
  - **两列自适应**：主列触发 BFC 不与浮动重叠、自动占满剩余宽度

### 02-布局

- **文档流与定位**
  - **文档流（Normal Flow）**：块级元素自上而下、行内元素从左到右排布
  - **`static`（默认）**：不定位，留在文档流中
  - **`relative`**：相对自身原本位置偏移，**不脱离文档流**（仍占位）
  - **`absolute`**：相对最近的非 static 祖先定位（没有则相对 body/视口），**脱离文档流**
  - **`fixed`**：相对浏览器视口定位，脱离文档流
  - **`sticky`**：滚动吸附，占位（滚动时吸附到视口边缘）
- **float**
  - **行为**：元素向左/右"飘"，脱离文档流但文本会环绕它，常用于图文混排
  - **父元素高度塌陷**：子元素 float 后不再占高度、父元素撑不起来
  - **清除浮动**：父元素触发 BFC（如 `overflow: hidden`）或 `::after + clear: both`（clearfix）
  - **现状**：已被 Flex/Grid 取代，仅图文环绕场景仍在使用
- **Flex 一维**
  - **主轴与交叉轴**：主轴由 `flex-direction` 决定（`row`/`column`/`row-reverse`/`column-reverse`），`justify-content` 控主轴对齐、`align-items` 控交叉轴对齐
  - **容器属性**：`flex-wrap`（换行）、`align-content`（多行整体对齐）、`gap`（子项间距）
  - **`flex` 简写**：`flex-grow`/`flex-shrink`/`flex-basis` 的简写；`flex: 1` 均分剩余空间、`flex: 0 0 200px` 固定不缩放
  - **项目属性**：`order` 排列顺序（越小越靠前）、`align-self` 覆盖容器的 `align-items`
  - **终极居中**：`justify-content: center` + `align-items: center`
- **Grid 二维**
  - **二维网格**：同时管行和列，`grid-template-columns`/`grid-template-rows` 定义行列
  - **`fr` 与 `repeat()`**：`fr` 比例单位按份数分配剩余空间、`auto` 按内容自适应、`repeat(4, 1fr)` 简化重复、`repeat(auto-fill, minmax(120px, 1fr))` 响应式自动填充
  - **`grid-template-areas`**：命名区域直接摆页面骨架（`"header header"`…）
  - **显式定位**：`grid-column: 1/3` 跨列、`grid-row` 占行
- **经典布局**
  - **两栏**：Flex"固定 + 自适应"（`flex: 0 0 200px` + `flex: 1`）
  - **三栏**：两侧固定 + 中间自适应
  - **圣杯 / 双飞翼**：核心思路是"中间 DOM 靠前 + 两侧固定 + 中间自适应"；圣杯用 padding + 负 margin，双飞翼在中间内部再包一层、用 margin 腾出空间
  - **现代简化版**：Grid 一行即可实现圣杯效果（`grid-template-columns: 150px 1fr 200px` + `grid-template-areas`）
- **居中与选型**
  - **Flex 居中**：`display: flex` + `justify-content: center` + `align-items: center`，通用推荐
  - **绝对定位 + `margin: auto`**：需已知尺寸/定宽
  - **绝对定位 + `transform`**：`translate(-50%, -50%)`，不知宽高也可用
  - **单行文字**：`line-height` 等于高度 + `text-align: center`
  - **性能排序**：Flex > transform > margin:auto
  - **选型**：页面骨架用 Grid、局部行列用 Flex、图文环绕才用 float

### 03-响应式与移动端

- **viewport**
  - **`width=device-width`**：布局视口宽度 = 设备屏幕宽度，核心属性；同时可消除移动端 300ms 点击延迟
  - **`initial-scale` / `maximum-scale` / `user-scalable`**：初始缩放比 1:1、允许的最大/最小缩放、禁止用户缩放
  - **`viewport-fit=cover`**：适配刘海屏/全面屏，配合 `env(safe-area-inset-*)` 处理安全区
  - **三对视口概念**：布局视口（CSS 布局用，受 meta 控制）/ 视觉视口（用户当前看到的区域）/ 理想视口（`width=device-width` 时布局视口=屏幕）
- **媒体查询**
  - **基本语法**：`@media (min-width: 768px)` 视口 ≥768px 时生效、`(max-width: 480px)` 小屏生效
  - **断点参考**：480（手机横屏/小屏）/ 768（平板）/ 992（桌面小屏）/ 1200（桌面大屏），不必死守、随设计走
  - **Mobile First**：默认写移动端样式、用 `min-width` 向上递进，大屏只覆盖小屏样式
  - **其他特性**：`prefers-color-scheme: dark` 深色模式、`orientation` 横竖屏、`min-resolution: 2dppx` 高清屏
- **适配方案四选**
  - **百分比**：`%` 相对父元素，思路简单但图片等比、字体等比不便
  - **弹性 Flex**：靠比例与内容自适应、不依赖具体尺寸，现代适配主力
  - **rem / flexible**：以设计稿（750px）为基准动态改根字号、全站等比缩放；依赖 JS 且 rem 不等比字体会带来问题，已逐渐被 vw 取代
  - **vw**：`1vw` = 视口宽 1%，无 JS、比重，当前主流；极端大屏需 `max-width` 兜底，可用 `postcss-px-to-viewport` 自动把 px 转 vw
- **dpr**
  - **定义**：`devicePixelRatio` = 物理像素 / 逻辑像素（CSS 像素）
  - **高清图**：dpr≥2 的屏需要 `@2x`/`@3x` 图或 SVG，避免发虚
  - **canvas 适配**：按 `1/dpr` 设物理宽高、再 `ctx.scale(dpr, dpr)` 绘制保持清晰
- **移动端坑**
  - **300ms 点击延迟**：设 `width=device-width` 即可消除；老方案 FastClick 已过时
  - **点击穿透**：300ms 后补发的 click 落在下层元素；用 tap 事件（`touchstart + touchend`）或给下层加遮挡层解决
  - **1px 边框**：`transform: scale(0.5)` 最常用（dpr=2 时缩一半）；`0.5px` 兼容性不统一
  - **点击高亮清理**：`-webkit-tap-highlight-color: transparent` 等移除系统默认样式
  - **滚动白屏**：`-webkit-overflow-scrolling: touch` / `overscroll-behavior` 处理 iOS 惯性滚动
  - **iOS 安全区**：`env(safe-area-inset-bottom)` 适配刘海屏
  - **图片与字体**：图标用 iconfont/SVG 等比缩放、高清用 @2x、字号避免小于 12px
- **实践建议**
  - **布局**：用 Flex + Grid
  - **尺寸缩放**：用 vw，字体可部分用 vw 或锁定 rem
  - **图标**：用 iconfont / SVG 等比缩放，不用位图
  - **边框**：用 `transform: scale(0.5)`

### 04-动画与变换

- **三套能力分工**
  - **`transform`**：管几何变换（translate/scale/rotate/skew，2D/3D），不改变文档流占位，是性能最好的动效基础
  - **`transition`**："被动"过渡，属性值改变（`:hover`/类名增删/JS 修改）才触发
  - **`animation`**："主动"执行的多关键帧序列，定义好自动执行
  - **配合方式**：`transform` 负责几何变化的"动作"，`transition`/`animation` 负责"时间轴"
- **transform 细节**
  - **`translate`**：百分比相对元素自身尺寸（`translate(-50%,-50%)` 是居中技巧），3D 用 `translate3d`
  - **`scale`**：缩放，默认以元素中心为基准
  - **`rotate`**：旋转，`rotateY(180deg)` 配合透视做卡片翻转
  - **`skew`**：倾斜，模拟立体透视/装饰条
  - **组合顺序**：多个变换函数从右往左作用于元素局部坐标系
  - **`transform-origin`**：决定变换原点（默认 `50% 50%`），改原点让同样 rotate 呈现不同轨迹（开门效果）
  - **3D 透视**：`perspective`（父容器或函数写法）+ `transform-style: preserve-3d`
- **transition 限制**
  - **四个子属性**：`transition-property` / `-duration`（必填）/ `-timing-function` / `-delay`
  - **可过渡范围**：只能过渡数值或可插值的属性；`display`、`width/height: auto` 无法过渡
  - **高度展开技巧**：用 `max-height` 过渡（0 → 300px）或 `transform: scaleY`
  - **推荐过渡属性**：`transform` 和 `opacity`（跳过布局/绘制、性能最好）；避免动 `width`/`height`/`top`/`left`
- **animation 与 @keyframes**
  - **`@keyframes`**：百分比对应时间轴（`0%` 起点、`100%` 终点），也可用 `from`/`to`
  - **子属性**：`name`/`duration` 必填；`timing-function`/`delay`/`iteration-count`（`infinite` 无限循环）/`direction`（`alternate` 正反交替）/`fill-mode`/`play-state`
  - **`fill-mode`**：`none`（默认）/`forwards`（保留末帧）/`backwards`（延迟期先应用首帧）/`both`；入场动画用 `both` 避免闪跳
  - **与 JS 交互**：切换类名或 `animation-play-state: paused` 暂停/恢复，让动画逻辑留在 CSS 层
- **性能铁律**
  - **渲染三环节**：layout（布局）→ paint（绘制）→ composite（合成）
  - **只动画 `transform` 和 `opacity`**：跳过 layout/paint 直接走合成层、跑 GPU，动画流畅不卡
  - **`will-change`**：提前告诉浏览器提升合成层、减少动画开始时的卡顿；按需添加、用完即移除，滥用会消耗显存
  - **3D 触发提升**：`translateZ(0)`/`backface-visibility: hidden` 会强制创建合成层（历史 hack，现在推荐按需用 will-change）
- **CSS vs JS 动画**
  - **选 CSS**：简单过渡、hover 动效、入场动画、无限循环——代码量少、性能好、天然可退化
  - **选 JS**：需要暂停/seek/回放、物理模拟、滚动手势联动——WAAPI（`element.animate()`）或 rAF
  - **通用原则**：无论哪种，坚持 transform/opacity 优先，避免动画中修改 width/height/top/left

### 05-BEM 与 CSS 规范

- **命名规范的价值**
  - **要解决的问题**：命名冲突（通用名互相覆盖却难察觉）、无从定位（看不出属于哪个组件/角色/状态）、覆写成本高（改一处影响全局）、重构困难
  - **核心价值**：为类名附加可预测信息（属于谁、什么角色、什么状态），不看原码也能推断结构
- **BEM 三段式**
  - **Block（块）**：独立可复用的组件，用单个命名空间表示（`card`）
  - **Element（元素）**：块内部的组成部分，用 `块__元素` 表示（`card__title`）
  - **Modifier（修饰符）**：块或元素的状态/变体，用 `块--修饰符` 表示（`card--highlighted`）
  - **符号规则**：`__` 连接块与元素、`--` 连接修饰符，分隔符两侧不加空格
  - **块的判断**：能否脱离当前上下文独立复用——能就提升为块，只在固定父级内存在则是父级的元素
- **关键约定**
  - **不写父级链**：块内元素不写中间元素（`card__title` 而非 `card__header__title`），避免过深嵌套
  - **修饰符挂基础类**：`card--highlighted` 不能脱离 `card` 单独存在，在基础类上做增量覆盖
  - **命名描述"是什么"**：`card--primary` 而非 `card--red`，避免颜色改动使类名失真
  - **JS 钩子解耦**：JS 用 `data-*` 或 `js-` 前缀选择，不依赖样式类名，改样式类不影响 JS
- **Sass 写法**
  - **`&` 嵌套**：`&__title` / `&--modifier` 让 BEM 更紧凑、避免手写超长类名
  - **取舍**：`&__` 拼写易错时可直接写完整类名；超小一次性样式与已引入 Tailwind 的项目不必追求完整 BEM
- **工程化四选一**
  - **普通全局 CSS**：零构建成本、便于全局主题，但全局作用域极易命名冲突、无样式隔离
  - **CSS Module / scoped**：构建工具编译成哈希类名实现局部作用域，组件级隔离，React/Vue 主流
  - **CSS-in-JS**：样式写在 JS 里运行时生成（styled-components/Emotion），动态主题强、有运行时开销
  - **Tailwind 原子化**：工具类按需 JIT 生成，视觉实现极快、按需摇树，但 HTML 可读性下降
- **选型**
  - **考虑因素**：项目规模、团队熟悉度、构建链与框架、可维护性/可调试性/性能的取舍、主题与设计系统
  - **务实组合**：小项目用普通 CSS 或 Tailwind；组件库/中后台用 CSS Module + 简单 BEM；需要运行时主题用 CSS-in-JS 或叠加 CSS 变量
  - **混合使用**：主体 CSS Module 或 Tailwind + 复杂业务组件用 BEM 承载语义，不是非此即彼

### 06-综合实战

- **能力对应表**
  - **BEM 命名（05）**：`feature__card--modifier` 承载卡片结构（`feature__title`/`feature--primary`）
  - **Grid + Flex（02）**：3 列特性卡片网格 + 导航 Flex（`justify-content: space-between`）
  - **媒体查询（03）**：断点自适应，桌面 3 列 → 平板 2 列 → 手机 1 列
  - **transform / animation（04）**：悬停与入场动效
- **Mobile First 写法**
  - **默认移动端**：`grid-template-columns: 1fr`
  - **向上递进**：`min-width: 600px` 两列、`min-width: 900px` 三列
  - **大屏只覆盖**：断点内只改列数，不动小屏样式
- **动效**
  - **入场**：`animation ... both` 保留末帧避免闪跳（`@keyframes rise` 从下方浮现）
  - **悬停**：`transform: translateY(-4px)` + box-shadow，走合成层流畅不卡
- **验收四查**
  - **断点自适应**：拖动窗口 1/2/3 列切换、内容不溢出
  - **悬停平滑**：卡片"上浮 + 阴影"流畅不卡顿
  - **入场浮现**：加载时卡片从下方依次浮现
  - **类名规范**：遵循 `block__element--modifier`，改一处不影响他处
