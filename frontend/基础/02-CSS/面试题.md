## 2. 重点题精答（五步法）

### Q1：什么是 BFC？怎么触发？

- **结论**：BFC 是块级格式化上下文，内部布局不影响外部、外部不影响内部。
- **原理**：独立渲染区域，浮动/边距在区域内隔离。
- **场景**：清除浮动、阻止 margin 折叠、隔离横向滚动溢出。
- **边界**：`overflow: hidden` 清浮动有裁切副作用，推荐 `display: flow-root`（无副作用）。
- **追问**：BFC 与层叠上下文是同一回事吗？→ 不是，前者管布局隔离，后者管绘制层级。

### Q2：层叠上下文导致 z-index 失效？

- **结论**：z-index 只在同一层叠上下文内比较，跨上下文比较的是各自祖先的层级。
- **原理**：`opacity<1`、`transform`、`filter`、`will-change`、`fixed`、flex/grid 子项 + z-index 都会创建层叠上下文。
- **场景**：弹窗被盖住 → 检查祖先是否创建了上下文。
- **边界**：大 z-index 数值是"权重战争"，正确做法是分层上下文管理。
- **追问**：`transform` 不写 z-index 也创建上下文吗？→ 会。

### Q3：px→vw 与 px→rem 怎么选？

- **结论**：px→vw 是编译期纯方案（项目选择），px→rem 是运行期 JS 设根字号方案。
- **原理**：`postcss-px-to-viewport-8-plugin` 把 px 编译为 vw（`viewportWidth: 375`），随视口等比缩放；rem 依赖 JS 设 `html` 根字号。
- **场景**：项目 `postcss.config.js`：`selectorBlackList: ['.ignore-', '.van-']` 排除 Vant 避免二次缩放；`minPixelValue: 1` 保护真实 1px 描边。
- **边界**：vw 在大屏（iPad/PC）会按比例放大，需 `max-width` 容器兜底。
- **追问**：为什么排除 Vant？→ Vant 基于自身设计稿，若按 375 二次缩放会尺寸错乱。

### Q4：`1px` 物理像素边框？

- **结论**：DPR≥2 时 1 CSS px = 2 物理像素，视觉变粗。
- **原理**：CSS px 是逻辑单位，高 DPR 下渲染成多物理像素。
- **场景**：伪元素 `transform: scaleY(0.5)` 模拟 0.5px；项目 `minPixelValue: 1` 保留真实 1px 不转 vw。
- **边界**：`border-width: 0.5px` 部分浏览器不支持，需兼容写法。
- **追问**：`minPixelValue: 1` 的副作用？→ 小于 1px 的设计间距不参与适配，通常可接受。

### Q5：安全区适配？

- **结论**：`viewport-fit=cover` 让布局延伸到刘海屏之下，用 `env(safe-area-inset-*)` 避让。
- **原理**：`env()` 返回安全区距离，需 `viewport-fit=cover` 才非零；`constant()` 是旧 iOS 11 前缀。
- **场景**：`padding-bottom: env(safe-area-inset-bottom, 0px)` 避开 Home 指示条；项目还用 JS 写入 `--phone-state-bar-height` 处理 App 内动态状态栏（`setProperty`）。
- **边界**：未设 `viewport-fit=cover` 时 `env()` 恒为 0。
- **追问**：`env()` 与 JS 写 CSS 变量各管什么？→ 系统级安全区用 env()，App 内动态状态栏用 JS 变量，二者互补。

### Q6：动画与合成层优化？

- **结论**：动画只用 `transform`/`opacity`，走合成线程不触发重排。
- **原理**：重排（Layout）→ 重绘（Paint）→ 合成（Composite）成本递减；`transform`/`opacity` 由 GPU 合成。
- **场景**：`will-change: transform` 提示浏览器提前提升合成层，动画结束移除。
- **边界**：滥用 `will-change` 占用 GPU 内存、增加合成层管理开销，反而更卡。
- **追问**：`contain: layout paint` 与 will-change 区别？→ contain 限制重排范围，非提升合成层。

## 3. 追问链

1. "为什么 flex 子项长文本溢出？" → 默认 `min-width: auto` 不收缩，加 `min-width: 0`。
2. "sticky 失效排查顺序？" → 父容器 overflow → 高度不足 → 未设阈值 → 祖先 transform。
3. "为什么 `gap` 比 `margin` 好？" → 容器级间距、无折叠、无首尾多余间距。
4. "browserslist 怎么约束 autoprefixer？" → 声明目标浏览器集合，autoprefixer 自动加对应前缀。

## 4. 场景设计题

**场景：H5 页面在 iPhone 刘海屏上底部按钮被 Home 条遮挡，怎么修？**
- 答题骨架：`viewport-fit=cover`（HTML 层）→ `padding-bottom: env(safe-area-inset-bottom, 0px)` → App 内动态状态栏用 JS 写 `--phone-state-bar-height` → 兼容回退 `constant()`/默认值。
- 加分点：说明 `env()` 需 `viewport-fit=cover` 才非零，以及 Android 需除以 `devicePixelRatio` 的坑。

## 5. 面试口径（简历项目如何表达）

- **项目证据**：`postcss.config.js`（viewportWidth 375 / selectorBlackList 排除 Vant / minPixelValue 1 / exclude node_modules）、`browserslist`（`> 0.2% in CN`、iOS≥11、Chrome≥61、not dead）、`useStateBarHeight` 用 `setProperty('--phone-state-bar-height', ...)` 写入 CSS 变量。
- **表达句式**："移动端适配是 375 设计稿 + px→vw 的编译期方案，排除 Vant 组件库防二次缩放；安全区用 `env()` 处理系统级避让，App 内动态状态栏用 JS 写入 CSS 变量，两层互补。"
- **主动暴露取舍**："`user-scalable=0` 是 H5 在 App 内一致性的取舍，伴随可访问性代价，我清楚这个权衡"——体现"懂代价的工程师"。
