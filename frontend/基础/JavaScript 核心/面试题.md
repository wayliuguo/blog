# 模块面试题 · JavaScript 核心

## 1. 数据类型与变量

### Q1（1.6）｜ `==` 与 `===` 的区别？类型转换有哪些坑？

- **判断**：`===` 不转类型、`==` 先做类型转换再比较；业务代码一律用 `===`。
- **展开**：`==` 的陷阱——`null == undefined` 为 true、`'0' == 0` 为 true、`[] == false` 为 true（先转字符串再转数字）；`+` 优先字符串拼接（`'1' + 2 = '12'`）、无 `+` 的运算符才转数字（`'5' - 2 = 3`）。
- **边界**：`==` 唯一合理用法是 `x == null`（同时判 null 与 undefined），团队规范通常禁止其余用法。

### Q2（1.4）｜ 数据类型有哪些？怎么准确判断类型？

- **判断**：7 种原始类型（string/number/boolean/null/undefined/symbol/bigint）+ 对象类型；最可靠判断用 `Object.prototype.toString.call`。
- **展开**：

```
typeof             基本类型；null 返回 'object'（历史 Bug）、function 返回 'function'
instanceof         对象与构造器沿原型链；基本类型恒 false、跨 realm 失效
constructor        经构造器属性；null/undefined 没有、原型被重写时失真
toString.call      返回 [object Array] 精确标签，能区分所有内置类型（最可靠）
```

- **边界**：`Array.isArray` 更轻、对跨 iframe 数组仍可靠；`instanceof` 判断基本类型恒 false（`1 instanceof Number`）且受跨 realm 影响。

### Q3（1.3）｜ `var` / `let` / `const` 的区别？暂时性死区是什么？

- **判断**：`var` 函数级作用域且可重复声明，`let`/`const` 块级作用域且不可重复声明；`const` 锁的是绑定关系不是值。
- **展开**：`var` 提升为 undefined；`let`/`const` 也存在提升但被 TDZ 保护——声明前访问直接 `ReferenceError`；`const` 锁绑定关系、不锁值。
- **边界**：`const a = {x:1}; a.x = 2` 合法；`for (var i..)` 回调全拿最终值，`for (let i..)` 每次迭代独立绑定各得 0 1 2。

### Q4（1.7）｜ `0.1 + 0.2 !== 0.3` 为什么？怎么处理浮点精度？

- **判断**：十进制小数无法用二进制有限位精确表示，IEEE 754 双精度的舍入在运算中放大成误差。
- **展开**：`0.1`/`0.2` 的二进制是无限循环小数，Number 只能存 53 位有效尾数，误差叠加得到 `0.30000000000000004`。
- **边界**：工程解法——用整数运算（元转分）、`Math.abs(a+b-c) < Number.EPSILON` 比较、`toFixed` 限显示位或引精确小数库。

## 2. 作用域与闭包

### Q1（2.4）｜ 什么是闭包？实际用来做什么、有什么坑？

- **判断**：闭包 = 函数 + 其词法作用域引用，让内层函数能访问外层函数的变量，即使外层已执行完。
- **展开**：外层函数执行完后，其词法环境因被内层函数引用而不被 GC 回收、变量被长期持有；应用有私有变量、柯里化、记忆缓存。
- **边界**：过度闭包让大对象常驻造成内存泄漏，用完置 null；循环里 `var` 捕获同一变量，用 `let`/IIFE 传参/`bind` 修复。

### Q2（2.5）｜ `this` 的指向规则？箭头函数为什么特殊？

- **判断**：`this` 在调用时决定，按优先级从高到低是 `new` > 显式绑定 > 方法调用 > 普通调用。
- **展开**：

```
普通调用  非严格 window、严格 undefined
方法调用  obj.fn() → obj
显式绑定  call / apply / bind
new       以新对象为 this
```

箭头函数没有自己的 `this`、捕获定义时外层词法作用域的 `this`，不受 call/apply/bind/new 影响，且不能 `new`、没有 `arguments`。
- **边界**：把 `obj.fn` 单独取出来调用 `this` 就变回普通调用（非严格 window、严格 undefined）——输出题最常见陷阱；注意 `arguments` 是类数组，转真数组用 `Array.from`。

## 3. 原型与继承

### Q1（3）｜ 原型链与继承？`class`/`new`/`instanceof` 的本质？

- **判断**：对象通过 `[[Prototype]]` 链式查找属性，继承的本质是"沿链查找"；`class` 是构造函数的语法糖，`new` 做四件事、`instanceof` 沿链查 prototype。
- **展开**：`obj.__proto__ === Ctor.prototype`；`p.constructor` 沿链找；寄生组合继承（`Object.create(Parent.prototype)`）不重复调父构造、正是 `extends` 底层；`instanceof` 判断 `B.prototype` 是否在 `a` 的原型链上。
- **边界**：原型上共享引用型属性会被所有实例共享、链过长影响查找性能；`class` 声明有 TDZ 且不能直接调用、内部严格模式；`Object.create(null)` 的对象无原型、`instanceof` 恒 false。

## 4. 异步与事件循环

### Q1（4.5）｜ 事件循环中宏任务与微任务的执行顺序？

- **判断**：每轮先执行一个宏任务、再一次性清空整个微任务队列（含期间新增），然后才进入下一轮。
- **展开**：同步代码 → 微任务（`Promise.then`/`queueMicrotask`/`MutationObserver`）→ 宏任务（`setTimeout`/I/O）；微任务里再产生的微任务会继续执行完；渲染在宏任务之间。
- **佐证**：`console.log("A")` + `setTimeout` + `Promise.then` + `console.log("D")` → 输出 **A D C B**。
- **边界**：`requestAnimationFrame` 在渲染前执行；滥用微任务递归会饿死渲染与后续宏任务；`setTimeout(0)` 并不保证 0ms、受微任务插队与 4ms 最小嵌套延迟影响。

### Q2（4.2）｜ Promise 的状态机？`all` / `race` / `allSettled` 怎么选？

- **判断**：Promise 三态 pending → fulfilled/rejected，状态一经落定不可逆；选型看"一个失败怎么算"。
- **展开**：

```
all         全成功或首败即败（短路）——并行请求合并渲染
allSettled  永不 reject、等全部落定——批量上传部分失败也要结果
any         取首个成功、全败才 reject(AggregateError)——多兜底接口取最快
race        取首个落定（成败都算）——超时控制
```

`then` 返回新 Promise 实现链式、回调放 `queueMicrotask` 保证永远异步。
- **边界**：`all` 空数组立即 fulfilled；`race` 常用于超时控制；忘记 `catch` 产生 `unhandledrejection`；手写 `all` 用下标存结果保证顺序一致。

### Q3（4.4）｜ `async/await` 的原理？怎么并发执行互不依赖的任务？

- **判断**：`async/await` 是 Generator + Promise 的语法糖，本质还是事件循环里的异步回调；`async` 函数总返回 Promise。
- **展开**：`await` 把后续代码放进 `then` 回调、挂起当前 async 函数、不阻塞主线程；`for` 循环里逐个 `await` 是串行，互不依赖的任务应 `Promise.all([...])` 并发。
- **边界**：`await` 只挂起当前 async 函数后半段；忘了 `await` 拿到 Promise 对象、异常变 unhandledrejection；`try/catch` 只在 async 函数内有效。

### Q4（4.2）｜ 接口竞态怎么解决？请求标记位和取消怎么选？

- **判断**：用"请求标记位 + 最新一次生效"比取消更稳——旧响应回来直接丢弃，保证展示最新结果。
- **展开**：每次发起冲突请求前更新递增序号，响应回来比对当前序号、不一致则丢弃；标记位只丢结果不中断请求、改动最小。
- **边界**：取消（`AbortController`）关心带宽与后端 QPS、还省一次无用响应，但请求层要统一改造且必须 catch 掉 `AbortError`；"连续触发试算"这类只求结果正确的场景用标记位足够。

## 5. 内存管理与垃圾回收

### Q1（5）｜ 垃圾回收：标记清除、引用计数与内存泄漏场景？

- **判断**：V8 主用标记-清除（分代收集）、从根出发判可达性，引用计数因无法处理循环引用只是概念补充；泄漏多是"可达但不需要"的引用。
- **展开**：标记清除能穿透循环引用；新生代 Scavenge 半空间复制、多次存活晋升老生代（标记清除+标记整理）；增量/并发标记降低主线程停顿。
- **佐证**：

```
意外全局变量    未声明变量挂全局永不回收 → "use strict" 拦截
闭包固化大对象  闭包长期持有大对象 → 最小捕获 + 用完置空
事件监听未移除  removeEventListener 成对移除 / AbortController 批量取消
定时器未清理    setInterval 回调持续持有引用 → clearInterval / clearTimeout
分离 DOM        从文档摘除后仍持有引用的节点无法回收 → 置空引用或重建节点
```

- **边界**：`WeakMap`/`WeakSet` 键是弱引用不阻止回收，缓存用它们不会泄漏。

## 6. DOM 与浏览器 API

### Q1（6.4/6.5）｜ 事件流有哪几个阶段？`target` 与 `currentTarget` 的区别？事件委托怎么做？

- **判断**：一次事件按"捕获 → 目标 → 冒泡"三段传播；`target` 是事件真正发生在哪个元素上、全程不变，`currentTarget` 是当前正在执行监听器所绑定的元素。
- **展开**：`addEventListener` 默认注册冒泡阶段、`{ capture: true }` 改捕获；事件委托在容器挂一个监听器、用 `e.target.closest(sel)` 找目标项，动态节点不用重绑；focus/blur 不冒泡改用 focusin/focusout。
- **边界**：回调结束后 `currentTarget` 被置为 `null`；`stopPropagation` 会打断上层委托；`el.click()` 派发的合成事件 `isTrusted` 为 false（风控/埋点据此过滤）；高频滚动监听声明 `{ passive: true }` 才不阻塞滚动。

### Q2（6.7）｜ `IntersectionObserver` / `ResizeObserver` / `MutationObserver` 分别解决什么问题？

- **判断**：IO 管"元素进没进视口"、RO 管"元素自身尺寸变了"、MO 管"DOM 被改了"——三者把轮询换成变化驱动的回调。
- **展开**：IO 的 `rootMargin` 是扩大判定边界（目标在折叠线下 50px、底部外扩 100px 后 `isIntersecting` 翻 true），这正是懒加载/无限滚动提前量的原理；RO 盯内容盒、窗口没变也能感知容器被挤窄；MO 的回调走微任务队列、不依赖渲染帧。
- **边界**：IO/RO 回调依赖渲染帧、无头 `--dump-dom` 收不到（MO 照常收到）；RO 回调里再改被观察元素尺寸形成循环并打警告；只想触发一次记得 `unobserve()`。

### Q3（6.8）｜ `fetch` 什么时候才会 reject？超时和取消怎么写？

- **判断**：`fetch()` 只在网络层失败时 reject（断网、DNS 失败、连接被拒、CORS 被拒）；HTTP 的 4xx/5xx 是"成功拿到一个表示错误的响应"，必须自己判 `res.ok`/`res.status`。
- **展开**：`AbortSignal.timeout(ms)` 到点抛 `TimeoutError`、`controller.abort()` 抛 `AbortError`，两者都是真的掐断请求、属"我方主动取消"，不能当网络故障上报；结合并用 `AbortSignal.any([...])`。
- **边界**：响应体是流只能读一次，第二次 `res.json()`/`res.text()` 抛 `TypeError`；响应头受 CORS 约束、只有 `Access-Control-Expose-Headers` 放行的才拿得到。

### Q4（6.3）｜ 页面滚动 / 拖拽卡顿，怎么判断是不是强制同步布局？

- **判断**：先看循环里有没有"写一次就读一次几何量"——读 `offsetWidth` 等必须等布局算完才能返回，循环里每读一次就强制一次布局。
- **展开**：样式写入只标脏、读取几何量才 flush；500 元素实测读写交替 288~539ms、先读后写 2.8~9.6ms，差 40~115 倍。
- **边界**：会强制布局的是 `offset*`/`client*`/`scroll*`、`getBoundingClientRect()`、`getComputedStyle()`，而 `style.x =`/`classList.add()`/`appendChild()` 只标脏；对策——读写分离、读的结果缓存、写合批到 `requestAnimationFrame`（排 200 次只落 1 次）；动画只用 `transform`/`opacity`。

### Q5（6.7）｜ 无限滚动要在"快到底部"就预加载下一页，怎么实现？

- **判断**：用 `IntersectionObserver` 观察列表底部哨兵元素，靠 `rootMargin` 把判定边界下扩一屏——元素还没进视口就先触发加载；"加载中"标志挡住重复触发，出错时解除观察并给"重试"入口。
- **展开**：`rootMargin` 改的是判定边界而非元素位置，所以提前量在不改布局的前提下就能配出——目标在折叠线下 50px、边界下扩 100px 时 `isIntersecting` 已是 true。
- **边界**：不要用 `scroll`+`getBoundingClientRect()` 手算（每帧强制布局）；列表 DOM 持续追加让渲染与内存一起涨，超几百条改虚拟滚动；快速滑动时在途请求返回旧数据要配序号守卫或 `AbortController`；最后一页加载完 `unobserve()`。

### Q6（6）｜ 含 50+ 字段、带级联校验与实时试算的复杂表单卡顿，怎么优化？

- **判断**：把"计算"从"渲染"里拆出来——校验纯函数化、试算纯函数化、派生结果缓存，再解决输入防抖与竞态。
- **展开**：卡顿根因是每次输入都触发全量校验与试算、且结果驱动大量受控组件重渲染；纯函数 + 单向数据流让计算可单测、可缓存、可回归。
- **边界**：派生结果缓存要保证 key 覆盖全部输入要素，否则脏缓存；受控组件收敛到"需要实时受控"的字段；试算字段要即时、防抖只对非实时反馈字段用，长列表可虚拟滚动。

## 7. 手写实现与源码

### Q1（7.3）｜ 深浅拷贝的区别？怎么实现健壮的深拷贝？

- **判断**：浅拷贝只复制一层引用、共享内层对象，深拷贝递归复制全部层级；数据要独立才用深拷贝。
- **展开**：手写深拷贝用 `WeakMap` 记录"原对象→拷贝对象"防循环引用；`Date`/`RegExp` 有内部槽需单独 `new`；`Symbol` 键用 `Reflect.ownKeys` 才能取到。
- **边界**：`JSON.parse(JSON.stringify(x))` 丢 undefined/Symbol/函数、Date 变字符串、BigInt 报错、循环引用抛错；`structuredClone` 是原生替代但函数仍不支持。

### Q2（7.1）｜ `call` / `apply` / `bind` 的区别？怎么手写？

- **判断**：三者都显式绑定 `this`——`call` 参数逐个传、`apply` 以数组传、`bind` 返回新函数且 `this` 永久锁定、可继续传参。
- **展开**：手写 `call` 是把函数临时挂到 `thisArg` 上调（用 Symbol 做 key 防覆盖冲突、用完 delete）；`bind` 用闭包保存 `this` 与部分参数返回包装函数；`null`/`undefined` 指向全局、基本类型用 `Object()` 包装。
- **边界**：`bind` 返回的函数 `this` 已固化，后续 call/apply 无法再改（new 除外）；箭头函数无自己的 `this`，三者对它无效。

### Q3（7.5）｜ 防抖与节流的区别与实现？

- **判断**：防抖是"停止触发后等 N 秒再执行一次"（最后一次算数），节流是"固定间隔内最多执行一次"（定期执行）。
- **展开**：防抖每次触发 `clearTimeout` 重置倒计时；节流用时间戳或定时器做闸门——时间戳版首触即执行、定时器版保证末尾也执行。
- **边界**：防抖让"迟迟不执行"产生延迟感（搜索建议），节流可能丢弃尾部触发；两个实现都要保存 `this` 与 `...args`，否则丢上下文。
