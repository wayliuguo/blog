fetch：状态码、超时、取消、竞态

本页所有请求都打到配套的本地接口，所以看到的是真实网络行为，不是模拟。先启动服务：在 code 目录执行 npm start，再打开 http://localhost:5176/dom-fetch.html（直接双击本文件也会自动指向本地接口）。

① 基本用法与响应状态

fetch() 返回的 Promise 只代表"拿到响应"，res.ok / res.status 才代表业务成败。

② 4xx / 5xx 不会 reject

这是最常踩的坑：服务端返回 500，await fetch() 依然正常返回，只有 res.ok 是 false。

③ 超时

AbortSignal.timeout(ms) 是最省事的超时写法，超时抛出的错误类型是 TimeoutError。

④ 主动取消

AbortController.abort() 是真的掐断请求（抛出 AbortError），而不是"忽略结果"——后者只是不再处理返回值，网络与带宽照旧消耗。

⑤ 竞态

搜索建议是经典场景：先输入 a、再输入 ab，如果 a 的响应更慢，它会把 ab 的结果覆盖掉。两种守卫都写在本页代码里，探针会给出"最终显示的是哪个关键字"。

⑥ 与 XMLHttpRequest 对照

XHR 只有回调式 API、要自己包一层 Promise；fetch 原生返回 Promise、语义更干净，但少了上传进度与同步请求这些能力。
