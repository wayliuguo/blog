# 模块面试题 · Vue

> 按知识体系章节分组，章号与 `总结.md` 大纲一一对应；章内 Q 编号、每题标注所属知识域 `（N.N）`；每题以一句判断句打头，配"判 / 展 / 证 / 界"四槽作答。

## 1. Vue 核心基础

### Q1（1.1）｜ Vue3 与 Vue2 的核心差异？

- **判断**：三大差异——响应式换 Proxy、组合式 API、编译优化（更快更小）；另加 TypeScript 一等公民。
- **展开**：Vue2 用 `Object.defineProperty` 逐属性劫持，新增/删除属性不响应；Vue3 用 Proxy 整对象代理，天然拦截动态属性与数组索引；模板编译加 patchFlag 静态提升，diff 更省。
- **佐证**：
- **边界**：Vue3 仍是"响应式 + 模板编译 + 虚拟 DOM"架构不是重写，选项式 API 仍可用；选项式可平滑迁移、组合式进新组件是主体。

### Q2（1.1）｜ `data` 为什么必须是函数？

- **判断**：组件可复用、多个实例需要独立数据——`data` 写成函数每次实例化返回新对象；写成对象会让所有实例共享同一引用。
- **展开**：组件是"工厂"，`data()` 在每次实例化时执行、返回独立对象；对象字面量是单一引用，实例 A 改数据、实例 B 跟着变。
- **佐证**：
- **边界**：根组件 `createApp({...})` 只有一个实例、`data` 可以是对象；选项式下 `data` 写对象 Vue 会告警。

### Q3（1.6）｜ `v-if` 与 `v-show` 的区别？

- **判断**：`v-if` 条件不成立时不渲染节点（销毁/创建），`v-show` 始终渲染只是 `display: none`。
- **展开**：`v-if` 走"增删 DOM"，切换有重建成本、也触发销毁钩子；`v-show` 只切 display，代价是元素常驻。
- **佐证**：
- **边界**：高频切换用 `v-show`，低频/首屏不为真用 `v-if`（懒渲染省首屏）；`v-if` 与 `v-for` 同元素时 `v-if` 优先（编译告警，应拆开）。

### Q4（1.7）｜ `v-for` 为什么必须用 key？用 index 行不行？

- **判断**：key 是 diff 时识别节点身份的依据，让复用走"移动"而非"删除重建"；应使用稳定业务 id、不用 index。
- **展开**：列表数据重排/增删时靠 key 配对新旧节点；用 index 作 key 在中间插入时后续节点被错位复用，输入框状态错乱。
- **佐证**：
- **边界**：key 在兄弟间唯一即可；整组重排（拖拽排序）更依赖稳定且不变的 key。

### Q5（1.4）｜ computed 与 watch 的区别？

- **判断**：computed 是"派生值"（有缓存、自动追踪依赖），watch 是"副作用监听"（数据变化时执行逻辑）。
- **展开**：computed 惰性求值 + dirty 标记，依赖不变直接返回缓存；watch 显式监听源，变化回调可做请求/埋点/异步。
- **佐证**：
- **边界**：能用 computed 表达的不要用 watch（声明式优于命令式）；watch 默认浅监听，深对象要 `{ deep: true }`；computed 应保持纯、不修改数据。

### Q6（1.2）｜ Vue3 响应式原理？（为什么用 Proxy）

- **判断**：`reactive` 用 Proxy 拦截 get/set——get 时收集依赖（effect），set 时触发更新；`ref` 用对象包装 `.value`。
- **展开**：渲染函数作为 effect 执行，读取响应式属性即建立"属性 → effect"依赖；数据变化把 effect 加入调度队列（`queueJob`）在微任务批量执行。
- **佐证**：
- **边界**：深度递归代理有初始化成本，可用 `shallowReactive`/`shallowRef` 降级；Map/Set 走专用 handlers；Proxy 补齐 Vue2 "新增属性/数组下标不响应"的盲区。

### Q7（1.2）｜ 依赖收集到触发更新的完整链路？

- **判断**：effect 执行 → 读取属性 → 属性对应 dep 收集该 effect → 属性变化 → dep 触发 effect。
- **展开**：数据结构是 `targetMap: WeakMap<对象, Map<key, Set<effect>>>`；`ref` 的 `.value` 读写同样走 getter/setter；computed 是惰性 effect（缓存）、watch 是显式收集目标。
- **佐证**：
- **边界**：在 effect 外读取不收集；Vue2 用 `Vue.set` 解决"新增属性不响应"，Vue3 Proxy 下不存在此痛点。

### Q8（1.2）｜ 批量更新与 nextTick 的原理？

- **判断**：连续改数据只渲染一次——effect 触发进 `queueJob` 去重 + 微任务调度；nextTick 在本次批处理完成后执行回调、拿最新 DOM。
- **展开**：同一 effect 被多次触发只入队一次；渲染在微任务批量执行，当前宏任务内的所有修改合并到一次更新；`nextTick` 把回调排到同一批微任务之后、Vue3 返回 Promise 可 `await`。
- **佐证**：
- **边界**：`flushSync`（Vue3.5 起）可强制同步渲染但牺牲批处理收益；nextTick 保证"DOM 已更新"不是"布局已稳定"，读尺寸仍需等渲染完。

### Q9（1.2）｜ 编译优化：patchFlag / 静态提升 / Block Tree？

- **判断**：编译期标记动态节点（patchFlag），diff 只对比动态部分；静态子树提升出渲染函数；Block Tree 把动态子节点收成扁平数组。
- **展开**：模板编译把"哪些部分是动态的"编码进标志位（TEXT/CLASS/PROPS 等）；静态节点创建一次、重复复用；`v-for` 等动态结构用 Block 收集动态子节点、diff 直接遍历。
- **佐证**：
- **边界**：手写渲染函数没有编译优化收益——这是"模板优先"的原因之一。

### Q10（1.2）｜ Vue3 的 diff 为什么比 Vue2 快？

- **判断**：快在"对比范围更小"——编译期 patchFlag 缩小动态范围 + 静态提升 + 双端 diff 优化，而不是算法本身突破。
- **展开**：Vue2 全量 patch 整棵 vnode 树；Vue3 静态提升免重建、patchFlag 跳过静态比较、Block Tree 扁平遍历，同层 diff 做双端/最长递增子序列优化。
- **佐证**：
- **边界**："快"是相对静态内容多的模板；动态内容密集的列表提升有限，仍需虚拟滚动等按需优化。

### Q11（1.1）｜ 响应式数据在"大数据 + 复杂联动"场景怎么设计？（场景综合）

- **判断**：试算/派生逻辑用纯函数 + 单向数据流，响应式只负责视图层派生——可枚举、可单测、可复用、可回归。
- **展开**：纯函数"输入决定输出"无副作用，摆脱响应式依赖追踪的隐式耦合；视图只消费纯函数的输出（computed/ref 派生状态）。
- **佐证**：
- **边界**：纯函数要可缓存（相同输入直接取上次结果）；不要用 watch 链式改数据（命令式易失控），用派生式表达；并发场景用请求标记位保证最后一次生效。

## 2. Vue 组件

### Q12（2.5）｜ Vue 生命周期有哪些？组合式怎么用？

- **判断**：创建（setup/onBeforeMount/onMounted）、更新（onBeforeUpdate/onUpdated）、卸载（onBeforeUnmount/onUnmounted）三段，组合式用 `onXxx` 钩子注册。
- **展开**：`setup` 在组件实例创建前执行（拿不到 this）；`onMounted` 在 DOM 挂载后（可读 DOM/发请求）；`onUnmounted` 做清理（定时器、监听器、订阅）。
- **佐证**：
- **边界**：`onBeforeUnmount` 里必须清理副作用，否则内存泄漏；`onErrorCaptured` 捕获后代组件错误；`<script setup>` 无 beforeCreate/created、逻辑直接写顶层。

### Q13（2.2）｜ 组件通信方式怎么选？

- **判断**：props 下行、emit 上行、v-model 双向、provide/inject 跨层、Pinia 全局共享；就近选择、避免滥用。
- **展开**：单向数据流下 props 只读、emit 通知父级改数据；provide/inject 跨多层传递不经过中间层；`defineExpose` + ref 暴露子组件方法。
- **佐证**：
- **边界**：provide/inject 传 ref/reactive 才保持响应式；EventBus 难追踪是反模式，Vue3 用 Pinia（见 Q20）替代。

### Q14（2.2）｜ `v-model` 的本质？组件上怎么用？

- **判断**：`v-model` 是 `:modelValue` + `@update:modelValue` 的语法糖（表单元素上是 value + input）。
- **展开**：模板编译展开成 prop 绑定 + 事件监听；子组件用 `defineModel()`（Vue3.4+）或 `modelValue` + `update:modelValue` 声明双向绑定。
- **佐证**：
- **边界**：Vue3 支持多个 `v-model:title` / `v-model:age`；Vue2 的 `.sync` 在 Vue3 统一为多参数 v-model。

### Q15（2.2）｜ provide / inject 跨级通信要注意什么？

- **判断**：祖先 `provide('key', value)`、任意后代 `inject('key', default)` 免逐层传 props，适合深层嵌套共享。
- **展开**：数据沿组件树向下传递、不经过中间层；遵循单向数据流——后代只读不直接改祖先的状态。
- **佐证**：
- **边界**：不传 ref/reactive 时是非响应式透传（快照）；适合"主题、当前用户"这类全局只读数据，不适合频繁变动的业务状态。

### Q16（2.4）｜ 选项式与组合式 API 怎么取舍？

- **判断**：组合式按"逻辑"组织（相关代码聚在一起、可复用），选项式按"类型"组织（data/methods 分块）；新代码用组合式。
- **展开**：组合式靠函数作用域复用逻辑（自定义 Hook/composable）；选项式靠 mixin 复用，有命名冲突与来源不明问题。
- **佐证**：
- **边界**：组合式更灵活也更容易写乱，需分层规范约束（api/hooks/utils/views）；中小项目与简单组件用选项式更省事。

### Q17（2.3）｜ 插槽的三种类型？

- **判断**：默认插槽、具名插槽（父 `#name` 传内容）、作用域插槽（子向插槽传数据）三种，用于父向子"传模板/结构"。
- **展开**：无 name 的 `<slot>` 是默认插槽、可写兜底内容；`name` 命名多个插槽；作用域插槽用 `<slot name="item" :user="u">` 传数据、父用 `#item="{ user }"` 接收。
- **佐证**：
- **边界**：作用域插槽常用来做"列表项可定制"（如泛型列表把项渲染交给父组件），是组件复用兼容性的常见手段。

### Q18（2.2）｜ 一个表格+表单+列表组件，通信方式怎么定？（场景综合）

- **判断**：按"关系最近原则"逐层选——父传数据用 props、子通知父用 emit、组件内部可编辑用 v-model、跨多级只读配置用 provide/inject、跨页面共享登录态等全局状态才上 Pinia。
- **展开**：能用局部沟通解决的不要升级到全局 store，耦合面越小越易维护；表单受控改 v-model 双向、展示型列表用 props 下行 + 作用域插槽定制项。
- **佐证**：
- **边界**：别为单一入口频繁读写 store（过度设计）；事件穿透多层时先考虑状态提升到最近公共父组件，而非跨越整棵组件树。

## 3. 路由与状态

### Q19（3.1）｜ 路由 hash 与 history 模式？`$route` 与 `$router` 的区别？

- **判断**：hash 模式用 URL `#` 后内容路由、不发请求、免服务端配置；history 模式用 HTML5 History API、URL 美观但需要服务端回退到 `index.html`。
- **展开**：hash 变化不发请求、纯静态部署天然可用；history 用 `pushState`/`replaceState` 改地址，刷新/直达子路由时服务端要配回退（Nginx `try_files ... /index.html`）否则 404。
- **佐证**：
- **边界**：`$route` 是"当前路由信息"（path/query/params 等），`$router` 是"路由实例"（push/replace/back）；组合式对应 `useRoute()`/`useRouter()`。

### Q20（3.5）｜ 路由守卫有哪几类？登录鉴权怎么落？

- **判断**：全局（beforeEach/beforeResolve/afterEach）、路由级（beforeEnter）、组件内（onBeforeRouteUpdate/onBeforeRouteLeave）；登录鉴权主落在全局 `beforeEach`。
- **展开**：`beforeEach` 里 `next()` 放行、`next({ path: '/login', query: { redirect: to.fullPath } })` 重定向并记录来源；`afterEach` 无 next、设页面标题与埋点。
- **佐证**：
- **边界**：守卫时序为 beforeEach → 组件内 beforeRouteUpdate → beforeEnter → beforeResolve → afterEach；用 `name` 跳转比写死 path 更健壮（改 path 不受影响）。

### Q21（3.2）｜ 动态路由与嵌套路由？组件复用返回时要不要重拉数据？

- **判断**：`:id` 占位定义动态路由、`useRoute().params` 读取；嵌套路由用 `children` 子 path 不带 `/` 自动拼前缀、每级各需一个 `<router-view>` 出口。
- **展开**：动态参数 `?` 可选、`/:pathMatch(.*)*` 通配做 404 兜底；`/article/1 → /article/2` 时组件不会重建，需 watch `route` 或 `onBeforeRouteUpdate` 重拉数据。
- **佐证**：
- **边界**：嵌套路由空串 `path: ''` 表示访问父路径时渲染该子组件；"布局壳 + 子页面"模式适合后台管理系统。

### Q22（3.6）｜ Vuex 与 Pinia 的区别？解构为什么用 storeToRefs？

- **判断**：Pinia 是 Vue3 官方推荐新状态管理（取代 Vuex）——去 mutation、天然 TS、可变更新、store id 即命名空间；state/getters 解构必须用 `storeToRefs`。
- **展开**：同构图 Vuex 四件套 state/getters/mutations/actions，mutation 必须同步；Pinia 只有 state/getters/actions、action 内直接改 state、可 setup 风格；直接解构 `store.count` 失去响应性，`storeToRefs` 保住响应性，actions 是普通函数可直接解构。
- **佐证**：
- **边界**：Vuex4 可用于 Vue3 但生态已转向 Pinia，Vue2 老项目继续用 Vuex；actions 同步/异步皆可、可 `this.$patch` 批量更新。
