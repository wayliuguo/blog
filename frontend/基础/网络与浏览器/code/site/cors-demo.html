同源策略与 CORS：浏览器到底拦了什么

本页由 http://localhost:5177 提供，页面里所有请求都打到 http://localhost:5178——端口不同就是不同源，所以每一条结果都是浏览器真的按同源策略判定过的。

请务必通过 http://localhost:5177/cors-demo.html 打开；用 file:// 直接打开时页面的 Origin 是 null，同源判定与 CORS 行为都不一样，看到的结果没有参考价值。

怎么跑

在 code 目录下开两个终端（或两个后台进程）：

npm start      # 静态站点 -> http://localhost:5177/   （提供本页）
npm run api    # 另一个源 -> http://localhost:5178/   （提供 /api/data 与 /__log）

端口被占用时两个服务都会自动 +1（实际端口以启动日志为准）。本页加载时会自动探测 api-server 的实际端口， 也可以用 ?api=端口 手动指定。

实测结果

页面加载后自动依次跑完 8 组对照，结果写在下方的探针里。服务端一共收到几次请求、几次预检也会一并列出——被 CORS 拦下的那几次，服务端其实都正常收到并返回了，被拦的只是"把响应交给 JS"这一步。
