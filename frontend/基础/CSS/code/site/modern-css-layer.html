@layer：用「层」替代选择器优先级战争

下面几组元素都套了 .box，唯一变量是把规则放进了哪个层。页面尾部的探针会把浏览器真正生效的计算值打出来——这就是结论的佐证。

① 层序决定胜负，源码位置不算数

层序声明为 @layer reset, components, utilities;，而 utilities 的规则写在源码最前面。三条规则同一选择器， utilities 最后声明，所以它赢。

我的文字颜色由 utilities 层决定

② 层比特异性更靠前

红色边框那条在 components 层里、选择器是 #layer-vs-spec .plain（一个 ID + 一个类）；绿色边框那条没进任何层、选择器只有一个 .plain。层先于特异性比较，所以低特异性的未分层规则赢。

我的边框颜色由层外那条低特异性规则决定

③ !important 把层序反转

reset（最早声明的层）里的 !important 最强，未分层的 !important 反而最弱——正好与普通声明相反。

我的文字颜色由最早层 reset 决定

④ 同一层内仍是源码顺序

两条规则同在 components 层，后写的青色赢过先写的紫色。

我的文字颜色由层内后写的规则决定
