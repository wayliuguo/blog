## 1. 选择器与层叠

### 1.1 CSS 引入方式

CSS 有四种引入方式，各有用处：

| 方式 | 写法 | 特点与适用 |
| ---- | ---- | ---- |
| 行内样式 | 标签 `style` 属性里 | 优先级最高（除 `!important` 外），结构与样式耦合，**不推荐生产使用** |
| 内嵌 `<style>` | `<head>` 里的 `<style>` 标签 | 适合单页测试、邮件模板等少量样式 |
| 外链 `<link>` | `<link rel="stylesheet" href="a.css">` | 样式与结构分离、可缓存可复用，**最推荐** |
| `@import` | CSS 文件内引入其他 CSS | 阻塞渲染且多一次 HTTP 请求，生产环境尽量避免 |**

对比 `link` 与 `@import`：

```
link(推荐)   HTML标签、与页面并行下载、不阻塞渲染
@import      CSS内部导入、须等外层样式表解析完才下载、串行
             JS动态创建的 @import 会被浏览器忽略
```

### 1.2 选择器

选择器回答"命中哪些元素"。按能力分组：

- **基本选择器**：标签（命中面宽）、类（BEM 等规范的基础，推荐优先）、ID（权重过高且不可复用）、通配 `*`（重置用）。
- **属性选择器**：`[type="submit"]` 精确匹配，`^=` 以…开头、`$=` 以…结尾、`*=` 包含、`~=` 匹配空格分隔的单词。
- **伪类 vs 伪元素**：

```
伪类 :hover :nth-child    改状态，单冒号
伪元素 ::before ::after  造元素，双冒号
```

- **组合器**：空格（后代）、`>`（子）、`+`（相邻兄弟）、`~`（通用兄弟）。

### 1.3 层叠机制与优先级

多条声明命中同一元素时，"谁赢"按**层叠四层判定**依次过滤：

```
!important        带 !important 的最优先（破坏可维护性，慎用）
来源              用户 !important > 作者 !important > 作者普通 > 用户普通 > 浏览器默认
优先级权重        内联 > ID > 类/伪类/属性 > 标签/伪元素（四位比较、不进位）
源码顺序          权重相同时，后出现覆盖先出现
```

权重近似四位数比较、**不产生进位**：一个类（0,0,1,0）永远压不过一个 ID（0,1,0,0），十个类也不如一个 ID。

### 1.4 继承

- **可继承**：文字类属性（`color`/`font-size`/`font-family`/`line-height`/`text-align` 等）。
- **不可继承**：盒子类属性（`width`/`height`/`margin`/`padding`/`border`/`position`/`display` 等）。
- **控制关键字**：`inherit` 强制继承、`initial` 用浏览器默认值、`unset` 可继承属性=inherit、否则=initial。
- **应用**：在 `body` 或 `:root` 上统一设置字体/颜色，子孙自动继承。

## 2. 盒模型与布局基础

### 2.1 盒模型

每个元素都长成四层盒子：

```
margin    外边距：清除相邻间距，不算盒子尺寸
  └ border     边框
     └ padding     内边距：内容与边框的距离
        └ content     内容区，由 width / height 决定
```

两种盒模型的差异是 **`width` 是否包含 padding/border**：

| 模型 | width 含义 | 后果 | 建议 |
| ---- | ---- | ---- | ---- |
| `content-box`（标准） | 只算 content 宽 | padding/border 会**撑爆**设定宽度 | 不推荐 |
| `border-box`（怪异/IE） | 即最终总宽，content 被压缩 | 百分比与 flex 分配可预期 | 全局 `*{box-sizing:border-box}` |

**`width: 100%` vs `auto`**：`100%` 的 content 等于父级 content、加 padding 易溢出；`auto` 让 border+padding+content 之和填满父级 content、**不溢出**，是块级默认。

### 2.2 单位

| 单位 | 相对基准 | 适用 |
| ---- | ---- | ---- |
| `px` | 绝对单位 | 固定最直观，屏幕端最常用 |
| `em` | 当前元素字体大小，**会嵌套累积** | 局部组件内部 |
| `rem` | 根元素 `<html>` 字体 | 全局统一，移动端适配主角 |
| `vw` / `vh` | 视口宽/高的 1% | 全屏/半屏布局方便；注意移动端 `100vh` 受地址栏影响可能偏大 |
| `%` | 父元素内容区 | 宽高比例 |

### 2.3 margin 与 BFC

**margin 两个坑**：

- **margin 合并**：垂直方向相邻的两个 margin **不相加、取较大值**（水平方向不合并）。
- **父子 margin 塌陷**：块级父元素无 padding/border 且未触发 BFC 时，子元素 `margin-top` 冲出父元素。
- **解决**：父级 padding/border、`overflow: hidden`、`display: flow-root`。

**BFC（块格式化上下文）**：页面上一块独立渲染区域，内部与外部布局**互不干扰**。

```
触发方式  overflow: hidden(常用) / display: flow-root / flex / grid
          absolute / fixed / sticky / float
用途      清除浮动包住子元素、防父子 margin 塌陷、两列自适应（主列不与浮动重叠、自动占满剩余宽）
```

## 3. 布局

### 3.1 文档流与定位

文档流（Normal Flow）：块级元素自上而下、行内元素从左到右排布。`position` 决定元素如何脱离/留在流中：

| 取值 | 相对谁 | 是否脱离文档流 |
| ---- | ---- | ---- |
| `static`（默认） | 不定位 | 否 |
| `relative` | 相对自身原本位置偏移 | 否（仍占位） |
| `absolute` | 最近的非 static 祖先（没有则相对 body/视口） | 是 |
| `fixed` | 相对浏览器视口 | 是 |
| `sticky` | 滚动吸附（占位，滚到_edge 吸附） | 否 |

**注意**：祖先有 `transform`/`filter` 时，`fixed` 的参照会从视口变成该祖先（表现等同 absolute）。

### 3.2 隐藏元素的方法

四种"看不见"的差异在**是否占位、是否可交互、走哪条渲染路径**：

| 方式 | 占位 | 可交互 | 渲染路径 | 备注 |
| ---- | ---- | ---- | ---- | ---- |
| `display: none` | 否 | 否 | 触发回流 | 不参与布局 |
| `visibility: hidden` | 是 | 否 | 只重绘 | 子元素可单独 `visibility: visible` |
| `opacity: 0` | 是 | **是** | 合成层(性能最好) | 读屏器仍可能读出 |
| `clip-path` 裁剪 | 是 | 是 | — | 用于轮播"看不见的下一张" |

### 3.3 float 浮动

- **行为**：元素向左/右"飘"，**脱离文档流但文本会环绕它**，常用于图文混排。
- **父元素高度塌陷**：子元素 float 后不再占高度、父元素撑不起来。
- **清除浮动**：父元素触发 BFC（`overflow: hidden`）或 `::after + clear: both`（clearfix）。
- **现状**：已被 Flex/Grid 取代，仅图文环绕场景仍在使用。

### 3.4 Flex 一维布局

Flex 处理**单轴**（主轴 + 交叉轴）的排列问题。

```
主轴    由 flex-direction 决定（row / column / row-reverse / column-reverse）
justify-content   主轴对齐
align-items       交叉轴对齐
容器属性  flex-wrap(换行) / align-content(多行整体) / gap(子项间距)
```

**`flex` 简写 = `flex-grow` / `flex-shrink` / `flex-basis`**：

```
flex: 1            即 1 1 0%，均分剩余空间
flex: 0 0 200px    固定 200px 不缩放
```

项目属性：`order` 排列顺序（越小越靠前）、`align-self` 覆盖容器的 `align-items`。终极居中 = `justify-content: center` + `align-items: center`。

**陷阱**：flex 子项默认 `min-width: auto` 不收缩到内容以下，长文本会撑破布局，加 `min-width: 0` 恢复收缩。

### 3.5 Grid 二维布局

Grid 同时管**行和列**，擅长划分页面骨架。

- **定义行列**：`grid-template-columns` / `grid-template-rows`。
- **`fr` 与 `repeat()`**：`fr` 按份数分配剩余空间、`auto` 按内容自适应、`repeat(4, 1fr)` 简化重复、`repeat(auto-fill, minmax(120px, 1fr))` 响应式自动填充。
- **命名区域**：`grid-template-areas` 直接摆骨架（`"header header"…`）。
- **显式定位**：`grid-column: 1/3` 跨列、`grid-row` 占行。

### 3.6 经典布局与居中选型

- **两栏**：Flex "固定 + 自适应"（`flex: 0 0 200px` + `flex: 1`）。
- **三栏**：两侧固定 + 中间自适应。
- **圣杯 / 双飞翼**：核心是"中间 DOM 靠前 + 两侧固定 + 中间自适应"；圣杯用 padding + 负 margin，双飞翼在中间内部再包一层、用 margin 腾空间。
- **现代简化版**：Grid 一行实现（`grid-template-columns: 150px 1fr 200px` + `grid-template-areas`）。

**居中四方案**：

```
Flex            display:flex + justify/align center，通用推荐，性能最好
abs+margin:auto 需已知尺寸/定宽
abs+transform   translate(-50%,-50%)，不知宽高也可用
单行文字        line-height 等于高度 + text-align: center
性能排序        Flex > transform > margin:auto
```

**选型**：页面骨架用 Grid、局部行列用 Flex、图文环绕才用 float。

## 4. 响应式与移动端

### 4.1 viewport 视口

`viewport` 控制布局视口宽度，核心是 `width=device-width`：布局视口宽度 = 设备屏幕宽度，同时消除移动端 300ms 点击延迟。

| 字段 | 含义 |
| ---- | ---- |
| `initial-scale` | 初始缩放比（1:1） |
| `maximum-scale` / `minimum-scale` | 最大 / 最小缩放 |
| `user-scalable=no` | 禁止用户缩放（违反可访问性，慎用） |
| `viewport-fit=cover` | 适配刘海屏/全面屏，配合 `env(safe-area-inset-*)` 处理安全区 |

**三对视口**：

```
布局视口   CSS 布局用的坐标系，受 meta 控制
视觉视口   用户当前看到的区域
理想视口   width=device-width 时，布局视口 = 屏幕
```

### 4.2 媒体查询

- **语法**：`@media (min-width: 768px)` 视口 ≥768px 生效、`(max-width: 480px)` 小屏生效。
- **断点参考**：480（手机横屏/小屏）/ 768（平板）/ 992（桌面小屏）/ 1200（桌面大屏），不必死守、随设计走。
- **Mobile First**：默认写移动端样式、用 `min-width` 向上递进，大屏只覆盖小屏样式。
- **其他特性**：`prefers-color-scheme: dark` 深色模式、`orientation` 横竖屏、`min-resolution: 2dppx` 高清屏。

### 4.3 适配方案

| 方案 | 原理 | 评价 |
| ---- | ---- | ---- |
| 百分比 | `%` 相对父元素 | 思路简单，图片/字体等比不便 |
| 弹性 Flex | 靠比例与内容自适应 | 现代适配主力 |
| rem / flexible | 以设计稿为基准动态改根字号、全站等比 | 依赖 JS；rem 不等比字体有坑，逐渐被 vw 取代 |
| **vw** | `1vw` = 视口宽 1% | **当前主流**：无 JS、比重；大屏需 `max-width` 兜底，可用 `postcss-px-to-viewport` 自动转换 |

### 4.4 高清屏与 dpr

- **定义**：`dpr`（devicePixelRatio）= 物理像素 / 逻辑像素（CSS 像素）。
- **高清图**：dpr≥2 的屏需要 `@2x`/`@3x` 图或 SVG，避免发虚。
- **canvas 适配**：按 `1/dpr` 设物理宽高、再 `ctx.scale(dpr, dpr)` 绘制保持清晰。

### 4.5 移动端坑与最佳实践

```
300ms延迟   设 width=device-width 即可消除；FastClick 已过时
点击穿透     300ms 后补发的 click 落下层；用 tap 事件或加遮挡层
1px边框     transform: scale(0.5) 最常用(dpr=2 缩一半)；0.5px 兼容性不统一
点击高亮    -webkit-tap-highlight-color: transparent 移除系统样式
滚动白屏    -webkit-overflow-scrolling: touch / overscroll-behavior
iOS安全区   env(safe-area-inset-bottom) 适配刘海屏
图标/字体   用 iconfont/SVG 等比缩放、高清用 @2x、字号避免小于 12px
```

**实践建议**：布局用 Flex + Grid；尺寸缩放用 vw；图标用 iconfont/SVG 等比缩放；边框用 `transform: scale(0.5)`。

## 5. 动画与变换

### 5.1 transform 变换

`transform` 管**几何变换**（translate/scale/rotate/skew，2D/3D），不改变文档流占位，是性能最好的动效基础。

- **`translate`**：百分比相对元素自身尺寸（`translate(-50%,-50%)` 是居中技巧），3D 用 `translate3d`。
- **`scale`**：缩放，默认以元素中心为基准。
- **`rotate`**：旋转，`rotateY(180deg)` 配合透视做卡片翻转。
- **`skew`**：倾斜，模拟立体透视/装饰条。
- **组合顺序**：多个变换函数从右往左作用于元素局部坐标系。
- **`transform-origin`**：决定变换原点（默认 `50% 50%`），改原点让同样 rotate 呈现不同轨迹（开门效果）。
- **3D 透视**：`perspective` + `transform-style: preserve-3d`。

### 5.2 transition 过渡

`transition` 是"**被动**"过渡——属性值改变（`:hover`/类名增删/JS 修改）才触发。

- **四个子属性**：`transition-property` / `-duration`（**必填**）/ `-timing-function` / `-delay`。
- **可过渡范围**：只能过渡数值或可插值属性；`display`、`width/height: auto` 无法过渡。
- **高度展开技巧**：用 `max-height` 过渡（0 → 300px）或 `transform: scaleY`。
- **推荐属性**：`transform` 和 `opacity`（跳过布局/绘制、性能最好）；避免动 `width`/`height`/`top`/`left`。

### 5.3 animation 与 @keyframes

`animation` 是"**主动**"执行的多关键帧序列，定义好自动执行。

- **`@keyframes`**：百分比对应时间轴（`0%` 起点、`100%` 终点），也可用 `from`/`to`。
- **子属性**：`name`/`duration` 必填；`timing-function`/`delay`/`iteration-count`（`infinite` 无限循环）/`direction`（`alternate` 正反交替）/`fill-mode`/`play-state`。
- **`fill-mode`**：`none`（默认）/`forwards`（保留末帧）/`backwards`（延迟期先应用首帧）/`both`；**入场动画用 `both` 避免闪跳**。
- **与 JS 交互**：切换类名或 `animation-play-state: paused` 暂停/恢复，让动画逻辑留在 CSS 层。

### 5.4 性能铁律与 CSS/JS 选型

**渲染三环节**：layout（布局）→ paint（绘制）→ composite（合成）。

- 只动画 `transform` 和 `opacity`：跳过 layout/paint 直接走合成层、跑 GPU，动画流畅不卡。
- **`will-change`**：提前告诉浏览器提升合成层；按需添加、用完即移除，滥用消耗显存。
- **3D 触发提升**：`translateZ(0)`/`backface-visibility: hidden` 强制创建合成层（历史 hack，现在推荐按需用 `will-change`）。

**CSS vs JS 动画**：

```
选 CSS   简单过渡、hover 动效、入场动画、无限循环——代码量少、性能好、天然可退化
选 JS    需要暂停/seek/回放、物理模拟、滚动手势联动——WAAPI(element.animate()) 或 rAF
通用原则  无论哪种，坚持 transform/opacity 优先，避免动画中改 width/height/top/left
```

## 6. 命名规范与工程化

### 6.1 BEM 命名规范

**要解决的问题**：命名冲突（通用名互相覆盖却难察觉）、无从定位（看不出属于哪个组件/角色/状态）、覆写成本高（改一处影响全局）。

**BEM 三段式**：

```
Block(块)        独立可复用的组件，单个命名空间    card
Element(元素)    块内部组成，块__元素             card__title
Modifier(修饰符) 状态/变体，块--修饰符            card--highlighted
```

**关键约定**：

- **不写父级链**：块内元素不写中间元素（`card__title` 而非 `card__header__title`），避免过深嵌套。
- **修饰符挂基础类**：`card--highlighted` 不能脱离 `card` 单独存在，在基础类上做增量覆盖。
- **命名描述"是什么"**：`card--primary` 而非 `card--red`，避免颜色改动使类名失真。
- **JS 钩子解耦**：JS 用 `data-*` 或 `js-` 前缀选择，不依赖样式类名。
- **块的判断**：能否脱离当前上下文独立复用——能则为块，只在固定父级内存在则是父级的元素。

**Sass 写法**：`&__title` / `&--modifier` 让 BEM 更紧凑；`&__` 拼写易错时可直接写完整类名；超小一次性样式或已引入 Tailwind 的项目不必追求完整 BEM。

### 6.2 样式工程化选型

| 方案 | 隔离方式 | 特点 |
| ---- | ---- | ---- |
| 普通全局 CSS | 无 | 零构建、便于全局主题，但极易冲突 |
| CSS Module / scoped | 编译成哈希类名 | **组件级隔离，React/Vue 主流** |
| CSS-in-JS | 运行时生成（styled-components） | 动态主题强、有运行时开销 |
| Tailwind 原子化 | 工具类按需 JIT 生成 | 视觉实现极快、按需摇树，但 HTML 可读性下降 |

**选型考虑**：项目规模、团队熟悉度、构建链与框架、可维护性/性能取舍、主题与设计系统。**务实组合**：小项目用普通 CSS 或 Tailwind；组件库/中后台用 CSS Module + 简单 BEM；需要运行时主题用 CSS-in-JS 或叠加 CSS 变量。可混合使用，不是非此即彼。

## 7. 现代 CSS

### 7.1 层叠层 @layer

`@layer` 把层叠排序改为**"来源与重要性 → 层 → 特异性 → 源码顺序"**——层与层之间先比层序，同层之内才比特异性与源码顺序。

- **未分层 = 隐式的最后一层**：普通声明里未分层最强，这是渐进迁移能成立的原因。
- **`!important` 反转层序**：最早声明的层最强，未分层的 `!important` 最弱。
- **落地写法**：`@layer reset, vendor, components, utilities;` 写死在第一行，引入顺序不再敏感。

### 7.2 自定义属性与设计令牌

**与 Sass 变量的本质差别**：自定义属性是**运行时的真实属性**（可继承、可被 JS 与媒体/容器查询改写）；Sass 变量编译期就被替换掉。

```
兜底      var(--x, fallback)，名字写错也不会让整条声明作废
作用域    :root 是全局默认，子树重定义 = 组件级主题
@property 注册后可指定类型与是否继承；未注册的一律继承
```

**颜色令牌**：`color-mix()` 按比例混、`oklch()` 按感知亮度调——浅色与半透明色由主色算出来。

### 7.3 容器查询

- **参照物是容器宽度**：媒体查询看视口，容器查询看**组件自己被放多宽**。
- **使用前提**：容器声明 `container-type: inline-size`（可用 `container-name` 限定）；行内尺寸因此不再由内容决定，必须有确定宽度来源。
- **分工**：设备级决策用媒体查询，组件级适配用容器查询。

### 7.4 现代选择器与函数

- **`:is()` 带权、`:where()` 清零**：基础样式用 `:where()` 保证可覆盖，业务选择器用 `:is()` 缩短列表。
- **`:has()`**：容器按后代状态上样式，省掉一个 JS 状态类；选择器要收窄以控制检查成本。
- **`clamp()`**：`clamp(下限, 理想值, 上限)` 一个值写完三档，理想值用 `rem + vw` 混合才不破坏文字缩放。
- **`aspect-ratio`**：给一个方向就能锁比例，顺带预留空间、避免布局跳动。

### 7.5 动效无障碍与兼容性基线

- **`prefers-reduced-motion`**：降级不是全禁——把位移/缩放换成透明度或去掉，保留状态反馈。
- **可直接用**：`var()`、`:is()`/`:where()`、`clamp()`、`aspect-ratio`、`color-mix()`。
- **先确认**：`@layer`、`@container`、`:has()` 是 2022～2023 年才在三大内核凑齐，受监管受众用 `@supports selector(...)` 兜底。

## 8. 综合实战收口

### 8.1 能力映射与 Mobile First

一张响应式卡片落地页把前面各章能力串成闭环：

- **BEM 命名（§6.1）**：`feature__card--modifier` 承载卡片结构（`feature__title`/`feature--primary`）。
- **Grid + Flex（§3）**：3 列特性卡片网格 + 导航 Flex（`justify-content: space-between`）。
- **媒体查询（§4）**：断点自适应——桌面 3 列 → 平板 2 列 → 手机 1 列。
- **transform / animation（§5）**：悬停与入场动效。

**Mobile First 写法**：

```
默认移动端    grid-template-columns: 1fr
向上递进      min-width: 600px 两列、min-width: 900px 三列
大屏只覆盖    断点内只改列数，不动小屏样式
```

### 8.2 动效落地与验收四查

- **入场**：`animation ... both` 保留末帧避免闪跳（`@keyframes rise` 从下方浮现）。
- **悬停**：`transform: translateY(-4px)` + box-shadow，走合成层流畅不卡。

**验收四查**：

```
断点自适应  拖动窗口 1/2/3 列切换、内容不溢出
悬停平滑    卡片"上浮 + 阴影"流畅不卡顿
入场浮现    加载时卡片从下方依次浮现
类名规范    遵循 block__element--modifier，改一处不影响他处
```
