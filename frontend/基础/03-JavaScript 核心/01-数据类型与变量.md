# 数据类型与变量

## 一、JavaScript 语言背景

JavaScript（简称 JS）诞生于 1995 年，最初由 Brendan Eich 在 10 天内设计出来，用于在浏览器端实现简单的交互。如今它早已不局限于浏览器，Node.js 让它能够运行在服务端，Tauri / Electron 让它能够构建桌面应用，React Native / 微信小程序让它渗透到移动端。

需要区分几个名字：

- **JavaScript**：由 ECMAScript 语言规范 + 浏览器/宿主提供的额外 API（DOM、BOM、fetch 等）组成。
- **ECMAScript（ES）**：语言的核心规范，由 ECMA-262 定义。ES6 也常被称为 ES2015，是一次里程碑式的大更新。
- **JS 的运行时**：浏览器中的 V8、Node.js 中的 Libuv 事件循环等，负责真正把代码跑起来。

JavaScript 是一门**动态类型**、**弱类型**、**基于原型**的脚本语言。所谓"动态类型"是指变量本身的类型在运行时才确定、且可以随时改变；"弱类型"是指不同类型的值之间可以自由进行隐式转换。

在开始学习细节之前，首先要建立起"**一切皆对象——但又不止是对象**"的印象：JS 的数据分为基本类型与引用类型两大类，二者在内存、比较、赋值上的行为完全不同。

## 二、基本数据类型（原始类型）

在 ES10（ES2019）之后，JavaScript 共有 **7 种基本数据类型**。基本数据类型的值在内存中占用固定大小，保存的是值本身，因此也叫**值类型**。

### 1. undefined

表示"未定义"。当声明了变量但未赋值时，其值就是 `undefined`。

```js
let a;
console.log(a); // undefined

// 访问对象上不存在的属性
const obj = {};
console.log(obj.name); // undefined

// 函数没有显式 return 时，返回 undefined
function foo() {}
console.log(foo()); // undefined
```

注意：**undefined 是全局对象上的一个全局属性**，不过在运行时基本不会被篡改。判断一个变量是否为 `undefined`，最稳妥的做法是 `typeof`：

```js
typeof a === "undefined"; // 即使 a 未声明也不会报错
```

### 2. Null

表示"空值 / 空对象引用"。语义上通常用于主动把某个变量置空，表示"这里没有东西了"。

```js
let user = null;
console.log(user); // null
```

一个著名的历史 Bug：`typeof null` 返回的是 `"object"` 而不是 `"null"`。这是 ES 规范第一版实现时留下的问题，因为规范已经确定且被广泛实现，至今无法修复。

```js
console.log(typeof null); // "object"
```

要注意 `undefined` 与 `null` 的区别：

- 语义：`undefined` 是"未定义"，`null` 是"显式置空"。
- 类型检测：`typeof undefined` 为 `"undefined"`，`typeof null` 为 `"object"`。
- 相等比较：二者松散相等（`==`）为 `true`，严格相等（`===`）为 `false`。

```js
console.log(undefined == null); // true
console.log(undefined === null); // false
```

### 3. Boolean

布尔值，只有 `true` 和 `false` 两个取值，通常用于条件判断和逻辑运算。

```js
let isLogin = true;
let isEmpty = false;
```

在条件判断场景中，会被隐式转化为布尔值的"假值"（falsy value）有：`false`、`0`、`-0`、`0n`、`""`、`null`、`undefined`、`NaN`。除此之外的几乎所有值都被视为"真值"（truthy），包括：

```js
Boolean(0);            // false
Boolean("");           // false
Boolean(null);         // false
Boolean(undefined);    // false
Boolean(NaN);          // false

Boolean("0");          // true  （非空字符串，即使内容是 "0"）
Boolean([]);           // true  （空数组是真值）
Boolean({});           // true  （空对象是真值）
```

记住这个经验法则：**"空的基本值"是假值，"非空的对象/数组"是真值**。

### 4. Number

数值类型，采用 IEEE 754 双精度浮点数标准存储。它既能表示整数，也能表示小数、正负无穷大、NaN 等。

```js
let num = 42;
let price = 3.14;
let big = 1e10;     // 科学计数法，1 * 10^10
let hex = 0xff;     // 十六进制，255
let oct = 0o17;     // 八进制，15
let bin = 0b1010;   // 二进制，10
```

Number 类型还有几个特殊值：

- `Infinity` / `-Infinity`：正负无穷大，运算结果溢出时出现。
- `NaN`（Not a Number）：表示"不是一个合法的数值"，例如把字符串转成数字失败的产物。

```js
console.log(1 / 0);      // Infinity
console.log(-1 / 0);     // -Infinity
console.log(+"abc");     // NaN
```

IEEE 754 双精度浮点数的有效位数约为 53 位（能安全表示的整数范围是 `Number.MAX_SAFE_INTEGER`，即 `2^53 - 1`），超出后会丢失精度，这也是大整数需要用 BigInt 的原因。

### 5. String

字符串类型，表示一段 Unicode 文本。创建方式有三种：

```js
let s1 = "double quote";
let s2 = 'single quote';
let s3 = `template literal`; // 模板字符串，支持插值 ${}
const name = "张三";
console.log(`你好，${name}`); // 你好，张三
```

在 ES6 之前没有真正的多行字符串，模板字符串（反引号）解决了这个问题，也带来了字符串插值能力。

### 6. Symbol

ES6 新增的原始类型，用于生成**唯一且不可变**的标识符。即使每次创建时传入相同的描述，两个 Symbol 也不相等。

```js
const s1 = Symbol("key");
const s2 = Symbol("key");
console.log(s1 === s2); // false

// 作为对象的属性键，可以避免属性名冲突
const obj = {
  [s1]: "这是 symbol 属性",
};
console.log(obj[s1]); // 这是 symbol 属性
console.log(Object.keys(obj)); // []，普通枚举拿不到 symbol 键
```

注意：用 `new Symbol()` 会抛错，Symbol 只能直接调用。Symbol 常用于实现"私有属性"、定义自定义迭代器（`Symbol.iterator`）或防止键名冲突。

### 7. BigInt

ES2020 新增，用于表示超过 `Number.MAX_SAFE_INTEGER` 的大整数。写法是在整数后面加 `n`，或用构造函数创建。

```js
const big1 = 9007199254740993n;
const big2 = BigInt(9007199254740993);
console.log(typeof big1); // "bigint"
console.log(big1);        // 9007199254740993n

// 注意：BigInt 不能与普通 Number 直接混合运算
// console.log(big1 + 1); // TypeError！需要 1n
console.log(big1 + 1n);   // 9007199254740994n
```

### 基本类型的存储方式（栈 Stack）

基本类型的值以**值拷贝**的方式存储在内存的栈（Stack）区，栈的特点是先进后出、读写速度快。当把一个基本类型的值赋给新变量时，是复制了一份值，两个变量完全独立。

```js
let a = 10;
let b = a;   // 拷贝值
b = 20;
console.log(a); // 10，a 不受影响
```

## 三、引用数据类型（Object / Array / Function 等）

除 7 种基本类型外，其余全部是**引用类型**，本质上都是 `Object` 的某种变体：

```js
const obj = {};          // 普通对象
const arr = [];          // 数组
function fn() {}         // 函数
const date = new Date(); // 日期
const regexp = /a/;      // 正则
const map = new Map();   // 映射
```

引用类型保存在内存的堆（Heap）区，变量中保存的是**堆地址（引用）**，而不是对象本身。栈中的变量指向堆中的真实数据。

### 引用类型的存储方式（堆 Heap + 栈引用）

```js
const obj1 = { name: "张三" };
const obj2 = obj1;   // 拷贝的是引用（地址），不是对象本身
obj2.name = "李四";
console.log(obj1.name); // "李四"，两者指向同一对象
```

上面的例子说明：赋值时复制的是**栈上的引用**，`obj1` 和 `obj2` 指向堆中同一个对象，因此改其中一个会影响另一个。

如果要真正拷贝一个对象，需要深拷贝或浅拷贝：

```js
// 浅拷贝：只拷贝第一层
const obj3 = { ...obj1 };
const obj4 = Object.assign({}, obj1);

// 深拷贝：结构递归拷贝（JSON 方式有局限，如丢失函数/undefined）
const obj5 = JSON.parse(JSON.stringify(obj1));
```

### 基本类型 vs 引用类型对比

| 对比项 | 基本类型 | 引用类型 |
| ------ | -------- | -------- |
| 存储位置 | 栈上存值本身 | 栈上存引用，堆上存对象 |
| 变量赋值 | 拷贝值，互不影响 | 拷贝引用，共享对象 |
| `===` 比较 | 比较值是否相等 | 比较引用（是否同一对象） |
| 数量 | 7 种 | 除 7 种外全部都是 |
| 是否可变 | 不可变（重新赋值） | 可变（可改属性） |

```js
// 引用类型比较的是引用地址
console.log({} === {});   // false，两个不同的对象
console.log([] === []);   // false
const same = {};
console.log(same === same); // true，同一个引用
```

## 四、变量

变量是"给值起个名字"。用 `var`、`let`、`const` 声明：

```js
var a = 1;      // 早期写法，有函数作用域和变量提升的问题
let b = 2;      // 块级作用域，可重新赋值
const c = 3;    // 块级作用域，声明后不可重新赋值（但对象内部属性可改）
```

- `const` 声明的是"绑定关系"不可变，而不是值不可变。`const obj = {}` 之后仍可以 `obj.x = 1`。
- `let` / `const` 具有块级作用域，且存在"暂时性死区（TDZ）"，详见下一章《作用域与闭包》。

```js
const person = { name: "张三" };
person.name = "李四"; // 允许，改的是属性
// person = {};       // 报错，不能重新绑定
```

## 五、类型检测的四种方式

### 1. typeof

最常用的操作符，返回一个表示类型的字符串。适合检测**基本类型**，但对引用类型几乎无区分度。

```js
typeof 42;            // "number"
typeof "hi";          // "string"
typeof true;          // "boolean"
typeof undefined;     // "undefined"
typeof null;          // "object"  ← 历史 Bug
typeof Symbol();      // "symbol"
typeof 1n;            // "bigint"
typeof {};            // "object"
typeof [];            // "object"
typeof function(){};  // "function"
```

注意两点：
- `typeof null` 返回 `"object"`。
- `typeof` 对**未声明变量**也不报错，返回 `"undefined"`，常用于安全检测。

### 2. instanceof

用于检测某个对象是否属于某构造函数（在原型链上）。适合检测引用类型在其原型链上的关系。

```js
[] instanceof Array;        // true
[] instanceof Object;       // true，数组也是对象
new Date() instanceof Date; // true
```

局限：无法检测基本类型（`1 instanceof Number` 为 `false`），且跨 iframe / 全局环境时可能失效。

### 3. constructor

通过属性访问构造函数来判断：

```js
"ab".constructor === String; // true
[].constructor === Array;    // true
(42).constructor === Number; // true
true.constructor === Boolean; // true
```

局限：`null` 和 `undefined` 没有 `constructor`；且当原型被重写时结果会失真。

### 4. Object.prototype.toString

最可靠的检测方案，利用 `Object.prototype.toString` 会返回 `[object 类型]` 的特性。它能区分所有内置类型。

```js
Object.prototype.toString.call(42);        // "[object Number]"
Object.prototype.toString.call("a");       // "[object String]"
Object.prototype.toString.call(true);      // "[object Boolean]"
Object.prototype.toString.call(undefined); // "[object Undefined]"
Object.prototype.toString.call(null);      // "[object Null]"
Object.prototype.toString.call({});        // "[object Object]"
Object.prototype.toString.call([]);        // "[object Array]"
Object.prototype.toString.call(function(){}); // "[object Function]"
Object.prototype.toString.call(new Date());   // "[object Date]"
Object.prototype.toString.call(/a/);          // "[object RegExp]"
```

因此可以封装一个通用的类型判断函数：

```js
function getType(value) {
  return Object.prototype.toString.call(value).slice(8, -1);
}

getType([]);  // "Array"
getType({});  // "Object"
getType(null); // "Null"
```

在实际工作中常把 `typeof`（快速判断基本类型）与 `Object.prototype.toString`（精确判断引用类型）结合使用。

### 5. 包装类型：为什么基本类型能调方法

`"abc".length` 能工作，是因为访问属性/方法时，JS 引擎临时把基本类型包装成对应的**包装对象**（`String` / `Number` / `Boolean`），用完即销毁：

```js
"abc".length;                    // 3 —— 临时包装成 String 对象
(42).toFixed(2);                 // "42.00" —— 临时包装成 Number 对象
"abc".charAt(0);                 // "a"
```

`new String("abc")` 显式创建的包装对象是**对象**，`typeof` 结果是 `"object"`，与字面量（`"abc"`）行为不同——实战中**不要**用 `new` 包装基本类型。

### 6. 空对象判断与 Object.is

**判断空对象**（无自有可枚举属性）：

```js
const isEmpty = (obj) =>
  Object.keys(obj).length === 0 && obj.constructor === Object;
isEmpty({});          // true
isEmpty({ a: 1 });    // false
```

**`Object.is` 与 `===` 的区别**：`Object.is` 是"更严格的 `===`"——行为基本一致，唯一区别是能区分 `+0` 与 `-0`（`Object.is(-0, 0) === false`），且 `NaN` 等于自身（`Object.is(NaN, NaN) === true`）。日常比较用 `===` 即可，`Object.is` 用于精确判等（如 `Array.prototype.includes` 底层语义）。

## 六、类型转换

### 1. 显式转换

程序员主动调用转换方法。

```js
// 转字符串
String(123);   // "123"
123..toString(); // "123"（注意点号写法）
(123).toString(); // "123"
String(true);  // "true"

// 转数字
Number("42");  // 42
Number("42px");// NaN
parseInt("42px"); // 42，解析到非数字为止，也可给进制 parseInt("10", 2)
parseFloat("3.14abc"); // 3.14

// 转布尔
Boolean(1);    // true
Boolean(0);    // false
Boolean("hi"); // true
```

### 2. 隐式转换

由 JS 引擎在运算符 / 条件判断中自动完成的转换，是很多"坑"的来源。

```js
// 字符串 + 数字 → 数字被转成字符串做拼接
"1" + 2;        // "12"
1 + "2";        // "12"
1 + 2 + "3";    // "33"（先算 1+2=3，再拼接）

// 无 + 号时，其他运算符会把字符串转数字
"5" - 2;        // 3
"5" * 2;        // 10
"10" / 2;       // 5

// 相等比较会触发隐式转换
"1" == 1;       // true（宽松相等：转数字后相等）
null == undefined; // true

// 关系比较
"10" > "9";    // false，字符串按首字符 ASCII 比较 '1' < '9'
10 > "9";      // true，转为数字比较
```

规则小结（宽松相等 `==` 的核心规则，推荐优先使用严格相等 `===` 规避这些坑）：

| 左右类型 | 转换行为 |
| -------- | -------- |
| 数字 vs 字符串 | 字符串转数字 |
| 布尔 vs 任意 | 布尔转数字（true→1，false→0） |
| 对象 vs 基本类型 | 对象调 `valueOf` / `toString` 转为基本类型 |
| `null` vs `undefined` | 二者相等 |

```js
[] == 0;      // true：[] 转 "" → "" 转 0
[1] == 1;     // true：[1] 转 "1" → "1" 转 1
![] == 0;     // true：![] 是 false，false 转 0
```

这组结果很反直觉，所以工程上**几乎总是使用 `===` 和 `!==`**，必要时才用 `==`（例如判断 `x == null` 等价于 `x === null || x === undefined`）。

## 七、NaN 特判

`NaN`（Not a Number）表示非数值，但它实际上属于 Number 类型。它的两个反直觉特性：

```js
console.log(typeof NaN);       // "number"
console.log(NaN === NaN);      // false，NaN 永不等于自身
```

判断是否为 `NaN` 有两种方式：

```js
isNaN("abc");   // true（有坑：会先隐式转数字，字符串 "abc" 转 NaN）
Number.isNaN("abc"); // false（推荐，不转换直接判断）
Number.isNaN(NaN);   // true
```

`isNaN`（全局函数）会先把参数转成数字再判断，导致 `isNaN("abc")` 为 `true`；而 `Number.isNaN` 不做转换，只有真·`NaN` 才返回 `true`。此外任何与 `NaN` 比较的结果都为 `false`，所以 `x !== x` 也可以判断 `x` 是否为 `NaN`。

## 八、0.1 + 0.2 的精度问题

这是 JS 最著名的面试题：`0.1 + 0.2 !== 0.3`。

```js
console.log(0.1 + 0.2); // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3); // false
```

### 原因

- 计算机内部用二进制表示数字。
- 十进制小数 `0.1` / `0.2` 无法用二进制**有限位**精确表示（类似十进制无法用有限位表示 `1/3`）。
- JS 的 Number 采用 IEEE 754 双精度（64 位），只能存 53 位有效尾数，多余的位被舍入，产生误差。
- 误差在运算时被放大，最终得到近似值 `0.30000000000000004`。

```js
// 十进制 0.1 对应的二进制是无限循环小数
// 0.1 = 0.0001100110011001100 ...（无限循环）
```

### 如何处理

日常业务中通常使用以下手段：

1. **用整数运算代替小数**：把"元"转成"分"等最小单位。
2. **使用定点小数显示的格式化**：

```js
// 保留特定位数再比较
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON; // true

// 或用 toFixed 决定显示位数
(0.1 + 0.2).toFixed(2); // "0.30"
```

3. **引入精确小数库**：如 `decimal.js`、`bignumber.js`。

```js
// 用整数分单位计算（推荐）
const priceInFen = 10;  // 0.1 元
const qty = 2;
console.log(priceInFen * qty); // 20 分 = 0.2 元
```

## 总结

- 数据类型与变量
  - 语言背景
    - JavaScript = ES 规范 + 宿主 API
    - 动态类型 / 弱类型 / 基于原型
    - 基本类型 vs 引用类型
  - 基本数据类型
    - `undefined`：未定义、`typeof` 安全检测
    - `null`：显式置空、`typeof null === "object"`
    - `Boolean`：falsy / truthy 规则
    - `Number`：IEEE 754 双精度、`Infinity` / `NaN`
    - `String`：引号与模板字符串
    - `Symbol`：唯一标识、私有属性键
    - `BigInt`：大整数、`n` 后缀
    - 栈存储：值拷贝
  - 引用类型
    - `Object` / `Array` / `Function` / `Date` / `RegExp` / `Map`
    - 堆存储 + 栈引用
    - 浅拷贝 vs 深拷贝
    - 基本类型 vs 引用类型对比
  - 变量
    - `var` / `let` / `const`
    - 块级作用域、TDZ
    - `const` 绑定不可变
  - 类型检测
    - `typeof`：基本类型、`typeof null` 历史 Bug
    - `instanceof`：原型链关系
    - `constructor`：原型重写会失真
    - `Object.prototype.toString`：最可靠、`getType` 封装
  - 类型转换
    - 显式转换：`String` / `Number` / `Boolean`、`parseInt` / `parseFloat`
    - 隐式转换：`+` 拼接、`==` 规则、`valueOf` / `toString`
    - 优先 `===`
  - `NaN` 特判
    - `typeof NaN === "number"`、`NaN !== NaN`
    - `isNaN` vs `Number.isNaN`
