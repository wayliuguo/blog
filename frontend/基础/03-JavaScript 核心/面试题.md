## 2. 重点题精答（五步法）

### Q1：事件循环中宏任务与微任务的执行顺序？

- **结论**：每轮先执行一个宏任务，再清空整个微任务队列，然后进入下一轮。
- **原理**：同步代码 → 微任务（Promise.then / queueMicrotask / MutationObserver）→ 宏任务（setTimeout / I/O / 渲染）。微任务里再产生的微任务会继续执行完。
- **场景**：`setTimeout(0)` 不一定立即执行，前面微任务会插队；React/Vue 的批量更新也基于微任务。
- **边界**：`requestAnimationFrame` 在渲染前；渲染时机在宏任务之间。
- **追问**：`queueMicrotask` 与 `Promise.then` 有区别吗？→ 机制相同，queueMicrotask 不产生 Promise 包装，更轻。

### Q2：闭包是什么？实际怎么用？

- **结论**：闭包 = 函数 + 其词法作用域引用，让内层函数能访问外层变量。
- **原理**：函数定义时捕获作用域链，即使外层执行结束，变量仍被引用存活。
- **场景**：模块化私有变量、防抖节流保存 timer、请求标记位保存"当前最新标记"（简历项目竞态方案）。
- **边界**：过度闭包会造成内存泄漏（变量常驻），用完置 null。
- **追问**：闭包里的变量是值拷贝还是引用？→ 引用同一变量，循环中经典陷阱 `var` + 闭包。

### Q3：原型链与继承？

- **结论**：对象通过 `[[Prototype]]` 链式查找属性，继承的本质是"沿链查找"。
- **原理**：`Object.create` 建链；`class extends` 是语法糖；`instanceof` 沿原型链找构造函数的 prototype。
- **场景**：组件基类、错误类继承、工具方法挂原型（Array.prototype 扩展需谨慎）。
- **边界**：链过长影响属性查找性能；共享引用型属性会被所有实例共享。
- **追问**：`A instanceof B` 判断的是什么？→ `A` 的原型链上是否存在 `B.prototype`。

### Q4：深拷贝的实现与边界？

- **结论**：JSON 深拷贝有先天缺陷，需手写处理边界。
- **原理**：`JSON.parse(JSON.stringify(x))` 丢失 undefined/Symbol/函数，且不支持循环引用、Date 变字符串、BigInt 报错。
- **场景**：递归遍历 + `WeakMap` 缓存防循环引用；分类型处理 Date/RegExp/Map/Set/Symbol/函数；`structuredClone` 是原生替代（但函数仍不支持）。
- **边界**：原型链不被保留；拷贝成本高，大对象慎用。
- **追问**：`structuredClone` 与手写的区别？→ 原生结构化克隆算法，性能好，但函数/类实例不可克隆。

### Q5：接口竞态怎么解决？（简历核心）

- **结论**：用"请求标记位 + 最新一次生效"，比取消请求更稳。
- **原理**：发起冲突请求前更新递增标记；响应回来比对当前标记，不一致直接丢弃。
- **场景**：用户快速切换分期数/计息方式并发触发试算，网络乱序会导致旧响应覆盖新结果。
- **边界**：为什么不用 AbortController？→ 取消要在请求层统一改造且容器内 fetch/XHR 行为不一致；标记位只丢弃结果不中断请求。
- **追问**：丢弃次数要埋点吗？→ 要，计入埋点观测切换频率与冗余请求规模。

### Q6：手写 `new` 的实现？

- **结论**：`new` 做了四件事：建对象 → 链原型 → 绑 this 执行 → 返回。
- **原理**：`obj = Object.create(ctor.prototype)`；`ret = ctor.call(obj, ...args)`；`ret` 是对象则返回 `ret`，否则返回 `obj`。
- **场景**：面试高频手写题，同时考察原型链理解。
- **边界**：构造函数显式返回原始值会被忽略，返回对象则覆盖。
- **追问**：箭头函数能 new 吗？→ 不能，无 prototype。

## 3. 追问链

1. "setTimeout 一定能延迟执行吗？" → 不保证，受宏任务队列与微任务插队影响，最小延迟 4ms（嵌套时）。
2. "内存泄漏有哪些场景？" → 全局变量、未清理的定时器/监听器、闭包长引用、分离 DOM。
3. "为什么上报用微任务？" → 当前宏任务后、渲染前执行，不阻塞主流程。
4. "`instanceof` 的原理？" → 沿原型链查找构造函数的 prototype。

## 4. 场景设计题

**场景：一个含 50+ 字段、带级联校验与实时试算的借款表单，提交与交互卡顿，怎么优化？**
- 答题骨架：校验拆成纯函数（可单测）→ 计算与视图解耦（纯函数 + 单向数据流）→ 派生结果缓存（相同输入直接取上次）→ 表单性能：受控组件收敛、按需渲染、防抖输入 → 竞态：请求标记位 → 大数据：虚拟滚动（长列表）。
- 加分点：呼应简历"金融要素级联流转"重构：要素（还款方式/计息方式/分期数/金额）→ 纯函数试算 → UI 只消费派生状态，可枚举、可单测、可复用、可回归。

## 5. 面试口径（简历项目如何表达）

- **项目证据**：`validation.ts`（校验纯函数）、`requestReport` 用 `queueMicrotask` 异步上报不阻塞渲染、接口竞态"请求标记位"方案、接口缓存（URL+入参为 key、TTL、时效性分级）。
- **表达句式**："借款页的金融要素流转是级联试算，我把它重构为纯函数 + 单向数据流——可枚举、可单测、可复用、可回归；并发试算用请求标记位保证最后一次请求生效。"
- **勿说**：不要把竞态方案说成 AbortController 或公共请求层拦截器——本项目是业务侧标记位实现。
