# 模块总结 · JavaScript 核心

## 知识主线

六篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 数据类型与变量（值是什么、存在哪、怎么判断）
        │  值/引用分清了，变量在哪些地方能看见、闭包为何能"记住"？
        ▼
02 作用域与闭包（变量在哪可见、怎么被持有）
        │  变量能被记住，对象之间怎么共享能力、new 出来的实例是什么关系？
        ▼
03 原型与继承（对象怎么沿原型链复用）  ★主轴
        │  对象/函数机制清楚了，单线程怎么同时处理一堆任务还不卡？
        ▼
04 异步编程与事件循环（单线程怎么并发、执行顺序怎么定）
        │  回调与 Promise 不断产生对象，不用了的内存谁来还、泄漏怎么来？
        ▼
05 内存管理与垃圾回收（对象生命周期、泄漏与检测）
        │  纸上原理都懂了，把 this/原型/拷贝/异步亲手实现一遍才算真懂
        ▼
06 手写实现与源码（全部机制的手写验证）
```

本模块的主轴是**原型链**（对象与函数之间的引用关系网络）——它是 JavaScript 区别于其它语言的核心机制：01 建立"值 vs 引用"的存储起点，02 讲作用域如何持有引用（闭包），03 讲对象如何沿原型链共享方法、`new`/`instanceof` 如何在链上工作；04 的 Promise 与回调建立在"函数也是对象、`this` 沿链解析"之上，05 的 GC 以引用可达性判定生死，06 把 `this`/原型链/拷贝/异步全部手写验证。整章回答"JavaScript 的对象世界从创建到回收如何运转"。

## 分篇知识点

### 01-数据类型与变量

- **值 vs 引用**：7 种基本类型（undefined/null/boolean/number/string/symbol/bigint）存栈按值拷贝；引用类型栈存地址、堆存对象，赋值拷贝引用共享对象、`===` 比较引用地址
- **假值清单**：false/0/-0/0n/""/null/undefined/NaN，其余几乎全真值——空数组、空对象都是真值
- **声明三兄弟**：`const` 锁的是绑定关系不是值（可改对象属性）；`let` 块级可重赋值；`var` 有提升与函数作用域问题；默认用 `const`、必要时 `let`、基本不用 `var`
- **类型检测四法**：`typeof` 管基本类型（`typeof null === "object"` 是历史 Bug）；`instanceof`/`constructor` 看原型关系；`Object.prototype.toString.call(x)` 最可靠、能区分所有内置类型
- **隐式转换的坑**：`"1" + 2 = "12"`、`"5" - 2 = 3`、`[] == 0` 为 true，工程上几乎总是用 `===`（只有 `x == null` 可酌情用）
- **NaN 与精度**：`NaN` 永不等于自身，判断用 `Number.isNaN`（全局 `isNaN` 会先转数字有坑）；`0.1 + 0.2 !== 0.3` 源于 IEEE 754 二进制无法精确表示，工程上用整数运算（元转分）或精确小数库

### 02-作用域与闭包

- **三种作用域**：全局 / 函数（`var`）/ 块级（`let`、`const`，以 `{}` 为界）；JS 是**词法作用域**——嵌套关系由书写位置决定，与调用位置无关
- **作用域链与执行上下文**：访问变量沿"当前 → 外层 → … → 全局"向上查找，找不到抛 `ReferenceError`；执行上下文按后进先出组成调用栈，无限递归会栈溢出
- **var/let/const 对比**：var 提升为 undefined 且可重复声明；let/const 有 TDZ（声明前访问抛 ReferenceError）；`for (var i...)` 回调全打 3、`for (let i...)` 打 0 1 2
- **闭包 = 内层函数 + 外层变量环境**：外层函数执行完其词法环境因被引用而不回收；应用有私有变量（银行账户）、柯里化、记忆缓存（memorize）
- **三个陷阱**：闭包长期持有大对象造成内存泄漏（用完置 null）、循环中 var 捕获同一变量（用 let/IIFE/bind 修复）、闭包里普通函数 `this` 丢失（用箭头函数）
- **IIFE**：创建独立作用域隔离变量，是 ES6 之前模块化的手段，也是修复 var 循环问题的经典写法

### 03-原型与继承

- **三角关系**：函数有 `prototype`、对象有 `__proto__`（指向构造它的函数的 prototype）、`prototype` 上的 `constructor` 指回函数形成闭环；读取原型推荐 `Object.getPrototypeOf`
- **原型链**：属性查找先自身、再沿 `__proto__` 逐级向上直到 `Object.prototype` 再到 null；`hasOwnProperty` 区分自身/继承属性
- **new 四步**：建空对象 → `Object.create(Ctor.prototype)` 接原型 → 以新对象为 this 执行构造函数 → 构造函数返回引用类型则用之、否则返回新对象
- **继承演进四代**：原型链继承（引用共享缺陷）→ 借用构造（无法复用原型方法）→ 组合继承（父构造调用两次、属性冗余）→ 寄生组合继承（`Object.create(Parent.prototype)`，最优，正是 ES6 `extends` 的底层）
- **class 是语法糖**：内部严格模式、方法不可枚举、声明有 TDZ 且必须 new；`extends + super` 本质是做完原型接线后再执行父构造
- **instanceof 原理**：`B.prototype` 是否出现在 `a` 的原型链上，可手写 while 循环沿 `Object.getPrototypeOf` 找；基本类型没有原型链，所以 `1 instanceof Number` 为 false

### 04-异步编程与事件循环

- **异步的本质**：单线程 JS 把耗时操作交给宿主（浏览器 Web API / Node libuv），就绪后回调压回主线程，避免慢任务卡死整个应用
- **Promise**：三态（pending/fulfilled/rejected）且不可逆；`then` 返回新 Promise 把回调地狱摊平成链；链上任一环抛错直达最近的 catch
- **静态方法分工**：`all` 全部成功才成功、任一失败立即失败；`allSettled` 永不 reject 收集 `{status, value|reason}`；`race` 最先落定者决定（超时控制）；`any` 第一个成功者决定、全败才 reject
- **async/await**：语法糖让异步像同步，async 总返回 Promise；互不依赖的任务要 `Promise.all` 并行而非顺序 await（2s 变 1s）；Generator 的 `yield` 是它的底层鼻祖（co 库思想）
- **事件循环口诀**：同步立即执行 → 当前宏任务结束一次性清空全部微任务（含新增，微任务能饿死渲染）→ UI 渲染/rAF → 下一个宏任务；经典输出 A D C B
- **浏览器 vs Node**：Node 有六个阶段；`process.nextTick` 优先级比 Promise 微任务还高；主模块里 `setImmediate` 与 `setTimeout(0)` 顺序不定、I/O 回调里 setImmediate 稳定先；setTimeout 非精确计时、动画用 rAF（后台自动暂停）、闲时任务用 requestIdleCallback

### 05-内存管理与垃圾回收

- **栈与堆**：栈存值类型值/局部变量/引用地址（函数结束自动释放），堆存对象本体；对象生命周期比函数作用域长，被引用就存活
- **两大策略**：标记清除（从根遍历可达对象，能处理循环引用，是现代 GC 基石）vs 引用计数（计数归零即回收，无法处理循环引用）；分代收集基于"短命对象高频回收"的经验规律
- **V8 分代**：新生代 Scavenge 半空间复制（From/To 交换，牺牲一半空间换吞吐，多次存活或空间不足则晋升）；老生代标记清除 + 标记整理（低频、防碎片）
- **降低停顿**：增量标记（拆小步骤穿插执行）、并发标记（后台线程）、惰性清理——"把想做的事拆小、挪到后台"
- **五类泄漏**：意外全局变量（`"use strict"` 拦截）、闭包固化大对象（最小捕获+置空）、事件监听未移除（`removeEventListener`/`AbortController`）、定时器未清理（生命周期结束 clear）、分离 DOM（置空引用）
- **检测与弱引用**：`performance.memory`/`process.memoryUsage()` 粗略观测；DevTools Memory 三招（Performance 曲线、Heap Snapshot 按 Retained Size 找大对象、Allocation instrumentation）；WeakMap/WeakSet 弱引用不阻止回收，适合缓存与对象私有数据

### 06-手写实现与源码

- **call/apply/bind**：谁调用 this 指向谁——把函数临时挂到 `thisArg` 上（用 Symbol 做 key 防冲突、用完 delete）；传 null/undefined 指向全局、基本类型用 `Object()` 包装
- **myNew**：`Object.create(Ctor.prototype)` 同时完成建对象+连原型；构造函数返回引用类型（对象/函数）才覆盖新对象，返回原始类型忽略
- **深拷贝**：WeakMap 记录"原对象 → 拷贝对象"处理循环引用；Date/RegExp 单独 `new`；Symbol 键必须用 `Reflect.ownKeys`（`for...in`/`Object.keys` 拿不到）
- **手写 Promise**：状态单向不可逆（PENDING 判断）；`then` 返回新 Promise 且回调放 `queueMicrotask` 保证异步时序；没传回调要补默认实现值穿透；`all` 用下标存结果保证输出顺序
- **防抖 vs 节流**：防抖是 `clearTimeout` 重置（最后一次生效，适合搜索/resize）；节流时间戳版首次立即执行、定时器版保证末尾也执行；两个实现都要保存 `this` 和 `...args`
- **EventBus 与函数式**：用对象而非数组存回调（按 callbackId 精确取消），once 用 `one${id}` 前缀标记、emit 时 `startsWith('one')` 删除；柯里化用 `fn.length` 判断参数收齐，compose 用 `reduceRight`、pipe 用 `reduce`
