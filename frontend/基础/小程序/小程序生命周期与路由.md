# 小程序生命周期与路由

小程序的生命周期是理解它"什么时候被创建、什么时候可见、什么时候销毁"的钥匙。它分三层：**应用生命周期**（整个小程序的启停）、**页面生命周期**（单个页面的进出）与**组件生命周期**（页面内组件的挂载卸载）。三层各管一段，共同决定了一次完整的"打开小程序 → 操作 → 退出"经历哪些回调。路由则回答"页面之间怎么跳"。

这篇文章按「应用 → 页面 → 组件 → 路由」的脉络展开。

## 一、应用生命周期

应用生命周期在小程序的入口文件 `app.js` 里通过 `App({...})` 注册，回调都挂在 App 构造器传入的对象上。

### 1. 六个核心钩子

| 钩子 | 触发时机 | 典型用途 |
| --- | --- | --- |
| `onLaunch` | 小程序初始化完成时触发，**全局只触发一次** | 初始化全局数据、检查登录态、更新版本 |
| `onShow` | 小程序启动，或从后台进入前台时触发 | 刷新数据、恢复页面状态 |
| `onHide` | 小程序从前台进入后台时触发 | 暂停任务、保存草稿、停止播放 |
| `onError` | 小程序发生脚本错误或 API 调用报错时触发 | 全局错误上报 |
| `onPageNotFound` | 要打开的页面不存在时触发 | 重定向到兜底页 |
| `onUnhandledRejection` | 小程序未处理的 Promise 拒绝时触发 | 兜底捕获异步异常 |

> 示意片段（无配套脚本）

```js
App({
  onLaunch(options) {
    // 小程序初始化，全局只执行一次
  },
  onShow(options) {
    // 小程序启动或从后台切回前台
  },
  onHide() {
    // 小程序切到后台
  },
  onError(msg) {
    console.error(msg)
  },
  globalData: {
    userInfo: null
  }
})
```

### 2. globalData：跨页面共享数据的"简单方案"

`App()` 里声明的 `globalData` 是所有页面都能读到的全局对象，通过 `getApp().globalData` 访问。适合放"全局只有一份、各页面都要读"的数据（登录态、配置项）。它的局限是**不响应式**——改了 globalData 页面不会自动更新，需要手动同步（或用事件通知页面刷新），所以只是简单场景的兜底，复杂状态还是交给页面自己的 store（如 mobx-miniprogram）管理。

## 二、页面生命周期

页面的生命周期钩子写在每个页面自己的 `Page({...})` 里，按固定顺序触发：

| 钩子 | 触发时机 | 典型用途 |
| --- | --- | --- |
| `onLoad` | 页面创建时执行，只触发一次 | **发请求取数据**、读取 `options` 参数 |
| `onShow` | 页面出现在前台时执行（可能多次） | 每次回到页面刷新数据 |
| `onReady` | 页面首次渲染完成后执行 | **获取页面元素**（`createSelectorQuery`） |
| `onHide` | 页面从前台变为后台时执行 | 终止任务：清定时器、停音乐 |
| `onUnload` | 页面销毁时执行 | 终止任务、释放资源 |

一次完整打开：`onLoad → onShow → onReady`；页面被盖住/切后台：`onHide`；再回来：`onShow`（不会再走 onLoad）。

> 示意片段（无配套脚本）

```js
Page({
  onLoad(options) {
    // 页面创建：取参数、拉数据
  },
  onShow() {
    // 每次回到前台：刷新
  },
  onReady() {
    // 首次渲染完：操作元素
  },
  onHide() {
    // 切后台：暂停任务
  },
  onUnload() {
    // 页面销毁：清理定时器
  }
})
```

> 对比：`onLoad` 只执行一次、适合初始化；`onShow` 可能执行多次、适合"回到页面就要更新"的场景（比如从详情页返回列表页刷新选中态）。

## 三、组件生命周期

自定义组件（`Component({...})`）有自己的生命周期，比页面更细：

| 钩子 | 触发时机 |
| --- | --- |
| `created` | 组件实例刚创建时，**此时还不能调用 `setData`** |
| `attached` | 组件实例进入页面节点树时 |
| `ready` | 组件在视图布局完成后执行 |
| `moved` | 组件实例被移动到节点树另一个位置时 |
| `detached` | 组件实例从页面节点移除时 |
| `error` | 每当组件方法抛出错误时执行 |

**为什么 `created` 里不能 `setData`？** `created` 时组件还不在页面节点树里，视图层没有对应的节点可以接收数据，`setData` 没有意义；数据初始化放到 `attached`（进入节点树、可以拿到组件所在页面的数据）更合适。`ready` 时视图已布局完成，此时才能 `createSelectorQuery` 获取组件内部节点。

## 四、页面路由

小程序页面跳转有五种 API，各自的适用面不同：

| API | 行为 | 限制 |
| --- | --- | --- |
| `wx.navigateTo` | 打开新页面，保留当前页（可返回） | 只能打开非 tabBar 页面；页面栈最多 10 层 |
| `wx.redirectTo` | 页面重定向，关闭当前页（不可返回） | 只能打开非 tabBar 页面 |
| `wx.navigateBack` | 页面返回，触发上一页的 `onShow` | 按 `delta` 指定返回层数 |
| `wx.switchTab` | 切换 tab 页 | 只能打开 tabBar 页面 |
| `wx.reLaunch` | 重启小程序到指定页，关闭所有页面 | 可以打开任意页面 |

注意事项：

1. `navigateTo`、`redirectTo` 只能打开非 tabBar 页面。
2. `switchTab` 只能打开 tabBar 页面。
3. `reLaunch` 可以打开任意页面。

页面栈：`navigateTo` 入栈、`navigateBack` 出栈；`redirectTo` 用新页替换栈顶、`reLaunch`/`switchTab` 清空后重开。栈顶页面永远处于 `onShow` 状态，所以从 B 页返回 A 页时 A 的 `onShow` 会再次触发——这正是"返回刷新"的实现依据。

## 小结

- 小程序生命周期与路由
  - 应用生命周期
    - `onLaunch` 全局只触发一次，做初始化
    - `onShow` / `onHide`：前台/后台切换
    - `onError` / `onPageNotFound` / `onUnhandledRejection`：异常兜底
    - `globalData` 跨页面共享但非响应式
  - 页面生命周期
    - `onLoad`：创建时一次，发请求取数据
    - `onShow`：每次到前台都触发，刷新数据
    - `onReady`：首次渲染完，取元素
    - `onHide` / `onUnload`：终止任务
  - 组件生命周期
    - `created` 不能 `setData`
    - `attached` 进节点树、`ready` 布局完成、`detached` 移除
  - 页面路由
    - `navigateTo` / `redirectTo` 非 tabBar；`switchTab` 只能 tabBar；`reLaunch` 任意
    - `navigateBack` 触发上一页 `onShow`
