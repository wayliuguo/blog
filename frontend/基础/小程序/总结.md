# 模块总结 · 小程序

## 知识主线

五篇正文是一条从"怎么写"到"怎么优化"的链：

```
01 WXML、WXSS 与基础语法（模板 / 样式 / 事件这套语法到底怎么写）
        │  页面写出来了，什么时候该更新数据、页面之间怎么跳？
        ▼
02 生命周期与路由（小程序有哪些时机回调、页面怎么跳）
        │  回调里要更新页面数据，跨线程怎么传？
        ▼
03 双线程架构与渲染机制（逻辑层与渲染层怎么协作，setData 为什么贵）
        │  打开慢、渲染卡，瓶颈在哪、怎么治？
        ▼
04 启动优化与性能优化（包体积、分包、预下载、setData 治理）
        │  选原生还是框架，两个方案差在哪？
        ▼
05 原生与跨端框架差异（原生 / Taro / uni-app 的取舍）
```

本模块的主轴是**双线程架构**：01 先把语法层过一遍——<code v-pre>{{ }}</code> 只求值、`wx:for` 要配 `wx:key`、`hidden` 与 `wx:if` 差在节点在不在、rpx 的基准是 750 等于屏宽，这些写法上的约束都会在后面几篇里变成"性能"与"选型"的理由；02 讲三层生命周期与路由这个"时机骨架"，03 讲这套架构的核心——逻辑层与渲染层靠 `setData` 跨线程通信，04 把启动与渲染性能问题全部归因到"包体积"与"setData 通信成本"，05 回到工程选型，说明框架最终也在小程序端收敛到同样的 `setData` 通道。串起来正好是"语法 → 生命周期 → 架构 → 性能 → 选型"的完整链路。

## 分篇知识点

### 01-WXML、WXSS 与基础语法

- **<code v-pre>{{ }}</code> 表达式**
  - 只求值、不执行：运算是表达式，`var` / `if` / 分号 / 赋值号都在编译期被拦下
  - 判逻辑放逻辑层、展示加工放 WXS；访问不存在的字段得到 `undefined` 而不是报错
- **列表渲染**
  - `wx:for` 默认变量是 `item` 与 `index`（从 0 起），重命名用 `wx:for-item` / `wx:for-index`
  - `wx:key` 取稳定字段：对象数组用 `id`、基本类型数组用 `*this`；不写会警告且重排时整段重建
  - `wx:for` 的值不是数组 → 编译期报错，不是渲染空白
- **条件渲染**
  - `wx:if` / `wx:elif` / `wx:else` 是**连写**的一组，未命中的分支不产出节点
  - `hidden` 只是 `display:none`：节点仍在渲染树里，状态得以保留
  - 切换频繁或要保留状态用 `hidden`；节点重、初始不需要用 `wx:if`
- **模板复用**
  - `template` 是带参片段，`data` 必须显式传；`import` 有作用域、只导入 `template`
  - `include` 是文本级拷贝，忽略被包含文件里的 `template` 与 `wxs`
- **WXSS**
  - `rpx` 的基准是 **750rpx = 屏幕宽度**，`px = rpx × 屏宽 / 750`
  - 支持的选择器只有 `.class` / `#id` / `element` / `element, element` / `::after` / `::before`
  - 作用域三层：`app.wxss` 全局、页面 `.wxss` 作用于本页、组件样式默认隔离；跨文件用 `@import`
- **事件绑定**
  - `bind*` 冒泡、`catch*` 阻止冒泡；`data-*` 传进 `dataset` 的**都是字符串**
  - 用 `currentTarget` 而不是 `target`；回调在逻辑层执行、事件对象跨线程传

### 02-小程序生命周期与路由

- **应用生命周期（app.js）**
  - `onLaunch`：初始化完成，全局只触发一次，做初始化
  - `onShow` / `onHide`：前台/后台切换，做刷新与暂停
  - `onError` / `onPageNotFound` / `onUnhandledRejection`：异常兜底
  - `globalData`：跨页面共享数据，但非响应式，简单场景兜底
- **页面生命周期（Page）**
  - `onLoad`：创建时一次，发请求取数据、读参数
  - `onShow`：每次到前台都触发，用于"返回刷新"
  - `onReady`：首次渲染完，取页面元素
  - `onHide` / `onUnload`：终止任务、释放资源
- **组件生命周期（Component）**
  - `created` 时还不能 `setData`；`attached` 进节点树、`ready` 布局完成、`detached` 移除
- **页面路由**
  - `navigateTo` / `redirectTo` 只能开非 tabBar 页；`switchTab` 只能开 tabBar 页；`reLaunch` 任意
  - `navigateBack` 返回触发上一页 `onShow`

### 03-双线程架构与渲染机制

- **双线程架构**
  - 渲染层 WebView 只负责视图，逻辑层 JS 引擎负责业务
  - 通信/数据/网络请求统一由 Native 层中转
  - 多页面 = 多 WebView，页面栈加深内存增长
- **setData 通信**
  - setData 是跨线程序列化传输，开销与数据量正相关
  - 会引发视图更新并阻塞交互
  - 原则：少调用、批量更新、只传视图要用的数据、用路径更新
- **WXS**
  - 运行在渲染层，做纯展示计算，避免数据加工跨线程传输
  - 不支持 ES6+/部分 API，只适合展示计算

### 04-启动优化与性能优化

- **启动流程**：固定启动界面 + 下载/加载代码包 + 初始化首页
- **启动优化**
  - 控制代码包大小：压缩、清理无用代码、图片上 CDN
  - 分包加载：主包只留核心，分包按需下载（有切换延迟）
  - 预下载：进某页提前下载分包，抵消分包切换延迟
- **首屏渲染优化**
  - 请求放 `onLoad` 提前发
  - data 只放视图要用的数据
  - onLoad 不做同步阻塞操作
- **渲染性能优化**
  - setData 少调用、数据量小
  - `wx:key` 精确识别列表节点
  - 长列表用虚拟列表 / recycle-view
  - 展示加工用 WXS 在渲染层算

### 05-原生与跨端框架差异

- **原生特点**：直接跑小程序运行时，能力最全、无桥接损耗；每端一套代码
- **跨端框架特点**：Taro（React/Vue）/ uni-app（Vue）一套代码多端编译；多端覆盖 + Web 生态复用 + 效率高；多一层编译与桥接，性能与排错有成本
- **关键差异**
  - 性能：原生更直接；框架最终也靠 setData 更新视图
  - 能力：原生第一时间可用；框架依赖适配
  - 选型：单端性能敏感用原生；多端 + Web 栈积累用框架
