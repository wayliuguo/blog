# 模块总结-核心（小程序）

> 精简核心版：按篇分组、抽出高频/重要的知识点——成员丰富的主题展开明细，要点型知识点列清单、点到为止。选点按「面试命中度 / 日常复用度」等维度（见[文档组织规范](../../../文档组织规范.md)）。详细知识树见[《模块总结 · 小程序》](./总结.md)。

## 知识主线（一句话）

小程序的主轴是**双线程架构**：01 的语法约束（`{{ }}` 只求值、`wx:key`、`hidden`、rpx）是后续性能取舍的伏笔，02 生命周期与路由定"时机骨架"，03 逻辑层与渲染层靠 `setData` 跨线程通信是核心代价，04 把"启动慢 / 渲染卡"归因到包体积与 setData 通信成本，05 的选型最终也收敛回同一条 setData 通道。

## 高频核心点

### 01 WXML、WXSS 与基础语法

**模板 `{{ }}`**

- **只求值不执行**：运算 / 三元 / 成员访问 / 方法调用是表达式；`var` / `if` / 分号 / 赋值号被编译期拦下
- 访问不存在的字段得 `undefined` 渲染空串、不报错；判逻辑放逻辑层、展示加工放 WXS

**列表与 key**

- `wx:for` 默认变量 `item` / `index`，重命名用 `wx:for-item` / `wx:for-index`
- **`wx:key` 取稳定字段**：对象数组用 `id`、基本类型数组用 `*this`；不写会警告且重排整段重建

**条件渲染**

- `wx:if` / `wx:elif` / `wx:else` 连写，未命中分支不产出节点
- `hidden` 只是 `display:none`，节点仍在、状态保留
- 切换频繁 / 要保留状态用 `hidden`；节点重 / 初始不需要用 `wx:if`

**WXSS**

- **`rpx` 基准 750 = 屏宽**，`px = rpx × 屏宽 / 750`；会算小数，"1px 细线"用 `1px`
- 选择器清单很短（`.class` / `#id` / `element` / `element, element` / `::after` / `::before`），通配符 / 属性选择器不在内，状态用类名
- 作用域三层：`app.wxss` 全局、页面 `.wxss` 本页、组件样式默认隔离

**事件**

- `bind*` 冒泡 / `catch*` 阻止冒泡
- `data-*` 进 dataset 全是字符串；用 `currentTarget` 而非 `target`
- 回调在逻辑层执行、事件对象跨线程传；长列表监听收容器上用 `data-*` 区分更省

### 02 生命周期与路由

- **应用层**：`onLaunch` 全局一次做初始化；`onShow` / `onHide` 前后台切换；`onError` 异常兜底
- **globalData**：跨页面共享但非响应式，简单场景兜底
- **页面层**：`onLoad` 一次发请求取数；`onShow` 每次回前台刷新；`onReady` 首渲染完取元素
- **组件层**：`created` 不能 `setData`；`attached` 进节点树、`ready` 布局完成取节点、`detached` 移除
- **路由**：`navigateTo` / `redirectTo` 只能非 tabBar；`switchTab` 只能 tabBar；`reLaunch` 任意；`navigateBack` 触发上一页 `onShow`；页面栈最多 10 层

### 03 双线程架构与渲染机制

- **双线程**：渲染层 WebView 只视图、逻辑层 JS 引擎跑业务，Native 中转通信 / 数据 / 网络
- **多页 = 多 WebView**：页面栈加深内存增长，`onHide` / `onUnload` 记得清定时器与播放器
- **setData**：跨线程序列化传输、开销与数据量正相关、会阻塞交互
- **减 setData 三原则**：只传视图要用的数据、一次回调合并多次、路径更新 `'list[0].name'` 局部改
- **WXS**：渲染层做纯展示计算避免跨线程；不支持 ES6+ / 部分 API

### 04 启动优化与性能优化

**启动流程**：固定启动界面 + 下载 / 加载代码包 + 初始化首页

- **包瘦身**：上传时压缩、删无用代码与资源、图片上 CDN
- **分包**：主包只留核心，分包按需下载省首启；硬限制主包约 2MB、总包约 20MB
- **预下载**：`preloadRule` 进某页提前拉分包、`network: wifi` 防耗流量，抵消分包切换延迟

**首屏 / 渲染**

- 请求放 `onLoad` 提前发、data 只放渲染要用的、`onLoad` 不做同步阻塞（如大对象 `getStorageSync`）
- `wx:key` 精确识别列表节点，避免整段重渲染
- 长列表用虚拟列表 / 官方 `recycle-view`；展示加工用 WXS 在渲染层算

### 05 原生与跨端框架差异

- **原生**：直接跑小程序运行时、能力最全、无桥接损耗；每端一套代码
- **跨端框架**：Taro（React/Vue 系）/ uni-app（Vue 系）一套代码多端编译；复用 Web 生态、效率高；多一层编译与桥接，性能与排错有成本
- **关键收敛**：框架在微信端最终也靠 setData 更新视图，性能上界由小程序运行时决定
- **选型**：单端 / 性能敏感 / 要第一时间用平台能力用原生；多端 + Web 栈积累用框架
