## 2. 重点题精答（五步法）

### Q1：Vue3 响应式原理？

- **结论**：`reactive` 用 Proxy 拦截 get/set——get 时收集依赖（effect），set 时触发更新。
- **原理**：渲染函数作为 effect 执行，读取响应式属性即建立"属性 → effect"依赖；数据变化把 effect 加入调度队列（`queueJob`），在微任务中批量执行。
- **场景**：页面视图依赖 `loanForm.amount`，改 amount 只重渲染依赖它的组件。
- **边界**：深度响应式递归代理有成本；Map/Set 等集合类型走专用 handlers；`ref` 用对象包装值（`.value`）。
- **追问**：为什么用 Proxy 而不用 defineProperty？→ 可拦截动态新增属性与数组索引，且一次性代理整个对象。

### Q2：依赖收集与触发更新的链路？

- **结论**：effect 执行 → 读取属性 → 属性对应的 dep 收集该 effect → 属性变化 → dep 触发 effect。
- **原理**：`targetMap: WeakMap<对象, Map<key, Set<effect>>>`；`ref` 的 `.value` 读写同样走 getter/setter。
- **场景**：computed 是惰性 effect（有缓存）；watch 是显式收集目标。
- **边界**：在 effect 外读取不收集；`Vue.set` 在 Vue2 的痛点（新增属性不响应）在 Vue3 Proxy 下不存在。
- **追问**：computed 为什么能缓存？→ 惰性求值 + dirty 标记，依赖不变直接返回缓存值。

### Q3：批量更新与 nextTick？

- **结论**：多次同步改数据只触发一次渲染；nextTick 在本次更新后拿最新 DOM。
- **原理**：effect 触发进 `queueJob` 去重 + 微任务调度；渲染在微任务中批量执行。
- **场景**：循环里改 100 次数据 → 只渲染一次；`this.$nextTick` 读更新后的 DOM 尺寸。
- **边界**：`flushSync`（Vue3.5 起）可强制同步渲染，但会牺牲批处理收益。
- **追问**：为什么用微任务而不用同步？→ 同步多次改数据会多次渲染，微任务合并为一次。

### Q4：编译优化：patchFlag 与静态提升？

- **结论**：编译期标记动态节点（patchFlag），diff 时只对比动态部分；静态节点提升出渲染函数。
- **原理**：模板编译把"哪些部分是动态的"编码进标志位（TEXT/CLASS/PROPS 等）；静态子树提升为常量不再重复创建。
- **场景**：`<div>{{ msg }}</div>` 只标记 text 动态；`<li v-for>` 用 Block 收集动态子节点。
- **边界**：手写渲染函数没有编译优化收益——这就是"模板优先"的原因。
- **追问**：Block Tree 是什么？→ 把动态子节点收集成扁平数组，diff 直接遍历，不再深度对比静态结构。

### Q5：组合式 API 与选项式 API？

- **结论**：组合式按"逻辑"组织（相关代码聚在一起），选项式按"类型"组织（data/methods 分块）。
- **原理**：组合式靠函数作用域复用逻辑（自定义 Hook）；选项式靠 mixin（命名冲突/来源不明）。
- **场景**：简历项目 hooks 分层：`api/`（接口）、`hooks/`（组合逻辑）、`utils/`（纯函数）、`views/`（视图）——`useLoanFlow` 把试算链路收敛在一个 Hook。
- **边界**：组合式更灵活也更容易写乱，需要分层规范约束。
- **追问**：自定义 Hook 与 mixin 的区别？→ Hook 是普通函数（显式传参、无命名冲突），mixin 隐式合并。

### Q6：`v-model` 的本质？

- **结论**：`v-model` 是 `:value` + `@input`（组件内为 `modelValue` + `update:modelValue`）的语法糖。
- **原理**：表单元素绑定 value + 监听输入事件回写；组件上绑定 prop + 监听更新事件。
- **场景**：自定义表单组件 `defineModel()`（Vue3.4+）简化双向绑定。
- **边界**：多个 v-model（`v-model:name`、`v-model:age`）Vue3 支持。
- **追问**：`v-model` 与 `.sync` 的关系？→ `.sync` 是 Vue2 的等价物，Vue3 统一为 v-model 多参数。

## 3. 追问链

1. "响应式深度代理的性能代价？" → 递归 Proxy 有初始化成本；可用 `shallowReactive`/`shallowRef` 按需降级。
2. "模板里每次渲染都重新计算，怎么避免？" → computed 缓存 + 纯函数 + 派生状态集中管理。
3. "Vue3 组件更新是精确到组件级吗？" → 是，但父组件更新子组件仍会 re-render，用 `defineOptions`/memo 优化。
4. "为什么金融试算用纯函数而不依赖响应式计算？" → 纯函数可枚举、可单测，响应式只管视图层派生。

## 4. 场景设计题

**场景：一个借款页，用户切换还款方式/计息方式/分期数会级联触发试算，怎么用 Vue3 实现才不卡、不乱、可测？**
- 答题骨架：金融要素 → 纯函数试算（无副作用，输入决定输出）→ 试算结果作为派生状态 → 视图只消费派生状态 → 相同输入缓存结果（避免重复计算）→ 并发切换用请求标记位 → 单测覆盖纯函数。
- 加分点：呼应简历"主组件职责从视图+数据+请求+校验+埋点混写，收敛为编排+渲染两类"的重构。

## 5. 面试口径（简历项目如何表达）

- **项目证据**：Vue 3.5 + Vite 7 + TS 5.8 + Vant 4；级联要素流转重构（纯函数 + 单向数据流）；组合式 API 分层（api/hooks/utils/views）；接口治理（分层 / 缓存 / 竞态 / 预取）；Weex（Vue2）转 Vue3 MPA。
- **表达句式**："借款页核心是'还款方式 → 计息方式 → 分期数'的级联试算，我把它从散落在 data/watch/事件里的逻辑重构成纯函数单向数据流——可枚举、可单测、可复用、可回归；并发试算用请求标记位保证最后一次请求生效。"
- **加分表达**：Vue3.5 特性（`useTemplateRef`、`onWatcherCleanup`、`flushSync`）按需提，体现跟版本节奏。
