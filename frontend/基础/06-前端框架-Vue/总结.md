# 模块总结 · 前端框架-Vue

## 知识主线

三篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 Vue 核心基础（数据怎么驱动视图）
        │  一块界面会写了，怎么拆成可复用、可通信的组件？
        ▼
02 Vue 组件（组件化与通信）  ★主轴
        │  页面多了、状态要全局共享，路由与状态怎么组织？
        ▼
03 Vue 路由与状态（vue-router + Pinia）
```

本模块的主轴是**组件化**：01 讲 Vue 的地基——MVVM 思想、createApp、模板语法（插值/指令）、computed/watch、条件与列表渲染、v-model 表单绑定，回答"数据怎么驱动视图"；02 讲 Vue 的核心——组件的注册、父子/跨级通信（props/emit/ref/v-model/provide-inject）、插槽、选项式 vs 组合式 API、生命周期、动态与异步组件，回答"一块界面怎么拆成可复用单元"；03 在组件之上加"路由 + 状态"——vue-router 4 的三种模式、嵌套/动态路由、守卫、懒加载，以及 Pinia 的 state/getters/actions 与 storeToRefs，回答"多页面怎么串、共享状态怎么管"。三篇合起来就是"用 Vue 从零搭一个可维护的 SPA"的完整路线。

## 分篇知识点

### 01-Vue 核心基础

- **MVVM 思想**：Model（数据）+ View（界面）+ ViewModel（桥梁）；ViewModel 由 Vue 实例承担，数据变视图自动更新、用户交互自动写回数据——"数据驱动视图"；`createApp` 创建应用、`.mount('#app')` 挂载
- **模板语法**：`{{ }}` 插值只能放**单个表达式**（不能是语句），`v-html` 渲染 HTML 有 XSS 风险；指令 `v-bind`（简写 `:`）、`v-on`（简写 `@`）、`v-model`、`v-if/v-show/v-for`；`{{ }}` 是 `v-text` 的简写
- **computed vs watch**：computed 根据已有数据**派生**新数据、有缓存、依赖不变不重算（可写 computed 支持 setter）；watch 在数据变化时**执行副作用**（`{ immediate: true }` 立即执行、`{ deep: true }` 深度监听、watchEffect 自动追踪依赖）；能用 computed 就不用 watch
- **class/style 绑定**：class 支持字符串 / 对象（`{ active: isActive }`）/ 数组语法；style 绑定驼峰对象
- **v-if vs v-show**：v-if 条件为假时从 DOM 移除、切换开销大、初始恒假时省首屏；v-show 只切 display、元素始终在 DOM；频繁切换用 v-show
- **v-for 与 key**：遍历数组/对象/数字；key 必须唯一且用稳定业务 id（不用 index，否则列表中间插入/删除会复用错项引发状态错乱）；**v-model 本质是 value 绑定 + input 事件监听的语法糖**，支持 `.trim` / `.number` / `.lazy` 修饰符；Vue3 已移除过滤器，用计算属性/方法替代

### 02-Vue 组件

- **组件注册**：全局注册（`app.component`，适合公共 UI 组件但增首屏体积）vs 局部注册（`<script setup>` 中 import 即用，可 tree-shaking，推荐）
- **通信方式与选型**：父传子 props（单向、defineProps 声明类型/默认值/必填）、子传父 emit（defineEmits 显式声明、事件名用 kebab-case）、父访问子 ref + defineExpose（`<script setup>` 默认私有须显式暴露）、父子双向 v-model（modelValue + `update:modelValue`，支持多 v-model）、跨级 provide/inject（深层嵌套免逐层传）、全局共享用 Pinia（Vue2 的 EventBus 是反模式）
- **插槽**：默认插槽（`<slot>` 内可写兜底内容）、具名插槽（`v-slot`/`#header`）、作用域插槽（子组件向插槽传数据，`#item="{ user }"`）
- **选项式 vs 组合式**：选项式按 data/computed/methods 组织、易上手；组合式（`<script setup>`）按功能组织、可抽组合函数、TS 支持强，新项目推荐
- **生命周期**：选项式 created/mounted/updated/beforeUnmount/unmounted；组合式对应 onMounted/onUnmounted 等（`<script setup>` 无 beforeCreate/created，逻辑写 setup 顶层）；卸载时清理定时器与监听器防内存泄漏
- **动态与异步组件**：`<component :is>` 按需切换组件，配合 `<KeepAlive>` 缓存实例；`defineAsyncComponent(() => import(...))` 懒加载重组件（可配 loading/error 组件与超时），减小首屏体积

### 03-Vue 路由与状态

- **createRouter 与三种 history 模式**：`createWebHistory`（History 模式，URL 整洁，刷新需服务端回落入口页，Nginx 配 `try_files ... /index.html`）、`createWebHashHistory`（Hash 模式，无需服务端配置、兼容最好、不利于 SEO）、`createMemoryHistory`（内存模式，用于 SSR/测试）；`<router-link>` 声明式跳转、`<router-view>` 路由出口
- **动态路由与参数**：`:id` 占位 + `route.params` / `route.query` 读取；可选参数 `?`、通配 `/:pathMatch(.*)*` 作 404 兜底；同一组件复用时（`/article/1` → `/article/2`）不会重建，用 watch route 或 `onBeforeRouteUpdate` 重新拉数据
- **嵌套路由**：`children` 数组声明子路由，子 path 不以 `/` 开头（自动拼父前缀），`path: ''` 渲染父路径；每一级路由都要有 `<router-view>`（布局壳 + 子页面模式适合后台系统）
- **编程式导航**：`useRouter()` 的 push / replace / back / go，支持字符串或 `{ name, params, query }` 对象，用 name 跳转更健壮
- **三类守卫**：全局（beforeEach 登录鉴权、beforeResolve、afterEach 设标题/埋点）、路由级 beforeEnter、组件内 onBeforeRouteUpdate/Leave；执行时序 beforeEach → 组件内 → beforeEnter → beforeResolve → afterEach
- **懒加载与 Pinia**：`component: () => import(...)` 按路由拆包；Pinia store = state（ref）+ getters（computed）+ actions（可异步），解构 state 必须用 `storeToRefs` 保响应性，多 store 按业务域拆分（一个文件一个 store）；守卫内用 `useUserStore()` 需在 `app.use(pinia)` 之后
