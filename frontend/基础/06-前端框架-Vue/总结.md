# 模块总结 · 前端框架-Vue

## 知识主线

三篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 Vue 核心基础（数据怎么驱动视图）
        │  一块界面会写了，怎么拆成可复用、可通信的组件？
        ▼
02 Vue 组件（组件化与通信）  ★主轴
        │  页面多了、状态要全局共享，路由与状态怎么组织？
        ▼
03 Vue 路由与状态（vue-router + Pinia）
```

本模块的主轴是**组件化**：01 讲 Vue 的地基——MVVM 思想、createApp、模板语法（插值/指令）、computed/watch、条件与列表渲染、v-model 表单绑定，回答"数据怎么驱动视图"；02 讲 Vue 的核心——组件的注册、父子/跨级通信（props/emit/ref/v-model/provide-inject）、插槽、选项式 vs 组合式 API、生命周期、动态与异步组件，回答"一块界面怎么拆成可复用单元"；03 在组件之上加"路由 + 状态"——vue-router 4 的三种模式、嵌套/动态路由、守卫、懒加载，以及 Pinia 的 state/getters/actions 与 storeToRefs，回答"多页面怎么串、共享状态怎么管"。三篇合起来就是"用 Vue 从零搭一个可维护的 SPA"的完整路线。

## 分篇知识点

### 01-Vue 核心基础

- **MVVM 思想**
  - **三层结构**：Model（数据层：应用的数据状态，如用户信息、列表数据）、View（视图层：界面 DOM）、ViewModel（视图模型层：连接 Model 与 View 的桥梁，负责数据与视图同步）
  - **双向数据绑定**：Model 变化时 ViewModel 自动更新 View；用户在 View 交互时 ViewModel 自动把更新写回 Model——"数据驱动视图"，ViewModel 的角色由 Vue 实例承担
  - **createApp 创建应用**：Vue3 用 `createApp(App)` 创建应用实例、`.mount('#app')` 挂载到 DOM 容器；一个页面可创建多个应用实例、各自独立互不影响
- **模板语法**
  - **插值 <code v-pre>{{ }}</code>**：把数据插入文本内容，可放变量、表达式、三元运算；只能是**单个表达式**、不能是语句；双大括号是 `v-text` 的简写
  - **v-html**：渲染 HTML 内容，但会解析 HTML、极易引发 XSS 攻击，只能用于可信任内容、不推荐拼接用户输入
  - **常用指令**：`v-bind`（简写 `:`）动态绑定属性、`v-on`（简写 `@`）绑定事件、`v-if`/`v-show`/`v-for` 条件与列表渲染、`v-model` 表单双向绑定；指令由参数与修饰符构成（如 `v-on:click.stop` 中 click 是参数、stop 是修饰符）
  - **事件处理**：`@click="handleClick('参数', $event)"` 传参并拿到事件对象；修饰符 `.stop` 阻止冒泡、`.prevent` 阻止默认行为、`.once` 只触发一次、`.capture` 捕获模式、`.self` 仅自身触发，还有键盘修饰符（`@keyup.enter`）
  - **插值简写总结**：<code v-pre>{{ }}</code> 是 `v-text` 简写、`:` 是 `v-bind` 简写、`@` 是 `v-on` 简写、`v-model` 无简写形式
- **computed vs watch**
  - **computed 计算属性**：根据已有数据**派生**新数据，自动缓存、依赖不变不重算，自动追踪计算过程中读取的响应式属性；可写计算属性传入 `{ get, set }` 对象支持 setter
  - **watch 侦听器**：数据变化时执行副作用（发起请求、写入本地存储、打印日志）；`{ immediate: true }` 初始化立即执行、`{ deep: true }` 深度监听（reactive 对象默认深度监听），支持监听多个数据源
  - **watchEffect**：自动追踪回调中依赖的所有响应式数据，任一依赖变化都会重新执行
  - **选型**：computed 用于派生新数据、尽量不执行副作用；watch 用于"数据变化时还要做别的事"；能用 computed 表达的尽量用 computed，逻辑更清晰、性能更好
- **class/style 绑定**
  - **绑定 class**：支持普通字符串、对象语法（`{ active: isActive }`）、数组语法（可混入字符串与对象）
  - **绑定 style**：绑定一个 JS 对象、属性名用驼峰写法（或加引号的 kebab-case），也可直接绑定样式变量对象
- **v-if vs v-show**
  - **v-if**：真正的条件渲染，条件为假时元素从 DOM 移除，可配合 `v-else-if`/`v-else`；切换涉及销毁/重建、开销大；初始恒假时懒渲染、省首屏资源
  - **v-show**：仅切换 CSS 的 display 属性、元素始终保留在 DOM；切换开销小
  - **选型**：频繁切换用 v-show；条件变化不频繁或初始即为假用 v-if
- **v-for 与 key**
  - **v-for 遍历**：遍历数组（`(item, index)`）、对象（`(value, key, index)`）、数字（`n in 10`）生成列表
  - **key 的作用与规则**：每项必须提供唯一 key、尽量用稳定业务 id（不用 index，否则列表中间插入/删除会复用错项、引发输入框内容错位等状态错乱）；key 是优化虚拟 DOM diff 的关键、减少不必要的重排与重建
- **v-model 与过滤器**
  - **v-model 本质**：`value` 属性绑定 + `input` 事件监听的语法糖，作用于 input/textarea/select 等表单控件，实现双向数据绑定
  - **不同控件的绑定**：文本类用 `value` + `input` 事件；复选框/单选/下拉用 `checked` + `change` 事件
  - **修饰符**：`.trim` 自动去除首尾空格、`.number` 将输入转为数字、`.lazy` 把 input 事件改为 change 事件（失焦或回车时才同步）
  - **过滤器（Vue2）**：Vue2 中用于模板文本格式化（<code v-pre>{{ price | currency }}</code>），Vue3 已移除，用计算属性或方法替代

### 02-Vue 组件

- **组件注册**
  - **全局注册**：`app.component('MyComponent', MyComponent)`，应用内任意组件模板直接使用；适合公共 UI 组件，但增加首屏加载体积、难以检测未使用的冗余组件
  - **局部注册**：`<script setup>` 中 import 即用，或选项式用 `components` 选项注册；只在当前组件内有效、配合构建工具可 tree-shaking，推荐
- **通信方式与选型**
  - **父传子 props**：数据流单向、子组件只能读取不能修改；`defineProps` 声明类型/默认值/必填（对象写法），也可直接传字符串数组
  - **子传父 emit**：`defineEmits` 显式声明事件、事件名建议 kebab-case；子组件 `$emit('add', 1)` 触发、父组件 `@add` 监听
  - **父访问子 ref**：`<Child ref="childRef">` 获取子组件实例；`<script setup>` 默认私有，须用 `defineExpose` 显式暴露属性和方法
  - **父子双向 v-model**：子组件通过 `modelValue` prop 接收值、`update:modelValue` 事件更新值；一个组件支持多个 v-model（`v-model:title`、`v-model:content`）
  - **跨级 provide/inject**：深层嵌套传数据免逐层传 props，祖先 `provide('key', value)`、任意后代 `inject('key', default)`；数据响应式但遵循单向数据流原则
  - **全局共享 EventBus vs Pinia**：Vue2 的 EventBus（借独立 Vue 实例 $emit/$on 中转）难以追踪、是反模式；Vue3 用官方推荐的 Pinia（`defineStore` + `useStore()`）集中管理共享状态
  - **选型建议**：父传子简单数据用 props、子传父事件用 emit、父访问操作子用 ref + defineExpose、父子双向用 v-model、深层跨级用 provide/inject、全局共享用 Pinia
- **插槽**
  - **默认插槽**：子组件中不写 name 的 `<slot>`，父组件标签内的普通内容渲染到该位置；`<slot>` 内可写兜底内容（父组件没传时显示）
  - **具名插槽**：通过 `name` 给插槽命名、一个组件可有多个插槽；父组件用 `v-slot`（简写 `#`）配合插槽名传入内容（`<template #header>`）
  - **作用域插槽**：子组件向插槽内容传数据（`<slot name="item" :user="user">`），父组件用 `#item="{ user, index }"` 显式接收；只有一个默认作用域插槽时可简写 `<List v-slot="{ item }">`
- **选项式 vs 组合式**
  - **选项式 API**：按 data/computed/methods/watch/components 等选项组织逻辑、代码结构固定、学习曲线低，适合中小项目与简单组件
  - **组合式 API（setup）**：通过 setup 函数或 `<script setup>` 按功能组织逻辑、可抽组合函数复用、TS 支持强（类型推断优秀），适合大型复杂项目；新项目推荐
  - **逻辑复用**：选项式依赖 mixins，组合式通过组合函数（composable）
- **生命周期**
  - **选项式钩子**：`beforeCreate`/`created`（created 后可访问 data/methods、尚未挂载 DOM）/`beforeMount`/`mounted`（DOM 已渲染、适合发请求与操作 DOM）/`beforeUpdate`/`updated`/`beforeUnmount`（卸载前清理监听器、定时器）/`unmounted`
  - **组合式钩子**：对应 `onBeforeMount`/`onMounted`/`onUpdated`/`onBeforeUnmount`/`onUnmounted` 等；`<script setup>` 中不存在 beforeCreate/created、逻辑直接写 setup 顶层
  - **清理防泄漏**：卸载时清理定时器与监听器（如 `onUnmounted` 里 `clearInterval`），避免内存泄漏
- **动态与异步组件**
  - **动态组件**：`<component :is="current">` 根据条件在同一位置动态切换渲染不同组件（is 可为已注册组件名或组件对象），常用于 Tab 切换
  - **KeepAlive 缓存**：配合 `<KeepAlive>` 缓存被切换的组件实例、避免重复创建与销毁
  - **异步组件**：`defineAsyncComponent(() => import('./BigChart.vue'))` 按需加载重组件、减小首屏体积；可配 `loadingComponent`/`errorComponent`/`delay`/`timeout`
  - **路由级懒加载**：路由配置中 `component: () => import(...)` 实现路由级按需加载

### 03-Vue 路由与状态

- **createRouter 与三种 history 模式**
  - **createRouter 与挂载**：接收 `history`（路由模式）与 `routes`（"路径 → 组件"映射的路由表）两个核心选项；`app.use(router)` 注册；`<router-link>` 渲染成 a 标签做声明式跳转、`<router-view>` 是路由出口、当前命中组件渲染于此
  - **createWebHistory（History 模式）**：URL 形如 `/about`、基于 HTML5 History API，最整洁；刷新/直接访问子路径需服务端回落到入口页（Nginx 配 `try_files $uri $uri/ /index.html;`），否则 404
  - **createWebHashHistory（Hash 模式）**：URL 形如 `/#/about`、改变 hash 不触发浏览器发请求、无需服务端配置、兼容性最好，适合纯静态部署；缺点是不美观、不利于 SEO
  - **createMemoryHistory（内存模式）**：路由保存在内存中、不反映在 URL 上，主要用于服务端渲染（SSR）与测试
- **动态路由与参数**
  - **动态参数**：`:id` 占位符定义动态路由（如 `/article/:id`），组件内 `useRoute()` 拿 `route.params` 读取；支持多个参数、可选参数 `?`、通配 `/:pathMatch(.*)*` 作 404 兜底
  - **Query 查询参数**：`?title=xxx` 这类查询串通过 `route.query` 读取
  - **组件复用注意点**：同一组件复用时（`/article/1` → `/article/2`）组件不会重新创建，需 watch `route` 或 `onBeforeRouteUpdate` 守卫响应参数变化、重新拉取数据
- **嵌套路由**
  - **children 子路由**：`children` 数组声明子路由；子 path 不以 `/` 开头（自动拼接父路径前缀），以 `/` 开头则视为绝对路径、脱离嵌套
  - **空串 path**：`path: ''` 表示访问父路径（如 `/manage`）时渲染该子组件
  - **多级出口**：每一级路由都需要对应的 `<router-view>` 出口（外层布局壳子内部再放 `<router-view>` 渲染子路由）；"布局壳 + 子页面"模式适合后台管理系统
- **编程式导航**
  - **useRouter**：`useRouter()` 拿到路由实例，`push` 压入历史栈可返回、`replace` 替换当前记录不产生新历史、`back` 回退一步、`go(n)` 前进/回退 n 步
  - **路由对象**：push/replace 支持字符串路径或 `{ name, params, query, hash }` 对象；用 `name` 跳转比写死路径更健壮（日后改 path 也不受影响）
- **三类守卫**
  - **全局守卫**：`beforeEach`（登录鉴权主要落点，`next()` 放行或 `next({ path: '/login', query: { redirect: to.fullPath } })` 重定向并记录来源）、`beforeResolve`（组件解析后、导航确认前）、`afterEach`（无 next，设页面标题/埋点上报）
  - **路由级守卫**：路由表里配置 `beforeEnter`，只对该路由生效
  - **组件内守卫**：`onBeforeRouteUpdate`（组件复用且参数变化时触发）、`onBeforeRouteLeave`（离开时触发，返回 false 可阻止离开）
  - **执行时序**：beforeEach（全局）→ 组件内 beforeRouteUpdate → beforeEnter（路由级）→ 组件内 beforeRouteEnter → beforeResolve（全局）→ 导航确认 → afterEach（全局）
- **懒加载与 Pinia**
  - **按路由拆包**：`component: () => import(...)` 让构建工具（Vite/Webpack）把每个路由拆成独立 chunk，首次访问才加载、减小首屏体积；可加注释命名 chunk、配合 Suspense 或 loading 态防白屏
  - **Pinia 是什么**：现代 Vue 官方推荐的状态管理方案（取代 Vuex），基于组合式 API 构建、设计简洁、天然支持 TS；`createPinia()` 创建 + `app.use(pinia)` 注册
  - **store 三要素**：state（响应式数据、类比 Vue 组件里的 data）、getters（由 state 派生的计算值、类比 computed）、actions（修改状态的方法、可含异步逻辑）
  - **defineStore 写法**：setup 写法 `defineStore('counter', () => { ... })`，state 用 ref、getters 用 computed、actions 用普通函数（可 async）；第一个参数是 store 唯一 id
  - **storeToRefs 解构**：直接解构 `store.count` 会失去响应性，state/getters 必须用 `storeToRefs(store)` 解构；actions 是普通函数、可直接解构
  - **模块化**：按业务域拆分多个 store（一个文件一个 store），store 之间可相互引用；守卫内用 `useUserStore()` 需在 `app.use(pinia)` 之后
