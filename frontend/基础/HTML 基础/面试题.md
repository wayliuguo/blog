# 模块面试题 · HTML 基础

> 用法：先遮住答案自测，再对照参考；每题以一句能背下来的判断句打头，可直接当复习清单用。

## 一、基础概念

### Q1: `<!doctype html>` 的作用是什么？缺失会怎样？（第 1 篇）

- **结论**：doctype 是标准模式开关，缺失会进入怪异模式。
- **原理**：浏览器按 doctype 选择解析模式；怪异模式下盒模型、行高、margin 折叠等规则与标准模式不一致，布局容易"看着对、量着错"。
- **边界**：`document.compatMode === 'CSS1Compat'` 是标准模式，`'BackCompat'` 是怪异模式；怪异模式下 `box-sizing` 默认值仍是 `content-box`。
- **追问**：SPA 一般不会遇到，但多页模板 / 服务端直出漏写 doctype 就会中招。

### Q2: `meta charset` 为什么要尽早声明？（第 1 篇）

- **结论**：它告诉解析器文档编码，必须放在 `<head>` 最前（前 1024 字节内）。
- **原理**：HTML 解析器按 BOM → `meta charset` → HTTP 头 `Content-Type` 的优先级确定编码；声明越靠后，之前的内容可能已被按错误编码解析成乱码。
- **边界**：HTTP 响应头里的 `Content-Type: text/html; charset=utf-8` 优先级高于 `meta`，但本地打开、静态托管的文件仍依赖 `meta`。
- **追问**：中文站点漏写可能直接出现"锟斤拷"式乱码，UTF-8 是事实标准。

### Q3: `src` 与 `href` 的区别是什么？（第 1 篇）

- **结论**：`href` 是"引用"，`src` 是"加载并嵌入"。
- **原理**：`<link href>`、`<a href>` 只建立关联、不替换内容；`<script src>`、`<img src>`、`<iframe src>` 需要下载并执行 / 渲染。
- **边界**：`<a href="app.js">` 不会执行脚本，`<script href>` 不加载——写错属性资源直接不生效。
- **追问**：同步 `script` 为什么阻塞解析而 stylesheet 不阻塞？因为 `src` 语义要执行、`href` 只是关联。

### Q4: HTML 语义化标签有哪些？收益是什么？（第 1 篇）

- **结论**：语义化让标签"自带含义"，收益是可访问性、SEO、可维护性与 AI 抽取。
- **原理**：`h1-h6` 构建文档大纲，`nav`/`main`/`article`/`section`/`aside`/`header`/`footer` 标记内容区块，`ol`/`ul` 区分有序无序列表；读屏器等辅助技术依赖语义角色做导航与朗读。
- **边界**：语义不等于样式——`<div>` 包裹不改语义；也不要为了"语义"而用错元素（如用 `article` 包导航）。
- **追问**：裸 `div` 的"div 汤"让读屏用户和爬虫都难定位内容，是语义化要解决的核心问题。

### Q5: viewport meta 各字段的含义是什么？（第 1 篇）

- **结论**：viewport meta 控制移动端布局视口，核心是 `width=device-width` + `initial-scale=1`。
- **原理**：移动浏览器默认布局视口 980px，内容会被等比缩小；`width=device-width` 把布局视口对齐设备宽度，`initial-scale=1` 锁定初始缩放。
- **边界**：`user-scalable=0` 能禁用双指缩放，但违反可访问性（详见 Q17）；`viewport-fit=cover` 控制是否延伸到刘海区域。
- **追问**：漏写 viewport 的移动页面会"整体缩小成桌面版"，是所有移动适配问题的源头。

## 二、机制与原理

### Q6: `defer`、`async`、`type="module"` 的区别是什么？（第 1 篇）

- **结论**：三者都不阻塞解析；defer 推迟执行且保序，async 下载完即执行不保序，module 自带 defer 语义。
- **原理**：defer 在 DOM 解析完成后、`DOMContentLoaded` 前按文档顺序执行；async 在下载完成瞬间执行（可能在解析中途）；module 默认 defer + 严格模式 + 模块作用域。
- **边界**：async 脚本若访问 `document.body` 可能拿到 null，需判空；defer 仍需等 DOM 就绪，首屏关键逻辑应内联而非依赖 defer。
- **追问**：模块顶层 `this` 是什么？→ `undefined`（不是 window）。

### Q7: 同步 `<script>` 为什么阻塞解析？白屏的根因有哪些？（第 1 篇）

- **结论**：同步脚本会暂停 HTML 解析去下载并执行，是白屏的常见根因之一。
- **原理**：解析器遇到无 `defer`/`async` 的 `<script>` 会停止构建 DOM，等待脚本下载 + 执行完才继续；外部脚本还要先网络下载。CSS 也会阻塞渲染（CSSOM 未就绪不绘制）。
- **边界**：白屏根因按"解析阻塞 → 渲染阻塞 → 首屏报错 → 资源过慢"四类排查，脚本只是其中一类。
- **追问**：`<script>` 放 `</body>` 前不阻塞 DOM 构建，但下载仍会推迟执行；真正不阻塞的是 `defer`/module。

### Q8: `dns-prefetch` / `preconnect` / `preload` / `prefetch` 的区别与选型？（第 1 篇）

- **结论**：四者都是预连接 / 预加载指令，但作用阶段与代价不同，选型看"当前页必需还是以后可能用"。
- **原理**：`dns-prefetch` 只做 DNS 解析（成本最低）；`preconnect` 做完 DNS+TCP+TLS；`preload` 高优先级加载"当前页必需"资源；`prefetch` 空闲时预取"以后可能用"的资源；`modulepreload` 预加载 ESM 依赖图。
- **边界**：`preload` 误用（预加载下一页资源）会抢占首屏带宽并触发 console 警告；`preconnect` 占用连接池，不宜超 4-6 个；跨域字体用 `preconnect` 必须带 `crossorigin`，否则建立两次连接、预连接失效。
- **追问**：项目里 13 条 `dns-prefetch` 覆盖 CDN / 上报域名，正是"成本低、覆盖广"的选型逻辑。

### Q9: `img` 的 `alt` / `loading="lazy"` / `srcset` 怎么用？（第 1 篇）

- **结论**：`alt` 提供语义替代，`loading="lazy"` 延迟加载，`srcset` 按设备选图。
- **原理**：`alt` 在图片加载失败或读屏时被读出；`loading="lazy"` 让图片接近视口才加载（浏览器原生，不依赖 JS）；`srcset + sizes` 让浏览器按 DPR 与视口宽度挑最合适的资源。
- **边界**：`title` 是鼠标悬停提示文本，**不等于** `alt`（替代描述）——两者职责不同，`alt` 才是无障碍/SEO 语义；首屏的 LCP 图片**不能** lazy——最大内容绘制会被推迟；装饰性图片用 `alt=""` 而非省略（省略会被读屏读出文件名）。
- **追问**：`loading="lazy"` 生效依赖浏览器支持与 iframe 内同源规则，且占用滚动监听类成本很低，可放心用。

### Q10: 回流（Reflow）与重绘（Repaint）是什么？HTML 层面怎么减少？（第 1 篇）

- **结论**：回流是重新计算布局，重绘是重新绘制像素；回流必带重绘，代价远高于重绘。
- **原理**：改宽高、增删节点、读 `offsetWidth` 等强制同步布局都会触发回流；`transform` / `opacity` 走合成层不触发回流；`display:none` 从文档流移除触发回流，`visibility:hidden` 只触发重绘。
- **边界**：HTML 层面的手段有限——`img`/`video` 声明 `width`/`height` 占位防布局抖动（CLS）、不用 `table` 布局（一行改动整表回流）、CSS 统一放 `<head>`。
- **追问**：读写分离是 JS 层的优化，HTML 层能做的是"从一开始就不制造回流点"。

### Q12: 表单校验链路（原生 → JS → 后端）怎么走？（第 2 篇）

- **结论**：三层防线——浏览器原生校验 → JS 校验 → 服务端校验，层层兜底、各司其职。
- **原理**：原生层用 `type`/`required`/`pattern`/`min`/`max` 约束，配合 `:invalid` 伪类与 `form.reportValidity()` 提示；JS 层做复杂联动校验与防重复提交；服务端是最终防线——前端校验可被 `curl` 直接绕过，只防君子不防黑客。
- **边界**：前端校验是"体验优化"不是"安全手段"；服务端不校验等于把脏数据写进数据库。
- **追问**：`novalidate` 关掉原生校验后必须用 `form.checkValidity()` 手动兜底，别让 HTML5 校验变成摆设。

### Q13: `template` / `slot` 与组件化的关系？（第 1 篇）

- **结论**：`template` 是惰性模板（不渲染、可克隆复用），`slot` 是插槽占位（父组件向子组件注入内容），是原生组件化的两块基石。
- **原理**：`template` 的内容是 `DocumentFragment`，不挂载就解析子资源；`slot` 配合 Web Components（`custom element` + Shadow DOM）让组件可组合，Vue/React 的具名插槽与 `children` 也是同一思想。
- **边界**：`template` 需 JS `content.cloneNode()` 后使用，不自动渲染；`slot` 是 Web Components 概念，框架内有对应实现。
- **追问**：`template` 里的脚本不会执行、图片不会加载，这是它"惰性"的本质。

### Q14: SPA 与 MPA 的 SEO 差异？（第 1 篇）

- **结论**：SPA 内容由 JS 在客户端生成，爬虫可能看不到；MPA 每页独立 HTML，天生利于 SEO。
- **原理**：爬虫执行 JS 的能力有限（Google 能执行但会降级），SPA 首屏 HTML 常是空壳 `#root`；内容型站点靠 SSR/SSG 预渲染 + 路由级 meta 补救。
- **边界**：后台管理系统、需要登录的页面没有 SEO 需求，SPA 是正确选择；判断依据是"内容是否需要被公开检索"。
- **追问**：SSR/SSG 能把首屏 HTML 提前生成，但动态交互仍要客户端水合（hydration）。

### Q15: 语义化 DOM 对 AI 程序化抽取的价值？（第 1 篇）

- **结论**：结构化的语义 DOM 让 AI / 程序化工具能稳定、低成本地抽取内容，是"AI 可读"的基础。
- **原理**：AI 与爬虫抽取内容依赖文档结构——标题层级（大纲）、`article` 边界、列表与表格语义；裸 `div` 的"div 汤"只能靠猜，抽取不稳定。
- **边界**：AI 解析能力在进步，但结构化数据（`aria-label`、微格式）依然显著提升抽取准确率与召回率。
- **追问**：语义化从"给读屏器看"升级为"给 AI 看"，同一份结构投资在可访问性与 AI 消费上双份回报。

### Q16: `viewport-fit=cover` 与安全区 `env()` 的配合？（第 1 篇）

- **结论**：`viewport-fit=cover` 让页面延伸到刘海屏安全区，`env(safe-area-inset-*)` 读取安全区做 padding 补偿。
- **原理**：默认 `auto` 下页面被限制在安全区内，`cover` 后页面铺满圆角 / 刘海区域，正文可能被遮挡；`env()` 返回上下左右的 inset 像素，配合 `padding` / `padding-bottom` 避让。
- **边界**：非 iOS 全面屏 `env()` 返回 0，不生效也不报错；用了 `cover` 却不做安全区 padding 会把按钮顶到刘海下。
- **追问**：`constant()` 是 iOS 11.0-11.2 的旧写法，`env()` 是新标准，两者可同时写做兼容。

### Q18: 如何用 Vite 插件在 `<head>` 后注入内联错误监控脚本？（附录）

- **结论**：用 `transformIndexHtml` 钩子在 `<head>` 标签后切片插入内联 `<script>`。
- **原理**：监控脚本必须最早执行才能捕获 polyfill 与业务代码之前的错误；内联零网络延迟；`enforce:'post'` 保证在 legacy 等插件之后执行、不被覆盖。
- **边界**：若插到 `<body>` 末尾，会漏掉 `<head>` 解析期间发生的错误——所以必须插 `<head>` 后。
- **追问**：内联 vs 外部 `src` 选哪个？→ 必须内联，外部脚本有网络延迟，期间的错误漏报。

### Q19: `crossorigin` 对错误监控堆栈获取的作用？（附录）

- **结论**：`crossorigin="anonymous"` 让跨域脚本错误能拿到堆栈，否则浏览器只上报一句 `Script error.`。
- **原理**：默认跨域脚本抛错被浏览器吞掉细节（安全策略）；加 `crossorigin` 后浏览器以 CORS 模式加载，配合服务器返回 `Access-Control-Allow-Origin` 才能拿到完整堆栈。资源错误不冒泡，必须用 `window.addEventListener('error', fn, true)` 捕获阶段监听。
- **边界**：`crossorigin="anonymous"` 要求服务器响应 CORS 头，否则脚本**不执行**——加了属性就得配服务器，二选一别只加一半。
- **追问**：`use-credentials` 变体会带 Cookie 走 CORS，静态资源监控用 `anonymous` 即可。

## 三、排障与选型

### Q11: H5 活动页首屏白屏，怎么从 HTML 层定位与优化？（第 1 篇）

- **结论**：按"脚本阻塞 → 渲染阻塞 → 首屏报错 → 资源过慢"四层排查，优化顺序是先让错误可见再动手。
- **原理**：同步脚本阻塞 HTML 解析、CSS 阻塞渲染、首屏 JS 报错导致渲染中断、跨域资源无预连接拖慢关键链路——白屏往往是几类问题叠加。
- **边界**：方法论是"先监控（错误可见）→ 再数据定位 → 最小改动修复"，没有监控就优化等于盲改。
- **追问**：LCP 图如果 `loading="lazy"`，最大内容会被推迟到滚动才加载，首屏白屏感更强。

### Q17: `user-scalable=0` 的可访问性代价与业务取舍？（第 1 篇）

- **结论**：禁用缩放违反 WCAG 文本缩放要求（1.4.4 需支持 200% 缩放），是可访问性风险，业务上要显式取舍。
- **原理**：WCAG 要求用户能放大文本；iOS 上 `user-scalable=no` 已被 Safari 强制忽略，Android 上仍可被禁；活动页禁缩放多为防误触放大，属体验妥协。
- **边界**：优先用 `minimum-scale` / `maximum-scale` 限制区间而不是完全禁用；残留的 `user-scalable=0` 要列入可访问性优化清单。
- **追问**：面试时主动说出"这是 A11Y 风险，我已列入优化清单"，比装作不知道更能加分。
