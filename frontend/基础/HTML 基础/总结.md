## 1. 文档结构与语义化

### 1.1 标签形态与文档骨架

HTML 用**标签**描述"这里是什么内容"，标签分三种形态：

```
成对标签    <p>段落</p>        开始 <p> + 结束 </p>
自闭合标签  <img src="a.png" />  没内容、不需结束标签
            <br />              换行
```

- 标签会嵌套出层级（**父 / 子 / 兄弟**），写时要正确嵌套、有缩进、命名见名知意。

每个页面都长一个固定的骨架：

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>我的网页</title>
    <meta name="description" content="页面描述，用于 SEO" />
  </head>
  <body>
    <h1>你好，世界！</h1>
  </body>
</html>
```

| 部分 | 作用 |
| ---- | ---- |
| `<!DOCTYPE html>` | 声明 HTML5，让浏览器用标准模式渲染 |
| `<html>` | 根元素，`lang` 声明页面语言 |
| `<head>` | 元信息（`title`/`meta`/`link`/`style`），不显示 |
| `<body>` | 所有可见内容 |

> `meta` 里的 `name="description"` 是给搜索引擎看的描述，别漏。

### 1.2 文档头部：meta 与渲染模式

`meta` 是文档的"元信息"，不显示但影响编码、SEO、移动适配。三类常用 `meta`：

| meta | 作用 |
| ---- | ---- |
| `<meta name="keywords" ...>` | 关键词（早期 SEO 用，现已基本失效） |
| `<meta name="author" ...>` | 作者信息 |
| `<meta name="robots" content="noindex">` | 告诉爬虫是否收录/跟链（`noindex`/`nofollow`） |
| `<meta http-equiv="refresh" content="0;url=...">` | 页面重定向 / 定时刷新 |
| `<meta http-equiv="X-UA-Compatible" content="IE=edge">` | 兼容旧 IE 的渲染模式（legacy 项目） |

viewport 字段逐个说清楚：

| 字段 | 含义 |
| ---- | ---- |
| `width=device-width` | 布局视口宽度 = 设备宽度 |
| `height` | 视口高度（极少用） |
| `initial-scale` | 初始缩放比例 |
| `maximum-scale` / `minimum-scale` | 最大 / 最小缩放 |
| `user-scalable` | 是否允许用户缩放（禁用违反可访问性） |

**`<!DOCTYPE html>` 到底做了什么**：不带它，浏览器可能进**怪异模式（Quirks Mode）**，按旧 IE 的怪癖规则渲染，你写的 CSS 会表现得怪。声明它 = 让浏览器开**标准模式**。一句话：DOCTYPE 是告诉浏览器"按谁的规则渲染"的开关。

### 1.3 语义化：结构即含义

语义化 = **用含义贴切的标签**描述内容，核心价值是让机器（爬虫 / 读屏器）读懂结构树。先用一张页面看全景：

```html
<header>   <!-- 页头：Logo、导航 -->
  <h1>我的博客</h1>
  <nav><a href="#">首页</a><a href="#">关于</a></nav>
</header>
<main>     <!-- 主体（每页建议一个） -->
  <article>
    <h2>文章标题</h2>
    <section><h3>小节</h3><p>正文</p></section>
  </article>
  <aside><h3>侧边栏</h3></aside>   <!-- 独立但相关的辅助内容 -->
</main>
<footer>   <!-- 页脚：版权 -->
  <p>© 2026</p>
</footer>
```

语义化标签的分工可以画成一棵树：

```
<header>  页面或区块的头部
  └─ <nav>   导航链接集合
<main>    主体内容（每页建议一个）
  ├─ <article>  独立可复用内容（一篇博客、一条新闻）
  │   └─ <section>  有主题的子区块
  └─ <aside>   侧边栏，独立但相关的辅助内容
<footer>  页面或区块的底部
```

| 标签 | 用途 |
| ---- | ---- |
| `header` / `footer` | 页面或区块的头部 / 底部 |
| `nav` | 导航链接 |
| `main` | 主体（每页一个） |
| `article` | 独立可复用内容（一篇博客、一条新闻） |
| `section` | 有主题的区块 |
| `aside` | 侧边栏 |

反例：用一堆 `<div>` 硬堆（`<div class="header">`）。`div` 没含义；语义化让你一眼看懂结构，也让机器看懂。`div`/`span` 仍有用，但**优先语义化**。

### 1.4 常用内容标签与全局属性

常用内容标签按用途分：

- **标题** `h1`~`h6`：层级按序，`h1` 每页一个。
- **文本**：`p` 段落、`strong` 加粗强调、`em` 斜体、`mark` 高亮、`pre` 保留空格/换行。
- **列表**：`ul` 无序、`ol` 有序、`dl`/`dt`/`dd` 定义列表。
- **链接** `<a>`：`href` 目标；`target="_blank"` 新窗口；页面内用 `href="#id"` 锚点。
- **图片** `<img>`：`src` 必填，`alt` 强烈建议（图挂时的文字，也是无障碍/SEO 信息）。
- **表格**：`table > thead/tbody > tr > th/td`；`colspan` 跨列、`rowspan` 跨行。

**全局属性**（任意标签可用）：

| 属性 | 作用 |
| ---- | ---- |
| `id` | 页面内唯一（JS/锚点用） |
| `class` | 可多个空格分隔（CSS/JS 定位） |
| `data-*` | 自定义数据，JS 用 `dataset` 读取 |
| `hidden` | 隐藏元素 |

```html
<div id="app" class="container" data-uid="1001">…</div>
<script>document.querySelector("div").dataset.uid; // "1001"</script>
```

### 1.5 进阶语义：响应式图片与精细标签

**响应式图片**：同一张图在不同设备给不同规格，不用 CSS 也能做，两条路线：

```
srcset / sizes —— 按屏幕宽度选图（纯 HTML 属性）
  600w / 1200w  告诉浏览器图片真实宽度，由它按屏幕宽度选资源
  sizes         提示图片最终展示宽度
picture + source —— 按媒体条件换源（更精细）
  source media="(min-width: 900px)" → 命中即切换
  最后一个 <img> 必填，作不匹配任何 source 时的兜底
```

```html
<img src="small.jpg" srcset="small.jpg 600w, large.jpg 1200w"
     sizes="(max-width: 600px) 600px, 1200px" alt="说明" />

<picture>
  <source media="(min-width: 900px)" srcset="wide.jpg" />
  <source media="(min-width: 500px)" srcset="mid.jpg" />
  <img src="small.jpg" alt="兜底图" />   <!-- 最后一个 img 必填且作兜底 -->
</picture>
```

**更精细的语义标签**：

```html
<figure>
  <img src="chart.png" alt="销量图" />
  <figcaption>图1：年度销量（图注会跟着图走）</figcaption>
</figure>
<time datetime="2026-09-10">今天</time>   <!-- 机器可读时间，利于 SEO -->
<address>联系地址…</address>
<details><summary>点我展开</summary>这里的内容默认收起</details>
```

- `figure` + `figcaption`：图片配图注，图注跟着图走。
- `time[datetime]`：机器可读时间，利于 SEO。
- `address`：联系地址等联系方式。
- `details` + `summary`：可折叠区块，默认收起、点 summary 展开。

**SEO 与 meta 优化前缀**：标题层级 `h1`（一个）→ `h6` 让爬虫读懂主次；`meta description` 显示为搜索结果摘要；`img` 的 `alt` 参与图片搜索与无障碍；`picture`/`figure`/`time` 提供更丰富语义给爬虫和读屏器。完整 SEO/性能策略属于后续工程化章节（参考 `网络与浏览器` 模块）。

### 1.6 脚本与资源加载

**`src` 与 `href` 的区别**：`href` 是"引用"，在当前文档与目标资源间**建立联系**（`<a>`、`<link>`），不替换内容、可并行下载不阻塞；`src` 是"加载并嵌入"（`<script>`、`<img>`、`<iframe>`），需下载后执行/渲染，浏览器解析到同步 `script` 时会**暂停解析**——这也是 JS 放底部 / 用 `defer` 的原因。

**`defer` 与 `async` 的区别**：两者都不阻塞 HTML 解析（下载与解析并行），区别在执行时机：

```html
<script defer src="a.js"></script>   <!-- 下载并行，HTML 解析完才执行，且按文档顺序 -->
<script async src="b.js"></script>   <!-- 下载并行，下载完立刻执行，不保序 -->
```

三种方式的执行时机对比：

| 方式 | 下载 | 执行时机 | 对 `DOMContentLoaded` 的影响 |
| --- | --- | --- | --- |
| 默认（同步） | 阻塞 HTML 解析 | 遇到即执行 | 推迟（解析被阻塞） |
| `defer` | 与解析并行 | 解析完成后、`DOMContentLoaded` 之前 | 推迟到脚本执行之后 |
| `async` | 与解析并行 | 下载完立即执行 | 不推迟 |

- `defer` 脚本"排在解析后面"，所以 `DOMContentLoaded` 要等它执行完才触发——适合依赖 DOM 的业务脚本。
- `async` 是"下载完插队即走"，`DOMContentLoaded` 不等它——适合独立无依赖的统计脚本。
- `type="module"`：自带 defer 语义 + 严格模式 + 模块作用域，Vite 产物入口默认用它。

> 预加载指令 `dns-prefetch` / `preconnect` / `preload` / `prefetch` 的选型详见 `网络与浏览器` 模块。

### 1.7 HTML5 新特性与 iframe

HTML5 新增的能力按用途分组：

- **语义化标签**：`header`/`nav`/`main`/`article`/`section`/`aside`/`footer`（见 1.3）。
- **媒体标签**：`<video>`、`<audio>` 原生播放音视频，配 `controls`/`autoplay`/`muted` 等属性。
- **表单增强**：新类型（`email`/`url`/`number`/`search`/`range`/`color`/`date`/`time`…）、新属性（`placeholder`/`autofocus`/`required`/`pattern`…）、原生约束校验——详见第 2 章。
- **进度条与度量器**：`<progress>`（任务进度，不确定值不加 `value`）与 `<meter>`（度量，如磁盘用量）。
- **Web 存储**：`localStorage`（持久）与 `sessionStorage`（会话级）——详见 `网络与浏览器`。
- **DOM 查询**：`document.querySelector()` / `querySelectorAll()`——详见 `JavaScript 核心`。
- **拖放**：`draggable` + `dragstart`/`dragover`/`drop` 事件实现拖拽。
- **画布**：`<canvas>` 提供 2D/3D 绘图 API。

**iframe 的优缺点**（在页面内嵌另一个文档）：

```
优点   加载慢的内容（广告）独立加载、并行下载脚本；
       可做跨子域通信与第三方内容嵌入（地图、支付表单）
缺点   阻塞主页面的 load 事件（要等 iframe 加载完）；
       部分搜索引擎不索引 iframe 内容；
       多个 iframe 产生多个独立文档，维护/调试成本高；
       安全上要防点击劫持（X-Frame-Options / frame-ancestors）
```

### 1.8 DOM 结构树：从 HTML 到结构树

浏览器拿到 HTML 后，会把它解析成一棵 **DOM 树**——每个标签变成树上一个节点，父子嵌套变成树的父子关系：

```
        <html>
       /      \
   <head>      <body>
              /      \
          <h1>       <p>
```

- 任何前端框架、JS 操作（`document.querySelector`）、爬虫解析，本质都是在这棵树上**找节点、挂事件**。
- **验证方式**：DevTools → Elements 面板显示的就是这棵树的实时样子，右键可增删改节点。详见浏览器渲染章节。

**为什么语义化能提升 SEO 与无障碍**：

- **对爬虫（SEO）**：它不"看"网页，只"读"结构树。`<nav>/<article>/<main>` 与 `h1` 层级能让它瞬间分清正文与导航，正确索引内容。
- **对读屏器（无障碍）**：闭眼靠听读屏器浏览。语义化让它能"跳过导航直接读正文"、"把图读成 alt 文字"。`div` 堆出的页面只会被读成一串无意义容器。

## 2. 表单与标签

### 2.1 表单基础：提交、输入控件与标签

**`<form>` 与提交**：

| `form` 属性 | 作用 |
| ---- | ---- |
| `action` | 数据发往的地址 |
| `method` | `get`（拼到 URL，适合搜索）或 `post`（放请求体，适合提交数据） |

提交时浏览器会**收集所有带 `name` 且非 `disabled` 的控件**去发送。**没有 `name` 的控件不会被带上，这是最常见的坑。**

**`<input>` 类型速查**：

```html
<input type="text" name="username" />      <!-- 文本 -->
<input type="password" name="password" />  <!-- 密码 -->
<input type="email" name="email" />        <!-- 邮箱（自带格式校验） -->
<textarea name="intro" rows="4"></textarea> <!-- 多行文本框：用 textarea，不是 input -->
<input type="radio" name="gender" value="male" /> 男  <!-- 单选（同组 name 只选一个） -->
<input type="checkbox" name="hobby" value="read" /> 阅读 <!-- 复选（可多选） -->
<select name="city">
  <option value="beijing">北京</option>
  <option selected>上海</option>   <!-- selected 默认选中 -->
</select>
<input type="file" name="avatar" />        <!-- 文件 -->
<input type="number" min="0" max="150" name="age" /> <!-- 数值 -->
<input type="date" name="birthday" />      <!-- 日期 -->
```

**HTML5 新增类型**（自带交互控件或格式校验）：`search` 搜索框（自带清除小叉）、`range` 滑块（配合 `min/max/value`）、`color` 颜色拾取器、`time`/`week`/`month`/`datetime-local` 时间类。

> 移动端数字输入优先 `inputmode="numeric"`；`date`/`time` 等类型在部分桌面浏览器上控件样式不统一，业务上常结合日期选择库使用。

**`<label>`：点文字聚焦控件**，两种写法：

```
隐式：<label>用户名：<input name="username" /></label>          标签包裹控件
显式：<label for="email">邮箱：</label>                         for 对应控件 id
      <input type="email" id="email" name="email" />
```

`label` 既是便利性（点文字聚焦/选中），也是无障碍：读屏器会把标签和控件绑在一起朗读。

### 2.2 表单属性、按钮与移动端细节

**常用属性**：

| 属性 | 作用 |
| ---- | ---- |
| `required` | 必填 |
| `placeholder` / `maxlength` | 占位提示 / 最大长度 |
| `pattern` / `min` `max` | 正则约束 / 数值范围 |
| `autocomplete` | 浏览器自动填充开关 |
| `autofocus` | 页面加载后自动聚焦该控件 |
| `multiple` | 允许选择多个值（`file` 多文件、`email` 多地址） |
| `form="表单id"` | 让**表单外的控件**归属到指定表单一起提交 |
| `readonly` / `disabled` | 只读（不可改但会提交）/ 禁用（不可交互且不提交） |

```html
<input type="file" name="files" multiple />          <!-- 多文件 -->
<input type="email" name="emails" multiple />        <!-- 逗号分隔多邮箱 -->
<input name="outside" form="reg" />                  <!-- 在 <form id="reg"> 外，仍随它提交 -->
```

**提交按钮三兄弟**：`<button>` 在表单内**默认是 `submit`**，想当普通按钮务必写 `type="button"`。

| `type` | 作用 |
| ---- | ---- |
| `submit` | 提交表单（默认） |
| `reset` | 重置为默认值 |
| `button` | 无默认行为，配合 JS |

**移动端 / 自动填充细节**：

- 手机端想让"数字键盘"弹出来，用 `inputmode="numeric"`（比 `type=number` 更稳）；
- 合理使用 `autocomplete`（`username`/`current-password`/`email`…）配合浏览器记住密码；
- 有明显依赖关系（二级城市跟随一级）时再交给 JS 做联动——原生只做"静态"约束。

### 2.3 原生约束校验

HTML5 内置校验，提交时自动拦截非法数据，不写 JS 也能拦：

```html
<form>
  <input type="text" name="username" required placeholder="用户名" />
  <input type="email" name="email" required />
  <input type="number" name="age" min="18" max="60" />
  <input name="phone" pattern="[0-9]{11}" placeholder="11 位手机号" />
  <button type="submit">注册</button>
</form>
```

**底层机制**：浏览器内置 **Constraint Validation**（约束校验 API）。流程本质是：

```
提交 → 逐一算 validity → 有错命中 :invalid 弹提示 → 拦截 invalid/submit
```

setCustomValidity 只是替换提示文案，机制由浏览器早就定好：

```
inp.validity.valueMissing     // 必填为空 → true
inp.validity.patternMismatch  // 不匹配正则 → true
inp.checkValidity()           // 是否全过 → true/false
inp.setCustomValidity("自定义错误") // 设为非空 → 判定为不通过
```

校验状态有 CSS 伪类可自定义样式：`:valid`（通过）/ `:invalid`（不通过）。

### 2.4 表单事件、FormData 与数据编码

**高频原生表单事件**：

- **`input`**：控件值每次变化都触发（比 `change` 更即时，`change` 在失焦/回车时才触发）——做实时校验、字数统计、搜索联想。
- **`invalid`**：原生校验**不通过**时触发——常配合 `setCustomValidity()` 替换默认英文气泡。

```js
phone.addEventListener("input", () => phone.setCustomValidity("")); // 输入时清空旧错误
phone.addEventListener("invalid", () =>
  phone.setCustomValidity("请填写 11 位手机号"));                   // 校验失败时替换提示
```

**FormData：以键值对读表单**，不逐个 `getElementById`，一次拿全表单（含文件）：

```js
const data = new FormData(form);
data.get("username");         // 单个
[...data.entries()];          // 全部键值对
Object.fromEntries(data);     // 转成对象
```

**数据如何编码**：

- **`get`**：把键值对拼成查询串挂在 URL（`/search?keyword=xx`），适合搜索、可收藏分享。
- **`post`**：放请求体，体积大、可含二进制。普通文本用 `application/x-www-form-urlencoded`（`a=1&b=2` 形式）；**上传文件**要把 `form` 的 `enctype` 设为 `multipart/form-data`，否则文件传不上去。

```html
<form action="/upload" method="post" enctype="multipart/form-data">
  <input type="file" name="file" />
  <button type="submit">上传</button>
</form>
```

**`preventDefault()` 到底阻止了什么**：提交的"默认行为"是 **收集数据 → 按 method 编码 → 跳转/刷新到 action 地址**。`preventDefault()` 把这个浏览器内置流程掐断、把控制权交回你的 JS。同理也能阻止 `<a>` 默认跳转、`<input type=checkbox>` 默认勾选。一句话：它不是在"停下执行"，而是"关掉浏览器帮我做的那个默认动作"。

**完整一环**（原生约束 + 自定义提示 + JS 拦截 + FormData 提交）：

```html
<form id="reg" method="post" novalidate>
  ...
  <button type="submit">注册</button>
</form>
<script>
  phone.addEventListener("input", () => phone.setCustomValidity(''));
  document.querySelectorAll('input').forEach(inp =>
    inp.addEventListener("invalid", () => inp.setCustomValidity("请按格式填写")));
  form.addEventListener("submit", (e) => {
    e.preventDefault();               // 阻止页面跳转
    if (!form.checkValidity()) return; // 未通过则停
    const data = Object.fromEntries(new FormData(form));
    console.log("提交的数据：", data);
  });
</script>
```

`novalidate` + `checkValidity()` 是"仍用原生校验、但要自定义展示"的常用组合；真正的数据发送（`fetch`）在 `网络与浏览器` 展开。

## 3. 无障碍与可访问性

### 3.1 无障碍树：role / name / state

无障碍做的绝大部分事情**是把标签用对**。前面讲的是标签怎么写，这里讲**怎么验证它们真的生效**。关键在一个看不见的结构：

```
浏览器把 DOM 翻译成 → 无障碍树（accessibility tree）
  每个节点带三个字段
    role   这是什么        button / textbox / heading / generic
    name   怎么念它        提交 / 搜索 / 手机号
    state  当前什么状态    展开 / 禁用 / 当前页

读屏软件、语音控制、部分自动化工具读的都是这棵树
你写的是标签，它们看到的是树
```

同一组控件写两遍（一遍故意写坏、一遍改对），树里的差别逐条可比（用 CDP 的 `Accessibility.queryAXTree` 直接读浏览器算好的 role 与 name）：

```
坏例子（div 假按钮 + 纯图标按钮）
  role = "generic"  name = ""        ← div 装的"提交"
  role = "StaticText"  name = "提交"
  role = "button"  name = ""          ← 没名字的图标按钮

改对（真 button + aria-label）
  role = "button"  name = "提交"      ← 文本自动成为 name
  role = "button"  name = "搜索"      ← aria-label 补的名字
```

结论：**外观与语义可以脱节**。`<div>` 装得像按钮、看得像按钮，但树里 role 是 `generic`，读屏按"按钮"跳转时跳不到它、也不知道它可点；真 `<button>` 的 role 是 `button`，文字自动成为 name。外观骗得过人眼，骗不过树。

### 3.2 原生标签优先与可访问名

**ARIA 是语义补丁不是行为补丁**。把一个 `div` 硬改成 `role="button"` 之后，原生 `<button>` 免费给的东西全要自己补：

| 原生 `<button>` 免费给你的 | `<div role="button">` 要自己补的 |
| --- | --- |
| role 是 `button` | `role="button"` |
| 能 Tab 聚焦 | `tabindex="0"` |
| 回车/空格触发 click | 监听 `keydown` 判断 `key === 'Enter'`/`' '`（还要 `preventDefault` 防滚动） |
| 禁用态 | `aria-disabled` 或 `disabled`（前者还要自己拦 click） |
| 读屏报"按钮" | 同上，靠 role |
| 表单里参与提交 | 自己处理 |

漏任何一条，就得到"看起来能用、用键盘或读屏时坏掉"的控件。所以顺序永远是：**先选对标签 → 确实没有原生方案时（自绘下拉/树/标签页）再用 ARIA 补语义**，且补语义的同时把键盘行为也补上。

实测「能不能聚焦」：`focus()` 对不可聚焦的元素是空操作，比对 `document.activeElement`：

```
div 假按钮：focus() 后 activeElement 仍是 body → 不可聚焦，tabIndex = -1
真 button ：focus() 后 activeElement 就是它自己 → 可聚焦，tabIndex = 0
```

**可访问名（name）**：读屏怎么念这个控件，计算有明确的优先级：

```
1. aria-labelledby 指向的元素文本   （最高，可跨元素拼接）
2. aria-label 属性
3. 原生关联的 <label for> / <label> 包裹 / <caption>
4. 元素自己的文本内容（按钮、链接）
5. 内部 img 的 alt、title 等兜底
```

三个实用要点：

- **图标按钮必须显式给名字**。`<button>` 里只有一个 `<svg>`（再标 `aria-hidden="true"`），树里 `name` 就是空。用 `aria-label`（或视觉隐藏文字）补上。
- **`title` 是最后的兜底，不可靠**：要鼠标悬停才显示、移动端基本没有、触屏和键盘用户都拿不到。
- **`aria-label` 会覆盖可见文本**。给"提交"写 `aria-label="提交订单"`，用户看到"提交"、读屏听到"提交订单"——语音控制用户喊"点击提交"可能就点不中。可见文本与可访问名尽量一致。

### 3.3 图片 alt 与对比度

**`alt` 的三种写法**：

| 写法 | 含义 | 无障碍树里 |
| --- | --- | --- |
| `alt="示例站点图标"` | **有信息**：把图里的信息说出来 | `role = "image" name = "示例站点图标"` |
| `alt=""` | **纯装饰**：明确告诉辅助技术跳过我 | 不作 image 出现（被标 presentational，整棵树找不到） |
| 不写 `alt` | **不知道**：读屏只能念"图像"或念文件名 | `role = "image" name = ""` |

关键：**"不写 alt" 与 `alt=""` 不是一回事**。前者是"我忘了"，后者是"我确认它是装饰"。`alt=""` 的目的不是省事，而是让装饰图从无障碍树里消失、不把噪音念给用户。

**对比度：可读性的下限**（WCAG 硬指标）：

| 内容 | 阈值 |
| --- | --- |
| 正文 | 4.5:1 |
| 大字（≥ 24px，或 ≥ 18.66px 加粗） | 3:1 |
| 图标 / 边框等非文本内容 | 3:1 |

```
对比度 = (亮色 + 0.05) / (暗色 + 0.05)
"亮度"不是颜色平均，而是按相对亮度公式算：
  先做 sRGB 反伽马，再按人眼对三种原色的敏感度加权
```

实践要点：**不要靠眼睛估**。灰字白底实测 `#999999` 只有 2.85:1（远低于 4.5:1，看起来"灰得挺清楚"但机器判不合格），换成 `#4b5563` 就是 7.56:1。Chrome DevTools 颜色选择器直接显示对比度与等级；要按感知调灰可用现代 CSS 的 `oklch()`（详见 `CSS` 模块）。

### 3.4 键盘、焦点、结构与状态

**键盘可达与焦点可见**（三条规则按重要性排列）：

1. **所有交互都能用键盘完成**——Tab 走一遍能不能提交表单、关弹窗、展开下拉，是比任何静态检查更有效的验收方式。
2. **Tab 顺序就是 DOM 顺序**——不要用 CSS 把视觉顺序和 DOM 顺序调成两回事（`flex-direction: row-reverse` 配不同 DOM 顺序，会让键盘顺序和眼睛看到的对不上）。`tabindex` 只用 `0`（进 Tab 序）和 `-1`（可被 `focus()` 但不在 Tab 序，适合模态框与错误跳转）；**正值会插队打乱整页顺序，不要用**。
3. **焦点必须可见**——`:focus` 是键盘用户唯一的"我在哪"指示器，`outline: none` 把它删掉等于让键盘用户盲操作。要自定义就**替换而不是删除**（`outline: 2px solid #2563eb; outline-offset: 2px`）；`:focus-visible` 只在"用户可能需要知道焦点在哪"时匹配（键盘导航匹配、鼠标点击不匹配），可实现"键盘用户看得到、鼠标用户不被打扰"。

焦点还有两处需主动管理：

- **模态框**：打开时焦点移进去、Tab 限制在框内（焦点陷阱），关闭后把焦点**还给触发它的元素**。
- **单页应用路由切换**：整体替换内容后焦点回 `body`，读屏用户不知道页面变了。切完把焦点移到新页面 `<h1>`（给它 `tabindex="-1"`）是最省事的做法。

**结构与状态**（让读屏能"跳读"）：

- **标题层级**只能一级一级往下走（`h1 → h2 → h3`）。注意：**层级问题不体现在 role 上**——树里 `h4` 与 `h3` 的 role 都是 `heading`，必须单独查文档结构。
- **地标（landmark）**：`header`/`nav`/`main`/`aside`/`footer` 各对应一个 landmark，读屏可整块跳转；一个页面只应有一个 `main`。
- **状态靠 ARIA 补**：

| 属性 | 用在哪 | 效果 |
| --- | --- | --- |
| `aria-expanded` | 折叠面板、下拉触发按钮 | 读屏念"已展开/已折叠" |
| `aria-current="page"` | 导航里当前页那项 | 读屏念"当前页"，不必只靠高亮色 |
| `aria-live="polite"` | 表单提示、异步结果区 | 内容变化时读屏主动播报（不打断用户） |
| `aria-live="assertive"` / `role="alert"` | 错误提示 | 立刻打断播报 |
| `aria-hidden="true"` | 纯装饰图标、重复文本 | 从无障碍树隐藏 |

两个容易踩的坑：

- **`aria-hidden="true"` 不要用在可聚焦元素上**——读屏忽略它、键盘还能 Tab 到它，形成"看得见但听不见"的幽灵焦点。真正的做法是同时把它移出 Tab 序。
- **ARIA 写错不报错**——`aria-lable`、`aria-live` 拼错、属性乱放，浏览器一律静默忽略，树里没效果、控制台也没提示。改完 ARIA 一定要回到无障碍树里确认。

**别只用颜色传达信息**——错误画红、必填标红星、图表靠颜色分系列，对色盲用户（男性约 8%）是无效信息。任何时候都要有第二个通道：错误用文字写出来、必填在 label 里写明、图表加线型或标记。

### 3.5 表单无障碍与验收

**表单无障碍**的要点：

- **placeholder 不能替代 `<label>`**。树里浏览器会把 placeholder 当作可访问名兜底（所以读得出"手机号"），但 placeholder 在用户开始输入后就消失、措辞也常与真实标签不一致。`<label for>` + `<input id>` 的收益是双份的：读屏能念出标签、鼠标用户点标签文字也能聚焦输入框（点击热区从一个小方块变成词组）。
- **错误提示四件套**，别只用红框：

```html
<label for="phone">手机号</label>
<input id="phone" aria-invalid="true" aria-describedby="phone-err" />
<p id="phone-err" role="alert">手机号需要 11 位数字</p>
```

`aria-describedby` 把错误文本挂到控件上，读屏聚焦输入框时会一起念出来——这是红框永远做不到的。

- **单选/多选组**用 `fieldset` + `legend` 把"这是哪一组"包进去，否则读屏只会念出一串孤立的选项。

**一份可执行清单**（覆盖实际项目 90% 的无障碍问题）：

1. 能用原生标签就用原生标签（`button`/`a`/`input`/`label`/`details`…）。
2. 每张图都有 `alt`：有信息就描述，纯装饰写 `alt=""`。
3. 每个表单控件都有 `<label>`；`placeholder` 只是提示，不是标签。
4. 标题一级一级往下走，`h1` 每页一个。
5. 焦点永远可见；要用 `:focus-visible` 自定义，不要 `outline: none`。
6. 键盘（Tab + Enter + 空格 + Esc）能走完全部流程。
7. 正文对比度 ≥ 4.5:1，大字与非文本内容 ≥ 3:1。
8. 不用颜色单独传达信息。
9. 需要动效时尊重 `prefers-reduced-motion`（见 `现代 CSS`）。
10. 用真读屏跑一遍：Windows 讲述人（Win + Ctrl + Enter）、macOS VoiceOver（Cmd + F5）。

**验收方式**：自动化工具（Lighthouse、axe、示例检查器）能覆盖前 8 条的相当一部分，但**只能发现 30%~40% 的问题**——它擅长查"属性写没写"（alt、label、对比度），不擅长查"顺序对不对、读起来顺不顺"。第 6 条（纯键盘走流程）与第 10 条（真读屏听一遍）只能人工验。
