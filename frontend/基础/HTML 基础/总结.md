# 模块总结 · HTML 基础

## 知识主线

三篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 HTML 语义化与结构（骨架怎么搭、结构怎么被机器读懂）  ★主轴
        │  页面搭好了只能看不能填，怎么把用户的输入收回来、发出去？
        ▼
02 表单与标签（输入怎么收集、校验、编码与提交）
        │  标签选对了、表单能用了，但键盘用户与读屏用户真的能用吗？怎么验证？
        ▼
03 无障碍与可访问性（从标签到无障碍树：role / name / 对比度 / 键盘）
```

本模块的主轴是**语义化**：01 建立"结构即含义"——语义化标签让 HTML 被解析成的 DOM 树对爬虫（SEO）与读屏器（无障碍）可读，这是整章的地基；02 的表单本质也是标签语义的一部分，`label`/`type`/`name` 的语义让表单既能被浏览器正确收集数据、也能被读屏器朗读，`required`/`pattern` 则把校验也"语义化"成浏览器原生能力；03 把前两篇说的"语义"落到可验证的层面——浏览器会把 DOM 再翻译成一棵**无障碍树**（`role` + `name`），那才是辅助技术真正读到的东西，`div` 装的按钮在这棵树里永远不是按钮。三篇合起来回答一件事：网页是什么结构、它怎么与用户交互，以及这些结构在机器眼里到底成了什么。

## 分篇知识点

### 01-HTML 语义化与结构

- **文档骨架三件套**
  - **`<!DOCTYPE html>`**：声明 HTML5、让浏览器走标准模式渲染；缺少时可能进入怪异模式（Quirks Mode），CSS 表现会失真
  - **`<html>`**：根元素，用 `lang="zh-CN"` 声明页面语言
  - **`<head>`**：放元信息（`title`/`meta`/`link`/`style`），页面不显示
  - **`<body>`**：承载所有可见内容
  - **`<meta>`**：`charset` 声明字符集；`name="viewport" content="width=device-width, initial-scale=1.0"` 是移动端布局的关键；`name="description"` 是给搜索引擎的页面摘要
  - **`<title>`**：浏览器标签页标题
- **语义化 = 用含义贴切的标签描述内容**
  - **核心价值**：让爬虫（SEO）与读屏器（无障碍）读懂结构树；用一堆 `<div>` 堆出的页面只会被读成无意义容器
  - **`header` / `footer`**：页面或区块的头部 / 底部
  - **`nav`**：导航链接集合
  - **`main`**：主体内容，每页建议一个
  - **`article`**：独立可复用内容（一篇博客、一条新闻）
  - **`section`**：有主题的区块
  - **`aside`**：侧边栏，独立但相关的辅助内容
- **进阶语义标签**
  - **`figure` + `figcaption`**：图片配图注，图注会跟着图走
  - **`time[datetime]`**：机器可读时间，利于 SEO
  - **`address`**：联系地址等联系方式
  - **`details` + `summary`**：可折叠区块，内容默认收起、点 summary 展开
- **响应式图片**
  - **`srcset` / `sizes`**：`600w/1200w` 告诉浏览器图片真实宽度，由它按屏幕宽度选资源；`sizes` 提示图片最终展示宽度
  - **`picture` + `source`**：按 `media` 媒体条件换源，比 `srcset` 更精细
  - **兜底 `<img>`**：`picture` 里最后一个 `<img>` 必填，作为不匹配任何 source 时的兜底
- **全局属性**
  - **`id`**：页面内唯一，供 JS 与锚点定位
  - **`class`**：可多个空格分隔，供 CSS/JS 定位
  - **`data-*`**：自定义数据，JS 用 `dataset` 读取
  - **`hidden`**：隐藏元素
- **DOM 结构树**
  - **解析过程**：HTML 被解析成 DOM 树，标签变节点、父子嵌套变树形关系
  - **谁在树上工作**：前端框架、JS（`querySelector`）、爬虫本质都是在这棵树上找节点与挂事件
  - **验证方式**：DevTools → Elements 面板显示的就是这棵树的实时样子，可增删改节点
- **语义化的价值**
  - **SEO（爬虫）**：爬虫不"看"网页、只"读"结构树，`nav`/`article`/`main` 与 `h1` 层级让它分清正文与导航、正确索引内容
  - **无障碍（读屏器）**：能"跳过导航直接读正文"、"把图读成 alt 文字"
  - **`alt`**：图片加载失败时的替代文字，参与图片搜索与无障碍
- **常用 meta 标签**
  - **SEO/信息类**：`keywords`（已基本失效）、`author`、`robots`（`noindex`/`nofollow`）
  - **行为类**：`http-equiv="refresh"`（重定向/定时刷新）、`http-equiv="X-UA-Compatible"`（legacy IE 渲染模式）
  - **viewport 字段**：`width=device-width`、`initial-scale`、`maximum-scale`/`minimum-scale`、`user-scalable`（禁用违反可访问性）
- **脚本与资源加载**
  - **`src` vs `href`**：`href` 建立联系不替换内容、并行不阻塞；`src` 加载并嵌入，同步 `script` 会暂停解析
  - **`defer`**：下载与解析并行，HTML 解析完按文档顺序执行，在 `DOMContentLoaded` 前
  - **`async`**：下载完立刻执行、不保序，适合独立统计脚本
  - **`type="module"`**：自带 defer 语义 + 严格模式 + 模块作用域
- **HTML5 新特性**
  - **媒体标签**：`video` / `audio` 原生播放，配 `controls`/`muted` 等
  - **表单增强**：新类型 / 新属性 / 原生约束校验（详见 02 篇）
  - **进度度量**：`progress`（任务进度）/ `meter`（度量值）
  - **其他**：`localStorage`/`sessionStorage`（网络模块）、`querySelector`（JS 模块）、拖放、`canvas`
- **iframe**
  - **优点**：独立加载慢内容（广告）、并行下载脚本、跨子域嵌入第三方内容
  - **缺点**：阻塞主页面 `load`、不被搜索引擎索引、多文档难维护，需防点击劫持（`X-Frame-Options`）

### 02-表单与标签

- **提交三件套**
  - **`action`**：表单数据发往的地址
  - **`method`**：`get` 把键值对拼到 URL（适合搜索、可收藏分享）；`post` 放请求体（适合提交数据、可含二进制）
  - **控件 `name`**：提交时浏览器只收集带 `name` 且非 `disabled` 的控件——**没有 `name` 的控件不会被提交**，是最常见的坑
- **控件速查**
  - **`input` 单行类型**：`text`/`password`/`email`（自带格式校验）/`number`（配 `min`/`max`）/`date`/`file`
  - **HTML5 新类型**：`search`（自带清除叉）/`range`（滑块）/`color`/`time`/`week`/`month`/`datetime-local`
  - **`textarea`**：多行文本框，用 `textarea` 而不是 `input`
  - **`radio` / `checkbox`**：单选（同组 `name` 只选一个）/ 复选（可多选）
  - **`select` + `option`**：下拉选择，`selected` 设默认选中
  - **`label for=id`**：点文字也能聚焦/选中控件，同时服务读屏器（标签与控件绑定朗读）
  - **提交按钮三兄弟**：`submit`（默认，提交表单）/`reset`（重置为默认值）/`button`（无默认行为、配合 JS）；表单内想当普通按钮务必写 `type="button"`
- **常用属性**
  - **`placeholder` / `maxlength`**：占位提示 / 最大长度限制
  - **`autofocus`**：页面加载后自动聚焦
  - **`multiple`**：`file` 多文件、`email` 多地址
  - **`form="表单id"`**：让表单外的控件归属指定表单一起提交
  - **`readonly` vs `disabled`**：只读（不可改但会提交） vs 禁用（不可交互且不提交）
  - **`autocomplete`**：浏览器自动填充开关，配 `username`/`current-password`/`email` 配合浏览器记住密码
  - **`inputmode="numeric"`**：手机端弹数字键盘（比 `type=number` 更稳）
- **表单事件**
  - **`input`**：控件值每次变化触发（比 `change` 更即时）——实时校验、字数统计、搜索联想
  - **`invalid`**：原生校验不通过时触发，配 `setCustomValidity()` 替换默认英文气泡
- **原生约束校验**
  - **约束属性**：`required`（必填）、`pattern`（正则约束，如 `[0-9]{11}`）、`min`/`max`（数值范围）——不写 JS 也能拦
  - **底层机制**：浏览器内置 Constraint Validation API，流程是「提交 → 逐一算 `validity` → 有错命中 `:invalid` 弹提示 → 拦截」
  - **API**：`validity`（`valueMissing`/`patternMismatch` 等布尔位）、`checkValidity()` 返回是否全过、`setCustomValidity()` 自定义错误文案
  - **CSS 伪类**：`:valid` / `:invalid` 定制校验状态的样式
- **编码与上传**
  - **`get` 编码**：键值对拼成查询串挂 URL（`/search?keyword=xx`），适合搜索、可收藏分享
  - **`post` 编码**：放请求体，普通文本用 `application/x-www-form-urlencoded`（`a=1&b=2` 形式）
  - **文件上传**：`form` 的 `enctype` 必须设为 `multipart/form-data`，否则文件传不上去
- **FormData**
  - **用途**：一次拿全表单（含文件），替代逐个 `getElementById`
  - **读取方式**：`data.get(name)` 取单个、`data.entries()` 取全部键值对、`Object.fromEntries(data)` 转成对象
- **preventDefault() 的本质**
  - **默认行为**：提交的默认流程是「收集数据 → 按 method 编码 → 跳转/刷新到 action 地址」
  - **作用**：`preventDefault()` 掐断这个浏览器内置流程、把控制权交回 JS；同样能阻止 `<a>` 默认跳转、`checkbox` 默认勾选
  - **常用组合**：`novalidate` + `checkValidity()` 是"仍用原生校验、但要自定义展示"的常用组合

### 03-无障碍与可访问性

- **无障碍树（a11y tree）**
  - **它才是辅助技术看到的东西**：浏览器把 DOM 翻译成 `role`（是什么）+ `name`（怎么念）+ `state`（什么状态），读屏 / 语音控制 / 自动化工具读的都是它
  - **外观与语义可以脱节**：`div` 装的按钮在树里 role 是 `generic`，读屏按"按钮"跳转时跳不到、也不认为它可点
  - **验证方式**：CDP 的 `Accessibility.queryAXTree` 直接读出浏览器算好的 role 与 name
- **原生标签优先**
  - **ARIA 是语义补丁不是行为补丁**：`role="button"` 不带来 Tab 聚焦、键盘触发、禁用态，全要自己补
  - **实测差别**：`div.focus()` 后 `activeElement` 仍是 `body`、`tabIndex = -1`；真 `button` 是它自己、`tabIndex = 0`
  - **ARIA 第一规则**：有原生方案就用原生方案；只有自绘控件才补 ARIA，且必须同时补键盘行为
- **可访问名（name）**
  - **优先级**：`aria-labelledby` → `aria-label` → 原生 `label` → 自己的文本 → 内部 `img` 的 `alt` / `title`
  - **图标按钮必须显式命名**：只放 `<svg>` 的按钮在树里 `name` 为空，读屏只会念"按钮"
  - **一致性**：`aria-label` 会覆盖可见文本，两边尽量一致；`title` 只是不可靠的兜底
- **图片 alt 的三种写法**
  - **有信息**：写具体描述；**纯装饰**：`alt=""`（树里整张图不再出现）；**不写**：树里留下 `role="image" name=""`
  - **"不写 alt" 与 `alt=""` 是两件事**：前者是遗漏（读屏可能念文件名），后者是明确声明"跳过我"
- **对比度**
  - **阈值**：正文 4.5:1、大字（≥ 24px 或 ≥ 18.66px 加粗）3:1、图标与边框 3:1
  - **按相对亮度算、不能靠眼睛估**：灰字白底实测 `#999999` = 2.85:1（不达标）、`#4b5563` = 7.56:1
  - **工具**：DevTools 颜色选择器直接显示对比度与达到的等级
- **键盘与焦点**
  - **Tab 顺序 = DOM 顺序**：不要用 CSS 把视觉顺序与 DOM 顺序调成两回事
  - **`tabindex` 只用 `0` 与 `-1`**：正值会插队打乱整页顺序；`-1` 用于"可被 `focus()` 聚焦但不进 Tab 序"
  - **焦点必须可见**：`outline: none` 让键盘用户盲操作；自定义要用 `:focus-visible` 替换而不是删除
  - **主动管理焦点**：模态框做焦点陷阱并在关闭后归还、路由切换后把焦点移到新页面的 `h1`
- **结构与状态**
  - **标题层级不跳级**，且这个问题**不体现在 role 上**（`h3` 与 `h4` 的 role 都是 `heading`），必须单独查文档结构
  - **地标**：`header`/`nav`/`main`/`aside`/`footer` 各对应一个 landmark，读屏能整块跳转，`main` 每页一个
  - **状态与播报**：`aria-expanded` / `aria-current` / `aria-live`（polite / assertive）/ `role="alert"`
  - **两个坑**：`aria-hidden="true"` 用在可聚焦元素上会造成"幽灵焦点"；ARIA 拼错浏览器静默忽略、不报错
- **表单无障碍**
  - **placeholder 不能替代 label**：树里有 placeholder 兜底出来的名字，但输入后就消失、措辞也不稳定
  - **错误提示四件套**：文字 + `aria-describedby` 关联 + `aria-invalid` + `role="alert"`，别只用红框
  - **分组**：单选 / 多选组用 `fieldset` + `legend`，否则读屏只会念出一串孤立选项
- **验收方式**
  - **自动化只能发现 30%~40% 的问题**：它擅长查属性（alt / label / 对比度），不擅长查顺序与体验
  - **必须人工做的两件事**：纯键盘（Tab / Enter / 空格 / Esc）走完流程、用真读屏（讲述人 / VoiceOver）听一遍
