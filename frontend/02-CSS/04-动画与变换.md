# 动画与变换

## 一、为什么需要 CSS 动画

网页的本质是"状态"，动画是"状态之间的过渡"。一个好的动画能给出清晰的**因果反馈**：按钮被按下、卡片被悬停、列表被插入一项……用户需要通过视觉变化感知到交互结果，否则界面会显得僵硬、迟钝。

CSS 为动画提供了两套互补的能力：

- **transform（变换）**：平移、缩放、旋转、倾斜元素，是性能最好的动效基础；
- **transition（过渡）**：定义元素属性在**两个状态之间**的变化过程；
- **animation（动画）**：定义元素在**多个关键帧之间**的完整动画序列。

一句话区分：`transition` 只有在某个属性值改变时才会触发，是"被动"的；`animation` 定义好之后会自动执行，是"主动"的。

在实际开发中，三者往往配合使用：`transform` 负责几何变化的"动作"，`transition` 或 `animation` 负责"时间轴"。

## 二、transform：变换

`transform` 可以施加一个或多个 2D / 3D 的变换函数，它**不会改变元素的文档流占位**，只会改变其渲染位置与外观。这是它与 `position` 定位最大的区别。

### 2.1 平移 translate

```css
.box {
  transform: translate(20px, 10px); /* x 方向 20px，y 方向 10px */
  transform: translateX(50%);
  transform: translateY(-30px);
  transform: translate3d(20px, 10px, 0); /* 3D 平移：xy 加 z 轴 */
}
```

注意：`translate` 的百分比是相对于**元素自身尺寸**，而非父容器。因此 `translate(50%, 50%)` 能让元素向右下移动自身一半的宽高，这是实现"居中"的常用技巧。

```css
.centered {
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%); /* 基于自身尺寸居中 */
}
```

### 2.2 缩放 scale

```css
.box {
  transform: scale(1.5);   /* 整体放大 1.5 倍 */
  transform: scaleX(2);    /* x 方向拉伸 2 倍 */
  transform: scaleY(0.5);  /* y 方向压缩一半 */
  transform: scale(1, 2);  /* x 1 倍、y 2 倍 */
}
```

`scale` 默认以元素的中心为缩放基准。`scale` 的值可以只有一个，也可以传入两个分别控制 x 与 y。

### 2.3 旋转 rotate

```css
.box {
  transform: rotate(45deg);       /* 平面旋转 45 度 */
  transform: rotate(-90deg);
  transform: rotateX(30deg);      /* 绕 x 轴旋转，产生 3D 翻转效果 */
  transform: rotateY(180deg);     /* 绕 y 轴旋转，常用于卡片翻转 */
  transform: rotateZ(45deg);      /* 绕 z 轴旋转，等价于平面 rotate */
}
```

`rotate(45deg)` 就是常见的图标旋转；`rotateY(180deg)` 配合透视可以做出"卡片翻面"效果。

### 2.4 倾斜 skew

```css
.box {
  transform: skew(20deg);        /* 沿 x 轴倾斜 20 度 */
  transform: skew(20deg, 10deg); /* x 轴倾斜 20 度、y 轴倾斜 10 度 */
  transform: skewX(30deg);
  transform: skewY(-15deg);
}
```

`skew` 常用于模拟立体透视或制作倾斜装饰条。

### 2.5 组合使用

多个变换函数可以叠加，按**从右往左**的顺序作用在元素坐标系上：

```css
.box {
  transform: translate(20px, 20px) rotate(45deg) scale(1.2);
}
```

实际理解时可以认为：先 `scale` 缩放，再 `rotate` 旋转，最后 `translate` 平移，效果会作用于元素自身的局部坐标系。

### 2.6 transform-origin：变换原点

`transform-origin` 决定变换的基准点，默认是元素中心 `50% 50%`：

```css
.box {
  transform-origin: top left;   /* 以左上角为原点 */
  transform-origin: 0 100%;     /* 以左下角为原点 */
  transform: rotate(30deg);
}

.box2 {
  transform-origin: 0 0;        /* 以左上角为原点旋转，形成"指针摆动"效果 */
  transform: rotate(-20deg);
}
```

改变原点会让同样的 `rotate` 呈现完全不同的轨迹，例如"开门"效果就以左边线为原点旋转。

### 2.7 透视 perspective

3D 变换需要配合透视才能看到纵深效果，透视有两种设置方式：

```css
/* 方式一：放在父容器上，作用给所有子元素的 3D 变换 */
.parent {
  perspective: 600px; /* 数值越小，透视感越强 */
}

/* 方式二：作为函数直接写在元素自身 */
.child {
  transform: perspective(600px) rotateY(30deg);
}
```

再配合 `transform-style: preserve-3d` 让子元素维持 3D 空间关系，即可做出立体卡片、翻牌等复杂效果：

```css
.scene {
  perspective: 800px;
}

.card {
  transform-style: preserve-3d;
  transition: transform 0.6s;
}

.card:hover {
  transform: rotateY(180deg);
}
```

### 2.8 注意：transform 与布局属性不同

对被变换的元素可应用的偏移量是有上限的客观约束。`transform` 只影响视觉与命中测试区域，不影响布局，是后续提到"合成层优化"的基础。

## 三、transition：过渡

`transition` 描述的是**属性从旧值到新值的变化过程**。它需要触发条件——通常是 `:hover`、`:focus`、类名增删或 JS 修改了属性值。

```css
.button {
  background: #333;
  color: #fff;
  transition: background 0.3s ease, color 0.3s ease;
}

.button:hover {
  background: #2a7;
  color: #fff;
}
```

### 3.1 transition 子属性

`transition` 是以下四个子属性的简写：

- `transition-property`：指定哪些属性参与过渡，可用 `all` 表示全部；
- `transition-duration`：过渡时长，必填；
- `transition-timing-function`：过渡的缓动函数；
- `transition-delay`：延迟多久后才开始过渡。

```css
.box {
  transition-property: transform, opacity;
  transition-duration: 0.4s, 0.2s;
  transition-timing-function: ease-in-out, linear;
  transition-delay: 0s, 0.2s;
}
```

### 3.2 过渡不能作用于哪些属性

过渡要求属性值是**数值或可插值的类型**。`display`、`visibility` 这类离散属性无法平滑过渡，`width: auto`、`height: auto` 这类无法插值也无法过渡。想让高度从 0 展开，可以用 `max-height` 技巧，或结合 `transform: scaleY` 实现。

```css
.menu {
  overflow: hidden;
  max-height: 0;
  transition: max-height 0.3s ease;
}

.menu.open {
  max-height: 300px;
}
```

### 3.3 推荐过渡的属性：transform 与 opacity

并非所有属性都能流畅过渡。**`transform` 和 `opacity` 是两个特例**——它们只涉及合成阶段，不需要触发布局与绘制，性能最好。而 `width`、`height`、`top`、`left` 等每次变化都要重新触发布局，应尽量避免用它们做动画。

```css
/* 推荐：只动 transform */
.menu {
  transform: translateY(-100%);
  transition: transform 0.3s ease;
}

.menu.open {
  transform: translateY(0);
}
```

## 四、animation：关键帧动画

`animation` 通过 `@keyframes` 定义关键帧，再通过 `animation` 简写属性调用，支持多阶段、循环、反向播放等更强能力。

### 4.1 定义关键帧

```css
@keyframes bounce {
  0% {
    transform: translateY(0);
  }
  50% {
    transform: translateY(-30px);
  }
  100% {
    transform: translateY(0);
  }
}

.ball {
  animation: bounce 1s ease infinite;
}
```

关键帧的百分比对应时间轴上的进度：`0%` 是起点，`100%` 是终点，中间可自由拆分。

### 4.2 animation 子属性

- `animation-name`：引用哪个 `@keyframes`（必填）；
- `animation-duration`：动画时长（必填）；
- `animation-timing-function`：缓动函数；
- `animation-delay`：延迟启动时间；
- `animation-iteration-count`：播放次数，可用 `infinite` 无限循环；
- `animation-direction`：方向，`normal` / `reverse` / `alternate`（正反交替）；
- `animation-fill-mode`：结束后样式保留方式；
- `animation-play-state`：`running` / `paused`，可用来暂停动画。

```css
@keyframes fadeIn {
  from { opacity: 0; }
  to   { opacity: 1; }
}

.box {
  animation: fadeIn 1s ease 0.5s 3 alternate both;
}
```

### 4.3 fill-mode：动画填充模式

动画播放前与结束后，元素的样式取决于 `animation-fill-mode`：

- `none`（默认）：动画前后都不保留关键帧样式；
- `forwards`：动画结束后保留**最后一帧**样式；
- `backwards`：动画延迟期间先应用**第一帧**样式；
- `both`：同时应用 `forwards` 与 `backwards`。

```css
.enter {
  animation: fadeIn 0.6s ease both; /* 入场动画用 both，避免闪现 */
}
```

`forwards` 或 `both` 是页面"入场动画"最常见的选择。

### 4.4 animation 与 JS 交互

推荐通过切换类名或控制 `animation-play-state` 来暂停/恢复，从而让动画逻辑留在 CSS 层：

```css
.ball {
  animation: spin 2s linear infinite;
}

.ball.paused {
  animation-play-state: paused;
}
```

## 五、will-change 与合成层优化

现代浏览器渲染一帧大致经历三个环节：**layout（布局）→ paint（绘制）→ composite（合成）**。如果动画只改变元素的定位、缩放、旋转、透明度，浏览器可以跳过 layout 与 paint，直接进入 composite，运行在 **GPU** 上，这就是"合成层（compositor layer）"优化。

### 5.1 什么是合成层

浏览器会把某些元素单独提升为一个独立图层（合成层），各图层先独立绘制，再由 GPU 合成产出最终画面。`transform` 和 `opacity` 的变化经常被提升到合成层处理，从而让动画非常流畅。`video`、`canvas`、带滚动容器等也常天然成为合成层。

### 5.2 will-change 的作用

`will-change` 用来**提前告诉浏览器**某个属性即将变化，让浏览器提前做相应的优化准备（例如提前提升为合成层），从而减少动画开始时的卡顿：

```css
.card {
  will-change: transform, opacity;
}

.card:hover {
  transform: scale(1.05);
}
```

### 5.3 will-change 的注意事项

`will-change` 不是越多越好，滥用反而有害：

- 不要为多个元素、多个属性同时声明，每提升一个合成层都会消耗显存；
- 一旦元素变化结束后，应移除 `will-change`，让浏览器回收资源；
- 用 `will-change` 提升的合成层可能带来模糊、边框缺失等渲染差异；
- 优先使用 JS 在"即将需要时"动态添加、结束后移除，而不是写死在样式里。

```js
// 推荐：临时提升合成层
card.addEventListener('mouseenter', () => {
  card.style.willChange = 'transform';
});
card.addEventListener('mouseleave', () => {
  card.style.willChange = '';
});
```

实践中，只要坚持"只动画 `transform` 和 `opacity`"，即便不用 `will-change`，浏览器多数情况下也能自动优化。

### 5.4 3D 触发的合成提升

声明 3D 变换（如 `translateZ(0)`、`backface-visibility: hidden`）也会强制创建合成层。历史上常用它来"欺骗"浏览器提升性能，但由于会消耗额外内存，现在更推荐配合 `will-change` 按需使用。

```css
/* 历史 hack：主动创建合成层 */
.smooth {
  transform: translateZ(0);
}
```

## 六、CSS 动画与 JS 动画对比

### 6.1 各自擅长什么

| 维度 | CSS 动画 | JS 动画（如 Web Animations API、JS 驱动 rAF） |
| --- | --- | --- |
| 基础动效（过渡、显隐、位移） | 简单高效，开箱即用 | 写起来啰嗦 |
| 复杂交互与物理模拟 | 难以表达 | 灵活，可精确控制每一帧 |
| 时间轴编排（暂停、seek、反转） | 有限支持 | 完全可控 |
| 与业务逻辑联动 | 需配合 JS 触发类名 | 直接在逻辑中驱动 |
| 性能 | 走合成器，通常更快 | 依赖写法的复杂度 |

### 6.2 何时选 CSS、何时选 JS

- 简单的过渡、hover 动效、入场动画、无限循环动画，优先用 **CSS**：代码量少、性能好、天然可退化；
- 需要**暂停/前进/回放/seek 指定时间点**、与滚动手势联动、做复杂物理/缓动，用 **JS（Web Animations API 或 rAF）**；
- 现代浏览器提供了 **Web Animations API（WAAPI）**，用 JS 获得 CSS 动画的性能，例如 `element.animate()`：

```js
element.animate(
  [
    { transform: 'translateY(0)' },
    { transform: 'translateY(-30px)' },
  ],
  {
    duration: 600,
    easing: 'ease-out',
    iterations: 3,
  }
);
```

### 6.3 通用原则

无论选哪种，坚持 **transform / opacity 优先**，避免动画中修改 `width`、`height`、`top`、`left`；能用 GPU 合成完成的动作，不要退化为逐帧布局计算。

## 七、常见动效案例

### 7.1 悬停缩放

```css
.card {
  transform: scale(1);
  transition: transform 0.3s ease, box-shadow 0.3s ease;
}

.card:hover {
  transform: scale(1.05);
  box-shadow: 0 8px 24px rgba(0, 0, 0, 0.2);
}
```

### 7.2 骨架屏脉冲

```css
@keyframes pulse {
  0%, 100% { opacity: 1; }
  50%      { opacity: 0.4; }
}

.skeleton {
  background: #eee;
  animation: pulse 1.2s ease-in-out infinite;
}
```

### 7.3 呼吸灯 / 提示点

```css
@keyframes breathe {
  0%, 100% { transform: scale(1); opacity: 0.6; }
  50%      { transform: scale(1.4); opacity: 1; }
}

.dot {
  width: 10px;
  height: 10px;
  border-radius: 50%;
  background: #2a7;
  animation: breathe 1.5s ease-in-out infinite;
}
```

### 7.4 元素入场（从下方浮现）

```css
@keyframes rise {
  from {
    opacity: 0;
    transform: translateY(40px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

.item {
  animation: rise 0.6s ease both;
}
```

### 7.5 卡片 3D 翻转

```css
.scene {
  perspective: 800px;
}

.card {
  position: relative;
  transform-style: preserve-3d;
  transition: transform 0.6s ease;
}

.card:hover {
  transform: rotateY(180deg);
}

.card .face {
  position: absolute;
  backface-visibility: hidden;
}

.card .back {
  transform: rotateY(180deg); /* 背面预先翻转，翻面时才转到正面 */
}
```

## 小结

`transform` 负责几何变换（平移 / 缩放 / 旋转 / 倾斜，2D/3D，配合 `transform-origin` 与 `perspective`）；`transition` 负责"状态改变时的过渡"；`animation` 与 `@keyframes` 负责"主动执行的多阶段动画"。性能上请记住一句话：**只动画 `transform` 和 `opacity`**，必要时辅以 `will-change` 让浏览器提前提升合成层、跑在 GPU 上。既然后端交互与业务状态频繁变化，将简单的视觉反馈交给 CSS、把复杂的时序编排交给 JS（WAAPI），才是平衡可维护性与性能的正解。
