# 响应式与移动端

> 级别：中级

现在的网站必须同时适配 PC 与手机。响应式设计的核心是"**一套代码，多端适用**"。按本书四层推进：

- **入门使用**：viewport、媒体查询、Mobile First；
- **进阶**：rem/flexible 与 vw 适配原理、300ms/1px/dpr/安全区等移动端坑；
- **实战**：见 `06-综合实战`；
- **最小实现掌握原理**：到 `code/frontend/02-css` 运行 `responsive.html`，缩放窗口观察断点与 vw 动态变化。

本文系统讲解响应式与移动端适配的完整方案：视口、媒体查询、rem/vw 适配、flexible 方案，以及移动端特有的坑。这也是前端面试的高频考点。

## 视口 viewport

移动端浏览器默认的布局视口宽度远大于屏幕宽度（通常 980px），导致网页被"整体缩小"显示。需要用 `<meta name="viewport">` 告诉浏览器按真实屏幕宽度布局。

```html
<!DOCTYPE html>
<html>
  <head>
    <meta
      name="viewport"
      content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no"
    />
  </head>
</html>
```

关键属性：

- `width=device-width`：布局视口宽度 = 设备屏幕宽度（核心）。
- `initial-scale=1.0`：初始缩放比 1:1。
- `maximum-scale/minimum-scale`：允许的最大/最小缩放（需配合 `user-scalable`）。
- `user-scalable=no`：禁止用户手动缩放。
- `viewport-fit=cover`：适配刘海屏/全面屏（配合 `env(safe-area-inset-*)`）。

> 三对视口概念务必分清：
> - **布局视口（layout viewport）**：CSS 布局使用，受 meta 控制。
> - **视觉视口（visual viewport）**：用户当前看到的区域，受缩放影响。
> - **理想视口（ideal viewport）**：`width=device-width` 时布局视口=设备屏幕，即理想视口。

## 媒体查询（Media Query）

媒体查询用于**根据设备特征（宽高、分辨率、方向等）应用不同样式**。

### 基本语法

```css
/* 视口宽度 ≥ 768px 时生效 */
@media (min-width: 768px) {
  .container {
    width: 750px;
  }
}

/* 视口 ≤ 480px 的手机 */
@media (max-width: 480px) {
  .nav {
    display: none;
  }
}
```

### 常用断点（断点不必严格遵守，随设计走）

| 范围 | 设备 |
|------|------|
| max-width: 480px | 手机横屏/小屏 |
| min-width: 768px | 平板 |
| min-width: 992px | 桌面小屏 |
| min-width: 1200px | 桌面大屏 |

### 专业写法

把移动端样式放外面，**断点向上递进（Mobile First）**，PC 覆盖移动端；或用 `>` 组合：

```css
.box {
  width: 100%; /* 移动端默认全宽 */
}
@media (min-width: 768px) {
  .box {
    width: 50%;
  }
}
```

```css
/* 同时在 768~992px 之间生效 */
@media (min-width: 768px) and (max-width: 991px) {
  .box {
    font-size: 14px;
  }
}
```

### 其他媒体特性

```css
@media (prefers-color-scheme: dark) { /* 深色模式 */
  body { background: #111; }
}
@media (orientation: landscape) { /* 横屏 */
  .box { display: flex; }
}
@media (min-resolution: 2dppx) { /* 高清屏（dpr≥2） */
  .bg { background-image: url("img@2x.png"); }
}
```

## 移动端适配方案

核心目标：**让不同分辨率的手机显示"一样大"的物理观感**。常见思路有百分比、弹性、rem、vw 四种。

### 1. 百分比布局

```css
.child {
  width: 50%; /* 相对父元素宽的一半 */
}
```

思路简单，但**百分比是相对父元素且不可继承背景等比缩放**，处理图片等比、圆角、字体等比时不便。

### 2. 弹性布局（Flex）

不依赖具体尺寸，靠比例与内容自适应，是现代适配的**主力**：

```css
.row {
  display: flex;
  gap: 12px;
}
.item {
  flex: 1; /* 均分 */
}
```

### 3. rem 适配方案（手淘 flexible）

思路：**以设计稿（通常 750px）为准，把根字体 `html` 的 font-size 设为视口宽度的 1/多少份，然后所有尺寸用 rem**，这样不同屏宽下 rem 换算出的实际像素等比缩放。

手淘 flexible 的核心逻辑（简化版）：

```js
(function () {
  var doc = document.documentElement;
  var set = function () {
    // 以 750 设计稿为基准：视口宽度 / 10，即 1rem = 视口宽度的 1/10
    doc.style.fontSize = doc.clientWidth / 10 + "px";
  };
  set();
  window.addEventListener("resize", set);
})();
```

设计稿中把每个尺寸除以 75（750 视觉稿用 flexible 的 1/10 折算时，`1rem = 75px`）换算成 rem：

```css
/* 设计稿 750px 宽，某元素宽 300px */
.item {
  width: 4rem; /* 300 / 75 */
}
```

> 现状：flexible 方案已逐渐被 **vw 方案** 取代（见下），因为它依赖 js 且 rem 不等比字体会带来问题。但面试常考其原理：**动态设置根字号让全站等比缩放**。

### 4. vw 适配方案（更现代）

`1vw = 视口宽度的 1%`，直接用 vw 即可做到等比，无需 JS：

```css
/*
  设计稿 750px，某元素 
  宽 = (300 / 750) * 100 = 40vw
*/
.item {
  width: 40vw;
  font-size: 3.2vw; /* 字体也随屏等比 */
}
```

配合工具（postcss-px-to-viewport）可自动把 `px` 转 `vw`。**vw 方案干净、无 JS、比重，已是当前主流**。缺点：极端大屏下过小，常在 `max-width` 上做兜底。

## 移动端常见坑与处理

### 1. 防 300ms 点击延迟

早期移动浏览器为了区分"单击"与"双击缩放"，会在单击后等待 300ms 才触发 `click`。现代浏览器已将 `width=device-width` 的页面视为可触摸页面自动消除该延迟，但在老设备/复杂场景仍会出现。

处理方式：

- 现代方案：确保设置了 `meta viewport`（`width=device-width`），宽屏即避免双击缩放延迟。
- 老方案：使用 `FastClick` 库（已过时，不推荐新项目引入）。
- 事件层：直接监听 `touchstart/touchend` 并判断位移，自定义 tap（库已能解决，日常不必手写）。

### 2. click 事件 300ms 与"点击穿透"

点击穿透（click 300ms 穿透）：触摸点击后，300ms 后补发的 `click` 事件落在了**下层元素**上，导致"点了蒙层却点到底下按钮"。多出现在 `touchstart` 立即隐藏元素再用 tap 的场景。

处理：使用 `tap` 事件（`touchstart + touchend` 模拟），或给下层加遮挡层、延迟关蒙层。理解原理即可，日常库已封装。

### 3. 1px 边框问题

设备像素比 `dpr≥2` 时，CSS 的 `1px` 物理上等于 2~3 个物理像素，看起来"粗"。要**真·高清 1px**，常见方案：

**方案 A：`transform: scale(0.5)` 缩放（最常用）**

```css
.hairline {
  position: relative;
}
.hairline::after {
  content: "";
  position: absolute;
  left: 0;
  top: 0;
  width: 200%;
  height: 200%;
  border: 1px solid #ccc;
  transform-origin: left top;
  transform: scale(0.5); /* dpr=2 时缩到一半，等于 1 物理像素 */
  pointer-events: none;
}
```

**方案 B：媒体查询按 dpr（旧 flexible 思路）**

```css
@media (min-resolution: 2dppx) {
  .border {
    border-width: 0.5px; /* 部分浏览器/机型支持 */
  }
}
```

`0.5px` 兼容性不统一，推荐优先 **scale 方案**。

### 4. 点击高亮与系统默认样式清理

```css
a,
button {
  -webkit-tap-highlight-color: transparent; /* 点击高亮 */
  -webkit-touch-callout: none;              /* iOS 长按呼出菜单 */
  -webkit-appearance: none;                 /* 移除默认外观 */
}
```

### 5. 滚动与白屏问题

```css
body {
  -webkit-overflow-scrolling: touch; /* iOS 惯性滚动（新写法：overscroll-behavior） */
}
```

### 6. safe-area 适配刘海屏/全面屏

```css
.bottom-bar {
  /* iOS 安全区底部内边距 */
  padding-bottom: constant(safe-area-inset-bottom); /* iOS11 老语法 */
  padding-bottom: env(safe-area-inset-bottom);      /* 新语法 */
}
```

### 7. 图片与字体大小

- 图标用 **iconfont / SVG** 等比缩放，不用位图。
- 高清屏需要 `@2x/@3x` 图或 SVG，避免发虚。
- 最小可读字号（尽量避免小于 12px，部分 Android 会强制放大）。

## 像素比 dpr

`dpr`（devicePixelRatio）= 物理像素 / 逻辑像素（CSS 像素）。

```js
// 获取 dpr
var dpr = window.devicePixelRatio;
console.log(dpr); // iPhone 一般 2 或 3
```

- **1x 屏**：1 个 CSS 像素 = 1 个物理像素。
- **2x 屏（dpr=2）**：1 个 CSS 像素 = 4 个物理像素，故高清图需 `@2x`。
- JS 端如需缩放（如 canvas），可按 `1/dpr` 设 canvas 实际宽高。

```js
var canvas = document.getElementById("c");
var ctx = canvas.getContext("2d");
canvas.width = cssWidth * dpr;   // 物理像素
canvas.height = cssHeight * dpr;
canvas.style.width = cssWidth + "px"; // 逻辑尺寸
ctx.scale(dpr, dpr); /* 之后按 CSS 尺寸绘制即可清晰 */
```

## 移动端适配方案选型

| 方案 | 核心 | 优点 | 缺点 |
|------|------|------|------|
| 百分比 | `%` 相对父级 | 简单 | 等比/字体不便 |
| 弹性 Flex | 比例自适应 | 现代主力 | 一维为主 |
| rem（flexible） | 改根字号 | 等比缩放 | 需 JS、字体问题 |
| vw | 视口百分比 | 无 JS、现代主流 | 极端大屏需兜底 |

实践建议：**布局用 Flex + Grid，尺寸缩放用 vw，字体可部分用 vw 或锁定 rem，PNG 用 @2x，borders 用 scale 0.5**。
