# 游戏物理引擎

> 级别：高级

按本书四层推进——属进阶：入门物理引擎的"积分 → 碰撞检测 → 约束求解"三步与刚体类型；进阶到碰撞形状、物理材质、物理与渲染同步；实战与最小实现见 `code/frontend/17-game` 的 `minigame.html`——用原生代码手写 AABB 碰撞与落体计分，亲证"没有引擎也能模拟简单物理"，原理自足是本层目标。

手写碰撞、跳不准、穿墙、物体乱飘——只要你想做有"手感"的游戏，物理引擎就避不开。物理引擎负责在渲染背后"算"出物体该往哪动、会不会碰撞、会不会反弹，让游戏对象的行为符合直觉的牛顿力学，而不只是一个定死的位移公式。

这一章从物理引擎的原理（刚体、碰撞检测、约束求解）讲起，横向对比 Matter.js、Planck、Cannon/物理扩展与 Box2D，深入碰撞形状与材质，阐述"物理世界与渲染同步"的正确姿势，最后给出从简单物理到进阶优化的完整进阶路径。

## 一、物理引擎原理

### 1. 物理引擎在游戏里干什么

物理引擎管理一组**刚体（RigidBody）**，每个刚体有质量、速度、力、转角、形状，引擎在每帧"步进"时：

1. **积分**：用力加速度更新速度，速度更新位置（主要是半隐式欧拉）。
2. **碰撞检测**：找出哪些刚体互相穿透。
3. **约束求解**：施加冲量让它们不再穿透，并产生反弹、摩擦、速度衰减。

```
输入：上一帧所有刚体状态
  ↓ 积分（用加速度改速度，用速度改位置）
  ↓ [ broadphase ] 宽相位：快速排除明显不相交的对（用包围盒/空间索引）
  ↓ [ narrowphase ] 窄相位：精确计算几何相交
  ↓ [ solver ] 约束求解：施加冲量推开穿透，算摩擦力与恢复系数
  ↓ 输出：本帧刚体新状态
```

### 2. 刚体与运动类型

| 运动类型 | 说明 | 常见用途 |
| --- | --- | --- |
| `STATIC` | 静止，质量无穷大，不受力 | 地面、墙壁、箱子（静态） |
| `DYNAMIC` | 受重力/力/碰撞影响 | 角色、子弹、掉落物 |
| `KINEMATIC` | 由我们用代码控制速度/位置 | 移动平台、由脚本驱动的玩家 |

> 混合：静态地面 + 动态球（自由落体），或用 **kinematic** 做"玩家驱动的平台/推箱子"。

### 3. 碰撞检测的两阶段

**宽相位（broadphase）**：用**包围盒（AABB）** 或**空间索引**快速排除绝大多数不相交的刚体对，避免两两精确计算。常见有"无脑两两"、SAP（扫描线）、动态网格（uniform grid）、四叉树。

**窄相位（narrowphase）**：对"可能相交"的对做精确几何相交检测——圆与圆、圆与多边形、多边形与多边形的分离轴分离（SAT）、分离质点法（GJK + EPA）等。

### 4. 约束求解（solver）

找到穿透的刚体对后，求解器依据**冲量**把它们推开，同时满足反弹（恢复系数 restitution）与摩擦（friction）。物理引擎的"稳定"主要取决于求解器的迭代次数（iterations）——越多越精确但越慢。

## 二、主流物理引擎对比

| 引擎 | 维度 | 定位 | 特点 |
| --- | --- | --- | --- |
| Matter.js | 2D | 最流行的 Web 2D 物理 | API 简单、结构清晰，适合 2D 游戏与学习 |
| Planck.js | 2D | Box2D 的 JS 移植 | 高性能、API 偏底层，移植自主流 C++ 引擎 |
| Box2D（wasm） | 2D | 移植到 ASM/WASM 的 Box2D | 性能最佳，微信小游戏常用 |
| Cannon.js / cannon-es | 3D | 3D 物理引擎 | 刚体、约束、车辆、子弹支持，配 Three.js |
| Rapier | 2D/3D | Rust 写的物理，编译 to WASM | 极高性能，多人服务器物理常用 |

```js
// Matter.js 最简用法
import { Engine, World, Bodies, Body } from "matter-js";
const engine = Engine.create();
const ground = Bodies.rectangle(400, 500, 800, 20, { isStatic: true });
const ball   = Bodies.circle(400, 0, 40);
World.add(engine.world, [ground, ball]);

// 主循环内推进物理世界
function step() {
  Engine.update(engine, 1000 / 60);
  requestAnimationFrame(step);
}
```

> **选型口径**：游戏需要物理，先想清楚是 2D 还是 3D。2D 用 Matter.js（上手）或 Planck/Box2D（性能）；3D 用 cannon-es（上手）或 Rapier（性能）。

## 三、碰撞形状与材质

### 1. 碰撞形状（Collider）

物理引擎不算真实模型，而是用**简化几何形状**做碰撞。形状越简单，精度越低但越快；越贴合，越贵。

| 形状 | 说明 | 性能 | 适用 |
| --- | --- | --- | --- |
| Circle / Sphere | 圆/球 | 高 | 球、炮弹、圆形精灵 |
| Rectangle / Box | 矩形/盒 | 高 | 箱子、墙体 |
| Polygon / ConvexHull | 凸多边形 | 中 | 平台、多变地形（凸包） |
| Compound | 多个基本形状组合 | 中 | 复杂物体用多个简单形状拼接 |

> **铁律**：物理用**碰撞形状（collision shape）**，跟"渲染网格"不是一回事。不要把高模 3D 模型直接当物理体喂给引擎，必然慢。

```js
// Matter：碰撞形状随 Body 形状自动生成
Bodies.rectangle(x, y, w, h);   // 矩形碰撞体
Bodies.circle(x, y, r);          // 圆碰撞体
Bodies.polygon(x, y, sides, r);  // 凸多边形
```

### 2. 物理材质（Material）

**物理材质**（不是渲染材质）控制"接触交互"的系数，不与外观相关：

| 材质属性 | 含义 | 值域参考 |
| --- | --- | --- |
| `restitution` 恢复系数 | 反弹程度 | 0（完全不弹）~ 1（完全弹） |
| `friction` 摩擦 | 滑动阻力 | 0（光滑）~ 1（粗糙） |
| `density` 密度 | 结合体积算质量 | 影响重量感 |
| `frictionAir` | 空气阻力 | 让物体会慢慢停 |

```js
Bodies.circle(x, y, r, {
  restitution: 0.7,   // 弹弹弹
  friction: 0.1,      // 有点滑
  frictionAir: 0.02,  // 轻微空气阻力
});
```

> `restitution` 与 `friction` 都有**匹配规则（混合规则）**：两个刚体接触时，不同值怎么合并。用 Matter 的 `setRestitution(a, b, value)` 可统一控制某对的合并。

## 四、物理世界与渲染同步

物理引擎运行在**物理坐标空间**，而渲染是另一套对象。两者必须**逐帧保持一致**，否则会出现"看见的物体与碰撞盒子错位、物体穿透感"的怪象。

### 1. 正确姿势：逻辑更新物理，渲染只读物理

绝对不要在 `render` 里改物理。推荐：**固定步长推进物理（over 定时器），每次推进后把物理刚体的位置/旋转同步到对应渲染对象**。

```js
// Three.js + 3D 物理（cannon-es）同步示例
import * as THREE from "three";
import * as CANNON from "cannon-es";

const ballBody = physicsBodyFromCannon();      // 物理刚体 tri
const ballMesh = ballMeshFromThree();          // 渲染网格

function step() {                              // 固定步长物理
  world.step(1 / 60);
  // 把物理位置写回渲染网格
  ballMesh.position.copy(ballBody.position);
  const q = ballBody.quaternion;               // 四元数同步旋转
  ballMesh.quaternion.set(q.x, q.y, q.z, q.w);
}

// 主循环
let acc = 0;
function tick(now) {
  requestAnimationFrame(tick);
  acc += Math.min(now - last, 100) * 0.001;    // 封顶防累加爆炸
  while (acc >= 1 / 60) { step(); acc -= 1 / 60; }  // 固定步长物理
  renderer.render(scene, camera);              // 渲染始终读最新物理状态
}
```

### 2. 常见同步坑

- **时间戳漂移**：物理步长固定，而帧率可变，用累加器保证物理次数稳定。
- **半程同步 / 插值**：物理步进与渲染不同步会产生抖动画。可用"渲染时在两次物理状态间插值（lerp）"消除抖动。
- **对象映射**：物理刚体和渲染对象要用 `userData` 或 map 一一对应，销毁时同时清理。

## 五、简单物理到进阶优化

### 1. 从简单开始

不引入整库，先用简单的**手动 AABB/圆形物理**（上一章讲过）处理角色和少量子弹，性能最高、心智负担最低。只有"物体互相作用复杂、需要堆叠/悬挂/高级接触反馈"时才上真物理引擎。

### 2. 进阶优化清单

| 优化点 | 手段 |
| --- | --- |
| 步长稳定 | 固定步长 + 累加器；适当 `maxSubSteps` |
| 迭代次数 | 按需调 `iterations`，别无限加大 |
| 宽相位索引 | 用 grid/SAP，避免"暴力两两" |
| 睡眠机制 | 启用引擎的 **sleep mode**，静止刚体不参与计算，大幅省 CPU |
| 唤醒阈值 | 调低唤醒时的抖动阈值 |
| 质量/密度设置 | 避免质量悬殊导致的求解不稳（质量比不过大） |
| 拆合碰撞体 | 复杂模型用多个简单凸碰撞体组合 |
| 禁用不必要接触 | 对 A/B 刚体 `setCollisionFilterGroup` 跳过不相干分类 |
| 同步插值 | 渲染插值消除物理与渲染时间差引起的抖动 |
| WASM 版引擎 | 性能瓶颈时用 Box2D/Rapier 的 WASM 构建 |

### 3. 示例：休眠机制提升堆叠性能

```js
World // physics world 配置
world.sleepEnabled = true;         // Matter 直接开休眠
world.sleepThreshold = 60;         // 静止超过阈值次数就进入休眠
// cannon-es：body.allowSleep = true; body.sleepSpeedLimit = 0.1;
```

### 4. 网络游戏中"服务器权威"物理

多人竞技的物理往往在**服务器**跑（固定步长、确定性），客户端只做预测与插值，避免客户端作弊与大延迟拉扯。这是"物理引擎 + 网络同步"结合的高级主题，但也是 3A 手游的标配思路。

## 小结

- 物理引擎核心是 **积分 → 碰撞检测 → 约束求解** 三步；碰撞分宽相位 + 窄相位两阶段。
- 刚体分 `STATIC / DYNAMIC / KINEMATIC` 三种，碰撞形状和渲染网格不是一回事。
- 2D 用 Matter.js / Planck / Box2D；3D 用 cannon-es / Rapier。
- **物理材质** 用 `restitution / friction / density` 控制接触手感，不是外观材质。
- 物理与渲染要**同步**：固定步长推进物理 + 把状态写回渲染对象（必要时插值）。
- 进阶优化 = 固定步长 + 空间索引 + 休眠 + WASM 高性能引擎。

## 最小实现：手写碰撞与计分

到 `code/frontend/17-game` 打开 `minigame.html`：一个让物品下落、你左右移动接住、命中加分、漏接则减命、Game Over 自动重开的小游戏。它用手写的 **AABB 矩形相交**判断与简单位移模拟重力，体会物理引擎的最小本质。原理一句话：物理引擎"手感"的底层，无非就是每一帧"按时间积分更新位置 + 检测两两是否穿透 + 施加冲量推开"，并没有更多玄机。
