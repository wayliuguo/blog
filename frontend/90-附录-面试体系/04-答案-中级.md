### Q46: 深拷贝与浅拷贝的区别？如何实现一个深拷贝？

① **一句话结论**：浅拷贝只复制第一层引用，深拷贝递归复制所有层级，得到完全独立的对象。

② **区别**：

- **浅拷贝**：`Object.assign`、展开 `{...obj}`、`Array.slice`——内层对象仍共享引用，修改内层会互相影响。
- **深拷贝**：内层也复制，修改后互不影响。

③ **深拷贝实现**：

```js
// 递归实现（简化，未处理循环引用/函数/new 实例）
function deepClone(target, map = new WeakMap()) {
  if (target === null || typeof target !== 'object') return target;
  if (map.has(target)) return map.get(target);   // 处理循环引用
  const clone = Array.isArray(target) ? [] : {};
  map.set(target, clone);
  for (const key of Object.keys(target)) {
    clone[key] = deepClone(target[key], map);
  }
  return clone;
}
```

④ **业界方案**：`JSON.parse(JSON.stringify(obj))` 简单但会丢失 `undefined`/函数/Symbol/Date；`structuredClone`（现代浏览器）或 lodash `cloneDeep` 更稳妥。

⑤ **追问**：深拷贝遇到 `Date`、`RegExp`、函数如何处理？`WeakMap` 为什么用于记录已拷贝对象？

### Q47: 普通函数中 `this` 的指向由什么决定？有哪些规则？

① **一句话结论**：多数情况下 `this` 由"调用时的方式"决定（调用点），非定义位置；取决于调用者是对象还是独立调用。

② **规则**：

| 调用方式 | this | 示例 |
|----------|------|------|
| 独立调用 | window / undefined（严格模式） | `fn()` |
| 方法调用 | 调用它的对象 | `obj.fn()` |
| `call/apply/bind` | 显式指定 | `fn.call(obj)` |
| 构造函数（new） | 新创建对象 | `new Fn()` |
| 箭头函数 | 外层词法作用域的 this | `() =>` |

③ **注意**：回调里 `this` 易丢，可先用变量保存 `const _this = this` 或用箭头函数。

### Q48: `call`、`apply`、`bind` 有什么区别？

① **一句话结论**：三者都用于改变 `this`，区别在传参方式和是否立即执行。

② **对比**：

- `fn.call(thisArg, a, b)`：立即执行，参数逐个传。
- `fn.apply(thisArg, [a, b])`：立即执行，参数数组传。
- `fn.bind(thisArg, a, b)`：返回"绑定了 this 的新函数"，不立即执行。

```js
function greet(greeting, name) {
  console.log(`${greeting}, ${name}, ctx: ${this.tag}`);
}
greet.call({ tag: 'A' }, 'Hi', 'Tom');
greet.apply({ tag: 'B' }, ['Hello', 'Jerry']);
const bound = greet.bind({ tag: 'C' }, 'Hey');
bound('Lucy');
```

③ **场景**：`Math.max.apply(null, arr)` 对数组求最大值；`bind` 常用于事件回调固定 this。

④ **追问**：如何手写实现 `call/apply/bind`（用 Symbol 或临时属性）？

### Q49: `async/await` 的原理是什么？和 Promise 是什么关系？

① **一句话结论**：`async/await` 是 Promise 的语法糖，让异步代码像同步代码一样写，底层仍是 Promise + 生成器（generator）。

② **原理**：

- `async` 函数总是返回一个 Promise。
- `await` 会暂停函数执行，等待 Promise resolve 后继续，其实质是把后续代码放进 `.then` 回调。
- 底层实现可理解为用 Generator 委托 + 自动执行器（类似 co 库）。

```js
async function fetchData() {
  try {
    const user = await api.getUser();   // 等价 user = await promise
    const list = await api.getList(user.id);
    return list;
  } catch (e) {
    console.error(e);
  }
}
```

③ **好处**：消灭回调地狱、错误处理用 `try/catch` 更直观。**注意**：`await` 必须在 `async` 函数内。

### Q50: 什么是防抖和节流？各适用于什么场景？

① **一句话结论**：防抖是"间隔内只执行最后一次"，节流是"固定时间内最多执行一次"，都用于限制高频触发函数。

② **防抖（debounce）**：触发后重置定时器，只有停止触发一段时间后执行。

```js
function debounce(fn, delay = 300) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
// 场景：输入框搜索联想、窗口 resize 结束后的处理
```

③ **节流（throttle）**：固定时间段内只执行一次（首/尾）。

```js
function throttle(fn, interval = 300) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) {
      last = now;
      fn.apply(this, args);
    }
  };
}
// 场景：滚动监听、拖拽、按钮防抖节流点击
```

④ **选型**：高频连续触发且只在"停止后"要结果用防抖；"持续触发但要按节奏"用节流。

⑤ **追问**：防抖的立即执行版（前缘 debounce）怎么实现？两者结合的场景？

### Q51: Promise 有哪些状态？`all`、`race`、`allSettled`、`any` 有什么区别？

① **一句话结论**：Promise 有 pending / fulfilled / rejected 三态，且不可逆转；四兄弟用于并行多个 Promise，区别在"返回策略"。

② **状态**：`pending`（待定）→ `fulfilled`（成功）/ `rejected`（失败），状态一旦改变不可逆。

③ **并行方法对比**：

| 方法 | 行为 | 结果 |
|------|------|------|
| `Promise.all` | 全部成功才成功 | 全部结果数组；只要有一个失败则整体 reject |
| `Promise.allSettled` | 等全部结束 | 返回每个的状态（成功/失败明细） |
| `Promise.race` | 第一个 settled 决定 | 谁先结束用谁（成功或失败） |
| `Promise.any` | 第一个成功决定 | 全部失败才 reject（AggregateError） |

```js
const p = [p1(), p2(), p3()];
const all = await Promise.all(p);        // 全绿才绿
const settled = await Promise.allSettled(p);
```

④ **场景**：`all` 等接口都 ok 再渲染；`race` 做超时控制（与 timeout 竞争）；`any` 从多个候选里取最先成功者。

⑤ **追问**：如何用 `Promise.race` 实现请求超时？`all` 失败时如何定位哪个失败？

### Q52: 原型与原型链是怎么工作的？如何用原型实现继承？

① **一句话结论**：每个对象有 `__proto__` 指向其构造函数的 `prototype`，沿着这条链向上查找属性即为原型链；继承可通过原型共享方法。

② **核心概念**：

- 每个函数都有 `prototype`（原型对象）。
- 实例的 `__proto__` 指向构造函数的 `prototype`。
- 读取属性时沿 `__proto__` 链逐级查找，找到为止，到 `Object.prototype`/`null` 结束。

③ **原型继承**：

```js
function Animal(name) { this.name = name; }
Animal.prototype.eat = function () { console.log(this.name + ' eat'); };

function Dog(name, breed) {
  Animal.call(this, name);   // 继承实例属性
  this.breed = breed;
}
Dog.prototype = Object.create(Animal.prototype); // 继承原型方法
Dog.prototype.constructor = Dog;
Dog.prototype.bark = function () { console.log('woof'); };
```

④ **现代写法**：ES6 `class extends` 就是基于原型的语法糖。

⑤ **追问**：`Object.create(null)` 的作用？`hasOwnProperty` 与 `in` 的区别？

### Q53: 什么是作用域链？它在闭包中如何体现？

① **一句话结论**：作用域链是函数查找变量时的"由内向外"的层级链（内层能访问外层的变量），它由代码的词法位置决定。

② **原理**：每个函数创建时保存了其外层作用域，形成一条链（自身作用域 → 外层函数作用域 → 全局）。变量查找沿链向上。

③ **闭包中的体现**：内部函数即使在外部函数返回后仍能访问外部函数作用域的变量，正是因为内部函数的"作用域链"保存了对外层作用域引用。

```js
function outer() {
  let count = 0;
  return function inner() {
    count++;
    return count; // 顺着作用域链找到 outer 里的 count
  };
}
```

④ **要义**：作用域链在"函数定义时"就确定（词法作用域），与调用无关。

⑤ **追问**：作用域链和原型链都用于"查找"，它们的区别是什么？

### Q54: 事件循环中宏任务和微任务的完整执行顺序是什么？

① **一句话结论**：每轮先执行一个宏任务，紧接着清空"本轮产生的所有微任务"，再进入下一个宏任务，循环往复。

② **浏览器中的顺序**：

1. 执行当前宏任务（脚本主体/一个任务）。
2. 执行所有微任务队列中的任务（`Promise.then`、`queueMicrotask`、`MutationObserver`）。
3. 渲染更新（浏览器会在合适的时机重绘）。
4. 取下一个宏任务（`setTimeout`、`setInterval`、I/O 等）继续。

```js
console.log('start');                       // 同步
setTimeout(() => console.log('timeout'));   // 宏任务
Promise.resolve().then(() => {
  console.log('micro1');
  Promise.resolve().then(() => console.log('micro2'));
});
// start → micro1 → micro2 → timeout
```

③ **注意**：微任务里如果再产生微任务，会在本轮继续清空；`requestAnimationFrame` 在渲染前执行。

④ **追问**：`await` 之后的代码算微任务吗？Node 与浏览器事件循环差异？

### Q55: 如何实现一个发布订阅（Event Bus）？它解决了什么问题？

① **一句话结论**：发布订阅是一种解耦机制，事件发送方 emit 触发，订阅方 on 监听，互不直接依赖。

② **实现**：

```js
class EventEmitter {
  constructor() { this.listeners = new Map(); }
  on(event, fn) {
    if (!this.listeners.has(event)) this.listeners.set(event, []);
    this.listeners.get(event).push(fn);
    return () => this.off(event, fn); // 返回取消订阅
  }
  emit(event, ...args) {
    (this.listeners.get(event) || []).slice().forEach(fn => fn(...args));
  }
  off(event, fn) {
    const list = this.listeners.get(event) || [];
    this.listeners.set(event, list.filter(f => f !== fn));
  }
  once(event, fn) {
    const wrapper = (...args) => { this.off(event, wrapper); fn(...args); };
    this.on(event, wrapper);
  }
}
```

③ **解决的问题**：

- 组件/模块之间解耦，不需要互相持有引用。
- 全局事件中心（如 `mitt`、`EventBus`）方便跨组件通信。
- 与观察者模式类似，但观察者中观察者订阅"被观察对象"，发布订阅中间还有事件通道。

## 第二阶段：网络进阶与浏览器原理（56-60）

### Q56: 浏览器渲染页面的大致流程是怎样的？什么是回流（reflow）和重绘（repaint）？

① **一句话结论**：渲染流程是"解析 HTML/CSS 建 DOM/CSSOM → 构造渲染树 → 布局 → 绘制 → 合成"；布局变化触发回流，仅样式外观变化触发重绘。

② **渲染流程**：

1. `HTML → DOM 树`、`CSS → CSSOM 树`。
2. 合并生成 **渲染树**（剔除 `display:none`）。
3. **Layout（布局/回流）**：计算每个节点的几何位置与尺寸。
4. **Paint（绘制/重绘）**：把内容绘制到像素。
5. **Composite（合成）**：合成层交给 GPU。

③ **回流（reflow）**：几何变化（宽高、位置、字体等）导致重新布局，代价最大。
④ **重绘（repaint）**：颜色、visibility 等外观变化，只重绘不重新布局。

⑤ **如何优化**：

- 用 `translate`/`transform` 做动画（进合成层，不走布局）。
- 批量改 DOM（fragment）、减少强制同步布局。
- 避免频繁读 `offsetWidth` 后再改。

⑥ **追问**：什么操作会强制同步布局（reflow）？`will-change` 的作用？

### Q57: HTTP 缓存机制是什么？强缓存与协商缓存有什么区别？

① **一句话结论**：缓存分"强缓存"（不发请求直接用）与"协商缓存"（带条件去问服务器 304）。

② **强缓存**：通过 `Expires`（绝对时间）或 `Cache-Control: max-age`（相对秒数）判断，命中则直接用本地副本，不发请求。

③ **协商缓存**：缓存过期后，带 `If-Modified-Since`/`If-None-Match` 去问服务器；服务器比对后未变返回 `304`，变了返回 `200` 新数据。

- `Last-Modified` / `If-Modified-Since`（秒级）
- `ETag` / `If-None-Match`（内容指纹，更精确）

④ **优先级**：`ETag` > `Last-Modified`；强缓存优先于协商缓存。

```http
Cache-Control: max-age=31536000, public
ETag: "abc123"
```

### Q58: HTTPS 的工作原理是什么？和 HTTP 有什么不同？

① **一句话结论**：HTTPS = HTTP + TLS/SSL，通过证书 + 加密保证传输的机密性、完整性、身份真实性。

② **三次密钥交互（简化）**：

1. 客户端发起，服务器返回证书（含公钥）。
2. 客户端验证证书（CA 信任链），生成随机"对称密钥"，用服务器公钥加密后发给服务器。
3. 服务器用私钥解开拿到对称密钥，之后的通信都用该对称密钥加密。

③ **核心**：HTTP 明文；HTTPS 内容用对称加密（快），密钥分发用非对称加密（安全），还提供数字签名防篡改。

④ **与 HTTP 区别**：默认端口不同（80 vs 443）、多了 TLS 握手、性能略低但安全性大幅提升。

⑤ **追问**：证书链与中间人攻击如何防范？http 转 https 对性能的影响？

### Q59: HTTP/1.1 和 HTTP/2 有什么区别？

① **一句话结论**：HTTP/2 通过二进制分帧、多路复用、头部压缩、服务端推送，解决 HTTP/1.1 的队头阻塞与重复开销。

② **对比**：

| 特性 | HTTP/1.1 | HTTP/2 |
|------|----------|--------|
| 传输格式 | 文本 | 二进制分帧 |
| 多路复用 | 同一连接串行（队头阻塞） | 一个连接并行多流 |
| 头部压缩 | 无 | HPACK 压缩 |
| 优先级 | 无 | 流优先级 |
| 服务端推送 | 无 | 服务端推送（Server Push） |

③ **好处**：减少 TCP 连接数、降低延迟、减少带宽。

④ **局限**：HTTP/2 的队头阻塞仍在 TCP 层（丢包重传）；HTTP/3 用 QUIC 解决。

⑤ **追问**：说了 HTTP/2，能顺带说下 HTTP/3/QUIC 吗？`ALPN` 是什么？

### Q60: 什么是 WebSocket？它和 HTTP 有什么关系和区别？

① **一句话结论**：WebSocket 是浏览器与服务器的全双工长连接协议，适合实时、双向、持续的通信；它基于 HTTP 握手升级而来。

② **原理**：客户端发 `Upgrade: websocket` 的请求完成握手（`101 Switching Protocols`），之后建立持久 TCP 连接，双方可随时互推消息，消息基于帧。

③ **与 HTTP 区别**：

- **HTTP**：请求-响应，单向，一次性，需轮询才能实时。
- **WebSocket**：双向、长连接、服务端能主动推。

④ **典型场景**：聊天、实时通知、在线协作、行情推送、游戏同步。

⑤ **追问**：WebSocket 与 HTTP 轮询/SSE 的对比？心跳与重连如何设计（断线重连）？

### Q61: 函数组件和类组件的区别是什么？

① **一句话结论**：函数组件用函数 + Hooks 实现逻辑，类组件用 class + 生命周期/this；现代 React 推荐函数组件。

② **对比**：

| 特性 | 函数组件 | 类组件 |
|------|----------|--------|
| 定义 | 纯函数 | class + render() |
| 状态 | useState | this.state / setState |
| 生命周期 | useEffect 等 hooks | componentDidMount 等 |
| this | 无 this，靠闭包 | 需绑定 this |
| 其他 | 更轻、易测试 | 样板代码多 |

```jsx
// 函数组件 + hooks
function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

③ **优点**：函数组件逻辑复用更灵活（自定义 hooks）、体积更小。

### Q62: `useState` 和 `useEffect` 的使用和注意事项？

① **一句话结论**：`useState` 定义状态并返回更新函数；`useEffect` 处理副作用（请求、订阅、DOM 操作）。

② **useState**：

```jsx
const [count, setCount] = useState(0);
setCount(c => c + 1); // 函数式更新
```

- 注意：状态异步批量更新，别依赖旧值直接读；多个异步更新应使用函数式更新。

③ **useEffect**：

```jsx
useEffect(() => {
  // 副作用
  const t = setTimeout(() => {}, 1000);
  return () => clearTimeout(t); // 清理
}, [deps]); // 空数组 = 挂载一次；带依赖 = 依赖变化时执行
```

- 依赖数组决定何时执行；清理函数在卸载或下一次执行前调用。
- 空数组里读不到最新值（闭包陷阱），需要时把依赖加进去或用 ref 读最新值。

④ **追问**：`useEffect` 的竞态问题（请求返回顺序）如何处理？`useLayoutEffect` 区别？

### Q63: React 中 `key` 属性的作用是什么？

① **一句话结论**：`key` 帮助 React 在 diff 中识别列表项身份，用于判断复用、移动还是重建，从而正确更新并优化性能。

② **原理**：渲染列表时，React 用 `key` 匹配新旧元素，尽量复用 DOM 节点而非重建。

③ **正确用法**：

- 用稳定的唯一值（如 id）作为 key。
- **不要用 index 作为 key**：顺序变化/插入删除时会导致状态错乱与错误复用。

```jsx
{items.map(item => <Item key={item.id} data={item} />)}
```

④ **注意**：`key` 只在兄弟节点间唯一即可；不同组件用相同 key 没问题。

### Q64: 什么是受控组件和非受控组件？它们的区别？

① **一句话结论**：受控组件由 React 状态控制 value，非受控组件由 DOM 自身维护值，通过 ref 读取。

② **受控组件**：表单值 `value` 绑定 state，`onChange` 更新，数据源在 React 中。

```jsx
const [name, setName] = useState('');
<input value={name} onChange={e => setName(e.target.value)} />;
```

③ **非受控组件**：

```jsx
const inputRef = useRef(null);
<input ref={inputRef} defaultValue="hi" />;
// 读取 inputRef.current.value
```

④ **区别**：

| 特性 | 受控 | 非受控 |
|------|------|--------|
| 数据来源 | React state | DOM |
| 实时校验 | 方便 | 需手动 |
| 受控能力 | 强（可格式化/校验） | 弱 |

⑤ **建议**：多用受控组件便于状态统一与校验；简单一次性表单可用非受控减轻重渲染。

⑥ **追问**：受控组件导致大量重渲染怎么优化（将表单拆成独立组件）？

### Q65: `useMemo`、`useCallback`、`useRef` 的用法和区别？

① **一句话结论**：`useMemo` 缓存计算结果，`useCallback` 缓存函数引用，`useRef` 保存可变值/访问不触发渲染的值。

② **对比**：

```jsx
const total = useMemo(() => compute(list), [list]);   // 缓存结果
const handler = useCallback(() => doThing(), [deps]); // 缓存函数
const countRef = useRef(0);                            // 可变 ref，不触发渲染
```

| Hook | 用途 | 特点 |
|------|------|------|
| `useMemo` | 计算开销大时缓存结果 | 依赖变化才重算 |
| `useCallback` | 返回稳定函数引用 | 防止子组件因 props 引用变化而多余重渲染 |
| `useRef` | 保存跨渲染的可变值 / 访问 DOM | 修改不触发渲染 |

③ **原则**：不要过度使用，避免用于"只要存值"的场景（用 ref）。`useMemo` 也不是免费，避免无谓缓存。

④ **追问**：`useRef` 在 hooks 闭包中读取最新值的作用（场景：setInterval 里的精确计数）？

### Q66: React 组件之间有哪些通信方式？

② **方式分类**：

- **父子双向**：`props` 传参，子用 `onXxx` 回调通知父。
- **跨层级**：`Context` 提供全局数据；`useReducer` + Context 共享复杂状态。
- **全局复杂共享**：Redux / Zustand / MobX。

③ **选型建议**：能就近就就近（props），避免全局状态滥用；跨多层的低频数据用 Context。

### Q67: React 类组件的生命周期有哪些？分别在什么时机触发？

① **一句话结论**：生命周期分"挂载 / 更新 / 卸载"三个阶段，含保留的 UNSAFE 钩子（老版本）。

② **挂载**：`constructor` → `render` → `componentDidMount`。
**更新**：`shouldComponentUpdate` → `render` → `componentDidUpdate`。
**卸载**：`componentWillUnmount`。

③ **关键钩子职责**：

- `componentDidMount`：发请求、订阅（这里可 `setState`）。
- `componentDidUpdate(prevProps, prevState)`：依赖变化后的二次处理。
- `componentWillUnmount`：清理定时器、取消订阅。
- `shouldComponentUpdate(nextProps, nextState)`：返回 false 跳过渲染优化。

④ **与函数组件映射**：`componentDidMount` ≈ `useEffect(..., [])`；`componentWillUnmount` ≈ useEffect 的清理函数。

### Q68: Vue 2 和 Vue 3 的核心区别有哪些？

### Q69: Vue 的响应式原理是什么（Vue 2 与 Vue 3 有何不同）？

① **一句话结论**：Vue 通过"依赖收集 + 触发更新"实现响应式；Vue 2 用 `Object.defineProperty` 劫持属性，Vue 3 用 `Proxy` 代理对象。

② **整体流程**：初始化时把 `data` 转成响应式 → 在 getter 中收集依赖（当前渲染 watcher）→ 在 setter 中触发依赖更新 → 调度重新渲染。

③ **Vue 2 局限**：

- `Object.defineProperty` 只能劫持已有属性，`Vue.set` 才能新增。
- 数组索引/长度变更检测不到。

④ **Vue 3（Proxy）**：

```js
const raw = { count: 0 };
const proxy = new Proxy(raw, {
  get(target, key) { track(target, key); return target[key]; },
  set(target, key, value) { target[key] = value; trigger(target, key); return true; },
});
```

- 可监听整对象、新增属性、数组下标，代码更简洁。

⑤ **追问**：`ref` 与 `reactive` 区别？`track/trigger` 的依赖收集大致怎么实现？

### Q70: 计算属性 `computed` 和侦听器 `watch` 有什么区别？

① **一句话结论**：`computed` 根据已有响应式数据派生出新值并缓存；`watch` 监听数据变化去执行副作用。

② **对比**：

| 特性 | computed | watch |
|------|----------|-------|
| 目的 | 派生/计算值，供模板或逻辑使用 | 监听变化做处理（请求、副作用） |
| 缓存 | 依赖不变缓存结果 | 不缓存 |
| 使用 | 模板里直接当变量读 | 去执行回调 |
| 是否必须返回 | 是（返回新值） | 否（执行逻辑） |

```vue
<script setup>
import { computed, watch } from 'vue';
const price = ref(10), qty = ref(2);
const total = computed(() => price.value * qty.value);
watch(total, (v) => console.log('total changed', v));
</script>
```

③ **建议**：能用 `computed` 就用 `computed`（声明式、缓存、更易读）；只有需要"做了某事"时才用 `watch`。

### Q71: Vue 组件之间有哪些通信方式？

② **方式枚举**：

- **事件总线**：`mitt`。

③ **官方推荐**：父→子用 props，子→父用 emit，跨层级低频用 provide/inject，复杂共享用 Pinia。

### Q72: Vue Router 的路由原理是什么？有哪些模式？

① **一句话结论**：Vue Router 有两类模式——`history` 基于 History API（现代），`hash` 基于 URL 锚点（兼容），核心是"URL 变化驱动视图切换"。

② **hash 模式**：URL 带 `#`，`hashchange` 事件监听变化，**不会向服务器发请求**，刷新/部署简单，兼容老浏览器。

④ **流程**：路由变化 → 匹配路由记录 → 渲染对应组件（`<router-view>`）。

### Q74: webpack 的核心概念有哪些？打包流程是怎样的？

① **一句话结论**：webpack 是"模块打包器"，核心概念包含 entry / output / module / loader / plugin / resolve；流程是"找入口 → 加载转换 → 形成依赖图 → 输出 bundle"。

② **核心概念**：

- **entry**：入口文件。
- **output**：输出路径与文件名。
- **loader**：把非 JS 文件（CSS、图片、TS 等）转换并交给 JS 模块（`use`）。
- **plugin**：在打包生命周期钩子里做增强（HtmlWebpackPlugin、SplitChunks）。
- **resolve**：模块解析（别名 alias、扩展名）。
- **mode**：`development` / `production`。

③ **打包流程**：

1. 从 entry 解析模块，加载并匹配 loader 转换。
2. 递归收集依赖，构建依赖图（Module Graph）。
3. 对模块做优化（Tree Shaking、代码分割）。
4. 打包成 chunk，输出到 output。

④ **追问**：loader 与 plugin 的区别？webpack 按需加载怎么配置（懒加载 chunk）？

### Q75: Vite 和 webpack 有什么区别？

② **对比**：

| 维度 | Vite | webpack |
|------|------|---------|
| 开发启动 | 原生 ESM，按需预构建（esbuild）快 | 全量打包，启动较慢 |
| HMR | 按需细粒度，快 | 整套打包热更 |
| 生产构建 | 底层用 Rollup esbuild | webpack 自研 |
| 生态 | 现代、更简洁配置 | 生态庞大、老项目多 |

③ **原理**：Vite 开发期把源码按 ESM `import` 直接发给浏览器，仅对依赖用 esbuild 预构建；webpack 需要先把所有模块打包成 bundle。

④ **选型**：新项目常用 Vite；老项目/复杂定制场景 webpack 仍广泛存在。

### Q76: 什么是模块化？CommonJS 和 ESM 的区别？

① **一句话结论**：模块化是把代码拆成可复用、有独立作用域的单元；CommonJS（`require`，Node 端）与 ESM（`import/export`，标准按需静态）是两种主流规范。

② **区别**：

| 特性 | CommonJS | ES Module |
|------|----------|-----------|
| 语法 | `require` / `module.exports` | `import` / `export` |
| 加载时机 | 运行时同步加载 | 编译期静态分析（可 Tree Shaking） |
| 动态 import | 天然支持 | 需要 `import()` |
| 顶层 await | 不支持 | 支持 |
| 浏览器 | 不直接支持 | 原生支持（script type=module） |

③ **示例**：

```js
// CommonJS
const { readFileSync } = require('fs');
module.exports = { demo: 1 };

// ESM
import { readFileSync } from 'fs';
export const demo = 1;
```

④ **意义**：ESM 的静态性让打包器能做 Tree Shaking、更优的优化。

### Q77: 什么是 Tree Shaking？它基于什么原理？

① **一句话结论**：Tree Shaking 是"摇树删除无用代码"，把未使用的导出移除，从而减小打包体积；其原理依赖 ESM 的静态导入分析。

② **原理**：

- ESM 的 `import/export` 是静态的（编译期已知），打包器能分析"哪个导出被用到、哪个没用到"。
- 生产构建时，未被引用的模块 / 导出会被移除（配合 `sideEffects`、minifier 移除无副作用死代码）。

③ **要求**：

- 使用 ESM（不能用 CJS 的 `require`，会导致无法静态分析）。
- `package.json` 声明 `"module"` 字段 / `"sideEffects": false`。
- 生产环境启用压缩（Terser 等）。

④ **追问**：副作用（sideEffects）怎么标记？为什么 lodash 需要按需引入（`lodash-es`）？

### Q79: 前端核心性能指标有哪些（LCP / CLS / INP 等）？

① **一句话结论**：核心 Web 指标（Core Web Vitals）为 LCP、INP、CLS，分别衡量加载、交互、视觉稳定。

② **指标解释**：

- **LCP（Largest Contentful Paint）**：最大内容绘制时间，衡量首屏主内容加载速度。目标 `< 2.5s`。
- **INP（Interaction to Next Paint）**：交互到下一帧的响应延迟，衡量交互体验。目标 `< 200ms`。
- **CLS（Cumulative Layout Shift）**：累积布局偏移，衡量页面抖动。目标 `< 0.1`。

③ **其他**：FCP（首次内容绘制）、TTFB（首字节）、TBT（阻塞总时间）、FID（已废弃，交棒给 INP）。

④ **测量工具**：Lighthouse、Performance 面板、`web-vitals` 库、浏览器 `performance` API。

⑤ **追问**：如何优化 LCP（预加载/资源优先级）、CLS（占位尺寸）？

### Q81: 图片懒加载如何实现？有哪些方案？

```js
const io = new IntersectionObserver((entries) => {

    if (e.isIntersecting) {
      const el = e.target;
      el.src = el.dataset.src;
```

### Q82: 什么是虚拟滚动？在什么场景下使用？

① **一句话结论**：虚拟滚动只渲染可视区域内的一小部分元素（几十个），用"滚动位置 + 偏移替换"，应对"上万条长列表"卡顿问题。

② **原理**：

- 容器固定高度，监听滚动拿到 scrollTop。
- 根据 item 高度算出可视区起止索引 `start/end`。
- 只渲染 `[start, end]` 之间的 items，并用上下 padding 或 translate 撑起总高度保持滚动条正确。

```jsx
// 伪代码
const { start, end } = computeRange(scrollTop, itemHeight, viewHeight);
<div onScroll={onScroll}>
  <div style={{ height: total, position:'relative' }}>
    <div style={{ transform: `translateY(${start*itemHeight}px)` }}>
      {slice(items, start, end).map(Item)}
    </div>
  </div>
</div>
```

③ **场景**：聊天记录、Feed 流、日志列表、表格大行数、下拉大数据。

④ **注意**：使用 `key` 复用；配合"不定高"需动态测量（virtual 库内部处理）。

⑤ **追问**：固定高度与动态高度的虚拟滚动有什么不同？虚拟滚动怎么抵消滚动空档（缓存 range）？

### Q83: 长列表/大数据量渲染如何优化？

① **一句话结论**：核心思路是"能不渲染的就不渲染"——分页/懒渲染、虚拟滚动、分片渲染，配合合理状态与 `memo`。

② **方案**：

- **分页/加载更多**：按需拉取与渲染。
- **虚拟滚动**：只渲染可视区的几十条（上题详解）。
- **分片渲染（time-slicing）**：用 `requestIdleCallback` 或按帧分割，避免一次渲染大量节点卡住主线程。
- **React.memo / Vue 的 v-memo**：避免无关子组件重复渲染。
- **数据量级**：大数组用不可变更新、索引查询，避免全量遍历。

③ **辅助**：列表项自身的 `shouldComponentUpdate`（较复杂）或 `useMemo` 缓存计算。

④ **追问**：immutable 更新 vs 原地修改的性能差异？大数据用 Table 组件的虚拟化（如 Ant Table virtual）？

## 第七阶段：TypeScript 进阶（84-86）

### Q84: 什么是联合类型、交叉类型、条件类型、索引签名？

① **一句话结论**：联合类型表示"多选一"，交叉类型表示"全都要"，条件类型按判断分派，索引签名用 `[key: string]` 约束对象键。

② **联合（Union `|`）**：`type A = string | number`，取值是其中一种。

**交叉（Intersection `&`）**：`type B = {a:number} & {b:string}`，需同时满足全部属性。

```ts
type Result = Success & {data: T};   // 交叉
type ID = string | number;           // 联合
type IsStr<T> = T extends string ? true : false; // 条件
interface Dict { [key: string]: number }         // 索引签名
```

③ **条件类型（T extends U ? X : Y）**：依赖泛型做类型分派，配合递归构建类型体操。

④ **索引签名**：`[key: string]: V` 声明"任意字符串键对应的值类型"，常用于映射对象；注意与具体属性能否共存、`Record` 的关系。

⑤ **追问**：`infer` 关键字配合条件类型的用法（提取函数返回值 `ReturnType`）？

### Q85: 装饰器是什么？在项目中如何使用？

① **一句话结论**：装饰器是给"类 / 类属性 / 方法 / 参数"打标签或增强能力的语法（`@xxx`），常用于记录元数据与 AOP。

② **原理**：装饰器本质是函数，接收目标（constructor / prototype / 属性描述符等），可修改实现或产出元数据；配合 `Reflect.defineMetadata` 记录信息。

```ts
function readonly(target: any, key: string) {
  Object.defineProperty(target, key, { writable: false });
}
class User { @readonly name = 'x'; }
```

③ **项目使用场景**：

- 表单校验声明（验证错误产物）。
- 权限标注 `@NeedLogin`。
- Nest/DI、类型信息反射。
- 组件/路由的声明式配置。

④ **注意**：标准装饰器（stage-3）与新提案存在 API 差异，TS 需开启 `experimentalDecorators`。

⑤ **追问**：装饰器与高阶组件（HOC）的区别？装饰器顺序与应用层级？

### Q86: 你在使用 TypeScript 的项目中遇到过哪些坑？如何规避？

① **一句话结论**：常见坑有 `any` 滥用、类型断言错误、`tsconfig` 配置不当、与 JS 库类型缺失、泛型推论不达预期。

② **常见坑与对策**：

- **大量 `any`**：外部响应不确定 → 用 `unknown` + 收窄 + 类型守卫，接口定义 DTO。
- **处理 Promise 类型丢失**：`await` 后类型变类型断言需显式写 `Promise<T>`。
- **`strict` 未开启**：漏判 `null`/`undefined` → 开启 `strict` 并在配置里 `strictNullChecks`。
- **第三方库无类型**：配合 `@types/pkg` 或写 `.d.ts` 声明。
- **模块解析不一致**：统一 `moduleResolution` / `paths` 别名。
- **泛型组件推断不理想**：用更精确的约束 + 泛型变量名规范。

③- **实践**：接口统一用 `interface` 或 `DTO`，枚举用 const enum，错误集中在类型边界处理。

④ **追问**：如何给一个没有类型的复杂 SDK 写 `.d.ts`？`satisfies` 解决什么问题？

## 第八阶段：浏览器存储与安全（87-90）

### Q87: `IndexedDB` 和 `localStorage` 有什么区别？

① **一句话结论**：`IndexedDB` 是浏览器内嵌的"NoSQL 数据库"（支持大量结构化数据、索引、事务），`localStorage` 是简单位值存储（小、同步）。

② **对比**：

| 特性 | localStorage | IndexedDB |
|------|-------------|-----------|
| 容量 | ~5MB | 大（可达数百 MB/GB） |
| 数据结构 | 仅字符串 | 多种，对象/索引 |
| API | 同步、简单 | 异步、回调/Promise |
| 支持索引/范围查询 | 否 | 是 |
| 事务 | 无 | 支持 |

③ **应用**：`IndexedDB` 存离线数据、大数据缓存、本地缓存静态资源；`localStorage` 存简单偏好/标记。

④ **封装**：工作中常用库如 `localforage`、`Dexie` 简化 IndexedDB 使用。

⑤ **追问**：离线应用如何结合 IndexedDB 做持久化（PWA）？缓存策略怎么设计？

### Q88: 什么是 XSS 攻击？如何防御？

① **一句话结论**：XSS（跨站脚本）是攻击者把恶意脚本注入页面，在用户浏览器执行，窃取数据/冒充用户。

② **成因**：未对用户输入 / 服务端回显进行转义或过滤，脚本被当作 HTML/JS 执行。

③ **常见类型**：

- **存储型**：恶意脚本存服务器，每次访问都被执行（如评论区）。
- **反射型**：恶意参数拼进 URL，一次性返回执行。
- **DOM 型**：前端 JS 把不可信数据写入 DOM（`innerHTML`）。

④ **防御**：

- **转义/编码**：输出时对 `& < > " '` 转义；框架默认转义（`textContent`、React/Vue 插值默认转义）。
- **不使用 `innerHTML` 拼不可信内容**；如用 `v-html` 需过滤。
- **CSP**：设置 `Content-Security-Policy` 限制脚本来源/不执行内联。
- **HttpOnly Cookie**：防止 JS 窃取凭证。

⑤ **追问**：CSP 如何配置？`textContent` vs `innerHTML` 安全区别？

---

### Q89: 什么是 CSRF 攻击？如何防御？

① **一句话结论**：CSRF（跨站请求伪造）是攻击者"借用户的登录态"伪造用户发起请求，执行非用户本意的操作。

② **成因**：浏览器会自动携带目标站点的 Cookie（即使来自恶意站点发起请求），攻击者诱导用户触发请求。

③ **场景**：用户在银行已登录，攻击者构造一个向 `bank.com/transfer` 发送 POST 的页面，用户访问即被转账。

④ **防御**：

- **SameSite Cookie**：`SameSite=Lax/Strict` 限制跨站请求携带 Cookie（现代主要手段）。
- **CSRF Token**：请求带随机 token，服务端校验。
- **校验来源**：`Origin` / `Referer` 头校验。
- **双重提交 / 验证码**：敏感操作要求二次确认。

⑤ **追问**：SameSite 的 Lax/Strict/None 具体行为？GET 请求怎么避免被利用？

---

### Q90: `Cookie` 的 `HttpOnly`、`Secure`、`SameSite` 属性各有什么作用？

① **一句话结论**：三者分别防护"JS 读取、非 HTTPS、跨站携带"三类风险，是 Cookie 安全三件套。

② **属性作用**：

- **HttpOnly**：禁止 JS（document.cookie）读取该 Cookie，防止 XSS 窃取凭证。
- **Secure**：仅在 HTTPS 连接下发送，防止明文传输被窃听。
- **SameSite**：控制跨站请求是否携带 Cookie，防护 CSRF。取值：`Strict`（严格，跨站不带）、`Lax`（GET 顶层导航带，其余不带）、`None`（都带，必须配 Secure）。

③ **示例**：

```text
Set-Cookie: session=abc; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=86400
```

④ **建议**：登录凭证用 HttpOnly + Secure，配合 SameSite 提升安全。

⑤ **追问**：token 存 Cookie 还是 localStorage？为什么有时用 `SameSite=None`？

### Q92: 什么是 MVVM？它和 MVC 有什么区别？

① **一句话结论**：MVVM 是 Model-View-ViewModel，视图与模型解耦，由 ViewModel（框架响应式层）双向绑定驱动，React/Vue 都属于 MVVM 思想。

② **三者职责**：

- **Model**：数据与业务逻辑。
- **View**：界面。
- **ViewModel**：连接 View 与 Model，监听数据变化自动更新视图（双向绑定）。

③ **MVC vs MVVM**：

- **MVC**：Controller 手动接收输入、更新 Model 再刷新 View，逻辑在 Controller，视图与控制器耦合较重。
- **MVVM**：ViewModel 自动响应数据变化刷新视图，数据驱动、声明式，逻辑分担更好测试。

④ **说明**：Vue 的双向绑定（v-model）、React 的"数据驱动视图"都是 MVVM 思想变体。

⑤ **追问**：MVVM 中"数据变化如何自动刷新视图"对应框架里的什么机制（响应式）？

### Q93: 组件设计有哪些原则？如何设计可复用组件？

① **一句话结论**：组件设计遵循"单一职责、接口稳定、组合复用、可测"等原则，像设计 API 一样设计组件。

② **原则**：

- **单一职责**：一个组件只做一件事。
- **接口稳定（Props 即公有 API）**：命名清晰、类型明确，避免过度依赖内部实现。
- **数据驱动与受控**：值由 props/state 决定，暴露事件回调。
- **可组合**：通过插槽（slot children）/ 子组件组合能力。
- **可复用而非"万能"**：通过 props + 样式扩展，而非每处 copy。
- **关注性能**：React.memo / 合理拆分粒度。

③ **实践**：组件分类为基础组件 / 业务组件 / 页面组件；用 storybook 与 TS 定型。

④ **追问**：如何做组件库的版本/API 兼容（kebab-case vs 命名空间）？可访问性（a11y）如何保证？

### Q94: 单页应用（SPA）和传统多页面（MPA）的区别及优缺点？

① **一句话结论**：SPA 只有一个 HTML 页、前端路由切换视图，MPA 是多个独立 HTML 页面、整页刷新。

② **对比**：

| 特性 | SPA | MPA |
|------|-----|-----|
| 页面数量 | 单 HTML，前端路由 | 多 HTML |
| 切换 | 前端局部更新，不刷新 | 整页刷新请求 |
| 首屏 | 需先加载 JS 较大 | 每页各自加载，首屏相关内容小 |
| SEO | 弱（需 SSR） | 好 |
| 体验 | 流畅、交互强 | 切换有刷新等待 |
| 维护 | 工程化强、状态管理统一 | 相对分散 |

③ **选型**：管理后台/交互应用用 SPA；内容型/SEO 强依赖用 MPA 或 SSR（Next/Nuxt）。

④ **追问**：SPA 的 SEO 问题怎么解决（SSR/预渲染）？SPA 与 MPA 如何共存？

### Q95: 什么是状态管理？中大型项目中为什么需要它？

① **一句话结论**：状态管理是把跨组件共享、易变的"应用状态"集中托管，并提供可预测的更新机制；中大型项目用它应对"多组件共享数据 + 复杂交互 + 可维护排查"。

② **解决的问题**：

- 兄弟/跨层级组件共享状态（如用户信息、购物车）。
- 状态来源多变更频繁，手动传递易失控。
- 需要统一的 action 轨迹、时间旅行、调试、持久化。

③ **核心思路（以 Redux/Zustand/Pinia 为参照）**：

- **单一数据源**：一个全局 store。
- **单向数据流**：`state → view → action → reducer → state`。
- **不可变更新**：返回新状态，可预测、可调试。

④ **边界**：不是所有项目都需要，过度使用反而增加复杂度；就近状态用组件内 state，跨层才用全局 store。

⑤ **追问**：状态上升（lifting state up）与全局 store 的选择？Redux 与 React context 的取舍？
