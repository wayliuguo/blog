## 一、五步答题法

### 什么是五步答题法？

① **一句话结论** → 用最简练的话给核心答案，先让面试官抓住要点。

② **原理剖析** → 深入底层原理，讲"为什么"，而不只是"怎么用"。

③ **场景举例** → 结合真实项目说明在什么场景用、怎么用，体现实战。

④ **优缺点与边界** → 主动讲局限与适用边界，体现辩证思维。

⑤ **追问预判** → 想好面试官可能顺藤摸瓜追什么，主动铺垫、掌控节奏。

---

### 示例：什么是虚拟 DOM？

**① 一句话结论**：虚拟 DOM 是用 JS 对象描述真实 DOM 的结构，框架通过对比新旧 VDOM 的差异最小化更新真实 DOM。

**② 原理剖析**：渲染时生成 VNode 树，更新时 `diff` 新旧 VNode（同层比较 + key 复用），把差异批量 `patch` 到真实 DOM。它天然具备跨平台能力（能渲染到 DOM / Native / Canvas）。

**③ 场景举例**：在 React/Vue 组件更新时，我们不手动 `document.querySelector` 改 DOM，而是声明式更新数据，框架自动 diff 只改变化部分，避免频繁 DOM 操作丢失性能。

**④ 优缺点与边界**：优点是跨平台、批量更新、声明式可预测；缺点是 VNode 与 diff 本身有成本，对超大列表不如手写 DOM 优（需虚拟滚动或增量渲染）。它是"开发体验 + 可预测性"与"绝对性能"取舍下的产物。

**⑤ 追问预判**：可能追问——"diff 的 key 原理？"、"虚拟 DOM 与 Web Components 的区别？"、"为什么大列表会卡（diff 全蒙）？"

---

### 示例：什么是响应式（Vue）？

**① 一句话结论**：响应式是"数据变化 → 自动更新视图"的机制，Vue 通过依赖收集 + 触发更新实现。

**② 原理剖析**：初始化时把 data 转成响应式（Vue2 用 `Object.defineProperty` 劫持属性，Vue3 用 `Proxy` 整体代理）；读取时 `track` 收集依赖（当前渲染 watcher），修改时 `trigger` 调度依赖执行更新的渲染。

**③ 场景举例**：表单输入绑定 `v-model`、列表数据变化自动补行，都是响应式自动完成的，我们无需手动刷新页面。

**④ 优缺点与边界**：优点是开发省心、细粒度更新；缺点是需要理解"响应式心智"（ref/reactive 的自动解包、Proxy 需现代环境）；对初学者隐性成本高。

**⑤ 追问预判**：常见追问——"Vue3 为什么用 Proxy 换 defineProperty？"、"ref 与 reactive 区别？"、"响应式与 diff 是什么关系？"

---

### 示例：什么是跨域？

**① 一句话结论**：跨域是浏览器同源策略对"协议/域名/端口任一不同"的请求限制，需通过 CORS 或代理解决。

**② 原理剖析**：为了防止恶意站点读取其他网站数据，浏览器阻止跨源响应被读取；合法跨站需服务端返回 `Access-Control-Allow-Origin` 等 CORS 头，复杂请求还发 `preflight` 预检。

**③ 场景举例**：`localhost:3000` 前端请求 `api.example.com`，开发期用 Vite/Rollup 代理（devProxy），生产用 Nginx 反代或服务端配置 CORS。

**④ 优缺点与边界**：CORS 是标准方案但需服务端配合；代理不改请求本身；非同源脚本等特殊资源不受同源限制（JSONP 原理）。

**⑤ 追问预判**：可能追问——"CORS 与 JSONP 区别？"、"preflight 什么情况触发？"、"如何优雅跨多个域名（配置白名单）？"

## 二、常见追问链

> 前端面试大量是"连环追问"，把单个知识点挖成一条链。这里给出几条高频主线。

### 追问链 1：事件循环

```
Q: 为什么 JS 是单线程？
  └── Q: 那异步怎么实现（回调/任务队列）？
        └── Q: 宏任务与微任务分别有哪些？
              └── Q: 一轮循环中宏/微任务怎么交替？
                    └── Q: 写段代码预测 setTimeout 0 与 Promise.then 输出顺序？
                          └── Q: 浏览器与 Node 事件循环差异？
```

### 追问链 2：HTTP 缓存

```
Q: 什么时候命中缓存而不发请求？
  └── Q: 强缓存靠哪个字段（Cache-Control/Expires）？
        └── Q: 强缓存失效后呢（协商缓存）？
              └── Q: 协商缓存 Last-Modified 与 ETag 区别？
                    └── Q: 静态资源如何配合 hash 指纹更新？
```

### 追问链 3：React 渲染知识

```
Q: 什么会触发 React 重渲染？
  └── Q: setState 是同步还是异步？批量提交？
        └── Q: 如何避免不必要的重渲染（memo / useCallback）？
              └── Q: diff 的三大策略是什么？
                    └── Q: 为什么 index 不能当 key？
```

### 追问链 4：Vue 响应式

```
Q: Vue 如何知道数据变了？
  └── Q: 依赖收集怎么做的（track/trigger）？
        └── Q: Vue2 的 defineProperty 有什么坑？
              └── Q: Vue3 为什么换 Proxy？好处？
                    └── Q: ref 是怎么实现的基本类型响应式的？
```

### 追问链 5：SSR

```
Q: 什么是 SSR？
  └── Q: 和 CSR 的区别？
        └── Q: 同构/Hydration 是什么？
              └── Q: 数据如何服务端取、避免重复请求？
                    └── Q: SSR 挂了怎么降级（CSR fallback）？
```

### 追问链 6：性能优化

```
Q: 页面首屏慢如何排查？
  └── Q: 是网络多还是渲染慢（怎么定位）？
        └── Q: 相关指标 LCP/FID/INP 理解？
              └── Q: 如何优化（懒加载/分包/缓存）？
                    └── Q: 如何持续监控与验证收益？
```

## 三、项目包装

### STAR 法则

| 环节 | 说明 | 话术要点 |
|------|------|----------|
| **S**ituation | 项目背景 | 业务目标、团队、你扮演的角色 |
| **T**ask | 具体任务/挑战 | 量化：性能瓶颈、QPS、数据量、事故 |
| **A**ction | 你的具体动作 | 技术选型、架构设计、实现与解决过程 |
| **R**esult | 最终成果 | 量化：性能提升百分比、错误率下降、人效 |

---

### 前端项目包装示例

**项目背景**：某电商中后台 + 可视化大屏，日请求数百万，首屏 3s+，滚动列表卡顿，跨部门低频复用组件重复造。

**S**：我是前端核心开发，负责订单大数据表格与监控大屏的重构。

**T**：订单列表 20 万行渲染导致首屏卡顿 4s、操作掉帧；大屏多图表刷新时整屏重绘；组件的 CRUD 页面开发成本高、复用差。

**A**：

- 用虚拟滚动重写订单表格，只渲染可视区行，首屏降到秒。
- 大屏改"配置化 DataMap + 分层刷新"，实时指标走 WebSocket 增量 `setOption`，静态层离屏缓存。
- 沉淀组件库（Form/Table 封装 + 权限指令），后续同类页面用配置 + 拖拽生成，schema 驱动。

**R**：列表首屏 4s→0.8s，滚动稳定 60fps；大屏单图表增量刷新不再整屏闪烁；新表单页面开发时间压缩约 60%，组件复用率提升显著。

> 提示：每个数字要经得起追问，答案文件里的技术点（虚拟滚动/增量化/低代码 schema）正好能支撑核对。

## 四、软素质与岗位匹配

### 软素质（behavioral）

- **沟通**：先结论后细节；用结构化（一二三）铺陈；听不懂先复述确认。
- **协作**：强调 code review、文档、技术方案评审、前后端/跨团队协同。
- **学习**：给一个"我是怎么学新技术/踩坑复盘"的具体例子。
- **抗压/ownership**：谈一次上线事故或紧急修复中你承担的角色与结果。

### 岗位匹配

- 打听清楚岗位偏"业务开发"还是"基建/可视化/低代码/音视频/跨端"，把答案向岗位需要的深度领域倾斜（如基建岗重点谈工程化与监控，可视化岗重点谈 Canvas/WebGL 与 LOD）。
- 主动表明"技术广度 + 岗位深度的结合"，用已补齐的章节（06 工程化基建、10 可视化、15 低代码、16 音视频、17 游戏、18 新兴、13 SSR、12 跨端）对应岗位要求。

## 五、如何复盘

**复盘流程**：

1. 结束后立刻回忆问题列表，标记"答得好/一般/翻车"。
2. 翻车题回到 [01-面试自测题](./01-面试自测题) / 答案文件，把"我当时怎么答"与"标准答法"对比。
3. 提炼"没答好的原因"——是没掌握、答非所问、还是紧张组织不好。
4. 建立"薄弱题号清单"（用 [08-自测记录表](./08-自测记录表)），针对性补。
5. 把追问链没接住的点记下来，下次主动把完整链条讲通。

**复盘产出**：整理出一份"个人高频翻车点"清单，反问自问——每次回答是否都做到了"结论→原理→场景→边界→追问"。

## 六、常见误区（避坑清单）

| 常见错误 | 表现 | 应对策略 |
|----------|------|----------|
| **只背概念** | 纯背诵，不变场景 | 每个知识点绑一个真实用过的场景；没用到就说"理论上…" |
| **答非所问** | 问 A 答 B | 停顿 2 秒组织，先确认问题再回答 |
| **堆砌术语** | 名词多但说不透 | 每个术语至少能解释原理与边界 |
| **硬编不会的** | 乱编漏洞百出 | 诚实"这块了解不深，我目前的理解是…" |
| **只说'会用'** | 没有原理 | 框架题追问到底层（Fiber/响应式/diff） |
| **项目太浅** | 只说做了什么没细节 | STAR + 量化 + 具体技术方案 |
| **忽视边界** | 只讲正常流程 | 主动补"这里还要考虑 XX 边界/异常" |
| **不主动引导** | 被动一问一答 | 答完"这块我可以展开讲 XX，需要吗？" |
| **简历夸大** | 细节经不起问 | 简历每一条能展开讲 5 分钟 |

## 七、技术面各类型题应对速查

| 题型 | 考察 | 应对要点 |
|------|------|---------|
| 概念题 | 是否理解 | 一句话结论 + 原理 + 边界 |
| 手写题 | 编码/边界 | 先列输入输出与边界，再写，写小步、注释意图 |
| 场景设计题 | 架构/权衡 | 先定思路与模块划分，给出选型理由与边界（见 [06-场景设计题](./06-场景设计题)）|
| 代码输出题 | 运行理解 | 关注事件循环、作用域/闭包、类型转换 |
