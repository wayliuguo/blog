> 答题建议套用五步法：① 一句话结论 ② 原理剖析 ③ 场景举例 ④ 优缺点与边界 ⑤ 追问预判。

## 第一阶段：入门与开发环境（1-5）

### Q1: 什么是前端开发？前端工程师需要掌握哪些核心技能？

① **一句话结论**：前端开发是负责用户在浏览器/客户端中看到和交互的内容的开发工作，涵盖结构、样式、交互与性能。

② **原理剖析**：前端以 HTML（结构）、CSS（样式）、JavaScript（行为）三个语言为基础，运行在浏览器渲染环境中，通过 HTTP 从后端获取数据。

③ **核心技能**：

- 三件套：HTML、CSS、JavaScript
- 进阶：TypeScript、前端框架（React/Vue）、工程化（webpack/Vite/npm）
- 通用：HTTP/网络、浏览器原理、调试工具、Git、性能优化

④ **边界**：前端还需具备基础审美与产品思维，但沉淀沉淀的核心永远是"渲染 + 交互 + 数据"。

⑤ **追问**：前端和后端的分工边界在哪？SSR 会让前端跑到服务器吗？

---

### Q2: HTML、CSS、JavaScript 三者的职责分别是什么？它们是如何配合的？

① **一句话结论**：HTML 管结构、CSS 管表现、JavaScript 管行为，三者各司其职共同构成网页。

② **原理剖析**：

- HTML（结构）：定义页面里有"什么"——标题、段落、按钮、表单。
- CSS（表现）：定义这些内容"长什么样"——颜色、布局、动画、响应式。
- JS（行为）：定义这些内容"怎么动"——点击、输入、请求接口、更新页面。

③ **配合方式**：浏览器先解析 HTML 构建 DOM 树，再解析 CSS 构建 CSSOM，JS 通过 DOM API 动态读写 DOM 并结合样式更新界面。

④ **优点**：关注点分离，便于维护与分工。**边界**：现代前端把三者打包进组件，但仍需理解底层分离逻辑。

⑤ **追问**：JS 是如何操作 DOM 和样式的？重排重绘发生在哪一层？

---

### Q3: 浏览器开发者工具（DevTools）常用的能力有哪些？

① **一句话结论**：DevTools 是浏览器内置的调试终端，能查看 DOM、调试 JS、分析网络与性能。

② **常用面板**：

- **Elements**：查看/修改 DOM 结构与样式，可实时调试 CSS。
- **Console**：查看日志、执行 JS 表达式、排查报错。
- **Network**：查看请求/响应、状态码、耗时、缓存命中。
- **Sources**：打断点、单步调试 JS、查看作用域。
- **Performance**：录制并分析渲染与脚本性能。
- **Application**：查看 Cookie、localStorage、IndexedDB。

③ **场景举例**：页面样式不对 → Elements 改 CSS 实时预览；接口报 404 → Network 看请求路径。

④ **边界**：DevTools 是开发期工具，性能面板是分析 Local 环境的利器。

⑤ **追问**：如何看某个接口的响应时间和请求头？如何模拟弱网和移动端？

---

### Q4: 从你输入一个网址到页面显示，大概会经历哪几个步骤？

① **一句话结论**：DNS 解析 → TCP 连接 → HTTP 请求/响应 → 浏览器解析渲染。

② **关键步骤**：

1. 输入 URL，浏览器解析协议、域名、路径。
2. DNS 解析：把域名解析成 IP 地址。
3. 建立 TCP 连接（三次握手），HTTPS 还需 TLS 握手。
4. 发送 HTTP 请求，服务器返回 HTML。
5. 浏览器解析 HTML 构建 DOM 树，加载并解析 CSS/JS，形成渲染树并绘制。

③ **边界**：现代浏览器会有缓存（强缓存直接命中不请求）、CDN、HTTP/2 多路复用等优化。

①③④⑤ 可用一段话：`输入URL → DNS → TCP → HTTP → 服务器响应 → 渲染绘制`。

⑤ **追问**：会讲 DNS 缓存吗？会讲重排重绘放在哪里发生吗？

---

### Q5: 如何在浏览器中查看并调试 JS 报错？

① **一句话结论**：打开 DevTools 的 Console 看报错日志，用 Sources 打断点定位。

② **步骤**：

1. F12 打开 DevTools → Console 面板，红色即为 JS 运行时错误（含堆栈与文件行号）。
2. 点击堆栈中的文件+行号跳转到 Sources。
3. 在该行打断点，刷新后单步执行（Step over/into），查看调用栈与变量。
4. 用 `console.log` / `debugger` 辅助观察。

③ **常见错误类型与排查**：

- 空指针：找不到 `undefined` 的属性 → 检查是否先判空或初始化。
- 类型错误：调用不存在的方法。
- 作用域错误：变量未定义。

④ **技巧**：`console.table`、`console.time`、`console.group` 让调试更高效。

⑤ **追问**：sourcemap 不生效怎么办？如何优雅地统一处理全局异常？

## 第二阶段：HTML 基础（6-10）

### Q6: 什么是 HTML 语义化？有哪些常用的语义化标签？

① **一句话结论**：语义化是使用有意义的标签描述内容含义，而非都用 `<div>`。

② **常用语义化标签**：

- 结构：`<header>` 页头、`<nav>` 导航、`<main>` 主体、`<footer>` 页脚
- 内容：`<article>` 文章、`<section>` 区块、`<aside>` 侧栏
- 文本：`<h1>-<h6>` 标题、`<p>` 段落、`<strong>` 强调、`<em>` 斜体强调

③ **好处**：提升可读性、利于 SEO、利于无障碍访问（读屏软件）、代码更规范。

④ **要点**：`h1` 页面尽量只用一个主标题；表单用 `<label>` 关联 `<input>`。

⑤ **追问**：语义化对无障碍（a11y）有哪些帮助？结构标签如何嵌套？

---

### Q7: `<div>` 和 `<span>` 有什么区别？

① **一句话结论**：`<div>` 是块级容器，`<span>` 是内联容器，二者都常用于"语义不明的包裹盒"。

② **区别**：

| 属性 | div | span |
|------|-----|------|
| 显示类型 | 块级（独占一行） | 内联（不换行，与文字同行） |
| 默认样式 | 无 | 无 |
| 用途 | 页面分块布局 | 行内文本切片 |

③ **边界**：两者都无语义，能用语义标签就别用 div/span 包裹功能块。

④ **追问**：`display:block/inline/inline-block` 区别？

---

### Q8: 块级元素与内联元素（行内元素）有什么区别？

① **一句话结论**：块级独占一行可设宽高，内联不换行且宽高由内容决定。

② **对比**：

- **块级**：独占一行，`width/height/margin/padding` 生效，如 `div/p/h1/ul/li`。
- **内联**：不换行，同行排列，宽高不可直接设置（内容撑开），如 `span/a/em/strong`。
- **inline-block**：兼有二者——不换行却又可设宽高，如 `img`。

③ **场景**：导航链接用 inline-block 排横排但可设内边距。

⑤ **追问**：display:none 和 visibility:hidden 的区别？浮动对内联元素的影响？

---

### Q9: HTML5 有哪些重要的新特性？

① **一句话结论**：HTML5 引入了全新语义标签、多媒体、表单控件以及更强的浏览器能力 API。

② **主要内容**：

- **语义标签**：`header/nav/section/article/footer`
- **多媒体**：`<video>`、`<audio>`
- **画布/图形**：`<canvas>`、内联 `SVG`
- **表单**：新的 input 类型 `email/number/date/range`、`placeholder/required/pattern` 属性、`datalist`
- **JS API**：`localStorage/sessionStorage`、`history.pushState`（SPA 路由）、`WebSocket`、`requestAnimationFrame`、拖放与 `Web Worker`

③ **意义**：让浏览器成为能力更强的应用平台，为后面 SPA、可视化、实时通信打基础。

④ **边界**：部分新 API（如 WebGL/WebRTC）需要现代浏览器支持，需考虑兼容。

⑤ **追问**：`<canvas>` 和 `<video>` 的实现原理？Web Worker 解决什么问题？

---

### Q10: `<form>` 表单中常见的 `<input>` 类型和常用属性有哪些？

① **一句话结论**：input 类型决定输入形态与校验方式，属性控制行为与约束。

② **常见 input 类型**：`text`、`password`、`email`、`number`、`date`、`radio`、`checkbox`、`file`、`range`、`submit`、`hidden`。

③ **常用属性**：

- `name`：提交时字段名
- `value`：默认值
- `placeholder`：占位提示
- `required`：必填
- `readOnly` / `disabled`：只读 / 禁用
- `maxlength` / `pattern`：长度 / 正则校验
- `autocomplete`：自动填充

④ **配合**：`<form>` 包裹，使用 `<label for>` 关联提升可用性，`submit` 事件可 `preventDefault` 阻止默认提交再走 AJAX。

⑤ **追问**：如何做前端表单验证？受控组件什么是（React）？表单的性能优化怎么做？

## 第三阶段：CSS 基础（11-18）

### Q11: CSS 选择器有哪些种类？优先级（specificity）如何计算？

① **一句话结论**：选择器分为类型/类/ID/属性/伪类/伪元素/通配符等；优先级按"权重 + 就近"决定。

② **种类**：

- 类型选择器 `div`、类 ` .class`、ID `#id`、通配 `*`
- 属性 `[type=text]`、伪类 `:hover`、伪元素 `::before`
- 后代 ` `、子 `>`、相邻 `+`、通用兄弟 `~`

③ **优先级计算（权重）**：

- ID：`(1,0,0)`
- 类 / 属性 / 伪类：`(0,1,0)`
- 类型 / 伪元素：`(0,0,1)`
- 通配符 / 继承：`(0,0,0)`
- `!important` > 内联样式 > ID > 类 > 类型

④ **规则**：同级时后写的覆盖先写的；`!important` 会打破正常层叠，慎用。

⑤ **追问**：`:not()` 怎么参与优先级计算？如何覆盖第三方组件样式？

---

### Q12: 盒模型是什么？标准盒模型和怪异盒模型（IE 盒模型）有什么区别？

① **一句话结论**：盒模型由 content + padding + border + margin 组成；区别在于 `width` 是否包含 padding/border。

② **两种模型**：

- **标准盒模型（`box-sizing: content-box`）**：`width` 只算内容区，`元素总宽 = width + padding + border`。
- **怪异盒模型（`box-sizing: border-box`）**：`width` 包含 padding 和 border，`总宽 = width`（容易算布局）。

③ **对比示例**：

```css
/* 标准：宽 220 = 200 + 10*2 的 padding */
.box { width: 200px; padding: 10px; box-sizing: content-box; }
/* 怪异：宽 200 = 内容自动缩 180 + padding */
.box { width: 200px; padding: 10px; box-sizing: border-box; }
```

④ **实践**：业界普遍 `* { box-sizing: border-box }` 简化布局计算。

⑤ **追问**：margin 塌陷（外边距合并）是什么？如何解决？

---

### Q13: `position` 定位有哪些取值？各自有什么特点？

① **一句话结论**：静态、相对、绝对、固定、粘性五种，区别在于参照物与是否脱离文档流。

② **各取值**：

| 值 | 参照 | 是否脱离文档流 |
|----|------|----------------|
| `static` | 默认，正常文档流 | 否 |
| `relative` | 自身原位置 | 否（占用原空间） |
| `absolute` | 最近的已定位祖先 | 是 |
| `fixed` | 视口（viewport） | 是 |
| `sticky` | 滚动容器 | 特殊（滚动触发粘住） |

③ **场景**：`absolute` 做元素覆盖、`fixed` 做吸顶导航、`relative` 给子用绝对定位当参照、`sticky` 做吸顶的表头。

④ **注意**：`absolute`/`fixed` 脱离文档流后，父容器需设置 position 才能包含，否则一直向上找 `body`/视口。

⑤ **追问**：`z-index` 生效前提？脱离文档流的元素如何影响布局？

### Q14: Flex 布局的核心概念和常用属性有哪些？

① **一句话结论**：Flex 是一维布局模型，通过"主轴 + 交叉轴"控制容器内子项的排列、对齐与伸缩。

② **容器（parent）属性**：

- `display: flex` 启用
- `flex-direction`：主轴方向（`row`/`column`/`row-reverse`）
- `justify-content`：主轴对齐（`flex-start`/`center`/`space-between`）
- `align-items`：交叉轴对齐（`center`/`stretch`/`flex-start`）
- `flex-wrap`：是否换行
- `gap`：子项间距

③ **子项（child）属性**：

- `flex: flex-grow flex-shrink flex-basis`（如 `flex:1`）
- `align-self`：单独覆盖交叉轴对齐

④ **核心优势**：一行代码实现水平垂直居中：`display:flex; justify-content:center; align-items:center`。

⑤ **追问**：`flex:1` 实际默认值？flex 与 grid 各自适用场景？

---

### Q15: Grid 布局与 Flex 布局的区别是什么？

① **一句话结论**：Grid 是二维布局（行列同时），Flex 是一维布局（主轴 + 交叉轴）。

② **对比**：

- **Flex**：适合"某一行/某一列"内的分布与对齐，子项沿主轴排列。
- **Grid**：适合"整个页面或独立区域"的行列网格，可精准控制单元格。

③ **实用 Grid 属性**：

```css
.container {
  display: grid;
  grid-template-columns: repeat(3, 1fr); /* 三列等分 */
  grid-template-rows: 100px 1fr;
  gap: 10px;
}
```

④ **选型**：页面整体用 Grid，导航/按钮/弹性内容用 Flex；两者可嵌套混用。

⑤ **追问**：`grid-template-areas` 怎么用？响应式栅格如何做？

---

### Q16: 分别有哪些方案可以实现元素水平垂直居中？

① **一句话结论**：居中方案取决于父元素是否为 flex/grid、元素是否定宽高，常见有 Flex、Grid、绝对定位 + margin、`transform`。

② **常用方案**：

```css
/* 方案1：Flex（最推荐） */
.parent { display: flex; justify-content: center; align-items: center; }

/* 方案2：Grid */
.parent { display: grid; place-items: center; }

/* 方案3：绝对定位 + 负 margin（需已知宽高） */
.child { position: absolute; left: 50%; top: 50%; margin: -50px 0 0 -50px; }

/* 方案4：绝对定位 + transform（不需已知宽高） */
.child { position: absolute; left: 50%; top: 50%; transform: translate(-50%, -50%); }
```

③ **选择依据**：渐次优先 Flex/Grid；对不支持 flex 的老环境用 transform 方案。

⑤ **追问**：文字垂直居中怎么处理？top:50% 参照的是什么？

---

### Q17: CSS 的层叠（Cascade）与继承（Inheritance）各是什么？

① **一句话结论**：层叠决定"同一个元素的多个规则谁生效"，继承决定"没有设置的属性是否沿用父级"。

② **层叠（Cascade）**：多个规则命中同一元素时，按"权重（!important > 内联 > 选择器优先级） + 源码顺序"决定最终值。

③ **继承（Inheritance）**：默认可继承的属性（`color、font-*`、`text-align`），子元素未设置时会沿用父值；不可继承的属性（`margin、padding、border、width`）默认不继承。

④ **控制继承**：`inherit`（强制继承）、`initial`（取默认值）、`unset`（有继承则继承，否则初始值）。

⑤ **追问**：`currentColor` 是什么？如何统一用 CSS 变量管理主题色？

---

### Q18: 常见 CSS 单位有哪些？`px`、`em`、`rem`、`vw`、`vh` 有什么区别？

① **一句话结论**：核心是区分绝对单位（px）与相对单位（em/rem/vw/vh），相对单位让布局更灵活。

② **对比**：

| 单位 | 参照 | 特点 |
|------|------|------|
| `px` | 像素 | 绝对，固定大小 |
| `em` | 父元素 font-size | 嵌套会累积放大，用于局部缩放 |
| `rem` | 根元素（html）font-size | 不累积，全局统一缩放，常用做响应式字号 |
| `vw`/`vh` | 视口宽/高（100vw=视口宽） | 适合全屏适配 |
| `%` | 父元素 | 宽高百分比 |

③ **实践**：

```css
html { font-size: 16px; }
.title { font-size: 2rem; }   /* 32px */
.card  { width: 90vw; }       /* 视口宽 90% */
```

④ **注意**：`em` 关注点分离在嵌套元素中容易算错大小；响应式常用 `rem` + 媒体查询或 `vw`。

⑤ **追问**：`rem` 适配方案 `<script>` 动态算根字号怎么写的？`dpr` 是什么？

## 第四阶段：JavaScript 基础（19-30）

### Q19: JS 有哪些数据类型？如何区分原始类型和引用类型？

① **一句话结论**：JS 有 7 种原始类型 + 引用类型（Object），区分核心在于"值存在栈中还是堆中"。

② **原始类型（Primitive，存值、不可变）**：`string、number、boolean、null、undefined、symbol、bigint`。

③ **引用类型（Reference，存引用）**：`Object`（包含 `Array`、`Function`、`Date`、`RegExp`），变量存的是堆内存地址。

④ **判断方式**：

```js
typeof null === 'object' // 历史 bug；判断是否为 null 用 null === v
typeof [1,2] === 'object' // 数组
```

⑤ **场景/边界**：

- 原始类型复制传值，互不影响；引用类型复制传址，指向同一对象。
- 函数传参引型会被外部修改（浅拷贝问题）。

⑥ **追问**：`NaN` 是什么类型？如何判断数组（Array.isArray 与 typeof）？

---

### Q20: `null` 和 `undefined` 有什么区别？

① **一句话结论**：`undefined` 表示"还没赋值（未定义）"，`null` 表示"有定义但值为空（空值）"。

② **区别**：

- `undefined`：声明了变量但未赋值、函数无返回值、对象属性不存在。
- `null`：主动把一个引用置空，如 `let a = null`。

③ **坑**：`typeof null === 'object'`，而 `typeof undefined === 'undefined'`；`null == undefined` 为 true，`===` 为 false。

④ **实践**：约定"用 null 表示空引用，用 undefined 表示确实未定义"更清晰。

⑤ **追问**：用 `==` 判断空值时要注意什么？

---

### Q21: `==` 和 `===` 有什么区别？如何正确比较？

① **一句话结论**：`===` 严格比较（类型 + 值），`==` 宽松比较（会做类型转换）。

② **原理**：

- `===`：先判断类型，不同则 false；`null === undefined` 为 false。
- `==`：类型不同时先隐式转换再比较，如 `'1' == 1` 为 true。

③ **常见陷阱**：

```js
0 == ''      // true（都转成 0）
null == undefined // true
NaN === NaN  // false
```

④ **建议**：默认都用 `===`；仅明确需要转换时用 `==`（如 `a == null` 同时判断 null/undefined）。

⑤ **追问**：`Object.is` 与 `===` 的区别（处理 +0/-0、NaN）？

### Q22: `typeof` 和 `instanceof` 的区别和使用场景？

① **一句话结论**：`typeof` 判断原始类型的"类型标签"，`instanceof` 判断引用类型是否属于某构造函数。

② **对比**：

| 工具 | 用途 | 局限 |
|------|------|------|
| `typeof` | 返回类型字符串 | 对 null/数组/date 不准 |
| `instanceof` | 判断原型链上是否有该构造函数 | 跨 iframe/多 window 失效 |

③ **补充判断**：

```js
Array.isArray(arr)   // 数组
Object.prototype.toString.call(v) // 最精确：[object Array] / [object Date]
```

④ **选择**：基本类型用 `typeof`；对象类型用 `instanceof` 或 `toString`。

⑤ **追问**：`Object.prototype.toString` 为什么能精确识别？Symbol.toStringTag？

### Q23: 什么是变量提升（hoisting）？`var` 存在变量提升吗？

① **一句话结论**：变量/函数声明会被提升到作用域顶部，`var` 会提升但只提升声明不提升赋值。

② **原理**：编译阶段，JS 引擎先把 `var` 声明和函数声明"预读取"到当前作用域顶部，此时值为 `undefined`。

```js
console.log(a); // undefined（已提升但未赋值）
var a = 10;
```

③ **区别**：`let`/`const` 也有"声明阶段提升"但存在**暂时性死区（TDZ）**，在声明前访问会报 ReferenceError，因此常被理解成"不提升"。

④ **函数 vs 变量**：函数声明整体提升可提前调用；`var` 只提升声明。

⑤ **追问**：`let` 为什么有暂时性死区？块级作用域与 this 的关系？

### Q24: 什么是闭包？它有什么优缺点和应用场景？

① **一句话结论**：闭包是"函数与其词法作用域的组合"，使内部函数能访问外部函数作用域的变量，并在外部函数返回后仍保持。

② **示例**：

```js
function counter() {
  let n = 0;
  return function () {
    n++;
    return n;
  };
}
const c = counter();
console.log(c()); // 1
console.log(c()); // 2  // 保留了 n
```

③ **用途**：封装私有变量（模块化）、函数柯里化、防抖节流、事件回调保留状态、React 中缓存。

④ **缺点**：滥用会占用内存不放导致泄漏，需避免循环引用。

⑤ **追问**：闭包为什么能"记住"外部变量（作用域链）？如何释放闭包？

### Q25: `var`、`let`、`const` 三者的区别？

| 作用域 | 函数作用域 | 块级作用域 | 块级作用域 |
| 变量提升 | 提升（值 undefined） | 有但 TDZ | 有但 TDZ |

### Q28: 什么是事件冒泡和事件捕获？如何阻止冒泡与默认行为？

④ **应用**：事件委托（event delegation）利用冒泡，在父元素统一监听子项点击。

### Q34: 什么是跨域？JSONP 的原理是什么？

① **一句话结论**：跨域是浏览器的同源策略限制——协议/域名/端口任一不同即为跨域；JSONP 利用 `<script>` 不受同源限制来实现跨域加载。

② **同源条件**：协议 + 域名 + 端口三者一致。

③ **JSONP 原理**：

1. 前端创建 `<script src="http://api.com/data?callback=fn">`。
2. 后端返回 `fn({...数据})` 这样的 JS 代码。
3. 全局定义的 `fn` 被调用，拿到数据。

```js
window.fn = (data) => console.log(data);
const s = document.createElement('script');
s.src = 'http://api.com/data?callback=fn';
document.head.appendChild(s);
```

④ **局限**：只支持 GET；现代主流用 CORS（Access-Control-Allow-Origin）。

### Q36: 简述 JavaScript 事件循环入门知识：什么是宏任务、什么是微任务？

① **一句话结论**：JS 单线程，靠事件循环调度任务；宏任务一轮轮排队执行，每个宏任务后清空微任务队列。

② **宏任务（Task）**：`setTimeout`、`setInterval`、I/O、`requestAnimationFrame`（浏览器）。
③ **微任务（Microtask）**：`Promise.then`、`async/await` 后续、`queueMicrotask`。

④ **执行顺序**：先执行当前同步代码 → 清空微任务队列 → 取一个宏任务执行 → 再清空微任务 → 循环。

```js
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
// 输出：1 3 2（微任务 3 先于宏任务 2）
```

⑤ **意义**：微任务让"本轮同步执行完后立马更新 UI"，宏任务把耗时操作排到后面。

⑥ **追问**：`async/await` 与 event loop 的关系？定时器 0 真的立即执行吗？

### Q37: 为什么说 JavaScript 是单线程的？异步编程解决了什么问题？

① **一句话结论**：JS 主线程单线程是为了避免多线程同时操作 DOM 的竞态；异步让"无法立即完成"的任务不阻塞后序代码。

② **原因**：如果多线程同时改同一个 DOM 节点，会出现不一致。浏览器用"主线程 + 事件循环"模型。

③ **异步解决的问题**：

- 网络请求、定时器、文件读取等耗时操作不阻塞 UI。
- 用户交互不卡顿。

④ **实现**：底层的耗时操作（如网络 IO）由浏览器/Node 交给系统或线程池处理，完成后把回调推回事件循环队列。

### Q38: TypeScript 是什么？它解决了 JavaScript 的哪些痛点？

### Q39: `interface` 和 `type` 有什么区别？

① **一句话结论**：两者都能描述对象类型，`interface` 可声明合并、偏向描述"形状"，`type` 更强大可组合任意类型。

② **区别**：

- `interface`：支持 `extends`，可通过同名声明合并；通常描述对象/类是"形状"。
- `type`：支持交叉（`&`）与联合（`|`），可对原始类型、元组、函数生成类型别名。
- `interface` 可被类 `implements`。

```ts
interface Animal { name: string }
type ID = string | number;          // type 支持联合
interface Dog extends Animal { bark(): void }
type Combine = Animal & { age: number }; // type 用交叉
```

③ **建议**：描述对象结构用 `interface`，需要联合/元组/复杂组合用 `type`。

### Q40: 什么是泛型？举一个简单的使用例子？

① **一句话结论**：泛型是一种"类型参数化"，让函数/类/接口在使用时才确定具体类型，提升复用性与类型安全。

② **原理**：定义时不写死类型，用 `T` 等占位符，调用时指定或由 TS 推断。

```ts
function identity<T>(value: T): T {

}
identity<number>(123); // 返回 number
identity('abc');       // 自动推断 string

function getFirst<T>(arr: T[]): T | undefined {
  return arr[0];
}
```

③ **应用**：集合容器、请求封装（`Promise<T>`）、React 泛型组件、从接口返回类型推断。

### Q41: `any`、`unknown`、`void`、`never` 之间有什么区别？

① **一句话结论**：`any` 关闭类型检查，`unknown` 是"未知但安全"，`void` 表示没有返回值，`never` 表示函数永不会返回。

② **对比**：

| 类型 | 含义 | 使用 |
|------|------|------|
| `any` | 任意类型，跳过检查 | 过渡阶段，避免滥用 |
| `unknown` | 类型未知，需收窄才能用 | 处理任意输入的安全选择 |
| `void` | 无返回值 | 事件回调/无返回函数 |
| `never` | 永远不会终止（抛错/死循环）或不可达分支 | 穷尽检查 |

```ts
let u: unknown = 'x';
// u.toUpperCase() // 报错：需先收窄
if (typeof u === 'string') u.toUpperCase();

function err(): never { throw new Error('boom'); }
```

③ **建议**：尽量避免 `any`，外部输入用 `unknown`，穷尽场景用 `never`。

⑤ **追问**：`unknown` 和 `any` 各自的收窄时机？`never` 在穷尽枚举中的作用？

### Q42: 什么是类型断言？`as` 的常见用法有哪些？

① **一句话结论**：类型断言告诉 TS"这里就是某某类型"，用于在开发者比 TS 更清楚类型时覆盖推断。

② **用法**：

```ts
const input = document.getElementById('name') as HTMLInputElement;
input.value = 'hello';

```

③ **注意安全**：断言是"编译期承诺"，类型写错运行期照样报错；能用收窄（typeof / instanceof）就不用生硬断言，`unknown` 常用双断言或先转 `unknown`。

④ **边界】助**：`as` 不能直接跨不相容类型，可先 `as unknown as X`。

### Q43: Git 有哪些常用的命令？提交代码的基本流程是怎样的？

① **一句话结论**：Git 是分布式版本控制，核心命令围绕"工作区-暂存区-本地仓库-远程"流转。

② **基本流程**：

```bash
git clone <url>          # 拉取远程
git checkout -b feature  # 新建并切换分支
git add .                # 加到暂存区
git commit -m "feat: xxx"# 提交本地
git pull                 # 同步远程（先拉再推）
git push origin feature  # 推到远程
git merge / rebase       # 合入目标分支
```

③ **常用查看/回退**：`git log`、`git status`、`git diff`、`git stash`、`git reset --soft/hard`。

④ **追问**：merge 和 rebase 区别？如何处理冲突？

### Q44: npm 是什么？`dependencies` 和 `devDependencies` 有什么区别？

① **一句话结论**：npm 是 Node.js 的包管理工具；两者都是依赖，区别在生产/开发环境的用途。

② **区别**：

- `dependencies`：生产运行所需，`npm install --save`（默认），构建后线上也要。
- `devDependencies`：开发期工具（eslint、webpack、jest、TypeScript），`npm install -D`，生产不需要。

③ **原因**：区分后节省线上体积，`npm ci --omit=dev` 跳过开发依赖。

④ **补充命令**：`npm install`、`npm ci`（锁文件精确安装）、`npx`（执行一次性二进制）。

⑤ **追问**：`^` 和 `~` 版本号范围含义？`package-lock.json` 作用？

### Q45: 什么是代码规范？ESLint 和 Prettier 的作用分别是什么？

① **一句话结论**：代码规范是统一写法与风格的约定；ESLint 管"代码质量规则"，Prettier 管"代码格式化"。

② **对比**：

- **ESLint**：静态分析，发现未使用变量、`==` 误用、未捕获错误等质量/规范性错误；可自动修复部分。
- **Prettier**：代码格式化（缩进、引号、换行、逗号），统一风格，不关心逻辑对错。

③ **配合**：CI 中跑 `eslint`，保存时 `Prettier` 自动格式化；配合 husky 的 pre-commit 钩子做提交前检查。
