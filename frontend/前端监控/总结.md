# 模块总结 · 监控与稳定性

本模块一篇讲透「如何从零设计一套监控 SDK」：先结构化列出 SDK 要有哪些能力（八项采集 + 内核底座），再按「内核：一条事件怎么走完」讲清公共链路，然后逐项拆八种采集能力用什么浏览器 API、怎么实现、有哪些坑，最后是可复现的验证链路与已知取舍。架构采用**内核 + 插件**：插件只能 `emit`，采样、节流、脱敏、批量全部收在内核，任何插件都绕不过治理；性能终值靠 `finalize` 在页面隐藏时定稿，保证「先入队再发送」的时序。每条设计判断都摘配套源码落地。

## 大纲

- **1. 监控 SDK 设计与实现**
  - 1.1 能力设计：三组能力清单（采集 / 内核 / 非目标）、三层架构、事件结构、插件契约、装配顺序
  - 1.2 内核：一条事件怎么走完——上下文快照、归一指纹、采样节流、队列离线、五个触发口、上报通道
  - 1.3 采集八项逐项拆解：性能 / JS 异常 / 资源 / 请求 / 路由 / 行为 / 白屏 / 自定义
  - 1.4 验证与取舍：能力 ↔ 操作对照、实测读数、已知取舍

## 1. 监控 SDK 设计与实现

### 1.1 能力设计

先划三条边界：不采录屏（体积/隐私不划算）、不做 sourcemap 还原（属于构建与符号表服务）、不做告警（属于下游平台）。SDK 只负责把「能解释问题的数据」以可控的成本发出去。

架构是三层单向依赖：插件层（采集）→ 内核（治理）→ 通道（发送）。**插件只能拿到 `emit`**——碰不到队列和通道，采样、节流、脱敏就没人能绕过。插件契约只有 `setup`（返回清理函数）与可选的 `finalize`（隐藏前定稿）两个口，`PluginContext` 只给 `emit` / `setPage` / `onRouteChange` / `log`。

事件外壳只有一种：`type` 收敛成八个枚举值，`data` 装各自的能力数据，`subtype` 细分排查路径。队列、通道、接收端只处理一种结构。装配顺序写在 `config.js`，顺序即依赖顺序：`router` 最先（补丁要赶在框架路由之前），`request` 最后。

### 1.2 内核

流水线固定：归一 → 记录 recent → 采样 → 指纹节流 → `beforeSend` → 入队 → notify。采样在节流之前，`stats.sampled` / `stats.throttled` 才解释得清。

- **上下文**：session（`sessionStorage`，30 分钟滑动过期）、匿名 uuid（`setUser` 覆盖）、page / device 启动算一次。**每条事件拷贝快照而不是引用**——队列是异步的，引用会被后续路由跳转改写。
- **指纹** = `type|subtype|message|栈顶三帧（去行号列号）`，同时服务节流去重与服务端聚合。`message` 截 500、`stack` 截 4000。
- **队列**：定长 200 丢最旧；发送失败回灌 + IndexedDB 落盘（降级 localStorage，上限 100 条），下次启动补发。
- **调度**：五个触发口（满量 / 定时 / 空闲 / hidden / 手动）汇进同一条 drain。**hidden 铁律：先 finalize 把性能终值入队，再 drain**；失败回灌再落盘；flushing 标志防并发。
- **通道**：一个请求一批事件（JSON 数组）。`sendBeacon` 优先：Blob 用 `text/plain;charset=UTF-8` 避免 CORS 预检、主动判 60KB 上限；不支持或超限时 `fetch(keepalive: true)`，失败按 200ms × 2ⁿ 退避重试，最终失败返回 false 交还调度器落盘。
- **emit 全程 try/catch**——SDK 自己绝不能抛异常。`beforeSend` 是最后的治理收口：脱敏、改写、丢弃都在这里。`stats` 八个计数对应流水线各出口（sent / failed / dropped / sampled / throttled / flushCount / lastFlushReason / restored），是 SDK 的自观测。

### 1.3 采集八项

| 能力 | 核心 API | 关键口径与坑 |
| --- | --- | --- |
| 性能 | `PerformanceObserver`（paint / LCP / layout-shift / longtask / event）+ navigation 条目 | `buffered: true` 否则 FCP 恒为 0；LCP 取最后一条；CLS 排除 `hadRecentInput`；TBT 只算超 50ms 部分；终值在 `finalize` 出 |
| JS 异常 | `window error`（捕获阶段）+ `unhandledrejection` + Vue `errorHandler` | 资源错误不冒泡必须捕获；`Script error.` 需 crossorigin；reason 未必是 Error；保留原 handler |
| 资源 | `error` 捕获 + `resource` timing | 游离元素不经过 window；失败看 error、耗时看 timing；状态提升到插件工厂闭包供 `finalize` 读 |
| 请求 | 包裹 `fetch` / XHR | 只报 `status>=400`、`status=0`、慢请求；catch 必须 rethrow；**必须屏蔽 SDK 自己的上报请求** |
| 路由 | `pushState/replaceState` 补丁 + `popstate` + `hashchange` | 只监听 popstate 抓不到 `router.push`；`duration` = 上一页停留时长；首屏补一条 `enter` |
| 行为 | 点击捕获委托 + `IntersectionObserver` + `MutationObserver` + 面包屑环形队列 | 观察后注销即去重；init 时框架未 mount，首扫必扑空 |
| 白屏 | `document.elementsFromPoint` 米字 33 点 | 三层判定：排除不可见/骨架屏 → 直接文本/替换元素 → 背景/边框/阴影绘制信号；`data-blank-safe` 豁免；2s 二次复检；附 recent 上下文 |
| 自定义 | `report()` 单入口 + `captureError()` | 事件名三段式；参数 4KB 截断；`source=manual` 用于算兜底率 |

### 1.4 验证

电商 demo（monishop）+ 实验室总控台 + 独立空白页：每个按钮对应一项能力，四处证据（Console 日志 / Network 批次 / `events.jsonl` / `GET /api/stats`）。实测：空白页 33/33 点空白、`stage=recheck`；商城首页→详情，路由 `enter`+`push` 与 `monishop.HOME.PV`、`monishop.PRODUCT.PV` 齐全；切标签后 perf 终值 `tbt=100 longTaskCount=2`、导航 `ttfb=70 domReady=429`。

已知取舍偏置明确：白屏偏漏报（白底空卡片不算白屏，交给错误与接口监控兜住）、INP 简化口径、资源失败只认 error 事件、采样率靠配置下发。
