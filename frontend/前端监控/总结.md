# 模块总结 · 监控与稳定性

本模块一篇讲透自建监控：**初始化、异常、性能、声明上报、上报** 五个能力文件——能力边界即模块边界，依赖方向单向（异常、性能、声明上报只产出事件交给上报，装配与收口集中在初始化）；手动上报只有 `report()` 一个入口，业务区分类型的二次封装在接入层完成。每条原理线都摘配套源码落地，最后是覆盖全部特性的演示工程。

## 1. 监控SDK

### 1.1 SDK 架构

模块划分依据是**能力边界**：异常怎么抓（exceptions）、性能怎么测（performance）、声明式埋点怎么挂（declarative）、事件怎么可靠地发（report），装配三者的过程就是初始化（init）。依赖方向单向：采集三模块只产出事件交给上报，模块间协作靠 init 注入回调（如请求拦截的耗时经 `onRequestTime` 交给性能模块）——增删任一模块只动装配行。

### 1.2 异常捕获

| 路 | 关键点 |
| ---- | ---- |
| error（捕获阶段） | 资源错误不冒泡；分流判据 `target.tagName`；**游离元素不经过 window** |
| unhandledrejection | reason 未必是 Error；stack 是唯一位置线索 |
| fetch 包裹 | 接口错误判据 `status>=400`（`!res.ok` 会把 304 误判）；**catch 只交耗时后 rethrow**（unhandledrejection 会兜底，再抓就是双报） |
| XHR 包裹 | `status=0` 的网络错误只能在这抓（与 fetch 互补不重复） |
| Vue errorHandler | 归一 + 保留原 handler；框架口是补充不是替代 |

每一路都包 try/catch：SDK 自己不能抛错，否则触发再上报死循环。

### 1.3 性能指标

`buffered: true` 补收（否则 FCP 恒为 0）；全指标覆盖 FP/FCP/LCP/CLS（双口径，`hadRecentInput` 豁免）/INP（简化版）/TBT（超出 50ms 门槛部分）/长任务数/导航明细（TTFB/DNS/TCP/DOM Ready/load）/慢请求 Top5。LCP 取最后一条候选、**hidden 才是终值**，finalize 只算一次，收口顺序铁律：先 finalize 入队再发送。

### 1.4 手动上报与声明上报

手动上报单入口 `report(event)`：event 带 `error`（Error 实例）时 SDK 归一拆出 message/stack；公参 init 静态传入（`commonParams`）每条事件自动附带。业务二次封装在接入层（形态同 cash-web 的 `hooks/useReport`）：`trackPageView`（PV 手动报，路由 afterEach 调用）/ `trackClick` / `errorReport`，事件名 = **平台.页面.行为** 三段式（数字段过滤防事件名爆炸，维度进 params 不进事件名）。声明式 `data-track`（捕获阶段委托）/ `data-expose`（IntersectionObserver 观察后注销），**init 时 Vue 未 mount 首扫必扑空，MutationObserver 补挂**。

### 1.5 上报

公共字段补全（先展开事件再补全，事件自带 tags/extra 不被覆盖）→ 采样（错误/业务与性能双采样率）→ 节流（归并键 = 类型+消息+位置，相同错误 1 秒一条，`stats.throttled` 观测丢弃量）→ beforeSend 治理收口 → **批量**（满量/超时触发，溢出丢最旧）→ sendBeacon 优先（判断支持即调用，text/plain 跨域不预检）→ keepalive 兜底 → 重试上限 → **hidden 统一收口**（先性能终值入队再发送）。

### 1.6 Demo 全特性覆盖

电商演示页（monishop）+ 实验室总控台：每个按钮的标签就是监控特性；采样演示运行时改 `cfg.sampleRate`（30% → 10 触发 1~3 入队）、节流演示（10 次同错 → 丢 9 存 1）。实测读数：漏斗 6→1→1→1、`fcp=340 cls=0.077 tbt=261`、慢请求 817ms 榜首；SPA 的 LCP 会被路由切换拉长——纯 JS 点击不算用户输入，是「LCP 越晚越准」的活教材。
