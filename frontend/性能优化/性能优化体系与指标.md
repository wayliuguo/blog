# 性能优化体系与指标

## 一、指标体系：核心指标是目标，辅助指标是刻度

三个核心指标（Core Web Vitals）是**要守的目标**，其余指标都不是目标，而是用来定位的刻度——核心指标告诉你去哪，辅助指标告诉你在哪，二者不可混用。

| 核心指标 | 中文含义 | 目标（p75） | 用户的话 |
| --- | --- | --- | --- |
| LCP | Largest Contentful Paint 最大内容绘制 | ≤ 2.5s 良好；2.5~4s 待改进；> 4s 差 | 多久能看到内容 |
| INP | Interaction to Next Paint 交互到下一次绘制 | ≤ 200ms 良好；200~500ms 待改进；> 500ms 差 | 点了多久有反应 |
| CLS | Cumulative Layout Shift 累积布局偏移 | ≤ 0.1 良好；0.1~0.25 待改进；> 0.25 差 | 页面会不会自己乱跳 |

- **LCP【加载体验】**：视口内**最大的可见元素**完成渲染的时间（大图、大标题文本块）。只记录页面**初始加载**，滚动后出现的元素不算；多次渲染会更新，取最后一次。常见元凶：大图未优化、服务端响应慢、阻塞 JS/CSS、字体加载。
- **INP【交互体验，替换旧 FID】**：用户任意交互（点击、输入、触摸）到浏览器下一次绘制完成的时间，取页面**所有交互里最差的那个值**。核心含义是衡量**点击卡顿**，主线程长任务是 INP 杀手。
- **CLS【稳定性体验】**：无用户主动操作下，页面元素意外位移的总分；每次位移 = 影响比例 × 位移距离比例。常见元凶：图片没宽高、动态加载广告/弹窗、字体 FOIT、异步插入 DOM。

一句话记忆：**LCP 看加载快不快，INP 看点击卡不卡，CLS 看页面跳不跳**。三个谁也替代不了谁——同一张详情页，主图不写尺寸时 CLS 差而 LCP 不动，**LCP 好不代表体验好**。

### 1. 旧指标：从核心降级为定位刻度

| 指标 | 含义 | 现状 |
| --- | --- | --- |
| FP | First Paint 首次绘制 | 浏览器第一次向屏幕绘制像素，白屏结束的起点；不区分内容是否有效 |
| FCP | First Contentful Paint 首次内容绘制 | 第一次绘制文本 / 图片 / SVG 等 DOM 内容，用户开始看到内容 |
| FMP | First Meaningful Paint 首次有意义绘制 | 标准已废弃，不推荐作为线上指标 |
| TTI | Time To Interactive 可交互时间 | 页面可稳定响应点击输入；长任务阻塞会拉高它，**Core Web Vitals 已移除** |
| TBT | Total Blocking Time 总阻塞时间 | FCP 到 TTI 之间所有长任务超过 50ms 部分的总和，衡量主线程卡顿；**INP 的实验室代理** |

### 2. 补充指标：把核心指标的「差」定位到时间轴上的哪一段

```
请求发出      首字节     首次绘制   首次内容    最大内容    可交互     一次交互
  │            │           │          │          │          │          │
  ◄──TTFB──►   FP         FCP        LCP        TTI        INP
```

- **TTFB**：请求发出到收到服务端第一个字节。TTFB 高 = DNS / CDN 路由 / 服务端 / 数据库慢——服务端处理那段**前端优化救不了**；它是所有加载指标的上游。
- **Long Task 长任务**：主线程任务执行超过 50ms。主线程负责 JS 解析执行、DOM、样式计算、Layout、Paint，长任务直接拉高 INP、TBT、TTI。
- **Layout Shift 单次布局偏移**：CLS 的组成单元。
- **资源指标**：JS 总大小、图片总大小、请求数量、缓存命中率。

## 二、渲染流水线：优化的本质是挑开销最低的那条路

```
请求资源 → 解析HTML生成DOM树 → 解析CSS生成CSSOM树 → 合并生成Render树
        → Layout(布局/重排) → Paint(绘制) → Composite(合成)
```

| 环节 | 触发条件 | 开销 |
| --- | --- | --- |
| 重排（Reflow / Layout） | 宽高、margin、top 等几何属性变化；DOM 增删；读取 offset 系列属性 | 最大：重新计算整棵布局树 |
| 重绘（Repaint） | 颜色、背景色、visibility 等不改变布局的样式 | 中等：跳过布局，重新绘制 |
| 合成（Composite） | transform、opacity | 最低：跳过布局与绘制，多个图层合并上屏，可走 GPU |

黄金原则：**优先让动画与视觉变化走合成层，避免频繁 Layout / Paint**。

### 主线程模型：前端卡顿的核心根源

- 主线程是**单线程**，负责 JS 解析执行、DOM 操作、样式计算、Layout、Paint——JS 执行会抢占主线程，期间既无法响应输入也无法渲染，这是「点了没反应」和「掉帧」的共同根源。
- 与之并行的还有合成线程、GPU 线程、网络线程；把它们利用起来（合成动画、Web Worker、预加载）就是绕开主线程瓶颈的手段。

分层、合成器与关键渲染路径的完整机制见浏览器原理模块《浏览器渲染原理》篇，本篇只保留与优化决策直接相关的最小集。

## 三、口径：先判断数可不可信，再决定怎么改

- **实验室管定位、现场管发现**：Lighthouse / DevTools 是实验室数据（受控环境、可复现），RUM 是真实用户数据。**线上以 RUM 为准**；分工是现场看分布发现问题 → 实验室复现定位根因 → 改完回现场验证。
- **统一看 p75 / p95 分位数**：性能是长尾分布，平均值被极少数样本带偏；P95 代表最差那批用户的体验，是优化重点。
- **评级是门槛不是排名**：LCP 8000ms 优化到 3000ms 评级仍是「待改进」，但体感已是两个世界；**一次只盯一个指标**，几个一起抠会互相干扰。
- **CLS 双口径**：`cls`（规范口径，剔掉交互后 500ms 内的「预期位移」，现场报表读）+ `clsRaw`（所有位移之和，对照实验读）。采集端两个值必须分开上报——手动对照时浏览器对「无输入位移」的判定与真实用户不一致。

## 四、采集与工具：读数从哪来、用哪个面板

### 1. 浏览器原生 API（线上采集首选，不需要埋点 hack）

- **PerformanceObserver**：订阅 LCP / INP / CLS 等指标条目。注意 LCP、INP 不是在页面 load 瞬间就能定值，会动态更新，**页面卸载时取最终值上报**。
- **Long Task API**：`PerformanceObserver` 监听 `longtask` 条目，捕获超 50ms 的长任务。
- **LayoutShift 条目**：捕获每次布局偏移，`hadRecentInput` 区分是否「预期位移」。
- **Performance API**：`performance.getEntriesByType('resource')` 拿每个资源的 `transferSize`（为 0 即命中缓存）。

> 示意片段（无配套脚本）

```js
import { onLCP, onINP, onCLS } from 'web-vitals'

function sendToReport(metric) {
    // sendBeacon：页面卸载也能发出、不阻塞主线程
    navigator.sendBeacon('/api/report', JSON.stringify(metric))
}
onLCP(sendToReport)
onINP(sendToReport)
onCLS(sendToReport)
```

### 2. 工具选型：标准只有一条——它替你做了什么决定

用序是先粗后细：先用粗粒度定位阶段（瀑布图 / TBT），再用细粒度定位函数（火焰图）——反过来做，会在火焰图里翻十分钟，最后发现是首屏图 3MB。

| 工具 | 替你做掉的事 | 代价 | 适合回答 |
| --- | --- | --- | --- |
| Network / 瀑布图 | 请求按时间排好、标优先级与阻塞 | 只看搬运、不看计算 | 时间花在哪个资源等待上 |
| Performance | 主线程采样、生成火焰图 | 录制有开销、体量大 | 那 500ms 在跑什么函数 |
| Coverage | 每文件已用 / 总字节 | 只给静态结论 | 有多少代码下了没用 |
| Memory | 堆快照 / 对比 / 分配时间线 | 快照暂停页面、体量大 | 越用越卡、什么没被回收 |
| Lighthouse | 全套审计打分 | 模拟环境、只代表这一次 | 整体水位、短板扫描 |

Lighthouse 最容易用错：分数是**固定权重汇总**、相对且只看这一次，正确用法是**当趋势与短板扫描，别当验收卡口**；要卡口就把 LCP / INP / CLS 的真实读数写进 CI。
