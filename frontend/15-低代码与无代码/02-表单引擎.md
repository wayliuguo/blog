# 表单引擎
> 级别：中级→高级

> 本章按四层推进：入门（表单驱动原理、Schema 三类型字段与校验）→ 进阶（控件体系、校验层、联动与依赖）→ 实战（JSON Schema 校验、动态表单、性能可扩展落地）→ 最小实现（到 `code/frontend/15-lowcode` 运行 `schema-driven-render.html`，看一份字段 Schema 被渲染成可交互表单）。原理均在本章自足。

表单引擎是低/无代码平台中最核心、最成熟的"微型内核"，它把"字段、校验、联动、布局"表达成可解释的 Schema，并驱动渲染与数据流。本章从表单驱动原理出发，依次讲解 Schema 设计、字段组件体系（控件/校验/联动/依赖）、JSON Schema 校验、渲染器与动态表单实现，最后收敛到性能与可扩展设计。表单引擎是理解后面"渲染引擎"与"协议设计"的最佳切入点，因为它足够小却五脏俱全。

## 一、表单驱动原理

### 1. 传统表单 vs Schema 驱动表单

- **传统**：每个表单写死组件、写死校验逻辑、指令式处理值（受控组件层层手写）。
- **Schema 驱动**：一份描述字段、规则、布局、联动的 JSON，交给通用渲染器统一渲染。

```js
// 传统：为每个字段手写受控逻辑
const [name, setName] = useState('');
const [phone, setPhone] = useState('');
return (
  <>
    <Input value={name} onChange={e => { setName(e.target.value); }} />
    <Input value={phone} onChange={e => { setPhone(e.target.value); }} />
  </>
);
```

```json
// Schema 驱动：声明字段与规则，引擎负责渲染与状态
{
  "type": "object",
  "properties": {
    "name": { "title": "姓名", "type": "string", "required": true },
    "phone": {
      "title": "手机号",
      "type": "string",
      "required": true,
      "pattern": "^\\d{11}$"
    }
  }
}
```

### 2. 表单引擎的核心闭环

```
Schema 定义 ──▶ 渲染器渲染字段 ──▶ 用户输入 ──▶ 状态管理（值域）
    ▲                                                       │
    └──────── 校验/联动/提交流入 ─────────────────────────┘
```

模型域（数据）、视图域（组件）、逻辑域（校验/联动）三者由引擎统一编排，构成"**FormState + FieldModel + 渲染器**"三段式。

### 3. 表单引擎的四大职责

- **渲染**：由 Schema 递归生成字段组件树。
- **状态**：维护表单值、脏标记（dirty）、字段错误（errors）。
- **校验**：同步/异步规则、跨字段校验、提交时聚合。
- **联动**：字段值变化触发其他字段的显隐、禁用、选项、回填。

## 二、Schema 设计

### 1. 一份完整的字段 Schema（json）

```json
{
  "name": "userForm",
  "type": "object",
  "properties": {
    "username": {
      "title": "用户名",
      "type": "string",
      "widget": "Input",
      "required": true,
      "minLength": 3,
      "maxLength": 20,
      "props": { "placeholder": "请输入用户名", "allowClear": true }
    },
    "age": {
      "title": "年龄",
      "type": "number",
      "widget": "InputNumber",
      "minimum": 0,
      "maximum": 150
    },
    "tags": {
      "title": "标签",
      "type": "array",
      "items": { "type": "string" },
      "widget": "Select",
      "props": { "mode": "tags" }
    },
    "hobby": {
      "title": "爱好",
      "type": "string",
      "enum": ["篮球", "音乐", "阅读"],
      "widget": "Radio"
    }
  },
  "layout": {
    "type": "grid",
    "columns": 2,
    "orderBy": ["username", "age", "tags", "hobby"]
  }
}
```

### 2. Schema 三类型字段：语义字段

| 类型 | 作用 | 示例 |
| --- | --- | --- |
| `string` | 文本 | 姓名、邮箱、手机号 |
| `number` | 数值 | 年龄、价格 |
| `integer` | 整数 | 数量 |
| `boolean` | 布尔 | 是否启用 |
| `array` | 数组/多选 | 标签列表 |
| `object` | 嵌套对象 | 地址({省,市,区}) |

跨越"语义类型"（string/number）与"交互组件"（widget: Input/Select）是表单 Schema 的关键设计——**同一个 string 可以是输入框也能是下拉**。

### 3. 扩展字段：平台自建 Key

在 JSON Schema 基础上，平台通常铺设自定义键（如 `widget`、`props`、`componentProps`、`x-*` 前缀）。

```json
{
  "inputWidth": "100%",
  "visible": true,
  "disabled": "&#123;&#123; formValues.age > 60 &#125;&#125;",
  "labelWidth": 120
}
```

建议用统一前缀（如 `x-component`、`x-linkages`、`x-validator`）隔离平台扩展与标准 JSON Schema，便于下游工具（校验器、文档、出码）兼容。

## 三、字段组件体系

### 1. 控制层（控件/Widget 注册表）

渲染器通过 `widget` 映射到实际 React/Vue 组件：

```ts
// 控件注册表：widgetName -> 组件
const widgetMap: Record<string, ComponentType> = {
  Input, InputNumber, Select, Radio, Checkbox,
  DatePicker, Switch, Upload, Cascader, TreeSelect,
};
```

- 同类型字段可切换不同控件（如 string → Input / TextArea / Select）。
- 支持自定义组件注册：`registerWidget('MyCustomer', CompWrapper)`。

### 2. 校验层

两类校验并存：

- **内置语义校验**：`minLength` / `maximum` / `pattern` / `enum` / `required`，由 JSON Schema 直接驱动。
- **自定义校验（async 函数）**：跨字段、调接口、复杂规则。

```ts
const customValidator = async (value, ctx) => {
  const exists = await api.checkUserName(value);
  if (exists) return { type: 'error', message: '用户名已被占用' };
  return null; // 通过
};

// 在 Schema 中注册
// "x-validator": "checkUserNameUniqueness"
```

### 3. 联动层与依赖

联动本质是"**监听某个字段值变化，驱动另一个字段的配置/显隐/回填**"，声明式表达为：

```json
{
  "linkage": {
    "type": "depend",
    "when": "&#123;&#123; formValues.type === 'member' &#125;&#125;",
    "actions": [
      { "target": "memberCode", "effect": "show" },
      { "target": "partnerCode", "effect": "hide" }
    ]
  }
}
```

常用联动效果清单：

| effect | 语义 |
| --- | --- |
| show / hide | 控制显隐 |
| enable / disable | 控制可用态 |
| fill | 由关联值回填 |
| setOptions | 联动更新下拉选项 |
| require | 动态调整是否必填 |

依赖链路要标记"依赖图"，避免 A 依赖 B、B 又依赖 A 的死循环，并通过**联动的拓扑序**执行。

## 四、JSON Schema 与数据校验

### 1. JSON Schema 标准（draft-07 / 2020-12）

表单引擎可直接复用成熟校验器（如 `ajv`），无需自造轮子。

```ts
import Ajv from 'ajv';

const ajv = new Ajv();
const validate = ajv.compile({
  type: 'object',
  properties: {
    email: { type: 'string', format: 'email' },
    age: { type: 'number', minimum: 0 },
  },
  required: ['email'],
});
const ok = validate({ email: 'a@b.com', age: 20 });
```

校验关键字速查：

| 关键字 | 含义 |
| --- | --- |
| `required` | 必填字段列表 |
| `type` | 类型约束 |
| `pattern` | 正则 |
| `minLength/maxLength` | 字符串长度 |
| `minimum/maximum` | 数值边界 |
| `enum` | 枚举可选 |
| `items` | 数组子项校验 |
| `format` | 扩展格式（email/date/uri） |

### 2. 前端实时校验 vs 后端兜底

前端校验负责"即时反馈"提升体验，后端必须做最终校验与安全兜底——**不要信任前端校验通过的数据**。

- 前端：`validateField`（单字段）、`validateForm`（整体）。
- 提交只要拦截非法值，不做过重业务。
- 后端：按同一 Schema 复用 `ajv`，保证校验逻辑前后一致。

## 五、表单渲染器与动态表单

### 1. 渲染流程（递归遍历 Schema）

```ts
function renderForm(schema: FieldSchema): ReactElement {
  const Widget = resolveWidget(schema.widget, schema.type);
  return (
    <Widget
      {...toWidgetProps(schema.props)}
      value={state.get(schema.name)}
      onChange={(v) => {
        state.set(schema.name, v);
        runLinkages(schema.name);
      }}
    />
  );
}
```

- `state` 是**表单值域**（Map/Proxy），维持受控值。
- 子字段是 object/array 时递归展开，形成完整的表单树。

### 2. 状态更新的细节：受控与非受控

低代码表单普遍采用**受控 + 独立 FormState**，理由：

- 联动、校验、提交需要统一读取"居中的权威值"。
- 通过 immutable 更新或 `Proxy` 拦截，确保组件只重渲染被影响的最小范围。

```ts
// 用 Proxy 监听字段写入，触发精确联动
const formState = new Proxy({}, {
  set(target, key, value) {
    target[key] = value;
    invalidateKey(key);   // 只更新依赖 key 的字段
    runLinkagesForKey(key);
    return true;
  }
});
```

### 3. 动态表单（Dynamic Form）

同一份 Schema 在不同场景复用（新增/编辑/详情/只读），通过配置开关：

| 模式 | 变化 |
| --- | --- |
| 创造 | 全部可编辑 |
| 编辑 | 部分禁用 |
| 详情 | 全部只读 |
| 打印 | 隐藏表单组件，纯文本展示 |

引擎用一个 `mode` 贯穿渲染器，字段根据 mode 加 `disabled`/`readonly`/`hidden` 属性，是"一份 Schema 多处消费"的典型实践。

## 六、性能与可扩展

### 1. 性能要点

- **最小化重渲染**：字段级订阅（dependency 收集），而非整表重渲。参考 Signals / useSyncExternalStore。
- **大表单分栏/懒渲染**：折叠面板内的字段按需挂载（visible 时再 create）。
- **校验去抖（debounce）**：输入类字段 onChange 校验做去抖，提交时做全量强校验。
- **只读/详情优化**：用字符串渲染替代组件树，减少渲染成本。

```ts
// 仅订阅被读取字段：字段依赖分析
const RenderOnlyVisible = withTracker(() => {
  // 只有 visible = true 的字段才挂载组件
});
```

### 2. 可扩展设计

- **自定义控件**：`registerWidget` + 适配器协议（value/onChange/componentProps 规范统一）。
- **自定义校验器**：`registerValidator(name, fn)`，Schema 用名称引用而非内联函数，保证可序列化。
- **自定义联动动作**：扩展 linkage effect 类型（跳转、发接口、写入 store）。
- **跨框架复用**：把"Schema 解析 + 校验 + 状态"做成框架无关核心，React/Vue 各自提供薄渲染适配层（Formily 即此范式）。

### 3. 表单引擎演进路径（实践建议）

```
阶段1  JSON→渲染器（单表单，字段+内置校验）
阶段2  + 状态管理 + 联动（show/enable/fill）
阶段3  + 自定义控件/校验器（注册表）
阶段4  + 动态模式（新增/编辑/详情/打印）+ 大表单性能优化
阶段5  + 对接可视化搭建（物料面板直接产出表单 Schema）
```

## 七、最小实现：Demo 掌握原理

在 `code/frontend/15-lowcode` 里 `node server.js` 后打开 `schema-driven-render.html`：用一段字段 Schema（声明 type/widget/required/linkage）由 JS 递归渲染出输入框、下拉、校验与联动提示。原理一句话：表单引擎 = "Schema 声明规则 + 渲染器解释渲染 + 状态驱动校验/联动"，这份 demo 就是去掉框架壳的内核最小映照。
