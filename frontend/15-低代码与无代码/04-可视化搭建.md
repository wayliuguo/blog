# 可视化搭建
> 级别：高级

> 本章按四层推进：入门（搭建器架构、设计态与运行态分离）→ 进阶（画布渲染与拖拽 DnD、物料体系）→ 实战（select/hover/resize、撤销重做、序列化与版本管理）→ 最小实现（到 `code/frontend/15-lowcode` 运行 `drag-palette.html`，亲手把物料拖进画布）。原理均在本章自足。

可视化搭建（可视化搭建器，Designer）把"写 Schema"抽象成"拖拽配置"，让非开发者也能产出页面。设计态与运行态共用同一套渲染内核，搭建器只是在其上叠加"结界层"（画布、选中、hover、调整大小、撤销重做）。本章剖析搭建器架构、画布渲染与拖拽（DnD）、组件物料体系、select/hover/resize/undo-redo 交互、序列化与版本管理，以及页面/区块/模板三级复用体系。掌握了搭建器，你就掌握了低代码平台的"生产力端"。

## 一、搭建器架构

### 1. 搭建器总览

```
┌──────────────────────────────────────────────────────┐
│  顶层：工具栏（撤销/重做/保存/预览/发布）               │
├───────────┬───────────────────────────┬───────────────┤
│ 物料面板   │        画布 Canvas        │  属性/大纲面板  │
│ (组件/区块)│  (实时渲染 + 装饰层)      │  (props/config)│
├───────────┴───────────────────────────┴───────────────┤
│  底层：Schema 数据模型 + 历史栈(undo/redo) + 快捷键     │
└──────────────────────────────────────────────────────┘
```

- **物料面板**：可拖入画布的组件/区块/模板清单。
- **画布 Canvas**：渲染当前页面 Schema（复用运行渲染器），叠加选中、hover、拖拽目标指示等装饰层。
- **属性面板**：编辑选中节点的 props、事件、表达式、数据绑定。
- **大纲面板**：以树形展示页面节点层级，支持选择/排序。
- **EditorState**：作为"设计态状态中枢"，与运行态状态分离，避免拖拽抖动串扰。

### 2. 设计态 vs 运行态的逐点对比

| 关注点 | 设计态 Designer | 运行态 Runtime |
| --- | --- | --- |
| 渲染目的 | 让用户看得见、可编辑 | 呈现最终页面 |
| 渲染核心 | 同一 Renderer + 装饰层 | Renderer |
| 交互 | hover 高亮、点击选中、拖拽移动 | 正常用户交互 |
| 数据 | 预览用 mock 数据源 | 真实接口数据 |
| 状态 | EditorState（选中/拖拽/历史） | 页面状态（form/pageState） |
| 安全 | 不受限（本地配置） | 表达式沙箱严格 |

**关键设计准则**：绝不直接改组件 props 来"做编辑"，而是通过"覆盖层脚本"（EditorOverlay）在画布上绘制选中框、resize 手柄等，从而保证运行渲染器零侵入。

## 二、画布渲染与拖拽（DnD）

### 1. 画布渲染实现

- 画布内使用与运行态相同的递归渲染器。
- 每个可编辑节点包一层 `EditorNode`，拦截事件（click 选中、drag 开启、hover 高亮）。
- `<iframe>` 隔离（可选）：把设计态 JS/CSS 与业务运行环境隔离，避免污染（阿里低代码引擎即用多窗口/iframe 设计）。

```
EditorNode 结构：
  <overlay-selected>      选中框
  <overlay-hover>         hover 高亮
  <content>  <RendererNode node=... />  </content>   实际内容
```

### 2. 拖拽的两类语义

| 语义 | 触发 | 结果 |
| --- | --- | --- |
| 拖入（drop to canvas） | 从物料面板拖进画布 | 新增节点，插入容器 |
| 拖移（reorder within canvas） | 画布内移动已有节点 | 改变层级/顺序 |

两套流程都基于 **HTML5 Drag & Drop** 或 **Pointer Events** + 自定义 drop target 命中检测。

### 3. 拖拽命中与插入位置计算

- 对每个容器节点计算其子节点的"槽位（slot）"矩形。
- 拖拽过程中实时计算当前指针命中哪个槽位，绘制插入/高亮指示线。
- drop 时把被拖节点的 Schema 树 **浅拷贝（deep clone）** 到目标容器 children。

```ts
function dropNode(targetContainerId, insertIndex, draggedNode) {
  const cloned = deepClone(draggedNode);
  insertAt(containerTree, targetContainerId, insertIndex, cloned);
}
```

> 拖拽 ≠ 直接移动引用；一定做深拷贝，保证撤销/重做与多实例安全。

## 三、组件物料体系

### 1. 物料在搭建器的角色

每个可拖拽单元需要**物料元数据（MaterialMeta）**，既决定它在物料面板的展示，也决定它 drop 后的默认 Schema：

```ts
interface MaterialMeta {
  name: string;                 // 物料唯一标识（= Schema.component）
  title: string;
  group: 'layout' | 'form' | 'datalist' | 'chart' | ...;
  thumbnail?: string;           // 物料面板预览图
  defaultSchema: SchemaNode;    // 拖入后生成的默认节点 Schema
  category: 'component' | 'block' | 'template';
  canContain: boolean;          // 是否容器（可容纳子节点）
  acceptChildTypes?: string[];  // 允许放入的子物料
}
```

### 2. 一级/二级物料：组件、区块、模板

| 层级 | 定义 | 复用粒度 | 示例 |
| --- | --- | --- | --- |
| 组件 Component | 最小可配置单元 | 字段/控件 | Button、Input、Card |
| 区块 Block | 组件+布局+静态配置的集合 | 页面局部 | 用户信息卡片、表格工具栏 |
| 模板 Template | 一个完整页面/场景模板 | 整页 | 登录页、商品详情模板 |

模板通常内置"数据源占位 + 区块组合 + 页面级 state"，是快速建站与最佳惯例的载体。

### 3. 物料接入协议

物料通过注册进入搭建器（与运行态 Registry 同源）：

```ts
registerMaterial(materialMeta);
```

物料元数据同时被三处消费：物料面板展示、drop 生成 Schema、属性面板渲染（`defaultSchema.props` 由哪个属性配置面板控制）。

## 四、select / hover / resize / undo-redo

### 1. 选中（select）与 hover

- 维护 `EditorState.selectedId` 与 `hoverId`。
- hover：轻量高亮（不打开属性面板）。
- select：绘制选中框 + 同步高亮大纲面板对应节点 + 打开属性面板。
- 点击空白画布 → 清空选择。点击子节点 → 优先选中子节点（最内层命中）。

```ts
function handleNodeClick(e) {
  e.stopPropagation();
  setSelected(nodeId);           // 命中最深层
}
canvasBackground.onpointerdown = () => setSelected(null);
```

### 2. 调整大小（resize）

用于绝对定位容器（如大屏、自由画布）或可拖大小容器：

- 选中节点渲染 8 个手柄（角/边）。
- drag 手柄通过指针 delta 缩放节点 width/height。
- 支持"参照物"吸附（对齐到其他节点/画布边缘），提升排版体验。

### 3. 撤销 / 重做（undo-redo）

核心是**历史栈**：

```
undoStack: [snapshot_0, snapshot_1, ...]
redoStack: [再次分叉的 future ...]
当前指针 cur
```

实现要点：

| 方案 | 粒度 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 整树快照（serialize 全量） | 粗 | 实现简单、可靠 | 大页面内存/性能开销 |
| 命令模式（Command） | 细 | 精细、可合并 | 命令多较复杂 |
| Patches（diff 增量） | 中 | 折中 | 需实现 diff 工具 |

常用**"命令 + 快照"混合**：每次编辑生成一条命令，命令记录前后快照（或逆向操作），栈顶合并连续小操作（拖动完成才压栈）。

```ts
function commit (doFn, undoFn) {
  undoStack.push({ doFn, undoFn });
  redoStack.length = 0; // 分叉即清空 redo
}
function undo() {
  const top = undoStack.pop();
  top?.undoFn();
  redoStack.push(top);
}
```

键盘快捷键（Ctrl/Cmd+Z 撤销、Ctrl+Shift+Z 重做、Delete 删除）覆盖同样命令。

## 五、序列化与版本管理

### 1. 序列化协议

- 设计态全部内容最终 `JSON.stringify` 为持久化 Schema（版本字段必含 `version`）。
- 存储单元分三种：

| 单元 | 作用域 | 复用 |
| --- | --- | --- |
| 页面 Schema | 单页 | 发布/路由 |
| 区块数据 | 组件组合切片 | 全站复用 |
| 模板包 | 整页含数据源/样式 | 多项目复用 |

```json
{
  "version": 3,
  "type": "page",
  "route": "/order/detail",
  "state": { "@flow": 1, "@table": "t_order" },
  "layout": { "component": "Page", "children": [] }
}
```

### 2. 版本与迁移

- **schema 升级**：版本号递增 + `migrate(oldV, newV)` 迁移函数，保证旧数据兼容渲染。
- **发布版本**：页面进入"历史版本"列表，支持回滚、对比、灰度发布。
- **草稿 vs 正式**：设计态保存草稿，发布生成正式快照（不可覆盖破坏）。

### 3. 冲突与协作（高级）

多人同时编辑同页面会有冲突。轻量方案：**乐观锁 + 版本号校验**；进阶方案：基于 CRDT / OP 的实时协作（类似协同文档），复杂度高、一般平台前期用前者。

## 六、页面 / 区块 / 模板体系

### 1. 三级复用与继承

```
模板 Template（整页惯例）
   └─ 实例化 → 页面 Page
         └─ 内含 区块 Block（可嵌套复用）
               └─ 由 组件 Component 组成
```

- 组件处于层级最底，可被"组件库（托管全局）"更新。
- 区块是"局部业务切片"，可在多页面复用，编辑后可"用最新版本替换旧引用"。
- 模板决定页面初始骨架，通常一次性落库为页面后独立演化。

### 2. 跨项目/跨团队的物料库

- 统一物料仓库（npm 包 / 平台内部物料中心）。
- 版本锁：页面记录其引用的物料版本，发布时打包固定版本，保证"历史页面如旧渲染"。
- 低代码内核与传统 npm 结合：物料即组件 npm 包，Schema 引用其 registry 名。

### 3. 搭建器到发布的链路

```
搭建(编辑 Schema) → 保存草稿 → 测试/预览 → 发布(生成正式快照+版本)
       └─> 出码（可选，接入静态代码）或 运行时直接读快照渲染
```

发布可选择"运行时解释 Schema"或"编译出码"两条路径，后者将在本系列第 5 篇详述（Parser/Compiler/Generator）。

## 七、搭建器工程沉淀清单

- 设计态与运行态状态**严格分离**（EditorState vs 页面状态）。
- 画布装饰层（选中/hover/resize）**叠加而不侵入**渲染器。
- 拖拽一律**深拷贝**，历史栈承载撤销/重做。
- Schema 带 `version`，提供迁移函数兼容旧数据。
- 物料元数据三处消费（面板/drop/属性面板）单一来源。

## 八、最小实现：Demo 掌握原理

在 `code/frontend/15-lowcode` 里 `node server.js` 后打开 `drag-palette.html`：左侧是物料面板（按钮/输入/卡片），点击或拖拽即可把物料加进右侧画布，每加一块都会更新当前页面 Schema。原理一句话：搭建器 = "物料（默认 Schema）→ 画布深层插入 → 序列化"，这份 demo 是"搭积木式搭建"的最小闭环。
