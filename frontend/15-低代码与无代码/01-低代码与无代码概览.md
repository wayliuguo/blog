# 低代码与无代码概览
> 级别：中级

> 本章按四层推进：入门（概念辨析、形态分类、优缺点与选型）→ 进阶（声明式与命令式差异、关键词语义、产业链分层）→ 实战（典型平台与选型决策落地）→ 最小实现（到 `code/frontend/15-lowcode` 运行 `schema-driven-render.html`，亲眼看到"一段配置渲染成界面"，理解低代码的本质）。原理均在本章自足，不依赖后文。

低代码（Low-Code）与无代码（No-Code）是两类以"数据驱动、可视化搭建、配置优先"为核心思想的开发范式，旨在以更少的代码量、更短的时间交付业务应用。本章从概念辨析、平台形态分类、产业链与落地场景、优缺点与选型、典型平台五个维度展开，为后续深度的 Schema 引擎、渲染器与搭建器内容建立全局认知。理解低代码/无代码的本质，是把"配置"转化为"运行时可解释的 Schema"这一建模能力。

## 一、概念与区别

### 1. 定义

- **低代码（Low-Code Platform，LCAP）**：通过少量代码（脚本、表达式、组件扩展）搭配可视化配置完成应用开发，面向专业开发者与"业务侧开发者（Citizen Developer）"。
- **无代码（No-Code Platform）**：不写任何代码，纯靠拖拽、表单、流程图配置完成应用搭建，面向完全非技术的业务人员。

### 2. 核心维度对比

| 维度 | 低代码 Low-Code | 无代码 No-Code |
| --- | --- | --- |
| 目标用户 | 专业/半专业开发者 | 业务人员、运营、非技术 |
| 是否需要写代码 | 需要（脚本/表达式） | 不需要 |
| 扩展能力 | 强（自定义组件、插件） | 弱（受平台物料约束） |
| 灵活性 | 高 | 低 |
| 适用复杂度 | 中高复杂度业务系统 | 简单表单、流程、页面 |
| 典型代表 | 宜搭、微搭、OutSystems | Airtable、Bubble、Retool 轻量场景 |
| 交付速度 | 快 | 最快 |
| 可控性/运维 | 平台内置为主 | 完全平台托管 |

> 现在多数头部平台是"低代码+无代码"混合体：核心靠配置，复杂点开放表达式与脚本入口。因此更准确的说法是"**低/无代码连续性（continuum）**"。

### 3. 与传统开发的根本差异

传统代码开发是"**指令式（imperative）**"——每一步都要写出具体逻辑；低/无代码是"**声明式（declarative）**"——描述"要什么"（Schema），由引擎解释"怎么做"。这一差异是所有渲染器、表达式引擎、出码器的理论起点。

```js
// 传统：命令式，写清楚每一步校验逻辑
const validate = (v) => {
  if (!v) throw new Error('不能为空');
  if (!/^\d{11}$/.test(v)) throw new Error('手机号格式错误');
  return true;
};

// 低代码：声明式——只描述规则，由引擎执行
// { "required": true, "pattern": "^\\d{11}$", "message": "手机号格式错误" }
```

### 4. 关键词集中罗列（面试语义辨析）

- **Schema**：可被引擎解释的统一描述结构，是低代码的"源代码"。
- **物料（Assets/Materials）**：可复用的组件、区块、模板的统称。
- **引擎（Engine）**：解析 Schema 并渲染的执行器，含渲染、表达式、联动等。
- **搭建器（Designer/Builder）**：生成 Schema 的可视化编辑工具。
- **出码（Codegen）**：由 Schema 编译生成传统代码（Vue/React/HTML）。
- **数据源（DataSource）**：Schema 引用的后端接口、字典、mock 数据。

## 二、平台形态分类

### 1. 表单类

以"表单驱动"为主的平台，强调字段配置、校验、联动与数据提交。

- **适用**：数据填报、审批、内部工具。
- **典型**：宜搭、简道云、金数据。
- **核心能力**：字段类型库、校验规则、联动表达式、提交与回显。

### 2. 报表/数据可视化类

- **适用**：BI 报表、经营看板、大屏指挥中心。
- **典型**：帆软 FineReport、DataV、ECharts 系配置平台。
- **核心能力**：数据查询绑定、图表组件、布局网格、大屏动效。

### 3. 大屏类（Dashboard/DataV）

- 2K/4K 分辨率、多图层定位（绝对定位）、数据轮询刷新、组内动效。
- 大屏本质也是"**Schema + 数据源 + 组件**"，只是定位与交互更偏展示。

### 4. 业务应用类

- 一个完整业务系统（表单+列表+详情+流程+权限），如进销存、CRM、工单系统。
- 典型：OutSystems、Mendix、微搭、宜搭。

### 5. API 集成/自动化类

- **适用**：应用间数据联动、定时任务、webhook 编排。
- **典型**：Zapier、Make（Integromat）、n8n、自建集成网关。
- **核心能力**：触发器、连接器（Connector）、步骤编排、数据映射。

### 6. 形态归属速查表

| 形态 | 核心抽象 | 产出 | 底层 Schema重点 |
| --- | --- | --- | --- |
| 表单 | 字段+规则 | 单页表单 | 字段Schema、校验、联动 |
| 报表 | 数据集+图表 | 报表页 | 数据绑定、图表配置 |
| 大屏 | 图层+数据源 | 大屏页面 | 绝对定位、轮询、动效 |
| 业务应用 | 页面+模型+流程 | 完整系统 | 模型驱动、路由、权限 |
| API集成 | 连接器+步骤 | 自动化流 | 步骤DSL、映射 |

## 三、产业链与落地场景

### 1. 产业链分层

```
┌────────────────────────────┐
│         应用层             │  👤 最终业务用户
├────────────────────────────┤
│      低/无代码平台层        │  🛠️ 开发者/业务开发者
├────────────────────────────┤
│  通用能力中台（DSL/引擎）    │  ⚙️ 平台内核
├────────────────────────────┤
│  PaaS/IaaS（云、容器、DB）   │  🖥️ 基础设施
└────────────────────────────┘
```

- **内核层**：Schema 协议、渲染引擎、表达式引擎、出码器、物料仓库。
- **平台层**：可视化搭建器、数据建模、权限、流程编排、版本与发布。
- **应用层**：最终交付的业务应用与其用户。

### 2. 典型落地场景

| 场景 | 价值 | 例子 |
| --- | --- | --- |
| 内部管理工具 | 快速上线、成本低 | 审批、报销、资产管理 |
| 对客前台页面 | 快速迭代、多渠道 | 营销落地页、活动页 |
| 数据填报分析 | 可视化建模 | 运营收集、报表系统 |
| 系统集成自动化 | 消除人工 | 系统间数据同步、告警通知 |
| 头部企业交付 | 组合入院 | 大厂中后台（阿里、腾讯企微侧） |

### 3. 落地中的"二八原则"

约 80% 的场景是通用 CRUD 与表单流程，20% 需要定制扩展。成熟平台用"**通用能力可配置 + 长尾能力可扩展（脚本/组件）**"覆盖，这正是低代码区别于无代码的底气。

## 四、优缺点与选型

### 1. 优点

- **交付快**：传统以周/月记，低/无代码以小时/天记。
- **门槛低**：业务人员可自建，减轻研发排期。
- **易维护**：统一 Schema，改动配置即发布，版本可回溯。
- **标准化**：组件、模板、规范内聚在平台，减少重复造轮子。

### 2. 缺点与风险

- **锁定效应（Vendor Lock-in）**：数据、Schema 被平台绑定，迁移成本高。
- **性能与可扩展受限**：复杂交互、超大列表、精细视觉难以极致优化。
- **上下边界模糊**：一旦需求超框架，改造比从零写还难（"黑色隧道"）。
- **调试困难**：配置出问题定位链路长，黑盒化。
- **安全问题**：表达式沙箱、权限模型、数据越权需重点设计。

### 3. 选型决策框架

```
需求复杂度（交互/性能/扩展）
        │
        ├─ 低 且 无技术团队 ────────────► 无代码（表单/报表平台）
        │
        ├─ 中 ─────────────────────────► 低代码（表单引擎+可视化搭建）
        │
        └─ 高 ─ 需要深度扩展/自研内核 ──► 自研低代码引擎 or 混合（微搭/宜搭+自定义组件）
```

关键问自己三问：
1. **谁在用**？业务自建偏高代码/无代码，研发出手可接受低代码。
2. **要做到什么复杂度**？决定是否需要表达式、自定义组件、出码。
3. **谁掌控生产环境**？决定选私有化部署还是 SaaS 托管。

## 五、典型平台

### 1. 阿里宜搭

- 定位：钉钉生态内低代码应用搭建，表单/流程/报表一体。
- 特点：与钉钉审批、通讯录、IM 深度集成；Schema 化；支持脚本。

### 2. 腾讯微搭

- 定位：微信生态的低代码平台，面向小程序/公众号 H5。
- 特点：基于 web 组件的可视化搭建 + 云开发（CloudBase）后端。

### 3. Shipwright / magnet（命令行低代码内聚）

- 这类工具偏"代码生成管线 + 本地开发"的低代码，强调 **Schema → 工程化出码**，用户在生成代码基础上继续用 Git 迭代。
- 特点：可审查的产物代码、CI/CD 友好、可脱离平台维护。

### 4. 开源内核与生态

- **Alibaba 低代码引擎（lowcode-engine）**：面向搭建工具/平台建设者，提供渲染器、设计器、物料协议、出码能力，是业内公开的完整内核范本。
- **Formily**：表单 Schema 与状态方案，低代码表单字段层的工业标准。
- **Amis（百度）**：JSON 配置驱动的富交互页面渲染器。

### 5. 选型场景对照

| 场景 | 推荐 | 理由 |
| --- | --- | --- |
| OA 审批流程 | 宜搭/简道云 | 审批/流程开箱即用 |
| 微信小程序营销 | 微搭 | 微信生态原生 |
| 需要源代码可审查 | Shipwright/magnet 类 | 出码可 Git 治理 |
| 自研平台内核 | 阿里低代码引擎/Formily | 开放协议、二次开发 |
| 内部工具 | Retool/Airtable | 快速 CRUD 与数据连接 |

## 六、自我定位与技术栈路径

对前端开发者，建议把"低代码"理解为一套**前端工程方法集合**，而不是某个产品：

- **字段/表单层**：掌握 Formily / Ant Design Form / JSON Schema。
- **渲染层**：能自己写出"读 Schema → 渲染组件"的通用渲染器。
- **搭建层**：理解画布、拖拽、选中、属性面板的数据流。
- **协议层**：能设计出"一次 Schema，多项消费（渲染/出码/校验/文档）"的协议。

本系列后续四篇将依次深入：表单引擎 → 渲染引擎与运行时 → 可视化搭建 → Schema 驱动与协议设计。建议先建立"Schema 即源码"的心智模型，再逐步下沉到引擎实现。

## 七、最小实现：Demo 掌握原理

在 `code/frontend/15-lowcode` 里 `node server.js` 后访问 `schema-driven-render.html`：一段 JSON 配置被少量 JS 渲染成可见的表单与卡片 UI，这就是"配置即界面"。原理一句话：低代码把"要什么"写成可解释的 Schema，由渲染器解释成组件，前面反复强调的"Schema 即源码、声明式优先"都服务于这条主线。想体验"搭积木式搭建"，再打开 `drag-palette.html`。
