# 渲染引擎与运行时
> 级别：高级

> 本章按四层推进：入门（Schema 到组件树到渲染的运行时链路）→ 进阶（React/Vue 渲染器、注册表与异步加载、表达式引擎）→ 实战（状态与联动、运行时架构分层落地）→ 最小实现（到 `code/frontend/15-lowcode` 运行 `schema-driven-render.html`，看最小渲染器如何把 Schema 解释成 DOM）。原理均在本章自足。

渲染引擎是低代码平台真正的"执行心脏"：它把层次化 Schema 翻译成组件树，跨越"设计态"与"运行态"，并承载表达式求值、状态管理、组件异步加载等能力。本章聚焦 Schema→组件树→渲染的运行时链路，深入 React/Vue 渲染器设计、组件注册表与异步加载、表达式引擎（作用域/求值/安全沙箱）、以及状态与联动的工程实现。掌握本章，你就具备了从"配置"到"像素"的完整解释能力。

## 一、Schema → 组件树 → 渲染

### 1. 运行时链路全景

```
页面 Schema (JSON)
   │  Parser 解析 → 节点图（Node Graph）
   ▼
组件树 (React/Vue Vnode 树)
   │  依层级递归创建组件实例并传入 props
   ▼
渲染器 render() → 真实 DOM 挂载
   ▼
交互事件 → 状态更新 → 局部重渲染 → 联动
```

- **解析层（Parser）**：把 Schema 字符串/对象转成内部节点结构，含节点 id、类型、props、子节点索引。
- **实例化层**：将节点映射为真实组件，建立"节点→组件实例"映射表（用于运行态更新/选中）。
- **渲染层**：递归产出 VNode 树并提交给宿主库（ReactDOM.createRoot / Vue createApp）。

### 2. 一个最小页面 Schema（json）

```json
{
  "component": "Page",
  "props": { "padding": 16, "title": "员工详情" },
  "children": [
    {
      "component": "Form",
      "name": "frm",
      "props": { "layout": "vertical" },
      "children": [
        { "component": "Input", "name": "frm.userName", "props": { "label": "姓名" } },
        { "component": "Select", "name": "frm.department", "props": { "options": [] } }
      ]
    }
  ],
  "dataSource": [
    { "id": "deptList", "type": "api", "url": "/api/dept/list", "method": "get" }
  ]
}
```

### 3. 渲染器核心（React 伪代码）

```tsx
function RenderNode({ node }: { node: SchemaNode }) {
  const Component = useResolveComponent(node.component);
  if (!Component) return <Fallback component={node.component} />;
  const props = useEvaluateProps(node.props, node.name); // 含表达式
  return (
    <Component {...props}>
      {node.children?.map(child => <RenderNode key={child.id} node={child} />)}
    </Component>
  );
}
```

关键点：**props 中命中表达式关键字的字段走"求值"而不是直接透传**，这是"动态配置"的根基。

## 二、React / Vue 渲染器设计

### 1. React 实现要点

- 用一个 `<RendererNode>` 函数组件递归渲染，配合 `React.memo` 减少无关节点重渲。
- 维护 `nodeIdToInstance` 的 ref，用于"选中/更新/联动"定位。
- 状态用 `Reducer` 或 `Store`（zustand/redux），字段级订阅避免整树 update。

```tsx
const MemoNode = memo(RenderNode, (prev, next) => prev.node === next.node);
```

### 2. Vue 实现要点

- 用 `h()` 函数式渲染节点，递归 `renderNode`。
- 动态 props 通过 `defineComponent` 的 props 透传或 `inheritAttrs: false` 控制。
- Vue 3 用 `reactive` 状态 + `watch` 耦合联动；组合式 API 更契合"字段级订阅"。

```vue
<script setup lang="ts">
import { h } from 'vue';
const props = defineProps(['node']);
const Comp = resolveComponent(props.node.component);
</script>
<template>
  <component :is="Comp" v-bind="resolvedProps">
    <template v-for="child in props.node.children" :key="child.id">
      <RenderNode :node="child" />
    </template>
  </component>
</template>
```

> 注意：示例中的 `<component>` 与 `<template v-for>` 是 Vue 特有内置组件；若渲染的组件名来自 Schema，一定要通过 `resolveComponent` 解析而非字符串直接拼模板，避免运行时未知组件报错。

### 3. 宿主隔离与版本对齐

- 渲染器运行态与搭建器设计态**共用同一套渲染核心**，仅在设计态额外注入 hover/选中框（装饰层）。
- React/Vue 各自提供宿主适配（mount 入口），核心逻辑（解析/求值/状态）保持框架无关。

## 三、组件注册表与异步加载

### 1. 组件注册表（Registry）

注册表是"名称→组件工厂"的字典，渲染器据此解析节点组件。

```ts
// 组件注册表与元信息
const registry = new Map<string, ComponentMeta>();

function register(meta: ComponentMeta) {
  registry.set(meta.name, meta);
}

interface ComponentMeta {
  name: string;
  component: ComponentType;       // 组件本身
  load?: () => Promise<ComponentType>; // 异步加载器（可选）
  defaultProps: Record<string, unknown>;
  widgetProps: string[];          // 哪些 props 支持表达式
  editable: { props: PropSchema[] }; // 供搭建器生成属性面板
}
```

### 2. 打包与异步加载策略

- **同步加载**：核心物料（基础表单控件）打入主包，减少首屏锯齿。
- **异步加载**：低频/重型组件（图表、富文本、地图）用 `load()` 懒加载。

```tsx
function useResolveComponent(name: string): ComponentType | undefined {
  const meta = registry.get(name);
  return meta?.component
    ?? meta?.load?.(); // 返回 Promise 时交由 Suspense / async 组件承载
}
```

对应到框架：

- Vue：`defineAsyncComponent(() => import('...'))`。
- React：`React.lazy` + `<Suspense>` 或自定义 Promise 缓存。

异步物料必须配合**按需配置（按 project 加载物料清单）**，避免全量注册导致体积膨胀。

### 3. 物料元信息驱动的"双端一致"

同一份 `ComponentMeta` 同时服务：
- 运行态：解析组件、异步加载。
- 搭建态：属性面板（`editable.props`）渲染配置表单。
- 文档态：自动生成组件说明。

## 四、表达式引擎

### 1. 表达式的定位

Schema 中的字符串字段若命中表达式前缀（如 `&#123;&#123; ... &#125;&#125;` 或 `$expr(...)`），运行时须先求值再作为 props。表达式引擎负责"解析字符串 → 计算值 → 安全隔离"。

平台通常约定三种形态：

| 形态 | 示例 | 求值方式 |
| --- | --- | --- |
| 字面量 | `"请输入"` | 直接透传 |
| 变量引用 | `$var.formValues.name` | 从作用域取值 |
| 表达式 | `&#123;&#123; formValues.age > 18 &#125;&#125;` | 编译执行 |

> 注意：本系列文档为避免 VitePress 构建把 `&#123;&#123;` 当成 Vue 插值，代码示例中的表达式文本采用 HTML 实体转义写法，如 `&#123;&#123; formValues.age > 18 &#125;&#125;`。JSON 等反引号代码块内按需谨慎处理。

### 2. 作用域（Scope）与求值

表达式需要一个明确的**作用域链**：`formValues`（表单值）、`pageState`（页面状态）、`context`（路由/用户）、内置方法（`utils`）。作用域设计决定表达式能触达哪些数据，也决定安全边界。

```ts
interface ExprScope {
  scope: {
    formValues: Record<string, unknown>; // 表单值
    pageState: Record<string, unknown>;  // 页面全局状态
    context: Record<string, unknown>;    // 路由/环境
    utils: Record<string, Function>;     // 白名单工具
  };
}

function evaluate(expr: string, scope: ExprScope) {
  // 1. 解析成 AST
  // 2. 通过 Interpreter 按作用域执行
  // 3. 回到调用方注入组件 props
}
```

### 3. 求值方式对比：eval vs 安全沙箱

| 方式 | 优点 | 风险 | 是否推荐 |
| --- | --- | --- | --- |
| `new Function('scope', 'return ' + expr)` | 快、功能全 | 可逃逸全局、注入危险代码 | 不推荐直接用 |
| 纯 AST 解释器（白名单操作符/函数） | 安全、可控 | 覆盖能力有限、性能略低 | ✅ 首选 |
| iframe / Web Worker 沙箱 | 强隔离 | 通信复杂、性能开销 | 重型场景 |

安全沙箱核心约束：

- **禁止访问全局**：`globalThis`、`window`、`document`、`require`、`process`。
- **白名单函数**：只开放 `utils` 内的受控方法（如 `formatDate`、`sum`）。
- **限制副作用**：表达式只读计算，不落库、不发请求（除非显式开放 action）。

```ts
// 简化版安全求值：AST 解释器白名单
const SAFE_KEYWORDS = ['&&', '||', '!', '===', '>', '<', '+', '-', '*', '/'];
function safeEval(node, scope) {
  switch (node.type) {
    case 'Identifier':
      return resolveInScope(node.name, scope); // 只在给定 scope 内查
    default:
      throw new Error('not allowed: ' + node.type);
  }
}
```

### 4. 表达式常见应用

- 条件显隐：`&#123;&#123; hasRole('admin') &#125;&#125;` 决定按钮是否渲染。
- 计算派生值：`&#123;&#123; formValues.price * formValues.quantity &#125;&#125;`。
- 动态校验/文案：根据状态拼装提示。

## 五、状态与联动

### 1. 状态模型

运行时统一维护**页面状态**，各节点通过"订阅/派生"访问：

```
页面状态 Store（pageState / formValues）
   ├─ 节点 A 订阅 formValues.a → 变化时重渲
   ├─ 节点 B 依赖派生函数 → 只算与自身相关子集
   └─ 联动 action 更新其他节点字段
```

字段级订阅用依赖收集（类似 `useSyncExternalStore` / Vue `reactive + effect`）阻断"整树闪烁"。

```ts
// 最小订阅模型
const subscriptions = new Map<string, Set<() => void>>();
function subscribe(key, fn) { ... }
function setState(key, value) {
  subscriptions.get(key)?.forEach(fn => fn());
}
```

### 2. 联动实现的两种路线

| 路线 | 机制 | 优点 | 适用 |
| --- | --- | --- | --- |
| 声明式（Schema 配置） | Schema 里写 `when/actions`，引擎执行 | 可序列化、可回放、搭建友好 | 通用业务 |
| 命令式（事件回调） | 组件/页面暴露事件，注册脚本 | 灵活 | 复杂自定义逻辑 |

实践中以声明式为基线、命令式做长尾扩展，并保证**联动的拓扑序**（依赖有向无环图）与循环检测。

### 3. 性能预算清单

- 表达式求值结果做 memo，避免同一节点反复求值。
- 异步组件缓存 Promise 单例，避免并发重复 import。
- 只在真实影响渲染的字段上触发更新（依赖收集）。
- 大列表节点（如表格行）使用虚拟滚动或数据切片。

## 六、运行时工程沉淀

把"解析、求值、状态、注册表、宿主适配"分层解耦，是最可维护的运行时架构：

```
                 ┌──────────────────────────────┐
       Schema     │          渲染引擎 Runtime      │
   ───────────────▶  Parser → Evaluator → Renderer │──▶ 宿主(DOM)
                  │          ↑        ↑            │
                  │     Registry   ExprSandbox     │
                  │     Store(状态/联动)           │
                 └──────────────────────────────┘
```

- **Parser** 保证 Schema 版本兼容（升级迁移）。
- **Registry** 是可扩展的物料接入点。
- **ExprSandbox** 是安全与能力边界。
- **Store** 是状态与联动的中枢。
