## 知识主线（一句话）

主轴是**「一次请求的成本可以从三个地方减掉：协议层少往返、缓存层不发请求、失败时正确地重试」**：01 把"同一连接上只能排队"变成"多路复用"（HTTP/2 与 HTTP/3），02 把"大部分请求"变成"不发"（缓存与 CDN），03 把"失败"变成"有界重试且不产生副作用"（超时 / 重试 / 退避 / 幂等），04 把"可信"变成"即使被注入也执行不了"（CSP / SRI / Trusted Types / 供应链）。

## 高频核心点

### 01 HTTP2 与 HTTP3

**HTTP/2 并发模型**

- **一句话**：把「请求」从「连接」里解耦，一条连接上开任意多 stream
- **实测 6 个 200ms 请求**：HTTP/1.1 单连接 1332ms · 六连接 231ms · HTTP/2 单连接 245ms（连接数 6 → 1）
- 域名分片、CSS 雪碧图、base64 内联等"绕开 6 连接"的手段价值随之下降

**两种队头阻塞**

- **应用层**：HTTP/2 消除（快请求 33ms 完成，慢请求自己 500ms 后返回）；**TCP 层**：HTTP/2 全跑在一条 TCP 上，丢包波及所有 stream——同一连接的问题换成了这一层

**HTTP/2 其它与 HTTP/3**

- 二进制分帧是基础；HPACK 头部压缩上下文是连接级 → CRIME/BREACH 攻击面；服务端推送已被移除，替代是 `103 Early Hints`
- **QUIC / HTTP/3**：stream 级重传（一条流丢包不影响它流）、TLS 1.3 内建、0-RTT 恢复只用于幂等请求、连接迁移靠 Connection ID
- 必须保留 HTTP/2 回退：中间设备可能拦 UDP（`Alt-Svc` 告知而非强制）

**工程落地**

- HTTP/2 实际使用必须 TLS + ALPN；含 h2c 只调试用；协议版本看 DevTools 的 Protocol 列或 `curl -I --http2`；正文压缩必开

### 02 CDN 与缓存体系

- **缓存是分层决策**：浏览器内存 / 磁盘 / SW / CDN 边缘 / 源站——同一套规则：`Cache-Control` + `Age` + `ETag` / `Last-Modified`；CDN 只是把规则在离用户更近的机器再跑一遍
- **三种策略**：强缓存 `max-age + immutable` 收益最大但更新靠改 URL · 协商缓存 `no-cache + ETag` 省正文不省 RTT（实测 200/2.5KB → 304/0B）· `no-store` 只给登录态这类；**`no-cache` ≠ 不缓存**，只是每次用前校验
- **协商缓存成立条件**：`ETag` 必须是内容指纹（带随机数/时间戳等于没配）；`Vary` 会进缓存键（`Vary: User-Agent` 崩边缘命中率）
- **stale-while-revalidate** 三区间：新鲜优先 → 先用旧的 + 后台刷新 → 过期必须同步请求；配 `stale-if-error` 源站故障兜底；库存/余额/权限不行
- **落地**：带哈希资源长缓存 + HTML/SW 用 no-cache；验收看 Size 列（memory/disk/304）与 X-Cache

### 03 网络可靠性与弱网

- **超时是前提且要分层**：连接 / 首字节（TTFB）/ 整体分设，只设总超时会误杀慢下载；值按接口类型定制（列表 3s、导出 30s）；**取消只发生在客户端**，前端超时 ≠ 服务端没执行 → 写操作靠幂等兜底
- **能不能重试看幂等**：GET/HEAD/PUT/DELETE 可自动重试、普通 POST 不可；幂等键三要求——客户端生成、语义是"一次业务意图"、有有效期；实测不带幂等键重试落了 2 单、带键 1 单
- **退避、抖动与上限**：必须尊重 `Retry-After`（四种策略一个都没采纳只把故障拖长）；抖动让重试风暴分散（20 客户端拥挤一刻 20 次 → 减半分散到 17 窗口）；完整策略 = 可重试类型 + 上限 + 退避抖动 + Retry-After，再上一层是熔断
- **弱网其它手段**：请求去重合并、并发限制与关键插队；离线队列重放必须带幂等键；乐观更新要能回滚且回滚有提示；`navigator.connection` 只能当优化信号
- **观测**：线上看成功率 / 超时率 / 重试率 / 重试后最终成功率；**重试率高但最终成功率低 = 重试在放大故障**

### 04 前端安全进阶

- **CSP 防的是能力不是输入**：`script-src 'self' 'nonce-…'` 下无 nonce 内联 / onclick / 第三方 CDN 被拦；nonce 逐请求生成；默认禁 eval 关掉"字符串变代码"；来源清单是白名单按资源类型收紧；上线顺序 Report-Only → 修内联 → 强制 → 保留上报端点
- **SRI 校验内容一致性**：`integrity` 必须配 `crossorigin` 否则拿不到可校验响应体；只保证"与声明一致"不保证"内容可信"；哈希构建期生成写进 HTML，最适合第三方 CDN 固定版本脚本
- **Trusted Types 的价值是收口**：`require-trusted-types-for 'script'` 后 `innerHTML = 字符串` 直接抛错，唯一通路是显式策略 + 净化——全项目只有一处能把字符串变 HTML
- **响应头与 Cookie**：体检五项 CSP / HSTS / nosniff / Referrer-Policy / frame-ancestors；HSTS `includeSubDomains` 谨慎（锁死整个域）；Cookie 四件套 HttpOnly / Secure / SameSite / `__Host-`
- **泄露面与供应链**：`.map` 不上线（`hidden-source-map` 只传监控平台）；上报白名单过滤；锁文件进仓库 + npm ci + 依赖审计进 CI，**减少依赖数量本身最有效**；最先被翻的是 `.git` / `.env` / 备份文件被部署到静态目录
