## 1. 渲染方式总览

### 1.1 两种绘制模式：即时模式与保留模式

本模块回答一个问题：**数据是怎么一步步变成屏幕上的像素，并且在海量数据下依然流畅的。** 底层画图只有两种模式：

```
即时模式   Canvas —— 一支画笔，画完就忘、画布上只有像素，没有场景图
保留模式   SVG / WebGL —— 声明"界面里有什么"，场景图交给浏览器托管
```

| 对比项 | Canvas（即时） | SVG（保留） |
| ---- | ---- | ---- |
| 场景图 | 无，自己建显示列表 | DOM 本身就是 |
| 重绘 | 手动整幅重画 | 浏览器按节点脏区更新 |
| 命中检测 | 自己算几何 | 事件直接绑元素 |
| 缩放 | 位图重采样 | 矢量无损 |
| 可访问性 | 无 | DOM 自带结构与语义 |

### 1.2 Canvas 心智模型：位图、状态机与显示列表

Canvas 的心智模型拆三件：

```
位图 + 即时   画完就忘、没有对象，任何变化都要重画；与 SVG 的取舍看规模与交互密度
状态机       设置状态 → 执行指令；save/restore 必须成对防状态泄漏，样式切换本身是开销
显示列表     把"当前画面由哪些指令构成"记下来，重绘 = 重放（ECharts ZRender 同思路）
```

理解"显示列表"是整条知识主线的第一步：即时模式没有对象，但你能自建一个"指令清单"，重绘不再是重算而是重放。

### 1.3 SVG 声明式：DOM 即场景图

SVG 用声明式节点描述图形，浏览器把每个图形当 DOM 节点来托管：

```
重绘   按节点脏区增量更新，不需要整幅重画
命中   事件直接绑元素，不用算几何
缩放   viewBox 解耦逻辑坐标与屏幕像素，矢量无损、响应式近零成本
可访问 DOM 节点自带结构，读屏器可读
```

对比之下 Canvas 的响应式要手动重设尺寸并整幅重画；SVG 在 scale 上天然免费。

### 1.4 分工边界：数量 × 交互密度

选型就盯两个变量——**图形数量 × 交互密度**：

```
几百以内 + 重交互        选 SVG（声明式、DOM 事件托管）
几千以上 + 逐帧变化      选 Canvas / WebGL
工程落地    ECharts renderer:'svg' 可一键切换渲染器
混合方案    高端大屏常"静态层 SVG/离屏 Canvas + 动态层 Canvas" 组合
```

## 2. Canvas 2D 性能

### 2.1 渲染成本模型：重绘 = 重放

即时模式没有对象，于是把「当前画面由哪些指令构成」记成**显示列表**，重绘 = 重放这个列表：

```
全量重绘   整幅 100 条指令全跑一遍
增量重绘   只重放变化的 1 条指令（脏矩形命中区）
实测(viz-lab)  100 根柱子改 1 根：全量执行 100 条、增量只执行 1 条
```

最小实现：`viz-lab` 是零依赖实验台，`node run.cjs` 六场景 `node:assert` 自检全绿——比例尺 / 布局 / 渲染成本 / 帧合并 / 降级。

### 2.2 帧纪律：标脏 + rAF 统一重绘

显示器 16.7ms 一刷，动画就要跟这个节拍对齐。核心纪律是**标脏 + 一帧一画**：

```
一切 setData 只标脏、不立即画
合并到 requestAnimationFrame 回调里统一重绘
实测一帧内 3 次变更只需画 1 次（viz-lab）
```

多条数据变更凑在同一帧只清一次屏、画一次，避免同一帧重复布局与重复绘制。

### 2.3 性能手法清单

性能手法可排序，**性价比从高到低**：

```
离屏 canvas 预渲染   不变部分（网格/背景）画一次存位图，每帧一次 drawImage
分层 canvas          静态层与动态层分离，动态层变化不影响静态层
帧内合并             多变更合并到一帧
增量重绘（脏矩形）   只重画受影响区域
批量同色 path        一次 beginPath 画完同色图形再 fill 一次
坐标取整             避免子像素抖动（半个像素的抗锯齿开销）
长任务切片           把超帧预算的重活分帧执行
```

### 2.4 降采样与降级策略

画不动了不是让页面卡住，而是**先量化再丢数据**：

```
最大点数 = 帧预算 ÷ 单点绘制成本
  实测单点成本 0.005ms 时上限约 3340 点，1 万点必须降采样
生产级方案  ECharts sampling:'lttb' 抽稀保形状（趋势图）
降级要诚实  降采样丢的点要在 tooltip / 图例里对用户可见
```

判定边界：趋势图用 LTTB 保峰值形状，监控折线按窗口聚合，超出 Canvas 能力上移 WebGL。

## 3. SVG 与声明式图形

### 3.1 path 指令与 viewBox 坐标

SVG 的 path 用指令串描述形状：

```
M 移动原点到某处     L 画直线      Z 闭合路径
C 三次贝塞尔曲线     折线加 C 变平滑曲线（过渡到光滑曲线）
描边动画   stroke-dasharray + stroke-dashoffset（进度环 / 签名动画原理）
```

**viewBox**：逻辑坐标系与屏幕像素解耦——设置好 viewBox 后，缩放/响应式近零成本（对比 Canvas 需手动重设物理尺寸并整幅重画）。

### 3.2 交互、动画与可访问性

```
事件   每个图形是元素，事件直接绑元素，浏览器托管命中检测
动画   CSS transition 连几何属性 r（半径）也能过渡
可访问 类如 path/rect/circle 自带 DOM 结构，读屏可读（Canvas 做不到）
```

交互与动画的成本被 DOM 托管，开发者不需要像 Canvas 那样手写命中与插值。

### 3.3 数据 join：增量更新骨架

D3 的 enter / update / exit 是增量更新的统一骨架——**数据变了只改差异节点**：

```
数据 100 → 105 条，只 append 新增的 5 个节点
与虚拟列表、框架 diff 同源——都是"记住旧态、算差异、只动变化部分"
```

这是 SVG 在大规模更新下仍能保持相对流畅的关键：不是整体重建，而是按数据差异做最小 DOM 变更。

## 4. WebGL 与 Three.js

### 4.1 GPU 渲染管线

先问"什么时候才值得上 WebGL"：**CPU 画不动的规模（万级图形 / 3D / 特效）才用；普通图表大屏别碰**。为什么它快——渲染管线只有两段可编程、中间固定：

```
顶点着色器   每顶点一次，算坐标（可编程）
光栅化       固定阶段，三角形 → 像素
片元着色器   每像素一次，算颜色（可编程）
GPU 并行     数千核心同时算——"一次 draw call 画几万三角形"的原因
```

两段可编程 + 数千核并行，正是"一次 draw call 画几万个三角形"的根源；代价是三维知识块多（相机 / 光照 / 矩阵 / draw call 合批）。

### 4.2 着色与材质

```
GLSL   一次只算一个顶点/像素的纯函数，时间变化走 uniform；没有共享全局状态的思维
材质(递进)  Basic 不受光 → Lambert 漫反射 → Standard PBR 主流 → Physical 透射/清漆
最低配  环境光 + 方向光就能做出质感
```

材质从简到繁，绝大多数场景 Standard（PBR）够用；光照最低配是 "环境光 + 方向光" 的组合。

### 4.3 Three.js 三件套与矩阵

Three.js 在 WebGL 上重建了保留模式场景图，核心是三件套：

```
Scene       装物体与灯
Camera      从哪看
Renderer    GPU 桥；renderer.render 每帧把场景图翻译成 draw call
```

网格 = 形状 × 材质。矩阵变换走 **模型 → 视图 → 投影**：

```
矩阵       模型 → 视图 → 投影
最佳实践   改物体属性(cube.rotation.y) 永远优于手动算顶点——框架每帧把模型矩阵与视图/投影相乘后随顶点提交
坑        裁剪面范围太宽会 z-fighting（深度精度不足）
```

## 5. 图表引擎原理

### 5.1 五层架构与两种流派

通用图表引擎把「数据 → 像素」拆成五层，交互层靠 invert 逆映射回数据：

```
数据 → 布局 → 比例尺 → 图形生成 → 渲染器
                              ↑ 交互层用 invert 逆映射回数据
```

| 流派 | 方式 | 特点 |
| ---- | ---- | ---- |
| ECharts | 配置驱动（option → 内部 processor 链 → ZRender） | 开箱即用，报表类几乎总是对的 |
| D3 | 数据驱动（selection / join，自由度即库本身） | 概念多，非标准信息图只有它顺手 |

### 5.2 比例尺：数据 ↔ 像素的桥

比例尺是「数据域 → 像素域」的映射函数，是连接数据与图形的唯一桥：

```
线性    k = 像素跨度 / 数据跨度；clamp 防异常值画出界
nice   步长对齐 1/2/5 × 10ⁿ 造出"整"刻度 —— 实测 [0,100]→5 格得 [0,20,40,60,80,100]
分段(类目)  5 类 600px、paddingInner 0.2 → step=125、柱宽 100
```

对数轴 / 序数轴 / 时间轴是同一个抽象的不同实现。最小实现：`viz-lab` 的 `scale.cjs` 是比例尺的最小可运行版本。

### 5.3 invert 逆映射与交互

交互能力建立在比例尺抽象上，而不是画图上：

```
hover / 点击拾取  先拿像素坐标
invert           用比例尺逆映射回数据域，才知道命中哪条数据
tooltip          依赖 invert 才能显示正确数据
```

所以"tooltip 怎么知道显示哪条数据"的答案是：像素反查数据（invert），而非基于某个画图对象。

### 5.4 布局：饼图与堆叠

布局层把「值」翻译成「几何」，两种典型：

```
饼图    angle = (v / total) × span，逐段累加起止角，弧段首尾相接（浮点累加留 1e-9 容差）
堆叠    多系列 y0/y1 区间首尾衔接，上一段 y1 = 下一段 y0 —— 堆叠柱 / 面积图的地基
```

布局应当是**纯函数**（输入不变输出不变）——这正是图表能做增量更新与动画插值的前提。最小实现：`viz-lab` 的 `layout.cjs`，实测全绿。

## 6. 性能实测与渲染管线

### 6.1 渲染管线与帧预算

一切性能优化都收敛到同一个数字——**16.7ms（一帧）**：

```
显示器 16.7ms 一刷 → 每帧留给 JS 才几十毫秒
主线程             布局计算与绘制都耗主线程预算
增量链路           diff → 局部重算布局 → 局部重放指令，把每帧成本压平
```

编号：一帧内所有懒归并、脏区化、切片，本质都是让"单帧成本 ≤ 16.7ms"。

### 6.2 三路实测基准与「1 万点」分水岭

`viz-bench` 是零依赖三路渲染帧率基准，`node bench.cjs` 起服务 + 无头 Chrome 收帧率，钉死决策边界（无头 swiftshader 只测相对趋势）：

```
实测(viz-bench)
  2000 点   三者均流畅
  1 万点    SVG 18.6fps / Canvas 60 / WebGL 44.9
  5 万点    SVG 3.6 / Canvas 23.9 / WebGL 21.2
结论   SVG 分水岭约 1 万点；> 1 万且要流畅动画优先 WebGL
```

这个"约 1 万点"就是 1.4 选型边界的实测依据。

## 7. 大屏与可视化工程

### 7.1 适配与 devicePixelRatio

大屏适配是等比缩放，不是铺满展示：

```
设计稿等比缩放   XY 铺满会把内容拉伸变形；等比缩放则留黑边（权衡取舍）
Canvas  注意 devicePixelRatio：按 1/dpr 设物理宽高、再 ctx.scale(dpr,dpr) 保持清晰
```

物理像素 vs 逻辑像素：高 DPR 屏上如果只按 CSS 尺寸建 canvas，图形会发虚。

### 7.2 时间切片与数据聚合

两项手段应对"数据太大 / 任务太重"：

```
时间切片   任务按帧预算分帧执行 —— 实测 10×3ms 切 2 帧；最小粒度是单任务，任务太大先拆任务
数据聚合   时间桶只留 min/max/count，保住尖峰特征 —— 实测 1 万点降维到 17 个分钟桶（约 500 倍）
```

聚合的意义：不是简单抽稀丢点，而是保留每个桶的极值，让峰值特征不丢失。

### 7.3 Worker、离屏渲染与降级阶梯

资源挪移 + 逐级降级，是超量场景的两条腿：

```
Worker / 离屏   布局计算与绘制都能挪出主线程（OffscreenCanvas）
            但先把主线程的活干干净，再谈搬出去
降级阶梯       视觉(去阴影渐变) → 数据(降采样) → 渲染器(WebGL)，逐级不跳级
            实测 2k→L0 / 4k→L1 / 8k→L2 / 2w→L3（screen-lab）
```

降级为什么"不跳级"：视觉降级用户无感、数据降级可感知、换渲染器是工程成本，跳级会付出无谓代价。

### 7.4 稳定性五件套

7×24 大屏的稳定性，常青五件套：

```
内存泄漏         定时器 / 监听器 / ECharts 实例随路由销毁（最常见线上问题）
断线重连         指数退避 + 全量对齐一次
乱序丢弃         迟到数据按序丢弃，防止读数乱跳
WebGL 上下文丢失  自动降级兜底
fps / 长任务埋点  量化卡顿，验证降级是否生效
```
