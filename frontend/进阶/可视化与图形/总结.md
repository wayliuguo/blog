# 可视化与图形：模块总结

> 本模块 5 篇，回答一个问题：**数据是怎么一步步变成屏幕上的像素，并且在海量数据下依然流畅的。**

## 知识主线

五篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 Canvas 2D 基础与性能（像素怎么画、怎么画得快）
        │  即时模式画好了，但声明式场景和 DOM 交互怎么办？
        ▼
02 SVG 与声明式图形（结构化图形与浏览器托管交互）
        │  两千个图形以上，Canvas/SVG 都到顶了怎么办？
        ▼
03 WebGL 与 Three.js 入门（GPU 并行渲染三维场景）
        │  图形底座都会了，通用图表是怎么把这些组装起来的？
        ▼
04 图表引擎原理（数据 → 布局 → 比例尺 → 图形 → 渲染）★主轴
        │  引擎会用了，真正的大屏项目还要什么工程手段？
        ▼
05 大屏与可视化工程（海量数据、增量更新、Worker、降级）
```

## 分篇知识点

### 01-Canvas 2D 基础与性能

- **心智模型**：Canvas 是位图 + 即时模式——画完就忘、没有场景图，任何变化都要重画；与 SVG 的取舍看规模与交互密度
- **状态机**：设置状态 → 执行指令；`save`/`restore` 必须成对防状态泄漏，样式切换本身是开销
- **渲染成本模型**
  - **显示列表**：把「当前画面由哪些指令构成」记下来（ECharts ZRender 同思路），重绘 = 重放
  - **实测（viz-lab）**：100 根柱子改 1 根，全量重绘执行 100 条指令、增量重绘只执行 1 条
- **帧纪律**：显示器 16.7ms 一刷；一切 `setData` 只标脏，rAF 回调统一重绘——实测一帧 3 次变更只画 1 次
- **性能手法清单**（性价比降序）：离屏 canvas 预渲染 / 分层 canvas / 帧内合并 / 增量重绘（脏矩形）/ 批量同色 path / 坐标取整 / 长任务切片
- **降级**：最大点数 = 帧预算 ÷ 单点成本，实测 0.005ms/点时 1 万点降采样到 3340 点；生产级方案如 ECharts `sampling: 'lttb'`
- **最小实现**
  - **`viz-lab`**：零依赖实验台，`node run.cjs` 六场景 `node:assert` 自检全绿（比例尺 / 布局 / 渲染成本 / 帧合并 / 降级）

### 04-图表引擎原理

- **五层架构**：数据 → 布局 → 比例尺 → 图形生成 → 渲染器；交互层靠 invert 逆映射回数据
- **两种流派**：ECharts 配置驱动（option → 内部 processor 链 → ZRender），D3 数据驱动（selection / join，自由度即库本身）
- **比例尺**
  - **线性**：斜率 k = 像素跨度 / 数据跨度；`clamp` 防异常值画出界
  - **nice 刻度**：步长对齐 1/2/5 × 10ⁿ，实测 `[0,100]→5 格` 得 `[0,20,40,60,80,100]`
  - **分段（类目轴）**：5 类 600px、paddingInner 0.2 → step=125、柱宽 100
- **invert**：hover / 点击拾取必须像素反查数据，tooltip 依赖它
- **布局**
  - **饼图**：值占比 → 弧段角度，弧段首尾相接（浮点留 1e-9 容差）
  - **堆叠**：多系列 y0/y1 区间首尾衔接，堆叠柱 / 面积图的地基
- **最小实现**
  - **`viz-lab` 的 scale.cjs / layout.cjs**：比例尺与布局的最小可运行实现，实测六场景全绿

### 02-SVG 与声明式图形

- **保留模式**：DOM 即场景图——重绘（按节点脏区）/ 命中（事件绑元素）/ 缩放（矢量无损）/ 可访问性全部浏览器托管
- **path 指令串**：M 移动 / L 直线 / Z 闭合 / C 三次贝塞尔（折线变平滑曲线）；`stroke-dasharray` + `stroke-dashoffset` 做描边动画（进度环 / 签名动画原理）
- **数据 join**：D3 的 enter / update / exit 是增量更新的统一骨架——数据变 100→105 条只 append 5 个节点；与虚拟列表、框架 diff 同源
- **viewBox**：逻辑坐标系与屏幕像素解耦，响应式近零成本（Canvas 要手动重设并整幅重画）
- **交互与动画**：事件绑元素、CSS transition 连几何属性（r）也能过渡
- **分工边界**：几百以内 + 重交互选 SVG；几千以上 + 逐帧选 Canvas/WebGL；ECharts `renderer: 'svg'` 可切换

### 03-WebGL 与 Three.js 入门

- **定位**：CPU 画不动的规模（万级图形 / 3D / 特效）才上 WebGL；普通图表大屏别用
- **渲染管线**：顶点着色器（每顶点）→ 光栅化（固定）→ 片元着色器（每像素），两段可编程、GPU 数千核并行——「一次 draw call 画几万三角形」的原因
- **Three.js 三件套**：Scene（装物体与灯）/ Camera（从哪看）/ Renderer（GPU 桥）；网格 = 形状 × 材质；`renderer.render` 每帧把场景图翻译成 draw call（在 WebGL 上重建保留模式）
- **材质**：Basic（不受光）→ Lambert（漫反射）→ Standard（PBR 主流）→ Physical（透射/清漆）；环境光 + 方向光是质感最低配
- **着色器**：GLSL 是一次算一个顶点/像素的纯函数，时间变化走 uniform；没有共享全局状态的思维
- **矩阵**：模型 → 视图 → 投影；改物体属性永远优于手动算顶点；裁剪面范围太宽会 z-fighting

### 05-大屏与可视化工程

- **适配**：设计稿等比缩放（XY 铺满会拉伸 / 等比留黑边），Canvas 注意 `devicePixelRatio`
- **渲染预算**：一切优化收敛到 16.7ms；增量链路 = diff → 局部重算布局 → 局部重放指令
- **降级阶梯**：视觉（去阴影渐变）→ 数据（降采样）→ 渲染器（WebGL），逐级不跳级——实测 2k→L0 / 4k→L1 / 8k→L2 / 2w→L3（screen-lab）
- **时间切片**：任务按帧预算分帧，实测 10×3ms 切 2 帧；最小粒度是单任务，任务太大先拆任务
- **数据聚合**：时间桶只留 min/max/count，保住尖峰特征——实测 1 万点降维到 17 个分钟桶（500 倍）
- **Worker / 离屏**：布局计算与绘制都能挪出主线程（OffscreenCanvas），但先把主线程的活干干净
- **稳定性五件套**：内存泄漏 / 断线重连（指数退避）/ 乱序丢弃 / WebGL 上下文丢失降级 / fps 长任务埋点
