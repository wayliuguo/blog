# 可视化与图形：模块总结

> 本模块 5 篇，回答一个问题：**数据是怎么一步步变成屏幕上的像素，并且在海量数据下依然流畅的。**

## 知识主线

五篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 Canvas 2D 基础与性能（像素怎么画、怎么画得快）
        │  即时模式画好了，但声明式场景和 DOM 交互怎么办？
        ▼
02 SVG 与声明式图形（结构化图形与浏览器托管交互）
        │  两千个图形以上，Canvas/SVG 都到顶了怎么办？
        ▼
03 WebGL 与 Three.js 入门（GPU 并行渲染三维场景）
        │  图形底座都会了，通用图表是怎么把这些组装起来的？
        ▼
04 图表引擎原理（数据 → 布局 → 比例尺 → 图形 → 渲染）★主轴
        │  引擎会用了，真正的大屏项目还要什么工程手段？
        ▼
05 大屏与可视化工程（海量数据、增量更新、Worker、降级）
```

## 分篇知识点

### 01-Canvas 2D 基础与性能

- **心智模型**：Canvas 是位图 + 即时模式——画完就忘、没有场景图，任何变化都要重画；与 SVG 的取舍看规模与交互密度
- **状态机**：设置状态 → 执行指令；`save`/`restore` 必须成对防状态泄漏，样式切换本身是开销
- **渲染成本模型**
  - **显示列表**：把「当前画面由哪些指令构成」记下来（ECharts ZRender 同思路），重绘 = 重放
  - **实测（viz-lab）**：100 根柱子改 1 根，全量重绘执行 100 条指令、增量重绘只执行 1 条
- **帧纪律**：显示器 16.7ms 一刷；一切 `setData` 只标脏，rAF 回调统一重绘——实测一帧 3 次变更只画 1 次
- **性能手法清单**（性价比降序）：离屏 canvas 预渲染 / 分层 canvas / 帧内合并 / 增量重绘（脏矩形）/ 批量同色 path / 坐标取整 / 长任务切片
- **降级**：最大点数 = 帧预算 ÷ 单点成本，实测 0.005ms/点时 1 万点降采样到 3340 点；生产级方案如 ECharts `sampling: 'lttb'`
- **最小实现**
  - **`viz-lab`**：零依赖实验台，`node run.cjs` 六场景 `node:assert` 自检全绿（比例尺 / 布局 / 渲染成本 / 帧合并 / 降级）

### 04-图表引擎原理

- **五层架构**：数据 → 布局 → 比例尺 → 图形生成 → 渲染器；交互层靠 invert 逆映射回数据
- **两种流派**：ECharts 配置驱动（option → 内部 processor 链 → ZRender），D3 数据驱动（selection / join，自由度即库本身）
- **比例尺**
  - **线性**：斜率 k = 像素跨度 / 数据跨度；`clamp` 防异常值画出界
  - **nice 刻度**：步长对齐 1/2/5 × 10ⁿ，实测 `[0,100]→5 格` 得 `[0,20,40,60,80,100]`
  - **分段（类目轴）**：5 类 600px、paddingInner 0.2 → step=125、柱宽 100
- **invert**：hover / 点击拾取必须像素反查数据，tooltip 依赖它
- **布局**
  - **饼图**：值占比 → 弧段角度，弧段首尾相接（浮点留 1e-9 容差）
  - **堆叠**：多系列 y0/y1 区间首尾衔接，堆叠柱 / 面积图的地基
- **最小实现**
  - **`viz-lab` 的 scale.cjs / layout.cjs**：比例尺与布局的最小可运行实现，实测六场景全绿
