## 知识主线（一句话）

本模块回答"**数据是怎么一步步变成屏幕上流畅的像素**"：01 Canvas 与 02 SVG 是即时/保留两条底层路线（怎么画、怎么画得快）；03 WebGL 与 Three.js 用 GPU 并行处理 CPU 画不动的规模；04 图表引擎把数据→布局→比例尺→图形→渲染组装成通用图表；05 大屏工程在超大数据量下用降级与增量保证流畅。

## 高频核心点

### 01 Canvas 2D 基础与性能

- **心智模型**：Canvas 是位图 + 即时模式——画完就忘、没有场景图，任何变化都重画；与 SVG 取舍看规模与交互密度
- **状态机**：`save`/`restore` 必须成对防状态泄漏；样式切换本身是开销
- **显示列表**：记录"画面由哪些指令构成"（ECharts ZRender 同思路），重绘 = 重放；实测改 1 根柱子全量 100 条指令、增量 1 条
- **帧纪律**：显示器 16.7ms 一刷；一切 `setData` 只标脏、rAF 统一重绘（一帧 3 次变更只画 1 次）
- **性能手法（性价比降序）**：离屏 canvas 预渲染 / 分层 canvas / 帧内合并 / 增量重绘（脏矩形）/ 批量同色 path / 坐标取整 / 长任务切片
- **降级**：最大点数 = 帧预算 ÷ 单点成本；生产级用 ECharts `sampling: 'lttb'`
- **分水岭**：**SVG 约 1 万点**（实测 2000 点三者都流畅；1 万点 SVG 跌至 18.6fps、Canvas 仍 60；5 万点 SVG 仅 3.6）；>1 万且要流畅动画优先 WebGL

### 02 SVG 与声明式图形

- **保留模式**：DOM 即场景图——重绘（按节点脏区）/命中（事件绑元素）/缩放（矢量无损）/可访问性全部浏览器托管
- **path 指令串**：M 移动 / L 直线 / Z 闭合 / C 三次贝塞尔；`stroke-dasharray` + `stroke-dashoffset` 做描边动画（进度环、签名动画原理）
- **数据 join**：D3 的 enter / update / exit 是增量更新统一骨架（数据变 100→105 条只 append 5 节点）——与虚拟列表、框架 diff 同源
- **viewBox**：逻辑坐标系与屏幕像素解耦、响应式近零成本（Canvas 要手动重设并整幅重画）
- **分工边界**：几百以内 + 重交互选 SVG；几千以上 + 逐帧选 Canvas/WebGL

### 03 WebGL 与 Three.js 入门

- **定位**：CPU 画不动的规模（万级图形/3D/特效）才上 WebGL；普通图表大屏别用
- **渲染管线**：顶点着色器（每顶点）→ 光栅化（固定）→ 片元着色器（每像素）；两段可编程、GPU 数千核并行——**一次 draw call 画几万三角形**的原因
- **Three.js 三件套**：Scene / Camera / Renderer；网格 = 形状 × 材质；`renderer.render` 每帧把场景图翻译成 draw call
- **材质**：Basic（不受光）→ Lambert（漫反射）→ Standard（PBR 主流）→ Physical（透射/清漆）；环境光 + 方向光是质感最低配
- **着色器**：GLSL 是一次算一个顶点/像素的纯函数、时间变化走 uniform；没有共享全局状态的思维
- **矩阵**：模型 → 视图 → 投影；改物体属性永远优于手动算顶点；裁剪面范围太宽 z-fighting

### 04 图表引擎原理（★主轴）

- **五层架构**：数据 → 布局 → 比例尺 → 图形生成 → 渲染器；交互层靠 `invert` 逆映射回数据
- **两种流派**：ECharts 配置驱动（option → processor 链 → ZRender）；D3 数据驱动（selection / join，自由度即库本身）
- **比例尺**：线性斜率 k = 像素跨度/数据跨度、`clamp` 防异常值出界；nice 刻度步长对齐 1/2/5 × 10ⁿ；类目（分段）轴 step 内扣 padding 得柱宽
- **invert**：hover / 点击拾取必须像素反查数据（tooltip 依赖它）——交互能力建立在比例尺抽象上而非画图上
- **布局**：饼图值占比→弧段角度、首尾相接（浮点留 1e-9 容差）；堆叠多系列 y0/y1 首尾衔接、`series.stack` 同名才堆
- **布局与渲染分离是关键**：同一份布局可驱动任一渲染器、才能做"只重算布局不重放全部指令"的增量更新

### 05 大屏与可视化工程

- **适配**：设计稿等比缩放（XY 铺满会拉伸 / 等比留黑边）；Canvas 注意 `devicePixelRatio`
- **渲染预算**：一切优化收敛到 16.7ms；增量链路 = diff → 局部重算布局 → 局部重放指令
- **降级阶梯**：视觉（去阴影渐变）→ 数据（降采样）→ 渲染器（WebGL），逐级不跳级（实测 2k→L0 / 4k→L1 / 8k→L2 / 2w→L3）
- **时间切片**：任务按帧预算分帧、最小粒度是单任务、任务太大先拆任务
- **数据聚合**：时间桶只留 min/max/count 保住尖峰特征（实测 1 万点降维到 17 桶、500 倍）
- **Worker / 离屏**：布局与绘制都能挪出主线程（OffscreenCanvas），但先把主线程的活干干净
- **稳定性五件套**：内存泄漏 / 断线重连（指数退避）/ 乱序丢弃 / WebGL 上下文丢失降级 / fps 长任务埋点
