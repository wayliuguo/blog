# 可视化与图形：面试题

> 格式：结论 → 原理 → 边界/坑 → 追问。标注「见第 X 篇」的题目按阅读顺序出题。

### Q1: Canvas 和 SVG 怎么选？（第 1 篇）

- **结论**：看两个变量——图形数量与交互密度。上千图形、逐帧动画、图像处理选 Canvas；几百以内、需要 DOM 事件与可缩放选 SVG。
- **原理**：Canvas 是即时模式，画完就忘、没有对象，任何变化整幅重画，交互要自己算几何命中；SVG 是保留模式，每个图形是 DOM 节点，浏览器托管重绘与事件，但节点多了 DOM 开销失控。
- **边界**：两者不是互斥的——ECharts 默认 Canvas 但支持切 SVG 渲染器；高端大屏常用「静态层 SVG/离屏 Canvas + 动态层 Canvas」混合。
- **追问**：为什么 Canvas 没有场景图？→ 即时模式 API 只是一支画笔，画布上只有像素；所以要自己建显示列表记录「画面由哪些指令构成」，重绘即重放（viz-lab 实测：改 1 根柱子全量 100 条指令、增量 1 条）。

### Q2: Canvas 高频更新怎么保证不卡？（第 1 篇）

- **结论**：三件套——帧内合并、增量重绘、降采样。
- **原理**：一切数据变更只标脏不画，合并到 `requestAnimationFrame` 里一帧一画（实测一帧 3 次 setData 只重绘 1 次）；重绘用脏矩形只画受影响区域；数据量超帧预算（16.7ms ÷ 单点成本）就降采样。
- **边界**：增量重绘要求显示列表可 diff，复杂图形（路径交叉、透明叠加）的脏区域计算成本会上升，得不偿失时退回全量；降采样丢点要在 tooltip 与图例里对用户诚实。
- **追问**：离屏 canvas 解决什么？→ 把不变的部分（网格、背景）画一次存成位图，之后每帧一次 `drawImage` 贴上，把「重画背景」的成本变成一次位图拷贝。

### Q3: ECharts 和 D3 的本质区别？（第 4 篇）

- **结论**：ECharts 是配置驱动的图表库，D3 是数据驱动的可视化原语库。
- **原理**：ECharts 内部完成「数据 → processor 链 → 布局 → ZRender 渲染 → 事件」全链路，用户只写 option；D3 只提供 selection / join / scale / shape 等模块，五层架构里每一层都由你显式组装。
- **边界**：ECharts 定制受 option 边界限制（可用 registerLayout / registerView 扩展）；D3 学习曲线在概念多，产出依赖开发者对图形学的理解；报表类需求选 ECharts 几乎总是对的，非标准信息图只有 D3 顺手。
- **追问**：tooltip 是怎么知道该显示哪条数据的？→ 拾取得到像素坐标后，用比例尺的 `invert` 逆映射回数据域——所以交互能力建立在比例尺抽象上，而不是画图上。

### Q4: 比例尺是什么，为什么图表引擎离不开它？（第 4 篇）

- **结论**：比例尺是「数据域 → 像素域」的映射函数，是连接数据与图形的唯一桥。
- **原理**：线性比例尺算斜率 k = 像素跨度 / 数据跨度，`v = r0 + (x - d0) × k`；类目轴用分段比例尺，step 内扣 padding 得柱宽；刻度线步长对齐 1/2/5 × 10ⁿ（nice 算法），实测 `[0,100]` 5 格得到 `[0,20,40,...,100]`。
- **边界**：数据含异常值时开 clamp 防止出界；对数轴、序数轴、时间轴是同一抽象的不同实现；invert 逆映射是 hover/点击拾取的前提。
- **追问**：5 个类目放 600px、留 20% 间隙，柱宽多少？→ step = 600 / (5 - 0.2) = 125，柱宽 = 125 × 0.8 = 100（viz-lab 实测）。

### Q5: 饼图和堆叠图的布局在算什么？（第 4 篇）

- **结论**：布局层把「值」翻译成「几何」——饼图算弧段角度，堆叠图算 y0/y1 区间。
- **原理**：饼图布局按值占比切总角度：`angle = (v / total) × span`，逐段累加起止角，弧段天然首尾相接（浮点累加需留 1e-9 容差）；堆叠布局逐系列累加，上一段的 y1 就是下一段的 y0。
- **边界**：布局是纯函数，输入不变输出不变——这是图表可以做增量更新与动画插值的前提；堆叠顺序决定读数语义（总量 vs 各自趋势），`series.stack` 同名才堆。
- **追问**：为什么说布局与渲染分离是图表引擎的关键设计？→ 布局结果与渲染目标解耦后，同一份布局可以驱动 Canvas/SVG/WebGL 任一渲染器，也才能做「只重算布局、不重放全部指令」的增量更新。

### Q6: 大屏项目的数据量超预算了怎么降级？（第 1、5 篇）

- **结论**：先量化再降级——最大点数 = 帧预算 ÷ 单点绘制成本，超限按策略丢数据，而不是让页面卡着。
- **原理**：60fps 下帧预算 16.7ms；实测单点成本 0.005ms 时上限约 3340 点，1 万点必须降采样。生产策略：趋势图用 LTTB 抽稀保形状、监控折线按窗口聚合、超出 Canvas 能力上移 WebGL。
- **边界**：降级要分层——先降视觉（去阴影/渐变），再降数据（采样），最后降渲染器（Canvas → WebGL → 服务端出图）；任何降采样都要在产品层可见，避免用户误读数据。
- **追问**：怎么验证降级生效了？→ 帧率埋点对比降级前后的长任务与 fps 分布；viz-lab 的 `planSample` 是决策模型，工程里还要加「实测单点成本」的校准环节。
