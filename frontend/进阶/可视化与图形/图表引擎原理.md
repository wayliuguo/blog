# 图表引擎原理

> 统一业务场景：实时交易监控大屏（见[全景](./全景.md)）。本篇是板块的原理核心：五层管线 + 手写比例尺/布局（最小实现），实战层看 screen-board 的 option 如何映射到五层。

## 一、入门：图表引擎到底在解决什么

拿到 ECharts 一个 option 就能出图——中间发生了什么？图表引擎把「数据变像素」拆成五层，每层只做一件事：

> 示意片段（无配套脚本）

```
数据（业务值）
  → 布局（值 → 几何：角度、堆叠区间、树图矩形）
  → 比例尺（数据域 → 像素域）
  → 图形生成（几何 → 绘制指令：path / rect / arc）
  → 渲染器（Canvas / SVG / WebGL 三选一执行）
  → 交互层（拾取 → invert 逆映射回数据 → 更新 → 重渲染）
```

理解这张图的钥匙：**布局与比例尺是渲染器无关的纯函数**。同一份布局结果可以驱动 Canvas、SVG 或 WebGL——这就是 ECharts 切渲染器不用改 option、也能做增量更新的架构前提。本篇的二、三、四节会把前四层里最核心的比例尺与布局**手写出来**。

**两种流派**的分歧就在这些层的组织方式上：

| | ECharts（配置驱动） | D3（数据驱动） |
| --- | --- | --- |
| 抽象层级 | 高：option 一把梭，内部帮你做完五层 | 低：五层拆成模块，你自由组装 |
| 学习曲线 | 陡峭在 option 的海量配置项 | 陡峭在概念多（selection / join / scale） |
| 定制能力 | 受限于图表类型与 option 边界 | 几乎无限：它只是「数据到 DOM/SVG 的映射库」 |
| 典型场景 | 后台报表、大屏、通用图表 | 定制可视化、信息图、非标准图形 |

## 二、核心机制：比例尺

比例尺是整个体系里最重要的一个抽象：**把数据域（domain）线性映射到像素域（range）**。轴、柱高、点的坐标，全部出自它。

> 摘自 `./code/viz-lab/scale.cjs`

```js
// 线性比例尺：把数据域 [d0,d1] 映射到像素域 [r0,r1]
function scaleLinear(domain, range, { clamp = false } = {}) {
  const [d0, d1] = domain
  const [r0, r1] = range
  const k = (r1 - r0) / (d1 - d0) // 斜率：像素 / 数据单位
  function scale(x) {
    let v = r0 + (x - d0) * k
    if (clamp) v = Math.min(r1, Math.max(r0, v))
    return v
  }
```

`clamp` 决定超域数据是画出界还是钳到边界——异常值多时开 clamp 可以防止一张图被一根尖刺撑爆。

刻度线不是随便等分出来的，D3 会把步长对齐到「好看的数」（1/2/5 × 10ⁿ）：

> 摘自 `./code/viz-lab/scale.cjs`

```js
// nice 刻度：先按目标刻度数估步长，再对齐到 1/2/5 × 10^n
function niceTicks(d0, d1, count) {
  const step0 = (d1 - d0) / count
  const mag = Math.pow(10, Math.floor(Math.log10(step0)))
  let step = 10 * mag
  for (const m of [1, 2, 5, 10]) {
    if (m * mag >= step0) { step = m * mag break } // 取最小的「好看步长」
  }
```

类目轴（横轴放「北京 / 上海 / 广州」这种）用分段比例尺：每类占一格，格内留 padding，柱宽从格里扣除间隙得到：

> 摘自 `./code/viz-lab/scale.cjs`

```js
// 分段比例尺：类目轴。每类占一格 step，格内留 padding，柱宽 = step × (1 - paddingInner)
function scaleBand(domain, range, { paddingInner = 0, paddingOuter = 0 } = {}) {
  const [r0, r1] = range
  const n = domain.length
  const step = (r1 - r0) / Math.max(1, n - paddingInner + paddingOuter * 2)
  const start = r0 + step * paddingOuter
  const scale = x => start + domain.indexOf(x) * step
  scale.step = step
  scale.bandwidth = step * (1 - paddingInner)
  return scale
}
```

实测：5 个类目放进 600px、格内留 20% 间隙，得到 step=125、柱宽 100——每个柱子之间正好 25px 的空隙（`node run.cjs` 场景二）。

### 2.1 invert：交互的逆映射

比例尺只负责「数据 → 像素」，但交互（hover 提示、点击选中）需要反着走：**鼠标在像素 300，对应数据值是多少？** 所以每个比例尺都配一个 `invert`：

> 摘自 `./code/viz-lab/scale.cjs`

```js
  // invert：像素坐标反查数据值，图表 hover / 点击定位全靠它
  scale.invert = y => (y - r0) / k + d0
```

没有 invert，tooltip 就不知道该显示哪条数据——这就是为什么「拾取交互」离不开比例尺，而不只是画图的事。

## 三、核心机制：布局

布局层回答「这个值该变成多大的弧、多高的矩形」。看两个最常用的：

**饼图布局**把值数组变成弧段，每段只记起止角：

> 摘自 `./code/viz-lab/layout.cjs`

```js
// 饼图布局：值数组 → 弧段（startAngle/endAngle，单位弧度）
function pie(values, { startAngle = 0, endAngle = Math.PI * 2 } = {}) {
  const total = values.reduce((s, v) => s + v, 0)
  const span = endAngle - startAngle
  let a = startAngle
  return values.map(v => {
    const angle = (v / total) * span // 值占比 → 角度占比
    const arc = { value: v, startAngle: a, endAngle: a + angle }
    a += angle
    return arc
  })
}
```

**堆叠布局**把多系列数据变成 y0/y1 区间——每段的底端踩在上一段顶端，这就是堆叠柱状图和面积图的全部秘密：

> 摘自 `./code/viz-lab/layout.cjs`

```js
// 堆叠布局：多系列数据 → 每条数据的 y0/y1 区间（堆叠柱状图 / 面积图的地基）
function stack(rows, keys) {
  return rows.map(row => {
    let y0 = 0
    const parts = {}
    for (const k of keys) {
      parts[k] = { y0, y1: y0 + row[k] }
      y0 = parts[k].y1 // 上一段的顶端就是下一段的底端
    }
    return { label: row.label, ...parts }
  })
}
```

ECharts 的 `series.stack: 'total'`、D3 的 `d3.stack()`，本质都是这段逻辑（加上排序、offset 等变体）。

实测（`node run.cjs` 场景一/三）：线性比例尺 50→150、invert(300)→100、clamp 生效；饼图弧段首尾相接时留 1e-9 浮点容差——这也是图表引擎处理角度累加的常见手法；堆叠布局 b 系列的 y0 正好踩在 a 系列的 y1 上。

## 四、实战：一份 option 的五层映射

`screen-board` 的渠道柱状图 option，逐字段对回五层：

> 摘自 `./code/screen-board/src/App.vue`

```js
  state.channelOption = {
    ...axisStyle(),
    xAxis: { type: 'category', data: data.channels.map(c => c.name), axisLabel: { color: '#9cc3e8' } },
    yAxis: { type: 'value', splitLine: { lineStyle: { color: 'rgba(44,90,143,0.4)' } } },
    series: [
      {
        type: 'bar',
        data: data.channels.map(c => c.value),
        barWidth: 26,
        itemStyle: { color: '#3f9f7f' },
      },
    ],
  }
```

| option 字段 | 五层中的位置 | 引擎里谁做 |
| --- | --- | --- |
| `series.data`（业务值） | 数据层 | 你提供 |
| `xAxis/yAxis` 的 domain 与 range | 比例尺层 | 引擎按 data 自动求极值建 scale |
| `type: 'bar'` + `barWidth` | 布局 + 图形生成层 | Chart view 组件算出每根柱的矩形 |
| 渲染器（默认 Canvas） | 渲染层 | ZRender 重放绘制指令 |
| tooltip（系列里未展开） | 交互层 | 拾取像素 → invert 回数据域 |

QPS 折线则多走了一步**降维**：60 个秒级原始点先经时间桶聚合（见《大屏与可视化工程》）再进 option——数据层进引擎之前就减负，这同样是「层与层解耦」的红利：上游换数据来源，下游 option 结构不变。

## 五、ECharts 与 D3 的架构差异

同样是画一张柱状图，两个库的内部路径完全不同：

| 环节 | ECharts | D3 |
| --- | --- | --- |
| 输入 | option 对象（series/data/axis） | 原始数组 |
| 布局 | 内部 processor 链（stack / sampling / dataFilter） | `d3.stack()` 等显式调用 |
| 图形 | 内部 Chart view 组件生成，画到 ZRender（自研 Canvas/SVG 渲染器） | 你用 selection 把数据 join 到 SVG/Canvas 元素 |
| 更新 | diff option → 增量更新 + 动画 | 数据 join（enter/update/exit）→ transition |
| 扩展 | 自定义 series（registerLayout / registerView） | 自由度即库本身 |

> 提示：面试中「ECharts 怎么画一张图的」能答出「option → 处理器链 → 布局 → ZRender 渲染 → 事件层」，就已经超过绝大多数背配置项的候选人。
