# 可视化与图形全景

> 本板块统一业务场景：**实时交易监控大屏**（QPS 折线 / 渠道柱状 / 终端占比 / 实时告警，配套真实工程 `code/screen-board/`）。每个技术选型的「实战」层都绑这个场景，而不是各画各的 demo。

## 一、三渲染器对比表：一切选型从这里开始

浏览器里画图只有三种底层方式，选型先看这张表，再看篇目：

| | Canvas 2D | SVG | WebGL |
| --- | --- | --- | --- |
| 渲染模式 | 即时模式（画笔指令） | 保留模式（DOM 场景图） | 即时模式（GPU 管线） |
| 执行者 | CPU | 浏览器排版引擎 | GPU 并行 |
| 一次重画 | 整幅重放指令 | 浏览器只更新受影响节点 | 重放 draw call（几万点一次） |
| 交互拾取 | 自己算几何（isPointInPath / invert） | 事件直接绑元素 | 射线拾取或 GPU ID |
| 缩放 | 位图重采样（会糊） | 矢量无损 | 需重渲染（3D 天然实时） |
| 数量上限（实测） | ~1 万点 60fps | ~2 千点舒适，1 万点掉到 18.6fps | 5 万点仍有 21fps（软件渲染） |
| 典型场景 | 图表、大屏、图像处理 | 报表、图例、可交互图、进度环 | 海量点位、3D、粒子特效 |

> 提示：三者不是互斥选型。ECharts 一套引擎可以切 Canvas/SVG 渲染器；高端大屏常混用——图表主体 Canvas、图例告警用 DOM/SVG（见《大屏与可视化工程》实战工程的 `AlertList`）。

## 二、数据 → 像素的五层管线

不管用哪个渲染器，「数据变像素」都要经过同样的五层——这是图表引擎的通用架构，也是本板块的原理主线：

```
数据（业务值）
  → 布局（值 → 几何：角度、堆叠区间）
  → 比例尺（数据域 → 像素域）
  → 图形生成（几何 → 绘制指令：path / rect / arc）
  → 渲染器（Canvas / SVG / WebGL 三选一执行）
  → 交互层（拾取 → invert 逆映射回数据 → 更新 → 重渲染）
```

- 布局与比例尺是**渲染器无关**的纯函数——同一份布局可以驱动三种渲染器，这是「ECharts 切渲染器不用改 option」的原因；
- 交互能力建立在 `invert` 逆映射上，而不是画图上；
- 五层的完整手写实现（比例尺 / 饼图 / 堆叠 / 增量重绘 / data join）就是本板块的最小实现群，见各篇。

## 四、与相邻板块的关系

- **性能优化**：帧预算（16.7ms）、长任务、rAF 纪律同源——可视化是「渲染性能」知识最密集的落点；
- **微前端 / 渲染架构**：大屏作为子应用被微前端集成时，Canvas 位图不受样式隔离影响，但等比缩放与宿主布局会叠加；
- **监控与稳定性**：大屏 7×24 的 fps/长任务埋点直接复用监控板块的采集链路。
