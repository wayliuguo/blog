# 研发平台与效能工程：模块总结

> 本模块 3 篇，回答一个问题：**「平台怎么建」——从构建平台到实验平台到效能度量。**

## 知识主线

```
01 构建平台与产物治理（缓存键 / 增量依赖图 / 产物溯源）
        │  构建好了，改动到底有没有效果？
        ▼
02 实验与增长平台（分桶与正交 / SRM / 显著性）
        │  实验能验证单个改动，那整体交付效率怎么看？
        ▼
03 研发效能度量（DORA 四指标 / 周期分解 / 反模式）
```

与「交付与质量」模块的边界：那篇讲**流水线怎么用**，本模块讲**平台怎么建**——前者是使用方视角，后者是建设方视角。

三篇的共同方法是同一条：**先把口径定清楚，再谈数值**。缓存键决定命中率、分桶决定可比性、指标定义决定团队会往哪走——这三件事做错了，后面所有数据都漂亮但不可用。

## 分篇知识点

### 01-构建平台与产物治理

- **缓存键必须由内容决定**：源码 hash + 依赖版本 + 构建参数 + 工具链版本；**mtime 是纯噪声**
- **实测**：内容一字未改只改 mtime，hash 缓存 0 重建 vs mtime 缓存 3 个全重建（CI 每次全新 checkout 就是这个效果）
- **最隐蔽的漏项**：工具链版本不入键——升级 Node/打包器后缓存仍命中，产出的却是旧工具链产物
- **增量构建实测**：依赖图 a→b/c→d，改叶子 d.js 只重建 1 个、改 c.js 重建 2 个（不含不相关的 b）、改底层 a.js 全脏 4 个
- **两个实现细节**：`dirty` 用 Set 防重复入队（菱形依赖）；反向图要持久化而非每次重算
- **产物溯源实测**：`app.8f3c.js:150` → `src/cart.js:31`；越界与查不到 bundle 都返回 `null`
- **manifest 与 sourcemap 分工**：manifest 管版本与粗定位，sourcemap（VLQ）管行列级映射
- **三条守线**：sourcemap 不随产物公开、版本按 hash 一一对应、构建可复现
- **平台化边界**：远程缓存 / 产物治理 / 依赖图值得平台化；**别把项目构建脚本翻译成平台 DSL**，否则本地与 CI 分叉

### 02-实验与增长平台

- **分桶**：`hash(userId + ':' + salt) % n`，可重算、不能用随机数；盐里要带实验名
- **实测**：同一用户 100 次稳定同桶；1 万用户落实验组 49.87%（偏差 < 2%）
- **实验单位由 ID 决定**：设备 ID 分桶是按设备、账号 ID 分桶才是按人——选错是隐性且致命的
- **正交分层实测**：UI 层与排序层不同盐，四格命中组合各约 25%，最大偏差 0.53%
- **层间交互仍要查**：核心指标在「只中 A / 只中 B / 都中」三群分别看
- **SRM 实测**：4980/5020 卡方 0.16（< 3.84 通过）、5200/4800 卡方 16.00（> 3.84 判失衡，结论作废）
- **SRM 成因排序**：埋点丢失 > 分流时机不一致 > 跳转丢参 > 机器人流量；必须做成平台自动巡检
- **显著性实测**：同样 8% 提升（5.0%→5.4%），n=2 万时 z=1.80 不显著、n=5 万时 z=2.85 才显著——**样本量决定结论**
- **三条纪律**：实验前算样本量、禁止中途偷看（peeking）、统计显著 ≠ 值得上线

### 03-研发效能度量

- **DORA 四指标**：部署频率、变更前置时间、变更失败率、MTTR
- **实测一例**：2 次/天（high）· 前置 20h（elite）· 失败率 8.3%（high，离 elite ≤5% 差一档）· MTTR 1h（elite）
- **口径三条**：用中位数不用平均值；四个指标必须一起看（单指标会被用质量换速度做坏）；跟自己历史比优于跨行业比
- **周期分解实测**：72h 里编码 4h（6%）、等待 62h（86%）——瓶颈在评审排队与发布窗口，不在编码速度
- **推论**：编码只占 6% 时，把编码效率翻倍的端到端收益仅约 3%
- **反模式一**：LOC 考核把「LOC 300→120、前置 48h→12h、故障 3→0」的优秀重构判成产出下降 60%
- **反模式二**：按部署次数考核个人，同样的 200 行改动拆成 10 个 PR 后指标翻 5 倍
- **三条原则**：度量团队不度量个人、多指标交叉验证、度量只用于找瓶颈不用于排名
- **难采集但重要**：满意度、认知负荷、文档质量——靠定期问卷，不靠事件流

## 最小实现

- **`platform-lab`**：零依赖探针实验台，`node run.cjs` 依次执行三探针（缓存键/增量依赖图/产物溯源 · 分桶/正交分层/SRM/显著性 · DORA 四指标/周期分解/反模式），`node:assert` 自检全绿
