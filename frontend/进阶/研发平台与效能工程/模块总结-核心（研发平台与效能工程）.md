## 知识主线（一句话）

本模块回答「平台怎么建」——从构建平台（缓存键、增量依赖图、产物溯源）到实验平台（分桶与正交、SRM、显著性）再到效能度量（DORA 四指标、周期分解、反模式）。三篇的共同方法是同一条：**先把口径定清楚，再谈数值**——缓存键决定命中率、分桶决定可比性、指标定义决定团队会往哪走。

## 高频核心点

### 01 构建平台与产物治理

- **缓存键必须由内容决定**：源码 hash + 依赖版本 + 构建参数 + 工具链版本；**mtime 是纯噪声**
- **最隐蔽的漏项**：工具链版本不入键——升级 Node/打包器后缓存仍命中，产出的却是旧工具链产物
- 增量构建实测：依赖图 a→b/c→d，改叶子 d 只重建 1 个、改 c 重建 2 个、改底层 a 全脏 4 个
- 两个实现细节：`dirty` 用 Set 防重复入队（菱形依赖）；反向图要持久化而非每次重算
- 产物溯源实测：`app.8f3c.js:150` → `src/cart.js:31`；越界与查不到都返回 `null`
- **manifest 与 sourcemap 分工**：manifest 管版本与粗定位，sourcemap（VLQ）管行列级映射
- 三条守线：sourcemap 不随产物公开、版本按 hash 一一对应、构建可复现
- 平台化边界：远程缓存 / 产物治理 / 依赖图值得平台化；**别把项目构建脚本翻译成平台 DSL**

### 02 实验与增长平台

- **分桶**：`hash(userId + ':' + salt) % n`，可重算、不能用随机数；盐里要带实验名
- **实验单位由 ID 决定**：设备 ID 分桶是按设备、账号 ID 分桶才是按人——选错是隐性且致命的
- 正交分层实测：UI 层与排序层不同盐，四格命中组合各约 25%，最大偏差 0.53%
- 层间交互仍要查：核心指标在「只中 A / 只中 B / 都中」三群分别看
- **SRM 实测**：4980/5020 卡方 0.16 通过、5200/4800 卡方 16.00 判失衡、结论作废
- SRM 成因排序：埋点丢失 > 分流时机不一致 > 跳转丢参 > 机器人流量；必须做成平台自动巡检
- 显著性实测：同样 8% 提升，n=2 万 z=1.80 不显著、n=5 万 z=2.85 才显著——**样本量决定结论**
- 三条纪律：实验前算样本量、禁止中途偷看（peeking）、统计显著 ≠ 值得上线

### 03 研发效能度量

- **DORA 四指标**：部署频率、变更前置时间、变更失败率、MTTR
- 口径三条：用中位数不用平均值；四个指标必须一起看；跟自己历史比优于跨行业比
- 周期分解实测：72h 里编码 4h（6%）、等待 62h（86%）——瓶颈在评审排队与发布窗口，不在编码速度
- 推论：编码只占 6% 时，把编码效率翻倍的端到端收益仅约 3%
- **反模式一（LOC）**：优秀重构 LOC 300→120 却被判成产出下降；**反模式二（部署次数）**：200 行改动拆 10 个 PR 后指标翻 5 倍——古德哈特定律
- 三条原则：度量团队不度量个人、多指标交叉验证、度量只用于找瓶颈不用于排名
- **读趋势看信噪比 / 反模式三·窗口裁剪**：同一批变更窗口口径一变就跨过 elite 门槛——窗口与口径必须固定
- 难采集但重要：满意度、认知负荷、文档质量——靠定期问卷，不靠事件流
