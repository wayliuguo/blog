# 模块总结 · 前端框架原理

## 知识主线

两篇不是并列的两堆 API 知识，而是围绕同一个问题展开的两条实现路径——**"状态/数据变了，框架如何以最小代价把界面更新到最新"**。每一篇都在回答上一篇留下的问题：

```
01 React 高级与原理（组件状态一变，React 怎么知道改哪里）
        │  先建立基线：渲染 = render/commit 两阶段
        │  → 虚拟 DOM + diff 三条启发式求最小变更
        │  → Fiber 链表把大更新拆成可中断小单元
        │  → Hooks 链表按调用顺序在 Fiber 上存状态
        ▼
02 Vue3 原理（同一个问题，另一条工程路径）
        │  编译：模板 → render 函数 + 静态标记（能提前确定的就不进 diff）
        │  → 响应式：Proxy 代理 + track/trigger（数据一变知道通知谁）
        │  → 运行时：createRenderer + patch 按差异落地（scheduler 批量更新）
        ▼
共同收口：状态变化 → 以最小代价把界面更新到最新
```

本模块的主轴是**"状态到界面的最小代价映射"**：01 篇以 React 为样本建立"渲染分两阶段 + 虚拟 DOM/diff + 链表（Fiber、Hooks）"这条基线，02 篇在同一个问题域里看 Vue3 的另一种实现——用编译期静态标记省掉不必要的 diff，用 Proxy 响应式把更新精确到"哪个数据变了、通知谁"，再交给运行时 patch 落地。两篇对照，React"运行时 diff + 可中断调度"与 Vue3"编译优化 + 精确响应式"的取舍与分工就清楚了。

## 分篇知识点

### 01-React 高级与原理

- **render / commit 两阶段**
  - **Render 阶段**：纯计算、可中断，只构建新虚拟 DOM / Fiber 并算 diff（差异），不碰真实 DOM，不允许副作用
  - **Commit 阶段**：不可中断，一次性把变更应用到真实 DOM 并执行副作用（`useEffect` / `useLayoutEffect` / 生命周期 / ref 赋值）——"纯函数在前、命令式在后"
  - **并发基础**：render 可被高优先级操作（输入、点击）抢占插队，commit 一旦开始不能半途而废，否则页面闪现中间态
- **Fiber 链表与双缓存**
  - **Fiber 是普通 JS 对象**：靠 `child` / `sibling` / `return` 三个指针构成双向链表树，把大更新拆成小单元逐个处理，解决递归不可中断的问题
  - **双缓存**：同时维护 current（当前展示）与 workInProgress（内存中构建）两棵树，完成后原子切换指针；构建被打断也不影响屏幕
  - **时间切片 workLoop**：每处理一个 Fiber 检查 `deadline.timeRemaining()`，时间片用完就让出主线程，全部处理完才进入 commit
- **并发特性**
  - **开启方式**：`ReactDOM.createRoot` 渲染即获得并发（可中断渲染 + 时间切片）能力
  - **低优先级更新**：`startTransition` / `useTransition` 把非紧急更新（如切换 tab）标记为低优先级，`useDeferredValue` 延迟某个值的计算，让输入、点击先响应
- **虚拟 DOM 与 diff 三条启发式**
  - **虚拟 DOM 是什么**：React 元素构成的普通 JS 对象树（type / props / children），是真实 DOM 的内存镜像；先改便宜的虚拟 DOM，diff 出最小操作集，最后一次性应用
  - **启发式一：类型不同直接重建**：新旧根节点 type 不同（如 div 变 span），直接销毁旧节点及其整棵子树重建
  - **启发式二：同类型只更新 props**：保留原 DOM 节点，只 update 变化的属性
  - **启发式三：同层兄弟列表用 key 定位**：用 key 识别"同一节点"，把复杂度从 O(n³) 压到 O(n)
- **key 的真正意义**
  - **有 key**：能识别"同一节点被移动"，只新增缺失项、复用其余 DOM，性能高
  - **无 key / index 陷阱**：只能按索引对号入座，导致节点被依次"更新"、出现状态错乱（如输入框内容串位）；动态列表务必给 key 且不要用 index
- **优化三板斧**
  - **`React.memo`**：浅比较 props 缓存组件，props 浅比较相等时跳过该子组件渲染
  - **`useMemo`**：缓存计算结果，依赖项不变不重算；它是性能优化手段而非语义上的保证
  - **`useCallback`**：`useMemo(() => fn, deps)` 的语法糖，缓存函数引用，配合 `React.memo` 才能真正跳过渲染
  - **配合要点**：memo 是浅比较，内联对象 / 新函数会让它失效，需配合引用稳定与状态上移 / 下移、组件拆分
- **Hooks 是 Fiber 上的链表**
  - **链表结构**：每个函数组件的 Fiber 节点上挂 hooks 链表（`memoizedState`），hook 节点含 `memoizedState`（状态）/ `queue`（更新队列）/ `next`（下一节点）
  - **按调用顺序存取**：每次渲染按同样顺序读取链表节点，所以必须顶层、固定顺序调用，放 if / 循环里就会错位
  - **useEffect 依赖比较**：deps 存在 hook 节点里，每次渲染浅比较新旧 deps，不同才执行副作用并在 Commit 阶段触发回调
- **代码分割**
  - **`lazy` + `Suspense`**：`lazy(() => import(...))` 声明动态加载的组件，`Suspense` 提供加载中 fallback；配合 React Router 实现路由级懒加载
  - **体积优化**：抽离公共依赖（react-dom、antd 等 vendors）成独立 chunk，配合 Gzip 压缩（约再压 1/3）与长缓存命中，减小首屏体积、加快首屏渲染

### 02-Vue3 原理

- **三大模块协作**
  - **编译模块**：`@vue/compiler-core`（模板 → AST → render 函数，平台无关）、`@vue/compiler-dom`（浏览器扩展 v-html / v-text / SVG 等）、`@vue/compiler-sfc`（拆 .vue 的 template / script / style 三块，处理 `<script setup>` 与 scoped 样式）
  - **运行时模块**：`@vue/runtime-core`（平台无关：组件实例化、VNode、生命周期、props / 插槽、provide / inject）+ `@vue/runtime-dom`（浏览器宿主操作、默认 `createApp`）
  - **响应式模块**：`@vue/reactivity` 独立可脱离 Vue 使用，为数据提供变更追踪——三者关系是"用编译换说法、用响应式驱动、用运行时落地"
- **Proxy 响应式 vs Object.defineProperty**
  - **reactive 用 Proxy 代理整个对象**：返回的不是原对象；支持属性增删检测、数组与 Map / Set 集合、深度响应式（访问嵌套对象时自动再代理）
  - **WeakMap 做缓存与依赖存储**：`reactiveMap` 缓存保证同一对象只代理一次；键是对象、弱引用可被 GC 回收避免内存泄漏
  - **readonly 不做依赖收集**：不可 set 就永远不会触发 trigger，收集没有意义；readonly / shallowReadonly 复用 `createGetter` 闭包区分
- **track / trigger 依赖收集**
  - **三层结构**：targetMap（WeakMap：对象）→ depsMap（Map：属性）→ dep（Set：effect 集合）
  - **track（get 时）**：把当前 `activeEffect` 收进对应 dep，避免重复收集
  - **trigger（set 时）**：取出 dep 里所有 effect 执行；effect 有 `scheduler` 就交用户自定义调度时机（runtime-core 用它实现 nextTick 异步批量更新），否则 `effect.run()`
- **ref 与自动解包**
  - **RefImpl 包装基本类型**：把值包进对象再代理，`.value` 读写、值为对象自动转 reactive，`__v_isRef` 标记供 `isRef` 判断
  - **unref / proxyRefs**：unref 是 ref 返回 `.value` 否则返回本身；proxyRefs 用 Proxy 让模板里写 `count` 而非 `count.value`（只解包第一层，嵌套 ref 不递归解包）
- **computed / watch**
  - **computed 惰性与缓存**：基于 lazy 的 ReactiveEffect，`_dirty` 脏标记控制是否重算——依赖未变直接返回缓存值，依赖变化经 scheduler 置脏并通知依赖它的渲染 effect
  - **watch 是 effect 的封装**：对源执行一次读取建立关联，源变化经 scheduler 执行用户回调；支持 immediate / deep / flush 选项
- **模板编译与静态标记**
  - **编译三阶段**：解析（模板字符串 → AST）→ 转换（AST 优化：静态节点标记、缓存动态绑定）→ 代码生成（AST → 可执行 render 函数代码）
  - **PatchFlags 静态标记**：编译期给节点打补丁标记，只有含插值 / 指令 / 绑定的动态节点参与更新对比，静态节点直接跳过——Vue3 相比 Vue2 的关键编译期性能优化
- **运行时与虚拟 DOM diff**
  - **createRenderer 注入宿主操作**：runtime-dom 通过 `createRenderer({ createElement, insert, remove, patchProp... })` 注入浏览器宿主操作，返回 render 与 createApp；平台相关运行时都基于 runtime-core 扩展（多端渲染的基础）
  - **shapeFlag 位运算分发**：VNode 形状标记（ELEMENT / COMPONENT / TEXT_CHILDREN / ARRAY_CHILDREN 等），一个值表达多种组合特征，patch 按位与分发到 processElement / processComponent / processText
  - **patch 与异步批量更新**：patch(n1, n2) 对比新旧 VNode 生成最小补丁（挂载 / 更新 / 卸载）；渲染 effect 包上 scheduler，数据变化后推进队列、在下一微任务统一执行（nextTick）
- **组件运行时能力**
  - **生命周期钩子**：本质是"特定时机调用的用户函数集合"，onMounted 把回调注册进 `instance.mounted`，挂载完成统一遍历调用；组件卸载时统一 stop 相关 effect 防内存泄漏
  - **props 与插槽**：props 用 shallowReadonly 代理防止子组件改父值；插槽是父组件编译出的"返回 VNode 树的函数"，子组件经 slots 渲染（作用域插槽函数接收 props 参数）
  - **provide / inject**：借原型链（`Object.create` 浅拷贝父 provides）实现就近覆盖、沿链向上查找，跳过中间组件跨层级传数据
