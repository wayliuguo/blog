## 知识主线（一句话）

主轴是「**状态到界面的最小代价映射**」：01 以 React 建立「render/commit 两阶段 + 虚拟 DOM / diff + Fiber / Hooks 链表」这条基线，02 看 Vue3 的另一条路径（编译期静态标记 + Proxy 响应式精确到"哪个数据变了通知谁"），03 / 04 用手写实现把「可中断渲染」「依赖表」「批处理」落成能数出宿主操作次数的代码，05 把状态搬出组件，回答「改完通知谁」这个判断放在哪一层。

## 高频核心点

### 01 React 高级与原理

**render / commit 两阶段**

- **Render 阶段**：纯计算、可中断，只构建新虚拟 DOM / Fiber 并算 diff，不碰真实 DOM、不允许副作用
- **Commit 阶段**：不可中断，一次性应用变更并执行副作用（useEffect / useLayoutEffect / 生命周期 / ref 赋值）
- **并发基础**：render 可被高优先级操作抢占，commit 一旦开始不能半途而废

**Fiber 链表与双缓存**

- **Fiber 是普通 JS 对象**：靠 `child` / `sibling` / `return` 三指针构成链表树，把大更新拆成小单元逐个处理
- **双缓存**：同时维护 current 与 workInProgress 两棵树，完成后原子切换，构建被打断不影响屏幕
- **时间切片**：每处理一个 Fiber 检查 `deadline.timeRemaining()`，时间片用完让出主线程

**虚拟 DOM 与 diff 三条启发式**

- 类型不同直接重建；同类型只更新 props；同层兄弟用 key 定位把复杂度压到 O(n)
- **key 的意义**：识别"同一节点被移动"，只新增缺失项复用其余；无 key / index 会按索引对号入座导致状态错乱

**优化三板斧**

- `React.memo` 浅比较 props 缓存组件；`useMemo` 缓存计算结果；`useCallback` = `useMemo(() => fn)` 缓存函数引用
- memo 是浅比较，内联对象 / 新函数会使其失效，需配合引用稳定与组件拆分

**Hooks 是 Fiber 上的链表**

- 函数组件的 Fiber 上挂 hooks 链表（`memoizedState`），按调用顺序存取，所以必须顶层固定顺序调用
- `useEffect` 每次渲染浅比较新旧 deps，不同才在 commit 阶段执行回调

### 02 Vue3 原理

**三大模块协作**

- 编译（compiler-core / dom / sfc）→ 运行时（runtime-core / runtime-dom）→ 响应式（reactivity 可独立使用）——"用编译换说法、用响应式驱动、用运行时落地"

**Proxy 响应式 vs Object.defineProperty**

- `reactive` 用 Proxy 代理整个对象：支持属性增删、数组与 Map / Set、深度响应式；WeakMap 缓存保证同一对象只代理一次
- `readonly` 不收集依赖（不可 set 不会触发 trigger）

**track / trigger 依赖收集**

- **三层**：targetMap（WeakMap）→ depsMap（Map）→ dep（Set）；track 在 get 时收依赖、trigger 在 set 时执行 dep 里所有 effect
- effect 带 `scheduler` 时交用户决定调度（runtime-core 用它实现 nextTick 异步批量更新）

**ref 与自动解包**

- `RefImpl` 包基本类型、`.value` 读写、值为对象自动转 reactive；`proxyRefs` 让模板里写 `count` 而非 `count.value`
- **computed / watch**：computed 惰性 + `_dirty` 脏标记缓存；watch 是 effect 的封装，支持 immediate / deep / flush

**模板编译与静态标记**

- 编译三阶段：解析 → 转换（静态节点标记、缓存动态绑定）→ 代码生成
- **PatchFlags** 只让含插值 / 指令 / 绑定的动态节点参与 diff，静态节点跳过——Vue3 关键编译期优化

**运行时与虚拟 DOM diff**

- `createRenderer` 注入宿主操作，平台相关运行时基于 runtime-core 扩展（多端渲染基础）
- shapeFlag 位运算分发 patch；渲染 effect 包 scheduler 实现微任务批量更新
- props 用 shallowReadonly 防子改父；插槽是父编译出的"返回 VNode 树的函数"；provide/inject 靠原型链就近覆盖

### 03 手写 mini-react

- **五层骨架**：element → host（6 个宿主操作）→ internal → reconciler → hooks，每层可单独跑
- **createElement 只描述不渲染**：产物只有 type / key / props；文本包成 TEXT_ELEMENT；key 独立成字段只参与 diff
- **Fiber 与时间切片**：`child` / `sibling` / `parent` 换递归，`workLoop` 每单元问一次 `dl.timeRemaining()`；切片不省时间只换响应性（实测 18.1 → 5.8 ms 最长阻塞）；两处不可切分——组件函数本身、commit 阶段
- **diff 与 commit**：身份 = 有 key 用 key、没 key 退化下标；`alternate` 即双缓存；实测删首项无 key 3 次宿主操作、有 key 1 次
- **Hooks**：状态挂 Fiber 的 hooks 数组按顺序存取；setState 只推队列；批处理是异步调度的自然结果；effect 在 commit 后统一执行
- **与真实 React 差距**：无事件系统 / Lane / Context / ref / memo / 错误边界 / Suspense / SSR，都是同一骨架上加的一层

### 04 手写 mini-vue

- **响应式地基**：三层依赖表 + `activeEffect` 用栈（effect 里再跑 effect）；`deps` 反向索引支撑 cleanupEffect 与 stop；依赖只认"读过"的
- **惰性代理与 ref**：get 到对象才继续代理（不预先遍历）；ref 包基本类型、proxyRefs 只解包第一层
- **computed**：脏标记 + scheduler，真正重算发生在有人读 value 时
- **列表 diff**：先头尾双端同步、中间乱序按 key 建索引；无 key 退化成按下标（实测删首项无 key 5 次操作、有 key 1 次）；有 key 的重排也不是零成本
- **组件与批量更新**：渲染 effect 读到的响应式数据就是依赖；`queue.includes(job)` 保证一组件一轮只渲染一次；卸载要 stop 渲染 effect
- **与真实 Vue3 差距**：无编译层 / LIS / 生命周期 / provide-inject / Teleport / Suspense / SSR

### 05 状态管理原理与实现

- **三个真问题**：状态放哪 / 谁能改 / 改完通知谁；分野在第三个——判断被放在订阅者手里还是 store 内部依赖表
- **reducer 与不可变更新**：纯函数只返回新对象；没被影响的切片返回原引用（`Object.is` 短路）；`dispatch` 一律通知所有订阅者；原地改的后果是状态错但屏幕不变
- **setState 与订阅切片**：浅合并 + 逐键 `Object.is`，赋同值连通知都不发；订阅单位是"组件 × 切片"；选择器返回新对象会失守（`Object.is` 永远不等）
- **依赖追踪**：依赖表下沉积到字段（改 `cart.items` 只唤醒读过它的 effect）；`cleanup` + 反向索引避免脏字段误唤醒；`signal` 与 `reactive` 的 `set` 先 `Object.is` 再 return
- **三条路线对照（同一场景实测）**：只改一个切片 reducer 3/3 · reducer+选择器 3/1 · signal 1/1——**减少叫醒**与**减少渲染**是两条不同优化路径；判断越靠前省得越多
- **选型与边界**：服务端状态交给请求库；单一 store vs 按域拆分看"谁能改"而非规模；状态只被一个子树用到就放最近的公共父组件
