## 1. TypeScript 类型系统

### 1.1 类型系统的心智模型

三个核心心智模型，先把"类型是什么"想清楚：

- **类型即集合**：一个类型是一组值的集合，能否赋值就是"子集是否包含于超集"。`|` 是并集、`&` 是交集，`never` 是空集、`unknown` 是全集。
- **结构类型**：兼容只看成员形状，与名字、是否 `implements` 无关；但对象字面量直接赋值会触发**额外属性检查**（见 1.4）。
- **可赋值性**：返回值协变（更窄安全）、参数逆变（更宽安全），参数逆变由 `strictFunctionTypes` 打开（详见 1.5、1.9）。
- **类型只在编译期存在**：编译后类型注解与 `interface` 全部擦除，`enum` 是少数会留下运行时对象的类型语法（详见第 4 章）。

一条依赖链贯穿全模块：类型怎么描述数据（类型系统）→ 怎么在真实项目落地（工程实践）→ 把最难推导技巧落成能判题的最小实现（类型体操）→ 擦除之后运行时这侧的边界由谁看守（类型与运行时）。主轴始终是**类型系统**。

### 1.2 基础类型速览

四个高频概念先分清楚：

| 概念 | 含义 | 关键点 |
| ---- | ---- | ---- |
| `any` | 关闭检查 | 会沿表达式传染 |
| `unknown` | 全集 | 用之前必须收窄，外部数据一律落它 |
| `never` | 空集 | 可赋给一切、不能被赋值 |
| `void` | 无返回值 | 函数不返回有用值 |

**字面量会放宽**：`let` 声明与对象属性会放宽成宽类型，`as const` 把字面量锁住（并加上 readonly）。

**satisfies**：只做校验、不改变推断结果，解决"要校验就得丢掉精确字面量"的两难——`satisfies` 之后 `r.method` 仍是 `'GET'`，用类型注解则会被放宽。

```ts
const r = { method: 'GET' } satisfies Record<string, Route>; // r.method 仍是 'GET'
const r2: Record<string, Route> = { method: 'GET' };          // r2.method 放宽成 Method
```

**元组与枚举替代**：元组定长、越界索引直接报错；常量对象 + 字面量联合可替代 `enum`，值与类型同名共存。

**联合 / 交叉 / 字面量**：联合是"或"（`A | B`），交叉是"与"（`A & B`），字面量把值收窄成类型（`'GET'`）。交叉两个对象类型得到"两者属性都有"；`string | number` 是任意其一、`string & number` 是 `never`。

### 1.3 收窄

- **判别式联合**：给每个成员加字面量标签字段，`switch` 后自动收窄；`assertNever` 把"漏改一个分支"变成编译错误。
- **内置收窄手段**：`typeof` / `instanceof` / `in` / `Array.isArray` / 真值判断。两个坑：`typeof null` 是 `'object'`，需 `=== null` 判空；真值判断会吞掉 `0` 与 `''`。
- **自定义类型谓词**：`x is T` 让收窄逻辑可复用，但它是向编译器做出的**承诺、不校验实现**——写错会骗过类型系统、错误逃过检查。

### 1.4 对象类型

- **interface 与 type**：interface 可声明合并，type 能表达联合、元组、映射与条件类型。**描述公开结构用 interface，做类型运算用 type**。
- **可选、只读与索引签名**：索引签名换来灵活性的代价是放弃 key 检查、取值变 `unknown`。
- **额外属性检查**：只作用于**对象字面量**；先赋给变量、加索引签名、类型断言是三种绕法（按这个顺序选）。
- **调用签名、构造签名与重载**：接口可以描述"可调用"与"可 new"；重载给出精确入出参，能用联合 + 收窄讲清楚就别上重载。重载签名列表在前、实现签名在后（对调用者不可见）、实现是唯一运行体且必须兼容所有重载。

### 1.5 泛型

- **泛型优于 any**：保留"入参与返回值之间的关系"，`function first<T>(list: T[]): T` 才能把类型带出去。any 丢失类型关系，泛型保留"同一类型"的约束。
- **约束与默认类型参数**：`extends` 约束是函数体内安全使用成员的依据；`<T = unknown>` 提供默认值。
- **keyof 约束**：`K extends keyof T` 让 key 必须真实存在，返回值 `T[K]` 跟着 key 走。
- **条件类型的分发**：裸类型参数会按联合成员逐个分发，`[T] extends [U]` 可阻止分发，`Exclude` 正依赖分发。
- **泛型的位置**：接口泛型在声明时确定，函数泛型在调用时确定。

### 1.6 类型推断

- **上下文推断**：回调参数的类型来自它所在的位置，不需要手写标注。
- **必须标注的三处**：空数组、对外 API 的返回值（防 any 扩散）、推断不出来处（`noImplicitAny` 会拦）。
- **字面量 widening 与 as const**：`as const` 得到 readonly 字面量，适合做常量表；再配合 `typeof` 生成联合（`type Method = typeof METHODS[number]`）。让 TS 自己推断尽量不写多余注解，但**边界处（函数参数/返回、API 请求/响应）必须显式声明**。

### 1.7 类型运算

- **keyof 与索引访问**：`keyof T` 取键的联合、`T[K]` 取值的类型，让派生类型跟着数据结构自动变化。
- **映射类型**：`[K in keyof T]` 遍历生成新类型，`+`/`-` 控制 `?` 与 readonly，`as` 子句可重映射键名。
- **条件类型与 infer**：`infer` 捕获匹配位置的类型，可递归解开 Promise；`MyReturnType` 的参数写 `never[]` 以避免 any 扩散。`infer` 只能写在 `extends` 右侧条件分支里。
- **内置工具类型**：

```
Partial / Required / Readonly / Pick / Omit / Record
Exclude / Extract / NonNullable / ReturnType / Parameters / Awaited
规律   Omit = Pick + Exclude
      Exclude 基于可分配性，联合中的 never 被忽略
      keyof any = string | number | symbol
```

```ts
type Partial<T>   = { [P in keyof T]?: T[P] }
type Pick<T, K extends keyof T> = { [P in K]: T[P] }
type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>
type Record<K extends keyof any, V> = { [P in K]: V }
type ReturnType<T> = T extends (...args: any) => infer R ? R : never
```

### 1.8 类与类型

- **一个类创建两样东西**：实例类型（`Clock`）与构造函数类型（`typeof Clock`）。
- **implements 只检查实例侧**：静态成员不在它的检查范围内。
- **private 的名义性**：`private` / `protected` 让结构类型退化成名义类型，形状相同但声明来源不同即不兼容。
- **函数重载与 this 类型**：重载让"同函数按参数形态返回不同类型"；`this: SomeType` 作为首个参数显式声明函数体内 `this` 的类型，编译后擦除。`this` 类型错误通常源于回调里 this 丢失（箭头函数/解构）。

### 1.9 常见编译错误速查

- **分两层看报错**：第一层"这两个类型不兼容"只是复述代码，第二层细节才是真正原因。
- **错误码对照**：

| 错误码 | 含义 |
| ---- | ---- |
| TS2322 | 赋值不匹配 |
| TS2339 | 属性不存在 |
| TS2345 | 实参不匹配（含额外属性检查） |
| TS7053 | 用 string 索引无签名对象 |
| TS18046 / TS2571 | unknown 未收窄 |
| TS18048 | 可能 undefined |
| TS2769 | 重载全部不匹配 |

**逆变与协变（在错误/兼容语境下再确认）**：函数参数逆变（更严格者可接受）、返回值协变（更宽泛者可接受），`strictFunctionTypes` 下参数逆变开启；方法语法（method shorthand）不强制参数逆变，用函数属性语法 `(x: T) => void` 才严格。记忆："参数要敢收（超类型），返回要能给（子类型）"。

## 2. TypeScript 工程实践

### 2.1 tsconfig 是落地之基

- **基础目标与模块**：`target` 编译目标、`lib` 可用类型库、`module` 模块系统、`moduleResolution: Bundler` 打包器解析策略。
- **strict 系列严格检查**：`strict` 总开关开启全部严格检查；`strictNullChecks` 严格区分 null/undefined、`noImplicitAny` 禁止隐式 any、`noUncheckedIndexedAccess` 标记索引访问可能为 undefined。
- **paths 路径别名**：`@/*` 映射到 `src/*`；只影响编译期类型解析，**运行时还要在 Vite/Webpack 的 `resolve.alias` 同步同一份映射**。
- **输出与产物体**：`noEmit` 只做类型检查不输出 JS、`isolatedModules` 配合打包器逐文件转译、`esModuleInterop` 兼容 CJS 依赖、`resolveJsonModule` 允许直接导入 JSON。

### 2.2 落地分层推进

- **先选编译/运行方案**：Vite 项目开箱即用 TS（esbuild 转译 + tsc 单独做类型检查），Webpack 用 ts-loader 或 babel-loader。
- **自然推导与边界显式**：让 TS 自己推断尽量不写多余注解，函数参数/返回类型、API 请求/响应等**边界必须显式声明**。
- **类型驱动开发**：定义好领域模型（interface/type）后编译器兜底所有引用处；`request<T>` 泛型封装把响应类型带进来。

### 2.3 .d.ts 声明文件

- **declare 只描述类型**：`declare` 只描述类型/形状，编译时不产生任何 JS 输出。
- **全局声明与模块内补充**：顶层 `declare const/function/class` 声明全局变量，`declare global {}` 在模块内向全局命名空间补充声明。
- **模块声明与简写兜底**：`declare module "xxx"` 声明无类型模块或做模块增强；`declare module "*.less"` 等简写是兜底，能用正式类型就不要堆 any 化声明。
- **三层兜底顺序**：查 `@types/*` → `declare module` → 自建声明 → 类型断言（`as any` 是最后手段，要注释理由）。
- **发出与发布**：`noEmit` 只查不编译；`tsc --emitDeclarationOnly` 从源生成 .d.ts 供消费者 import。

### 2.4 断言克制、守卫优先

- **类型断言 `as`**：是"信任声明"要谨慎用、不掩盖类型漏洞；`as const` 制造字面量类型。
- **运行时守卫收窄**：`typeof` / `instanceof` / `in` / 自定义谓词 `x is T` 才是安全的收窄方式。
- **可辨识联合**：用 `status` 等字段区分各分支，处理复杂状态的头号推荐方案，效率与类型安全兼得。

### 2.5 类型体操范式

- **三大基础模式**：条件类型（三元 + infer 提取）、映射类型（遍历键、键重映射）、keyof + 索引访问。
- **递归模板**：如 `[...infer _Rest, infer L]` 对齐解构元组，实现取首尾元素等类型操作。
- **内置工具类型实战**：`typeof`/`keyof` 取值的类型与键名，Partial/Required/Pick/Omit、Record/Readonly/ReturnType、Awaited 拆 Promise、NonNullable 去空，高频实用不必背题。

### 2.6 构建集成与 JS→TS 迁移

- **Vite 集成**：把 `tsc --noEmit` 独立为 `typecheck`/`build` 脚本，保证无类型错误再产出；`resolve.alias` 与 tsconfig `paths` 同步同一份映射。
- **Webpack 集成**：ts-loader 真正编译并带类型检查（更慢），babel-loader 更快但无类型检查，需单独 tsc 兜底。
- **渐进式迁移**：先 `allowJs` 跑通 → 逐步收紧（`noImplicitAny` → `strictNullChecks` → `strict`）→ 排查 any（unknown 优先）→ 把 `tsc --noEmit` 纳入 CI，切忌一次性推翻重建。
- **迁移常用技巧**：`@ts-nocheck` 跳过暂不迁移文件、`@ts-expect-error` 更严谨的逐行忽略、优先 `@types/xxx` 再写 .d.ts。
- **不拖慢构建**：多套 tsconfig 分治（`tsconfig.app.json` 管业务、`tsconfig.node.json` 管脚本）+ 类型检查与构建并行 + `skipLibCheck` + lint-staged 门禁（只查暂存文件）。

## 3. TypeScript 类型体操

### 3.1 体操的本质与判题

- **类型体操 = 类型层面的计算**：用条件类型做分支、`infer` 提取片段、映射类型遍历键与修饰符、模板字面量做字符串模式匹配、递归处理不定长结构——五类凑齐覆盖绝大多数需求。
- **判题靠编译器**：`Equal<A,B>`（用函数类型双向赋值判定结构等价）+ `Expect<T extends true>` 把关；训练场 `exercises.ts`（答案位 `TODO` = never，未解 61 错）/ `solutions.ts`（0 错）就是现成的类型单测。

### 3.2 五大套路

| 套路 | 技法 | 例 / 内置对应 |
| ---- | ---- | ---- |
| 提取 | `X extends (...)=>infer R ? R : never` | `ReturnType`/`Parameters`/`Awaited`/`InstanceType` 同构 |
| 改写键 | `{ [K in keyof T]?: T[K] }` + `?`/`-?`/`readonly`/`-readonly` | key 重映射 `as`（`Uppercase<K & string>` 改名） |
| 递归 | 元组 `[infer F, ...infer R]` 取首项与剩余；`T extends object` 当嵌套终止条件 | `Repeat` 用"累加元组长度"逼近数字 `N` |
| 字符串 | `${infer X}` 在类型字符串里抠片段 + `Uppercase`/`Capitalize` | 路由 `:param` 解析、key 改名 |
| 集合运算 | 裸 `T extends U ? never : T` 对联合逐成员分发 | `Exclude`/`Extract`/`NonNullable` 由此而来 |

`infer` 只能写在 `extends` 右侧条件分支里。

### 3.3 实战落点与两条纪律

- **实战落点**：判别联合（`LoadingState` 按 `status` 收窄）、属性映射（`FormErrors` 每字段一个可选错误串）、对象覆盖（`Merge` 用映射而非交叉，避开 `Equal` 对交叉类型的误判）。

```ts
type MyOmit<T, K extends keyof any> = { [P in Exclude<keyof T, K>]: T[P] }
type DeepReadonly<T> = {
  readonly [P in keyof T]: T[P] extends object ? DeepReadonly<T[P]> : T[P]
}
```

- **两条纪律**：要比较相等就用扁平对象别用交叉类型；递归类型别用于无限长结构（会撞编译器上限）。
- **边界**：`DeepReadonly` 的 `extends object` 会误伤函数与 Date（函数也是 object），需额外排除；深度递归对超大类型有栈深压力。

## 4. TypeScript 类型与运行时

### 4.1 擦除是选择性的

- **被擦除**：interface / type / 泛型参数 / 类型断言，编译后整段消失。
- **保留为运行时值**：类（构造函数）、普通枚举（双向映射对象）、装饰器。
- **结论**：`instanceof` 判接口必崩；能写在 `: ` 后面的未必运行时可寻（接口 `typeof` 是 `undefined`）；普通枚举编译成正向取值 + 值反查名字的双向映射对象。
- **类型系统安全的前提**是"数据在编译期已知形状"，外部数据（网络 / 存储 / 反序列化）进入程序时只能是 unknown。

### 4.2 运行时校验：unknown → typed 的桥

- 手写 schema 或 `zod` / `io-ts` / `superstruct`，schema 作单一事实源（既生成类型又执行校验）。
- 非法输入**必须抛错**，不能靠类型系统默认相信——接口数据编译器根本看不见，类型正确不等于数据正确。

### 4.3 编译期与运行时的桥

- **类型守卫 `a is T`**：把运行时判断提升成编译期收窄；**断言函数 + `assertNever`**：未穷尽分支在编译期报错。
- **品牌类型**：给底层同型值贴编译期标签（各类 id / token），入口收口 + 运行期校验，防混用。

### 4.4 JSON 不是类型系统

Date / Map / Set / undefined 序列化后保不住：

```
Date        → 字符串
Map / Set   → 退化成普通对象
undefined   → 字段消失
```

跨进程需自带类型信息或对称编解码。

### 4.5 端到端类型安全与类型发布

- **端到端类型安全**：前后端共享同一份契约（tRPC / OpenAPI codegen / GraphQL codegen），字段错配前移成编译期错误。在 api 层把接口入参出参收口成类型，页面只消费 api 层导出的类型——改契约编译期全局报错。
- **类型发布 = 发 .d.ts**：`tsc --emitDeclarationOnly` 从源生成声明文件，消费者 import 的是类型、运行时零成本；用 `types` / `exports.types` 指向声明文件。
