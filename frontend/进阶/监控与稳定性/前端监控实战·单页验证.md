# 前端监控实战·单页验证

## 三十秒速览

**结论：`前端监控体系.md` 讲「是什么、为什么」，本篇用一个 SPA 把概念落地成「点了会怎么样」。** 一个 Vite+Vue 的三路由页面，分别演示错误 / 性能 / 埋点三类上报；页面上**不造日志面板**——验证交给你自己用 DevTools 看：

- **Console**　SDK 开发态彩色日志：每条事件入队打一行 `[monitor] 采集`、每批发送打一行 `[monitor] 发送`（来源：`sdk/dev-logger.mjs`）。
- **Network**　看 `POST /collect` 的 `events` 请求体——攒批是不是真的把好几条拼成了一次请求。

跑法一行（生产形态，单一端口）：

```
cd code/monitor-lab && npm install   # 首次：装 Vite / Vue
cd code/monitor-lab && npm run start # 构建 + 起采集端，端口 5189
# 浏览器打开 http://localhost:5189/
```

改码调试用双进程：`npm run server`（采集端 5189）＋ `npm run dev`（Vite 5173，`/collect` 已代理回采集端）。路由是 hash 形式，`#/errors` / `#/perf` / `#/track`，刷新不 404。

## 一、三个路由 = 三类数据

| 路由 | 对应篇目 | 验证什么 |
| --- | --- | --- |
| `#/errors` | [前端监控体系](./前端监控体系.md) 第 四 节 | 六类错误六种抓法、指纹频控 |
| `#/perf` | 第 五 节 | RUM 采集、LCP/CLS 越晚越准、指标评级 |
| `#/track` | 第 六 节 | 声明式埋点、会话/曝光/点击、脱敏 |

三页共用**同一个 SDK 实例**（`sdk/index.mjs` 的 `init` 单例，一次初始化挂上三类采集插件），切身体会「插件只负责采、`emit` 只把事件丢进传输层、`transport` 只负责攒批发送」的分工。

## 二、稳定性路由：六类错误，六次点击

`#/errors` 每一行对应 [前端监控体系](./前端监控体系.md) 第 四 节的一种抓法：

| 按钮 | 触发什么 | 验证的概念 |
| --- | --- | --- |
| 运行时错误 | 读 `undefined` 的属性，冒泡成 `window` 的 `error` | `addEventListener('error')` 兜底同步抛错 |
| Promise 拒绝 | `Promise.reject(...)` 不 catch | **不走 `onerror`**，需单独 `unhandledrejection` |
| 资源加载失败 | 把 `<img src>` 指到不存在的文件 | 资源错误**不冒泡**，只看捕获阶段 + 事件上无 message |
| 接口 404 | `fetch('/definitely-missing')` | SDK 包 `fetch`，`!ok` 记 `http` 错误（status） |
| 网络错误 | 请求 `127.0.0.1:1`（拒绝连接） | 连响应都没有，走 `catch` 记 `network` |
| 跨域脚本 | 派发 `Script error.` 事件 | 同源策略抹平细节，只剩一句 |

点完看 Console——六条错误几乎各有各的指纹 `fp`（`message + 位置 + 行号`），即便是同一页也能彼此分开；本 demo 用 `throttleMs: 0` 关掉频控，点一次看全六条，线上一般开 3 秒频控。

## 三、性能路由：三类性能降级

`#/perf` 三个按钮 + 一个「收口上报」：

| 按钮 | 触发什么 | 验证的概念 |
| --- | --- | --- |
| 长任务 140ms | 一条 `jam(140)` 同步循环 | 生成长任务，**TBT 只算超出 50ms 的部分**（约 90ms） |
| 无预留横幅 | 在 `body` 顶部插横幅 | 产生 `layout-shift`，进入 CLS 统计 |
| 晚到大元素 | 最后插一个占满的 hero | 面积最大的内容最后出现，**LCP 被刷新** |
| 收口上报 | 调 `perf.finalize()` 读现测值 | 看 LCP / CLS / TBT 的当前快照与官方阈值评级 |

关键点同上篇：LCP 与 CLS 是**越晚越准**的收敛值，页面 `visibilitychange → hidden`（切后台 / 关页）时 SDK 才定稿上报终值。你收口看到的是"现在这一刻"，而 Network 里 finally 那条才是终值。

## 四、埋点路由：声明式埋点，业务只写属性

`#/track` 里那些按钮和卡片**没有一行采集代码**，只写了 `data-track` / `data-expose` 属性：

```html
<button data-track="cta-hero">开始体验</button>
<button data-track="cta-card" class="primary">卡片内按钮</button>
<div data-expose="card-intro">首屏可见的卡片</div>
<!-- 底部有 data-expose="footer-banner"，要滚动到才曝光 -->
```

| 触发 | 采集到的事件 | 验证的概念 |
| --- | --- | --- |
| 点「PV / 会话」 | `pv { ref:'direct' }` | PV 挂会话上，UV 靠 `anonId` 去重 |
| 点「开始体验」 | `click { id:'cta-hero' }` | 事件委托一次监听覆盖全站 |
| 卡片进入视口 | `expose { id:'card-intro' }` | `IntersectionObserver` 采曝光，且首屏不漏 |
| 滚到底 | `expose { id:'footer-banner' }` | 底部元素不因"滚动"漏采（对照 `scroll` 监听的坑） |
| 点「自定义事件」 | `search { keyword:'性能优化' }` | 埋点字典之外的一次性事件 |

关闭 / 刷新页面时会结算 `stay`（停留时长）一起上报。Console 里 `[monitor] 采集` 的行和 Network 里 `POST /collect` 的 body 能对得上，就完成了「概念 → 上报 → 接收」的闭环验证。

## 五、验证链路：到底采没采、发没发、收没收

因为不做自建日志 / 聚合面板，三层证据分别在三个地方看：

| 想问的问题 | 看哪 | 长什么样 |
| --- | --- | --- |
| SDK 采到了吗 | Console | `[monitor] 采集 script	Uncaught TypeError…` |
| 采的攒成一发送了吗 | Console / Network | `[monitor] 发送 5 条 ✓（原因 batch-full…）` 对应一条 `POST /collect` |
| 采集端真的接收了吗 | 跑采集端那个终端 | `▼ 收到 N 条：error×… track×…（累计 …）` |
| 落盘了吗 | `data/events.jsonl` | 每条事件一行 JSON |

这个边界本身就是结论：**浏览器端只负责「采 + 送」，接收端只负责「收 + 落盘」**；秒桶、分位值、告警这些服务端聚合属于采集端后端，不在本 demo 里展开——它们不改变"SDK 到底对不对"这个验证目标。

## 配套代码

本篇的验证台就是 `frontend/进阶/监控与稳定性/code/monitor-lab/`。

| 文件 | 角色 |
| --- | --- |
| `./code/monitor-lab/app/src/views/{Home,Errors,Perf,Track}.vue` | 三路由的按钮与「该看什么」说明 |
| `./code/monitor-lab/app/src/monitor.js` | 全局唯一 `init` + 三类触发函数 |
| `./code/monitor-lab/app/vite.config.mjs` | `root=app`；dev 时 `/collect` 代理回 5189 |
| `./code/monitor-lab/sdk/index.mjs` | SDK 入口：单例 init、插件注册、生命周期收口、dev-logger 开关 |
| `./code/monitor-lab/sdk/dev-logger.mjs` | 开发态彩色 console：每条入队 / 每批发送 |
| `./code/monitor-lab/collector.mjs` | 极简采集端：静态下发 app/dist + `POST /collect` + 落盘 + 打印批次 |

运行方式：`npm run start` 后浏览器打开 `http://localhost:5189/` 手动点；或 `npm run server` + `npm run dev` 双终端改码调试。
