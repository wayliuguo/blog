## 1. 前端监控体系

### 1.1 三类数据与监控闭环

监控先回答"看什么"——三类数据把线上状态拆成三个互不替代的视角：

| 视角 | 回答的问题 | 采集对象 / 关键信号 |
| ---- | ---- | ---- |
| **稳定性** | 有没有坏 | JS 错误、Promise 异常、资源加载失败、接口异常、白屏 |
| **体验** | 快不快 | TTFB / FP / FCP / FMP / FID、>50ms 长任务 |
| **业务** | 用户在做什么 | PV、UV、停留时长、转化漏斗 |

> 三类数据量级与口径完全不同，混在一个采集逻辑里必然顾此失彼，必须分开定采样。

**监控闭环**（不只"报个错"）：`目标设定与数据采集 → 传输与存储处理 → 分析与可视化 → 告警预警与定位优化`。本篇只讲前端「采集—上报」这一段，服务端聚合是模块外范畴。

### 1.2 上报方式

- **手动 vs 自动**：自动兜底（监听内置事件）+ 手动补上下文（关键分支），配合而非二选一。
- **三代手段**：图片打点（GET、URL 上限 2~8KB、拿不到响应）→ `sendBeacon`（请求体 ~64KB、跨域不预检、卸载能送达）首选 / `fetch+keepalive` 兜底。
- **`sendBeacon` 拿不到响应体**，只能回答"提交出去了没有"，确认收到靠服务端入库计数。

### 1.3 错误监控

- **六类错误无一抓全**，各挂监听：运行时（`error`）、Promise（`unhandledrejection`）、资源（同一 `error` 但 `capture` 捕获阶段）、接口（包 `fetch` 记 `!ok`）、网络（`fetch` `catch`）、跨域（只剩 `Script error.`）。
- **三个坑**：资源错误不冒泡（判据 `target.tagName`）；`Script error.` 是同源策略在保护；`onerror(msg, source, lineno, colno, error)` 参数易记混。
- **指纹频控按 `message + 位置 + 行号`**，不是 message——循环报错 message 全一样；资源/接口错误没 message 要把 `src`/`url` 算进指纹。
- **sourcemap 还原**：生产栈是压缩后的，用 `release` 绑定 map；服务端还原优于客户端；框架层（Vue `config.errorHandler` / React 错误边界）只兜框架内错误，React 边界不覆盖异步与事件处理器。

### 1.4 性能与体验监控

RUM 面对真实用户，三个必然设计：

- `buffered: true` 补收注册前条目（否则 FCP 恒为 0）；
- `visibilitychange → hidden` 定稿（LCP / CLS 越晚越准）；
- 不支持的 entry 类型 `try/catch` 静默跳过。

取数两范式：导航类走 `getEntriesByType('navigation')` 快照，动态指标（LCP/CLS/长任务）走 `PerformanceObserver` 订阅（不用轮询）。

**两个容易写错的指标**：

- **CLS 存两数**：`cls`（规范口径，剔除 `hadRecentInput`）与 `clsRaw`（全部位移）——看板用前者、排查用后者；位移 500ms 窗口 / ≤5% 视口合并。
- **TBT 只算超出 50ms**：`Σ max(0, duration-50)`，140ms 长任务只贡献 90ms。

采集自律：回调只累加不序列化、指标只算一次、资源明细限流 Top N。

### 1.5 埋点与行为分析

- **三种埋法组合**：核心路径代码埋点（口径准）、长尾可视化、兜底无埋点；实验台走**声明式埋点**（业务只写 `data-track`/`data-expose`）。
- **三个 ID 别混用**：设备 / 匿名 / 登录，生命周期与用途不同；**会话按 30 分钟不活跃切**，判定放事件入口。
- **四指标先定口径**（PV 加载 vs 路由、UV 按哪个 ID、停留"离开时结算 + enter/stay 双写兜底"、跳出两口径）。
- **曝光用 IntersectionObserver 不监听 scroll**（scroll 方案每次滚动同步读布局即布局抖动，且漏首屏）；`unobserve` 只报一次；`entry.time` 不是停留时长。
- **脱敏放采集口**：URL 只留 path、文本截断、表单值不采。
- **治理四件套**：埋点字典、命名规范、开发环境未登记告警、超期下线。

## 2. 前端监控 SDK 实现

### 2.1 四层分工与组装方式

```
采集层   错误 / 性能 / 埋点三块独立成模块，互不感知
传输层   采样 → 攒批 → 投递 → 重试 → 溢出丢弃
治理层   采样率在传输层、脱敏与频控在采集层
生命周期 init 时机 + 页面离开时收口上报
```

组装两个约定：**单例**（多处 `init` 只返回首个实例，否则重复上报乘 N）；**插件化**（采集器只共用 `emit(event)` 签名，加采集不动传输与生命周期）。

### 2.2 传输层四个必备机制

| 机制 | 解决什么 | 实测口径 |
| ---- | ---- | ---- |
| 攒批 | 减少请求数 | 12 条事件：逐条 12 次请求 vs 攒批 3 次 |
| 采样 | 控制量（放**入队口**丢） | 2000 条 @10% 只接受 198 条 |
| 重试 | 兜偶发失败 | `maxRetry=2` 即首投+2 重试，耗尽放弃计入 `dropped` |
| 溢出 | 保住内存 | `maxQueue` 上限、丢**最旧**的，50 入队→10 投递 |

要点：重试必须有限（监控数据不值得无限重试）；采样放 **入队口**（被采样掉尽早消失）；溢出丢最旧的；采样按用户维度稳定否则分位失真。

### 2.3 投递顺序与生命周期收口

```
sendBeacon 优先   卸载能送、不阻塞、拿不到响应
fetch + keepalive 兜底   有响应、请求体 64KB 上限
同步 XHR          阻塞卸载，浏览器已基本禁用
```

生命周期**用 `visibilitychange → hidden` 而不是 `unload`**（移动端 `unload` 常不触发）；LCP / CLS 越晚越准，离开时定稿。

### 2.4 自身开销与治理口径

- **开销**：一次 `flushAll` 实测 593B / 4 条、单条约 148B；回调只累加不序列化；指标只算一次。
- **治理**：错误不采样、埋点低比例、长任务明细 1%~5%；URL 只留 path、文本截断 40 字符、表单值不采；频控按指纹（message+位置+行号）。

## 3. 前端监控实战·单页验证

### 3.1 单页验证台与三类数据

`npm run site` + 打开 `/monitor-lab.html`，三个面板 = 三类数据，右「刷新聚合」从 `/api/report` 看接收端证据。

### 3.2 错误 / 性能 / 埋点三种验证

- **错误**：6 个按钮对应 6 类抓法；关掉 `throttleMs` 一次看全六条；每条指纹 `fp` 几乎都不重复。
- **性能**：长任务（TBT 只算超 50ms）+ 无预留横幅（layout-shift）+ 晚到大元素（刷新 LCP），页 hidden 才定稿。
- **埋点**：声明式属性 + `IntersectionObserver` 曝光（首屏不漏、`unobserve` 只报一次）+ 事件委托点击 + `stay` 离开结算。

### 3.3 自动化场景与口径对齐

`?scenario=errors|perf|track` 复刻原三个实验台序列，原三张散页收拢为这一张单页，框架与表单一处维护。

- `npm run errors` → 6 类错误字段表、指纹频控 6→4
- `npm run perf` → 5 指标评级、`cls`/`clsRaw` 对照、TBT 90ms、flush 体积
- `npm run track` → 8 条事件流、小看板、漏斗
