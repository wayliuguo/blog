## 2. 重点题精答（五步法）

### Q1：`interface` 与 `type` 的区别？

- **结论**：多数场景可互换；interface 可声明合并，type 可表达更复杂的类型运算。
- **原理**：interface 面向对象语义（extends/合并），type 是类型别名（联合/交叉/映射/条件）。
- **场景**：公共 API 契约用 interface；联合类型、工具类型推导用 type。
- **边界**：interface 合并是特性也是风险（意外扩展）。
- **追问**：能互相继承吗？→ type 可通过交叉实现类似继承，interface extends type 也允许。

### Q2：类型收窄的手段？

- **结论**：`typeof`、`in`、`instanceof`、`Array.isArray`、自定义类型守卫、可辨识联合。
- **原理**：控制流分析（CFA）在分支内收紧类型。
- **场景**：接口响应 `{ code: 0, data } | { code: 1, msg }` 用 `code` 判别；表单校验错误对象用 `in` 收窄。
- **边界**：`typeof` 对 `null` 返回 "object"，需 `=== null` 判空。
- **追问**：自定义守卫 `x is T` 写错了会怎样？→ 类型系统被欺骗，运行时错误逃过检查。

### Q3：工具类型的实现（Pick / Omit / ReturnType）？

- **结论**：基于映射类型、`keyof`、条件类型、`infer` 组合实现。
- **原理**：
```ts
type Pick<T, K extends keyof T> = { [P in K]: T[P] }
type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>
type ReturnType<T> = T extends (...args: any) => infer R ? R : never
```
- **场景**：表单提交参数 `Pick<LoanParams, 'amount' | 'period'>`；事件回调返回值推导。
- **边界**：`Exclude` 基于可分配性，联合中的 never 会被忽略。
- **追问**：`keyof any` 是什么？→ `string | number | symbol`。

### Q4：枚举 vs `as const`？

- **结论**：字符串枚举语义清晰但有运行时代码；`as const` + 联合类型零运行时成本且类型更精确。
- **原理**：枚举编译为对象；`const` 断言让字面量类型窄化。
- **场景**：请求方法、错误码、状态机用 `as const` + 联合；需要反向映射（值→名）才用枚举。
- **边界**：数字枚举反向映射是特性，但也允许运行时拿到不存在的值。
- **追问**：`const enum` 呢？→ 完全内联，无运行时代码，但调试与 Babel 处理有坑。

### Q5：泛型约束 `extends keyof`？

- **结论**：`K extends keyof T` 把泛型参数限制为 T 的键集合。
- **原理**：`keyof T` 返回 T 的键联合；约束保证索引访问 `T[K]` 安全。
- **场景**：`getProp(obj, key)` 的类型安全取值；表单字段映射表。
- **边界**：对象字面量传参时 TS 会做多余属性检查，需注意。
- **追问**：`T[K]` 索引访问类型是什么？→ 对应键的值类型。

### Q6：类型检查怎么不拖慢构建？（工程核心）

- **结论**：多套 tsconfig 分治 + 类型检查与构建并行 + `skipLibCheck`。
- **原理**：`tsconfig.json` 管引用、`tsconfig.app.json` 管业务、`tsconfig.node.json` 管构建脚本；`vue-tsc --noEmit` 与 `vite build` 并行跑，类型检查不再串行阻塞。
- **场景**：简历项目"类型检查与构建并行编排"——`vue-tsc --noEmit` 与 `vite build` 同时执行。
- **边界**：`skipLibCheck` 跳过 .d.ts 检查省时，但会掩盖三方库类型问题。
- **追问**：改动范围怎么缩小检查？→ lint-staged 只对暂存文件检查。

## 3. 追问链

1. "unknown 和 any 的区别？" → any 关闭类型检查，unknown 需要收窄后才能用。
2. "怎么把第三方库无类型的问题解决？" → `declare module` / `@types` / 自建 `.d.ts`，再不行类型断言。
3. "条件类型什么时候会提前求值？" → 未分配（non-distributive）时，直接判断整个联合；可用 `[]` 包住避免分配。
4. "逆变协变怎么记？" → 函数参数是逆变（严格者可用），返回值是协变。

## 4. 场景设计题

**场景：一个 30+ 人协作的 Vue3 + TS 项目，页面多、接口多，怎么用类型控制质量？**
- 答题骨架：api 层类型收口（入参/出参 TS 类型即契约，页面只消费 api）→ 后端返回做可辨识联合/兜底类型 → 表单/状态用 `as const` + 联合而非魔法字符串 → tsconfig 分治 + 类型检查并行 → 提交前 lint-staged 类型检查门禁。
- 加分点：呼应简历"接口分层：页面不关心 URL、参数、返回解析，类型在 api 层收口"。

## 5. 面试口径（简历项目如何表达）

- **项目证据**：Vue 3.5 + TypeScript 5.8；多套 tsconfig 分治（app 管业务 / node 管构建脚本）；`vue-tsc --noEmit` 与 `vite build` 并行编排；api 层"类型即契约"（入参出参在 api 层收口）。
- **表达句式**："TS 落地做了三件事：api 层把接口的入参出参类型收口，页面只消费 api 不直接碰请求；多套 tsconfig 分治避免构建脚本类型混进业务检查；类型检查与构建并行跑，不让类型检查成为串行瓶颈。"
- **勿说**：不要说"项目里到处是 any"——要展示的是用类型表达契约的实践。
