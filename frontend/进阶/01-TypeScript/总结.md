# 模块总结 · TypeScript

## 知识主线

两篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 TypeScript 类型系统（类型怎么描述数据）
        │  类型注解会写了，但"严格模式怎么配、声明文件怎么写、怎么落进真实项目"还不知道
        ▼
02 TypeScript 工程实践（类型怎么在真实项目里落地）  ★主轴
```

本模块的主轴是**类型系统**：01 篇讲类型本身——基础类型、接口、类、函数、泛型、推断与高级类型，把"类型如何描述数据"讲透；02 篇讲它在真实工程里如何配置与应用——tsconfig 严格度、.d.ts 声明、类型守卫与可辨识联合、类型体操、内置工具类型，以及构建集成与 JS→TS 迁移，把"会写类型"升级为"能在真实项目里优雅落地"。

## 分篇知识点

### 01-TypeScript 类型系统

- **安装与配置**：`npm i -g typescript` 后用 `tsc` 编译；`tsconfig.json` 中 `strict` 是整套严格模式的总开关，`strictNullChecks` 严格区分 `null`/`undefined` 是写出安全代码的关键
- **基础类型**：boolean/number/string/数组/元组/enum/any/void/null/undefined/never/object；`never` 是任何类型的子类型、只能赋给它自己，`any` 会跳过类型检查需克制使用
- **接口与类**：interface 用「结构性子类型化」（鸭式辨型）检查值的外形，支持可选/只读属性、函数类型、可索引类型、继承与混合类型；类有 public/private/protected、readonly、参数属性、抽象类，`private` 兼容性要求来自同一处声明
- **函数与泛型**：函数类型、可选/默认/剩余参数、`this` 参数与函数重载；泛型用类型变量 `T` 保持「传入与返回同型」，`T extends` 约束泛型，`keyof` 保证属性存在于对象上
- **类型推断与高级类型**：最佳通用类型与上下文类型；交叉类型（`&`）、联合类型（`|`）、类型守卫（typeof/instanceof/自定义谓词 `x is T`）、映射类型与条件类型
- **内置工具类型**：Pick/Omit/Partial/Required/Readonly/Record/ReturnType 等构成类型运算基础设施；条件类型 + `infer` 正是 `ReturnType` 的实现思路

### 02-TypeScript 工程实践

- **tsconfig 是落地之基**：`strict`/`strictNullChecks`/`noImplicitAny`/`noUncheckedIndexedAccess`/`paths` 逐项配好；`paths` 只影响编译期类型解析，运行时还要在 Vite/Webpack 的 `resolve.alias` 同步同一份映射
- **落地分层推进**：先选编译方案（Vite 用 esbuild 转译 + tsc 单独做类型检查）→ 拿自然推导 → 边界显式声明（如 `request<T>` 泛型封装把响应类型带进来）→ 类型驱动开发
- **.d.ts 声明文件**：`declare` 只描述类型/形状、编译时不产生任何 JS 输出；全局声明、`declare module "xxx"` 模块声明、`declare global {}` 模块内补充全局三种形态
- **断言克制、守卫优先**：`as` 是「信任声明」要谨慎用；typeof/instanceof/in/自定义谓词才是安全的收窄方式；可辨识联合（discriminated union）是处理复杂状态的头号推荐方案
- **类型体操范式**：条件类型 + `infer` + 映射 + 递归三大基础模式；内置工具类型（Partial/Pick/Record/Awaited/ReturnType 等）高频实用，不必背题
- **构建集成与 JS→TS 迁移**：Vite 把 `tsc --noEmit` 独立为脚本、Webpack 用 ts-loader/babel-loader；迁移要渐进式——先 `allowJs` 跑通 → 逐步收紧严格度 → 排查 any → 纳入 CI，切忌一次性推翻重建

## 代码与自测入口

配套代码项目：`./code`，启动 `node server.js` 后打开 `http://localhost:5178/`（零依赖静态服务器，无需 `npm install`）。

- `structural.html`：结构类型（鸭式辨型）可视化
- `union-intersection.html`：联合/交叉类型可视化
- `generic-infer.html`：泛型与 `infer` 原理可视化
- `utility-practice.html`：手写 Partial/Exclude 工具类型
- `check.ts`：可用 `tsc` 直接编译做类型检查自测

原理一句话：interface、联合交叉、泛型、映射/条件类型都只存在于**编译期**，运行时执行的仍是普通 JS，所以这些 demo 用 JS 对象把类型概念「可视化」出来即可直观看到它们的含义。
