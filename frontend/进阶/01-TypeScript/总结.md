# 模块总结 · TypeScript

## 知识主线

两篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 TypeScript 类型系统（类型怎么描述数据）
        │  类型注解会写了，但"严格模式怎么配、声明文件怎么写、怎么落进真实项目"还不知道
        ▼
02 TypeScript 工程实践（类型怎么在真实项目里落地）  ★主轴
```

本模块的主轴是**类型系统**：01 篇讲类型本身——基础类型、接口、类、函数、泛型、推断与高级类型，把"类型如何描述数据"讲透；02 篇讲它在真实工程里如何配置与应用——tsconfig 严格度、.d.ts 声明、类型守卫与可辨识联合、类型体操、内置工具类型，以及构建集成与 JS→TS 迁移，把"会写类型"升级为"能在真实项目里优雅落地"。

## 分篇知识点

### 01-TypeScript 类型系统

- **安装与配置**
  - **npm 安装与 `tsc` 编译**：`npm i -g typescript` 后用 `tsc` 编译文件，`tsc -v` 查看版本
  - **tsconfig.json 关键选项**：`target`/`strict`/`strictNullChecks`/`module`/`outDir` 描述编译行为
  - **`strict` 与 `strictNullChecks`**：`strict` 是整套严格模式的总开关，`strictNullChecks` 严格区分 `null`/`undefined` 是写出安全代码的关键
  - **直接运行工具**：`ts-node` / `tsx` 让 TypeScript 直接运行而不必先编译
- **基础类型**
  - **原始类型**：boolean/number/string 与 JS 一致，number 支持二进制/八进制字面量，string 支持模板字符串；数组用 `T[]` 或 `Array<T>` 两种写法
  - **元组 Tuple**：已知元素数量和类型的数组，各元素类型不必相同，按索引访问得到对应类型
  - **枚举 enum**：为一组数值赋予友好名字，默认从 0 编号，支持手动赋值与数值反向查找名字
  - **特殊类型**：any 跳过类型检查需克制使用；void 表示无返回值；null/undefined 在 strictNullChecks 下需显式联合；never 是任何类型的子类型、只能赋给它自己；object 表示非原始类型
  - **symbol 与 bigInt**：symbol 是独一无二的值、可作对象属性名且不参与常规枚举（需 getOwnPropertySymbols 取到）；bigint 安全存放大整数（超出 MAX_SAFE_INTEGER 精度不丢），需 target ES2020
- **接口与类**
  - **interface 结构性子类型化**：用「鸭式辨型」检查值的外形，只关注属性存在且类型匹配、不关心顺序与多余属性
  - **接口的进阶能力**：可选/只读属性、额外属性检查、函数类型（调用签名）、可索引类型、继承与混合类型
  - **类的访问修饰符**：public/private/protected，`private` 兼容性要求来自同一处声明，protected 成员派生类仍可访问
  - **readonly 与参数属性**：构造器参数加 readonly/private/public 修饰符即可一处定义并初始化成员，getter/setter 存取器截取成员访问
  - **抽象类与类即类型**：抽象类可含实现细节、抽象方法必须在派生类实现；类声明同时产出实例类型与构造函数值，可当接口使用
  - **装饰器**：附加在类/方法/属性/参数上的特殊声明（需 experimentalDecorators）；类装饰器扩构造函数、方法装饰器改写 descriptor 实现 AOP；属性方法装饰器先执行、类装饰器最后且自下而上
- **函数与泛型**
  - **函数类型与参数**：完整函数类型由参数与返回值用 `=>` 连接，支持可选/默认/剩余参数、`this` 参数与函数重载
  - **泛型保持同型**：类型变量 `T` 保持「传入与返回同型」，支持泛型接口与泛型类，静态属性不能使用泛型类型
  - **泛型约束**：`T extends` 约束泛型必须满足某接口，`keyof` 约束类型参数保证属性存在于对象上
- **类型推断与高级类型**
  - **类型推断**：最佳通用类型兼容所有候选类型、上下文类型按表达式的类型及所在位置推断
  - **交叉与联合类型**：`&` 把多个类型合并为一个类型（常用于混入），`|` 表示值可以是几种类型之一
  - **类型守卫**：typeof/instanceof/自定义谓词 `x is T` 在运行时收窄类型
  - **可空类型与非空断言**：strictNullChecks 下 null/undefined 需显式联合，用守卫、短路运算符或非空断言 `!` 去除 null
  - **字符串字面量类型**：指定字符串必须具有的确切值，常与联合类型配合实现类似枚举的效果
  - **映射类型与索引访问**：`keyof T` 取所有 key 的联合、`T[K]` 取对应值类型，映射类型基于旧类型创建新类型（如把属性变可选或只读）
  - **条件类型与 infer**：`T extends U ? X : Y` 按类型关系选结果，配合 `infer` 可提取函数返回类型
- **内置工具类型**
  - **`Partial<T>`**：把 T 所有属性变可选，常用于表单局部更新
  - **`Required<T>`**：把所有属性变必选，与 Partial 相反
  - **`Pick<T, K>`**：从 T 中挑出 K 指定属性组成新类型
  - **`Omit<T, K>`**：从 T 中剔除 K 属性
  - **`Record<K, V>`**：以 K 为键名、V 为值类型构造对象类型
  - **`Readonly<T>`**：所有属性只读
  - **`ReturnType<T>`**：取函数返回值类型，实现思路是条件类型 + infer
  - **`Awaited<T>`**：解包 Promise 得到最终值类型

### 02-TypeScript 工程实践

- **tsconfig 是落地之基**
  - **基础目标与模块**：`target` 编译目标、`lib` 可用类型库、`module` 模块系统、`moduleResolution: Bundler` 打包器解析策略
  - **strict 系列严格检查**：`strict` 总开关开启全部严格检查；`strictNullChecks` 严格区分 null/undefined、`noImplicitAny` 禁止隐式 any、`noUncheckedIndexedAccess` 标记索引访问可能为 undefined
  - **paths 路径别名**：`@/*` 映射到 `src/*`；只影响编译期类型解析，运行时还要在 Vite/Webpack 的 `resolve.alias` 同步同一份映射
  - **输出与产物体**：`noEmit` 只做类型检查不输出 JS、`isolatedModules` 配合打包器逐文件转译、`esModuleInterop` 兼容 CJS 依赖、`resolveJsonModule` 允许直接导入 JSON
- **落地分层推进**
  - **先选编译/运行方案**：Vite 项目开箱即用 TS（esbuild 转译 + tsc 单独做类型检查），Webpack 用 ts-loader 或 babel-loader
  - **自然推导与边界显式**：让 TS 自己推断尽量不写多余注解，函数参数/返回类型、API 请求/响应等边界必须显式声明
  - **类型驱动开发**：定义好领域模型（interface/type）后编译器兜底所有引用处；`request<T>` 泛型封装把响应类型带进来
- **.d.ts 声明文件**
  - **declare 只描述类型**：`declare` 只描述类型/形状，编译时不产生任何 JS 输出
  - **全局声明与模块内补充**：顶层 `declare const/function/class` 声明全局变量，`declare global {}` 在模块内向全局命名空间补充声明
  - **模块声明与简写兜底**：`declare module "xxx"` 声明无类型模块或做模块增强；`declare module "*.less"` 等简写是兜底，能用正式类型就不要堆 any 化声明
- **断言克制、守卫优先**
  - **类型断言 `as`**：是「信任声明」要谨慎用、不掩盖类型漏洞；`as const` 制造字面量类型
  - **运行时守卫收窄**：typeof/instanceof/in/自定义谓词 `x is T` 才是安全的收窄方式
  - **可辨识联合**：用 `status` 等字段区分各分支，处理复杂状态的头号推荐方案，效率与类型安全兼得
- **类型体操范式**
  - **三大基础模式**：条件类型（三元 + infer 提取）、映射类型（遍历键、键重映射）、keyof + 索引访问
  - **递归模板**：如 `[...infer _Rest, infer L]` 对齐解构元组，实现取首尾元素等类型操作
  - **内置工具类型实战**：typeof/keyof 取值的类型与键名，Partial/Required/Pick/Omit、Record/Readonly/ReturnType、Awaited 拆 Promise、NonNullable 去空，高频实用不必背题
- **构建集成与 JS→TS 迁移**
  - **Vite 集成**：把 `tsc --noEmit` 独立为 typecheck/build 脚本，保证无类型错误再产出；`resolve.alias` 与 tsconfig `paths` 同步同一份映射
  - **Webpack 集成**：ts-loader 真正编译并带类型检查（更慢），babel-loader 更快但无类型检查，需单独 tsc 兜底
  - **渐进式迁移**：先 `allowJs` 跑通 → 逐步收紧（noImplicitAny → strictNullChecks → strict）→ 排查 any（unknown 优先）→ 把 `tsc --noEmit` 纳入 CI，切忌一次性推翻重建
  - **迁移常用技巧**：`@ts-nocheck` 跳过暂不迁移文件、`@ts-expect-error` 更严谨的逐行忽略、优先 `@types/xxx` 再写 .d.ts
