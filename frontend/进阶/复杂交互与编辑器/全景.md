# 复杂交互与编辑器全景

## 一、四个问题域：共同点是「状态与位置难管」

富文本、协同、复杂表单、流程编排看起来是四个领域，难的是同一件事：**状态不再是一个值，位置不再是一个数字**：

| 问题域 | 核心难点 | 状态模型 | 本模块篇目 |
| --- | --- | --- | --- |
| 富文本编辑 | 浏览器写 DOM 不受控；文档一变「位置」就失效 | 文档模型 + 位置映射 | [富文本与编辑器架构](./富文本与编辑器架构.md) |
| 协同编辑 | 位置会被别人的编辑失效 | OT 变换 / CRDT 字符身份 | [协同编辑](./协同编辑.md) |
| 复杂表单 | 派生值定序、联动传播、异步竞态 | schema + 依赖图 + 订阅粒度 | [复杂表单引擎](./复杂表单引擎.md) |
| 流程交互 | 布尔标志位组合爆炸、幽灵定时器 | 显式状态机 + 事件日志 | [状态机与流程编排](./状态机与流程编排.md) |

一条主线贯穿：**把「状态是什么」（数据模型）与「状态怎么渲染」（组件）分开**——编辑器分离文档模型与视图、表单分离 schema 与渲染器、流程分离状态机与 UI。分离之后才有可测试性、可撤销性、可协同性。

## 二、与相邻板块的分工

- **低代码与搭建体系**：讲「schema 驱动的页面从哪来」（协议 → 渲染 → 编辑器 → 出码）；本板块讲「编辑器内部的交互内核」（模型、选区、联动、状态机）——低代码编辑器的属性面板联动就是本模块表单引擎的子问题，画布的撤销重做就是本模块状态机的应用。
- **可视化与图形**：讲像素与帧预算；本板块讲字符、位置与状态空间。

## 三、统一业务场景：工单系统

四个问题域绑同一个场景：**工单系统**。

- **富文本**：工单描述支持加粗/列表（受控 contentEditable，粘贴清洗）；
- **协同**：客服与用户同时编辑工单备注（yjs，撤销只撤自己的）；
- **表单**：工单表单几十字段联动（城市级联清值、金额派生、工单号异步查重）；
- **流程**：工单生命周期（草稿 → 提交 → 处理中 → 完成/驳回），守卫拦非法提交、超时自动升级、事件日志可重放。

真实工程 `code/collab-app/`（vite + yjs，`npm run dev` 起 5202）实现了协同一环的完整可玩版本：双客户端实时收敛、撤销只撤自己的、墓碑可视化、光标感知。

## 四、本模块的探针实验台

`editor-lab`（`node run.cjs` 依次执行）把四篇机制钉死：

```
model.cjs   位置映射（插入分左右/删除分三段）/ 选区归一化 / 操作合并
crdt.cjs    OT 变换收敛 / CRDT 字符模型 / 墓碑 vs 真删对比 / 穷举到达顺序
form.cjs    依赖拓扑求值 / 联动清值收敛 / 异步校验竞态 / 订阅粒度对比
flow.cjs    转移表 / 守卫与幽灵定时器 / DAG 分层+补偿 / 事件重放
```
