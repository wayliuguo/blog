# 复杂交互与编辑器：模块总结

> 本模块 4 篇，回答一个问题：**编辑器、协同、动态表单与状态机这些「硬骨头」怎么啃。**

## 知识主线

```
01 富文本与编辑器架构（contentEditable / 数据模型 / 选区光标 / 操作合并）
        │  一个人编辑已经稳了，多人同时改怎么办？
        ▼
02 协同编辑（OT 与 CRDT / 删除墓碑 / 收敛性验证）
        │  交互复杂度不只来自协同，还来自"字段互相依赖、状态互相嵌套"
        ▼
03 复杂表单引擎（依赖求值 / 联动传播 / 异步校验 / 订阅粒度）
        │  表单之上还有流程：状态怎么管、任务怎么编排
        ▼
04 状态机与流程编排（转移表 / 守卫与延迟 / DAG 重试与补偿 / 事件重放）
```

四篇的共同底色是同一件事：**把隐含状态显式化**。编辑器的隐含状态是 DOM，协同的隐含状态是位置，表单的隐含状态是组件 state，流程的隐含状态是一堆布尔量——把它们各自变成可枚举、可验证、可重放的数据结构，复杂度才真正可控。

## 分篇知识点

### 01-富文本与编辑器架构

- **三条路线**：裸 contentEditable（产物脏）、受控 contentEditable（主流）、完全自绘（可控但工作量最大）
- **contentEditable 三个陷阱**：产物不可控、行为不一致、与框架渲染冲突（打字光标跳开头）
- **位置映射实测**：插入左右分治（正好插在光标处时光标停在原字符前）、删除三段（区间内拉回起点）
- **选区归一化实测**：反向拖选整体交换并保留 `forward=false`；越界 offset 与块索引裁剪到合法范围
- **操作合并实测**：逐字符输入 5 次 → 历史只剩 1 条 op；跨客户端与不相接位置不合并
- **三个躲不掉**：输入法隔离（`compositionstart/end` 吞字）、粘贴白名单清洗、大文档分块渲染
- **schema 必须有**，否则只能无限追赶浏览器的脏 DOM

### 02-协同编辑

- **问题根源**：操作记录位置，位置因他人编辑失效；朴素覆盖丢字
- **OT 实测**：同位置并发插入 A/B，两条路径都收敛为 `"abxce"`，裁定规则 clientId 小的在前
- **OT 代价**：变换矩阵随操作类型平方增长、需中心服务定序、正确性难证明
- **CRDT 实测**：同一位置并发插入，两种到达顺序都为 `"bx"`；排序靠 left-origin + clientId
- **删除墓碑实测**：删 b 与「在 b 后插入 x」并发，墓碑版两种顺序都为 `"ax"`，真删版发散为 `"xa"` / `"ax"`
- **墓碑的代价**：文档只增不减，需服务端定期压缩
- **收敛性实测**：3 客户端并发、6 种到达顺序结果唯一；验证要穷举而非随机
- **工程现实**：优先 Yjs；撤销只撤自己的（区间要映射）；awareness 不进文档；算法不解决语义冲突

### 03-复杂表单引擎

- **schema 驱动**：把「表单是什么」（schema + 值 + 规则）与「怎么渲染」分开，前者是纯数据、可单测
- **依赖求值实测**：qty 3→10 时 amount 60→200、discount 0→10、payable 60→190；拓扑序 + 三态访问标记检测成环
- **联动传播实测**：改 province 级联清空 city/district（2 次传播），目标已为空时不传播（0 次）
- **互清陷阱**：不会死循环（值不再变化即收敛），代价是用户刚选的 province 被反向抹掉——配置错误而非性能问题
- **赋值型互推**（每次写入新值）才会无限传播，靠深度上限兜底
- **异步校验竞态**：连发 a/ab/abc、返回顺序 ab→a→abc，只有 abc 的结果被采纳；**防抖管请求量，序号管结果归属**
- **订阅粒度实测**：100 字段改 1 个，全量订阅唤醒 100 个 vs 按字段订阅唤醒 1 个（100×）；写入相同值 0 通知
- **选型边界**：字段少别上引擎；schema 需要持久化/迁移/出码时才值得自研

### 04-状态机与流程编排

- **状态空间**：n 个布尔量给出 2ⁿ 种组合、绝大多数非法；状态机收缩为 n 个显式命名状态
- **转移表实测**：`idle` 下 `send('onSuccess')` 返回 `rejected` 且状态不变，合法路径正常
- **非法事件绝不静默**：返回 `rejected`；`can(event)` 让 UI 能提前禁用按钮
- **守卫**：区分「没有这条边」（`rejected`）与「有边但被条件拦下」（`blocked`）
- **幽灵定时器实测**：`onCancel` 后定时器被清（`pending=false`），到点也不再转移；超时目标必须跟着状态走而非写死在边上
- **DAG 编排实测**：5 节点分层只需 4 轮（串行 5 步）；`pay` 失败 2 次后第 3 次成功（attempts=3）
- **补偿必须逆序**：`undo:merge → undo:fetchOrder → undo:fetchUser`；补偿本身也要重试与告警
- **事件重放实测**：8 个事件里 `onRetry` 被拒且不入历史，重放 50 次状态恒为 `success`；重放不一致说明混入了隐藏状态

## 最小实现

- **`editor-lab`**：零依赖探针实验台，`node run.cjs` 依次执行四探针（位置映射/选区归一化/操作合并 · OT 变换/CRDT/墓碑/收敛 · 依赖求值/联动清值/异步校验/订阅粒度 · 转移表/守卫与延迟/DAG 编排/事件重放），`node:assert` 自检全绿
