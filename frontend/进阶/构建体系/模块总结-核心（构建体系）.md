> 精简核心版：按篇分组、抽出高频/重要的知识点——成员丰富的主题展开明细，要点型知识点列清单、点到为止。选点按「面试命中度 / 日常复用度」等维度（见[文档组织规范](../../../文档组织规范.md)）。详细知识树见[《模块总结 · 构建体系》](./总结.md)。

## 知识主线（一句话）

构建体系的主轴是**构建**：01 给全景与选型坐标系，02 讲第一道工序编译与 AST，03~06 拆开 webpack / Vite / Rollup / esbuild 与 Rust 工具链的机制，07 讲如何写扩展，08 回到产物讲体积从哪省，09 用手写 mini-bundler 把概念自己实现一遍。两个贯穿判断：**构建速度差距主要来自「开发态要不要拼装」；产物体积差距主要来自「引用方式与副作用」而不是压缩**；打包成 CJS 会改变模块语义（ESM 活绑定与 TDZ 退化为静默 undefined）。

## 高频核心点

### 01 构建全景与选型

- **构建四步**：解析建图 → 转换 → 拼装 → 优化输出；生产必须全做，开发环境可少做
- **三代工具**：任务流（不解析依赖）→ 打包器（依赖图）→ 原生 ESM + 原生语言；第三代把打包从开发态挪走
- **实测对比**（200 模块）：esbuild 557ms / rollup 1303ms / webpack 3698ms；进程总耗时多约 400ms Node 启动成本
- **tree-shaking 真相**：webpack 是「标记（usedExports）+ 删除（压缩器）」两步，只声明 `sideEffects:false` 不删代码必须开 minimize
- **选型**：应用 → Vite/webpack（需 MF 用 webpack）；库 → Rollup；工具链 → esbuild；生产构建 8.x 起走 Rolldown

### 02 编译与 AST

- **编译器三件事**：parse（文本→树）、transform（改树）、generate（树→文本）；**AST 与源码是两份数据**，改树必须 generate
- **AST 结构**：顶层 Program、语句在 `program.body`；`type` 决定字段，靠 astexplorer 查；增删改需要路径（Path）而非朴素遍历
- **visitor 模式**：按节点类型回调；判断用 `t.isXxx`、构造用 `t.xxx()`、容器操作传父节点字段名
- **写 Babel 插件坑**：替换后会被重新遍历可能递归；plugins 先于 presets（plugins 顺序、presets 逆序）
- **codemod**：正则误伤字符串注释、AST 不会；generate 会重写格式→先统一格式化基线再跑
- **工具选择**：自定义转换用 Babel、只求快用 SWC/esbuild；类型检查永远交给 `tsc --noEmit`

### 03 Webpack 深入

- **五个对象**：Compiler（进程级）/ Compilation（一次编译）/ Module / Chunk / Asset；模块数 ≠ 文件数，中间隔 Chunk 分组
- **loader**：本质是「源码字符串 → 代码字符串」的函数；链式从右往左、结果会被缓存
- **plugin**：有 `apply(compiler)` 的对象；产出文件用 `compilation.emitAsset` 不用 `fs.writeFileSync`；`processAssets` 带 `stage`
- **SplitChunks**：minChunks / minSize（默认 20KB）/ 匹配规则三个条件同时满足才抽；vendor 与路由级值得切、小共享模块不值得
- **持久化缓存**：缓存目录进 CI 缓存；`require('webpack')` 本身要 2.8~3.3s，墙钟时间淹没优化效果；诡异问题先删缓存目录
- **运行时代价**：业务 981B / 运行时 6.37KiB；库不该用 webpack 打包，`runtimeChunk:'single'` 值得开

### 04 Vite

- **双引擎**：dev 用 esbuild 预构建 + 单文件转换、浏览器原生 ESM 不打包；build 8.x 起默认 Rolldown 全量打包
- **依赖预构建**：解决 CJS→ESM 与碎片合并；`optimizeDeps.include` 提前声明避免中途重预构建；`exclude` 给本地 workspace 包留活路；缓存 `node_modules/.vite` 诡异问题先删
- **环境变量**：编译期静态替换，只有 `VITE_` 前缀暴露、不能动态拼 key；`define` 替换代码文本必须 `JSON.stringify`
- **产物形态**：`assetsInlineLimit` 决定内联/发文件；`build.target` 只管语法不管 API；`import.meta.glob` 默认懒加载、`eager` 合并
- **HMR**：只重转变更模块 + WS 通知，与项目规模无关；没有 accept 边界冒泡不到就整页刷新，`handleHotUpdate` 可接管

### 05 Rollup

- **ESM 优先**：静态 import 让构建期拿完整依赖图，收益精确 tree-shaking、作用域提升、无运行时注入；CJS 要靠插件、动态 require 不支持
- **tree-shaking 两档控制**：`/*#__PURE__*/` 管表达式、`moduleSideEffects` 管模块；对比 webpack——Rollup 一步完成、webpack 要两步
- **五种输出格式**：esm 最小 → cjs → iife → system → umd；差异只在包裹层、只有 es 能被二次 tree-shaking
- **四个产物开关**：`external`（打不打进来）、`output.globals`（UMD/IIFE 外部全局变量）、`manualChunks`（拆几文件）、`preserveModules`（一比一还原源目录，组件库）
- **两类钩子**：build 钩子一次构建只跑一次、output 钩子每个 output 各跑一次
- **体积门禁插件**：`generateBundle` 里算 gzip、卡阈值、出 manifest；量 gzip 而非 raw、按 chunk 定阈值

### 06 esbuild 与 Rust 工具链

- **两个 API**：`transform` 只转换不解析依赖、`build` 建依赖图出产物；首次调用含加载原生二进制约 700ms
- **target**：降级要注入运行时辅助代码，由浏览器基线决定、不是越新越好
- **三工具对比**（50 次转换）：SWC 0.13ms / esbuild 1.50ms / Babel 20.10ms（167x）；单文件转换 SWC 赢、整包构建 esbuild 赢（跨进程开销）
- **Rust 全景**：SWC 替 Babel、Rspack 替 webpack、Rolldown 替 Rollup、Biome/Oxlint 替 ESLint/Prettier；选型关键是替换成本（配置兼容/行为一致/插件生态）
- **不该换**：构建只要几秒、重度自定义 Babel 插件、瓶颈不在构建、无人能排查

### 07 构建插件开发

- **扩展点只有三类**：解析（resolveId/load）· 转换（transform/loader）· 产物（generateBundle/emitAsset）
- **三套钩子差异根源**：Rollup/Vite 声明式"回答 id 与内容"；webpack 模块必须真实存在、内容由 loader 加工
- **unplugin**：一份实现跑 Rollup/Vite/webpack；API 用 `unplugin.rollup(options)`；代价是只能用它抽象的那层
- **六个坑**：虚拟 id 别用冒号、未被引用的导出会被摇掉、Vite 虚拟模块要 `enforce:'pre'`、transform 要还 sourcemap（magic-string）、分清 dev/build（`config.command`）、webpack 改配置要趁早

### 08 产物分析与体积优化

- **顺序**：先看清产物（元数据/可视化/读文本），再选手段
- **体积四类来源**：业务代码（tree-shaking/分割）、第三方依赖（换轻依赖/按需引入）、重复打包（dedupe/external）、产物形态（压缩/现代语法）
- **引用方式**：`import * as ns` 再 `export` 出去是摇不到失效点；CJS 产物无法静态分析、改引用无效
- **副作用**：顶层副作用整块保留；`sideEffects` 是给打包器的承诺、数组外文件可整块删
- **代码分割**：改的是"体积分布"不是"总量"（实测首屏 2946→175）；粒度按路由 > 按交互 > 按依赖
- **压缩**：不能替代 tree-shaking（压缩后仍差 20 倍）；传输体积还要过 gzip/brotli
- **误区**：拆包可能总体积变大；vendor 收益来自 hash 稳定、不在抽取本身

### 09 手写 mini-bundler

- **四步骨架**：解析依赖 → 建模块图 → ESM→CJS 转换 → 生成运行时 + 模块表；真实打包器结构相同、差别只在运行时
- **依赖解析**：相对路径以「引用者所在目录」为基准所以要带 `importer`；补后缀 `.js`/`index.js`
- **建图**：`modules.has` 兼做去重与防环；「先登记再递归」是循环依赖不爆栈前提；id=发现顺序 DFS 前序
- **转换**：四种 import → `__require(id)` + 解构；删关键字 + 末尾统一赋值，代价是快照而非活绑定
- **运行时**：cache 让模块只执行一次；`cache[id]=module` 必须早于执行否则循环依赖死循环
- **循环依赖实测**：函数导出 ESM 读到 `function`、产物 `undefined`；const 导出 ESM 抛 `ReferenceError`、产物静默 undefined——打包把加载期错误推迟成运行期 undefined 是 CJS 固有代价
