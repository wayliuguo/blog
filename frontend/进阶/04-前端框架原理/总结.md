# 模块总结 · 前端框架原理

## 知识主线

两篇不是并列的两堆 API 知识，而是围绕同一个问题展开的两条实现路径——**"状态/数据变了，框架如何以最小代价把界面更新到最新"**。每一篇都在回答上一篇留下的问题：

```
01 React 高级与原理（组件状态一变，React 怎么知道改哪里）
        │  先建立基线：渲染 = render/commit 两阶段
        │  → 虚拟 DOM + diff 三条启发式求最小变更
        │  → Fiber 链表把大更新拆成可中断小单元
        │  → Hooks 链表按调用顺序在 Fiber 上存状态
        ▼
02 Vue3 原理（同一个问题，另一条工程路径）
        │  编译：模板 → render 函数 + 静态标记（能提前确定的就不进 diff）
        │  → 响应式：Proxy 代理 + track/trigger（数据一变知道通知谁）
        │  → 运行时：createRenderer + patch 按差异落地（scheduler 批量更新）
        ▼
共同收口：状态变化 → 以最小代价把界面更新到最新
```

本模块的主轴是**"状态到界面的最小代价映射"**：01 篇以 React 为样本建立"渲染分两阶段 + 虚拟 DOM/diff + 链表（Fiber、Hooks）"这条基线，02 篇在同一个问题域里看 Vue3 的另一种实现——用编译期静态标记省掉不必要的 diff，用 Proxy 响应式把更新精确到"哪个数据变了、通知谁"，再交给运行时 patch 落地。两篇对照，React"运行时 diff + 可中断调度"与 Vue3"编译优化 + 精确响应式"的取舍与分工就清楚了。

## 分篇知识点

### 01-React 高级与原理

- **render / commit 两阶段**：Render 是纯计算、可中断，只构建新虚拟 DOM / Fiber 并算 diff，不碰真实 DOM；Commit 不可中断，一次性应用变更并执行副作用（`useEffect` / 生命周期 / ref 赋值）——"纯函数在前、命令式在后"
- **Fiber 链表与双缓存**：Fiber 是普通 JS 对象，靠 `child` / `sibling` / `return` 三个指针构成双向链表树，把大更新拆成小单元逐个处理；同时维护 current 与 workInProgress 两棵树，完成后原子切换指针，构建被打断也不影响屏幕
- **并发特性**：时间切片 + 可中断渲染，`createRoot` 即开启；`startTransition` / `useTransition` / `useDeferredValue` 把非紧急更新标记为低优先级，让输入、点击先响应
- **虚拟 DOM 与 diff 三条启发式**：不同类型直接重建整棵子树、同类型只更新 props、同层兄弟列表用 key 定位，把复杂度从 O(n³) 压到 O(n)
- **key 的真正意义**：有 key 能识别"同一节点被移动"、只新增缺失项；没有 key 或用 index 会按索引对号入座，导致不必要的更新甚至状态错乱（如输入框内容串位）
- **优化三板斧**：`React.memo` 浅比较缓存组件、`useMemo` 缓存计算结果、`useCallback` 缓存函数引用；memo 是浅比较，内联对象 / 新函数会让它失效，需配合引用稳定与状态下沉
- **Hooks 是 Fiber 上的链表**：每个函数组件的 Fiber 节点上挂着 hooks 链表（`memoizedState`），按调用顺序存取，所以必须顶层、固定顺序调用，放 if / 循环里就会错位
- **代码分割**：`lazy` + `Suspense` + 路由懒加载按需加载 chunk，配合 Gzip 与长缓存减小首屏体积

### 02-Vue3 原理

- **三大模块协作**：编译模块把模板"翻译"成 render 函数，运行时拿到 render 创建 VNode 并挂载 / 更新到真实 DOM，响应式模块为数据提供变更追踪——"用编译换说法、用响应式驱动、用运行时落地"
- **Proxy 响应式 vs Object.defineProperty**：`reactive` 用 Proxy 代理整个对象，支持属性增删检测、数组与 Map/Set 集合、深度响应式（访问时自动再代理）；WeakMap 做代理缓存与依赖存储，键是对象、弱引用可被 GC 回收避免内存泄漏
- **track / trigger 依赖收集**：targetMap（WeakMap）→ depsMap（Map）→ dep（Set）三层结构；get 时 track 把 activeEffect 收进 dep，set 时 trigger 取出所有 effect 执行；readonly 不做依赖收集（不可 set 就永远不会触发）
- **ref 与自动解包**：RefImpl 把基本类型值包进对象再代理（值为对象自动转 reactive）；`proxyRefs` 用 Proxy 让模板里写 `count` 而非 `count.value`
- **computed / watch**：computed 基于 lazy 的 ReactiveEffect，靠 `_dirty` 脏标记实现缓存与惰性；watch 是 effect 的封装，源变化经 scheduler 回调执行用户函数，支持 immediate / deep / flush
- **模板编译与静态标记**：compiler-sfc 拆 .vue 三块，compiler-core 走"解析 → 转换 → 代码生成"；编译期给节点打 PatchFlags 静态标记，只有动态节点参与更新对比，静态节点直接跳过
- **运行时与虚拟 DOM diff**：runtime-dom 通过 `createRenderer` 注入宿主操作，patch 按 shapeFlag 位运算分发到元素 / 组件 / 文本；更新时 diff 新旧 VNode 生成最小补丁，渲染 effect 包上 scheduler 实现异步批量更新（nextTick）
- **组件运行时能力**：生命周期钩子是"特定时机调用的用户函数集合"；props 用 shallowReadonly 代理防止子组件改父值；provide / inject 借原型链（`Object.create`）实现就近覆盖、向上查找

## 代码与自测入口

配套代码项目：`./code`（零依赖静态服务器 + 6 个原生 JS demo，无需 `npm install`）。启动方式：在 `code` 下执行 `node server.js`（`npm start` 等价），然后打开 `http://localhost:5182/`，从 index 页进入各 demo，浏览器直接可跑。

React 侧 3 个，对应 `01` 篇：

- `mini-runtime.html` —— 手写极简渲染器 createElement + render + onUpdate（虚拟 DOM + 声明式更新）
- `vdom-diff.html` —— 两棵轻量虚拟 DOM 树做最小 diff，输出生成的 patch
- `hooks-demo.html` —— 用普通数组实现极简 useState / useEffect（hooks 调用顺序原理）

Vue3 侧 3 个，对应 `02` 篇：

- `mini-reactive.html` —— 手写 Proxy 版响应式 track / trigger（读时收集、改时触发）
- `vdom-vue-diff.html` —— 轻量 VNode 树 diff 生成 patch（按差异补丁更新）
- `compiler-demo.html` —— 模板字符串 → 渲染函数（编译模块最小实现）
