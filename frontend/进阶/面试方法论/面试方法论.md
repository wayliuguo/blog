# 面试方法论

本篇把"怎么答好一道前端面试题"从零散经验里抽成一套可复用的方法。核心主张只有一条：**答题结构由"题型"决定，而不是一套模板通吃**。无论你刷的是各模块的面试题页，还是自己整理的题目，这套框架都能直接套上去用。

---

## 一、题型驱动答题法

### 为什么不是"五步答题法"

统一走「结论 → 原理 → 场景 → 边界 → 追问」五步有两个问题：

- **平均用力**：简单题（`src` 与 `href` 区别）也被迫凑出"场景举例、优缺点"，答得冗余、重点被稀释。
- **题型不分家**：概念题、对比题、场景题共用一套模板，每类题真正要突出的关键点反而被埋没。

所以改成**先按题型定骨架**——每类骨架 2–3 步，几步用不上就果断跳过。

### 4 类题型与骨架

| 题型 | 骨架（2–3 步） | 一句话标注 |
|------|----------------|-----------|
| **概念题**（是什么） | 定义一句 → 为什么/原理 → 反例或边界 | 讲"它是什么" |
| **机制题**（怎么工作） | 输入→过程→输出（步骤/时序）→ 一个关键细节 | 讲"它怎么动起来的" |
| **对比题**（A vs B） | 一句话本质区别 → 按固定维度列对比 → 一句实际取舍 | 讲"它俩差在哪" |
| **场景/选型题**（怎么办） | 目标 → 排查/步骤顺序 → 最终选型或修复 | 讲"出问题时怎么做" |

每种题型第一句都必须是**一句能背下来的判断句**，先给结论保证不冷场；往深答与否由题型骨架和时间决定。

### 归型原则

- **题型由"题眼"决定**，而非"题目里有几个知识点"。看面试官真正问什么——"解释原理"归机制、"给方案"归场景。
- 一道题既涉及机制又涉及场景时，以主题型为主，另一类作纵深（不另起骨架）。

## 二、判定对照：题型驱动 vs 五步答题法

| 维度 | 五步答题法 | 题型驱动答题法 |
|------|-----------|----------------|
| 结构来源 | 统一五步（结论/原理/场景/边界/追问） | 由题型决定 2–3 步骨架 |
| 重点 | 平均用力，易冗余 | 每类题的关键点天然突出 |
| 题型适配 | 概念/对比/场景一套模板通吃 | 各自骨架，不凑步骤 |
| 时间匹配 | 五步全走易拖沓 | 骨架短，符合 1–3 分钟答题节奏 |

---

## 三、怎么用这套方法

- **自测**：遮住答案，只看题面判断题型 → 按对应骨架先答第一句结论，卡住就回到该模块正文补。
- **复习**：每个知识点过一遍"它属于哪类题型 + 骨架里的关键点"，答不出的标出来，回正文补漏，再回来用骨架重答一遍。
- **纵深**：一道题需要讲深时，按骨架往下钻（机制题讲完整时序、对比题列全对比维度），但仍以该题型为主线，不为凑步骤硬讲其它维度。
