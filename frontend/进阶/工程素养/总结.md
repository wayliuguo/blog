# 工程素养：模块总结

> 本模块 3 篇（L3），回答一个问题：**资深工程师的「怎么做」——方案、评审与事故复盘。**

## 知识主线

```
01 技术方案写作与架构评审（八块必备 / 取舍论证 / 风险矩阵 / 评审流程）
        │  方案过了，代码怎么进主干？
        ▼
02 代码评审与技术债治理（CR 自动化门槛 / 债的打分 / 重构安全网）
        │  都做到位了还是出事了，怎么办？
        ▼
03 线上事故复盘与应急响应（分级 / MTTD·MTTR / 行动项闭环 / 演练）
```

与 `面试方法论` 的边界：方法论教「怎么讲」，本模块教「怎么真的做出来并讲清楚」。

三篇的共同方法是同一条：**把靠人记住的东西变成可判定的规则**。方案八块必备项、CR 四条硬规则、行动项三要素——写成规则之后，它们就不再是"资深工程师的经验"，而是任何人都能执行、任何流程都能检查的东西。

## 分篇知识点

### 01-技术方案写作与架构评审

- **八块必备**：背景 / 目标 / 非目标 / 方案 / 取舍 / 风险 / 回滚 / 验证；实测缺 4 项时完整度不足 60%
- **非目标最容易被删**，删了之后评审就会反复拉扯范围
- **取舍要有 ≥2 个候选**，每个给结论 + 理由；只有一个候选的方案是「通知」不是「论证」
- **取舍只写结论**（如「选 SSR」）会被判弱——必须写被否决的方案与为什么
- **风险按 概率×影响 排序**：实测 SSR 内存上涨 1.8 > 缓存击穿 1.5 > SDK 超时 0.4
- **每条风险要带信号与兜底**：缺任一条即判未就绪（没有信号=不可观测，没有兜底=只能祈祷）
- **流程三件事**：会前指定主要评审人并预读、会中按风险排序且区分阻塞与建议、会后 24 小时出结论并同步更新文档
- **六个毛病**：目标不可度量、方案写成愿景、取舍只写结论、风险没兜底、回滚靠发版、验证靠感觉

### 02-代码评审与技术债治理

- **CR 四条自动规则**：改公共接口要兼容、加依赖要说明必要性、动构建配置要本地验证、>50 行要有测试——实测全命中的变更被拦下
- **自动化管门槛，人管判断**：命名、抽象、边界条件才是评审真正的价值
- **PR 大小**：超过 400 行缺陷发现率断崖下降，大改动要拆成可独立看懂与回滚的小 PR
- **技术债打分**：影响面 × 恶化速度 ÷ 修复成本
- **实测排序**：散落的工具函数 6.0（便宜且在扩散）> 核心模块没测试 5.0 > 硬编码路径 3.0 > 遗留 jQuery 0.8（贵但不恶化）
- **还债产能**：固定留 15%~20%；存量慢慢还，**新增必须有门槛**，否则永远赶不上欠的速度
- **重构安全网四件套**：测试 / CI / 回滚 / 监控；缺 0 项可大改、缺 1 项只小改、缺 ≥2 项先补网——没有网的重构就是赌博

### 03-线上事故复盘与应急响应

- **分级**：核心不可用或有资损 → P0（**与影响人数无关**）；大范围或核心降级 → P1；无绕过 → P2；可绕过 → P3
- **先定级再讨论**：级别决定谁被叫起来、多快响应、要不要升级
- **时间线拆两段**：MTTD（发现）+ MTTR（恢复）；实测 35min + 15min = 50min，瓶颈在发现
- **两段对应不同改进**：MTTD 靠监控告警，MTTR 靠预案与回滚能力——混在一起说"响应太慢"会改错地方
- **响应顺序**：先止血（回滚 / 降级 / 限流）再查根因，别在 P0 现场追根因
- **行动项三要素**：owner / 截止时间 / 验收标准，缺一即判不合规；实测 5 条只闭环 1 条（20%）
- **复盘原则**：对事不对人但要落到可执行的机制改进（"缺二次确认机制"而非"张三不小心"）；48 小时出初版、一周定稿
- **演练**：回滚、告警有效性、混沌演练、值班手册——**降级开关只有真切过才知道还在不在**

## 最小实现

- **`practice-lab`**：零依赖探针实验台，`node run.cjs` 依次执行三探针（方案必备项/取舍论证/风险矩阵 · CR 检查器/技术债打分/重构安全网 · 事故分级/MTTD·MTTR/行动项闭环），`node:assert` 自检全绿
