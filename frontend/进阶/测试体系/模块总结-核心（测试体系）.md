# 模块总结-核心（测试体系）

> 精简核心版：按篇分组、抽出高频/重要的知识点——成员丰富的主题展开明细，要点型知识点列清单、点到为止。选点按「面试命中度 / 日常复用度」等维度（见[文档组织规范](../../../文档组织规范.md)）。详细知识树见[《模块总结 · 测试体系》](./总结.md)。

## 知识主线（一句话）

测试体系的主轴是**单元测试那套"处理依赖"的方法论**，贯穿全模块：01 定策略与分层（该测什么、分几层），02 深入单元测试（纯逻辑 + 依赖处理：假定时器/替身/`vi.mock`），03 在组件层复用（契约 + 查询 + 异步三态），04 到 E2E 层变成"等条件而不是等时间"（flaky 根治），05 靠基建把这一切变成不依赖人自觉的机制（覆盖率只做增量阈值 + 门禁 + 报告趋势）。

## 高频核心点

### 01 测试策略与分层

- **测试买的三样东西**：防回归 / 设计压力 / 可执行文档；三条筛选题——挂了会不会立刻修、能否定位、重构时要不要改
- **五层分层**：静态检查（TS/ESLint，最便宜）→ 单元测试（毫秒级）→ 组件测试（props/事件/异步）→ E2E（关键路径/真实浏览器）→ 手工探索
- **金字塔 vs 奖杯**：前端更贴近**测试奖杯**——中间层最厚，因为逻辑长在组件里；比例按"反馈速度 × 定位精度 × 维护成本"定
- **测试点分级**：P0（主流程/钱权限，进 CI 门禁）/ P1（体验分支，建议）/ P2（边缘，允许手工）；不测清单：三方库、样式像素、实现细节
- **断言钉在行为上**：反模式 mock 依赖断言调用参数、重言式断言（期望用同一算法算）；正模式表驱动 + 手写常数期望 + 边界单独成例；硬标准是换了写法用例一行不改

### 02 单元测试深入

**Vitest 与断言**

- **Vitest 心智**：复用 Vite（TS/JSX/CSS 直接用）；`environment` 按文件切换（首行注释），纯逻辑用 node 更快；`globals` 保持关闭多一行 import 换来源清晰
- **用例组织**：describe/it/四种钩子；`only`/`skip`/`todo`/`fails`（锁已知 bug）；命令行按路径或 `-t` 过滤
- **断言**：`toBe`（原始）/ `toEqual`（深比较）/ `toStrictEqual`（连 undefined 属性也查）；写具体值而非 `typeof`，失败信息即定位线索

**时间与依赖处理**

- **假定时器**：`useFakeTimers` + `advanceTimersByTime`（等 300ms 变拨表）、`setSystemTime` 连 `Date` 冻结、涉及真实 await 用 `advanceTimersByTimeAsync`、用完必须 `useRealTimers`
- **四类替身**：stub（给固定答案不记录）/ spy（真实实现照跑只记录）/ mock（行为由测试指定并记录）/ fake（有内部状态能表达时序）
- **模块替换**：`vi.mock` 提升到顶部 + `importActual` 只替换部分导出；`vi.doMock` 需先 `resetModules`
- **替身纪律**：只 mock 边界（网络/时间/随机/全局）；必须还原 `restoreAllMocks`/`unstubAllGlobals`
- **参数化**：`it.each` 一行一条；factory 造数据新增字段不用改所有用例

### 03 组件测试

- **测的是契约**：渲染契约（props→渲染）/ 交互契约（操作→回调与状态）/ 异步契约（三态）；不测样式像素、动画时序、内部变量名
- **查询优先级**：Role → LabelText → Placeholder → Text → DisplayValue → AltText → Title → TestId
- **三种查询**：`getBy*`（必须存在）/ `queryBy*`（应该不存在）/ `findBy*`（最终会出现）；查不到时 RTL 打印整棵 DOM 即调试线索
- **模拟交互**：**user-event 比 fireEvent 真实**（完整事件序列）、`user.type` 逐字符输入、每次交互要 await
- **异步中间态**：**deferred 模式**手动控制 Promise 兑现稳定断言 loading；失败分支要断言按钮恢复可用；等条件（waitFor/findBy*）不等时间
- **反模式**：`container.querySelector` 按 DOM 结构查、整树快照、测内部 state
- **组织**：与组件同级 `.test.jsx`；抽 `renderXxx` helper 但不抽断言；`globals:false` 需显式 `afterEach(cleanup)`

### 04 E2E 与稳定性

- **E2E 守什么**：只放关键路径（登录/支付/跨页/三方集成），规模几十条
- **写法**：定位器语义化 `getByRole`/`getByLabel`/`getByText`；每用例自带完整前置不共享登录态；URL 用正则
- **自动等待**：web-first 断言自动重试到超时；**不写 `waitForTimeout`**；等 URL/Response/元素可见
- **数据准备**：每用例独立数据、前置用 API 造；三方依赖用 `page.route` 拦截、自己的系统接口不拦
- **flaky 四个根因**：sleep 赌时间（→等条件成立）、用例间共享状态（→beforeEach 重置 + shuffle 暴露）、依赖"现在"（→时间注入 `setSystemTime`）、时区（→固定 TZ/UTC）；反例写成确定性的 `it.fails`
- **规模化**：并行 worker 前提是数据独立；`retries` 只降噪不治本；治理流程量化 Top10 → 隔离 → trace 定位 → 修根因 → 重复跑验证 → 立规矩

### 05 测试基建与门禁

- **覆盖率口径**：语句/行/分支/函数四种，**分支覆盖最有信息量**；v8 快、istanbul 细，中途不要换 provider
- **覆盖率陷阱**：衡量"代码被执行"、"结果被验证"独立——弱断言能刷出 100% 覆盖、换强断言立刻暴露 bug
- **阈值策略**：不达标 → 非 0 退出码即门禁技术基础；**存量用增量覆盖率**；分层设阈值、只升不降（CODEOWNERS 保护配置）
- **门禁落地**：一条 `&&` 命令链就是全部机制；pre-commit 只做增量、全量/E2E 放 CI/发布前
- **CI 加速**：缓存依赖、并行分片、只跑受影响部分、`isolate:false` 复用 worker（前提无共享状态）、快慢分层
- **报告趋势**：JSON reporter + 汇总脚本；长期盯用例总数、套件耗时、单条失败率三指标
