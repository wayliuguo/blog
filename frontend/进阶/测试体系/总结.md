# 模块总结 · 测试体系

## 知识主线

五篇不是并列的知识点，而是一条"从判断该不该测，到让它自动拦住问题"的链：

```
01 测试策略与分层（该测什么、分几层）
        │  分层定了，每层具体怎么写？
        ▼
02 单元测试深入（纯逻辑 + 依赖怎么处理）  ★主轴
        │  逻辑写完了，组件里的渲染与交互怎么测？
        ▼
03 组件测试（契约 + 查询 + 异步三态）
        │  组件测完了，真实浏览器里的关键路径谁守？
        ▼
04 E2E 与稳定性（关键路径 + flaky 根治）
        │  用例都写好了，怎么让它长期不腐化？
        ▼
05 测试基建与门禁（覆盖率真相 + CI + 门禁）
```

本模块的主轴是**单元测试那套"处理依赖"的方法论**：时间用假定时器、网络用替身、模块用 `vi.mock`、断言钉在行为上。这套方法在组件层同样适用（deferred 控 Promise、user-event 模拟交互），在 E2E 层变成"等条件而不是等时间"。最后靠基建把这一切变成不依赖人自觉的机制 —— 覆盖率只做增量阈值、报告画趋势、flaky 有治理流程。

## 分篇知识点

### 01-测试策略与分层

- **测试买的三样东西**
  - **防回归**：改坏了立刻知道；发现越晚修复链路越长
  - **设计压力**：不好测的代码通常写得也不好
  - **可执行文档**：新人看用例就知道边界在哪
  - 三条筛选题：挂了会不会立刻修 / 能否定位 / 重构时要不要改
- **五层分层**
  - **静态检查**（TS/ESLint）：最便宜的一层，零维护
  - **单元测试**：纯函数与状态机，毫秒级
  - **组件（集成）测试**：props / 事件 / 条件渲染 / 异步中间态
  - **E2E**：关键用户路径与真实浏览器
  - **手工探索**：新功能第一轮与视觉体感
- **金字塔 vs 奖杯**
  - 前端更贴近**测试奖杯**：中间层最厚，因为逻辑长在组件里
  - 比例按"反馈速度 × 定位精度 × 维护成本"定，不按教条
- **测试点分级**
  - **P0**：主流程与钱/权限分支，进 CI 门禁
  - **P1**：影响体验的分支，建议覆盖
  - **P2**：边缘场景，允许手工
  - 不测清单：第三方库、样式像素、实现细节、环境穷举
- **断言钉在行为上**
  - 反模式一：mock 内部依赖断言调用参数 —— 重构即红
  - 反模式二：重言式断言 —— 期望值用同一套算法算出来
  - 正模式：**表驱动 + 手写常数期望 + 边界单独成例**
  - 硬标准：实现换了写法，用例一行不改
- **代价与治理**
  - 维护成本 / 速度成本 / 信任成本（flaky）
  - 该删的三类：测实现的、长期 skip 的、与产品意图不符的
  - 测试范围由**页面配置派生**，避免人工清单遗漏

### 02-单元测试深入

- **Vitest 心智模型**
  - 复用 Vite：TS / JSX / CSS Modules 直接可用
  - `environment` 按文件切换（首行注释），纯逻辑用 node 更快
  - `globals` 保持关闭，多一行 import 换来源清晰
  - `include` 可用 `!` 排除目录
- **用例组织**
  - describe / it / 四种生命周期钩子
  - `only` / `skip` / `todo` / **`fails`**（锁已知 bug 与反例）
  - 命令行按路径或 `-t` 按名字过滤
- **断言**
  - `toBe`（原始值）/ `toEqual`（深比较）/ `toStrictEqual`（连 undefined 属性也查）
  - 写具体值而不是 `typeof`，失败信息即定位线索
- **异步**
  - 返回 Promise 或 `async`，**不用 `done` 回调**
  - **不用固定 sleep 等结果**
  - 超时可调，但调大只是掩盖问题
- **假定时器**
  - `useFakeTimers` + `advanceTimersByTime`：等 300ms 变成拨表
  - `setSystemTime` 连 `Date` 一起冻结，能锁住毫秒级边界
  - 涉及 await 真实 Promise 用 `advanceTimersByTimeAsync`
  - 用完必须 `useRealTimers`
- **四类替身**
  - **stub**：给固定答案，不记录调用
  - **spy**：真实实现照跑，只做记录
  - **mock**：行为完全由测试指定，记录调用
  - **fake**：有内部状态的简化实现，能表达时序变化
- **模块级替换**
  - `vi.mock` 被提升到顶部，配合 `importActual` 只替换部分导出
  - `vi.doMock` 需先 `resetModules`
- **替身纪律**
  - 只 mock 边界：网络 / 时间 / 随机 / 全局
  - 必须还原：`restoreAllMocks` / `unstubAllGlobals` / 配置全局自动还原
- **参数化与数据构造**
  - `it.each` 一行一条用例
  - factory 造数据，新增字段不用改所有用例

### 03-组件测试

- **测的是契约**
  - 渲染契约（props → 渲染）/ 交互契约（操作 → 回调与状态）/ 异步契约（三态）
  - 不测：样式像素、动画时序、内部变量名
- **查询方式**
  - 优先级：Role → LabelText → Placeholder → Text → DisplayValue → AltText → Title → TestId
  - `getBy*`（必须存在）/ `queryBy*`（应该不存在）/ `findBy*`（最终会出现）
  - 查不到时 RTL 打印整棵 DOM，报错即调试线索
- **模拟交互**
  - **user-event 比 fireEvent 真实**：完整事件序列
  - `user.type` 逐字符输入；每次交互都要 await
- **异步中间态**
  - **deferred 模式**：手动控制 Promise 兑现，稳定断言 loading
  - 失败分支要断言按钮恢复可用
  - 等条件（`waitFor` / `findBy*`），不等时间
- **反模式**
  - `container.querySelector` 按 DOM 结构查
  - 整树快照：分不清什么是重要的
  - 测内部 state
- **边界与分工**
  - 浏览器差异 / 跨页流程 → E2E；视觉 → 截图对比
  - E2E 已覆盖的长链路不在组件层重复
- **组织方式**
  - 与组件同级放 `.test.jsx`；用例名写成完整句子
  - 抽 `renderXxx` helper，但不抽断言
  - `globals: false` 时需显式 `afterEach(cleanup)`

### 04-E2E 与稳定性

- **E2E 守什么**
  - 只放关键路径：登录 / 支付 / 跨页跳转 / 第三方集成
  - 规模控制在几十条
- **写法要点**
  - 定位器语义化：`getByRole` / `getByLabel` / `getByText`
  - 每用例自带完整前置，不共享登录态
  - URL 用正则匹配
- **自动等待**
  - web-first 断言自动重试到超时
  - **不写 `waitForTimeout`**
  - 等条件：URL / Response / 元素可见
- **数据准备**
  - 每用例独立数据；前置数据用 API 造
  - 第三方依赖用 `page.route` 拦截；自己系统的接口不拦
- **flaky 四个根因**
  - **sleep 赌时间** → 等条件成立
  - **用例间共享状态** → beforeEach 重置，用 shuffle 暴露
  - **依赖"现在"** → 时间注入 + `setSystemTime`
  - **时区** → 明确业务口径，固定 `TZ` 或用 UTC 方法
  - 反例要写成确定性的（`it.fails`）
- **规模化**
  - 并行 worker 的前提是数据独立
  - 分片按稳定顺序切，失败才保留 trace
  - `retries` 只降噪，不治本
- **治理流程**
  - 量化 Top10 → 隔离 → trace 定位 → 修根因 → 重复跑验证 → 立规矩

### 05-测试基建与门禁

- **覆盖率口径**
  - 语句 / 行 / 分支 / 函数四种，**分支覆盖最有信息量**
  - v8 快、istanbul 细，**中途不要换 provider**
- **覆盖率的陷阱**
  - 覆盖率衡量"代码被执行"，断言质量衡量"结果被验证"，两者独立
  - 弱断言能刷出 100% 覆盖；同份代码换强断言立刻暴露 bug
- **阈值策略**
  - 不达标 → 非 0 退出码，这是门禁的技术基础
  - **存量代码用增量覆盖率**
  - 分层设阈值；阈值只升不降，用 CODEOWNERS 保护配置
- **门禁落地**
  - 一条 `&&` 命令链就是全部机制
  - pre-commit 只做增量；全量与 E2E 放 CI / 发布前
  - 准入清单：本地 lint → commit-msg → 静态 → 测试+覆盖率 → 构建 → E2E → 发布后监控
- **CI 加速**
  - 缓存依赖、并行分片、只跑受影响的部分
  - `isolate: false` 复用 worker（前提是无共享状态）
  - 快慢分层，让快反馈先回来
- **报告与趋势**
  - JSON reporter + 汇总脚本：一份给机器、一份给人
  - 长期盯三个指标：用例总数、套件耗时、单条失败率
- **落地清单**
  - 静态 → 测试门禁 → 增量阈值 → 趋势 → pre-commit 增量 → E2E → flaky 治理 → 季度回顾
