## 1. 测试策略与分层

### 1.1 测试买的三样东西

测试不是"写代码外的负担"，而是买三样东西：

- **防回归**：改坏了立刻知道；发现越晚修复链路越长。
- **设计压力**：不好测的代码通常写得也不好——测试倒逼你拆出干净的接口。
- **可执行文档**：新人看用例就知道边界在哪。

> 三条筛选题：挂了会不会立刻修？改完能否定位？重构时要不要跟着改？都答"是"才值得写。

### 1.2 五层分层

测试按**反馈速度 × 定位精度 × 维护成本**分成五层，各管一段：

| 层 | 成本 | 覆盖内容 |
| ---- | ---- | ---- |
| 静态检查（TS/ESLint） | 最便宜，零维护 | 类型 / 未使用变量 / 潜在 bug |
| 单元测试 | 毫秒级 | 纯函数与状态机 |
| 组件（集成）测试 | 比 E2E 快一个数量级 | props / 事件 / 条件渲染 / 异步中间态 |
| E2E | 秒到分钟级、脆 | 关键用户路径与真实浏览器 |
| 手工探索 | 新功能第一轮 | 视觉体感、浏览器差异 |

单测只有单测逻辑、测不到渲染与集成，E2E 全铺则慢到没人愿意跑——**分层就是因为每层的成本组合不同，单层必然在某处失衡**。

### 1.3 金字塔 vs 奖杯

```
金字塔    底层单测最厚，依次向上变薄，最顶端手工/端到端
奖杯      中间层最厚，两侧是单测与 E2E，顶部手工
```

- 前端更贴近**测试奖杯**：因为逻辑长在组件里，中间层（组件/集成）最厚。
- 比例按"反馈速度 × 定位精度 × 维护成本"定，**不按教条**；高频模块密度高，钱/权限路径必进 E2E。

### 1.4 测试点分级

| 级别 | 含义 | 投入 |
| ---- | ---- | ---- |
| **P0** | 主流程与钱/权限分支 | 进 CI 门禁 |
| **P1** | 影响体验的分支 | 建议覆盖 |
| **P2** | 边缘场景 | 允许手工 |

**不测清单**：第三方库、样式像素、实现细节、环境穷举。

### 1.5 断言钉在行为上

断言要钉在"行为"，不要钉在"实现"：

- **反模式一**：mock 内部依赖后断言调用参数——重构即红，掩盖真回归。
- **反模式二**：重言式断言——期望值用同一套算法算出来，等于没说。
- **正模式**：**表驱动 + 手写常数期望 + 边界单独成例**。

> 硬标准：实现换了写法，用例一行不改。

### 1.6 代价与治理

测试有成本，也要治理：

- **三类成本**：维护成本 / 速度成本 / 信任成本（flaky）。
- **该删的三类**：测实现的、长期 skip 的、与产品意图不符的。
- 测试范围由**页面配置派生**，避免人工清单遗漏。

## 2. 单元测试

### 2.1 Vitest 心智模型

Vite 技术栈用 Vitest，理由都在"复用 Vite"上：

- 复用 Vite：TS / JSX / CSS Modules 直接可用，不用额外配置。
- `environment` 按文件切换（首行注释），纯逻辑用 node 更快，组件用 jsdom/happy-dom。
- `globals` 保持关闭，多一行 import 换来源清晰，也避免与页面全局变量混淆。
- `include` 可用 `!` 排除目录。

### 2.2 用例组织

- 结构：`describe` / `it` + 四种生命周期钩子（`beforeAll` / `beforeEach` / `afterEach` / `afterAll`）。
- 标记：`only`（只管这条）/ `skip`（跳过）/ `todo`（占位）/ **`fails`**（锁已知 bug 与反例）。
- 过滤：命令行按路径，或 `-t` 按名字过滤。

### 2.3 断言

| 断言 | 含义 |
| ---- | ---- |
| `toBe` | 原始值（严格相等） |
| `toEqual` | 深比较对象 / 数组 |
| `toStrictEqual` | 深比较，连 `undefined` 属性也查 |

> 写具体值而不是 `typeof`——失败信息本身就是定位线索。

### 2.4 异步

- 返回 Promise 或 `async`，**不用 `done` 回调**。
- **不用固定 `sleep` 等结果**——快机器白等、慢机器不够，是 flaky 之源。
- 超时可调，但调大只是掩盖问题。

### 2.5 假定时器

用假时钟把"等多久"变成"拨多久/拨多少"：

```
useFakeTimers() + advanceTimersByTime(n)
   把 setTimeout / setInterval 换成可手动拨动的假时钟
   等 300ms → 拨 300ms；第 299 不触发、第 300 触发的边界可精确断言
setSystemTime   连 Date 一起冻结，能锁死毫秒级边界（跨天、有效期）
```

- 涉及 await 真实 Promise 时用 `advanceTimersByTimeAsync`（假定时器不会推进真实 Promise 的 await）。
- 用完必须 `useRealTimers`。

### 2.6 四类替身

四类替身的区别在"是否保留真实实现"与"是否记录调用"两个维度：

| 替身 | 行为 | 记录调用 |
| ---- | ---- | ---- |
| **stub** | 给固定答案 | 不记录 |
| **spy** | 真实实现照跑 | 只做记录 |
| **mock** | 行为完全由测试指定 | 记录调用 |
| **fake** | 有内部状态的简化实现 | 能表达时序变化 |

- 需要表达"第一次失败第二次成功"这类时序时用 **fake**，比一串 `mockReturnValueOnce` 清晰。

### 2.7 模块级替换

- `vi.mock` 会被**提升到文件顶部**执行，替换模块依赖图里的那个模块，所有 import 拿到的都是替身；配合 `importActual` 只替换部分导出。
- 运行时动态替换用 `vi.doMock`，但必须先 `vi.resetModules()` 清掉模块缓存。
- `vi.mocked()` 只是拿回类型提示的包装，运行时透明。

### 2.8 替身纪律

- **只 mock 边界**：网络 / 时间 / 随机 / 全局；自己维护的内部函数不要 mock。
- **必须还原**：`restoreAllMocks` / `unstubAllGlobals` / 配置全局自动还原。

### 2.9 参数化与数据构造

- `it.each` 一行一条用例，直接来自参数表。
- 用 factory 造数据（如 `makeUser()`），新增字段不用改所有用例。

## 3. 组件测试

### 3.1 测的是契约

组件测试测的是"契约"，不是组件内部：

```
渲染契约   props → 渲染结果
交互契约   用户操作 → 回调与状态
异步契约   请求三态（loading / success / error）
```

**不测**：样式像素、动画时序、内部变量名。

### 3.2 查询方式

查询优先级（等价于"用户怎么找到这个元素"）：

```
Role → LabelText → Placeholder → Text → DisplayValue → AltText → Title → TestId
```

- `getBy*`（必须存在）/ `queryBy*`（应该不存在）/ `findBy*`（最终会出现）。
- 按 role / label 查把断言与实现解耦——按 class / DOM 结构查，改个标签名就红。
- **查不到时 RTL 打印整棵 DOM**，报错即调试线索。

### 3.3 模拟交互

- **`user-event` 比 `fireEvent` 真实**：模拟完整事件序列，能测出逐字符输入、聚焦丢失。
- `user.type` 逐字符输入；**每次交互都要 await**。

### 3.4 异步中间态

- **deferred 模式**：手动控制 Promise 兑现时机，`mockReturnValue(deferred.promise)` 让组件停在 pending，稳定断言 loading。
- 失败分支要断言**按钮恢复可用**，否则用户卡死在 loading 上。
- 等条件（`waitFor` / `findBy*`），**不等时间**；不要 `sleep` 固定时间。

### 3.5 反模式

```
container.querySelector   按 DOM 结构查，改结构即红
整树快照                   分不清什么是重要的，噪声淹没信号
测内部 state               耦合实现，违反"测契约"
```

### 3.6 边界与分工

- 浏览器差异 / 跨页流程 → E2E；视觉 → 截图对比。
- E2E 已覆盖的长链路不在组件层重复。

### 3.7 组织方式

- 与组件同级放 `.test.jsx`；用例名写成完整句子（`it('点击提交后发送请求并禁用按钮')`）。
- 抽 `renderXxx` helper，但**不抽断言**。
- `globals: false` 时需显式 `afterEach(cleanup)`。

## 4. E2E 与稳定性

### 4.1 E2E 守什么

- 只放**关键路径**：登录 / 支付 / 跨页跳转 / 第三方集成——"挂了就是事故"的路径。
- 规模控制在几十条，不是几百条；组件分支、边界值、表单校验组合都不进 E2E。

### 4.2 写法要点

- 定位器语义化：`getByRole` / `getByLabel` / `getByText`。
- 每用例自带完整前置，**不共享登录态**。
- URL 用正则匹配。

### 4.3 自动等待

- Playwright 断言是 **web-first** 的，自动重试到超时，吸收"元素还没渲染"的时序。
- **不写 `waitForTimeout`**——慢机器上不够、快机器上白等，是 flaky 头号来源。
- 等条件：URL（`waitForURL`）/ Response（`waitForResponse`）/ 元素可见（`:toBeVisible`）。

### 4.4 数据准备

- 每用例**独立数据**；前置数据用 API 造。
- 第三方依赖用 `page.route` 拦截；**自己系统的接口不拦**。
- 自动等待治不了"数据不可控"——数据独立是并行的前提。

### 4.5 flaky 四个根因

| 根因 | 对策 |
| ---- | ---- |
| **sleep 赌时间** | 等条件成立 |
| **用例间共享状态** | beforeEach 重置，用 `--sequence.shuffle` 暴露 |
| **依赖"现在"** | 时间注入 + `setSystemTime` |
| **时区** | 明确业务口径，固定 `TZ` 或用 UTC 方法 |

- 反例要写成确定性的（`it.fails`）。
- `retries` 只降噪，不治本。

### 4.6 规模化

- 并行 worker 的前提是**数据独立**。
- 分片（`--shard`）按稳定顺序切，**失败才保留 trace**。
- 用例多了提速：并行 worker + 分片 + 失败才保留 trace。

### 4.7 治理流程

flaky 治理当成项目做：**量化 Top10 → 隔离 → trace 定位 → 修根因 → 重复跑验证 → 立规矩**。

## 5. 测试基建与门禁

### 5.1 覆盖率口径

覆盖率分四种口径：

```
语句   每条语句执行过
行     每行执行过
分支   每个分支都走到   ← 最有信息量
函数   每个函数调用过
```

- v8 快、istanbul 分支粒度细，**中途不要换 provider**，否则趋势会断。

### 5.2 覆盖率的陷阱

- 覆盖率衡量"**代码被执行**"，断言质量衡量"**结果被验证**"，两者独立。
- 弱断言（`expect(typeof x).toBe('number')`）能刷出 100% 覆盖；同份代码换强断言（期望 81 实得 65）立刻暴露 bug。
- 反过来，脚本 / 配置 / 一次性代码不该要求覆盖率。

### 5.3 阈值策略

- 不达标 → **非 0 退出码**，这是门禁的技术基础。
- **存量代码用增量覆盖率**，只卡本次改动的行被覆盖，让数字随改动缓慢上升。
- 分层设阈值；**阈值只升不降**，用 CODEOWNERS 保护配置。

### 5.4 门禁落地

- 一条 `&&` 命令链就是全部机制（前一步失败即终止）。
- pre-commit 只做增量；全量与 E2E 放 CI / 发布前。
- 准入清单：本地 lint → commit-msg → 静态 → 测试+覆盖率 → 构建 → E2E → 发布后监控。

### 5.5 CI 加速

按性价比依次做：缓存依赖、并行分片、只跑受影响的部分、减少 worker 启动开销、快慢分层。

- `isolate: false` 复用 worker（**前提是无共享状态**——与"用例必须独立"是同一件事的两面）。
- 快反馈先回来：快慢分层。

### 5.6 报告与趋势

- JSON reporter + 汇总脚本：**一份给机器、一份给人**。
- 长期盯三个指标：用例总数、套件耗时、单条失败率。

### 5.7 落地清单

```
静态检查 → 测试门禁 → 增量阈值 → 趋势 → pre-commit 增量 → E2E → flaky 治理 → 季度回顾
```
