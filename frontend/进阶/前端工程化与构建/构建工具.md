# 构建工具

现代前端开发几乎离不开构建工具：它们负责把源码中的模块、ES 新语法、CSS 预处理器、静态资源统一打包成浏览器能够安全运行的产物。本文围绕 Webpack、Vite、Rollup 三套主流方案展开，覆盖 Webpack 的核心概念、loader/plugin 机制、代码分割与打包优化、Vite 与 Rollup 的核心配置、以及 node_modules 的定位问题，最后给出三者选型对比，帮助你建立完整的前端构建知识框架。

## 一、Webpack 核心概念与基本配置

Webpack 本质上是一个**模块打包器（Module Bundler）**。它从入口出发，把项目中所有的模块（JS、CSS、图片、字体等）通过依赖图组织起来，最终打包成浏览器可识别的静态资源。

### 核心配置项

一份 `webpack.config.js` 常见的基础结构如下：

> 示意片段（无配套脚本）

```js
const path = require('path')

module.exports = {
    mode: 'development',               // 模式：development / production
    entry: './index.js',               // 入口（必须）
    output: {                          // 输出（必须）
        // 输出目录
        path: path.resolve(__dirname, 'dist'),
        filename: '[name].[hash:4].bundle.js'
    },
    module: {},                        // 非必须，loader 的编写位置
    plugins: [],                       // 非必须，插件
    optimization: {},                  // 非必须，优化相关
    devServer: {},                     // 非必须，开发模式配置
    resolve: {}                        // 非必须，路径/扩展名简化
}
```

各字段说明：

- `entry`：**必须项**，入口文件，Webpack 从它开始递归构建依赖图。
- `mode`：`production`（默认）或 `development`，Webpack 4 之后必填，决定自动启用的优化能力。
- `module`：`loader` 编写的地方。
- `output`：**必须项**，最终产出 JS 的配置。
- `plugins`：插件，扩展 Webpack 能力。
- `optimization`：优化相关，如代码分割、压缩。
- `devServer`：开发模式配置（热更新、端口、代理）。
- `resolve`：路径别名、扩展名省略等简化功能。

### 安装

> 示意片段（无配套脚本）

```bash
npm install webpack webpack-cli --save-dev

# 全局安装（可选）
npm install webpack webpack-cli -g
webpack -v
```

### 最小可运行示例

> 示意片段（无配套脚本）

```js
const path = require('path')

module.exports = {
    mode: 'development',
    entry: './index.js',
    output: {
        path: path.resolve(__dirname, 'dist'),
        filename: '[name].[hash:4].bundle.js'
    }
}
```

这里的 `[name]`、`[hash:4]`、`[ext]` 等都是**占位符**，用于在产物文件名中加入模块名 / 内容哈希 / 扩展名，进而实现基于内容的缓存失效。

## 二、loader：如何让 Webpack 处理"非 JS"资源

Webpack 本身只能识别 JS，其他一切资源（`babel` 处理前的语法、CSS、图片、Less 等）都需要借助 **loader** 在 `module.rules` 中声明处理规则。

> loader 的原理很简单：**接收文件内容，对内容进行加工并返回**。

一个最小的自定义 loader（`mycss-loader/index.js`）：

> 示意片段（无配套脚本）

```js
module.exports = function (cssContent) {
    cssContent = cssContent.replace('0', '1px')
    return cssContent
}
```

> 示意片段（无配套脚本）

```js
module: {
    rules: [
        {
            test: /\.css$/i,
            use: [minicss.loader, 'css-loader', './mycss-loader']
        }
    ]
}
```

注意 `use` 数组中 loader 的**执行顺序是从右到左（从下到上）**，即先经过 `./mycss-loader`，再经过 `css-loader`，最后交给 `mini-css-extract-plugin` 的 loader。

### 处理 JS：babel-loader

用于把新版本 JS 语法转译为兼容目标环境的写法。

> 示意片段（无配套脚本）

```bash
npm i babel-loader @babel/core @babel/preset-env
```

- `babel-loader`：处理 JS，内部依赖 `@babel/core`。
- `@babel/preset-env`：转译的规范 / 预设，决定按哪些目标环境做降级。

> 示意片段（无配套脚本）

```js
module: {
    rules: [
        {
            test: /\.js$/,
            use: {
                loader: 'babel-loader',
                options: {
                    presets: [
                        [
                            '@babel/preset-env',
                            {
                                targets: {
                                    browsers: ['>1%', 'last 2 versions', 'not ie<=8']
                                }
                            }
                        ]
                    ]
                }
            }
        }
    ]
}
```

更推荐把 `presets` 抽到 `.babelrc` 中集中管理：

> 示意片段（无配套脚本）

```json
{
    "presets": [
        [
            "@babel/preset-env",
            {
                "targets": {
                    "browsers": [">1%", "last 2 versions", "not ie<=8"]
                }
            }
        ]
    ]
}
```

### 处理样式：css-loader + style-loader / mini-css-extract-plugin

webpack 无法直接处理 CSS，两条常见处理路径是：

1. js 中引入 css → `css-loader` → `style-loader`（把 css 写入 JS，运行时作为 `<style>` 标签插入页面）。
2. js 中引入 css → `css-loader` → `mini-css-extract-plugin`（把 css **提取**为独立文件）。

> 示意片段（无配套脚本）

```bash
npm install css-loader style-loader mini-css-extract-plugin -D
```

> 示意片段（无配套脚本）

```js
const minicss = require('mini-css-extract-plugin')

module.exports = {
    module: {
        rules: [
            {
                test: /\.css$/i,
                // 开发模式：use: ['style-loader', 'css-loader']
                use: [minicss.loader, 'css-loader']
            }
        ]
    },
    plugins: [
        // 用于把 css 提取为独立文件
        new minicss({
            filename: 'test.bundle.css'
        })
    ]
}
```

#### 预处理语言（Less / Sass）

以 Less 为例，在 `css-loader` 之前再经 `less-loader` 编译：

> 示意片段（无配套脚本）

```bash
npm i less less-loader -D
```

> 示意片段（无配套脚本）

```js
{
    test: /\.less/,
    use: [minicss.loader, 'css-loader', 'less-loader']
}
```

#### CSS 压缩

> 示意片段（无配套脚本）

```bash
npm i css-minimizer-webpack-plugin -D
```

在 `optimization.minimizer` 中启用即可。

### 处理静态资源（图片/字体）

Webpack 5 原生支持资源模块（`type`），比旧版 `file-loader` / `url-loader` 更推荐。

> 示意片段（无配套脚本）

```bash
npm i file-loader url-loader -D   # 需要自定义时安装
```

> 示意片段（无配套脚本）

```js
{
    test: /\.(png|svg|jpg|jpeg|gif)$/i,
    type: 'asset',                 // 自动在 inline 与单独文件间选择
    parser: {
        dataUrlCondition: {
            maxSize: 4 * 1024      // 小于 4kb 转 base64
        }
    },
    generator: {
        filename: '[name].[hash][ext]'
    }
}
// 旧版 url-loader 写法
/* {
    test: /\.(png|svg|jpg|jpeg|gif)$/i,
    loader: 'url-loader',
    options: {
        limit: 5 * 1024,           // 小于 5kb 转 base64
        name: '[name].[hash:4].[ext]'
    }
} */
```

Webpack 5 的四种资源类型：

- `asset/resource`：发送一个单独文件并导出其 URL，等同旧的 `file-loader`。
- `asset/inline`：导出资源的 data URI（base64），等同旧的 `url-loader`。
- `asset/source`：导出资源的源代码，等同旧的 `raw-loader`。
- `asset`：在 data URI 与单独文件之间**自动选择**，等同配置了体积限制的 `url-loader`。

## 三、plugin：拓展构建能力

plugin 是 Webpack 复用能力的核心载体，与 loader 的"单文件处理"不同，plugin 可以监听整个构建生命周期。这里重点介绍最常用的 `html-webpack-plugin`。

### html-webpack-plugin

**期望效果：** 提供一个 HTML 模板复用公共结构；打包时自动生成一个 html；打包出来的 html 自动引入 JS。

> 示意片段（无配套脚本）

```bash
npm i html-webpack-plugin -D
```

模板 `index.html`：

> 示意片段（无配套脚本）

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>webpack</title>
</head>
<body>
    <div id="app"></div>
</body>
</html>
```

> 示意片段（无配套脚本）

```js
new htmlwebpackplugin({
    template: './index.html',
    filename: 'index.html',
    // 生产模式默认开启压缩等能力
    minify: {
        collapseWhitespace: true,
        removeComments: true,
        removeAttributeQuotes: true
    }
})
```

## 四、代码分割（SplitChunks）

如果所有代码打进一个文件，会造成文件过大、首屏加载变慢；但分割过细又会带来过量的 HTTP 请求。需要分割的，通常是**体积特别大且首屏并不需要**的代码。

`optimization.splitChunks` 相关参数：

- `chunks`：`async`（异步代码）/ `initial`（同步代码）/ `all`（两者均拆分）。
- `minChunks`：模块被引用次数大于多少才分隔。
- `minSize`：打包体积达到多大才分隔。
- `maxSize`：超过该体积继续拆分。

> 示意片段（无配套脚本）

```js
optimization: {
    splitChunks: {
        chunks: 'all',
        minChunks: 1,
        minSize: 0,
        // 单独定义分隔规则（如单独打包第三方库）
        cacheGroups: {
            vendor: {
                test: /[\\/]node_modules[\\/]/,
                filename: 'vendor.js',
                chunks: 'all',
                minChunks: 1
            }
        }
    },
    // 把运行时代码单独打包成一个文件
    runtimeChunk: {
        name: 'runtime'
    }
}
```

## 五、技巧性配置

### hash 的意义

`[hash]` / `[contenthash]` 让文件名带有内容指纹，**避免浏览器缓存未变更的文件**。

### resolve：别名与扩展名省略

> 示意片段（无配套脚本）

```js
resolve: {
    alias: {
        '@': path.resolve(__dirname)      // 路径别名，提供简短引用
    },
    extensions: ['.js', '.css', '.json']  // 可省略的扩展名
}
```

### require.context：批量引入

批量引入指定文件夹下所有匹配的文件：

> 示意片段（无配套脚本）

```js
// index.js
let _all = 0
const r = require.context('@/total', false, /.js/)   // (路径, 是否引入子目录, 匹配规则)
r.keys().forEach(item => {
    console.log(r(item).default)
    _all += r(item).default
})
console.log(_all)
```

### filename：指定输出子目录

凡是带 `filename` 选项的（如 `mini-css-extract-plugin`），都可以指定输出路径：

> 示意片段（无配套脚本）

```js
new minicss({
    filename: './css/test.bundle.css'
})
```

### publicPath

用于在 HTML 引用时作为前缀，一般作为 CDN 使用：

> 示意片段（无配套脚本）

```js
output: {
    publicPath: 'www.baidu.com'
}
```

打包出来的 HTML 中引用会加上此前缀。

## 七、实战技巧：配置拆分与打包加速

### 配置按环境拆分

借助 `cross-env` 注入环境变量，按开发/生产分别加载不同配置文件：

> 示意片段（无配套脚本）

```bash
npm i cross-env -D
```

> 示意片段（无配套脚本）

```json
{
    "scripts": {
        "start": "cross-env NODE_ENV=development webpack-dev-server --config ./webpack.dev.js",
        "build": "cross-env NODE_ENV=production webpack --config ./webpack.pro.js"
    }
}
```

**编程式配置**：根据 `process.env.NODE_ENV` 动态决定插件列表。

> 示意片段（无配套脚本）

```js
let pluginArr = [
    new htmlwebpackplugin({
        template: './index.html',
        filename: 'index.html',
        minify: {
            // collapseWhitespace: true,
            // removeComments: true,
            // removeAttributeQuotes: true
        }
    })
]

function hasMiniCss() {
    if (process.env.NODE_ENV === 'production') {
        pluginArr.push(new minimizer())
        pluginArr.push(
            new minicss({
                filename: './css/test.bundle.css'
            })
        )
    }
}

hasMiniCss()

module.exports = {
    plugins: pluginArr
}
```

### 提升打包速度：Dll 预构建

把不变的第三方库提前打包一次并生成 `manifest` 清单，正式打包时命中清单的模块不再重复处理。

`webpack.dll.js`：

> 示意片段（无配套脚本）

```js
const webpack = require('webpack')

module.exports = {
    mode: 'production',
    entry: {
        vendor: ['axios']              // 把 axios 单独打包
    },
    output: {
        path: __dirname + '/dist',
        filename: '[name].dll.js',
        library: '[name]_library'
    },
    plugins: [
        new webpack.DllPlugin({
            path: __dirname + '/[name]-manifest.json',
            name: '[name]_library',
            context: __dirname
        })
    ]
}
```

`package.json` 增加脚本：

> 示意片段（无配套脚本）

```json
{
    "dll": "webpack --config ./webpack.dll.js"
}
```

`webpack.pro.js` 引用清单：

> 示意片段（无配套脚本）

```js
plugins: [
    new webpack.DllReferencePlugin({
        manifest: require(__dirname + '/vendor-manifest.json')
    })
]
```

模板 `index.html` 手动引入：

> 示意片段（无配套脚本）

```html
<script src="vendor.dll.js"></script>
```

### tree-shaking

开启 `usedExports`，配合生产模式（`mode: production`）即可实现"摇树"，剔除未使用代码：

> 示意片段（无配套脚本）

```js
optimization: {
    usedExports: true
}
```

### prefetch 与 preload

- **Preload**：强制立即获取关键资源，适用于当前页面加载必需的资源。
- **Prefetch**：在**空闲时间异步**获取非关键资源，适用于未来导航可能用到的资源。

> 示意片段（无配套脚本）

```html
<link rel="prefetch" href="...">
<link rel="preload" href="...">
```

> 示意片段（无配套脚本）

```js
const PreloadWebpackPlugin = require('@vue/preload-webpack-plugin')

plugins: [
    new PreloadWebpackPlugin({
        rel: 'preload',   // preload 兼容性更好
        as: 'script'
        // rel: 'prefetch'  // prefetch 兼容性更差
    })
]
```

## 九、Vite

Vite 的最大特点是**基于 ESM（原生 ES 模块）**：它不像传统构建工具那样去分析所有引入并打包，而是让浏览器通过 `<script type="module">` 自己分析模块，省去大量编译时间，从而让开发时的代码改动响应速度大幅提升。

> 原理上与构建侧的手动打包不同，Vite 直接把模块保持为原生 import 交给浏览器，因此对**低版本浏览器的兼容性**是其需要考虑的问题。

### 特性

- 天生支持 CSS 及预处理语言，支持 TypeScript，能直接处理各种静态资源。
- 特殊语言需要额外插件，例如 Vue：`npm i @vitejs/plugin-vue -D`。
- JSX 可通过 `esbuild` 配置：

> 示意片段（无配套脚本）

```js
esbuild: {
    jsxFactory: 'h',
    jsxFragment: 'Fragment',
    jsxInject: "import {h} from 'vue'"
}
```

### 代码分割

Vite 会自动分割异步引入的代码；第三方库 `vendor` 或特殊拆分需求，需要借助 Rollup 的 `manualChunks`。

### server 配置

> 示意片段（无配套脚本）

```js
server: {
    port: 8080,
    proxy: {
        '/api': {
            target: 'http://localhost:3000',
            rewrite: path => {
                console.log(path)
                return path
                // return path.replace(/^\/api/, '')
            }
        }
    }
}
```

## 十、Rollup

Rollup 的特点：

- **不会生成过多的运行时代码**，产物更干净简洁。
- 支持多种模块规范（ESM、CommonJS、UMD 等）打包。

### 核心配置

> 示意片段（无配套脚本）

```js
// rollup.config.js
export default {
    input: './src/index.js',   // 入口
    output: {
        // dir 与 file 二选一
        dir: 'dist',           // 输出目录（多入口常用）
        file: 'bundle.js',     // 输出文件
        format: 'esm'          // 必须，输出的模块规范
    },
    external: ['react'],       // 忽略打进 bundle 的依赖
    plugins: []
}
```

### 常用插件

打包第三方依赖：

> 示意片段（无配套脚本）

```bash
npm i @rollup/plugin-node-resolve -D
```

产物压缩：

> 示意片段（无配套脚本）

```bash
npm i @rollup/plugin-terser -D
```

## 十一、node_modules 定位问题

在使用 VS Code 的 **Search node_modules** 插件查找 `node_modules` 下的依赖时，从某个版本开始，搜索依赖后跳转过去，左侧的资源管理器（目录树）**不会自动切换**到对应文件，需要手动切换一次。

### 解决方法

在 VS Code 设置中启用如下配置，让搜索跳转后自动将资源管理器定位到所在文件：

> 示意片段（无配套脚本）

```json
{
    "search.useIgnoreFiles": true,
    "explorer.autoReveal": true,
    "search.explorerReveal": "always"
}
```

其中 `explorer.autoReveal` 控制资源管理器是否自动定位并高亮当前文件，设置为 `true` 即可在跳转后自动切换到目标文件。若仍未生效，可在设置面板搜索 `autoReveal` / `auto reveal` 手动确认。

> 提示：`node_modules` 默认会被 `.gitignore` 忽略，个别搜索插件需要额外配置对你的目标仓库生效。

## 十二、Webpack vs Vite vs Rollup 选型对比

| 维度 | Webpack | Vite | Rollup |
| --- | --- | --- | --- |
| 定位 | 通用全功能打包器，生态最庞大 | 开发体验优先的下一代构建工具 | 专注 ESM 库 / 发布物打包 |
| 核心机制 | 静态分析构建依赖图 | 依赖 esbuild + 原生 ESM，开发启动快 | 基于 ESM 的 tree-shaking 强项 |
| devServer | 成熟，需手动配热更新/代理 | 内置高性能 server，开箱即用 | 一般不承担开发服务器角色 |
| 生产构建 | 强大且可深度定制 | 底层仍用 Rollup 完成生产打包 | 产物干净、体积小 |
| 适用场景 | 大型应用、复杂配置 | 开发体验优先的应用 | 库、组件、工具的发布 |
| 学习成本 | 较高（配置丰富） | 低（约定优于配置） | 中 |

简单来说：**Vite 适合作为新一代应用脚手架的默认选择**，其开发与构建体验都很好；**Webpack** 以生态和可定制性见长，适合需要深度控制构建流程的项目；**Rollup** 则是打包 npm 库、组件、工具项目的首选。

## 配套代码

本篇的可运行示例在仓库 `frontend/进阶/前端工程化与构建/code/site/`。

## 总结

- 前端构建工具
  - Webpack 核心概念
    - 模块打包器与依赖图
    - `entry` / `output` / `mode`
    - 占位符 `[name]` / `[hash]` / `[ext]`
  - loader 机制
    - `module.rules` 声明处理规则
    - 执行顺序从右到左
    - `babel-loader` / `css-loader` / `style-loader` / `less-loader`
    - 静态资源：Webpack 5 `type: 'asset'`
  - plugin 机制
    - 监听构建生命周期
    - `html-webpack-plugin`
  - 代码分割
    - `splitChunks` 与 `cacheGroups`
    - `runtimeChunk` 提取运行时代码
  - 技巧性配置
    - hash 内容指纹与缓存失效
    - `resolve.alias` / `extensions`
    - `require.context` 批量引入
    - `publicPath` 与 CDN
  - 开发模式
    - `devServer` 热更新 / 代理
    - source-map
  - 实战技巧
    - 配置按环境拆分（cross-env）
    - `webpack-bundle-analyzer` 产物分析
    - Dll 预构建
    - tree-shaking（`usedExports`）
    - prefetch / preload
  - 优化总结
    - 代码层面 / 依赖层面 / 网络层面
  - Vite
    - 基于原生 ESM
    - esbuild 转译与插件
    - 自动代码分割与 server 配置
  - Rollup
    - 产物干净、支持多模块规范
    - `input` / `output.format` / `external`
    - 常用插件：node-resolve / terser
  - node_modules 定位问题
    - VS Code Search node_modules 配置
  - 选型对比
    - Webpack：大型应用深度定制
    - Vite：应用脚手架默认选择
    - Rollup：库 / 组件 / 工具发布
