## 知识主线（一句话）

本模块的主轴是**沙箱与隔离机制**：01 篇回答选型（路由分发 / 微件 / 容器式、iframe 取舍与代价清单）；02 篇深入容器式的技术核心——快照 / Proxy 单例 / Proxy 多例三种 JS 沙箱与 Shadow DOM / scoped / 动态样式表三条样式隔离；03~05 篇补齐通信与状态、资源加载与依赖共享，最终收拢为手写 mini 框架。

## 高频核心点

### 01 微前端方案全景与选型

- **动机判定**：多团队 × 多技术栈 × 独立发布同时出现才值得上；仅"代码多"用模块化 + 代码分割即可
- **三类方案**：路由分发式（Nginx 按路由转发，整页级、零侵入但切换整页刷新）；微件式（Web Components 作页面局部区块）；**容器式**（容器管布局/路由/生命周期/沙箱/通信——qiankun / micro-app / wujie）
- **iframe 取舍**：隔离最强、接入成本最低，但 URL 状态易丢、弹窗困框内、内存与首屏成倍、只能 postMessage；适合一次性接入不可控老系统；wujie 思路正是"iframe 管 JS 隔离 + Web Components 管渲染"
- **决策矩阵**：中后台多团队→qiankun/micro-app；同构建链共享依赖→Module Federation；嵌单卡片→Web Components；完全不可控老系统→iframe/wujie
- **代价清单**：容器基建复杂度上移、公共依赖重复、样式一致性难、调试链路变长、版本兼容矩阵——微前端是组织问题的技术解

### 02 沙箱与隔离机制（★主轴）

- **隔离对象**：`window` 运行时、样式表、DOM 查询、定时器/监听器/fetch 劫持等副作用
- **快照沙箱（legacy）**：激活拍全量快照、失活 diff 还原；简单可靠但必须完整交替、同一时刻只能跑一个
- **Proxy 单例沙箱**：`set` 陷阱记账、失活只撤销记账的属性；仍是单例交替
- **Proxy 多例沙箱**：每个应用一份 `fakeWindow`（`Object.create(sharedGlobal)`），读沿原型链回落共享全局、写只进自己那份；天然支持多应用并存——**qiankun 2.x / micro-app 采用，新项目一律选它**（IE11 只能退回快照）
- **样式隔离三路线**：Shadow DOM（浏览器级，但弹窗逃出边界）；选择器前缀 scoped（`[data-app=main] .card`，构建期 CSS Modules/postcss）；动态样式表（按应用整批启停）
- **DOM 与副作用**：`querySelector`/`createElement` 重定向到容器；拦截 `setInterval`/`addEventListener` 记账、unmount 统一回滚——与沙箱"记账"同一思路

### 03 应用通信与状态共享

- **生命周期协议**：bootstrap 只跑一次 / mount 每次激活 / unmount 清副作用（否则 repeat mount 叠加两份）
- **props 透传**：一次性、单向、低频下发（用户、全局配置、封装好的 request）；要双向同步不能靠 props
- **事件总线**：通知类交互（改数据→刷角标）；纪律：事件名加应用前缀、**unmount 必须退订**（否则幽灵回调）、payload 传拷贝不传引用
- **shared store**：持续读写（登录态/主题/购物车）；主应用下发实例或独立共享包单例 import（MF 主流）；分工原则「事件传发生了什么、store 存现在是什么」
- **路由同步**：主应用路由是唯一真相源——主管 activeRule 分发、子管应用内剩余路径；三坑：子应用直改 `location.href` 整页刷新、主子双跳、iframe 刷新丢内部路由
- **版本兼容**：协议是公共 API——新增向后兼容、删除留一周期旧名、payload 内嵌 `{ v: 2, data }`、容器 try-catch 跨应用调用

### 04 资源加载与依赖共享

- **HTML entry vs JS entry**：HTML entry（qiankun 默认）顺带样式与首屏占位、接入成本低；JS entry 更轻但样式自己做
- **共享收益两层**：网络层公共依赖只下载一次进 HTTP 缓存；运行层同一份 React 实例保住 hooks 状态/Context/事件系统全局唯一（不共享时跨应用 Context 打不通）
- **MF shared 协商**：从高到低找满足所有消费方 `requiredVersion` 的版本——成功全场一份（`copies:1`）；失败按约束分组 fallback、React 17/18 并存内存翻倍
- **工程要点**：React/状态管理必须 `singleton: true`（宁可告警不留两份）；`requiredVersion` 从宽（`^`）+ 主应用定基准大版本；上线用产物分析核对 React 出现次数、协商 `copies === 1`

### 05 手写 mini 微前端框架

- **四层**：`sandbox.cjs`（隔离）/ `entry.cjs`（解析+样式）/ `scheduler.cjs`（调度）/ `run.cjs`（自检），约 200 行零依赖
- **关键一行 `with(window)`**：让裸标识符也走 Proxy——没有它子应用直接调 `log()` 会逃逸到真实全局（micro-app 同款）
- **执行方式**：`new Function('window','with(window){'+code+'}')` 在沙箱执行；`new Function` 不闭包外层作用域（公共能力放共享全局）
- **调度**：url 级缓存（全生命周期一次网络）→ preload 只抓不执行 → bootstrap→mount；unmount 清副作用、撤销沙箱属性（仅留 `__MICRO_APP_NAME__`）
