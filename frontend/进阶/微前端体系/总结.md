## 1. 方案全景与选型

### 1.1 动机判定与代价清单

「**多团队 × 多技术栈 × 独立发布**」三个条件同时出现才值得上微前端——它解决的是组织架构问题，不是代码量问题。仅"代码多"用模块化 + 代码分割即可。代价五笔：容器基建复杂度上移、公共依赖重复打包、样式/全局一致性变难、跨应用调试链路变长、协议升级的版本兼容矩阵。

### 1.2 五方案对比矩阵

| 维度 | iframe | qiankun | micro-app | wujie | Web Components |
|---|---|---|---|---|---|
| 接入形态 | 原生标签 | 生命周期协议 | `<micro-app>` 标签 | `<WujieVue>` 组件 | 自定义元素标签 |
| 子应用改造 | 零 | 必须 UMD + lifecycle | 近零 | 零 | 构建成元素产物 |
| JS 隔离 | 最强 | Proxy（可逃逸） | Proxy（可逃逸） | iframe 运行时 | 无 |
| 通信 | postMessage | initGlobalState | data/dispatch | props/bus | attribute/CustomEvent |

### 1.3 三条硬边界

彻底防串选 iframe；改造成本最低选 micro-app/wujie；长期演进选 Web Components。qiankun 是"子应用团队愿意配合协议"时的生态最优解。统一工程 `mf-workspace` 把五方案跑在同一业务流上，选型前先跑一遍工程。

## 2. iframe 方案（基线）

### 2.1 心智迁移：零改造的隔离

iframe 是唯一零改造方案：不导出生命周期、不改构建、不感知宿主。隔离是浏览器赋予的（独立 Window/Document），不是实现出来的。

### 2.2 postMessage 协议设计

跨源唯一通道。工程要点：消息格式/方向/时序/校验四件事都要自己定；下行传参用 URL 重载最可靠（postMessage 有"监听器未就绪丢消息"问题）；**origin 校验是底线**。

### 2.3 三面墙：弹窗/路由/登录态

弹窗 `fixed` 只覆盖 iframe 视口；子应用路由不进宿主地址栏；跨源不共享 Cookie/localStorage。每个都要手写协议（弹窗代渲染、路由双向同步、token 握手）——后续方案的内置机制就是在替代这些手写协议。

### 2.4 IframeBridge 最小实现

就绪握手 + 请求-响应式消息 + origin 校验，40 行覆盖真实项目核心诉求。真正复杂度在协议设计而非 API 调用。

## 3. qiankun（single-spa 系）

### 3.1 生命周期协议心智

子应用从"页面"变"应用"：`bootstrap`（一次）/ `mount(container)`（每次）/ `unmount()`（清理）。接入成本 = 把启动代码包进三个函数并导出 UMD。

### 3.2 import-html-entry 加载链路

fetch entry html → 摘 script/link → CSS 注入（带隔离处理）→ JS 包 eval 执行 → 从 exports 找生命周期。这解释了两个约束：子应用必须 UMD（ESM 静态 import 无法运行时重定向）；entry 内脚本顺序敏感。

### 3.3 Proxy 沙箱与样式隔离档位

`with(proxy)` 让写入落 fakeWindow（防无意污染，不防有意逃逸）。样式隔离两档：strictStyleIsolation（shadow，弹窗丢样式）、experimentalStyleIsolation（前缀改写）——实践中多数团队不开隔离靠约定。

### 3.4 initGlobalState

qiankun 托管的共享 state，props 注入 `setGlobalState`/`onGlobalStateChange`。广播语义：只放令牌/主题类轻状态，业务数据走各自 API 层。

### 3.5 实测双坑：preamble 与 process

`@vitejs/plugin-react can't detect preamble`——React 子应用 qiankun 接线必须走生产产物；`process is not defined`——构建层 `define` 替换 + 宿主垫片（qiankun 官方 FAQ）双层修。

## 4. micro-app（Web Components 化接入）

### 4.1 标签即接入

`microApp.start()` 一次注册，之后 `<micro-app url>` 标签即接入。子应用零生命周期协议——时序交给元素生命周期（connectedCallback/disconnectedCallback）。

### 4.2 元素壳 + scopecss

架构 = custom element 容器 + 内部迷你版 import-html-entry。scopecss 运行时给 CSS 规则加 `micro-app[name=xxx]` 前缀，比 qiankun 的实验性隔离边界少（弹窗也生效）。

### 4.3 data/dispatch 组件式通信

`:data` 下行（props 语义）、`dispatch` 上行（事件语义）、`addDataListener` 推送订阅——与 React props/回调几乎同构。

### 4.4 Vite dev ESM 坑与产物统一

实测 micro-app 对 Vite dev 的 module script 路径拼接 bug（`undefined../src/main.ts`）。与 qiankun 的 preamble 坑殊途同归：**classic script（UMD 产物）是容器方案最稳的共同消费形态**。

## 5. wujie（iframe 运行时 + 影子渲染）

### 5.1 隔离与体验兼得的组合拳

JS 跑在隐藏 iframe（结构性隔离），DOM 搬运到宿主 shadow DOM 渲染。意外收获：`document.body` 被代理到宿主——**弹窗天然逃逸，五方案唯一开箱即用**。

### 5.2 alive 保活与销毁

alive 模式 iframe 保活、二次切换秒开（脚本不重执行）；destroy 模式卸载即销毁。高频切换业务用 alive，内存敏感场景用 destroy。

### 5.3 props/bus 通信

`:props` 下行（`window.$wujie.props`）、`bus.$emit/$on` 双向事件——内置通道，比 postMessage 舒服。

### 5.4 依赖共享的定价

各 iframe 独立解析脚本，依赖必然各一份——**体积换隔离**是 wujie 的定价。共享需求让位给隔离需求时选它。

## 6. Web Components 方案（标准即方案）

### 6.1 子应用即自定义元素

Vue 用 `defineCustomElement` 一行变元素；React 手写 30 行 wrapper。宿主零运行时，标签即接入。

### 6.2 attribute 下行与 CustomEvent 上行

attribute 是 props 通道（元素须声明 observedAttributes）；CustomEvent 须 `bubbles + composed` 才穿透 shadow 边界。协议就是 HTML 标准。

### 6.3 React 手写 wrapper

`connectedCallback` ↔ mount、`disconnectedCallback` ↔ unmount、`attributeChangedCallback` ↔ props 更新——**元素生命周期就是微前端生命周期协议的原型**。

### 6.4 样式 ?inline 注入 shadow 坑

lib 构建默认抽独立 css，shadow 里全裸。必须 `?inline` 变字符串、经组件 `styles` 选项注入。真实工程出现率极高。

## 7. 沙箱与隔离机制（原理）

### 7.1 全局共享点与危险分级

window 篡改（最难发现）、样式互串（最常见）、定时器/监听器泄漏（最隐蔽）——隔离方案逐一对付。

### 7.2 快照沙箱

激活拍快照、失活 diff 还原。局限：必须"上台—下台"，同一时刻只能一个应用；全量 diff 有性能开销（qiankun legacy）。

### 7.3 Proxy 单例与多例沙箱

单例：记账代替拍照（set 陷阱记账，失活只撤销记过的账）。多例：一人一份 fakeWindow 原型链挂共享全局（读回落、写只写自己）——qiankun 2.x/micro-app 现行方案，天然多应用在线。

### 7.4 样式隔离三路线

Shadow DOM（强，弹窗逃逸）/ 选择器前缀（中，运行时改写）/ 动态样式表（中，整批启停）。工程落点：wujie/WC 用 shadow，micro-app 用前缀且默认开，qiankun 多数不开。

### 7.5 副作用记账清理

沙箱拦截 `setInterval`/`addEventListener` 记账，unmount 统一回滚——与属性记账同一思路，记的对象换成副作用。

## 8. 应用通信与状态共享（原理）

### 8.1 五方案通信矩阵

同一动作（点击订单）五条通道：postMessage / setGlobalState / dispatch / bus.$emit / CustomEvent——语义同构，差异只在载体。发送端 20 行 switch 分流，接收端五通道集中适配。

### 8.2 props 透传

一次性、单向、低频下发。wujie `:props`、micro-app `:data` 是工业化形态。

### 8.3 事件总线

通知类交互。三纪律：事件名加前缀、unmount 退订、payload 拷贝。

### 8.4 shared store 与 initGlobalState

持续读写的公共状态。qiankun 的 initGlobalState 是内置版（广播语义、轻状态专用）；MF 体系走 shared singleton 包。分工：事件传"发生了什么"，store 存"现在是什么"。

### 8.5 路由同步与协议兼容

路由真相源唯一（主应用）；子应用跳转用 Router API 不改 location.href；popstate 由主应用分发防双跳。通信协议是公共 API：新增向后兼容、删除留周期、payload 内嵌版本字段。

## 9. 资源加载与依赖共享（原理）

### 9.1 三种产物形态与加载链路

dev server（iframe 用）/ UMD 产物（qiankun/micro-app/wujie 共用）/ 自定义元素产物（WC 用）。远程加载主干：fetch entry → 解析 → 执行 → 挂载，三家实现同构。

### 9.2 url 级缓存与预加载

同 url 全生命周期只拉一次（命中缓存 0 网络开销）；预加载只抓资源不执行。

### 9.3 Module Federation shared 协商

从高到低找同时满足所有消费方约束的版本：找到全场一份；找不到按约束分组 fallback（代价是多份副本不是报错）。

### 9.4 构建期与运行期协同

构建期外置 shared 依赖出版本清单；运行期容器协商只加载需要的 chunk。要点：singleton 语义（React/hooks 状态全局唯一）、版本范围从宽、上线核对 copies===1。

## 10. 手写 mini 微前端框架（原理落点）

### 10.1 四层结构

run.cjs（假 CDN）→ scheduler.cjs（调度）→ entry.cjs（解析/样式）→ sandbox.cjs（隔离）。约 200 行装下容器式微前端全部主干。

### 10.2 沙箱/解析/调度三件套

多例 Proxy + 副作用记账；HTML entry 正则解析 + scoped 前缀；url 级缓存/预加载/start/stop。`with(window)` 是裸标识符走 Proxy 的关键（micro-app 同款）。

### 10.3 mini 机制与五方案的对应收束

parseHtmlEntry ↔ import-html-entry；with(proxy) ↔ qiankun/micro-app 沙箱；scopeStyle ↔ scopecss；手动 start/stop ↔ 路由驱动。先造轮子再认轮子——生产机制的每一个模块都有你亲手写过的原型。
