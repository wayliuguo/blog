## 知识主线（一句话）

本模块把"解耦"从代码层一路推到系统层：01 设计模式与 02 组件设计给出单个模块内的解耦词汇与界面单元边界；03 前端架构与分层把它拉成整个项目的依赖方向（六层单向依赖 + 四类可自动检查的违规）；04~07 是四个高频落地场景——权限（准入）、请求层与缓存（数据进出）、大文件上传（重数据传输）、虚拟滚动（大数据渲染），每篇都在回答同一个问题：**边界画在哪，怎么自动守住**。

## 高频核心点

### 01 设计模式在前端

**九种高频模式一句话**

- **单例**：全局唯一实例，用于全局 store / 事件总线 / Toast（构造器判断已有实例直接返回）
- **观察者 / 发布订阅**：一方变化、多方自动更新；Observer 直持观察者列表，Pub/Sub 中间加事件中心彻底解耦（`reactive`、事件总线）
- **工厂**：由参数决定返回哪种实例，调用方不关心构造细节
- **策略**：一组可替换算法各自封装、上下文选择，用组合替代大量 if/else（表单校验）
- **代理**：不改原对象、访问前后插逻辑（防抖节流、Proxy 响应式、拦截器加 token）
- **装饰器 / 适配器 / 组合 / 命令**：不改原对象叠加能力（HOC、埋点）/ 接口翻译（统一数据结构）/ 树形结构一致接口 / 操作封装成对象支持撤销重做

**选型对照**

- 创建与结构：全局唯一→单例；参数化创建→工厂；树形→组合
- 行为与协作：一对多→观察者/发布订阅；替换算法干掉 if/else→策略；撤销重做→命令
- 接口与增强：访问前后插逻辑→代理；不改对象加能力→装饰器；接口不匹配→适配器

**实践建议**：先有真实"变化点"再上模式（否则过度设计）；优先组合而非继承；读 Vue / Redux / axios 源码对号入座是掌握模式最快方式

### 02 组件设计

**设计原则**：单一职责（解释时用"并且/还有"即职责过重）；开闭原则最具指导性——用 props/slots 扩展而非改内部源码；"三次法则"防过度抽象（第三次出现才真正抽象）

**划分策略**：原子设计五层（atoms→molecules→organisms→templates→pages）；容器管数据/状态/逻辑 vs 展示组件只收 props 渲染；受控 vs 非受控按"数据由谁拥有"取舍

**props 与通信**：props 收窄职责 + 合理默认值 + 单向数据流 + TS 类型即文档；子传父用回调 props / emits；深层跨层交给 Context / provide-inject / 状态库而非层层透传；组合优于继承

**复用手段演进**：HOC 问题在 props 来源混乱、包装地狱；Render Props 数据来源清晰但回调地狱；**Hooks / Composable 是当代首选**——逻辑与 UI 彻底解耦、可组合可测试

### 03 前端架构与分层

- **目录即架构**：按类型切横跨多目录、按领域切改动集中，核心差别是**改动半径**；顶层按领域、领域内按类型是主流
- **六层单向依赖**：`views → hooks → store → api → utils → shared`，反向禁止；`toLayer > fromLayer` 即算反向违规
- **视图额外约束**：禁直连 `utils/http`、`utils/storage`，请求与存储必须走 api
- **四类可自动检查的违规**：反向依赖 / 绕过接口层 / 跨领域引用（应走公共出口 `index.js`）/ **循环依赖**（初始化顺序不可预测，项目小时不报错、最危险）
- **扇入与影响面**：扇入高（如 constants 波及 84%）必须有单测，扇入低可放手重构；下线判据是"消费方不存在"
- **分层不是越细越好**：间接层本身是成本，信号没出现就先不分
- **规约落进 CI**：`no-restricted-imports` / `eslint-plugin-boundaries` / `dependency-cruiser`；循环反向往报错、跨领域警告起步；baseline 只许降不许升

### 04 权限系统设计

- **只认权限码（RBAC）**：用户→角色→权限码（`资源:动作`），前端只判断"有没有这个码"；`role==='admin'` 会让角色×操作组合爆炸
- **通配取舍**：`*` 慎用、写/删动作逐个列举——具体码安全默认，通配让危险动作自动放行
- **路由级**：菜单由过滤后的路由派生（单一来源）；叶子剪码、父节点因子项全剪而整枝消失；`addRoute` 后要重新导航、刷新要有 `routesLoaded` 标记
- **按钮级**：先看路由可达性（实测 12 按钮里 7 个路由本身就进不去）；权限码写常量防魔法字符串
- **数据级**：脱敏在下发之前——服务端裁剪响应体 ≠ 前端打码；行级必须服务端注入查询条件、列级可降级为聚合
- **契约与边界**：下发权限码数组而非角色名；前端权限只做体验收敛，真正边界是接口鉴权

### 05 请求层与缓存设计

- **职责边界**：该管 baseURL/超时/token/拦截器/去重/并发上限/缓存/取消重试；不该管业务规则、loading、跳路由（401 除外）；HTTP 码进 `catch`、业务码进 `then`
- **拦截器是洋葱**：请求拦截器**后注册先执行**、响应拦截器**先注册先执行**（axios 同款：request 用 unshift、response 用 push）
- **竞态**：慢请求后到覆盖新结果；两种保护——自增令牌比对 + `AbortController` 掐断；`AbortError` 是主动取消不是错误，混进上报会淹没真实错误
- **去重与并发上限**：in-flight 表复用 Promise、**请求结束后才清**（仅防"同时发生"）；并发 `4~6` 安全、去重放并发控制之前、首屏关键请求可插队
- **缓存与失效**：TTL 把命中压到近 0 网络、`force` 是刷新出口；SWR 先交旧值后台刷新（适合列表详情，不适合余额库存）；失效策略：写后就地删 key ＞ 标签失效 ＞ 短 TTL 兜底

### 06 大文件上传与断点续传

- **为什么切片**：失败全量重来、进度不可信（onprogress 是"已交缓冲区"）、服务端要一次性缓冲、无法并发——切片一次全解
- **协议四端点**：`init`（含秒传判定）/ `part`（**必须幂等**，断点续传的地基）/ `status`（查缺失）/ `complete`（校验关不是合并关，缺片返回 400 + missing 数组）
- **并发取值**：`3~4`（同域 HTTP/1.1 只有 6 条连接，超了在连接层排队）；分片 `1~5MB`
- **断点续传**：靠 `init` 返回的 `received` 续传；`uploadId` 按文件指纹复用；`chunkSize` 定下不许改；会话要过期清理
- **秒传与指纹**：判据是 sha256 内容指纹；**指纹计算必须放 Web Worker / crypto.subtle**（50MB 同步 132ms）；服务端 `complete` 阶段仍要校验、不能只信客户端
- **完整性与进度**：合并后必须重算哈希（截断/改写/ index 错都会坏文件）；进度按**已确认分片数**聚合不按已发出字节（否则先冲到 100% 再卡住）

### 07 虚拟滚动与大数据渲染

- **三要素**：内容容器高 `total×rowH` 撑滚动条、渲染区间 `[start,end)`、`translateY(start×rowH)` 平移；`start=floor(scrollTop/rowH)`、`end=start+ceil(viewportH/rowH)`
- **性质**：渲染量与数据量无关（十万条也渲染十几条）；省 DOM 与渲染、**不省内存**（百万级配分片/游标分页）
- **与分页 / 懒加载区别**：分页要点击不能连续滚；懒加载首屏与总高度持续增长；虚拟滚动两者恒定
- **缓冲区**：`overscan` 多渲染 `overscan×2` 条、取值 5~10；更快滚动靠空位骨架不是加大缓冲；scroll 放 rAF
- **不定高：前缀和 + 二分**：`offsets[i]` 前 i 条总高、二分定位起点（实测 16 步 vs 线性 50001 步）；单行高度变化增量更新、未测量行先估后回填；**能定高就别做不定高**
- **滚动锚定**：顶部插入要 `scrollTop += 插入总高` 补偿；隐蔽触发源是图片加载撑高上方内容；`overflow-anchor` 对虚拟列表无效
- **细节**：key 用业务主键（下标会让输入框串行）；行内事件用事件委托 `closest()`；搜索在数据层做（防抖 200~300ms）
