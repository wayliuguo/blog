# AI 前端工程：模块总结

> 本模块 4 篇，回答一个问题：**怎么把 AI 能力做成真正好用的前端产品。**

## 知识主线

```
01 LLM 应用前端形态（对话式 UI / SSE vs WebSocket / 流式渲染 / 中断与重试）
        │  前端能把流接进来了，但模型吐出来的东西怎么保证能用？
        ▼
02 AI 与前端工程结合（结构化输出 / 白名单 DSL / 上下文装配 / 设计稿转代码边界）
        │  能不能不联网、不出端也跑起来？代价是什么？
        ▼
03 端侧推理与 WASM（分片加载 / WASM 内核 / 内存预算 / Worker 卸载）
        │  功能跑起来了，等待、成本与失败时怎么办？
        ▼
04 AI 应用的性能与体验（TTFT 分解 / flush 合帧 / 成本模型 / 降级阶梯）
```

与 `ai/` 板块的边界：`ai/` 讲工具怎么用，本模块讲「如何把 AI 能力做进前端产品」——通信协议、可靠性、性能与成本。

## 分篇知识点

### 01-LLM 应用前端形态

- **对话式 UI 三前提失效**：响应长度不确定、时间是流式的、正确性需前端兜底
- **传输选型**：纯文本生成用 SSE（自动重连 + Last-Event-ID 续传），双向/二进制才用 WebSocket
- **SSE 解析按行分帧**：逐字节与撕裂分包实测都能完整还原事件，残行必须留在缓冲区
- **流式渲染半开代码块**：fence 奇偶判断，半开按住 2 次增量、闭合放行，语法不外泄
- **中断语义**：abort 后已收 token 保留、后续丢弃
- **重试双防**：指数退避 300→8000 封顶 + 抖动，全程同一幂等键防重复计费

### 02-AI 与前端工程结合

- **三层基建**：上下文（检索+装配）、约束（schema+DSL）、评测（prompt 即隐性发版）
- **噪声剥离实测**：围栏/客套话包裹的 JSON 三轮修复重试后通过，错误清单回喂是关键
- **组件生成走白名单 DSL**：schema 即文档，坏结果按节点定位；表达力被锁死是定价不是缺陷
- **上下文装配**：预算 1600 装下 1520 的 system+检索+代码，历史对话最先丢
- **token 粗算**：中文按字、英文按 4 字符，80% 填充兜底误差
- **设计稿转代码**：布局骨架高自动化，交互逻辑与可访问性仍是人的边界

### 03-端侧推理与 WASM

- **端侧 vs 云端**：隐私/离线/零边际成本 换 体积/算力/兼容；落地形态是分层
- **分片加载实测**：80MB 分 20 片，峰值缓冲区 4MB（整包需 80MB）
- **WASM 反直觉实测**：2e7 紧循环 WASM 46.6ms vs JS 16.0ms，慢约 3×；价值在可移植与无 deopt/GC 停顿
- **内存预算**：1B 参数 fp16 2.0GB，int4 量化 0.50GB（1/4）；4k 上下文 KV cache 384MB 且线性增长
- **线程模型**：单帧 20ms 推理 ×3 = 60ms 主线程零响应，必须 Worker + WebGPU/WASM/云端降级链

### 04-AI 应用的性能与体验

- **TTFT 三段分解实测**：428ms → 342ms；队列段前端改不动，能做的是连接复用 + 上下文压缩 + 感知填充
- **flush 合帧实测**：600 token 的 DOM 更新 600 → 150 次（25%）
- **成本实测**：单次 0.0390 → 前缀缓存 0.0228 → 叠加压缩 0.0185；前缀必须字节级稳定
- **降级阶梯**：full → lite（切小模型）→ short（限上下文）→ static（静态兜底 + 重试入口），且要可见
- **指标**：TTFT(P90) / TPOT / 完成率 / abort 率 / 单位成本，abort 率按 prompt 版本分组

## 最小实现

- **`ai-lab`**：零依赖探针实验台，`node run.cjs` 依次执行四探针（SSE 分帧/半开代码块/中断/重试 · 结构化输出/上下文装配/token 估算 · 分片加载/手工 WASM 内核/内存预算/主线程阻塞 · TTFT/flush 合帧/成本/降级），`node:assert` 自检全绿
