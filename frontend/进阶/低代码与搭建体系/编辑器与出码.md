# 编辑器与出码

前两篇把 schema 到组件树的链路跑通了，这一篇补上「谁来生产 schema」和「产物怎么脱离平台」。编辑器负责让人**看得见地改**，出码负责让产物**离得开平台**——两件事看着独立，实际共用同一套节点模型：编辑器改的是 schema，出码读的也是 schema。这一篇用 `lowcode-lab` 的 `editor.cjs` 逐条给出实现与实测。

## 一、编辑器交互：落点判定与树操作约束

拖拽是编辑器的门面，也是 bug 最密集的地方。核心就两个判定：**指针落在目标容器的哪一段**（决定是插为兄弟还是塞成孩子）、**这次移动会不会形成环**（把父节点拖进自己的子孙里）。

> 摘自 `./code/lowcode-lab/editor.cjs`

```js
function computeDrop(rect, pointerY) {
  // 上 25% 是「插到前面」，下 25% 是「插到后面」，中间 50% 是「放进里面」
  const edge = rect.height * 0.25
  if (pointerY < rect.top + edge) return 'before'
  if (pointerY > rect.top + rect.height - edge) return 'after'
  return 'inside'
}

function isDescendant(root, ancestorId, maybeChildId) {
  const found = findNode(root, ancestorId)
  if (!found) return false
  let hit = false;
  (function walk(node) {
    if (node.id === maybeChildId) hit = true;
    (node.children || []).forEach(walk)
  })(found)
  return hit // 注意：ancestor 自身也算命中，所以「拖到自己身上」同样被挡掉
}
```

> 摘自 `./code/lowcode-lab/editor.cjs`

```js
{
  const rect = { top: 0, height: 200 }
  assert.equal(computeDrop(rect, 10), 'before')
  assert.equal(computeDrop(rect, 100), 'inside')
  assert.equal(computeDrop(rect, 190), 'after')
  assert.equal(isDescendant(page, 'list', 'item'), true)
  assert.equal(isDescendant(page, 'item', 'list'), false)
  console.log('[1] 拖拽落点：上/中/下三段判定正确，把 list 拖进 item（自己的子孙）被拒绝')
}
```

几个容易忽略的点：

- 三段比例不是固定的 33%。容器高度很小时（一行文字高），上下各 25% 只有几像素，用户几乎塞不进中间——**要给边缘区一个最小像素值**（如 `Math.max(h * 0.25, 8)`），否则小容器永远只能"放进里面"。
- `isDescendant` 把自身也算命中，所以「拖到自己身上」被一并挡掉。这个判定必须在**移动前**做，而不是移动后校验树——移动后再校验，页面已经闪过一次错位的 UI。
- 落点计算依赖 `getBoundingClientRect`，滚动与缩放会让它漂移。实测里最常见的是**画布用了 CSS `transform: scale()` 做缩放预览**：`rect` 是缩放后的值，而指针坐标来自 `clientX/Y`，两者混算会整体偏移。要么把指针坐标除以缩放比，要么统一用画布内的相对坐标。

## 二、属性面板：隐藏字段必须连带清值

属性面板看着是表单，坑在**字段之间的依赖**：改了 A，B 应该消失。很多人只做「隐藏」，不做「清值」，于是提交了一份看不见的旧值——线上表现为「我明明选了上传，怎么还在请求那个 URL」。

> 摘自 `./code/lowcode-lab/editor.cjs`

```js
const fieldSchema = {
  srcType: { type: 'enum', options: ['url', 'upload'] },
  url: { type: 'string', visibleWhen: 'srcType === "url"' },
  fileId: { type: 'string', visibleWhen: 'srcType === "upload"' }
}
```

> 摘自 `./code/lowcode-lab/editor.cjs`

```js
  // 这里用「显式解构 + 求值」而不是 with：本文件开了 'use strict'，且属性条件只依赖 values 一个来源
  const evalCond = (cond, values) => new Function('values', `const { ${Object.keys(values).join(', ')} } = values; return (${cond}); `)(values)
  const normalize2 = values => {
    const out = {}
    for (const [k, v] of Object.entries(values)) {
      const f = fieldSchema[k]
      if (!f) continue
      if (f.visibleWhen && !evalCond(f.visibleWhen, values)) continue
      out[k] = v
    }
    return out
  }
  assert.deepEqual(normalize2({ srcType: 'url', url: 'https://a', fileId: 'f1' }), { srcType: 'url', url: 'https://a' })
  assert.deepEqual(normalize2({ srcType: 'upload', url: 'https://a', fileId: 'f1' }), { srcType: 'upload', fileId: 'f1' })
  console.log('[4] 属性联动：切换 srcType 后不可见字段被连带清空（url / fileId 互斥，不留幽灵值）')
```

注意这里清洗发生在**提交时**而不是渲染时。渲染时清洗会导致用户切回来发现值没了（体验差），提交时清洗才能保证落库数据干净；更好的做法是**切换时立即清值并给一次提示**，两者都做。

## 三、出码：schema 编译成人能读的源码

出码的目标不是「让代码能跑」——运行时渲染已经能跑了。出码的目标是让产物**脱离平台后仍然可维护**：能进 git、能 code review、能被专业开发接手。所以它必须是人写的样子，而不是一堆运行时解释的中间态。

> 摘自 `./code/lowcode-lab/editor.cjs`

```js
function serializeProp(v) {
  if (typeof v === 'string' && /^(state|item|index)\b/.test(v)) return `{${v}}` // 表达式
  if (typeof v === 'string') return JSON.stringify(v) // 字面量字符串
  return `{${JSON.stringify(v)}}`
}
```

> 摘自 `./code/lowcode-lab/editor.cjs`

```js
  const props = Object.entries(node.props || {})
    .map(([k, v]) => ` ${k}=${serializeProp(v)}`)
    .join('')
  const children = node.children || []
  let inner = ''
  if (node.loop) {
    // 循环：容器本身保留，子项在 map 里展开，并补 key（否则列表更新会整段重建）
    const body = children.map(c => codegen({ ...c, props: { key: 'index', ...(c.props || {}) } }, depth + 2)).join('\n')
    inner = `\n${pad}  {${node.loop}.map((item, index) => (\n${body}\n${pad}  ))}\n${pad}`
  }
```

条件编译成三元（false 分支显式 `null` 而不是留空），循环编译成 `map` 并**自动补 `key`**。探针实测输出：

```
<Page>
  {state.vip ? (
    <Banner title="大促" vip={state.vip} />
  ) : null}
  <List>
    {state.items.map((item, index) => (
      <Text key={index} text={item.name} />
    ))}
  </List>
</Page>
```

出码最容易翻车的三处：

- **key 不能省**。循环里不写 key，列表一更新整段重建，输入焦点、动画、滚动位置全丢。平台侧必须自动补，不能指望搭页面的人记得。
- **表达式与字面量要分道**。上面 `title="大促"` 是字符串、`vip={state.vip}` 是表达式，全靠 `serializeProp` 的前缀约定区分。约定一旦含糊（比如允许 <code v-pre>{{...}}</code> 和裸字符串两种写法同时存在），出码就会出现 `title="state.xxx"` 这种把表达式当字符串输出的静默错误。
- **括号配平要断言**。探针里直接断言了 `(`/`)` 与 `{`/`}` 数量相等——出码错一个括号，编译期才报错，而那时用户已经不知道是自己的 schema 有问题了。

## 四、手写区：二次出码不许吃掉人写的代码

出码那一刻就产生了两个真相：schema 与源码。最毁信任的事是「我手改过，平台一导出又没了」。解法是**锚点**：出码时把手写区原样搬回。

> 摘自 `./code/lowcode-lab/editor.cjs`

```js
function extractRegions(source) {
  const re = /\/\* @region:start (\w+) \*\/([\s\S]*?)\/\* @region:end \*\//g;
  const out = new Map()
  let m
  while ((m = re.exec(source))) out.set(m[1], m[2])
  return out
}
```

> 摘自 `./code/lowcode-lab/editor.cjs`

```js
  const kept = []
  const missing = []
  for (const [id, body] of regions) {
    const s = lines.findIndex(l => l.includes(`@region:start ${id}`))
    const e = lines.findIndex(l => l.includes('@region:end'))
    if (s >= 0 && e > s) {
      lines.splice(s + 1, e - s - 1, ...body.split('\n').filter(l => l.length))
      kept.push(id)
    } else {
      missing.push(id)
    }
  }
  if (missing.length) lines.push('', ...missing.map(id => `// 已失效的手写区 ${id}：${regions.get(id).trim()}`))
  return lines.join('\n')
```

实测两种结果：锚点还在 → 手写代码原样搬回；锚点被整块删掉 → **降级为注释挂在文件末尾**，而不是静默丢弃。这个降级很关键：静默丢代码，用户要过很久才发现；留下注释，至少 `git diff` 里看得见。

要点：

- 编辑器改的是 schema，出码读的也是 schema——两者共用一套节点模型，不要维护两份结构定义。
- 拖拽的两个判定：落点三段（小容器要给边缘区最小像素）、移动前做环检测。
- 属性面板的字段依赖要**连带清值**，清洗点在提交时（或切换时），不能只隐藏。
- 出码产物要能进 git：三元、map、key、括号配平都要自动化保证。
- 手写区用锚点标记，二次出码原样搬回；锚点失效降级为注释，绝不静默丢弃。
