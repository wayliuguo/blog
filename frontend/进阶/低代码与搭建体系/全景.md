# 低代码与搭建体系全景

## 一、四层架构：越往下越难改

低代码平台不是「一个编辑器」，而是四层叠加的系统——**每层都可以单独讲一小时，但协议层决定其余三层的上限**：

| 层 | 内容 | 改动代价 | 本模块篇目 |
| --- | --- | --- | --- |
| 协议层 | schema 结构、物料描述、表达式约定 | **最高**：牵动所有存量页面 | [协议与 schema 设计](./协议与%20schema%20设计.md) |
| 渲染层 | schema → 组件树（沙箱、条件、循环、更新粒度） | 高 | [渲染引擎](./渲染引擎.md) |
| 编辑器层 | 拖拽、属性面板、撤销重做 | 中（可重构） | [编辑器与出码](./编辑器与出码.md) |
| 物料层 | 具体组件 | 低（随时加） | — |

一个反直觉的结论：**低代码平台的第一份交付物不是编辑器，是协议**。编辑器可以重写，渲染器可以换框架，唯独 schema 一旦有存量页面落库，每一步演进都要带迁移链走。

## 二、与三条路线的关系

| 路线 | 代表 | 本模块的取舍 |
| --- | --- | --- |
| 开源引擎 | 阿里 lowcode-engine、 amis | 协议思想同源（物料描述 + 表达式 + 数据源），本模块取其「协议即契约」的最小内核自研讲解 |
| SaaS 搭建 | 各家云厂商搭建平台 | 边界判断（什么该上平台）、成本账（变更盈亏平衡）完全适用 |
| 自研最小平台 | 大厂内部平台 | 本模块的落点：四篇正文各自给出可实测的最小机制，`mini-lowcode` 给出可跑的真实工程 |

## 三、统一业务场景：运营活动页搭建器

四个角色绑同一个场景：**运营提需求 → 产品搭页面 → 开发接扩展**。

- **协议层**：活动页 schema（Banner / 商品 List / 报名表单），带 version 与迁移链——活动每年改版，老活动页必须能活到新协议；
- **渲染层**：`state.vip` 控制会员 Banner 显隐（表达式沙箱），商品列表 `loop` 展开（子项 id 带下标）；
- **编辑器层**：运营改文案、切图片上传方式（属性联动清值）、撤销重做；
- **出码与边界**：活动页要被专业开发接手时出码脱离（hash 漂移检测），变更次数逼近盈亏平衡点时是出码信号。

真实工程 `code/mini-lowcode/`（vite + Vue，`npm run dev` 起 5201）把这个场景做成了可操作的三栏搭建器：画布 + 属性面板 + 出码预览。

## 四、本模块的探针实验台

`lowcode-lab`（`node run.cjs` 依次执行）把每个机制用 `node:assert` 钉死：

```
schema.cjs    物料协议校验 / 版本迁移链 / 重复 id 与循环引用检测
render.cjs    表达式软沙箱 / 递归渲染（条件剪枝 + 循环展开）/ 更新粒度对比
editor.cjs    拖拽落点三段 / 出码（三元、map、补 key）/ 手写区锚点 / 属性联动清值
boundary.cjs  适用性短板判定 / 出码漂移检测 / 变更成本盈亏 / 逃逸机制
```
