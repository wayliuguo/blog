# 低代码与搭建体系：面试题

> 格式：结论 → 原理 → 边界/坑 → 追问。标注「第 X 篇」的题目按阅读顺序出题。

### Q1: 搭建平台里，为什么协议（schema）要最先定稳？（第 1 篇）

- **结论**：四层改动代价排序是**协议 > 渲染 > 编辑器 > 物料**，越靠底层改动越贵。协议一变，存量 schema、渲染器、编辑器、物料全要跟着动。
- **原理**：协议是唯一会被持久化并跨版本存在的东西（数据库里躺着几万份 schema）。渲染器改了重新发版即可，协议改了要写迁移链、要兼容老数据、还要保证老页面不崩。
- **边界**：协议不可能一次定对，所以要**一开始就留版本号字段和迁移链机制**，而不是等第一次大改时临时补救。
- **追问**：有了版本号还需要迁移链吗？→ 需要。版本号只告诉你「从哪来到哪去」，迁移链才定义每一级怎么走；跨多级的老数据要逐级迁移（实测 v1 → v3 走两级）。

### Q2: schema 版本迁移要注意什么？（第 1 篇）

- **结论**：迁移是**逐级链式**执行，每一级只负责自己那一次变更；补默认值和清理废弃字段都要在链里完成。
- **原理**：实测（`lowcode-lab/schema.cjs`）——v1 页面经两级迁移到 v3，补上默认值 `size=md`，旧字段 `visible` 改写为 `when` 且被清理干净。
- **边界**：迁移必须**幂等且可回滚**：同一份 schema 迁移两次结果一致；迁移失败要能停在半路并给出明确错误，而不是写坏一半。
- **追问**：为什么不能一次性写个 v1→v3 的大迁移？→ 存量数据版本分布不可控（可能有 v2 的），且大迁移一旦出错无法定位是哪一步；链式迁移每一级都能单独测试。

### Q3: 渲染前为什么必须先建索引并做校验？（第 1 篇）

- **结论**：重复 id 与循环引用必须挡在渲染之前，否则定位错乱、递归栈爆掉，且错误现象离根因很远。
- **原理**：实测（`lowcode-lab/schema.cjs`）——正常树 4 节点无错；重复 id 与循环引用都被检出。环检测按**对象身份**做（维护访问过的对象集合），不能用值比较（两个内容相同的节点会被误判）。
- **边界**：索引还承担了「按 id 定位脏节点」的职责（见第 2 篇更新粒度），一份索引两用。
- **追问**：循环引用在什么操作里最容易产生？→ 复制粘贴节点（把父节点粘进子节点）和拖拽（见第 3 篇），两处都要拦。

### Q4: 用户写的表达式怎么关进沙箱？`with` 有哪些坑？（第 2 篇）

- **结论**：`with` + `Proxy` 软沙箱：所有标识符先过一道 `get`，不在白名单作用域里的一律抛错。
- **原理**：实测（`lowcode-lab/render.cjs`）——`state`/`item` 可用，`window`/`process` 一律抛错。两个必须知道的坑：**① `with` 在严格模式禁用**，所以该文件不能写 `'use strict'`；**② `with` 会先查 `Symbol.unscopables`**，symbol 键必须放行，否则连合法表达式都跑不起来。
- **边界**：这只是**软沙箱**，原型链逃逸（`({}).constructor.constructor('return process')()`）依然存在，只防误用不防恶意；真隔离靠 Web Worker 或 iframe `sandbox`。
- **追问**：为什么不干脆禁用用户表达式？→ 禁用意味着条件、循环、插值全做不了，平台立刻退化成静态页生成器；正确做法是限制能力 + 隔离执行。

### Q5: 循环节点展开成什么结构？为什么要带 key？（第 2 篇）

- **结论**：循环节点**本身保留为容器**，展开的是它的子项，且子项 id 要带下标（如 `item#0`）；列表项必须带稳定 `key`。
- **原理**：把自己展开成 N 个兄弟会让父层节点数失控，且 N 个同名 id 会导致定位与局部更新全错。实测（`lowcode-lab/render.cjs`）——循环展开 2 份且 `item` 变量在子项作用域内可见。
- **边界**：`key` 要稳定且尽量用业务 id 而不是下标（下标在插入/删除时会导致整段重建）；出码时探针自动补 `key={index}` 是兜底，不是最优解。
- **追问**：条件节点和循环节点同时存在时怎么展开？→ 先判条件（不成立整棵剪掉），再展开循环；顺序反过来会白算一遍子项。

### Q6: 改一个属性要整棵树重渲染吗？（第 2 篇）

- **结论**：不要。按 id 定位脏节点，只重算它的子树；依赖关系要收集到「哪个 state 字段 → 哪些节点」。
- **原理**：实测（`lowcode-lab/render.cjs`）——全量渲染访问 5 个节点，只重算脏子树 3 个。编辑器里每拖一下就全量重渲染，页面一大就卡，这是搭建平台卡顿的头号原因。
- **边界**：表达式依赖是**运行时**才能确定的（用户写 `state.a.b.c`），所以要么在渲染时动态收集依赖，要么静态分析表达式取根字段（保守取 `state.a`）。
- **追问**：局部更新失效时会表现成什么？→ 改了属性页面没反应，或者要切换一下面板才刷新——典型的依赖没收集全。

### Q7: 拖拽落点怎么算？什么操作必须拦？（第 3 篇）

- **结论**：按目标容器的上/中/下三段判定 `before` / `inside` / `after`；**把节点拖进自己的子孙必须拦**，且要在移动前拦。
- **原理**：实测（`lowcode-lab/editor.cjs`）——三段判定正确，`isDescendant(page, 'list', 'item')` 为 true 时拒绝移动；该判定把自身也算命中，顺带挡掉「拖到自己身上」。
- **边界**：两处工程细节——小容器要给边缘区**最小像素值**（否则永远塞不进中间）；画布用了 CSS `transform: scale()` 时，`getBoundingClientRect` 是缩放后的值，指针坐标要除回缩放比。
- **追问**：属性面板的字段联动要注意什么？→ **隐藏不等于清值**：只隐藏不清值，用户会提交一个看不见的旧值。实测切换 `srcType` 后 `url` / `fileId` 互斥字段被连带清空。

### Q8: 出码之后，schema 和源码谁说了算？（第 3、4 篇）

- **结论**：出码那一刻就产生两份真相。用 hash 检测漂移：**原样 = clean**（可安全重新出码覆盖），**手改过 = drifted**（必须先 diff 或标记为源码优先）。
- **原理**：手写区用锚点注释标记，二次出码时原样搬回；锚点被整块删掉时**降级为注释保留**在文件末尾，绝不静默丢弃。实测（`lowcode-lab/boundary.cjs`）——手改一行即判 `drifted`。
- **边界**：什么时候该彻底脱离平台？看成本账——实测搭建 8h vs 24h、单次变更 2.5h vs 0.8h，**盈亏平衡在第 9.4 次变更**；低频变更页面是低代码主场，高频演进的核心页面应尽早出码脱离。
- **追问**：未注册的物料怎么处理最稳妥？→ **明确抛错**，绝不静默降级成 `<div>`；静默降级会把错误推迟到线上，最后只表现成「这块样式不对」。平台的逃生舱是「注册自定义物料」，不是让用户在表达式里写业务。
