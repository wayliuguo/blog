# 低代码与搭建体系：模块总结

> 本模块 4 篇，回答一个问题：**搭建平台从协议到渲染到出码的完整技术栈，以及它的边界在哪。**

## 知识主线

```
01 协议与 schema 设计（物料协议 / 版本迁移 / 索引与环检测）
        │  schema 有了，怎么稳定、够快地变成组件树？
        ▼
02 渲染引擎（表达式沙箱 / 递归渲染 / 条件与循环 / 更新粒度）
        │  谁来生产 schema，产物又怎么脱离平台？
        ▼
03 编辑器与出码（拖拽落点 / 属性联动 / schema→源码 / 手写区锚点）
        │  什么场景不该用，用了之后这份代码归谁？
        ▼
04 低代码的边界（适用性打分 / 逃生舱 / 成本盈亏 / 双真相治理）
```

四篇共用一套节点模型（id / type / props / children / when / loop），协议层框架无关、渲染层框架相关，两者用适配器解耦。

## 分篇知识点

### 01-协议与 schema 设计

- **四层改动代价**：协议 > 渲染 > 编辑器 > 物料，越靠底层改动越贵，协议要最先定稳
- **物料注册表 + props 描述**：一份描述三用（校验 / 属性面板 / 文档）
- **校验实测**：必填 / 类型 / 枚举 / 未注册四类全命中，未知组件直接拒绝
- **版本迁移实测**：v1 → v3 两级迁移，补默认值 `size=md`、旧字段 `visible → when` 且清理干净
- **索引校验**：重复 id 与循环引用（按对象身份检测）都挡在渲染之前

### 02-渲染引擎

- **表达式沙箱实测**：`state`/`item` 可用，`window`/`process` 一律抛错
- **`with` 两个坑**：严格模式禁用（该文件不能写 `'use strict'`）；会先查 `Symbol.unscopables`，symbol 键必须放行
- **软沙箱只防误用**：原型链逃逸仍在，真隔离靠 Worker / iframe
- **递归渲染实测**：条件剪枝（顶层 2 → 1 个）、循环展开 2 份且 item 变量可见
- **循环是容器 + N 子项**，子项 id 带下标保证可定位
- **更新粒度实测**：全量渲染 5 个节点 vs 只重算脏子树 3 个

### 03-编辑器与出码

- **拖拽落点实测**：上/中/下三段判定 before / inside / after
- **落点两处工程细节**：小容器要给边缘区最小像素；缩放画布需把指针坐标换算回画布坐标
- **环检测必须在移动前做**：`isDescendant` 把自身也算命中，顺带挡掉「拖到自己身上」
- **属性联动实测**：切换 `srcType` 后不可见字段被连带清空（`url` / `fileId` 互斥），不留幽灵值
- **出码实测**：条件 → 三元（false 分支显式 `null`）、循环 → `map` 并自动补 `key`、字面量与表达式分道
- **括号配平断言**：出码错一个括号会把错误推迟到编译期
- **手写区锚点实测**：二次出码原样搬回手写代码；锚点被删时降级为注释保留而非静默丢弃

### 04-低代码的边界

- **适用性实测**：表单 = 低代码（总分 2）、看板 = 低代码+扩展点（6）、画布编辑器 = 专业开发（单维满分出局）
- **短板决定上限**：交互 / 状态 / 集成 / 性能任一维满分即不宜进平台
- **逃生舱实测**：未注册物料明确抛错而非静默降级成 `div`
- **成本盈亏实测**：搭建 8h vs 24h、单次变更 2.5h vs 0.8h → 平衡点第 9.4 次变更；20 次时 58h vs 40h 专业开发反超
- **低频变更页面是低代码主场**，高频演进的核心页面应尽早出码脱离
- **漂移检测实测**：原样 = clean、手改一行 = drifted；drifted 时必须先 diff 或标记源码优先
- **治理三件事**：schema 与源码一起进版本库、页面级权限、出码产物要有回归测试

## 最小实现

- **`lowcode-lab`**：零依赖探针实验台，`node run.cjs` 依次执行四探针（物料校验/版本迁移/索引环检测 · 表达式沙箱/递归渲染/更新粒度 · 拖拽落点/出码/手写区/属性联动 · 适用性打分/逃逸机制/成本盈亏/漂移检测），`node:assert` 自检全绿
