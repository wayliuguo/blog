# 模块面试题 · 跨端与桌面深化

## 1. 跨端框架原理

### Q1（1.1）｜ 跨端方案三条路线的本质区别是什么？怎么选？

- **判断**：三种路线的区别只有一个问题——**JS（或 Dart）描述的 UI 由谁画出来**；选型在「生态复用 / 体验上限 / 动态化」三点间权衡。
- **展开**：

```
WebView 容器    UI 由系统 WebView 画    → 复用 Web 生态、受 WebView 性能上限
原生渲染 RN      UI 映射成原生控件      → 体验接近原生、付通信成本
自绘引擎 Flutter UI 由自带渲染管线画   → 像素级一致、包体积大、动态化弱
```

高频交互重体验选自绘/原生渲染；内容型页面求快速迭代选容器；同一 App 内混用（容器 + RN）是常态。
- **边界**：没有全局最优；追问「Flutter 为什么一致性好但热更新难」→ 不走 JS 引擎，产物是编译后的机器码，缺 JS 动态下发执行的法律与技术通道。

### Q2（1.2）｜ RN 老 Bridge 为什么慢？新架构 JSI 快在哪？

- **判断**：老 Bridge 每次调用都 JSON 序列化往返 + Promise 包装 + 消息排队、只能异步；JSI 让 JS 直接持有 Native 对象引用，同步直通调用零序列化。
- **展开**：老桥要「JS 编码 → 原生解码 → 处理 → 编码回传 → JS 解码」，两次编解码 + 队列排队，所以同步拿不到返回值。JSI 是 C++ 层、JS 引擎无关（Hermes/JSC/V8 都能接）；配套 TurboModules 按需加载、Fabric 同步渲染。
- **佐证**：`cross-lab/jsi.cjs` 实测 2 万次调用——bridge 72.6ms vs jsi 1.3ms，约 58 倍；序列化有损：`Date` 退化为字符串、函数被静默丢弃。
- **边界**：追问「序列化丢函数意味着什么」→ 回调不能直接过桥，只能靠 `callbackId` 在桥两侧各持半张表关联——这正是 JSBridge 回调表设计的由来。

### Q3（1.4）｜ 小程序为什么用双线程？setData 有什么性能铁律？

- **判断**：双线程（逻辑层 JS 引擎 + 渲染层 WebView + Native 转发）的动机是**安全管控**——渲染层拿不到 BOM/DOM、逻辑层碰不到页面；代价是过桥数据必须可序列化，通信成为第一性能瓶颈。
- **展开**：`setData` 三铁律——同一 tick 的多次 setData 合并成一帧、同 key 取最后一次；只传本次传入的数据、路径写法只通信变化的叶子；函数无法过桥、`Date` 退化为字符串。
- **边界**：`this.data` 同步更新（本地立即可读）而通信异步——不要连续 setData 依赖「渲染已完成」；追问「长列表怎么优化」→ 分页 append 只传新增段、路径写法更新单叶子、避免把整棵大对象重新 set 上桥。

## 2. Hybrid 与 WebView 深度优化

### Q4（2.1）｜ H5 页嵌进 App 白屏一秒起步，怎么系统性优化？

- **判断**：把白屏拆成三段独立成本——容器创建（200~500ms）/ 网络往返 / 首屏渲染——分别对应预热、离线包、预渲染，三段优化可叠加。
- **展开**：预热在空闲期预创建容器进池、点击取用；离线包由容器全权管理、命中零网络；预渲染把壳 + 首屏提前到点击前，只做高概率入口并设超时回收。
- **佐证**：`cross-lab/webview.cjs` 实测——预热池空闲期预创建付 8 单位、点击取用 0 单位、池空冷启动兜底；离线包命中 0 网络、未命中在线兜底。
- **边界**：预热池 2~3 个就够（Android 空 WebView 占 30~50MB）；离线包必须留在线兜底；预渲染不设回收就是内存黑洞；追问「怎么验证有效」→ 白屏分段监控，t0 取容器创建起点，按容器/网络/渲染三段上报归因，没有分段数据就是在猜。

### Q5（2.3）｜ 离线包怎么保证安全？被篡改了怎么办？

- **判断**：每个本地文件带 hash 签名，拦截层命中后**先校验再用**；签名不符拒用本地、回退在线请求。
- **展开**：离线包与 HTTP 缓存的关系——缓存由 WebView 自管、不可控且可能被逐出；离线包由容器全权管理、随包版本可控失效，是「**可控的缓存**」。差量下发走版本清单 + 差量包（全量的 10%~20%），合成后校验整体 hash 再切换生效。
- **佐证**：`cross-lab/webview.cjs` 实测——篡改包内容但不改签名，请求立即回退在线，`networkHits` 加一。
- **边界**：拦截点 Android `shouldInterceptRequest`、iOS `WKURLSchemeHandler`；离线包只解决静态资源，接口数据要走预取。

## 3. JSBridge 设计与演进

### Q6（3.3）｜ JSBridge 的回调表为什么会泄漏？怎么兜底？

- **判断**：Native 不回复（崩溃 / 超时 / 丢消息）时回调表**只进不出**——这就是桥上的内存泄漏；兜底是每 API 设超时，超时 reject 并从表里清理该项。
- **展开**：`callbackId` 关联异步回复、桥两侧各持半张表；铁律是一次性、用后即清——正常回复执行完即删，**重复触发同一 callbackId 直接报错**（协议被破坏的信号）。高频埋点防拥堵：同 tick 入队批量 flush + 队列长度阈值 + `visibilitychange` 强制 flush 防丢尾部数据。
- **佐证**：`cross-lab/bridge.cjs` 实测——超时后 `callbacks.size === 0`；同 tick 三次调用合并成一条消息，空队列不发。
- **边界**：超时按 API 类别分级——读配置几百 ms、支付类放宽到数十秒；**超时不等于失败**，回复晚到要能静默丢弃。

## 4. Electron 与桌面端

### Q7（4.2）｜ Electron 的安全基线是什么？

- **判断**：`contextIsolation: true` + `nodeIntegration: false` + contextBridge 白名单暴露——渲染层看到的不是整个 Node，而是主进程愿意给的少数几个函数。
- **展开**：主进程（Node 完整环境）收拢系统能力，渲染进程跑不可信内容；contextBridge 只把 `expose: true` 的 API 挂上 `window.desktop`；IPC 走 `invoke`/`handle`，未注册 channel **明确 reject 不静默**——静默无响应的 IPC 是排查地狱，开发期炸出来、生产期按 channel 白名单拒绝。
- **佐证**：未暴露的能力在渲染层根本不存在（实测 `exec` 查无此键）。
- **边界**：老项目 `nodeIntegration: true` 一次 XSS 就全盘沦陷；asar 是归档不是加密、可被解包——敏感逻辑放主进程或服务端；追问「为什么未注册 channel 要报错而不返回 undefined」→ 静默无响应没法排查，宁可开发期炸出。

### Q8（4.4）｜ 桌面端自动更新怎么做才能不把用户更新坏？

- **判断**：状态机四步——检查清单版本比对 → 下载 → **hash/签名校验，失败回滚不落盘** → 重启切换入口；宁可停在旧版本，不能让损坏/被篡改的包污染本机。
- **展开**：增量更新（只下 diff）把包体从 100MB 降到几 MB；双版本目录 + 重启切换入口，失败可回退旧目录。桌面端不像 Web「刷新即上线」——代码运行在用户本机磁盘，替换运行中程序有原子性问题，必须重启生效。
- **佐证**：`cross-lab/electron.cjs` 实测——新版本正常落盘；版本相同 `up-to-date`；下载内容与清单 hash 不符返回 `verify-failed`，本地版本保持不变。
- **边界**：连续更新失败要有熔断与回滚预案，不能让用户卡在损坏版本上反复重试。
