# 跨端与桌面深化：模块总结

> 本模块 4 篇，回答一个问题：**一套前端代码跑在 App、WebView、桌面上的原理、优化与边界。**

## 知识主线

```
01 跨端框架原理（三条路线：WebView 容器 / 原生渲染 / 自绘引擎——UI 由谁画）
        │  任何路线都绕不开同一个问题：逻辑层与渲染层之间那座桥怎么设计？
        ▼
02 Hybrid 与 WebView 深度优化（容器路线的账本：白屏三段成本，预热/离线包/预渲染）
        │  容器里最核心的基础设施——桥本身怎么设计？
        ▼
03 JSBridge 设计与演进（协议 / 回调表 / Promise 化 / 批量 / 白名单）
        │  桥的思路换到桌面：两个进程怎么安全地分工与通信？
        ▼
04 Electron 与桌面端（主/渲染进程分工、IPC 与 contextBridge、更新状态机）
```

与基础板块 `浏览器渲染原理` 的边界：基础讲「页面在浏览器里怎么渲染」，本模块讲「同一套前端代码怎么跑到非浏览器宿主里，以及宿主差异带来的工程题」。

## 分篇知识点

### 01-跨端框架原理

- **三条路线**：WebView 容器（Cordova/小程序）/ 原生渲染（RN/Weex）/ 自绘引擎（Flutter）——本质区别是「UI 由谁画」
- **老架构 Bridge**：异步消息 + JSON 序列化，两次编解码 + Promise 包装 + 队列排队
- **序列化有损实测**：Date 退化为字符串、函数被静默丢弃
- **JSI 实测**：2 万次调用 bridge 72.6ms vs jsi 1.3ms（约 58×），同步直通零序列化
- **小程序双线程**：逻辑层与渲染层分离，安全管控换来通信成本；setData 合并成一帧、只传变化
- **Flutter 三棵树**：Widget（配置）→ Element（复用/diff）→ RenderObject（布局绘制）

### 02-Hybrid 与 WebView 深度优化

- **白屏时间线三段成本**：容器创建（200~500ms）/ 网络往返 / 首屏渲染，三段独立可叠加
- **容器预热实测**：空闲期预创建付 8 单位，点击取用 0 单位，池空冷启动兜底
- **预热工程要点**：首帧后触发、池 2~3、release 复用而非销毁
- **离线包实测**：命中 0 网络、未命中在线兜底、签名不符拒用
- **离线包三件配套**：shouldInterceptRequest/WKURLSchemeHandler、差量更新、静默下发
- **预渲染**：壳与首屏提前到点击前，只做高概率入口 + 超时回收；白屏分段监控是一切优化的前提

### 03-JSBridge 设计与演进

- **三代机制**：URL Scheme 拦截 → 原生注入 API → 注入 + 协议化；同步语法与异步执行的矛盾贯穿始终
- **协议**：module/method 命名空间 + callbackId + encodeURIComponent，编解码严格对称
- **回调表**：callbackId 关联异步回复，一次性用后即清，重复触发报错
- **Promise 化 + 超时兜底实测**：超时 reject 且回调表清空，防桥上泄漏
- **批量合并实测**：同 tick 三次调用一条消息，空队列不发
- **安全**：origin 白名单拒绝非授权调用，Native 侧重做参数校验，敏感 API 原生确认

### 04-Electron 与桌面端

- **进程模型**：单主进程（Node，系统能力收拢）+ 多渲染进程（Chromium，不可信内容隔离）
- **invoke/handle 实测**：Promise 往返；未注册 channel 明确 reject，不静默
- **contextBridge 实测**：白名单外的能力在渲染层不存在；基线 = contextIsolation + 禁 nodeIntegration
- **asar 是归档不是加密**；体积来源是每平台捆绑的 Chromium + Node（80~100MB）
- **更新状态机实测**：版本比对 → 下载 → hash 校验失败回滚不落盘 → 重启切换
- **桌面特有账**：多窗口内存、单实例锁、离线可用、双端崩溃上报

## 最小实现

- **`cross-lab`**：零依赖探针实验台，`node run.cjs` 依次执行五探针（Bridge vs JSI 开销与序列化有损 · 双线程 setData · 预热池/离线包 · 桥协议/回调表/批量/白名单 · IPC/contextBridge/更新状态机），`node:assert` 自检全绿
