## 1. 跨端渲染架构全景

四条路线的本质区别只有一个问题：**JS（或 Dart）写下的 UI 描述，最终由谁渲染？** WebView 容器（复用 Web 生态，受 WebView 上限）、原生渲染 RN（映射原生控件，付通信成本）、自绘引擎 Flutter（像素级一致，包体大动态化弱）、桌面双进程 Electron（等同 Web，捆绑 Chromium）。

所有路线的共同难点：**逻辑层与渲染层不在同一个运行时里，中间必须有一座桥**。桥的设计（序列化 vs 直通、白名单）决定性能与安全上限——这是 RN 的 JSI、Hybrid 的 JSBridge、Electron 的 IPC+contextBridge 三条主线的交汇点。

统一业务场景：三个实战工程承载同一个订单工作台（列表 + 详情 + 状态推进），与渲染架构、微前端板块同构。实跑分级：rn-app Metro 全量编译 ✅（设备层需真机）、electron-app 烟雾测试 ✅、flutter-app 完整代码交付（未实跑，环境配置见工程 README）、cross-lab 七探针 ✅。

## 2. React Native

- **心智迁移**：RN 是 React 的宿主替换——组件模型/Hooks/状态管理原样保留，替换的只有渲染层（View/Text/FlatList）与样式层（无级联的 StyleSheet）。
- **Bridge→JSI**：老 Bridge 是异步消息 + JSON 序列化（有损：函数丢弃、Date 退化；实测 2 万次调用 235.4ms）；JSI 让 JS 直接持有 Native 对象引用，同步直通零序列化（实测 2.2ms，**约 105 倍**）。TurboModules（按需加载）与 Fabric（同步渲染）共用 JSI 底座；Hermes 提供字节码预编译。
- **实战**：FlatList 虚拟化是列表性能底线；状态更新与 web 完全同构；样式数组写法表示合并。
- **最小实现**：40 行原生映射器——diff 描述树产出最小指令集，实测首帧 6 条指令（整树创建）、第二帧 1 条（单点更新）、类型变化触发子树重建。**JS 重渲染 ≠ 重建原生控件**。

## 3. Flutter

- **心智迁移**：自绘引擎路线，换语言（Dart）+ everything is a widget；声明式模型与 React 同构，switch 穷举让状态机由编译器约束。
- **三棵树**：Widget（不可变配置，每帧重建廉价）→ Element（实例，diff 发生在 canUpdate：type+key 相同即复用）→ RenderObject（布局绘制，跨帧复用）。探针实测三帧渲染 Element 复用、RenderObject 仅类型变化时重建。
- **编译模式**：开发期 JIT（热重载）/ 发布期 AOT（机器码）——AOT 没有运行时 JS 引擎，这是「动态化弱」的技术根源。
- **实跑分级**：工程完整代码交付未实跑；环境配置四步（SDK / Android Studio / flutter doctor / run -d chrome 最低成本验证）。

## 4. Electron

- **进程模型**：主进程（Node 完整环境，能力最大，代码可信）+ 渲染进程（Chromium，默认无 Node，必须假设被攻破）。安全基线三件套：`contextIsolation: true` + `nodeIntegration: false` + contextBridge 白名单。
- **IPC**：invoke/handle Promise 往返（未注册 channel 明确 reject，防「静默无响应」排查地狱）；preload 是唯一合法的桥。
- **实战**：electron-app 烟雾测试全过（真实窗口 + 渲染层加载 + 主进程数据层）。CI 真坑：`ELECTRON_RUN_AS_NODE=1` 让 electron.exe 退化成纯 Node（require('electron') 返回字符串），必须 `env -u` 移除。
- **最小实现**：更新状态机 check → download → verify → swap，hash 不符回滚不落盘；配套增量更新与双版本目录。
- **体积账**：每平台捆绑一份 Chromium+Node（80~100MB 起）；asar 是加载优化不是安全边界；主/渲染进程分开打包。

## 5. Hybrid 与 JSBridge

- **白屏三段成本**：容器创建（预热/复用池，实测预热 8 单位·取用 0 单位）/ 网络往返（离线包，实测命中 0 网络·篡改回退）/ 首屏渲染（预渲染，只做高概率入口）——三段独立可叠加，分段监控是一切优化的前提。
- **桥三代**：URL Scheme（长度限制/丢并发）→ 注入 API（反射漏洞）→ 协议化（今天主流）。核心问题永恒：**JS 调用是同步语法，Native 执行是异步过程**。
- **桥协议四件套**：module/method 命名空间 + callbackId 关联（一次性用后即清，重复触发报错）+ 超时兜底（回调表只进不出 = 桥上泄漏）+ origin 白名单（`evil.example` 实测被拒）。
- **小程序双线程参照**：逻辑层与渲染层物理分离，动机是安全管控，代价是 setData 两条铁律（同 tick 合并一帧、路径写法只传变化）——「少传数据、只传变化」军规的由来。
