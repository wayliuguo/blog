> 本章配套「模块面试题」：高级岗最终考核的是"设计取舍"——组件怎么拆、状态怎么管、架构怎么演进。按**五步答题法**口述，结合「面试口径」落到简历项目（组件边界、技术债治理、分层架构）。
> 对应原附录面试体系：设计模式区（Q91-95）+ 场景设计题 A（虚拟滚动）。

## 0. 五步答题法（所有题统一节奏）

| 步骤 | 动作 | 示例（组件边界） |
| --- | --- | --- |
| ① 结论 | 一句话先给答案 | "按变化频率 + 可复用数据闭环 + 可独立测试来判断是否抽组件" |
| ② 原理 | 讲机制 | 边界由"独立变化"决定，不是由"代码多少"决定 |

## 2. 重点题精答（五步法）

### Q1：观察者模式与发布-订阅模式？

- **结论**：观察者模式是"对象直接通知依赖"；发布-订阅多一层事件中心，发布者与订阅者完全解耦。
- **原理**：观察者是目标持有订阅者列表；pub-sub 通过事件总线/EventEmitter 转发。
- **场景**：Vue 响应式（观察者：effect 直接依赖数据）；跨组件/跨模块通信（事件总线）。
- **边界**：事件总线容易失控（事件名无约束、难追踪），大项目慎用。
- **追问**：Vue 响应式属于哪种？→ 观察者模式（依赖收集直连）。

### Q2：组件边界怎么判断？

- **结论**：三点判据——变化频率是否独立、是否有可复用的数据闭环、是否能独立测试。
- **原理**：抽组件是为了隔离变化；频率低的变化不值得抽（过度抽象比重复更贵）。
- **场景**：简历项目优惠券模块：券规则变、主流程不变 → 抽组件；组件内聚自己的状态，向父级只暴露**结果**（选中的券 + 影响金额）。
- **边界**：边界不是越细越好，要看"改一个需求动几个文件"。
- **追问**：组件与主流程的试算联动怎么做？→ 券只产出抵扣结果，试算仍由主流程纯函数完成。

### Q3：单向数据流为什么重要？

- **结论**：数据单向流动（状态 → 视图 → 事件 → 状态），可预测、可调试、可单测。
- **原理**：状态唯一来源 + 视图只消费派生 + 修改必须走明确路径。
- **场景**：简历项目金融要素流转：要素 → 纯函数试算 → 派生结果 → UI 只渲染。四条收益：可枚举、可单测、可复用、可回归。
- **边界**：简单页面套全局状态管理是过度设计；状态本地化优先。
- **追问**：组件状态被父级偷偷改怎么办？→ 组件不暴露内部状态，只暴露结果事件。

### Q4：前端分层架构？

- **结论**：`api/`（接口与契约）→ `hooks/`（组合逻辑）→ `utils/`（纯函数）→ `views/`（视图），职责单向依赖。
- **原理**：分层让"改一处"（接口变了只动 api 层）与"可测"（纯函数不挂组件）成为可能。
- **场景**：简历项目接口治理：页面只消费 api，不直接碰请求；api 工具层收口缓存/竞态/错误分级。
- **边界**：分层要防"层间穿越"（视图直接写业务逻辑）；小项目不必全套分层。
- **追问**：hooks 与 utils 的区别？→ hooks 持有响应式状态与生命周期，utils 是纯函数。

### Q5：技术债怎么判定可下线？（简历核心）

- **结论**：下线判据不是"看起来没人用"，而是"消费方不存在"。
- **原理**：四种形态——失效业务分支（接口/配置不存在）、失效埋点（面板不再消费）、历史兼容判断（端版本全覆盖）、废弃配置（无读取方）。
- **场景**：简历项目冗余下线：主组件职责从"视图+数据+请求+校验+埋点"混写收敛为"编排+渲染"两类。
- **边界**：三步判定：找消费方 → 看端版本/接口是否还在 → 灰度或加兜底后再删。
- **追问**：怎么确定一个分支可以删？→ 分支条件对应的接口/配置是否还存在，消费方是否还在用。

### Q6：虚拟滚动实现原理？

- **结论**：只渲染可视区 + 缓冲区的条目，滚动时用 translateY 平移内容容器。
- **原理**：视口高度 / 行高估算可视条数；内容容器高度撑起总高度；列表项绝对定位或整体平移。
- **场景**：千条级列表、长表格、聊天记录。
- **边界**：行高不固定需测量或估算（有偏差）；key 必须稳定（复用项状态）。
- **追问**：固定行高 vs 动态行高？→ 固定行高简单，动态需 ResizeObserver + 缓存每项高度。

## 3. 追问链

1. "状态放全局还是组件？" → 多组件共享 + 跨页面 + 需持久化才全局；否则本地状态 + props 提升。
2. "策略模式在前端的体现？" → 表单校验器集合、支付渠道选择、平台解析配置（新增平台 = 加一份配置）。
3. "装饰器模式呢？" → 高阶组件（HOC）/ mixin / 拦截器（请求包装、权限校验）。
4. "架构演进怎么不推倒重来？" → 边界先行（分层 + 契约）+ 增量迁移 + 灰度验证。

## 4. 场景设计题

**场景：实现一个支持十万条数据、可滚动可搜索的列表（虚拟滚动），怎么设计？**
- 答题骨架：固定行高方案（估算 + 可视区渲染 + 总高度撑位 + translateY 平移）→ 稳定 key → 搜索在数据层过滤（纯函数）→ 防抖输入 → 可视区外不渲染 DOM → 行内交互用事件委托 → 性能度量（渲染时长/内存）。
- 加分点：说明"可视区 + 缓冲"的意义（提前渲染防白屏）与动态行高的测量成本，体现取舍。

## 5. 面试口径（简历项目如何表达）

- **项目证据**：优惠券模块组件化（边界三判据 + 只暴露结果）；主组件职责收敛（编排 + 渲染）；接口分层（业务域 api 模块 + api 工具层收口横切关注点）；技术债四种形态与下线三步判定；纯函数 + 单向数据流的级联试算重构。
- **表达句式**："架构上我做的是收敛——接口收敛到 api 层（页面不关心 URL/参数/返回解析）、逻辑收敛到纯函数（可枚举可单测）、组件收敛到'只暴露结果'（状态不外泄）。判断要不要抽组件看三点：变化频率、数据闭环、可测性。"
- **加分表达**：讲技术债用"消费方不存在"判据，讲组件用"变化频率"判据——体现"有判据的设计"而非"感觉"。
