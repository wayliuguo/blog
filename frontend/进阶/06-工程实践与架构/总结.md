# 模块总结 · 工程实践与架构

## 知识主线

两篇不是并列的知识点，而是一条有依赖关系的链，每一篇都在回答上一篇留下的问题：

```
01 设计模式在前端（模式语言：单例 / 观察者·发布订阅 / 工厂 / 策略 / 代理 / 装饰器 / 适配器 / 组合 / 命令） ★主轴
        │  先掌握"解耦与复用"的通用词汇，读源码不迷路、写代码抗变化
        ▼
02 组件设计（把模式落到界面单元：原则 / 划分 / props·API / 复用手段 / 跨框架 / 抽象层级）
        │  它在回答上一篇的什么问题：有了模式思路，"界面单元"具体怎么拆、怎么对外设计、怎么复用
```

本模块的主轴是**解耦**：01 给出解耦与复用的模式词汇——发布订阅、策略、适配器、代理、装饰器本质上都在"把变化点隔开"；02 把"在正确层次上做出正确的解耦"落到组件设计的每一个环节——单一职责、容器与展示分离、受控与非受控、组合优于继承、Hooks 复用、抽象层级。两篇一篇讲思想、一篇讲落地，主轴始终是解耦。

## 分篇知识点

### 01-设计模式在前端

- **九种高频模式一句话**：单例（保证全局唯一实例，store/事件总线/Toast）、观察者/发布订阅（一方变、多方自动收到通知，Vue `reactive`、事件总线 `emit/on`）、工厂（参数化创建对象，按类型建组件/按钮/弹窗）、策略（可替换算法集合消灭 if/else，表单校验）、代理（不改变原对象、访问前后插逻辑，防抖节流、`Proxy` 响应式、拦截器）
- **装饰器 / 适配器 / 组合 / 命令**：装饰器不改原对象动态叠加能力（React HOC、AOP 埋点/鉴权）；适配器把不兼容接口翻译成期望接口（统一后端/第三方数据结构）；组合让"叶子与整体"用一致接口（组件递归渲染目录树）；命令把操作封成对象支持延迟执行与撤销重做（编辑器历史）
- **选型对照表**：全局只该有一个→单例；一方变多方受影响→观察者/发布订阅；想统一参数化创建→工厂；一堆可替换算法想干掉 if/else→策略；想在访问前后插逻辑→代理；不改原对象加能力→装饰器；接口不匹配→适配器；树形结构→组合；想撤销重做/回放→命令
- **实践建议**：别为模式而模式——先有真实的"变化点"再上模式，否则是过度设计；优先组合而非继承（模式大多建立在"组合 + 依赖注入"之上）；读 Vue / Redux / axios 源码时主动对号入座是掌握模式最快的方式
- **最小实现**：`pubsub.html` 手写事件中心、`store.html` 手写单例 store + `subscribe` 订阅更新；解耦的本质是"双方不直接引用对方，只通过一个中间调度者（事件中心 / store）建立发布-订阅关系"

### 02-组件设计

- **设计原则**：单一职责（解释组件时用到"并且/还有"即职责过重，拆分目标不是越细越好而是"变更原因唯一"）；SOLID 前端化——开闭原则最具指导性（用 props/slots 扩展而非改源码）；可维护性与可复用性需平衡，用"三次法则"（第三次出现才抽象）防过度抽象
- **划分策略**：原子设计五层（atoms → molecules → organisms → templates → pages）提供团队统一语言；容器 vs 展示组件分离数据与渲染（展示组件可无后端接入开发测试）；受控 vs 非受控按"数据由谁拥有"取舍，成熟组件库同时支持两者（未传 `value` 自管、传了走受控）
- **props 与事件通信**：收窄职责、合理默认值、单向数据流、TS 类型即文档；子传父 React 用回调 props、Vue 用 emits，深层跨层通信交给 Context / provide-inject / 状态库而非层层透传；组合优于继承是铁律（children / 插槽 / 自定义渲染）
- **API 设计**：语义化命名（大驼峰 + 社区通用词如 `value`/`onChange`/`disabled`）；可选 props 给安全默认值但别用假默认值掩盖缺陷（该必填就让 TS 报错）；向前兼容——新增属性可选默认关闭、弃用先 deprecated 标记、semver 约束 + CHANGELOG 记录迁移路径
- **复用手段演进**：HOC（props 来源混乱、包装地狱、难复用逻辑）→ Render Props（数据来源清晰但嵌套回调地狱）→ Hooks / Composable（逻辑与 UI 彻底解耦、可自由组合可测试，当今首选）
- **跨框架与抽象层级**：无框架底层 + 适配层、Web Components、headless 模式、统一运行时四种跨框架路线；单一框架优先框架原生组件，"真正能跨端的是业务领域层逻辑而非 UI 层"；复合组件（Context / provide-inject 共享上下文）、配置化渲染引擎（schema 驱动，低代码场景）、headless 库（Radix / Headless UI / TanStack，行为与样式分离）
