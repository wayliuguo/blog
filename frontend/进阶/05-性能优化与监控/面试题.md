## 2. 重点题精答（五步法）

### Q1：性能指标的含义与取舍？

- **结论**：FP（首帧）→ FCP（首内容）→ LCP（最大内容，体验关键）→ CLS（布局偏移）→ INP（交互延迟）。
- **原理**：LCP 衡量"页面核心内容可感知"的时间；采集用 PerformanceObserver 而非打点。
- **场景**：指标要能落监控；LCP 优化 = 资源优先级 + 关键路径。
- **边界**：指标有采集成本（观测器不阻塞，但上报链路要可控）；不同端（H5/小程序）口径不同。
- **追问**：为什么 LCP 比 FCP 更重要？→ FCP 可能只是首块文字，LCP 才代表"主要内容出现"。

### Q2：首屏优化的三层手段？

- **结论**：关键路径（并行化）+ 阻塞（非关键兜底）+ 网络（预取 + 降级）。
- **原理**：并行化减少关键路径长度；兜底与增量更新减少阻塞时间；预取省一次网络往返。
- **场景**：简历项目接口串行改并行（1 个前置依赖 + 4 个并行）；运营位失败按空对象兜底不阻塞首屏；App 预取 + 500ms 超时降级。
- **边界**：比"请求本身更快"更可控的是减少等待与阻塞。
- **追问**：首屏接口哪些必须串行？→ 下游接口依赖上游返回值的才串行，其余并发。

### Q3：异常监控五维？

- **结论**：JS 错误率 · 白屏 · 资源加载失败 · 接口成功率与耗时 · 初始化流程健康度。
- **原理**：白屏直接工具是 LOAD.ERROR（页面级埋点）；资源错误必须捕获阶段监听（error 事件不冒泡）；监控脚本要早于 polyfills 执行。
- **场景**：简历项目覆盖五维 + 错误分级（network-error / logic-error）——分级决定谁来看。
- **边界**：只监控不定位 = 白搭；要能串到"哪个页面/接口/版本"。
- **追问**：错误分级有什么价值？→ network-error 找运维/网关，logic-error 找前端，避免互相甩锅。

### Q4：双视角指标设计？（简历核心设计）

- **结论**：产品视角看漏斗（进入→试算→提交→授信逐段转化），研发视角看接口（成功率/耗时/健康度），共用同一套埋点口径。
- **原理**：同一份埋点事件派生两套视图——字段命名与口径一致，否则两套账对不上。
- **场景**：`report_serial_num` 把前后端埋点串成一条链路；页面级（LOAD.*）/ 曝光级（SHOW.*）/ 交互级（CLICK.*）/ 结果级（*_SUC/_FAIL）。
- **边界**：口径必须双视角同源，这是设计的关键不是实现细节。
- **追问**：埋点遗漏怎么防？→ 埋点清单随方案生成（AI Skill 沉淀），新增分支必须补埋点。

### Q5：告警阈值怎么设计？

- **结论**：基线（近 N 天分位数）+ 波动容忍 + 量与率同时看。
- **原理**：只看率被小样本放大；只看量漏掉转化率下滑。
- **场景**：告警图把"哪个接口/页面/版本"对齐到一张图，直接指向问题域。
- **边界**：阈值不是拍脑袋，要随基线滚动；告警太多会麻木。
- **追问**：告警与发版怎么联动？→ 版本维度对齐，发版后指标异常优先查本次改动。

### Q6：白屏怎么定位？（最有故事性的 case）

- **结论**：先让错误可见（早期注入监控）→ 用数据定位（资源加载错误）→ 最小改动修复并注释留痕。
- **原理**：iOS 容器多页跳转后白屏，靠捕获阶段资源错误上报定位到 modulePreload 预加载失败且无降级。
- **场景**：修复 = 关闭 `modulePreload` + 配置处写明原因注释（防止后人"优化"改回去）。
- **边界**：预取降级与真实接口失败要在监控上分开，否则误判问题域。
- **追问**：为什么资源错误要用捕获阶段？→ error 事件在资源加载失败时不冒泡，只有捕获阶段能监听到。

## 3. 追问链

1. "性能优化怎么证明有效？" → 优化前打点 → 上线后对比同口径指标（A/B 或前后对比），不报未度量数字。
2. "监控上报会不会影响性能？" → 上报放微任务（queueMicrotask），当前宏任务后、渲染前执行。
3. "大列表怎么不卡？" → 虚拟滚动（只渲染可视区）+ 分页 + 稳定 key + 事件委托。
4. "包体积怎么治理？" → 按需引入 + manualChunks 分层 + 分析产物（rollup-plugin-visualizer）+ 图片压缩。

## 4. 场景设计题

**场景：线上反馈某页面白屏率上升，但本地无法复现，怎么排查？**
- 答题骨架：先确认监控是否覆盖（LOAD.ERROR / 资源加载错误 / JS 错误率）→ 按版本/机型/接口维度切片 → 区分"预取超时降级"与"真实接口失败" → 查初始化流程是否中断（polyfill 前错误需最早注入的监控）→ 定位到具体资源/接口 → 修复 + 回归 + 埋点验证。
- 加分点：把"先让错误可见 → 数据定位 → 最小修复 + 注释留痕"方法论完整讲出来，呼应 iOS modulePreload case。

## 5. 面试口径（简历项目如何表达）

- **项目证据**：性能治理（首屏接口串行改并行、非关键兜底、App 预取 + 超时降级）；监控（异常五维：JS 错误 / 白屏 / 资源 / 接口 / 初始化健康度）；双视角指标（产品漏斗 + 研发接口健康度，同一套埋点口径）；四层级埋点（LOAD/SHOW/CLICK/结果）；天表/实时表 + 告警阈值建议。
- **表达句式**："监控我做了两件关键设计：一是双视角——同一套埋点，产品看漏斗、研发看接口，口径不一致就会对不上账；二是错误分级——network-error 找运维、logic-error 找前端，决定谁来看。性能上首屏优化是三层：关键路径并行、非关键兜底、预取降级。"
- **勿说**：不报未取证的量化数字（首屏 ms / 包体积 MB 未做严格 A/B 度量，宁缺毋滥）。
