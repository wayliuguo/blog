## 2. 重点题精答（五步法）

### Q1：ESLint 9 flat config 相比 `.eslintrc` 的变化？

- **结论**：配置从"级联继承"变为"显式数组组合"，配置即数据。
- **原理**：`extends` 的隐式解析与 `overrides` 嵌套被取消；插件要显式 `plugins: { vue }` 声明；`ignores` 替代 `.eslintignore`。
- **场景**：简历项目 `export default [js.recommended, ...tseslint.recommended, vue.flat/recommended, { rules, ignores }]`。
- **边界**：升级成本是旧配置改造；可被程序化组合是最大收益。
- **追问**：flat config 怎么忽略文件？→ `ignores: ['dist/**']` 数组项。

### Q2：四层测试体系？

- **结论**：单元（纯函数）→ 组件（渲染与交互）→ 集成（多组件+数据流）→ E2E（真实浏览器主流程）。
- **原理**：每层工具与判据不同：Vitest + 分支覆盖；@vue/test-utils + props/事件契约；Vitest + mock 请求；Cypress/Playwright + 用户旅程。
- **场景**：简历项目按页面盘点测试点并分级（P0 主流程 / P1 边界 / P2 异常），91 个测试点，不是一上来追求覆盖率。
- **边界**：测试范围随页面配置自动生成——新增页面自动纳入，否则"忘了加测试"必然发生。
- **追问**：测试点怎么排落地路径？→ 先 P0 主流程，再 P1 边界，最后 P2 异常。

### Q3：单元测试与组件测试的区别？

- **结论**：单元测纯函数（输入输出断言），组件测渲染与交互契约（props/事件）。
- **原理**：单元测试不挂载组件、不 mock 请求；组件测试用挂载器模拟用户交互。
- **场景**：金额计算、校验、格式化走单元（纯函数可单测）；按钮点击触发事件、props 变化重渲染走组件测试。
- **边界**：组件测试不能替代 E2E——真实浏览器环境的行为差异测不到。
- **追问**：为什么要让业务逻辑是纯函数？→ 不挂载组件、不 mock 请求就能测，是"可测性设计"。

### Q4：真机调试链怎么搭？

- **结论**：真实域名 + whistle 域名代理 + 扫码入口 + vConsole。
- **原理**：导航页链接不能写 `127.0.0.1`（手机上指向手机自己），必须真实域名；whistle 把线上域名代理到本地 dev server；Vite `allowedHosts` 放行（默认拒绝未知 Host 防 DNS Rebinding）。
- **场景**：简历项目开发导航插件（`configureServer` + `configurePreviewServer`）——开发态与预览态都有导航页。
- **边界**：只配了 dev 没配 preview，构建产物真机预览时找不到页面。
- **追问**：为什么 Vite 默认拒绝未知 Host？→ 防 DNS Rebinding 攻击。

### Q5：CI/CD 流水线里前端做什么？

- **结论**：代码检查 → 单元/组件测试 → 构建 → E2E → 产物上传 → 按页/按包发布 → 灰度放量 → 监控与回滚。
- **原理**：门禁前置（pre-commit lint-staged / pre-push 测试）、构建产物可追溯（版本/哈希）、发布可灰度可回滚。
- **场景**：`start-server-and-test` 解决 E2E 启动顺序导致的 flaky——起服务后等端口就绪再跑测试；preview 构建后测试保证产物一致。
- **边界**：E2E 慢且脆，放发布前关键路径即可；别让测试成为发布瓶颈。
- **追问**：测试在 CI 里失败会怎样？→ 阻断合并与发布，质量门禁兜底。

### Q6：发布与灰度？

- **结论**：发布粒度决定回归成本——MPA 按页发布，灰度放量 + 监控指标 + 自动/手动回滚。
- **原理**：按页构建产物独立，单页改动只发布该页；灰度按比例放量观察错误率/成功率；回滚是"回到上一版本产物"。
- **场景**：简历项目"按页构建、按页发布、按页回归"；产物归集插件对接发布系统。
- **边界**：灰度必须配监控口径（同一套埋点基准），否则放量风险不可观测。
- **追问**：灰度观察哪些指标？→ 接口成功率、JS 错误率、白屏率、转化漏斗（产品视角）。

## 3. 追问链

1. "CR 最看重什么？" → 接口契约（入参/返回/兜底）→ 状态与副作用 → 兼容与降级 → 埋点覆盖新增分支。
2. "规范怎么不腐化？" → 规则资产化 + 门禁（lint-staged/pre-commit）+ 模板兜底，而不是靠人记。
3. "测试资产怎么沉淀？" → 用例文档随页面目录沉淀，回归时照文档验；AI 批量生成用例。
4. "pre-commit 太慢怎么办？" → lint-staged 只处理暂存文件 + 只做增量检查。

## 4. 场景设计题

**场景：一个新页面要上线，质量保障怎么做全？**
- 答题骨架：规范（代码生成即合规：脚手架/规则文件）→ 单测（纯函数）+ 组件测试（交互契约）+ E2E（P0 主流程）→ CR（契约/兜底/埋点）→ 构建产物（单版本 ESM + 按需 polyfill）→ 按页发布 + 灰度 → 监控（错误/白屏/接口）→ 回滚预案。
- 加分点：说"新增页面自动纳入测试范围（配置派生）"与"灰度看同一套埋点口径"，体现体系而非单点。

## 5. 面试口径（简历项目如何表达）

- **项目证据**：四层测试体系设计与分级落地（91 个测试点，P0/P1/P2 分级，测试范围随 `pages.config.ts` 自动派生）；ESLint 9 flat config（显式数组组合）；类型检查与构建并行（vue-tsc --noEmit + vite build）；脚手架命令一键生成页面目录骨架与测试文件。
- **表达句式**："测试体系是分层设计 + 分级落地：单元测纯函数、组件测契约、集成测链路、E2E 测旅程；因为页面注册唯一来源是页面配置，新增页面自动纳入测试范围，不用人去补配置。"
- **勿说**：不要说"覆盖率 80%"或"全部接入 CI 门禁"——简历口径是"设计与分级落地"，没取证的数字不报。
