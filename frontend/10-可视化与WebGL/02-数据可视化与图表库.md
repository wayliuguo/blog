# 数据可视化与图表库

> 级别：中级

按本书四层推进：

- **入门使用**：`echarts.init(dom)` + 一份 `option` 就能出图，掌握常见图表类型与 `setOption` 更新；
- **进阶**：理解 `setOption` 的增量合并语义、销毁与复用、大数据量渲染优化手段；
- **实战**：在 Vue/React 里封装"单实例 + 生命周期对齐 + resize 同步"的图表组件，对齐真实业务；
- **最小实现掌握原理**：到 `code/frontend/10-visualize` 运行 `canvas-chart.html`、`svg-chart.html` 两个 demo，看清图表库渲染内核"数据 → 像素"的最小映射。

如果说 Canvas 与 SVG 是绘图的"手"，那么图表库就是把这张"手"封装成一句话就能出图的"工具"。在业务系统里，报表、看板、监控大盘、数据分析页面几乎离不开 ECharts、Chart.js、AntV 这些成熟方案。掌握图表库，不等于止步于"调 API 出图"——懂得其渲染原理、数据绑定与更新模型、性能调优，才能应对真实项目里的复杂诉求。

这篇文章以 ECharts 为主线，对比 Chart.js 与 AntV 家族的定位与选型，接着深入图表类型选型、数据绑定与更新、大数据量渲染优化，最后给出工程化封装思路。

## 一、主流图表库概览

### 1. 三大生态一张表看懂

| 库 | 出品方 | 渲染方式 | 定位 | 典型场景 |
| --- | --- | --- | --- | --- |
| **ECharts** | Apache / 百度 | 默认 Canvas（可切换 SVG 渲染器） | 全功能、大而全、数据量大 | 大屏、复杂图表、大数据渲染 |
| **Chart.js** | 社区 | Canvas | 轻量、简洁、易上手 | 中小型图表、仪表盘 |
| **G 系（AntV）** | 蚂蚁集团 | Canvas 为主，支持 SVG/WebGL | G2/G2Plot 统计图表、L7 地图、X6 图编辑 | 数据可视化产品级方案 |
| **D3.js** | 社区 | 直接操作 SVG/Canvas/DOM | 底层数据驱动，高度自由 | 定制化、实验性可视化 |

> 定位一句话：**ECharts 省心倒糙、量大也能抗；Chart.js 小而美；AntV 更偏"企业级产品体系"；D3 是"手工打造"的终极自由但成本高**。

### 2. ECharts 快速上手

ECharts 的核心模式是 **`init` 一个容器 → 传一份 `option`（配置项）**，配置即数据描述，声明式地告诉它"要画什么"。

```html
<div id="chart" style="width: 600px; height: 400px;"></div>
```

```js
import * as echarts from "echarts";
const chart = echarts.init(document.getElementById("chart"));

const option = {
  tooltip: {},                    // 悬停提示
  xAxis: { type: "category", data: ["Mon", "Tue", "Wed"] },
  yAxis: { type: "value" },
  series: [
    {
      name: "销量",
      type: "bar",                // 图表类型
      data: [120, 200, 150],
      itemStyle: { color: "#4a90d9" },
    },
  ],
};
chart.setOption(option);
```

要点：
- `echarts.init(dom, theme?, opts?)` 指定容器与可选主题。
- 容器必须有**可测量的宽高**，否则图表不显示。
- `setOption` 是幂等的**增量合并**更新，反复调用会 diff 后重绘。

## 二、常见图表类型与选型

### 1. 按数据关系分类

| 数据关系 | 推荐图表类型 | 一句话说明 |
| --- | --- | --- |
| 分类对比 | 柱状图/条形图 | 看高低多寡、排位 |
| 趋势变化 | 折线图/面积图 | 看随时间/序号的升降 |
| 占比构成 | 饼图/环形图/南丁格尔玫瑰图 | 看各部分占比，**占比项不宜过多** |
| 相关性 | 散点图/气泡图 | 看两（多）维变量关系与分布 |
| 分布 | 直方图/箱线图 | 看数值分布形态 |
| 层级 | 树图/矩形树图 | 看嵌套层级与大小 |
| 地图/空间 | 地图/散点地图/热力图 | 看地域分布 |
| 流程 | 桑基图 | 看流量走向与汇聚 |
| 多变量雷达 | 雷达图 | 横向比较多指标属性 |
| 词频 | 词云 | 看关键词热度 |

### 2. 选型的反直觉结论

- **饼图慎用**：超过 5~6 个扇区人眼就难比较；对比精确值不如柱状图。
- **折线图 vs 柱状图**：时间序列连续性强用折线；分类离散用柱状。
- **堆叠图留坑**：堆叠柱/面积图虽能看总量，但**中间层难以精确对比**，慎用做多系对比。
- **颜色主数据为辅**：同一张图配色尽量克制，标注 & 图例承担解释职责。
- **图表是讲故事的工具**：选型要服务于"想表达什么结论"，而非"能画什么形式"。

## 三、数据绑定与更新

### 1. 更新与合并语义

`setOption` 的第二个特性：默认是**增量合并**（merge），而非整体替换。手动控制用第三参：

```js
// 增量更新：只更新 data 字段，其它配置保持不变
chart.setOption({
  series: [{ data: [230, 320, 400] }],
});

// 整体替换（清除旧配置，完全用新配置渲染）
chart.setOption(option, true);

// 关闭默认的防抖自动动画? 否，第二个 true 是 notMerge
chart.setOption(option, { notMerge: true });
```

### 2. 动态数据（实时刷新）

实时看板常见的"数据不断追加"做法：用 `setOption` 传入新数组即可，ECharts 会衔接原有数据并平滑过渡。

```js
const data = [];
setInterval(() => {
  // 追加或替换数据
  data.push(Math.round(Math.random() * 100));
  chart.setOption({
    series: [{ data }],         // 增量合并
  });
}, 2000);
```

### 3. 销毁与复用

- **`chart.dispose()`**：销毁实例释放内存（单页/路由切换时必须调用，避免内存泄漏）。
- **`chart.clear()`**：清空绘图区域与 setOption 配置，但实例本身可复用。
- **容器 resize 时同步图表**：`chart.resize()`；容器不可见时 init 会失败或无尺寸，需在可见后再 init。

```js
window.addEventListener("resize", () => chart.resize());
// 组件卸载时
beforeDestroy() {
  chart.dispose();
  chart = null;
}
```

## 四、大数据量渲染优化

当点/柱数以万计时，默认渲染会卡顿。以下是高频优化手段。

### 1. sampling 采样

折线图对数据做采样，降低绘制点数同时保留趋势：

```js
series: [
  {
    type: "line",
    data: largeArray,
    sampling: "lttb",   // 降采样算法；常见: lttb / average / max / min / sum
    showSymbol: false,  // 关闭散点标记，降低绘制量
  },
]
```

> `lttb`（Largest-Triangle-Three-Buckets）是业界常用的保趋势降采样算法。

### 2. 大数据专用类型

- **`scatterGL` / `linesGL`**：用 WebGL 渲染散点/折线，可承载十万级节点。
- **`custom` 系列**：完全自控绘制，配合渲染器缓存达到最优性能。
- **分段渲染 / 按需加载**：地图按层级懒加载，表格/树懒展开。

### 3. 关闭不需要的能力

```js
const option = {
  animation: false,            // 大数据量下动画会拖帧
  progressive: 5000,           // 分批绘制阈值，避免一次性渲染卡死
  large: true,                 // 散点图开启大数据模式
  xAxis: { axisLabel: { interval: "auto" } }, // 标签自动跳过
  tooltip: { trigger: "axis" },// 轴触发比分点触发更省
};
```

### 4. 用 SVG 渲染器兜底部分场景

ECharts 默认 Canvas；当节点多且浏览器 Canvas 频繁重绘时，可切换 SVG：

```js
import * as echarts from "echarts";
import "echarts/svg-renderer";
const chart = echarts.init(dom, null, { renderer: "svg" });
```

## 五、Chart.js 与 AntV 概览

### 1. Chart.js 特点

轻量、配置直观、开箱即用，适合中小型仪表盘：

```js
import { Chart } from "chart.js";
const ctx = document.getElementById("myChart");

new Chart(ctx, {
  type: "bar",
  data: {
    labels: ["一", "二", "三"],
    datasets: [{ label: "销量", data: [12, 19, 3], backgroundColor: "#4a90d9" }],
  },
});
```

特点与限制：**无内置地图**、复杂交互弱，但**体积小、上手快**，适合快速撑起一个标准图表。

### 2. AntV 家族

AntV 不是一个库而是一个**可视化体系**：

| 子库 | 定位 |
| --- | --- |
| **G2 / G2Plot** | 统计图表绘制，G2Plot 是 G2 的高阶封装，声明式更贴近业务 |
| **L7** | 地理空间数据可视化（地图、轨迹、热力） |
| **X6** | 图编辑引擎（流程图、DAG、脑图） |
| **S2** | 表格可视化（透视表、明细表） |
| **G** | 底层渲染引擎（Canvas/WebGL/SVG 统一） |

```js
import { Column } from "@antv/g2plot";
const plot = new Column("container", {
  data: [
    { type: "苹果", value: 120 },
    { type: "香蕉", value: 90 },
  ],
  xField: "type",
  yField: "value",
});
plot.render();
```

## 六、Vue/React 中的封装思路

### 1. 通用封装要点

- **单实例原则**：组件只 init 一次，数据变化走 `setOption` 增量更新，避免重复 init。
- **生命周期对齐**：`update` 时 `setOption`，`unmount` 时 `dispose`。
- **响应式 resize**：监听容器尺寸变化并 `chart.resize()`（常配 ResizeObserver）。
- **导出复用**：把"公共主题 + 工具函数 + 通用组件"沉淀成内部 Vue 组件或 npm 包。

### 2. Vue 组件封装示例（要点）

```vue
<template>
  <div ref="chartRef" class="chart-box"></div>
</template>
```

```js
// setup 脚本里封装
let chart = null;
function update(data) {
  if (!chart) chart = echarts.init(this.$refs.chartRef);
  chart.setOption(buildOption(data));
}
```

> 封装追求"业务只传数据、组件管生命周期与重绘"。

## 小结

- **主流库选型**：量大重交互选 ECharts，轻量快速选 Chart.js，企业级体系选 AntV，极致自由选 D3。
- **选图表先看数据关系**：对比→柱状、趋势→折线、占比→饼（慎用）、相关→散点。
- **`setOption` 是增量合并更新**，动态刷新靠传新数据；销毁用 `dispose`。
- **大数据优化三板斧**：采样 `sampling`、大数据类型/`progressive` 分批、关闭动画。
- **工程化**：封装单实例组件，对齐生命周期，做好 resize 与内存释放。

## 最小实现：看懂图表库背后的"数据 → 像素"

图表库（ECharts）底层就是把一份 `option` 折算成 Canvas 或 SVG 的绘制指令。到 `code/frontend/10-visualize` 打开 `canvas-chart.html` 与 `svg-chart.html` 两个 demo，用最原始方式复刻"柱状图 / 折线图"的渲染核心：

- `canvas-chart.html` —— 数据数组 → 像素坐标 → Canvas 逐笔绘制，即 ECharts 默认 Canvas 渲染器的最小形态；
- `svg-chart.html` —— 数据数组 → 逐个生成 SVG 元素（`<rect>`、`<polyline>`），即 ECharts 切到 SVG 渲染器时的最小形态。

原理一句话：图表库的价值在于把"业务数据 + 配置"映射成坐标与绘制指令，而这段映射逻辑本身与引擎（Canvas/SVG）无关——这正是它能在不同渲染器之间切换的原因。
