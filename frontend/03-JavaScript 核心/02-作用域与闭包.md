## 一、什么是作用域

**作用域（Scope）** 定义了"变量在何处、如何被访问"的规则。简单说，它决定了你在某段代码里能"看见"哪些变量。作用域最直接的作用是：限制变量的访问范围，避免命名冲突，隔离内部状态。

JavaScript 使用的是**词法作用域（Lexical Scoping）**——作用域的划分发生在**代码编写阶段**，而不是执行阶段。也就是说，一个函数嵌套在哪里，就决定了它能访问哪些外层变量，与调用位置无关。这一点是理解闭包的关键前提。

```js
const x = 1;

function outer() {
  const y = 2;
  function inner() {
    const z = 3;
    console.log(x, y, z); // 可以访问到外层所有变量
  }
  inner();
}
outer();
```

## 二、作用域的类型

### 1. 全局作用域（Global Scope）

在函数外、模块顶层的变量属于全局作用域。全局变量在任何位置都能访问，但过多全局变量会引起命名冲突，应尽量避免。

```js
// 全局作用域
const globalVar = "我是全局变量";

function foo() {
  console.log(globalVar); // 可访问
}
```

### 2. 函数作用域（Function Scope）

由 `var` 产生的作用域。函数内部声明的变量在函数外部不可访问，但函数内部可以访问外层。

```js
function bar() {
  var inner = 1;
}
console.log(inner); // ReferenceError，函数作用域外访问不到
```

### 3. 块级作用域（Block Scope）

由 `let` / `const` 产生的作用域，以 `{}` 为界。这是 ES6 的重要改进。

```js
if (true) {
  let block = 1;
  const block2 = 2;
}
console.log(block);  // ReferenceError
console.log(block2); // ReferenceError
```

注意：`var` 没有块级作用域，只有函数作用域。

```js
if (true) {
  var leaked = "逃逸了";
}
console.log(leaked); // "逃逸了"，var 不受块限制
```

## 三、词法作用域与作用域链

### 词法作用域

词法作用域意味着作用域的嵌套关系由**源代码书写的位置**决定。看下面这个例子，函数 `inner` 在写代码时位于 `outer` 内部，所以无论你怎么调用 `inner`，它都能访问 `outer` 的变量：

```js
const name = "全局";

function outer() {
  const name = "outer";
  function inner() {
    console.log(name); // 词法上嵌套在 outer 里，访问到 "outer"
  }
  return inner;
}

const fn = outer();
fn(); // "outer"，而不是 "全局"
```

`fn()` 虽然是在全局被调用的，但由于 `inner` 的词法位置在 `outer` 内部，它优先访问的是 `outer` 中的 `name`。

### 作用域链（Scope Chain）

当访问一个变量时，JS 引擎会**沿着"当前作用域 → 外层作用域 → … → 全局作用域"**这条链一层层向上查找，找到第一个匹配就停止；如果全局都没有，则抛出 `ReferenceError`。这条从内到外的链就是作用域链。

```js
const globalVar = "g";

function a() {
  const aVar = "a";
  function b() {
    const bVar = "b";
    function c() {
      // c 的作用域链：c → b → a → 全局
      console.log(bVar, aVar, globalVar); // 都能找到
      // console.log(notExist); // ReferenceError
    }
    c();
  }
  b();
}
a();
```

作用域链的规则一句话总结：**向上一级找，内层找不到就向外层找**。

## 四、执行上下文与调用栈

作用域链决定了"能看到什么"，而**执行上下文（Execution Context）**和**调用栈（Call Stack）**决定了"代码如何被执行"。

### 执行上下文

每当一段代码即将执行，JS 引擎都会创建一个执行上下文。它主要包含三件事：

- **变量环境 / 词法环境**：装着当前作用域里的变量、函数等。
- **this 值**：当前 this 的指向。
- **对外层作用域的引用**：用于构建作用域链。

常见的三种执行上下文：

- **全局执行上下文**：程序启动时创建，只有一个。
- **函数执行上下文**：每次调用函数时创建。
- **Eval 执行上下文**：`eval` 执行时创建（不推荐使用）。

### 调用栈

JS 是单线程的，执行上下文按"**后进先出**"的方式组织成一条调用栈。当前正在执行的函数在栈顶，函数执行完毕就出栈，然后继续执行上一层。

```js
function first() {
  second();
}
function second() {
  third();
}
function third() {
  console.log("top");
}
first();
// 调用栈变化：first → second → third → 逐个出栈
```

如果调用栈被填满（比如无限递归），就会抛出栈溢出错误（`RangeError: Maximum call stack size exceeded`）：

```js
function boom() {
  boom();
}
// boom(); // RangeError
```

## 五、var / let / const 的区别与提升

这三种声明方式在作用域、提升（Hoisting）、是否可以重新赋值上有明显差异。

### 1. var

- **函数作用域**，不具有块级作用域。
- 存在**变量提升**：声明被提升到作用域顶部，但初始化不提升，因此值为 `undefined`。
- 可以重复声明，可以重新赋值。

```js
console.log(v); // undefined（提升，但未初始化）
var v = 1;
```

`var v` 的声明被提升到顶部，相当于：

```js
var v;       // 被提升
console.log(v); // undefined
v = 1;
```

### 2. let / const

- **块级作用域**。
- 存在提升，但处于**暂时性死区（Temporal Dead Zone, TDZ）**：在声明语句之前访问会抛出 `ReferenceError`。
- 不能重复声明。
- `let` 可重新赋值；`const` 声明后不得重新绑定。

```js
console.log(l); // ReferenceError: Cannot access 'l' before initialization
let l = 1;
```

### 3. 消除经典问题：for 循环中的 var

```js
// 使用 var：所有回调都拿到最终值 3
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i));
}
// 输出：3 3 3

// 使用 let：每个迭代有独立的块级作用域，各自保存 i
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i));
}
// 输出：0 1 2
```

原因：`var` 只有一个共享的函数级变量 `i`，回调执行时 `i` 已变成 3；`let` 为每次迭代创建独立的块级绑定，闭包各自捕获了不同的 `i`。

### 4. 对比总结

| 关键字 | 作用域 | 提升 | 暂时性死区 | 可重复声明 | 可重新赋值 |
| ------ | ------ | ---- | ---------- | ---------- | ---------- |
| `var`  | 函数 | 是（undefined）| 无 | 可以 | 可以 |
| `let`  | 块   | 是   | 有 | 不可以 | 可以 |
| `const`| 块   | 是   | 有 | 不可以 | 不可以（绑定） |

实践中：默认用 `const`，需要重新赋值时用 `let`，**基本不用 `var`**。

## 六、IIFE（立即执行函数）

**IIFE（Immediately Invoked Function Expression）** 是"定义完立即执行"的函数表达式。写法常见两种：

```js
(function () {
  console.log("IIFE 1");
})();

(function () {
  console.log("IIFE 2");
}());
```

### IIFE 的两个核心用途

1. **创建独立作用域**，隔离变量，避免污染全局（ES6 之前实现模块化的常用手段）。
2. **配合闭包保存状态**，在循环中捕获每次的值。

```js
// 用 IIFE 修复 var 的循环问题
for (var i = 0; i < 3; i++) {
  (function (n) {
    setTimeout(() => console.log(n)); // 0 1 2
  })(i);
}
```

注意：函数声明不能直接加 `()` 调用，需要外面包一层括号把它变成表达式，或用 `!`、`+` 等一元运算符：

```js
!function () { console.log("立即执行"); }();
+function () { console.log("立即执行"); }();
```

## 七、闭包的定义与原理

### 定义

**闭包（Closure）** 是"**内层函数 + 它绑定的外层作用域的变量环境**"的结合体。当一个函数能够**访问并记住**它定义时所在作用域的变量，即使这个外层函数已经执行完毕，我们就说形成了闭包。

更直白的定义：**能够访问父作用域变量的函数，就是闭包**。

### 原理

为什么外层函数执行完，它的局部变量还没有被销毁？因为"**内层函数引用了它**"，因此外层变量被闭包"持有"，不会被垃圾回收（GC）回收。

```js
function createCounter() {
  let count = 0;                 // count 被闭包持有
  return function () {
    count++;                     // 内层函数记住了 count
    return count;
  };
}

const counter = createCounter();
console.log(counter()); // 1
console.log(counter()); // 2
// createCounter 已经返回，但 count 仍然被内部函数引用而存活
```

从执行上下文角度看：`createCounter` 执行完后其执行上下文本应出栈销毁，但返回的内部函数带上了对它的词法环境的引用，于是 `count` 被保留下来。每次调用 `counter`，都会在其词法环境上修改 `count`。

## 八、闭包的应用

### 1. 私有变量

模拟"私有"状态，外部无法直接访问，只能通过暴露的方法操作。

```js
function createBankAccount(initial) {
  let balance = initial; // 私有
  return {
    deposit(amount) {
      balance += amount;
    },
    withdraw(amount) {
      if (amount > balance) {
        console.log("余额不足");
        return;
      }
      balance -= amount;
    },
    getBalance() {
      return balance;
    },
  };
}

const account = createBankAccount(1000);
account.deposit(500);
console.log(account.getBalance()); // 1500
// console.log(account.balance);   // undefined，外部拿不到私有变量
```

### 2. 柯里化（Currying）

把接收多个参数的函数，转化为"分步接收参数"的一系列函数。闭包让中间状态得以保存。

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn(...args);
    }
    // 保存已收集的参数，继续返回函数收集剩余参数
    return (...more) => curried(...args, ...more);
  };
}

const add = curry((a, b, c) => a + b + c);
console.log(add(1)(2)(3)); // 6
```

一个更基础的柯里化例子：

```js
function multiply(a) {
  return function (b) {
    return function (c) {
      return a * b * c;
    };
  };
}
console.log(multiply(2)(3)(4)); // 24
```

### 3. 计数器 / 记忆缓存

利用闭包持久保存上一次计算的结果，避免重复计算。

```js
function memorize(fn) {
  const cache = {};
  return function (key) {
    if (key in cache) {
      console.log("命中缓存");
      return cache[key];
    }
    const result = fn(key);
    cache[key] = result;
    return result;
  };
}

const square = memorize((n) => n * n);
console.log(square(5)); // 25
console.log(square(5)); // 命中缓存 25
```

## 九、闭包的陷阱与内存问题

### 1. 内存泄漏

闭包会长期持有外层变量，如果这个变量是很大的对象，且闭包被长期引用（例如挂在全局、用于事件监听但从不解除），内存就无法被回收。

```js
function createBigClosure() {
  const bigData = new Array(1000000).fill(0); // 大对象
  return function () {
    console.log(bigData.length);
  };
}

// 长期持有 largeFn，bigData 无法被回收 → 潜在内存泄漏
const largeFn = createBigClosure();
// 不再使用时，应置 null 以便 GC
// largeFn = null;
```

**建议**：不再需要时切断引用（置 `null`），或避免在长生命周期作用域中持有大对象。

### 2. 循环中的闭包陷阱

经典案例已经在 var/let 中演示过：用 `var` 在循环里创建闭包，闭包捕获的是同一个最终变量。修复方式：

- 用 `let` 声明迭代变量（推荐）。
- 用 IIFE 传参捕获。
- 用 `Function.prototype.bind`。

```js
for (var i = 0; i < 3; i++) {
  setTimeout(function (n) {
    console.log(n);
  }.bind(null, i)); // bind 也会立即固化参数
}
```

### 3. 闭包与 this 的丢失

闭包里的普通函数 `this` 指向不再绑定到外部函数的对象。这个陷阱容易踩到，需用箭头函数或显式绑定。

```js
const obj = {
  count: 0,
  start() {
    setTimeout(function () {
      // 这里的 this 是 window/undefined，不是 obj
      // this.count++; // 出错
    }, 100);

    setTimeout(() => {
      this.count++; // 箭头函数捕获外层 this，正常
    }, 100);
  },
};
obj.start();
```

## 十、小结与面试衔接

### 核心概念回顾

- 作用域：变量可访问的范围，分全局 / 函数 / 块 三种。
- 词法作用域：由书写位置决定，与调用位置无关。
- 作用域链：内部到外部逐层查找变量的链条。
- 执行上下文 + 调用栈：代码执行时的组织方式，栈溢出来自调用栈填满。
- `var` / `let` / `const`：作用域、提升、TDZ 的差异。
- 闭包：内层函数记住并访问外层变量的机制，是私有变量、柯里化、记忆化的基础。
- 陷阱：内存泄漏、循环捕获、this 丢失。
