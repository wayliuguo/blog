## 1. 数据类型与变量

### 1.1 值 vs 引用

JavaScript 的数据分两族，存储与赋值语义完全不同：

```
基本类型(7)   undefined / null / boolean / number / string / symbol / bigint
             值存栈、赋值按值拷贝 → 两个变量完全独立
引用类型      栈存地址、堆存对象
             赋值拷贝引用 → 两个变量共享同一对象，改一个影响另一个
```

- **比较语义**：`===` 基本类型比值、引用类型比引用地址（`{} === {}` 为 false，同一引用才 true）。

### 1.2 假值与真值

- **假值（falsy）**：`false` / `0` / `-0` / `0n` / `""` / `null` / `undefined` / `NaN`，条件判断中隐式转 false。
- **真值（truthy）**：其余几乎全为真值——空数组 `[]`、空对象 `{}`、`"0"` 都是真值。
- **记忆法则**："空的基本值"是假值，"非空的对象/数组"是真值。

### 1.3 变量声明三兄弟

| 声明 | 作用域 | 绑定 | 特点 |
| ---- | ---- | ---- | ---- |
| `const` | 块级 | 锁绑定关系不是值 | `const obj = {}` 后可改属性但不能重新绑定 |
| `let` | 块级 | 可重新赋值 | — |
| `var` | 函数级 | 可重复声明 | 有提升（初始化为 undefined） |

- **实践约定**：默认用 `const`、必要时 `let`、基本不用 `var`。

### 1.4 类型检测四法

| 方法 | 作用 | 局限 |
| ---- | ---- | ---- |
| `typeof` | 判断基本类型 | `typeof null === "object"` 是历史 Bug；对未声明变量不报错 |
| `instanceof` | 对象与构造函数沿原型链的关系 | 无法检测基本类型、跨 iframe 可能失效 |
| `constructor` | 通过构造器属性判断 | `null`/`undefined` 没有、原型被重写时失真 |
| `Object.prototype.toString.call(x)` | **最可靠**，能区分所有内置类型 | 封装成 `getType` 得 `"Array"`/`"Null"` 等精确名 |

### 1.5 包装类型与精确判等

- **包装类型**：`"abc".length` 能工作，是因为访问属性/方法时引擎临时把基本类型包装成 `String`/`Number`/`Boolean` 包装对象、用完即销毁；`new String()` 显式包装出来的是对象，实战不要用。
- **空对象判断**：`Object.keys(obj).length === 0 && obj.constructor === Object` 判断"无自有可枚举属性"的真空对象。
- **`Object.is` vs `===`**：唯一区别是能区分 `+0`/`-0` 且 `NaN` 等于自身，日常用 `===`、精确判等才用 `Object.is`。

### 1.6 隐式转换与相等比较

- **`+` 拼接优先**：`"1" + 2 = "12"`，数字被转成字符串拼接；无 `+` 的运算符把字符串转数字（`"5" - 2 = 3`）。
- **`==` 宽松相等**：触发隐式转换，`[] == 0` 为 true、`null == undefined` 为 true。
- **工程约定**：几乎总是用 `===`，只有 `x == null`（等价于 null 或 undefined）可酌情用。

### 1.7 NaN 与浮点精度

- **`NaN` 特判**：`NaN` 永不等于自身，判断用 `Number.isNaN`（全局 `isNaN` 会先转数字，`isNaN("abc")` 误报 true）。
- **浮点精度**：`0.1 + 0.2 !== 0.3` 源于 IEEE 754 二进制无法精确表示部分十进制小数。
- **工程解法**：用整数运算（元转分）、`Number.EPSILON`/`toFixed` 比较显示，或精确小数库（decimal.js）。

## 2. 作用域与闭包

### 2.1 三种作用域与词法作用域

```
全局作用域      模块/函数外顶层声明，任何位置可访问（过多造成命名冲突）
函数作用域 var 函数内声明外部不可见，var 不受 {} 块限制
块级作用域     以 {} 为界的 let/const，块外访问抛 ReferenceError
```

- **词法作用域**：嵌套关系由**书写位置**决定、与调用位置无关，是理解闭包的关键前提。

### 2.2 作用域链与执行上下文

- **作用域链**：访问变量沿"当前 → 外层 → … → 全局"逐层向上查找，找到即停、全局没有则抛 `ReferenceError`。
- **执行上下文**：装着变量/词法环境、`this` 值、外层引用，程序启动建全局、每次调用建函数级。
- **调用栈**：执行上下文按后进先出组织，无限递归填满栈抛 `RangeError: Maximum call stack size exceeded`。

### 2.3 var / let / const 细节

- **`var`**：提升为 undefined、可重复声明、可重新赋值，无块级作用域。
- **`let`/`const`**：有 TDZ（声明前访问抛 ReferenceError）、不可重复声明；`let` 可重新赋值、`const` 锁定绑定。
- **for 循环陷阱**：`for (var i...)` 回调全打 3、`for (let i...)` 每次迭代独立绑定打 0 1 2。

### 2.4 闭包

- **定义**：内层函数 + 它绑定的外层作用域变量环境的结合体，能访问并记住定义时所在作用域的变量。
- **原理**：外层函数执行完其词法环境因被内层函数引用而不被 GC 回收，`count` 等变量被闭包长期持有。
- **应用**：私有变量（银行账户 balance）、柯里化（分步收参）、记忆缓存（memorize 命中缓存）。
- **三个陷阱**：
  - **内存泄漏**：闭包长期持有大对象无法回收，用完置 `null` 切断引用。
  - **循环捕获同一变量**：`var` 在循环中让回调全拿最终值，用 `let`/IIFE 传参/`bind` 修复。
  - **`this` 丢失**：闭包里的普通函数 `this` 不再绑定外层对象，改用箭头函数捕获外层 `this`。
- **IIFE**：创建后立即执行、隔离内部变量避免污染全局，是 ES6 之前模块化的手段；配合闭包在循环中传参捕获每次迭代值。

### 2.5 this 指向规则

**四种调用规则（优先级 new > 显式绑定 > 方法调用 > 普通调用）**：

```
普通调用  非严格 window、严格 undefined
方法调用  obj.fn() → obj
显式绑定  call / apply / bind
new       以新对象为 this
```

- **箭头函数例外**：没有自己的 `this`，捕获定义时外层词法作用域的 `this`，不受 call/apply/bind/new 影响，也不能 `new`、没有 `arguments`。
- **`arguments`**：类数组（有 length、无数组方法），转真数组用 `Array.from(arguments)`；箭头函数内没有自己的 `arguments`。
- **this 丢失场景**：把 `obj.fn` 单独取出来调用或回调里传函数引用，`this` 会变回普通调用，用箭头函数或显式 `bind` 修复。

## 3. 原型与继承

### 3.1 prototype / __proto__ / constructor 三角关系

```
prototype(显式)   函数独有，new 出来的所有实例的隐式原型都指向它
__proto__(隐式)   对象独有，指向创建它的函数的 prototype，构成原型链
constructor       prototype 上默认带有、指回函数本身形成闭环，实例沿链访问到
```

- **读取推荐**：用 `Object.getPrototypeOf`（`__proto__` 是历史非标准属性）。

### 3.2 原型链与属性查找

```
对象自身属性 →
沿 __proto__ 逐级向上直到 Object.prototype → 再往上到 null
```

- **`hasOwnProperty`**：区分自身属性与继承属性（如 `name` 是自身的、`eat` 是继承的）。

### 3.3 new 四步

```
1 建空对象并接原型   Object.create(Ctor.prototype)，让 __proto__ 指向构造函数 prototype
2 以新对象为 this   执行构造函数，给新对象加属性
3 返回值判定         返回引用类型则用之；返回原始类型则忽略；否则返回新对象
```

### 3.4 继承演进四代

| 方案 | 做法 | 缺陷 |
| ---- | ---- | ---- |
| 原型链继承 | `Child.prototype = new Parent()` | 引用类型属性被所有实例共享 |
| 借用构造函数 | 子构造里 `Parent.call(this)` | 无法复用父类原型方法 |
| 组合继承 | 原型链 + 借用构造 | 属性方法都完美，但父构造被调两次、属性冗余 |
| 寄生组合继承 | `Object.create(Parent.prototype)` 接链且不触发父构造 | **最优，正是 ES6 `extends` 底层** |

### 3.5 class 语法糖与 extends

- **与普通构造的区别**：内部严格模式、方法不可枚举、声明有 TDZ 且不能直接调用（必须 `new`）。
- **`extends + super`**：本质是 `Object.setPrototypeOf` 做完原型接线后再执行父构造。

### 3.6 instanceof 原理

- **判定逻辑**：判断 `B.prototype` 是否出现在 `a` 的原型链上，手写 while 循环沿 `Object.getPrototypeOf` 逐级上找。
- **边界**：基本类型没有原型链，所以 `1 instanceof Number` 为 false，判断基本类型用 `typeof`。

## 4. 异步与事件循环

### 4.1 异步的本质

- **单线程 + 宿主协作**：单线程 JS 把耗时操作交给宿主（浏览器 Web API / Node libuv）处理。
- **回调回主线程**：任务就绪后回调被压回主线程执行，主线程不等待、避免一个慢任务卡死整个应用。

### 4.2 Promise 状态机

- **三态不可逆**：pending → fulfilled/rejected，状态一旦落定就锁死，`resolve`/`reject` 谁先调用谁生效。
- **链式调用**：`then` 返回新 Promise 把回调地狱摊平成链，回调返回 Promise 时下一个 `then` 会等待。
- **错误处理**：链上任一环抛错或 reject 直达最近的 `catch`，`.finally` 不论成败都执行适合清理。

### 4.3 静态方法分工

| 方法 | 行为 | 适用 |
| ---- | ---- | ---- |
| `Promise.all` | 全部成功才成功、任一失败立即失败 | 并行请求后合并渲染 |
| `Promise.allSettled` | 永不 reject，收集每项 `{status, value|reason}` | 批量上传部分失败也要结果 |
| `Promise.race` | 最先落定者（成败都算）决定 | 超时控制 |
| `Promise.any` | 第一个成功者决定、全部失败才 reject（AggregateError） | 多兜底接口取最快可用 |

### 4.4 async / await

- **语法糖**：让异步代码看起来像同步，`async` 函数总返回 Promise（即使内部直接 return 普通值）。
- **`await` 语义**：暂停当前 async 函数到右侧 Promise 落定，用 try/catch/finally 捕获错误。
- **并行写法**：互不依赖的任务先并发发起再 `Promise.all` 汇总，而非逐个顺序 await（2s 变 1s）。
- **底层鼻祖**：Generator 的 `yield` 配合自动执行器（co 库思想）是 async/await 的前身。

### 4.5 事件循环口诀

```
同步执行 → 当前宏任务结束一次性清空全部微任务(含期间新增)
         → UI 渲染 / rAF → 下一个宏任务
```

- **微任务能饿死渲染**：微任务里不断创建新微任务会无限推迟渲染与后续宏任务。
- **经典输出**：`console.log("A")` + `setTimeout` + `Promise.then` + `console.log("D")` → **A D C B**。

### 4.6 浏览器 vs Node 与定时器分工

- **六阶段**：Node 基于 libuv 有 timers/pending/poll/check/close 六个阶段，比浏览器复杂。
- **nextTick 优先级**：`process.nextTick` 比 Promise 微任务还高，当前阶段结束、下一阶段之前执行。
- **setImmediate vs setTimeout(0)**：主模块里顺序不定、I/O 回调里 setImmediate 稳定先。
- **定时器 API 分工**：setTimeout 非精确计时、动画用 rAF（后台自动暂停、帧率同步）、闲时任务用 requestIdleCallback（按 timeRemaining 分片）。

## 5. 内存管理与垃圾回收

### 5.1 栈与堆

```
栈(Stack)   存值类型、局部变量、引用地址，函数结束自动弹出释放、分配极快
堆(Heap)    存对象本体，何时释放交给 GC，不随函数作用域结束而消失
```

- **核心结论**：对象生命周期比函数作用域长，函数返回的对象只要还被引用就仍然存活。

### 5.2 两大回收策略

- **标记清除**：从根（全局对象、调用栈）遍历可达对象打标记、未标记即垃圾，**能处理循环引用**，是现代 GC 基石。
- **引用计数**：为对象记录被引用次数、归零即回收，**无法处理循环引用**（互相引用成不可回收孤岛）。
- **分代收集**：基于"绝大多数对象短命"的规律，短命对象高频回收、长命对象低频回收。

### 5.3 V8 分代与 Scavenge

```
新生代(Scavenge)  半空间复制：存活对象 From 复制到 To 再交换，
                  牺牲一半空间换高吞吐；多次存活或空间不足则晋升老生代
老生代            标记清除 + 标记整理(压缩防碎片)，空间大、存活率高、回收低频
```

### 5.4 降低主线程停顿

```
增量标记   把一次全量标记拆成小步骤、穿插在 JS 执行间隙完成
并发标记   在后台工作线程标记，主线程继续执行 JS 互不阻塞
惰性清理   垃圾清除不必一次做完、可放后台——"把想做的事拆小、挪到后台"
```

### 5.5 五类泄漏与检测

```
意外全局变量    未声明变量挂到全局永不回收 → "use strict" 拦截
闭包固化大对象  闭包长期持有大对象 → 最小捕获 + 用完置空
事件监听未移除  removeEventListener 成对移除 或用 AbortController 批量取消
定时器未清理    setInterval 回调持续持有引用 → clearInterval/clearTimeout
分离 DOM       从文档摘除后仍持有引用的节点无法回收 → 置空引用或重建节点
```

- **粗略观测**：浏览器 `performance.memory`、Node `process.memoryUsage()`（rss/heapUsed/external）。
- **DevTools Memory 三招**：Performance 记录看内存曲线是否只升不降、Heap Snapshot 按 Retained Size 找大对象、Allocation instrumentation 找持续分配者。

### 5.6 弱引用 WeakMap / WeakSet

- **弱引用不阻止 GC 回收**，键必须为对象、不可迭代，适合缓存与对象私有数据。

## 6. DOM 与浏览器 API

### 6.1 查询节点与活集合

- **两大家族**：`querySelector(All)` 走 CSS 选择器、返回静态 `NodeList`；`getElementsByTagName/ClassName`、`children`、`form.elements` 返回**活**集合。
- **活集合跟着 DOM 变**：插入一个 `li` 后 `HTMLCollection` 的 `length` 从 2 变 3、`NodeList` 停在 2；`length` 是查询不是缓存字段。
- **工程约定**：拿到集合先 `Array.from()` 展开再遍历；要"跟随变化"用 `MutationObserver`。

### 6.2 改动节点

- **三种批量插入实测同量级**：3000 个 `li` 下逐条 `appendChild` / `DocumentFragment` / `innerHTML` 都在 2~7 ms——逐条追加只标脏、布局攒到渲染时机统一做。
- **`innerHTML` 的代价不在速度**：重建整棵子树，丢掉输入值、焦点、监听器与动画；追加用 `insertAdjacentHTML` 或 `fragment`。

### 6.3 强制同步布局

- **读写交替 = 每次读一次布局**：500 个元素实测读写交替 288~539 ms、先读后写 2.8~9.6 ms，差 40~115 倍。
- **会强制布局的读取**：`offset*` / `client*` / `scroll*`、`getBoundingClientRect()`、`getComputedStyle()`；`style.x =` / `classList.add()` 只标脏。
- **三条对策**：读写分离、读的结果缓存、写合批到下一帧（rAF 排 200 次只落 1 次）；动画只用 `transform`/`opacity`。

### 6.4 事件流与事件对象

- **三个阶段**：捕获 → 目标 → 冒泡；`addEventListener` 默认冒泡，`{ capture: true }` 改捕获。
- **`target` vs `currentTarget`**：前者是真实目标、全程不变，后者是当前绑定的元素，**回调结束后被置为 `null`**。
- **不冒泡的事件不能委托**：`focus`/`blur` 用 `focusin`/`focusout`；滚动监听声明 `{ passive: true }` 才不会阻塞滚动。
- **合成事件 `isTrusted` 为 false**：`el.click()` 派发的事件与真实交互可区分，风控与埋点会据此过滤。

### 6.5 事件委托

- **一个监听器管住所有子节点**：实测 `ul` 上 1 个监听器处理 4 次点击，动态插入的项不重绑也命中。
- **配 `e.target.closest(sel)`**：覆盖"点在子元素上"的情况；数据从 `data-*` 读。

### 6.6 解绑监听器

- **`removeEventListener` 按"类型 + 函数引用 + capture"匹配**：匿名函数、`.bind()` 结果、capture 不一致都解不掉且不报错。
- **`{ once: true }`**：只处理一次的场景写在注册处；**`{ signal }`**：一个 controller 管一组监听器，`abort()` 一次全摘。

### 6.7 三个观察者

```
IntersectionObserver  管"元素进没进视口"；rootMargin 扩大判定边界 → 懒加载提前量原理
ResizeObserver        管"元素自身尺寸变了"；只改高度也回调；回调里再改尺寸会循环并警告
MutationObserver      管"DOM 被改了"；回调走微任务，不依赖渲染帧
```

- **环境差异**：IO/RO 回调依赖渲染帧，无头 `--dump-dom` 抓不到；MO 任何环境都能收到。

### 6.8 fetch

- **4xx / 5xx 不 reject**：`await fetch()` 正常返回，必须自己判 `res.ok`/`res.status`。
- **响应体只能读一次**：第二次 `res.json()`/`res.text()` 抛 `TypeError`。
- **超时与取消**：`AbortSignal.timeout(ms)` → `TimeoutError`、`controller.abort()` → `AbortError`，都是"被我方取消"；合并信号用 `AbortSignal.any([...])`。
- **竞态三种守卫**：无守卫最终显示旧结果；序号守卫与取消守卫都得到最新结果，后者顺带省掉一次无用响应。
- **XHR 只在要上传进度或维护老代码时用**：`fetch` 多了 Promise 语义、流式响应与 `keepalive`。

## 7. 手写实现与源码

### 7.1 call / apply / bind

- **核心原理**：谁调用函数 `this` 就指向谁——把目标函数临时挂到 `thisArg` 上再调用（用 Symbol 做 key 防覆盖冲突、用完 delete 不留痕迹）。
- **边界处理**：传 null/undefined 指向全局（window/globalThis）、基本类型用 `Object()` 包装。
- **三者分工**：`call` 立即调用逐个传参、`apply` 立即调用以数组传参、`bind` 返回新函数 `this` 永久锁定可继续传参。

### 7.2 myNew

```
1 建对象并连原型   Object.create(Ctor.prototype)，一步完成"建空对象 + 指向 prototype"
2 执行与返回判定   以新对象为 this 执行构造函数；只有返回引用类型才覆盖新对象，原始类型忽略
```

### 7.3 深拷贝

- **循环引用**：WeakMap 记录"原对象 → 拷贝对象"映射，遇到已拷贝对象直接返回缓存避免无限递归。
- **Date/RegExp 特判**：内部有特殊槽不能按普通对象递归，需单独 `new Date(...)`/`new RegExp(...)`。
- **Symbol 键**：`for...in`/`Object.keys` 拿不到，必须用 `Reflect.ownKeys`（字符串键 + 符号键）。

### 7.4 手写 Promise

- **状态单向不可逆**：`resolve`/`reject` 前先判断 `state !== PENDING` 直接忽略后续调用。
- **链式与异步**：`then` 返回新 Promise、回调放 `queueMicrotask` 保证"永远异步"的时序。
- **值穿透**：`then` 没传回调要补默认回调（`v => v` / 抛错），否则结果传不下去。
- **`all` 的实现**：用下标存结果（而非 push）保证输出顺序与输入一致，count 计数判断全部完成。

### 7.5 防抖与节流

- **防抖**：`clearTimeout` 重置倒计时、最后一次触发才生效，适合搜索输入/resize。
- **节流**：固定间隔内最多执行一次；时间戳版首次立即执行、定时器版保证末尾也执行。
- **共同要点**：两个实现都要保存 `this` 和 `...args`，否则丢失上下文与参数。

### 7.6 EventBus 与函数式组合

- **EventBus 存储结构**：用对象而非数组存回调（`eventMap[eventName][callbackId]`），按 callbackId 精确取消订阅。
- **once 实现**：`subscribeOne` 用 `one${id}` 前缀标记，emit 时 `startsWith('one')` 判断并删除。
- **柯里化**：用 `fn.length`（形参个数）判断参数是否收齐，不够则返回继续收参的新函数。
- **compose/pipe**：`compose` 从右往左用 `reduceRight`、`pipe` 从左往右用 `reduce`。
