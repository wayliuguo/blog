DOM 查询与批量操作：哪些写法在悄悄触发布局

页面加载时自动跑一遍并把结果写进页尾的探针；下面两个按钮用来自己反复验证。

① 强制同步布局（layout thrashing）

两段代码做的事完全一样——把每个盒子的宽度 +1px。差别只在读写的顺序：写一次就读一次，浏览器为了给出准确的 offsetWidth 必须立刻把刚写的样式落地成布局；先把要读的读完再统一写，循环里一次布局都不触发。

② 批量插入

3000 个 li 插入到一个已挂载（在文档里）的容器中，三种写法的耗时对比写在页尾探针里。

    ③ 活集合与静态集合

    getElementsByTagName() 返回的是一个活集合，DOM 一变它就跟着变；querySelectorAll() 返回的是静态快照。

      ④ 把连续写合并到下一帧

      连续 200 次调整宽度，如果每次都直接写、写完再读回去，就是 200 次强制布局；只把"最终要写什么"记下来、用一个 requestAnimationFrame 落到下一帧，实际写操作就只剩 1 次。
