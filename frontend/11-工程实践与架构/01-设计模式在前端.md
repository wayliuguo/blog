# 设计模式在前端

> 级别：中级→高级

设计模式（Design Pattern）是一套**被反复使用的、针对特定问题的成熟解法**。很多前端开发者会觉得"设计模式是后端才用"——其实恰恰相反，Vue 的响应式、Redux 的单一数据源、表单校验的解耦、按钮的防抖节流……处处都是设计模式的身影。理解了它们，你看源码不再云里雾里，写出的组件也更能抗住变化。

本章按四层推进：入门（先认识前端最高频的九种模式的思想与典型应用）→ 进阶（模式间对比、选型与组合取舍）→ 实战（把模式落到组件、状态与事件通信上）→ 最小实现（亲手写一个发布/订阅事件中心与极简状态管理，从零看懂"解耦"与"订阅更新"的骨架）。原理均在本章自足，不依赖后文。

这篇文章不追求罗列 23 种模式，而是精选**前端工作中真正高频**的模式：单例、观察者/发布订阅、工厂、策略、代理、装饰器、适配器、组合、命令。每个模式都给出**一句话思想 + 典型前端应用 + 迷你示例**。

## 一、单例（Singleton）

> **思想**：保证一个类全局只有唯一实例。**典型前端**：全局 store、配置对象、全局消息弹窗管理器。

```js
class Store {
  constructor() {
    if (Store.instance) return Store.instance;
    this.state = {};
    Store.instance = this;
  }
  set(key, value) { this.state[key] = value; }
  get(key) { return this.state[key]; }
}

const a = new Store();
const b = new Store();
console.log(a === b); // true —— 全局唯一实例
```

应用：Redux / Pinia 的单一 store、全局日志、事件总线、Toast 弹窗单例。

## 二、观察者（Observer）与发布订阅（Pub/Sub）

> **思想**：一方变化时自动通知依赖它的多方，实现"一对多"解耦（观察者）或通过中间调度者彻底解耦（发布订阅）。**典型前端**：Vue 的响应式 `reactive`、React 的状态订阅、事件总线的 `emit/on`。

**观察者模式（Observer）**——目标直接持有观察者列表：

```js
class Subject {
  constructor() { this.observers = []; }
  subscribe(fn) { this.observers.push(fn); }
  notify(data) { this.observers.forEach((fn) => fn(data)); }
}

const sub = new Subject();
sub.subscribe((v) => console.log("观察者A收到", v));
sub.subscribe((v) => console.log("观察者B收到", v));
sub.notify("状态更新");
```

**发布订阅（Pub/Sub）**——中间加一个"事件中心"：

```js
const EventBus = {
  handlers: {},
  on(event, fn) { (this.handlers[event] ||= []).push(fn); },
  emit(event, ...args) {
    (this.handlers[event] || []).forEach((fn) => fn(...args));
  },
  off(event, fn) {
    if (fn) this.handlers[event] = this.handlers[event].filter((f) => f !== fn);
    else delete this.handlers[event];
  },
};

EventBus.on("login", (user) => console.log("登录成功", user));
EventBus.emit("login", { name: "张三" });
```

应用：Vue3 的 `reactive` + `effect`、浏览器 `EventTarget`、组件库中的跨组件通信事件总线。

## 三、工厂模式（Factory）

> **思想**：把"创建对象"的逻辑集中起来，由传入参数决定返回哪种具体实例，调用方不用关心构造细节。**典型前端**：根据类型配置动态创建组件、生成不同样式的弹窗、创建不同数据源适配器。

```js
// 简单工厂：根据文案/类型生成不同按钮
class PrimaryButton { render() { return `<button class="btn-primary">确认</button>`; } }
class DangerButton  { render() { return `<button class="btn-danger">删除</button>`; } }

class ButtonFactory {
  static create(type) {
    switch (type) {
      case "primary": return new PrimaryButton();
      case "danger":  return new DangerButton();
      default: throw new Error("未知按钮类型");
    }
  }
}

const btn = ButtonFactory.create("danger");
console.log(btn.render());
```

应用：按路由注册页面组件、按设备建不同渲染器、`axios` 响应拦截里按 code 造错误对象。

## 四、策略模式（Strategy）

> **思想**：把"一组可互相替换的算法"各自封装成对象，由上下文选择使用，从而用**组合替代大量的 if/else**。**典型前端**：表单校验、多种排序/规则引擎、弹窗文案策略。

```js
// 校验策略集
const validators = {
  required: (val) => val.trim() !== "" || "必填项为空",
  email: (val) => /^[\w.%+-]+@[\w.-]+\.[A-Za-z]{2,}$/.test(val) || "邮箱格式不正确",
  minLength: (len) => (val) => val.length >= len || `至少 ${len} 个字符`,
};

function validate(rules, value) {
  let firstError = "";
  for (const r of rules) {
    const msg = validators[r.type](value);
    if (typeof msg === "string" && valInvalid) {
      firstError = msg;
      break;
    }
  }
  return firstError;
}
```

应用：表单校验的核心形态、表格列排序规则的配置化、多种渲染器的分发。相比 `switch`，新增一种校验只需加一个策略对象，开闭原则。

## 五、代理模式（Proxy）

> **思想**：在不改变原对象的前提下，通过一个"替身/代理"控制对其的访问，可在访问前后插入额外逻辑。**典型前端**：防抖/节流、`Object.defineProperty`/`Proxy` 实现响应式、拦截器、缓存。

```js
// 防抖（debounce）：高频触发时延迟执行
function debounce(fn, delay = 300) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

// 代理对象：拦截读写
const target = { count: 0 };
const proxy = new Proxy(target, {
  set(obj, key, value) {
    console.log(`设置 ${key} = ${value}`);
    obj[key] = value;
    return true;
  },
});
proxy.count = 1; // 触发拦截日志
```

应用：Vue3 用 `Proxy` 实现响应式、`debounce`/`throttle` 包装事件、接口请求统一加 token 的拦截代理。

## 六、装饰器模式（Decorator）

> **思想**：在不修改原函数/类的前提下，用"包装"为它**动态叠加新能力**。**典型前端**：React 高阶组件（HOC）、函数包装、AOP 切面（埋点、日志、鉴权）。

React 高阶组件装饰器示例：

```jsx
// HOC：给组件注入 props 或包一层
function withLoading(Component) {
  return function WithLoading(props) {
    return props.isLoading
      ? <div>加载中…</div>
      : <Component {...props} />;
  };
}

// 使用：为任何组件叠加"加载态"能力
const UserList = withLoading(UserListInner);
```

纯函数装饰（埋点上报）：

```js
function logAround(fn) {
  return function (...args) {
    console.log("before:", args);
    const result = fn(...args);
    console.log("after:", result);
    return result;
  };
}
const add = logAround((a, b) => a + b);
add(1, 2);
```

## 七、适配器模式（Adapter）

> **思想**：把"不兼容的接口"翻译成调用方期望的接口，让它能无缝接入。**典型前端**：把第三方库/不同后端数据格式统一成内部结构。

```js
// 后端返回格式可能与前端约定不一致，用适配器对齐
function legacyApi(legacyUser) {
  // { username, user_id } → 内部所需的 { name, id }
  return { name: legacyUser.username, id: legacyUser.user_id };
}

const fetched = { username: "alice", user_id: 7 };
const user = legacyApi(fetched);
console.log(user); // { name: "alice", id: 7 }
```

应用：统一不同浏览器的 API 差异、把某图表库的数据结构转成自己组件的入参、对 localStorage 做一层"内存操作适配"封装。

## 八、组合模式（Composite）

> **思想**：把对象组织成**树形结构**，"叶子"与"整体"使用一致的接口，让单个元素与整棵树的处理方式相同。**典型前端**：组件树、目录树、`render` 递归。

```jsx
// 递归渲染一棵树，叶子节点与分支节点的渲染都走同一函数
function TreeNode({ node }) {
  return (
    <li>
      {node.name}
      {node.children?.length > 0 && (
        <ul>{node.children.map((child) => <TreeNode key={child.id} node={child} />)}</ul>
      )}
    </li>
  );
}
// 传入 { name: "root", children: [{ name: "a" }, { name: "b", children: [...] }] }
```

应用：React/Vue 的组件递归渲染树、目录树组件、文件系统 UI。

## 九、命令模式（Command）

> **思想**：把"一个操作"封装成一个对象（含参数与执行），从而支持延迟执行、排队、以及**撤销/重做**。**典型前端**：编辑器/画布的撤销重做、操作日志、批量回放。

```js
// 命令对象：封装"修改 + 撤销"两个动作
class Command {
  constructor(doFn, undoFn) { this.doFn = doFn; this.undoFn = undoFn; }
  execute() { this.doFn(); }
  undo() { this.undoFn(); }
}

const history = [];
function pushValue(canvas, value) {
  const prev = canvas.value;
  // 新的命令实例入栈
  const cmd = new Command(
    () => (canvas.value = value),
    () => (canvas.value = prev)
  );
  cmd.execute();
  history.push(cmd);
}
function undo() {
  const cmd = history.pop();
  cmd?.undo();
}

// 使用：pushValue(canvas, "红色"); pushValue(canvas, "蓝色"); undo(); // 回到"红色"
```

应用：富文本编辑器的撤销重做、画布操作步骤回放、表单批量操作的日志记录。

## 十、小结：什么时候用哪种

| 模式 | 一句话场景 | 一句话前端应用 |
| --- | --- | --- |
| 单例 | 全局只该有一个 | 全局 store / 事件总线 / Toast 弹窗 |
| 观察者 / 发布订阅 | 一方变、多方受影响 | Vue 响应式、事件总线、订阅机制 |
| 工厂 | 想统一、参数化地创建对象 | 按类型创建组件 / 按钮 / 弹窗 |
| 策略 | 一堆可替换算法、想干掉 if/else | 表单校验、排序规则、渲染策略 |
| 代理 | 想在访问前后插逻辑 | Proxy 响应式、防抖/节流、拦截器 |
| 装饰器 | 不改原对象、动态加能力 | React HOC、AOP 埋点 / 鉴权 |
| 适配器 | 接口不匹配、想对齐 | 统一后端/第三方数据结构 |
| 组合 | 树形结构、叶子与整体一致 | 组件递归渲染目录树 |
| 命令 | 想支持撤销重做 / 回放 | 编辑器操作历史、步骤回放 |

**实践建议**：

- **别为模式而模式**——先有真实的"变化点"再上模式，否则是过度设计。
- **优先组合而非继承**，模式大多建立在"组合 + 依赖注入"之上。
- 读源码（Vue、Redux、axios）时主动对号入座，是掌握模式最快的方式。
