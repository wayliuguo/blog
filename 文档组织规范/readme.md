# 文档组织规范

本规范是**通用**写作约定，适用于博客所有板块（`ai/ frontend/ interview/ node/`）。它是一份写给 AI（以及协作者）的指引：每次新建或修改博客文档前，先按这里的约定产出，再以仓库内配套校验脚本兜底。约定已在 `node/` 全量落地，可作为现成实例参考。

本规范按主题拆分为：`readme.md`（本文件，编排章节）与 `reference/` 下五篇细则。各章节与细则篇的对应如下：

| 章节 | 细则篇 |
| ---- | ---- |
| 1. 板块、模块与配套代码 | [`reference/板块与配套代码.md`](./reference/板块与配套代码.md) |
| 2. 单篇文档体例 | [`reference/单篇体例.md`](./reference/单篇体例.md) |
| 3. 代码片段与配套代码表 | [`reference/代码片段与配套代码表.md`](./reference/代码片段与配套代码表.md) |
| 4. 模块元页面：总结.md 与 面试题.md | [`reference/模块总结.md`](./reference/模块总结.md) · [`reference/模块面试题.md`](./reference/模块面试题.md) |
| 5. 改动后的校验 | [`reference/改动后的校验.md`](./reference/改动后的校验.md) |

按内容涉及范围来读：确认目录结构看第 1 章，写单篇正文看第 2、3 章，写模块总结 / 面试题看第 4 章，改完兜底看第 5 章。

## 1. 板块、模块与配套代码

博客基于 VitePress（`base: '/blog/'`），按内容领域分板块（`ai / frontend / interview / node/`），板块下再分「模块」。所有目录与文档文件名**不带数字前缀**，真实阅读顺序以侧边栏为准。配套代码放 `<板块>/<模块>/code/<项目名>/`，被 `srcExclude` 排除出页面集合。测量型模块的配套代码做成「实验台」，让结论可复现。

详见 [`reference/板块与配套代码.md`](./reference/板块与配套代码.md)。

## 2. 单篇文档体例

一篇标准文档固定骨架：篇标题 → 小节标题（问题 / 判断句）正文 → `## 配套代码` → `## 参考`。小节标题写成可回答的问题或判断句，篇间引用写「见第 X 篇」，ASCII 图用裸围栏。

详见 [`reference/单篇体例.md`](./reference/单篇体例.md)。

## 3. 代码片段与配套代码表

正文代码块**必须逐字来自标注的脚本**，每个代码块上方标注来源；无脚本的纯 API 速查标为「示意片段」。`## 配套代码` 表列出脚本、npm script 与覆盖小节。行内代码写双花括号用 `<code v-pre>`。

详见 [`reference/代码片段与配套代码表.md`](./reference/代码片段与配套代码表.md)。

## 4. 模块元页面：总结.md 与 面试题.md

每个模块在侧边栏保留两个入口：总结.md 与面试题.md。

- **总结.md**：`# 模块总结` 后直接 `## 大纲`，大纲按知识体系章节分层（不扁平）；正文用 `## N` / `### N.N` 与大纲编号一一对应，逐项展开。**全量收纳**知识体系内容，不遗漏、不按高频筛、不注出处篇号。
- **面试题.md**：题目按知识体系章节分组（章号与 总结.md 大纲一致），每题用「判断 → 展开 → 佐证 → 边界/追问」四槽骨架结构化作答。

详见 [`reference/模块总结.md`](./reference/模块总结.md) · [`reference/模块面试题.md`](./reference/模块面试题.md)。

## 5. 改动后的校验

改完文档按序跑：链接检查 → 侧边栏覆盖 → 代码同步 → 构建。VitePress 构建会被宿主安全删除保护拦在清空 `.vitepress/.temp` 一步，绕法是 `NODE_OPTIONS=` 干净环境启动：

```bash
NODE_OPTIONS= node node_modules/vitepress/bin/vitepress.js build .
```

详见 [`reference/改动后的校验.md`](./reference/改动后的校验.md)。
