每个模块在侧边栏保留两个入口：`总结.md` 与 `面试题.md`（在 `node/` 内按主题合并为 6 组：01 · 03 · 04 · 05 跨 06 · 07 跨 08 · 09 跨 10,11）。本篇讲面试题.md；总结.md 见 [`模块总结.md`](./模块总结.md)。

## 题目顺序：与知识体系一致

面试题**按知识体系章节分组**，章号与 `总结.md` 大纲一一对应：章内 `Q1/Q2…` 编号、每题标注所属知识域 `（N.N）`。不按「基础概念 / 机制与原理 / 排障与选型 / 场景设计题」四段切分——那会把同一章节的问题拆散、让背题的人抓不住章的考点。

```markdown
# 模块面试题 · 运行环境

## 1. 模块加载与解析            ← 章号与 总结.md 大纲一致
### Q1（1.1）｜ 题面（结论先行）
…
```

## 答案组织：「判 · 展 · 证 · 界」四槽骨架

每题作答统一走四个可记忆槽位，**按题型取舍、不硬填**：

```markdown
### Q1（1.1）｜ 题面（结论先行）
- **判断**  一句话总判，直接答题眼（必有）
- **展开**  机制/原理，套「形态→表达」（对比→表格、先后→分步、父子→树）
- **佐证**  可选的代码 / ASCII / 实例（没有代码或过程就不放）
- **边界**  坑 / 反例 / 不适用 + 可追问方向
```

规则：

- **判断必有**：一句话先给结论，再讲理，杜绝「上来倒原理」。
- **展开按结构选形态**：父子→树、先后→分步、对比→表格、平级→列表，禁止流水账式长段。
- **佐证按需**：代码 / 过程类题目才放，理论题省掉。
- **边界含追问**：把易错坑与「面试官下一步会追什么」放在同槽，方便背题人预演。

四槽与《面试方法论》呼应，但按题型取舍、不整段套五步法。
