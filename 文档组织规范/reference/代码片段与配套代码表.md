# 代码片段与配套代码表

正文里的代码块**必须逐字来自标注的脚本**——缩进、注释、变量名、箭头语法（`x =>` 与 `(x) =>`）都照抄，不允许手抄改写。每个代码块上方一行标注来源。

来自可运行脚本：

```markdown

```js
const path = require('path')
// …

```
```

无对应脚本的纯 API 速查，标注为示意片段：

```markdown
> 示意片段（无配套脚本）
```

省略处用单独一行 `// …` 表示，省略不能破坏代码连续性（按省略行切段后，每段都要能在脚本原文里找到）。

`## 配套代码` 表——路径写纯文本、不链接，并列出覆盖的小节：

| 脚本 | npm script | 对应小节 |
| --- | --- | --- |
| `code/node-basics/src/02-module.js` | `npm run module` | 模块解析规则 |

标注的脚本必须出现在本篇配套代码表第一列；`npm script` 名、lab `README.md` 的表、`## 配套代码` 表三处保持一致。

受检的语言不止 JS：`javascript / js / typescript / ts / css / scss / html / jsx / tsx / vue / json` 都要写出处或标「示意片段」——写 `html` 围栏展示页面结构与属性时同样如此。**不标语言的裸围栏不受检**，所以实测输出与 ASCII 图用裸围栏；不要在围栏上加 `text` 这类语言名，多一个名字就多一条构建告警。

**正文（行内代码、表格、普通段落）里要写双花括号时，用 `<code v-pre>` 而不是反引号**——VitePress 只给围栏代码块加 `v-pre`，行内代码里的双花括号会被 Vue 当插值解析，构建直接报 `Error parsing JavaScript expression`；围栏代码块（含不标语言的实测输出块）不受影响，照常写。

也不要用 `&#123;&#123;` 这类 HTML 实体绕：markdown-it 会把 `&` 再转义一次，页面上原样显示出 `&#123;&#123;` 这几个字符，既不报错也不对。实体只在本规范自身的示例里出现。

````markdown
正文里写 <code v-pre>{{ item.name }}</code>，不要写成反引号包起来的样子。

```wxml
<view wx:for="{{ items }}">{{ item.name }}</view>
```
````
