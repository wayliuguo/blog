# 单篇文档体例

一篇标准文档的固定骨架：

```markdown
# 篇标题

## 小节标题写成问题或判断句
正文……（可从脚本摘录代码，见「代码片段与配套代码表」篇）

## 配套代码
（表格，见「代码片段与配套代码表」篇）

## 参考
- [模块总结](./总结.md)
- [模块面试题](./面试题.md)
```

约定要点（用例子说明，不逐一列禁项）：

- **篇首不写铺垫**：篇标题后直接进第一个小节标题，不用元叙述句交代「本篇是模块的 XX」「与 XX 篇的关系」「数据来自哪个 lab」。这类信息若必要则归位——模块定位 / 篇间关系由 `总结.md` 大纲承载，配套 lab 说明只留 `## 配套代码` 表格与跑法注释。
- **小节标题**写成问题或判断句：`require 与 import 的本质区别是什么？`
- **篇间引用**写「见第 X 篇」，不硬编码文件路径。
- **结尾两段顺序固定**：配套代码 → 参考；`## 参考` 前两行固定为本模块「总结 / 面试题」入口。
- **ASCII 图**用裸 ` ``` ` 围栏，不要写成 ` ```text `（VitePress 会刷告警）。

## 长节：标题就是结论，证据跟在结论下

一整章要讲透一组手段（指标、分层、机制）时，按**章 → 子层 → 手段**三层钻取。规则只有两条：**标题写成结论**、**结构化表达直接跟在标题下**。

```markdown
## 三、加载层：把 LCP 打下来

LCP 由四段构成，这四段正好对应加载层的四层——哪一段长，就去改哪一层。

（一段 ASCII：指标怎么拆成几段、每段对应哪一层）

| 子层 | 服务指标的哪一段 | 手段清单 |
| ---- | ---------------- | -------- |
| 3.1 网络层 | TTFB：请求发出 → 首字节 | `dns-prefetch`、`preconnect`、HTTP/2、CDN |

### 3.1 网络层：TTFB（DNS / TCP / TLS / 服务端）

先在 Network 面板把这一次请求拆成五段，定位到底慢在哪：

（一段 ASCII 瀑布图，或一张判断表）

| 哪一段慢 | 判断依据 | 前端能不能改 |
| ---- | ---- | ---- |

#### dns-prefetch

- 只做 DNS 预解析，把查询提前到主文档解析期；只对「确定会用」的跨域资源加，乱加白占带宽。
- `<link rel="dns-prefetch" href="https://cdn.example.com">`；Network 面板里该域的 DNS 行从「关键资源前」移到「主文档解析期」。

#### preconnect

- 提前走完 DNS + TCP + TLS，适合「同一个域后面还要发多个请求」的 CDN。
- 四个「提前」指令的分工容易混：

| 指令 | 它做的事 | 用在哪 |
| ---- | ---- | ---- |
| `preconnect` | 提前走完 DNS + TCP + TLS | 同域后面还要发多个请求 |
```

要点：

- **标题即结论**：章与子层的标题写成判断句。读一遍全篇标题，应该能串出一条完整的结论线；标题下**直接放结构化表达**，不再另立「总览」「小结」这类中间标题。
- **选形按信息形态**：并列对比 → 表格；并列条目或先后次序 → 有序 / 无序列表；结构或流程用列表说不清 → ASCII 图（**按需，不是每层必备**）。
- **手段内部用列表，不贴标签**：不必写「这是解析」「这是佐证」——列表项本身就是判据，证据（代码块、读数表、补充说明）直接跟在它后面。
- **证据逐字保留**：读数表与代码块**原样搬运**，不缩写、不重排——`check-code-sync` 按围栏内容逐字比对，改一个字符就报「代码对不上」。
- **注意事项并进列表**：易错点、反例、什么情况下这条手段无效，直接写成该手段下的一条列表项，不单开一节。
- 实例：`frontend/进阶/性能优化/性能优化体系与指标.md`（一章指标体系 → 二章口径与工具 → 三/四/五 三个优化层 → 六章收口，全按此结构写）。
