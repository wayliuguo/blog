# 板块、模块与配套代码

博客基于 VitePress（`base: '/blog/'`），按内容领域分板块，板块下再分「模块」。

- 编号规则：**所有目录与文档文件名都不带数字前缀**（含章节文档）；真实阅读顺序以**侧边栏**为准，篇间引用写「见第 X 篇」（X 按侧边栏顺序）。
- 配套代码放在 `<板块>/<模块>/code/<项目名>/`，被 `srcExclude: ['**/code/**']` 排除出页面集合，不进导航、不进构建产物。

实例：

```
node/
  运行环境/                模块目录（不带编号）
    code/                    配套可运行代码
      node-basics/           code 下的项目
    Node.js 是什么.md      章节文档（文件名不带编号）
  总结.md                     模块元页面（见「模块总结与模块面试题」篇）
  面试题.md
```

## 测量型模块：配套代码做成「实验台」

当文章里的结论必须是**可复现的真实数字**（性能、监控、并发、内存这类模块）时，配套代码不写成"演示页"，而写成一个**实验台**：每个现象对应一个能跑出数字的场景脚本，文章里的实测输出块全部来自它的 stdout。本仓实例：`frontend/进阶/性能优化/code/perf-lab`、`frontend/进阶/监控与稳定性/code/monitor-lab`、`frontend/进阶/网络与协议进阶/code/net-lab`、`frontend/进阶/工程实践与架构/code/eng-lab`。

```
<模块>/code/<lab>/
  harness.*       脚手架：对齐表格、起服务、起无头浏览器、等结果
  scenarios/*     一个现象一个脚本，各自能单跑（runAsMain 判断主入口，或用 cli.mjs 分发）
  pages/ 或 site/ 浏览器侧的被测页面
  package.json    每个场景一条 script，名字与文章里的「运行：npm run xxx」逐字一致
```

几条固定做法：

- **零依赖优先**：只用语言内置能力起服务与浏览器（`PORT=0` 让系统分配端口，再从进程输出里回读真实端口）。
- **让差异可观测**：本机网络下什么都一样快，需要差异时在**服务端**按限速切片发送，把差别放大出来。
- **输出要可复现**：随机数据用固定种子，时间戳对齐到整秒，否则写进文章的数字每次都不一样。
- **依赖注入**：浏览器 API 从 `options.env || globalThis` 取，同一份实现既能进浏览器也能在 Node 里跑单测。
- **被测样本另放 `fixtures/`**：需要被扫描、分析、压测的对象（示例业务目录、待解析的源码）与实验台本身分开，并在 README 里写明「它是故意写坏的」以及坏在哪，读者可以自己先找答案再对答案。
- **口径差异要显式打印**：同一现象两套口径会给出不同的数（窗口 vs 秒桶、`cls` vs `clsRaw`），输出里就要把差异打出来并解释，否则读者会当成 bug。
