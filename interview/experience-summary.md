# 面经汇总

> 本页是[面经](/interview/experience)的「方法论版」：不看单个公司的细节，而是从大量面经里沉淀出**题型分布、公司风格、各阶段打法、被拒原因**，帮你按图索骥。

## 一、前端面试常见题型分布

综合多数一二线公司面经，题型大致按以下占比出现：

| 考察模块 | 常见占比 | 高频题目举例 |
| --- | ---: | --- |
| JS 基础与原理 | 25% | 闭包、原型链、事件循环、this、Promise、异步 |
| CSS / HTML 基础 | 10% | 盒模型、布局、flex、BFC、语义化 |
| 浏览器 / 网络 | 15% | 同源/跨域、渲染机制、缓存、HTTP/HTTPS、TCP |
| 框架（Vue/React） | 20% | 响应式原理、diff/虚拟 DOM、组件通信、生命周期、数据流 |
| 工程化 / 性能 | 10% | 打包、构建优化、首屏优化、监控、部署 |
| 手写 / 算法题 | 15% | 手写 new/bind/Promise、数组/字符串/树类算法 |
| 软技能 / 行为面 | 5% | 自我介绍、项目难点、离职原因、职业规划 |

> 注意：**占比会随职级变化**。初级偏基础与语法题；中高级偏原理、工程化与场景设计；资深更偏架构、团队与疑难杂症。

## 二、各公司面试风格差异

- **阿里系**：重基础与原理深挖，「问到底」式连环追问，强调代码实现与 Java 思维迁移；过程常有多轮、体验较长。
- **腾讯系**：面试官亲和，偏算法与编码，会引导你逐步做对；重视学习能力与抗压。
- **字节系**：算法考得多且快，节奏紧凑，常上来就 coding；重思维与工程落地。
- **百度系**：基础较全面，前端方向偏重、也问框架源码与性能。
- **美团系**：注重真实业务场景和项目细节，爱深挖「你做的 vs 你懂的」，工程化、监控、性能问得多。
- **华为 / 国企与外企部分**：流程长，可能有在线测评、性格测试；更看综合匹配与稳定性。
- **中小厂 / 独角兽**：一般 1~2 轮纯技术 + HR，重「能不能直接上手干活」，项目实战和工具链熟练度关键。

> 归纳：**大厂重「潜力与深度」，中小厂重「上手与实用」**。话虽如此，个体面试官风格差异很大，以上只是整体倾向。

## 三、各阶段注意点

### 1. 投递阶段

- **选对入口**：内推 > 官网直投 > 平台海投；内推能加快流程、进面试池机会更大。
- **准备简历投递**：针对性微调，不同岗位侧重点不同；同一时间别把一家公司的多个端口都投了。
- **时间节奏**：避开集中爆发期（如金三银四刚开始），面试机会多但竞争也大；冷门岗位 hc 多。
- **雇主背调前多确认**：拿到口头 offer 再离职，避免空窗。

### 2. 笔试阶段

- **环境适应**：提前用牛客 / leetcode 熟悉在线评测的输入输出，很多翻车不是不会而是格式错。
- **先易后难**：快速扫题，做有把握的，留时间给两三道；做不完别慌，AC 率比「全写完都错」强。
- **写注释与思路**：部分笔试看代码风格，清晰命名、边界处理能加分。
- **善用样例**：跑一遍示例确认 IO 逻辑再提交。

### 3. 一面（技术基础面）

- **打牢八股**：基础题占了大部分，把[知识复习](/interview/css)和高频题背透。
- **编码要稳**：手写题慢一点、逻辑清晰，宁可小步验证也别一次性写完再 debug。
- **遇到不会先想**：说思路再去猜，别直接「不知道」；面试官更看你怎么靠近答案。
- **主动补充**：答完一个点主动带出相关点，展示深度，但别堆砌。

### 4. 二面（深度 / 交叉面）

- **讲项目**：用 STAR + 难点亮点，高频在这里翻车，务必提前打磨（见[难点亮点](/interview/lightspot)）。
- **场景题**：慢一点，先澄清再分层设计，套[场景设计题](/interview/scenario-design)的答题框架。
- **体现工程化思维**：不仅「能用」，还要讲「为什么」与「取舍」。
- **抗压**：被质疑项目/答案很常见，稳住，用事实和数据回应，别辩解过度。

### 5. HR面 / 终面

- **软素质与意愿**：表现出靠谱、抗压、上进，以及对业务的兴趣。
- **薪资与外派**：明确沟通期望与可谈空间，别模糊。
- **入职时间**：诚实给出到岗时间，别画大饼。
- **反问环节**：准备好几个有质量的问题，体现你的思考深度。

## 四、常见被拒原因与改进建议

| 常见被拒原因 | 表现 | 改进建议 |
| --- | --- | --- |
| 基础不牢 / 一问到底就露馅 | 八股背得出 API 但答不清原理 | 回归源码与原理，把解释讲成自己的话 |
| 手写题卡壳 / 边界错误 | 会背 API 但写不完整 | 多练[手写题](/interview/writecode)，重边界与鲁棒性 |
| 项目细节经不起追问 | 「我做的」和「我懂的」不一致 | 深挖自己负责的每一行，能讲清取舍与数据 |
| 只会用不会设计 | 场景题没思路、全是套路 | 用[场景设计题](/interview/scenario-design)练分层设计与落地 |
| 表达混乱 / 过度紧张 | 语速快、逻辑不清、答非所问 | 结构化表达、STAR、慢下来想清楚再说 |
| 与岗位/团队不匹配 | 能力不差但方向、技术栈或行情不匹配 | 瞄准目标岗位微调简历与准备方向 |
| 期望薪资超出范围 | 谈崩在 HR 环节 | 了解市场与对方预算，给合理区间 |
| 学习能力与潜力信号弱 | 只说「会」不说「为什么/怎么学的」 | 展示遇到新东西怎么主动学习落地 |
| 缺乏对公司的了解 | 反问环节问不出有质量的问题 | 面试前做足功课，看官网/技术博客/产品 |
| 时间线过长 / 拿到 offer 后犹豫 | 拖到对方给别的候选人 | 目标明确，别把 offer 当备胎 |

## 五、面试后快速复盘清单

每次结束后立刻完成：

1. 记录所有被问到的问题（借用[自测记录表](/interview/tracking-sheet)）。
2. 把卡壳题标注为「需复习」，当天补上。
3. 反推这家公司的风格与考察偏好。
4. 调整下一场的准备重点与简历措辞。

**一句话总结**：被拒不是否定你，而是定位你；把每一场面经变成下一次的弹药。
