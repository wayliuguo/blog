# 面试题 · 数据库缓存与部署（全覆盖版）

> 对齐知识体系：node 模块四·数据与缓存（数据库、Redis）+ 模块六·工程化与拓展（部署与工程化、脚手架开发）。
> 项目结合点：赴演记（MySQL + Redis + Docker）+ 监控配置脚手架（CLI/npm）。红线：定位全栈拓展，不吹后端专家/DBA。

## 一、MySQL

**Q1：索引原理与优化？**
- B+ 树：最左前缀、覆盖索引回表少；索引列不做函数/运算，区分度低的列不值
- explain 看 type/rows/extra（Using filesort、Using temporary 是信号）
- 深分页：游标方式 where id > ? limit n；大事务拆小

**Q2：事务怎么用？隔离级别了解吗？**
- TypeORM transaction 包裹多表写操作，保证原子性；注意事务内不做远程调用（长事务锁表）
- 隔离级别：RU / RC / RR（MySQL 默认）/ 串行化；脏读、不可重复读、幻读三级问题对应

**Q3：连接池为什么需要？**
- TCP 建连 + 鉴权开销大，池化复用；上限防打爆数据库，下限保并发吞吐
- TypeORM 配置项：连接数、队列上限、超时——连接泄漏（只借不还）是常见线上事故
- 追问「为什么不每次新建」能答出开销账即可，不用背参数

## 二、Redis

**Q4：Redis 数据结构与场景？**
- String：缓存/计数器；Hash：对象缓存；List：队列；Set：去重/共同关注；ZSet：排行榜/延时队列
- 三件套：穿透（空值缓存/布隆）、击穿（热点永不过期+互斥重建）、雪崩（过期时间加随机）

**Q5：缓存与数据库一致性？**
- 旁路缓存：先更新 DB 再删缓存；延迟双删应对读旧写并发的窗口
- 强一致不现实，按业务容忍度定策略
- 追问「为什么是删缓存不是更新缓存」：并发写会乱序覆盖，删除让下次读回源更安全

**Q6：Redis 为什么快？单线程为什么够？**
- 内存操作 + IO 多路复用 + 高效数据结构；6.0 后网络 IO 多线程、命令执行仍单线程（无锁竞争）
- 单线程含义：避免锁与上下文切换，瓶颈通常在网络与内存不在 CPU

## 三、可观测与稳定性

**Q7：日志怎么做？**
- 结构化 JSON 日志 + 分级 + traceId 串联请求链路；按天切割轮转控制磁盘
- 错误日志对接告警；winston 体系：分级 + 轮转 + 请求日志

**Q8：限流怎么做？**
- 算法：计数器（窗口突刺）、滑动窗口、令牌桶/漏桶（匀速）
- 单机 Throttler 中间件按路由配置；分布式用 Redis 计数

**Q9：慢接口怎么排查？**
- 链路定位：traceId 串日志 → 拆「应用计算 / DB 查询 / 外部调用」三段计时
- DB 段：慢查询日志 + explain；外部段：超时与重试策略是否合理
- 答题框架比结论重要：先测量再下结论，与前端性能定位同一思想

## 四、部署与交付

**Q10：Docker 部署流程？**
- 多阶段构建（builder 装依赖编译 → runner 只拷产物）减小镜像；环境变量注入配置；健康检查
- 追问「镜像怎么瘦」：alpine 基础镜像、.dockerignore、依赖与源码分层缓存

**Q11：PM2 了解多少？**
- cluster 模式多进程 + 零停机重载（reload 逐个换进程）、日志管理、开机自启
- 与 Docker 判断线：单机/node 生态内 PM2 够用；跨环境一致、编排与扩缩容交给容器

**Q12：CLI 工具怎么开发发布的？（脚手架项目）**
- package.json 配 bin 字段指向入口（shebang）；commander 注册命令与选项；axios 调平台接口
- npm publish 前置：registry 指向、版本 semver（major/minor/patch）、登录凭据
- 追问「怎么让全局命令可用」：bin 字段 + npm link 本地调试，发布后 npx/全局安装生成可执行链接
