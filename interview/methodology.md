# 面试方法论

> 面试考察的从不是「背了多少」，而是「能不能把一个知识点、一个项目、一次决策讲得清楚」。本页从流程、准备到复盘，给你一套可执行的方法。

## 一、面试流程与考察点

典型的互联网公司前端面试通常分四到五轮：

| 阶段 | 时长 | 主要考察点 | 考察形态 |
| --- | --- | --- | --- |
| 笔试 / 在线评测 | 1~2h | 编程能力、基础扎实度 | 算法、手写题、理解题 |
| 一面（技术） | 40~60min | 基础知识、框架原理、深度 | 八股深挖、编码 |
| 二面（交叉/主管） | 40~60min | 工程化、方案设计、难题、项目 | 场景设计、开放题 |
| HR面 / 三面 | 20~40min | 软素质、意愿、可信度 | 行为面、开放题 |

各阶段通用逻辑：**一面看「会不会」，二面看「行不行」，HR面看「合适不合适」**。

### 常见考察维度

- **基础大科**：JS 语言细节、CSS、浏览器/网络原理、性能。
- **框架深度**：Vue/React 的实现原理，不只是 API 用法。
- **编码能力**：手写 API、解决实际问题、算法与数据结构。
- **工程能力**：多人协作、代码规范、构建、监控、质量保障。
- **软素质**：沟通表达、自驱、学习能力、抗压。

## 二、如何准备

准备不是刷题，而是**有针对性地建立能力矩阵**。给自己做一个差距分析：对着面试考察点，标出「熟 / 半熟 / 不会」，优先补半熟和不会里最常考的。

### 1. 简历

- **一页以内**，重点突出，排版干净、无错别字。
- 用**事实和数据**说话，弱化「精通/熟练掌握」这种形容词。
- 按 STAR 写项目：背景、任务、行动、结果，每个项目写 2~3 个要点。
- 千万别写不会的东西——被深挖时很难圆。

### 2. 项目

- 挑 2~3 个最能代表你能力的项目，把整体架构和你的职责讲清楚。
- 每个项目预演：**做的什么 → 难点 → 怎么解决的 → 结果 → 还能怎么优化**。
- 如果你是主力，能讲出业务背景和数据变化的大幅加分。

### 3. 基础

- 回归源码与原理，不要停留在「用过」。
- 把高频八股题整理成自己的话，覆盖：JS、浏览器、网络、框架原理、性能、工程化。
- 用[代码输出](/interview/codeconsole)和[手写题](/interview/writecode)验证掌握程度。

### 4. 算法

- 前端面试算法一般到**中等难度**为止，围绕数组、字符串、链表、栈、哈希、双指针、递归、基础 DFS/BFS。
- 学会写**清晰、有边界处理、有复杂度分析**的代码。
- 刷的题按 LeetCode 高频 + 标签分类，别只记答案。

## 三、自我介绍模板

自我介绍核心是**「我是谁 + 我做过什么 + 我为什么合适」**，控制在 1~2 分钟。

> 面试官你好，我叫×××，毕业于×××，× 年前端经验。
> 过去我在 A 公司负责 B 项目，主导了 C 功能的重构，把首屏性能从 × 提到 ×，获得过 × 认可；也搭建过团队的前端监控体系……
> 我对前端基础、Vue 实战和性能优化比较有研究，平时会写技术方案和技术笔记。
> 这次应聘贵司前端岗位，一是看中业务方向与我的经验匹配，二是希望在一个更高的舞台上有更多挑战。谢谢。

要点：

- **有数字**：多年经验、项目影响、优化指标。
- **有记忆点**：一句能让人记住的话或案例。
- **提前排练**，但别背得像念稿。

## 四、简历项目 STAR 法则

STAR 是讲项目的骨架，把一句话拆成一个故事：

- **S（Situation）背景**：项目是什么，解决什么问题，规模和团队如何。
- **T（Task）任务**：你在其中负责什么，目标是什么。
- **A（Action）行动**：你具体怎么做，用了什么技术，做了什么决策。
- **R（Result）结果**：量化产出，比如性能提升、效率提升、上线效果。

> 示例：
> S 背景：用户端 H5 首屏白屏严重，3G 场景下约 3s。
> T 任务：负责首屏优化，目标压到 1.5s 内。
> A 行动：建立性能监控埋点定位瓶颈；拆分核心代码，路由/组件懒加载；把大图转 WebP 并做 CDN；对首屏数据做接口并行与缓存。
> R 结果：首屏时间从 3s 降到 1.2s，白屏率下降 60%，用户跳出率下降 15%。

注意：面试官会顺着 ST 追问 AR，所以**每个项目都要能展开成 STAR**，并在说完 A 后主动给 R。

## 五、如何讲项目（难点与亮点）

「难点亮点」是二面拉开差距的核心，参见[难点亮点](/interview/lightspot)，这里讲方法论：

- **先讲业务复用性**：你说出来别人也能用到，比私人炫技强。
- **难点讲"真难"**：不要只讲"用了某技术"，要讲当时的**取舍与权衡**——为什么这么选、放弃了什么。
- **亮点要可量化**：性能提升、成本下降、开发效率、稳定性。
- **主动引导**：讲到一个点主动展开，把面试官往你熟悉的方向带。
- **被问住时**：先表达思路再承认盲区，「我知道 A 方案，B 方向我还没深入，我理解的思路是……」，比硬编强。

## 六、常见问题回答思路

| 问题 | 回答思路 |
| --- | --- |
| 介绍一下你自己 | 见上方模板，突出经历匹配度 |
| 为什么从上一家离开 | 说成长与机会，不贬低前东家 |
| 为什么选择我们公司 | 结合业务、技术栈、团队，体现你做过功课 |
| 你的优缺点 | 优点用实例佐证；缺点说一个「真但正在改」的，别说不痛不痒的 |
| 职业规划 | 短期提升技术与某方向深度，中期往架构/带团队，长期与公司共同成长 |
| 期望薪资 | 给区间，说明依据（历史薪资 + 市场 + 自身价值） |
| 还有什么想问我的 | 提前准备 2~3 个，问团队、技术栈、业务、成长路径 |
| 你遇到的最大困难/挑战 | 用 STAR 讲一次真实经历，突出解决的思路与结果 |
| 平时怎么学习 | 讲看源码、写笔记、技术分享、参与开源等可持续途径 |
| 你的压力来源 / 如何应对 | 讲压力的具体场景 + 你的应对策略 + 收获 |

## 七、薪资谈判

- **先给出诚实的基础线**：根据当前薪资与市场行情定一个 **保底 + 目标** 两个数。
- **别先出口**：尽量让对方先给报价，你在此基础上往上谈。
- **要有依据**：历史薪资流水、offer 对比、自身能力与岗位匹配度。
- **谈整体 package**：不仅月薪，还有年终、期权、晋升空间、工作时长，综合评估。
- **避免情绪化**：谈崩了就礼貌收尾，好聚好散，圈子很小。

## 八、面试后复盘

每场面试结束 = 复习起点。建议建立一个**面试复盘清单**：

1. **立刻记录**：趁热把被问到的问题全部写下来（可借用[自测记录表](/interview/tracking-sheet)）。
2. **分类归档**：分为「答得好的」「答不上的」「需要补的」。
3. **别跳过卡壳题**：被反复卡的题就是你的短板，当天就查资料补上。
4. **反推风格**：记录这家公司爱问基础还是算法，调整下一家准备重点。
5. **一周后再测**：隔几天重测卡壳题，确认真的掌握了，而不是记住了答案。
6. **心态整理**：把失败当作定位工具，而不是打击。

**一句话总结方法论**：把面试当一次「被检验的演示」，准备充分度决定了你的发挥下限。
