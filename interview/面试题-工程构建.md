## 一、模块化（基础常考）

**Q1：CommonJS 和 ESM 的区别？**
- CJS 运行时加载、值拷贝（导出快照）、this 指向当前模块、动态 require
- ESM 编译时确定依赖关系（静态结构 → 可 tree-shaking）、值绑定（实时只读视图）、顶层 await
- 互操作：Vite/Rollup 把 CJS 依赖预构建转 ESM

## 二、Vite

**Q2：Vite 为什么快？**
- 开发期原生 ESM 按需编译：请求到哪编译到哪，不整包构建
- 依赖预构建用 esbuild（Go，快一个量级）：CJS 转 ESM + 零散模块合并防瀑布请求
- 生产用 Rollup：成熟 tree-shaking 与产物优化
- 本质：bundleless 开发 vs webpack 全量 bundle

**Q3：Vite 插件机制？写过什么？**
- 钩子分两类：构建类（resolveId → load → transform，改模块内容）、服务类（config / configureServer / handleHotUpdate）
- 兼容大部分 Rollup 插件钩子
- 【项目】有构建流程扩展的实践（编写构建插件）：可展开一个具体插件「解决什么问题 → 钩子选在哪 → 产物形态」，纸面已删但口述保留

**Q4：HMR 热更新原理？**
- dev server 与浏览器建 WebSocket；文件变化推送模块路径
- 客户端请求该模块最新版本，运行时替换并只重跑受影响边界（vue 组件单文件替换，css 直接换 style 标签）
- 替换失败（改了导出结构等）自动整页刷新兜底

## 三、Webpack 与编译原理

**Q5：loader 和 plugin 的区别？**
- loader：文件转换器（链式，源→目标），如 .vue/.ts/.scss 转模块
- plugin：基于 tapable 事件流，介入构建全生命周期（打包优化、资源注入、环境变量）——能力大于 loader

**Q6：tree-shaking 原理？**
- 依赖 ESM 静态结构：编译期分析导出引用关系，未引用的导出在压缩阶段删除
- sideEffects 字段标记无副作用模块，防止「有副作用的 import 被误删」；CJS 动态特性摇不动

**Q7：Babel 工作流程？polyfill 怎么处理？**
- 三段：parse（源码→AST）→ traverse+transform（访问者模式改 AST）→ generate（AST→代码+map）
- preset-env 按目标浏览器决定转换集合；useBuiltIns: usage + core-js 按需注入 polyfill
- 新项目很多场景 esbuild/swc 替代 babel（快，但插件生态少）

**Q8：source map 是什么？**
- 编译产物与源码的位置映射（mappings 的 VLQ 编码），报错定位回源码
- 安全：线上不暴露 .map（泄露源码）——上传到错误监控平台按版本还原（口径：原理了解，未落地）

## 四、构建优化

**Q9：产物优化清单？**
- 分包：路由动态 import + manualChunks 拆第三方，利用长缓存（内容 hash）
- 按需引入组件库；压缩（esbuild/terser）；小图内联、图片压缩
- 分析工具：rollup-plugin-visualizer / webpack-bundle-analyzer 看体积构成再动手

**Q10：构建速度优化？**
- 预构建缓存、缩小处理范围（include/exclude）、并行与持久缓存
- 类型检查拆出构建链（dev 不全量 tsc，交给 IDE + 独立 lint 阶段）
- 【项目】迁移时统一构建配置：Vite 7 + 分层目录约定 + ESLint/TS 严格规范

## 五、规范与协作

**Q11：ESLint / Prettier 怎么协作？**
- ESLint 管质量规则、Prettier 管格式；关掉二者冲突规则（eslint-config-prettier）
- 落地：编辑器保存即修 + lint-staged 只查改动文件 + husky pre-commit 卡点
- 【项目】新架构统一规范，避免多人多风格

**Q12：CI/CD 流程设计？**
- 流水线：lint → 单测 → 构建 → 部署（测试环境）→ 验收 → 灰度 → 生产
- 分支策略：feature 分支 + MR 评审 + 主干保护；产物不可变、环境配置注入
- 口径注意：讲行业做法与设计思路即可，别声称当前已全量落地

**Q13：微前端了解吗？**
- 场景：多团队多技术栈共存、巨石应用渐进迁移
- qiankun：JS 沙箱（Proxy 代理 window）、样式隔离（shadow DOM / scoped 前缀）、应用注册与生命周期
- 成本：样式与全局变量冲突、公共依赖治理、通信复杂——不是默认解，先想清楚要不要拆

**Q14：monorepo 与 pnpm？**
- pnpm：内容寻址硬链接省磁盘 + 严格依赖（治幽灵依赖）
- workspace 多包共享配置与联调；适合组件库 + 多应用的仓库结构
