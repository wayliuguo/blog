# 面试题 · 监控系统（全覆盖版）

> 高频常考为主，简历结合点标【项目】。红线：监控是「在团队既有 SDK 上迭代补齐」，不是从 0 自建；sourcemap 还原了解原理即可，别声称项目已落地。

## 一、体系总览

**Q1：前端监控体系包含什么？**
- 采集：JS 错误、接口成功率与耗时、白屏、性能指标、业务埋点
- 上报：批量/采样/重试，sendBeacon 兜底
- 处理：清洗聚合 → 指标计算 → 看板 → 告警 → 定位还原
- 【项目】在既有 SDK 上补齐采集项与口径，不重造轮子

**Q2：怎么设计一个前端监控 SDK？（架构题）**
- 分层：核心（初始化/配置/插件注册）+ 采集插件（错误/接口/性能/埋点）+ 上报器 + 生命周期
- 设计要点：无侵入或低侵入、性能开销可控（采样与延迟初始化）、可扩展插件化、数据脱敏
- 【项目】迭代经验落在：补采集项、统一埋点口径、对接告警配置

## 二、错误采集

**Q3：JS 错误采集的几条通路？**
- window.onerror：同步运行时错误（含堆栈）
- window.addEventListener('unhandledrejection')：未捕获的 Promise 异常
- error 事件（捕获阶段）：资源加载错误（script/img）
- try-catch 兜关键流程；Vue 场景加 errorHandler 统一收口组件错误

**Q4：跨域脚本的错误堆栈为什么是 Script error？怎么解决？**
- 浏览器安全策略隐藏跨域脚本细节
- 解决：script 标签加 crossorigin="anonymous" + 资源服务端返回 Access-Control-Allow-Origin

**Q5：错误怎么聚合与归因？**
- 按 message + 顶部堆栈帧聚类成 issue；维度下钻：版本、机型、系统、网络、页面
- 新版本错误率突增 → 关联发布记录定位回滚；单个用户路径还原辅助复现
- sourcemap 原理：发布时按版本上传映射文件，堆栈经源映射还原行列——线上 bundle 不暴露 map（口径：了解原理，本项目未落地）

## 三、性能采集

**Q6：性能指标怎么采集？**
- web-vitals / PerformanceObserver：LCP（largest-contentful-paint）、INP（事件时延）、CLS（布局偏移）
- 自定义计时：performance.mark/measure；接口耗时在请求层统一打点（发起与响应差值）
- 【项目】接口耗时与成功率在请求层统一采集；口径先于工具（先定义怎么算，再谈怎么采）

**Q7：白屏检测方案？**
- 采样点检查：elementsFromPoint 取关键坐标的元素，或检查根容器 children 为空
- 时机：onload 后延迟检查 + 周期复检；上报附带关键接口状态辅助归因（数据挂了还是渲染挂了）

## 四、上报

**Q8：上报方式怎么选？**
- sendBeacon：页面卸载也可靠发出（离开页面的最后埋点首选）
- fetch keepalive：需带响应处理时；img/gif：兼容性兜底（302 限制注意）
- 策略：批量合并 + 采样 + 失败重试（localStorage 暂存下次补报）；数据脱敏（不传敏感字段）

## 五、埋点与指标口径

**Q9：埋点体系怎么设计？**
- 事件分层：页面生命周期（进入/离开）、曝光（可见性，IntersectionObserver）、交互（点击）、结果（业务结果）
- 事件命名有规范（页面_对象_行为），公共参数 SDK 注入，业务只传业务字段
- 关注数据质量：埋点也有测试（上报校验、参数核对）
- 【项目】补全页面埋点并统一口径与上报入口

**Q10：什么是指标口径？为什么要沉淀文档？**
- 口径 = 指标的计算定义：来源事件、过滤条件、统计维度与周期
- 痛点：产品与研发各说各的「成功率/转化率」对不上
- 【项目】沉淀产品/研发双视角口径文档 + 配套看数 SQL，对齐认知、看数可复用

## 六、告警与闭环

**Q11：告警怎么配置？怎么避免狼来了？**
- 阈值 + 持续时间（连续 N 分钟超阈值才触发）、分级（警告/严重）、按版本/接口维度分别设
- 收敛：聚合去重、通知限频；无主告警定期清理
- 【项目】告警配置由自研监控配置脚手架批量完成，替代逐项手工配置；数据监控 Skill 产出配置、人工审查后由脚手架执行

**Q12：线上问题的处理闭环？**
- 告警触发 → 影响面确认（版本/机型/接口维度）→ 止血优先（回滚/降级/开关）→ 根因定位 → 复盘
- 每次事故产出：补监控盲区、补用例、补预案——个案变防线
- 【项目】上线后主动发现业务放量导致的问题 2 个

**Q13：前端容灾了解吗？**
- 思路：永远留退路——CDN 多源备份、接口降级（缓存兜底/默认值）、功能开关快速止血
- 发布侧：灰度放量 + 一键回滚；大促/重要版本冻结窗口
