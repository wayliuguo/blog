# 面试题 · 浏览器与网络（全覆盖版）

> 前端面试高频基础题，与简历结合点标【项目】。

## 一、浏览器渲染

**Q1：从输入 URL 到页面展示的完整过程？（必考）**
- URL 解析 → DNS（缓存→递归查询）→ TCP 三次握手 → TLS 握手（https）→ HTTP 请求响应
- HTML 解析建 DOM（遇到 CSS 建 CSSOM，JS 阻塞解析除非 defer/async）→ 渲染树 → 布局 → 分层绘制 → 合成显示
- 优化切口全在这条链上（详见性能优化文档）

**Q2：重排、重绘、合成？**
- 改几何 → 重排（布局重算）→ 重绘 → 合成；只改颜色 → 重绘；transform/opacity → 只合成（GPU，最高效）
- 动画优先 transform/opacity；高频滚动事件避免同步布局（读写分离）

**Q3：script 标签 async / defer / module 的区别？**
- 默认：下载+执行都阻塞 HTML 解析
- defer：并行下载，DOM 解析完按序执行（DOMContentLoaded 前）；async：下载完立即执行，顺序不保证
- module：默认 defer 语义，严格模式 + ESM

**Q4：事件机制：冒泡、捕获、委托？**
- 三阶段：捕获（window→target）→ 目标 → 冒泡；addEventListener 第三参控制阶段
- 委托：父元素统一监听利用冒泡，省监听器、天然支持动态子元素；stopPropagation 阻断传播
- 事件循环关系：事件回调是宏任务（派发后进队列）

## 二、存储

**Q5：cookie / localStorage / sessionStorage / IndexedDB？**
- cookie：4KB、每次请求携带（主用于服务端会话；加 HttpOnly/Secure/SameSite）
- localStorage：5-10MB、持久、同源共享；sessionStorage 会话级、标签页隔离
- IndexedDB：大容量结构化存储（离线缓存）；Token 存哪：localStorage（XSS 风险）vs cookie HttpOnly（CSRF 面）——按威胁模型选

## 三、HTTP 协议

**Q6：常见状态码？**
- 200/201/204；301/302（永久/临时跳转，SEO 区别）、304（协商缓存命中）
- 400 参数错、401 未认证、403 已认证无权限、404、409 冲突、429 限流
- 500 服务器错、502/504（网关错误/上游超时）——【项目】解析类接口限流返回 429

**Q7：HTTP 缓存机制？（必考）**
- 强缓存：Cache-Control（max-age/no-cache/no-store/private）> Expires；不发请求
- 协商缓存：If-None-Match/ETag（内容指纹，优先）与 If-Modified-Since/Last-Modified；命中回 304
- 实践：html 用 no-cache，带 hash 的静态资源长缓存

**Q8：HTTP/1.1 → /2 → /3 演进？**
- 1.1：keep-alive 复用连接但应用层队头阻塞、文本协议、头部冗余
- 2：二进制分帧 + 多路复用（并行流）+ HPACK 头压缩；TCP 层队头阻塞仍在
- 3：QUIC（UDP）——连接迁移、0-RTT、流级独立重传根治队头阻塞

**Q9：HTTPS 握手原理？**
- TLS：非对称（ECDHE）协商出对称密钥 + 证书链验证身份 → 之后对称加密通信
- 防窃听（加密）、防篡改（MAC）、防冒充（证书）；抓包工具能看明文是因为装了根证书做中间人

## 四、跨域与安全

**Q10：同源策略与跨域方案？**
- 同源 = 协议+域名+端口全同；限制 DOM/cookie/接口访问
- CORS：简单请求直发；非简单（自定义头/PUT 等）先 OPTIONS 预检——服务端配 Access-Control-Allow-Origin/Headers/Methods 与 credentials
- 开发期 devServer proxy / Nginx 反向代理（同源化）；JSONP 是历史方案（只 GET、有注入风险）
- 【项目】NestJS enableCors 配置白名单来源

**Q11：XSS 攻击与防御？**
- 存储型/反射型/DOM 型：注入脚本在用户浏览器执行
- 防御：输出转义（默认不信任 HTML）、CSP 限制脚本来源、HttpOnly cookie 防 token 窃取、避免 v-html 渲染用户输入
- 【项目】富文本/用户输入一律转义或白名单过滤后再渲染

**Q12：CSRF 攻击与防御？**
- 伪造用户请求（借用浏览器自动带 cookie）；用户不知情
- 防御：CSRF token、SameSite=Strict/Lax cookie、校验 Referer/Origin、敏感操作二次确认
- 对比：XSS 偷信任执行代码，CSRF 借身份发请求——防御思路不同

**Q13：点击劫持？**
- 透明 iframe 覆盖诱导点击；防御：X-Frame-Options DENY / CSP frame-ancestors
