# 面试题 · 性能优化（全覆盖版）

> 高频常考为主，简历结合点标【项目】。红线：不编造「快 X%」对比数字；接口治理口径 = 缓存逐接口传参配置 + 请求标记位竞态 + 1 前置 4 并行；不用「容器预取」表述。

## 一、指标与测量

**Q1：核心性能指标有哪些？达标值？**
- LCP ≤ 2.5s（最大内容绘制）；INP ≤ 200ms（交互响应，取代 FID）；CLS ≤ 0.1（视觉稳定）
- 辅助：FCP、TTFB、TBT（长任务阻塞总时长）
- 采集：web-vitals 库 / PerformanceObserver，真实用户监控（RUM）优先于实验室工具

**Q2：怎么定位性能问题？**
- 先测量后优化：监控分机型/网络/版本下钻 → Performance 面板看长任务与布局抖动 → Network 看瀑布与阻塞
- 【项目】白屏、接口成功率与耗时进监控看板，优化前先确认瓶颈在首屏链路

## 二、网络与缓存（常考重点）

**Q3：强缓存和协商缓存的区别？**
- 强缓存：Cache-Control（max-age / no-cache / no-store / private / public）优先于 Expires；命中不发请求
- 协商缓存：no-cache 时带 If-None-Match（ETag）/ If-Modified-Since 问服务器，未变回 304
- 实践：html 用 no-cache，静态资源带 hash + 长缓存——改版本即换 URL，缓存精准失效

**Q4：CDN 的原理？**
- 就近返回：DNS（CNAME）把请求调度到边缘节点；节点有缓存直接回，没有则回源并缓存
- 收益：降低 RTT 与源站压力；注意：命中率和缓存刷新（主动 purge）、回源风暴

**Q5：HTTP/2 解决了什么？**
- 多路复用：一个 TCP 连接并行多请求，解决 HTTP/1.1 队头阻塞（应用层）
- 头部压缩 HPACK、二进制分帧、服务端推送（实际收益有限）
- 残留：TCP 层队头阻塞 → HTTP/3 QUIC（UDP）

**Q6：preload / prefetch / dns-prefetch / preconnect 的区别？**
- preload：当前页关键资源提前高优加载（字体、首屏图）；prefetch：下一跳可能用到的低优空闲加载
- dns-prefetch / preconnect：提前 DNS / 建 TLS 连接，第三方域名收益大

**Q7：从输入 URL 到页面展示，发生了什么？（性能视角）**
- DNS → TCP/TLS 握手 → 请求响应 → HTML 解析建 DOM/CSSOM → 渲染树 → 布局 → 绘制 → 合成
- 优化切口就藏在这条链上：减少 RTT（CDN/缓存）、关键资源小而早、不阻塞解析的脚本（defer/async）

## 三、加载与资源

**Q8：首屏优化清单？**
- 链路：请求编排——关键数据前置、并行化，非关键接口不阻塞渲染
- 资源：路由分包、组件库按需（Vant）、图片压缩/懒加载/webp、关键 CSS 内联、JS defer
- 渲染：骨架屏/占位（防 CLS）、预渲染或 SSR（内容型页面）
- 【项目】首屏串行改「1 前置 + 4 并行」（Promise.all），主信息先渲染；缓存命中直接返回减少重复请求

**Q9：懒加载的原理？**
- 图片：loading="lazy" 或 IntersectionObserver 进入视口再赋 src；路由组件 () => import() 动态导入
- 注意占位尺寸，避免加载后跳动（CLS）

**Q10：白屏的原因和排查？**
- JS 错误中断渲染 / 关键资源加载失败 / 接口阻塞 / 根节点挂载异常
- 手段：监控白屏检测 + 错误上报归因；防御：错误边界、资源多源兜底、非关键接口空值兜底
- 【项目】非关键接口异常不阻塞渲染，主流程始终可用

## 四、运行时

**Q11：重排（reflow）和重绘（repaint）？**
- 改几何（宽高位置）→ 重排 → 必然重绘；只改视觉（颜色）→ 重绘；合成层动画（transform/opacity）两者都免
- 减少方式：批量读写 DOM（避免读写交叉强制同步布局）、class 批量切换、will-change 提升合成层

**Q12：防抖和节流的原理与场景？**
- 防抖：停触发 N ms 后执行一次（搜索联想、resize 完成）；节流：每 N ms 最多一次（scroll、拖拽）
- 本质都是控制事件处理频率；注意销毁时清理定时器

**Q13：长列表 / 大数据渲染？**
- 分页 / 滚动加载优先；真长列表用虚拟滚动：只渲染可视区 + 缓冲（起止索引 + 容器总高 + transform 偏移）
- 大数组不做深度响应式（shallowRef/Object.freeze）；重计算移出主线程（Web Worker）

**Q14：Web Worker 什么时候用？**
- 大计算（解析、加解密、图像处理）与 UI 抢主线程时；限制：无 DOM、通信靠 postMessage（可 Transferable 零拷贝）

**Q15：Vue 运行时卡顿排查？**
- Performance 找长任务 → Vue devtools 看组件渲染耗时 → 定位不必要的深度 watch / 全量列表 diff
- 【项目】组件拆分收敛更新范围，Vue3 靶向更新，表单联动不再大范围重渲染

## 五、架构与验证

**Q16：SSR / CSR / 预渲染怎么选？**
- CSR：交互型应用默认；预渲染：静态落地页/营销页；SSR：内容型、SEO 与首屏敏感
- 代价与收益对齐：SSR 增加服务端与同构复杂度，不是默认选项

**Q17：优化效果怎么验证？**
- 同口径前后对比（监控 RUM 数据、分机型分网络看分布不看均值）；灰度对比防季节因素
- 【项目】结论都用监控口径的结构性表述，不引用无实测依据的百分比
