## 4. 子项目 B：12 个总结两级树改造

### 4.1 目标形态（对齐 node 基准，如 `node/运行环境/总结.md`）

```
## 知识主线        ← 保留现有内容不动
## 分篇知识点
### <篇名>        ← 保留现有 ### 标题
- **概念域**      ← 保留现有第一层条目标题
  - **知识点**：作用 + 用法概览一句话（展开）
## 参考           ← 保留现有内容不动
```

样板（TypeScript「内置工具类型」改造后）：

```
- **内置工具类型**
  - **Partial<T>**：把 T 所有属性变为可选，常用于表单局部更新
  - **Pick<T, K>**：从 T 中挑出 K 指定属性组成新类型
  - **Omit<T, K>**：从 T 中剔除 K 属性
  - **Record<K, V>**：以 K 为键名、V 为值类型构造对象类型
  - **Readonly<T>**：所有属性只读
  - **ReturnType<T>**：取函数返回值类型，实现思路是条件类型 + infer
  - **Awaited<T>**：解包 Promise 得到最终值类型
```

### 4.2 规则

- 骨架 = 保留 `## 知识主线`、`### <篇名>`、`## 参考` 及现有第一层 `- **X**` 条目标题；把每条后的「一句话」展开为缩进 2 空格的第二层 `  - **知识点**：作用 + 用法概览`。
- 第一层概念域有信息量（不能是「模块系统」这类空壳）；若现有第一层条目标题是空壳（无法承载子知识点），由子代理按正文提炼为有信息量的概念域；知识点覆盖该概念域下每个工具/子概念，逐个给出作用与用法概览。
- 严格并列项（如工具类型清单）用子弹逐条列，不使用 `1. 2.` 编号（与 node 形态一致）。
- 最多三级、每级缩进 2 空格、同层 ≤ 8 条（超过则拆分概念域）。

### 4.3 执行方式（方案 B1）

- **脚本只做机械活**：子项目 A 全部动作 + 子项目 C 去编号；不碰总结内容。
- **并行子代理填充**：每代理处理 1-2 个模块，输入 = 模块正文各篇 + 现有 `总结.md` + node 形态模板，输出 = 改造后的 `总结.md`。12 个模块分批并行。
- 子代理提示词固定输出模板（见 4.1/4.2），保证 12 个模块结构强一致。
