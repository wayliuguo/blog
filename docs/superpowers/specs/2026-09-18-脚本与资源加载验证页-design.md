## 3. 新增文件（`code/site/script-loading/`）

| 文件 | 作用 |
| --- | --- |
| `order.html` | 执行顺序验证页。加载 `defer` 脚本 a/b + `async` 脚本 c/d（c 带 `?delay=800`）；页面内「执行日志」面板按时间戳记录每段脚本执行时刻与 `DOMContentLoaded` 时刻，直观显示 defer 按文档顺序、async 按下载完成顺序乱序。内联样式，自闭环 |
| `blocking.html` | 阻塞对比验证页。三个 iframe（同步/defer/async 各一）加载同一份 `slow.js?delay=2000`；各对照页在可见内容之后的内联脚本把「内容可见时刻」`postMessage` 上报给本页，表格实时显示：同步 ≈2s（白屏），defer/async ≈0ms（立即渲染）。附「重新测量」按钮 |
| `first-screen.html` | 首屏/白屏验证页。并排三个 iframe——`first-screen-sync.html`（head 同步 `slow.js?delay=2000`）vs `first-screen-defer.html` / `first-screen-async.html`（同脚本 `defer`/`async`）；配「重新加载」按钮同时刷新，附观察要点说明 |
| `first-screen-sync.html` | 对照页：一段可见内容 + head 内同步 `slow.js?delay=2000`；内容后的内联脚本上报「内容可见时刻」（name=sync） |
| `first-screen-defer.html` | 对照页：同内容 + head 内 `defer` 版 slow 脚本（name=defer） |
| `first-screen-async.html` | 对照页：同内容 + head 内 `async` 版 slow 脚本（name=async） |
| `order-a.js` / `order-b.js` | defer 脚本，执行时向日志面板追加「defer-a/defer-b」及时间戳 |
| `order-c.js` / `order-d.js` | async 脚本，同上（order-c 从页面以 `?delay=800` 引入） |
| `slow.js` | 慢脚本（配合 `?delay=` 使用），执行时向父页面上报执行时刻（name 取 `window.__LOAD_NAME`） |

要点：

- 脚本通过 `window.__log(msg)`（在页面 head 定义，含缓冲兜底）向日志面板追加记录，时间戳用 `performance.now().toFixed(1)`。
- `order.html` 顶部给出一行预期结论文字，页面加载后日志面板即展示结果。
- 「内容可见时刻」= 对照页可见内容之后那行内联脚本的执行时刻（内容能被解析/渲染的时间）；`blocking.html` 与 `first-screen.html` 都复用这三个对照页。

## 4. server.js 改动

`safePath` 解析 URL 时同时解析 `?delay=ms` 查询参数：`decodeURIComponent(url.split('?')[0])` 已剥离查询串，需在 `req.url` 上单独提取 delay 值；命中时 `setTimeout` 延迟发送响应，并附加 `Cache-Control: no-store`（模拟场景禁缓存，保证「重新测量/重新加载」真的重新下载）。其余逻辑不动。
