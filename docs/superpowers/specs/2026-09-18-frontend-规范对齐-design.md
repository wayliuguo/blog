# frontend 对齐《文档组织规范》设计

> 日期：2026-09-18
> 关联：仓库根 `文档组织规范.md`（通用规范，node 已全量落地）、`frontend/`（基础 + 进阶 两级，52 篇正文）

## 1. 背景与目标

仓库根目录新增了**通用**《文档组织规范》（适用于 `ai/ frontend/ interview/ node/`，node 已按它全量落地）。用户要求按该规范对 `frontend/` 进行处理，目标是消除 frontend 与规范的**结构性差距**，使其与 node 板块形态一致。

### 已确认决策（brainstorming 澄清结果）

- **范围**：仅结构性大项（去编号 + 侧边栏/导航 + 内部引用 + 代码出处标注 + 面试题格式）。
- **目录层级**：保留「基础/进阶」两级，模块目录去编号（`基础/HTML 基础`、`进阶/TypeScript`…）。
- **面试题**：保留每模块一份，格式对齐规范（四段组织 + 每题 结论/原理/边界/追问 四条）。
- **教学代码**：正文无配套脚本的代码块统一加 `> 示意片段（无配套脚本）`；有配套脚本的加 `> 摘自 …`。

### 3.3 小节标题去号（全部正文）

`## 1. 标签的三种形态` → `## 标签的三种形态`。正则 `^##\s+\d+\.\s+` → `## `（注意只匹配 ## 级，不动 ### 及以下）。

### 3.4 侧边栏与导航

- `.vitepress/config/frontend.js`：所有 `link` 的 frontend 路径去编号（`/frontend/基础/HTML%20基础/HTML%20语义化与结构`…），`text` 不动。
- `.vitepress/config/nav.js`：frontend 入口 link 同步去编号。
- 其他板块（nav.js 的 node 入口等）不受影响。

### 3.5 内部引用

- 全文把「第 0X 篇」→「第 X 篇」（如「第 01 篇」→「第 1 篇」），包括面试题 `（第 01 篇）` 出处标注。
- 指向 frontend 内部 md 的 markdown 链接路径去编号（与文件名重命名一一对应）。
- 篇间正文引用若硬编码了编号路径，一并改为去编号路径；「见第 X 篇」语义不变。

### 3.6 正文代码出处标注（52 篇逐篇）

- 有配套脚本的代码块：块上一行 `> 摘自 ./code/…（运行：…）`（按 node 实例格式）。
- 无配套脚本的代码块（frontend 绝大多数教学片段）：块上一行 `> 示意片段（无配套脚本）`。
- 同一页面多处代码块都要标注；已带标注的跳过。

### 3.7 面试题格式对齐（13 模块）

- 分段统一为四段：`## 一、基础概念` / `## 二、机制与原理` / `## 三、排障与选型` / `## 四、场景设计题`（现有自定义段名并入最贴近的一段）。
- 每题删去「场景」一条，保留 `结论 / 原理 / 边界 / 追问` 四条，顺序不变。
- 题号与出处 `（第 X 篇）` 保留（X 去 0）。

## 4. 实施分工

1. **临时脚本**（Node，一次性，执行后删除）：完成 3.1/3.2 目录与文件重命名（git mv）、3.3 小节去号、3.4 侧边栏/导航路径、3.5 内部引用去 0 与链接路径（全仓库 grep 范围：`.vitepress/` + `frontend/`）。
2. **并行子代理（3 个）**：按模块分组逐篇执行 3.6 代码标注（读文件、核对配套脚本、加标注）与 3.7 面试题格式；每组完成后自查 grep。
3. **校验**（见 §5）→ prettier（指定文件）→ build。

## 5. 验证标准（验收）

1. `grep` 断言：`frontend/` 下目录与文件名无 `\d{2}-` 前缀（git ls-files 核验）；小节无 `^## \d+\.` 残留。
2. `.vitepress/config/*.js` 无 `/frontend/.*\d{2}-` 残留路径；`nav.js` frontend 链接可用。
3. 全文（frontend + 配置）无「第 0X 篇」残留；内部链接无 404（build 兜底）。
4. 抽查每模块 ≥1 篇：每个 ``` 代码块上方有 `> 摘自` 或 `> 示意片段` 标注（grep 统计标注块数 ≥ 代码块数 * 0.95，允许表内代码块例外）。
5. 13 份面试题均为四段 + 每题四条（grep `### Q\d+` 行后无 `- \*\*场景\*\*`）。
6. `npx vitepress build --outDir .vitepress/dist-check` 通过、无 404 警告（构建因宿主安全删除保护，绕行 dist-check）。
