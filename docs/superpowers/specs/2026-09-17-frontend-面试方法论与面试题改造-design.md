# 前端文档：面试方法论独立模块与模块面试题改造 设计

> 日期：2026-09-17
> 关联：`frontend/`（基础 + 进阶 两级目录，VitePress 博客）、`.vitepress/config/frontend.js`

## 1. 背景与目标

用户对 `frontend/` 现有 12 个模块面试题页提出 3 项需求：

1. **五步答题法重复**：每个模块面试题页都写了一遍「五步答题法」（`## 0.` 表格 + 示例），11 篇重复。
2. **答题方法独立成模块**：把答题方法抽成一个独立模块（如 HTML 基础那样独立），与 node 侧「面试方法论」一致。
3. **每题按五步法给答案**：模块面试题只列了题目（`## 1. 高频自测题（分级）` checkbox 无答案），需要每题都按五步法作答。

### 已确认决策（brainstorming 澄清结果）

- **对齐 node 形态**：面试题页采用 node 面试题形态——引言块引用 → 按知识主题分节（`## 一、`）→ `### Q#` 每题五条子弹（结论/原理/边界/追问/场景），无五步法表格、无分级 checkbox。
- **独立「面试方法论」模块**：与 node 一致，frontend 新建独立导航分组 + 独立目录（`frontend/12-面试方法论/`）。
- **按知识主题分节**：11 篇正文题目按知识点重排分节（初级/中级/高级自然融合，同主题由浅入深），保留 `（第 XX 篇）` 出处标注。
- **方案 B：逐篇全人工重写**：不用脚本/代理，主代理逐篇完整重写 11 篇面试题 + 新增方法论模块。

## 2. 现状盘点（探索阶段实测）

- **12 个 frontend 模块**：基础 6（HTML/CSS/JS 核心/网络与浏览器/React/Vue）+ 进阶 6（TypeScript/工程化/交付质量/框架原理/性能监控/工程实践），每模块含 文章 + `总结.md` + `面试题.md`。
- **11 篇面试题页结构**（框架原理篇除外）：
  `# 模块面试题 · XX` → 引言块引用 → `## 0. 五步答题法`（步骤表 + 该模块示例）→ `## 1. 高频自测题（分级）`（初级/中级/高级 checkbox，仅列题无答案）→ `## 2. 重点题精答（五步法）`（`### Q#` + 五条子弹，5-7 题）。
- **量化**：`## 0.` 表格 11 处；分级 checkbox 题 178 条（每文件 14-18 题）；精答 `### Q#` 77 条（每文件 5-10 题）；checkbox 与精答有重叠，去重后每篇约 15-20 题。
- **node 面试题形态基准**（`node/01-运行环境/面试题.md`）：引言（用法说明 + 题目来源）→ `## 一、基础概念` 主题分节 → `### Q1: "Node.js 是单线程的"这个说法准确吗？（第 01 篇）` + 结论/原理/边界/追问 子弹（部分题含场景；node 篇个别题四步）。**frontend 侧统一五步**：每题固定五条子弹，以 `frontend/进阶/04-前端框架原理/面试题.md`（结论/原理/边界/追问/场景）为内部基准。
- **node 方法论模块基准**（`node/12-面试方法论/01-面试方法论.md`）：一、五步答题法（定义 + 示例）→ 二、追问链（按主题组织）→ 三、项目包装（STAR）→ 四、面试避坑清单 → 五、自我介绍模板 → 六、量级数据参考表 → 结尾「这套体系怎么用来准备面试」模块对应表。
- **frontend 导航**（`.vitepress/config/frontend.js`）：基础 + 进阶两组，末尾无独立方法论分组；node 侧末尾有 `{ text: '面试方法论', collapsed: true, items: [{ text: '01-面试方法论', link: '/node/12-面试方法论/01-面试方法论' }] }`。
- **框架原理篇**（`frontend/进阶/04-前端框架原理/面试题.md`）：已是 node 形态（`## 一、React 原理`/`## 二、Vue3 原理` 分节，10 题全部作答），无 `## 0.` 表格。

## 3. 独立模块「面试方法论」（新增）

新建 `frontend/12-面试方法论/01-面试方法论.md`，结构对齐 node 版、内容全部前端化：

| 章节 | node 版 | frontend 版 |
| --- | --- | --- |
| 一、五步答题法 | 示例 = 事件循环 | 示例换前端题（如「闭包」「React 为什么需要 key」） |
| 二、追问链 | 8 条按后端主题 | 按前端主题组织（JS 核心 / 网络与浏览器 / React / Vue / 工程化 / 性能与质量） |
| 三、项目包装 | STAR + 后端订单项目 | STAR + 前端项目示例（商城 H5 / 中台系统） |
| 四、面试避坑清单 | 后端向 | 前端向（含首屏渲染、图片优化、包体积等坑） |
| 五、自我介绍模板 | 后端版 | 前端版（1 分钟 / 3 分钟） |
| 六、量级数据参考表 | Node 运行时默认值 | 前端硬数字：LCP < 2.5s、FCP < 1.8s、CLS < 0.1、16.7ms 帧预算、gzip 包体积参考、HTTP/2 多路复用连接数等 |
| 结尾 | 6 模块对应表 + 用法循环 | 12 个 frontend 模块 → 各面试题页对应表 + 用法循环（自测 → 回正文补 → 五步重写 → 追问链压三层） |

导航：`.vitepress/config/frontend.js` 末尾（进阶组之后）追加：

```js
{
    text: '面试方法论',
    collapsed: true,
    items: [{ text: '01-面试方法论', link: '/frontend/12-面试方法论/01-面试方法论' }]
}
```

## 4. 11 篇面试题正文改造（对齐 node 形态）

改造范围：11 篇（基础 6 + 进阶 5）；框架原理篇仅引言微调、正文不动。

### 4.1 每篇目标结构

```markdown
# 模块面试题 · XX

> 用法：先遮住答案自测，再对照参考；每题以一句能背下来的判断句打头，可直接当复习清单用。
> 答题节奏遵循「面试方法论」的五步答题法（链接到独立模块）。
> 题目来源：各篇正文原有 `## 面试题`（口径与新版正文一致）与原附录题库去重合并。

## 一、<知识主题>

### Q1: <题目>（第 XX 篇）

- **结论**：一句判断句
- **原理**：机制讲解
- **边界**：局限/代价
- **追问**：预判下一句
- **场景**：实际场景
```

### 4.2 具体动作

1. 删除 `## 0. 五步答题法` 整段（迁至方法论模块，不再逐篇重复）。
2. 删除 `## 1. 高频自测题（分级）` checkbox 列表——每题转成有答案的 `### Q#`。
3. `## 2. 重点题精答` 内容并入新结构，与 checkbox 题合并**去重**（同题保留精答的五步内容，检查与正文口径一致）。
4. 全部题目按知识主题重排分节（同主题内由浅入深），保留 `（第 XX 篇）` 出处标注。
5. 引言块引用指向「面试方法论」模块链接。
6. 每题**固定五条子弹**，顺序为 结论/原理/边界/追问/场景（与框架原理篇内部基准一致）；「结论」必须是一句能背下来的判断句。
7. **文末附加段（严格 node 形态）**：`## 3. 追问链`、`## 4. 场景设计题`、`## 5. 面试口径` 三段移除——场景设计题转为一条综合 Q（五步作答，归入相应主题节）；追问链由方法论模块「二、追问链」覆盖；面试口径由方法论模块「三、项目包装（STAR）」覆盖。不新增 `## 参考` 段。

### 4.3 框架原理篇

- 正文与题目不动（已是 node 形态、10 题全部作答）。
- 仅引言补一句指向「面试方法论」模块的引用，保持 12 篇口径一致。

### 4.4 去重后体量

每篇约 15-20 题、11 篇合计约 180 题，每题五条子弹，全人工撰写。

## 5. 实施方式（方案 B：逐篇全人工重写）

- 不使用临时脚本、不启用并行子代理；主代理按模块顺序逐篇完整重写 11 篇 `面试题.md`。
- 顺序建议：先建方法论模块与导航（引用目标先存在），再按基础 → 进阶逐篇改造，最后统一校验。
- 每篇重写时：通读该模块 `总结.md` 与正文各篇（取 `## 面试题` 题源与知识点），合并 checkbox 与精答题，去重后按主题分节作答。
- 提交：单次 commit（`frontend/` + `.vitepress/` 相关文件），提交前先 `prettier --write .` 使 pre-commit 钩子 no-op。

## 6. 验证标准（验收）

1. grep 复查：11 篇均无 `## 0. 五步答题法`、无 `## 1. 高频自测题`、无 `- [ ]` checkbox 残留。
2. 每篇均有 `## 一、` 主题分节；`### Q#` 每题含 结论/原理/边界/追问/场景 五条子弹且结论为判断句。
3. 12 篇引言均引用「面试方法论」模块链接。
4. 新增 `frontend/12-面试方法论/01-面试方法论.md` 存在，`frontend.js` 导航注册成功（build 无 404）。
5. `prettier --write .` 通过 → `npx vitepress build` 通过、无 404 警告。
6. 提交前检查：未触碰 node/ 目录未提交改动。

## 7. 非目标

- 不改 node 侧任何内容（node 面试题、方法论模块、导航均不动）。
- 不新增模块内容：方法论模块只做这一页，不再拆分多页。
- 不改 12 个模块 `总结.md`（`## 参考` 中的面试题链接继续有效）。
- 不为 11 篇新增题目数量目标：题目数由「现有 checkbox + 精答去重」决定，不额外扩题。
