# 前端文档：内容去层化与总结统一 设计

> 日期：2026-09-16
> 关联：`frontend/`（基础 + 进阶 两级目录，VitePress 博客）

## 1. 背景与目标

用户对 `frontend/` 现有文档提出 4 类问题，需在本任务中一并解决：

1. **标题冗余**：如「HTML 语义化与结构（入门→进阶→实战→最小实现原理）」、「级别：初级（含进阶）」、「本章掌握一切网页的骨架。按四层推进：…」等描述。
2. **四层框架不再使用**：不需要按「入门、进阶、实战、最小实现」推进；**基础章节只需入门和用法**。
3. **面试自测对照**：去除每章内的面试自测内容。
4. **小结统一**：「小结」与「本节小结」重复，只保留一个；且总结不是"本章讲了什么"的概括性复述，而是**知识的结构性总结**（层级树）。

### 已确认决策（brainstorming 澄清结果）

- 四层推进/级别头部：**全部章节（基础+进阶共 12 章）统一去掉**。
- 「级别：XXX」块引用与「按四层推进：」介绍段：**直接整体删除**，不加替代语。
- 面试内容：`## N. 面试自测对照` 内嵌题块 与 `## 面试衔接` 引导段 **两类都删**（`面试题.md` 文件保留）。
- 每篇保留的单一总结段：**统一为 `## 总结`**，内容为结构性知识树。
- 实施方案：**方案 A**（脚本机械清理 + 并行子代理重写总结树）。
- 导航句（「进入下一节 `NN-xxx`」等）：**一并删除**（含 HTML 2 篇独立句、面试衔接段内嵌句、CSS 05 行内「（见下一节）」）。

- 「最小实现：」小节标题带编号前缀（如 `## 十、最小实现：用 Demo 验证原理`）或 `###` 级，均按统一规则处理。
- 「实战」类标题（如 `## 实战：用 Redux 管理用户信息`、`## 【实战】开发 List 页`、`## 路由实战`）**保留**，不属于删除范围。
- 工程化成熟度 L1-L5 模型（「自我评估清单」）是独立内容，**保留**。
- 模块级 `总结.md`（12 个）与 `面试题.md`（12 个）主体**不动**，仅修正 1 处过时提及（见 §5）。

## 3. 清理规则（脚本删除清单）

对 48 篇知识文章统一执行（脚本对不存在的模式自动跳过）：

1. 标题后缀：`（入门→进阶→实战→最小实现原理）` 从 `#` 标题剥离。
2. `> 级别：XXX` 块引用行及其后空行。
3. 「本章…按四层推进：…所有原理都自足可懂，不依赖后续章节。」整段（含前后空行）。
4. `# 第X层 · XXX` 标题 + 紧随的「目标：…」行 + `> **入门验收**：…` / `> **实战验收**：…` 引用块。
5. `## N. 面试自测对照` 标题 + 其下 ```text 题块。
6. `## 面试衔接` 标题 + 其下段落（含「进入下一节…」尾句）。
7. `##/### 最小实现：…` 小节：从标题到下一个同级或更高级标题前，整体删除（含内容与代码）。
8. `## 小结` / `## 小结：XXX` / `## 本节小结` 标题 + 其下内容。
9. 导航句：独立「下一节 `NN-xxx` 讲…」行、行内「（见下一节）」。

> 删除后若文末残留孤立 `---` 分隔线或多余空行，一并清理。

## 4. 总结树规范（每篇唯一的 `## 总结`）

- 位置：每篇知识文章**末尾**，标题为 `## 总结`。
- 内容：**结构性知识树**——缩进列表（`-` 逐级缩进），根为篇核心概念，向下展开到知识点叶子，覆盖全篇内容；不是复述正文的概括段落。
- 参考示例（用户给定）：

```markdown
## 总结

- 数据类型
  - 基本类型
    - xxx
  - 引用类型
- xxx
```

- 每篇恰好一个 `## 总结`；无「小结/本节小结/面试衔接/最小实现」残留。
- 不在总结后追加「下一节」导航句（已确认删除）。

## 5. 保留与联动修改
