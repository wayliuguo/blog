## @Module 装饰器

`@Module` 是 NestJS 组织代码的基本单元，每个应用至少有一个根模块。

```typescript
import { Module } from '@nestjs/common'

@Module({
    imports: [],      // 导入其他模块
    controllers: [],  // 该模块下的控制器
    providers: [],    // 该模块下的服务/提供器
    exports: []       // 导出给其他模块使用的提供器
})
export class AppModule {}
```

## 模块化组织代码

```typescript
// users.module.ts
@Module({
    controllers: [UserController],
    providers: [UserService],
    exports: [UserService]  // 导出 UserService 以便其他模块使用
})
export class UsersModule {}

// app.module.ts
@Module({
    imports: [UsersModule],  // 导入用户模块
    controllers: [AppController],
    providers: [AppService]
})
export class AppModule {}
```

## 模块共享

通过 `exports` 导出 Provider，其他模块导入后即可使用：

```typescript
// 数据库模块：提供数据库连接
@Module({
    providers: [DatabaseService],
    exports: [DatabaseService]  // 导出 DatabaseService
})
export class DatabaseModule {}

// 用户模块：使用数据库服务
@Module({
    imports: [DatabaseModule],  // 导入数据库模块
    providers: [UserService],
})
export class UsersModule {}
```

## 全局模块

使用 `@Global()` 将模块标记为全局，它的 Provider 在所有模块中可用，无需导入：

```typescript
@Global()
@Module({
    providers: [ConfigService],
    exports: [ConfigService]
})
export class ConfigModule {}
```

> 注意：全局模块只用于真正需要全局共享的模块（如配置、日志），不要滥用。

## 动态模块

动态模块允许在导入时传入配置参数，广泛用于库模块：

```typescript
// 定义动态模块
@Module({})
export class DatabaseModule {
    static forRoot(options: DatabaseOptions): DynamicModule {
        return {
            module: DatabaseModule,
            providers: [
                {
                    provide: 'DATABASE_OPTIONS',
                    useValue: options
                },
                DatabaseService
            ],
            exports: [DatabaseService]
        }
    }
}

// 使用时传入配置
@Module({
    imports: [
        DatabaseModule.forRoot({
            host: 'localhost',
            port: 3306,
            database: 'myapp'
        })
    ]
})
export class AppModule {}
```

### forRoot vs forRootAsync

```typescript
// 同步配置
DatabaseModule.forRoot({ host: 'localhost', port: 3306 })

// 异步配置：从 ConfigService 读取配置
DatabaseModule.forRootAsync({
    imports: [ConfigModule],
    inject: [ConfigService],
    useFactory: (config: ConfigService) => ({
        host: config.get('DB_HOST'),
        port: config.get('DB_PORT')
    })
})
```

## 小结

- **@Module：组织代码的基本单元**
  - **四个字段**：`imports` 导入别的模块、`controllers` 挂控制器、`providers` 注册服务、`exports` 导出给别处用
  - **根模块有且只有一个**：其余模块从根模块的 `imports` 开始被递归挂载，这条递归链决定了模块可见性
- **模块共享的完整链条**
  - **注册 → 导出 → 导入**：提供方先 `providers` 注册再 `exports` 导出，使用方在 `imports` 里引入，三步缺一就报 DI 错
- **@Global() 全局模块**
  - **免导入即可用**：Provider 在所有模块里都能注入，只留给配置、日志这类真正全局的东西，不要滥用
- **动态模块**
  - **forRoot**：`static forRoot(options): DynamicModule` 让库在被导入时接收一份配置参数
  - **forRoot 与 forRootAsync**：同步直接传对象，异步用 `imports + inject + useFactory` 从 ConfigService 读配置
