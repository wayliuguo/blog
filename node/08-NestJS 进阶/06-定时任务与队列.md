# 定时任务与队列

> 定时任务（@Cron）和消息队列（Bull）是后端处理异步和延迟任务的常用方式。
> 承上：[模块与提供器](../07-NestJS%20入门/03-模块与提供器) —— 定时任务与队列都要注册成 Provider 并放进模块，先会组织 Module 才知道生产者/消费者该放哪
> 启下：[微服务架构](./07-微服务架构) —— 用 `Transport.TCP` 起一个微服务，并通过 `ClientProxy` 在网关里跨服务调用 `@MessagePattern` 方法

---

## 定时任务（@nestjs/schedule）

### 安装

```bash
npm install @nestjs/schedule
```

### 注册模块

```typescript
import { Module } from '@nestjs/common'
import { ScheduleModule } from '@nestjs/schedule'

@Module({
    imports: [ScheduleModule.forRoot()],
    providers: [TasksService],
})
export class AppModule {}
```

### 定义定时任务

```typescript
import { Injectable, Logger } from '@nestjs/common'
import { Cron, CronExpression } from '@nestjs/schedule'

@Injectable()
export class TasksService {
    private readonly logger = new Logger(TasksService.name)

    // 每天凌晨 2 点执行
    @Cron(CronExpression.EVERY_DAY_AT_2AM)
    handleDailyReport() {
        this.logger.log('生成昨日销售报表...')
        // 查询数据库 → 生成报表 → 发送邮件
    }

    // 每 10 分钟执行一次
    @Cron('*/10 * * * *')
    handleHealthCheck() {
        // 检查服务健康状态
    }

    // 延迟执行（相对时间，仅一次）
    @Timeout(5000)  // 5 秒后执行
    handleTimeout() {
        console.log('启动后 5 秒执行')
    }

    // 间隔执行
    @Interval(10000)  // 每 10 秒执行
    handleInterval() {
        console.log('每 10 秒执行一次')
    }
}
```

### 动态控制任务

```typescript
import { Injectable } from '@nestjs/common'
import { SchedulerRegistry } from '@nestjs/schedule'
import { CronJob } from 'cron'

@Injectable()
export class TaskManager {
    constructor(private schedulerRegistry: SchedulerRegistry) {}

    // 动态添加任务
    addCronJob(name: string, cronTime: string) {
        const job = new CronJob(cronTime, () => {
            console.log(`任务 ${name} 执行`)
        })
        this.schedulerRegistry.addCronJob(name, job)
        job.start()
    }

    // 停止任务
    stopJob(name: string) {
        const job = this.schedulerRegistry.getCronJob(name)
        job.stop()
    }

    // 获取所有任务
    getJobs() {
        return this.schedulerRegistry.getCronJobs()
    }
}
```

## 消息队列（@nestjs/bull）

### 安装

```bash
npm install @nestjs/bull bull
npm install -D @types/bull
```

### 注册模块

```typescript
import { Module } from '@nestjs/common'
import { BullModule } from '@nestjs/bull'

@Module({
    imports: [
        BullModule.forRoot({
            redis: {
                host: 'localhost',
                port: 6379,
            },
        }),
        BullModule.registerQueue({
            name: 'email',       // 队列名称
        }),
    ],
    providers: [EmailProcessor, EmailQueue],
})
export class QueueModule {}
```

### 生产者：发送任务

```typescript
import { Injectable } from '@nestjs/common'
import { InjectQueue } from '@nestjs/bull'
import { Queue } from 'bull'

@Injectable()
export class EmailQueue {
    constructor(@InjectQueue('email') private emailQueue: Queue) {}

    // 发送验证邮件
    async sendVerification(to: string, code: string) {
        await this.emailQueue.add('verification', {
            to,
            code,
        }, {
            attempts: 3,           // 最多重试 3 次
            backoff: 5000,         // 重试间隔 5 秒
            removeOnComplete: true,
        })
    }

    // 延迟发送（预约邮件）
    async scheduleEmail(to: string, content: string, delayMs: number) {
        await this.emailQueue.add('scheduled', {
            to,
            content,
        }, {
            delay: delayMs,        // 延迟执行
        })
    }
}
```

### 消费者：处理任务

```typescript
import { Processor, Process } from '@nestjs/bull'
import { Job } from 'bull'

@Processor('email')
export class EmailProcessor {
    @Process('verification')
    async handleVerification(job: Job<{ to: string; code: string }>) {
        const { to, code } = job.data
        console.log(`发送验证码 ${code} 到 ${to}`)
        // 调用邮件服务...
    }

    @Process('scheduled')
    async handleScheduled(job: Job<{ to: string; content: string }>) {
        console.log(`发送预约邮件到 ${job.data.to}`)
        // 调用邮件服务...
    }
}
```

## 生产场景对比

| 场景 | 方案 | 原因 |
|------|------|------|
| 每日报表生成 | `@Cron` | 固定时间执行，无需队列 |
| 发送验证码邮件 | Bull 队列 | 异步执行，失败自动重试 |
| 订单超时取消 | Bull 延迟任务 | 30 分钟不支付则取消 |
| 用户注册欢迎邮件 | Bull 队列 | 主流程不阻塞，异步发送 |
| 健康检查 | `@Interval` | 固定间隔，轻量级 |

## 小结

- **定时任务的注册与三类装饰器**
  - **`ScheduleModule.forRoot()` 是前提**：不导入这个模块，`@Cron` 装饰器不会注册任何任务，只是死标签
  - **`@Cron` 两种写法**：用 `CronExpression.EVERY_DAY_AT_2AM` 这类常量，或直接写 `'*/10 * * * *'` 表达式
  - **`@Timeout` 与 `@Interval` 的区别**：`@Timeout(5000)` 是只跑一次的延迟任务，`@Interval(10000)` 是按固定间隔重复执行
  - **`SchedulerRegistry` 动态管理任务**：`addCronJob` 加、`getCronJob(name).stop()` 停、`getCronJobs()` 列出全部
- **Bull 队列：生产者与消费者**
  - **注册**：`BullModule.forRoot({ redis: { host, port: 6379 } })` 配 Redis，再 `BullModule.registerQueue({ name: 'email' })` 建队列
  - **生产者**：`@InjectQueue('email')` 注入 `Queue`，用 `queue.add('verification', data, opts)` 投递任务
  - **消费者**：`@Processor('email')` 标类、`@Process('verification')` 标方法，回调参数是 `job`，任务载荷在 `job.data`
  - **重试与延迟选项**：`attempts: 3` 重试次数、`backoff: 5000` 重试间隔、`delay` 延迟执行、`removeOnComplete: true` 完成后清理记录
- **选型：定时任务还是队列**
  1. **固定时间点执行**：每日报表生成用 `@Cron`
  2. **固定间隔的轻量任务**：健康检查用 `@Interval`
  3. **异步且要失败重试**：发送验证码邮件、用户注册欢迎邮件用 Bull 队列，主流程不阻塞
  4. **延迟触发的业务动作**：订单 30 分钟不支付则取消，用 Bull 的延迟任务
