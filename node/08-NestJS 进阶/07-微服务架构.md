# 微服务架构

> NestJS 原生支持微服务架构，通过不同的传输层（TCP、Redis、RabbitMQ、Kafka 等）实现服务间通信。
> 承上：[模块与提供器](../07-NestJS%20入门/03-模块与提供器) —— 微服务本质是多模块拆分，先会组织 Module 才分得清 API 网关与各子服务

## 微服务架构概览

```
                    ┌──────────────┐
                    │  API 网关     │
                    │  (HTTP)       │
                    └──────┬───────┘
                           │
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
    ┌────────────┐  ┌────────────┐  ┌────────────┐
    │ 用户服务    │  │ 订单服务   │  │ 商品服务   │
    │ (TCP:3001)  │  │(TCP:3002)  │  │(TCP:3003)  │
    └────────────┘  └────────────┘  └────────────┘
```

## 创建微服务

```typescript
// microservices/user/src/main.ts
import { NestFactory } from '@nestjs/core'
import { MicroserviceOptions, Transport } from '@nestjs/microservices'
import { UserModule } from './user.module'

async function bootstrap() {
    const app = await NestFactory.createMicroservice<MicroserviceOptions>(
        UserModule,
        {
            transport: Transport.TCP,
            options: {
                host: '0.0.0.0',
                port: 3001,
            },
        },
    )
    await app.listen()
}
```

### 定义微服务控制器

```typescript
import { Controller } from '@nestjs/common'
import { MessagePattern, Payload } from '@nestjs/microservices'

@Controller()
export class UserController {
    @MessagePattern({ cmd: 'get_user' })
    getUser(@Payload() data: { id: number }) {
        // 查询用户信息
        return { id: data.id, name: '张三', email: 'zhangsan@example.com' }
    }

    @MessagePattern({ cmd: 'create_user' })
    createUser(@Payload() data: { name: string; email: string }) {
        // 创建用户
        return { id: 1, ...data }
    }
}
```

## API 网关（TCP 客户端）

```typescript
// api-gateway/src/user/user.controller.ts
import { Controller, Get, Post, Body, Inject } from '@nestjs/common'
import { ClientProxy } from '@nestjs/microservices'

@Controller('users')
export class UserController {
    constructor(
        @Inject('USER_SERVICE') private userClient: ClientProxy,
    ) {}

    @Get(':id')
    async getUser(id: number) {
        // 通过 TCP 调用用户微服务
        return this.userClient.send(
            { cmd: 'get_user' },
            { id },
        )
    }
}
```

### 客户端连接配置

```typescript
// api-gateway/src/app.module.ts
import { Module } from '@nestjs/common'
import { ClientsModule, Transport } from '@nestjs/microservices'

@Module({
    imports: [
        ClientsModule.register([
            {
                name: 'USER_SERVICE',
                transport: Transport.TCP,
                options: { host: 'localhost', port: 3001 },
            },
            {
                name: 'ORDER_SERVICE',
                transport: Transport.TCP,
                options: { host: 'localhost', port: 3002 },
            },
        ]),
    ],
    controllers: [UserController],
})
export class AppModule {}
```

## RabbitMQ 传输

```typescript
// 微服务端
const app = await NestFactory.createMicroservice<MicroserviceOptions>(
    AppModule,
    {
        transport: Transport.RMQ,
        options: {
            urls: ['amqp://localhost:5672'],
            queue: 'user_queue',
            queueOptions: { durable: false },
        },
    },
)

// 客户端
ClientsModule.register([
    {
        name: 'USER_SERVICE',
        transport: Transport.RMQ,
        options: {
            urls: ['amqp://localhost:5672'],
            queue: 'user_queue',
        },
    },
```

## 传输方式对比

| 传输 | 特点 | 适用场景 |
|------|------|---------|
| **TCP** | 点对点、简单、低延迟 | 内部服务间通信，中小规模 |
| **Redis** | 基于 Pub/Sub，无需额外中间件 | 已有 Redis 的场景 |
| **RabbitMQ** | 消息持久化、路由灵活、ACK 机制 | 需要可靠投递的场景 |
| **Kafka** | 高吞吐、分区、持久化 | 大数据量、日志收集 |

## 生产场景：用户注册流程

```
API 网关 (HTTP)
    │
    ├── TCP ──→ 用户微服务：创建用户
    │
    ├── RMQ ──→ 邮件微服务：发送验证邮件（异步）
    │
    ├── RMQ ──→ 积分微服务：赠送注册积分（异步）
    │
    └── TCP ──→ 日志微服务：记录操作日志
```

## 小结

- **微服务有两种启动方式**：`NestFactory.createMicroservice()` 起子服务，`NestFactory.create()` 起 HTTP 网关
- **@MessagePattern 定义消息处理器**：`@MessagePattern({ cmd: 'get_user' })` 配 `@Payload()` 读参数，取代 HTTP 路由
- **网关用 ClientProxy 发起调用**：`@Inject('USER_SERVICE')` 注入后 `client.send({ cmd }, data)` 走传输层调下游
- **ClientsModule.register 声明下游服务**：每个服务一项 `name + transport + options`，`name` 就是注入时用的 Token
- **四种传输方式的权衡**：TCP 点对点低延迟、Redis 基于 Pub/Sub 免额外中间件、RabbitMQ 支持可靠投递与路由、Kafka 高吞吐
- **同步与异步要混用**：注册流程里创建用户走 TCP 等结果，发邮件、加积分走 RMQ 异步，不阻塞主流程
