## CommonJS（require / module.exports）

Node.js 默认使用 CommonJS 模块系统。

### 导出模块

```javascript
// math.js
function add(a, b) {
    return a + b
}

function subtract(a, b) {
    return a - b
}

module.exports = { add, subtract }
```

### 导入模块

```javascript
// index.js
const math = require('./math')
console.log(math.add(1, 2)) // 3
```

也可以使用解构：

```javascript
const { add, subtract } = require('./math')
```

## ESM（import / export）

从 Node.js 16+ 开始，ES Module 已稳定支持。

### 启用方式

- 文件后缀改为 `.mjs`
- 或在 `package.json` 中设置 `"type": "module"`

> `"type": "module"` 是一个"整包开关"：一旦在 `package.json` 里声明，该目录（及其子目录，除非显式用 `.cjs`）下的所有 `.js` 文件都会被当作 ESM 解析。这解释了为什么很多项目要么全用 ESM，要么全用 CommonJS——混用会让一个文件到底是哪种模块系统变得依赖"它在哪个 package.json 的作用域内"。

### 导出

```javascript
// math.mjs
export function add(a, b) {
    return a + b
}

export const PI = 3.14

export default { add, PI }
```

### 导入

```javascript
// index.mjs
import { add } from './math.mjs'
import myMath from './math.mjs' // 默认导入
```

> 在 ESM 里，导入路径通常必须带扩展名（`./math.mjs` 而不是 `./math`），因为 ESM 不做 CommonJS 那种"自动补全扩展名 + 路径解析"的猜测。这是静态可分析的代价，也是它能支持 Tree Shaking 的前提。

## CommonJS vs ESM 核心区别

| 特性 | CommonJS | ESM |
|------|----------|-----|
| 语法 | `require` / `module.exports` | `import` / `export` |
| 加载方式 | 同步 | 异步 |
| 运行时 | 运行时加载 | 编译时静态分析 |
| Tree Shaking | 不支持 | 支持 |
| 文件后缀 | `.js` / `.cjs` | `.mjs` / `.js`（需配置 type） |

> 上面的"同步/异步"只是表面现象。更本质的区别是：**CommonJS 在运行时才解析 `require`，可以写在 `if` 里、可以动态拼接路径**；而 **ESM 在解析阶段就静态确定了所有依赖关系**，因此 `import` 必须写在顶层、不能根据条件动态构造。正是这份"死板"，换来了 Tree Shaking、循环依赖更安全、以及浏览器/Node 统一的能力。

## 为什么需要两套模块系统

CommonJS 是 Node.js 早期为了"在服务端快速有模块"而自己设计的，比 ES 标准早了好几年。等到 ES Module 成为语言标准时，npm 生态里已经是海量 CommonJS 包了——所以 Node.js 不能简单地一刀切，只能让两者长期共存。

### 心智模型：加载时机

- **CommonJS**：执行到 `require` 那一行时，才**同步**去读文件、编译、执行那个模块，把 `module.exports` 缓存后返回。所以"循环 `require`"有可能拿到尚未初始化完的半成品对象。
- **ESM**：进入文件后先**静态扫描**所有 `import`，把依赖关系建图，等整张图解析完毕再按依赖顺序实例化、求值。求值顺序是确定且可预测的。

### 顶层 await 与互操作

ESM 允许顶层 `await`（文件顶层直接 `await`，整个模块及其导入方会等它完成），CommonJS 做不到——`require` 是同步的，无法等待一个 Promise。

互操作则是工程里最常见的坑：

```javascript
// CommonJS 里想用 ESM 包：不能直接 require 一个顶层 await 的 ESM
// 需要包一层 async 函数
async function main() {
    const { something } = await import('some-esm-pkg') // 动态 import 返回 Promise
    something()
}
main()

// ESM 里用 CommonJS 包：通常可以直接 default import（Node 会帮你包装）
import pkg from 'some-cjs-pkg' // pkg 就是 module.exports
```

> 决策模型：新项目直接用 ESM（`"type": "module"`）；维护老库或要兼容海量 CommonJS 依赖时保留 CommonJS；两者之间用动态 `import()` 桥接，而不是在同步的 `require` 里硬塞异步依赖。

## npm 包管理

### 常用命令

```bash
npm init          # 初始化项目，生成 package.json
npm init -y       # 快速初始化，跳过交互
npm install xxx   # 安装依赖（简写：npm i xxx）
npm install -D xxx # 安装开发依赖
npm uninstall xxx # 卸载依赖
npm update        # 更新依赖
```

### package.json 常用字段

```json
{
    "name": "my-project",   // 项目名称
    "version": "1.0.0",     // 版本号
    "main": "index.js",     // 入口文件
    "scripts": {            // 脚本命令
        "start": "node index.js",
        "dev": "nodemon index.js"
    },
    "dependencies": {       // 生产依赖
        "express": "^4.18.0"
    },
    "devDependencies": {    // 开发依赖
        "typescript": "^5.0.0"
    }
}
```

### 语义化版本

```
^4.18.0  → 允许 4.x.x 范围内的更新（不改变首位）
~4.18.0  → 允许 4.18.x 范围内的更新（不改变前两位）
4.18.0   → 锁定版本
```

> 语义化版本（`主版本.次版本.补丁`）的含义是：主版本变更 = 不兼容的 API 改动；次版本变更 = 向后兼容的新功能；补丁变更 = 向后兼容的 bug 修复。所以 `^` 敢跨次版本（新功能通常不破坏旧调用），但不敢跨主版本（可能破坏性升级）。

### 锁定文件

`package-lock.json`（或 `pnpm-lock.yaml` / `yarn.lock`）记录了**实际安装的每个依赖的精确版本和哈希**。即使 `package.json` 写的是 `^4.18.0`，锁文件能保证团队里每个人、CI 机器上装到的都是**完全一致**的那一棵树，避免"在我机器上能跑"的问题。

> 决策模型：提交 `package.json` 时**一定也要提交锁文件**；`npm install` 默认会尊重锁文件，只有 `npm install <pkg>` 显式加依赖时才会更新它。需要可复现构建（生产、CI）时，用 `npm ci` 而非 `npm install`，它严格按照锁文件安装且更快。

## node_modules

- `npm install` 后，依赖会下载到 `node_modules` 目录
- 该目录通常很大，**不要提交到 Git**
- 在 `.gitignore` 中添加 `node_modules/`

## 面试题

### Q1: CommonJS 和 ESM 的区别是什么？

CommonJS 使用 `require` 同步加载，运行时执行；ESM 使用 `import` 静态加载，编译时分析，支持 Tree Shaking。ESM 是标准，CommonJS 是 Node.js 的历史产物。

### Q2: `npm install` 时 `^` 和 `~` 的区别？

`^` 允许小版本更新（不改变主版本号），`~` 只允许补丁版本更新（不改变主版本和小版本）。`^4.18.0` 可以安装到 `4.19.0`，而 `~4.18.0` 只能安装到 `4.18.x`。

### Q3: 为什么 CommonJS 里不能 `require` 一个顶层有 `await` 的 ESM 包？

因为 `require` 是同步的，它必须"立刻拿到返回值"；而顶层 `await` 意味着模块求值要等一个 Promise，这是异步的，同步 API 无法等待它。正确做法是用动态 `import()`（返回 Promise）在 `async` 函数里引入，或者用 ESM 文件去 `import` 这个包。
