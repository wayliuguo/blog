## fs 模块（文件系统）

`fs` 模块提供了文件读写、目录操作等功能。

### 文件读取

```javascript
const fs = require('fs')

// 同步读取（阻塞）
const data = fs.readFileSync('file.txt', 'utf8')
console.log(data)

// 异步读取（推荐）
fs.readFile('file.txt', 'utf8', (err, data) => {
    if (err) throw err
    console.log(data)
})

// Promise 方式（推荐）
const fsPromises = require('fs/promises')

async function readFile() {
    try {
        const data = await fsPromises.readFile('file.txt', 'utf8')
        console.log(data)
    } catch (err) {
        console.error('读取失败:', err.message)
    }
}
```

### 文件写入

```javascript
const fs = require('fs/promises')

// 写入文件（覆盖）
await fs.writeFile('output.txt', 'Hello World', 'utf8')

// 追加内容
await fs.appendFile('output.txt', '\n新的一行', 'utf8')

// 检查文件是否存在
const exists = await fs.access('file.txt').then(() => true).catch(() => false)
```

### 目录操作

```javascript
const fs = require('fs/promises')

// 创建目录
await fs.mkdir('logs', { recursive: true })  // recursive 创建多级目录

// 读取目录
const files = await fs.readdir('./')
console.log(files)  // ['file1.txt', 'dir1', ...]

// 删除目录
await fs.rm('old-dir', { recursive: true })

// 删除文件
await fs.unlink('temp.txt')
```

## path 模块

`path` 模块用于处理文件路径。

```javascript
const path = require('path')

// 路径拼接
const fullPath = path.join('users', 'docs', 'file.txt')
// → 'users/docs/file.txt'（跨平台，Windows 用 \，Linux 用 /）

// 获取路径信息
path.basename('/users/docs/file.txt')     // → 'file.txt'
path.dirname('/users/docs/file.txt')      // → '/users/docs'
path.extname('/users/docs/file.txt')      // → '.txt'
path.parse('/users/docs/file.txt')
// → { root: '/', dir: '/users/docs', base: 'file.txt', ext: '.txt', name: 'file' }

// 解析为绝对路径
path.resolve('docs', 'file.txt')
// → 'C:/Users/.../docs/file.txt'（当前工作目录下的路径）
```

## http 模块

`http` 模块用于创建 HTTP 服务器，是 Express 等框架的底层基础。

```javascript
const http = require('http')

const server = http.createServer((req, res) => {
    // req: 请求对象（方法、URL、头信息）
    // res: 响应对象（状态码、头信息、响应体）

    res.statusCode = 200
    res.setHeader('Content-Type', 'text/plain')
    res.end('Hello World\n')
})

server.listen(3000, () => {
    console.log('Server running at http://localhost:3000')
})
```

### 路由处理（纯 Node.js 方式）

```javascript
const http = require('http')
const url = require('url')

const server = http.createServer((req, res) => {
    const { pathname } = url.parse(req.url, true)

    // 设置 JSON 响应头
    res.setHeader('Content-Type', 'application/json')

    if (pathname === '/users' && req.method === 'GET') {
        res.end(JSON.stringify({ users: [] }))
    } else if (pathname === '/users' && req.method === 'POST') {
        let body = ''
        req.on('data', chunk => body += chunk)
        req.on('end', () => {
            const data = JSON.parse(body)
            res.end(JSON.stringify({ created: true, data }))
        })
    } else {
        res.statusCode = 404
        res.end(JSON.stringify({ error: 'Not Found' }))
    }
})

server.listen(3000)
```

## Buffer 基础

`Buffer` 用于处理二进制数据，是 Node.js 特有的数据类型。

把 `Buffer` 想象成一个**固定长度的"水桶"**：桶里装的不是字符，而是一个个 0~255 的字节（byte）。你无法往桶里"无限加水"——创建时就定好了容量；要往里放东西，只能按字节填。

```javascript
// 创建 Buffer
const buf1 = Buffer.from('Hello', 'utf8')       // 字符串 → Buffer
const buf2 = Buffer.alloc(10)                    // 分配 10 字节空间
const buf3 = Buffer.from([0x48, 0x65, 0x6c])     // 字节数组 → Buffer

// Buffer → 字符串
console.log(buf1.toString('utf8'))  // 'Hello'
console.log(buf1.toString('hex'))   // '48656c6c6f'

// 合并 Buffer
const combined = Buffer.concat([buf1, buf2])
```

### 服务端为什么必须懂二进制

浏览器主要处理文本和 DOM，但**服务端天生就在和二进制打交道**：

| 场景 | 对应的二进制数据 |
|------|------------------|
| 图片 / 音视频上传下载 | 原始文件字节流 |
| PDF / Office 文档 | 带格式的字节序列 |
| 网络传输（TCP 包） | 字节帧，需要按协议拆包 |
| 压缩（gzip） | 压缩后的字节流 |
| 加解密 | 密文字节 |

字符串 `toString('utf8')` 只是"把字节按 UTF-8 规则翻译成人能读的字符"的一种解读方式；同一段字节用 `'hex'` 解读就是十六进制串，用 `'base64'` 解读就是 Base64 串。**字节本身没有编码，编码只是解读视角**——这正是 `Buffer.from(str, 'utf8')` 与 `buf.toString('utf8')` 成对出现的原因。

## Stream 流

Stream 是 Node.js 处理大数据的核心方式，**边读边处理**，不一次性加载到内存。

```javascript
const fs = require('fs')
const zlib = require('zlib')

// 读取流
const readStream = fs.createReadStream('large-file.txt', 'utf8')
readStream.on('data', (chunk) => {
    console.log('收到数据块:', chunk.length)
})
readStream.on('end', () => {
    console.log('读取完成')
})

// 管道：读取 → 压缩 → 写入
readStream
    .pipe(zlib.createGzip())
    .pipe(fs.createWriteStream('large-file.txt.gz'))

// 写入流
const writeStream = fs.createWriteStream('output.txt')
writeStream.write('第一行\n')
writeStream.write('第二行\n')
writeStream.end()
```

### Stream 的四种类型

| 类型 | 特点 | 典型例子 |
|------|------|----------|
| `Readable` | 只能读（生产数据） | `fs.createReadStream`、HTTP 请求体 |
| `Writable` | 只能写（消费数据） | `fs.createWriteStream`、HTTP 响应 |
| `Duplex` | 既能读又能写（双向） | `net.Socket`、TCP 连接 |
| `Transform` | 读写同时**转换**数据 | `zlib.createGzip()`、加解密流 |

`Transform` 最常用在"边过边改"的管道里。比如下面的代码一面读一面把每个数据块转成大写，再写出去：

```javascript
const { Transform } = require('stream')

const upper = new Transform({
    transform(chunk, encoding, callback) {
        // chunk 是 Buffer，先转成字符串处理，再 push 出去
        this.push(chunk.toString().toUpperCase())
        callback()
    }
})

fs.createReadStream('a.txt')
    .pipe(upper)
    .pipe(fs.createWriteStream('a.upper.txt'))
```

### 背压（Backpressure）：为什么不能一次性 readFile 10GB

`fs.readFile` 会把**整个文件读进内存**再回调。10GB 文件直接把进程内存撑爆。Stream 的价值正在于"分块流动"，但流动的两端速度往往不匹配：磁盘读得比网络发得快，上游就会越积越多。

`writable.write(chunk)` 的返回值是关键——它是一个 **boolean**：

- 返回 `true`：内部缓冲还没到阈值，可以继续写。
- 返回 `false`：缓冲已达上限，**应该暂停读取**，否则内存还是会暴涨。

等可写端消化完、缓冲降下来，它会触发 `'drain'` 事件，此时再恢复写入：

```javascript
const readable = fs.createReadStream('big.iso')
const writable = fs.createWriteStream('out.iso')

readable.on('data', (chunk) => {
    // 返回 false 表示下游跟不上了，先暂停读取
    if (!writable.write(chunk)) {
        readable.pause()
    }
})

// 下游排空后再恢复读取
writable.on('drain', () => {
    readable.resume()
})
```

> 决策模型：手写 `pause/resume` 很容易出错。绝大多数场景直接用 `readable.pipe(writable)`——`pipe` 内部已经**自动协调了背压**：可写端忙不过来时自动 `pause` 可读端，收到 `drain` 再 `resume`。所以"需要背压控制"时，优先用 `pipe`（或 `pipeline`），而不是手动搬运数据块。

### Stream 的适用场景

| 场景 | 不用 Stream | 用 Stream |
|------|------------|-----------|
| 大文件上传 | 内存耗尽 | 边读边写 |
| 视频流 | 加载完再播放 | 边下载边播放 |
| 日志处理 | 消耗大量内存 | 逐行处理 |
| 流式响应 / SSE | 等全部生成完才返回 | 生成一段就 `res.write` 一段，前端逐字渲染 |

> 关联场景：流式推送（如上游服务一段段返回内容）和 Server-Sent Events（SSE）本质就是 `Readable`/`res`（Writable）的流式推送——上游每产出一段内容，服务端就 `res.write(chunk)` 推给前端，而不是等完整内容生成完再一次性返回。理解 Stream 与背压，是写出"不卡内存的流式接口"的前提。

## 面试题

### Q1: `fs.readFileSync` 和 `fs.readFile` 的区别？

`readFileSync` 是同步方法，会阻塞事件循环，直到文件读取完成。`readFile` 是异步方法，不会阻塞，读取完成后通过回调通知。生产环境尽量使用异步方法。

### Q2: 什么是 Stream，为什么需要它？

Stream 是 Node.js 处理流式数据的抽象接口，允许边读取边处理，而不需要将全部数据加载到内存中。适合处理大文件、网络请求等大数据量场景。

### Q3: 什么是背压（Backpressure）？`writable.write` 返回 false 意味着什么？

当可读端生产数据的速度快于可写端消费速度时，中间缓冲会越积越多，这就是背压。每次 `writable.write(chunk)` 返回一个 boolean：`false` 表示内部缓冲已达阈值，调用方应当暂停读取（如 `readable.pause()`）避免内存暴涨；等可写端触发 `'drain'` 事件、缓冲降下来后再 `resume()`。最省心的做法是直接用 `pipe`，它内部已自动协调背压。

### Q4: `Buffer` 和 `String` 在 Node 里是什么关系？

`Buffer` 是固定长度的字节序列（本质是 `Uint8Array` 子类），存的是原始字节；`String` 是带编码（如 UTF-8）的字符序列。`Buffer.from(str, 'utf8')` 按编码把字符编码成字节，`buf.toString('utf8')` 反向解码。同一段字节用不同编码 `toString` 会得到不同结果——字节本身无编码，编码只是解读视角。
