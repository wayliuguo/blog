# 请求处理链

> 一个请求从进入到返回，会经过 NestJS 的请求处理链。

---

## [初级] 请求处理流程总览

```
请求到达
    ↓
Middleware（中间件）→ 日志、CORS
    ↓
Guard（守卫）→ 是否允许访问（身份验证）
    ↓
Interceptor（拦截器）→ 请求前处理
    ↓
Pipe（管道）→ 参数校验与转换
    ↓
Handler（控制器方法）→ 执行业务逻辑
    ↓
Interceptor（拦截器）→ 响应后处理
    ↓
Exception Filter（异常过滤器）→ 统一错误处理
    ↓
返回响应
```

## [中级] 中间件（Middleware）

中间件函数在请求到达路由之前执行，与 Express 中间件一致。

### 方式一：类式中间件（可注入依赖）

```typescript
import { Injectable, NestMiddleware, MiddlewareConsumer, Module, NestModule } from '@nestjs/common'
import { Request, Response, NextFunction } from 'express'

@Injectable()
export class LoggerMiddleware implements NestMiddleware {
    use(req: Request, res: Response, next: NextFunction) {
        console.log(`${req.method} ${req.url}`)
        next()
    }
}

// 在模块中配置
@Module({
    providers: [LoggerMiddleware]
})
export class AppModule implements NestModule {
    configure(consumer: MiddlewareConsumer) {
        consumer
            .apply(LoggerMiddleware)
            .forRoutes('*')  // 对所有路由生效
    }
}
```

### 方式二：函数式中间件（无依赖注入，更轻量）

```typescript
import { Request, Response, NextFunction } from 'express'

// 纯函数，不需要 @Injectable()
export function logger(req: Request, res: Response, next: NextFunction) {
    console.log(`${req.method} ${req.url}`)
    next()
}

// 在模块中直接应用（无需注册 provider）
@Module({})
export class AppModule implements NestModule {
    configure(consumer: MiddlewareConsumer) {
        consumer
            .apply(logger)  // 直接传函数引用
            .forRoutes('*')
    }
}
```

### 方式三：Express 原生中间件（在 main.ts 中全局使用）

```typescript
// main.ts
import { NestFactory } from '@nestjs/core'
import { AppModule } from './app.module'
import * as cookieParser from 'cookie-parser'
import * as helmet from 'helmet'

async function bootstrap() {
    const app = await NestFactory.create(AppModule)

    // Express 原生中间件（绕过 Nest 管道，全局生效）
    app.use(cookieParser())
    app.use(helmet())

    await app.listen(3000)
}
```

**使用场景**：请求日志、CORS、静态文件处理、cookie 解析、安全头设置。

## [中级] 守卫（Guard）

守卫决定请求是否放行，返回 `true` 放行，`false` 拒绝。

```typescript
import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common'
import { Observable } from 'rxjs'

@Injectable()
export class AuthGuard implements CanActivate {
    canActivate(context: ExecutionContext): boolean | Promise<boolean> | Observable<boolean> {
        const request = context.switchToHttp().getRequest()
        const token = request.headers.authorization

        if (!token) return false

        // 验证 token...
        return true
    }
}
```

### 使用方式

```typescript
// 方式一：路由级别（@UseGuards）
@Controller('users')
@UseGuards(AuthGuard)          // 整个控制器需要登录
export class UserController {
    @Get()
    @UseGuards(AuthGuard)      // 或只对某个路由生效
    findAll() {}
}

// 方式二：全局注册（main.ts）
async function bootstrap() {
    const app = await NestFactory.create(AppModule)
    app.useGlobalGuards(new AuthGuard())  // 全局生效，但无法注入依赖
    await app.listen(3000)
}

// 方式三：全局注册（Provider 推荐）
import { APP_GUARD } from '@nestjs/core'

@Module({
    providers: [
        {
            provide: APP_GUARD,
            useClass: AuthGuard,
        }
    ]
})
export class AppModule {}
```

**使用场景**：身份验证、权限检查。

## [中级] 拦截器（Interceptor）

拦截器可以在请求处理**前后**执行逻辑，实现 `NestInterceptor` 接口。

### 基础示例

```typescript
import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common'
import { Observable } from 'rxjs'
import { tap } from 'rxjs/operators'

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
    intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
        console.log('请求前...')

        return next.handle().pipe(
            tap(data => console.log('请求后...', data))
        )
    }
}
```

### 统一响应格式

```typescript
import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common'
import { Observable } from 'rxjs'
import { map } from 'rxjs/operators'

export interface ApiResponse<T> {
    code: number
    data: T
    message: string
}

@Injectable()
export class TransformInterceptor<T> implements NestInterceptor<T, ApiResponse<T>> {
    intercept(context: ExecutionContext, next: CallHandler): Observable<ApiResponse<T>> {
        return next.handle().pipe(
            map(data => ({
                code: 0,
                data,
                message: 'success'
            }))
        )
    }
}
```

### 请求耗时统计

```typescript
@Injectable()
export class TimingInterceptor implements NestInterceptor {
    intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
        const start = Date.now()

        return next.handle().pipe(
            tap(() => {
                const duration = Date.now() - start
                console.log(`请求耗时: ${duration}ms`)
            })
        )
    }
}
```

### 使用方式

```typescript
// 方式一：路由级别（@UseInterceptors）
@Controller('users')
@UseInterceptors(TransformInterceptor)
export class UserController {
    @Get()
    @UseInterceptors(TimingInterceptor)  // 可叠加多个
    findAll() {}
}

// 方式二：全局注册（main.ts）
async function bootstrap() {
    const app = await NestFactory.create(AppModule)
    app.useGlobalInterceptors(new TransformInterceptor())
    // 缺点：无法注入依赖
    await app.listen(3000)
}

// 方式三：全局注册（Provider 推荐）
import { APP_INTERCEPTOR } from '@nestjs/core'

@Module({
    providers: [
        {
            provide: APP_INTERCEPTOR,
            useClass: TransformInterceptor,
        },
        {
            provide: APP_INTERCEPTOR,
            useClass: TimingInterceptor,
        }
    ]
})
export class AppModule {}
```

**使用场景**：统一响应格式、请求耗时统计、缓存。

## [中级] 管道（Pipe）

管道对传入的参数进行转换或校验。

### 内置管道

```typescript
@Get(':id')
findOne(
    @Param('id', ParseIntPipe) id: number,  // 将字符串 "1" 转为数字 1
) {}

@Get()
findAll(
    @Query('page', DefaultValuePipe(1), ParseIntPipe) page: number,  // 默认值 + 类型转换
) {}
```

**常用内置管道**：

| 管道 | 作用 |
|------|------|
| `ValidationPipe` | 基于 DTO 的声明式校验 |
| `ParseIntPipe` | 字符串转整数 |
| `ParseFloatPipe` | 字符串转浮点数 |
| `ParseBoolPipe` | 字符串转布尔值 |
| `DefaultValuePipe` | 设置默认值 |

### DTO 与 class-validator

DTO（Data Transfer Object）用于定义请求体的结构，配合 `class-validator` 实现声明式校验。

```bash
npm install class-validator class-transformer
```

```typescript
import { IsString, IsInt, IsOptional, Min, Max, IsEmail } from 'class-validator'

export class CreateUserDto {
    @IsString({ message: '姓名必须是字符串' })
    @MinLength(2, { message: '姓名至少 2 个字符' })
    @MaxLength(50)
    name: string

    @IsInt()
    @Min(0)
    @Max(150)
    age: number

    @IsEmail({}, { message: '邮箱格式不正确' })
    email: string

    @IsOptional()
    @IsString()
    phone?: string
}
```

### 自定义管道

```typescript
import { PipeTransform, Injectable, BadRequestException } from '@nestjs/common'

@Injectable()
export class ParseIdPipe implements PipeTransform {
    transform(value: string) {
        const id = parseInt(value, 10)
        if (isNaN(id) || id <= 0) {
            throw new BadRequestException('ID 必须是正整数')
        }
        return id
    }
}
```

### 使用方式

```typescript
// 方式一：路由级别（在 @Param/@Body/@Query 中直接使用）
@Get(':id')
findOne(@Param('id', ParseIdPipe) id: number) {
    return this.userService.findById(id)
}

@Post()
create(@Body(new ValidationPipe()) body: CreateUserDto) {
    // 如果校验失败，NestJS 会自动返回 400 错误
    return this.userService.create(body)
}

// 方式二：全局注册（main.ts）
async function bootstrap() {
    const app = await NestFactory.create(AppModule)

    app.useGlobalPipes(new ValidationPipe({
        whitelist: true,               // 自动剔除 DTO 中未定义的字段
        forbidNonWhitelisted: true,    // 发现未定义字段则拒绝请求
        transform: true,               // 自动类型转换（"1" → 1）
        disableErrorMessages: false,   // 生产环境设为 true 隐藏错误详情
    }))

    await app.listen(3000)
}

// 方式三：全局注册（Provider）
import { APP_PIPE } from '@nestjs/core'

@Module({
    providers: [
        {
            provide: APP_PIPE,
            useClass: ParseIdPipe,
        }
    ]
})
export class AppModule {}
```

**whitelist 的作用**：
```typescript
// DTO 只定义了 name 和 age
export class CreateUserDto {
    name: string
    age: number
}

// 请求体包含额外字段
{
    "name": "张三",
    "age": 25,
    "role": "admin"  // 未定义字段
}

// whitelist: true → role 会被自动剔除
// forbidNonWhitelisted: true → 直接返回 400 错误
```

**使用场景**：参数类型转换、数据校验、ObjectId 格式校验、分页参数范围校验。

## [中级] 异常过滤器（Exception Filter）

异常过滤器捕获未处理的异常并返回统一格式的错误响应。

### 内置 HTTP 异常

```typescript
// NestJS 内置了常用的 HTTP 异常类
throw new BadRequestException('参数错误')       // 400
throw new UnauthorizedException('未登录')      // 401
throw new ForbiddenException('无权限')          // 403
throw new NotFoundException('资源不存在')        // 404
throw new ConflictException('资源冲突')          // 409
throw new InternalServerErrorException('服务器错误') // 500
```

### 自定义异常过滤器

```typescript
import { ExceptionFilter, Catch, ArgumentsHost, HttpException } from '@nestjs/common'
import { Response } from 'express'

@Catch(HttpException)
export class HttpExceptionFilter implements ExceptionFilter {
    catch(exception: HttpException, host: ArgumentsHost) {
        const ctx = host.switchToHttp()
        const response = ctx.getResponse<Response>()
        const status = exception.getStatus()
        const exceptionResponse = exception.getResponse()

        response.status(status).json({
            code: status,
            message: typeof exceptionResponse === 'string'
                ? exceptionResponse
                : (exceptionResponse as any).message || exception.message,
            timestamp: new Date().toISOString(),
            path: ctx.getRequest().url
        })
    }
}
```

### 捕获所有异常

```typescript
@Catch()  // 不指定类型，捕获所有异常
export class AllExceptionsFilter implements ExceptionFilter {
    catch(exception: unknown, host: ArgumentsHost) {
        const ctx = host.switchToHttp()
        const response = ctx.getResponse<Response>()

        let status = 500
        let message = '服务器内部错误'

        if (exception instanceof HttpException) {
            status = exception.getStatus()
            message = exception.message
        }

        response.status(status).json({
            code: status,
            message,
            timestamp: new Date().toISOString()
        })
    }
}
```

### 使用方式

```typescript
// 方式一：路由级别（@UseFilters）
@Controller('users')
@UseFilters(HttpExceptionFilter)
export class UserController {
    @Get()
    @UseFilters(HttpExceptionFilter)
    findAll() {}
}

// 方式二：全局注册（main.ts）
async function bootstrap() {
    const app = await NestFactory.create(AppModule)
    app.useGlobalFilters(new HttpExceptionFilter())
    // 缺点：无法注入依赖
    await app.listen(3000)
}

// 方式三：全局注册（Provider 推荐）
import { APP_FILTER } from '@nestjs/core'

@Module({
    providers: [
        {
            provide: APP_FILTER,
            useClass: HttpExceptionFilter,
        }
    ]
})
export class AppModule {}
```

**使用场景**：统一错误响应格式。

## 面试题

### Q1: 拦截器和过滤器的区别？

拦截器（Interceptor）在请求处理前后执行，可以修改请求和响应，适合统一响应格式、日志、缓存等。过滤器（Exception Filter）在异常发生时执行，捕获异常并返回统一格式的错误响应。

### Q2: 全局绑定拦截器有哪两种方式？有什么区别？

`app.useGlobalInterceptors`（无法注入依赖）和 `APP_INTERCEPTOR` 提供者（可以注入依赖）。推荐使用 `APP_INTERCEPTOR` 方式，因为拦截器通常需要依赖其他服务。

### Q3: `ValidationPipe` 的 `whitelist` 和 `forbidNonWhitelisted` 有什么区别？

`whitelist: true` 会自动剔除 DTO 中未定义的字段；`forbidNonWhitelisted: true` 更严格，发现未定义字段直接返回 400 错误。两者结合使用可以获得最佳安全性。

### Q4: 为什么说 DTO 比直接在控制器中写校验更好？

DTO 将校验逻辑从控制器中分离出来，职责单一、可复用（同一个 DTO 可以在多个地方使用）、可测试（可以单独测试 DTO 的校验逻辑）。
