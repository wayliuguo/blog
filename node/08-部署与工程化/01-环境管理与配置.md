# 环境管理与配置

> 从 `.env` 到生产级配置系统：NestJS 环境变量管理的渐进式演进
> 实战参考：show-track-server 生产项目的配置体系（`src/config/`）

---

## 为什么这一篇是部署的开始

部署的本质是"同一份代码，跑出不同行为"——本地连本地库、生产连云库、测试跑在隔离环境。这种"代码不动、行为可变"的能力，全靠**配置**：一组可替换的环境变量。

很多新人把配置写成"一堆 `process.env.XXX` 到处散落"，能跑但一团糟。本系列就从配置入手，把它做成体系。我们分四步渐进：

| 阶段 | 目标 | 你能获得 |
|------|------|---------|
| ① 跑起来 | 用 `.env` + `@nestjs/config` 读取配置 | 最小可用 |
| ② 多环境 | `.env.development / .env.production` 按环境加载 | 一套代码多环境跑 |
| ③ 类型安全 | `registerAs` 命名空间 + `ConfigType` 类型推断 | IDE 补全 + 编译期纠错 |
| ④ 校验与敏感信息 | 启动校验、构建产物类型、敏感变量拦截 | 生产级可信 |

> 每一步都是真实生产项目（show-track-server）里落地过的写法，不是教学 toy。

---

## ① 跑起来：.env + @nestjs/config

### 你知道 node 自带读取环境变量

```typescript
// 最朴素的写法
const port = process.env.PORT; // string | undefined
const dbHost = process.env.DB_HOST;
```

问题随之而来：

| 问题 | 说明 |
|------|------|
| 类型全是 `string` | 端口、数字配置无法自动转型，得手动 `Number()` |
| 默认值全靠手写 | 每次都要 `process.env.X || 'default'` |
| 到处直接访问 | 散落在各处，改个变量名要全局搜索替换 |
| `.env` 文件不生效 | Node 不会自动读 `.env` 文件，得装 `dotenv` 手动加载 |

### 引入 @nestjs/config

`@nestjs/config` 内部封装了 `dotenv` 和 `process.env` 读取，还提供了类型安全的 `ConfigService`。

```bash
npm install @nestjs/config
```

```typescript
// app.module.ts
import { Module } from '@nestjs/common';
import { ConfigModule, ConfigService } from '@nestjs/config';

@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true, // 全局可用，任意模块无需再导入
    }),
  ],
})
export class AppModule {}
```

```typescript
// 在任何 Service / Controller 中使用
@Injectable()
export class DatabaseService {
  constructor(private configService: ConfigService) {
    // get 返回 string | undefined
    const host = this.configService.get<string>('DB_HOST');
    // 注意：想拿数字仍需手动转型
    const port = this.configService.get<number>('DB_PORT');
  }
}
```

`.env` 文件：

```ini
# .env（注意：不要提交到 Git，见 ④）
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=password
JWT_SECRET=my-secret
```

`ConfigService.get<T>()` 的 `<T>` 只是"告诉 TypeScript 你期望什么类型"，**并不会真正运行时转换**——这就是下一阶段要解决的问题。

> **小结**：① 解决了"读取"问题。但类型不安全、默认值散落、`.env` 不分环境。继续看 ②。

## ② 多环境：一套代码多环境跑

### 为什么需要多套环境变量

同一个项目，开发时想连本地 MySQL、测试想连测试库、生产想连云 RDS——端口、密码、域名全不一样。做法是**按环境拆 `.env` 文件**：

```
.env.local          # 个人本机覆盖（gitignored，绝不提交）
.env.development    # 开发环境（从 .env.example 复制，不提交）
.env.production     # 生产环境（从 .env.example 复制，不提交）
.env.test           # 测试环境
.env.example        # 模板（占位符，提交到 Git）
.env                # 对所有人相同的默认值（提交到仓库）
```

### @nestjs/config 的多文件加载

`envFilePath` 支持传数组，**越靠前的优先级越高**：

```typescript
ConfigModule.forRoot({
  isGlobal: true,
  envFilePath: [`.env.${process.env.NODE_ENV}`, '.env'],
});
```

其中 `.env.development` 在 `NODE_ENV=development` 时被加载，覆盖 `.env` 的默认值。

### 优先级全景（how the load chain works）

```
process.env（操作系统注入，最高优先）
   ↑
.env.local（个人覆盖）
   ↑
.env.development（开发环境）
   ↑
.env.production（生产环境）
   ↑
.env.example（模板占位符）
   ↑
.env（默认值，最低优先）
```

> 符合 12-Factor App 的配置原则："配置与代码严格分离，随环境变化而变化"。

### 容器/CI 场景的兜底逻辑

生产容器里环境变量常由 Docker Compose / CI 直接注入，不再需要读 `.env` 文件。此时应**跳过 dotenv 加载**。show-track 的 `load-env.helper.ts` 就是这样做的：

```typescript
// src/config/load-env.helper.ts
export function loadEnv(defaultEnv: string): void {
  // 已通过容器/CI 注入环境变量（以 DB_HOST 判断），无需加载 .env 文件
  if (process.env.DB_HOST) return;
  const envFile = `.env.${process.env.NODE_ENV || defaultEnv}`;
  if (fs.existsSync(envFile)) {
    dotenv.config({ path: envFile });
  }
}
```

> **小结**：② 解决了"按环境切配置"的问题。但现在 `configService.get('app.port')` 拿到的是 `any`，零补全、零校验。继续看 ③。

## ③ 类型安全：registerAs 命名空间 + 类型推断

多环境解决了"切配置"，但访问配置依然全是 `any`。show-track 用 **`registerAs` + `ConfigType`** 把配置做成强类型。你拿到的不再是神秘字符串，而是 IDE 可补全、编译期可纠错的对象。

### 拆分命名空间（namespace）

配置按领域拆成独立文件，每个用 `registerAs(token, factory)` 注册：

```typescript
// src/config/app.config.ts
import { ConfigType, registerAs } from '@nestjs/config';
import { env, envNumber, envBoolean } from '~/global/env';

/** 命名空间标识，后续 configService.get('app') 取到 */
export const appRegToken = 'app';

export const AppConfig = registerAs(appRegToken, () => ({
  name: env('APP_NAME', 'Show Track Server'),
  port: envNumber('APP_PORT', 3000),
  baseUrl: env('APP_BASE_URL', `http://localhost:${envNumber('APP_PORT', 3000)}`),
  globalPrefix: env('GLOBAL_PREFIX', 'api'),
  /** 是否允许多设备同时登录 */
  multiDeviceLogin: envBoolean('MULTI_DEVICE_LOGIN', true),
  logger: {
    level: env('LOGGER_LEVEL', 'verbose'),
    maxFiles: envNumber('LOGGER_MAX_FILES', 31),
  },
}));

/** 从工厂函数返回值推断出的配置类型，无需手动维护 interface */
export type IAppConfig = ConfigType<typeof AppConfig>;
```

### 类型安全的读取工具函数

注意上面用了 `env` / `envNumber` / `envBoolean`——这不是框架自带的，是一个 30 行的全局工具（show-track 的 `src/global/env.ts`），用来让配置读取就带转换和默认值：

```typescript
// src/global/env.ts
/** 读取字符串，不存在返回默认值 */
export function env(key: string, defaultValue = '') {
  const value = process.env[key];
  return value === undefined ? defaultValue : value;
}

/** 读取数字，非法值立刻 throw，避免带病启动 */
export function envNumber(key: string, defaultValue = 0) {
  const value = process.env[key];
  if (value === undefined) return defaultValue;
  const num = Number(value);
  if (Number.isNaN(num)) throw new Error(`${key} is not a number`);
  return num;
}

/** 读取布尔，true/1/yes（不分大小写）为真，其余为假 */
export function envBoolean(key: string, defaultValue = false) {
  const value = process.env[key];
  if (value === undefined) return defaultValue;
  return ['true', '1', 'yes'].includes(value.toLowerCase());
}
```

> 有了 `envNumber`，`port` 就真的是 `number` 而不是"看起来像 number 的 string"。

### 聚合导出 + 类型路径

把所有命名空间收进 `src/config/index.ts`：

```typescript
// src/config/index.ts
import { RedisConfig, redisRegToken } from './redis.config';
import { SecurityConfig, securityRegToken } from './security.config';
// ... 其余 config

/** 所有命名空间的联合类型 */
export interface AllConfigType {
  [redisRegToken]: IRedisConfig;
  [securityRegToken]: ISecurityConfig;
  // ...
}

export default { AppConfig, RedisConfig, SecurityConfig, /* ... */ };
```

然后在 `ConfigModule.forRoot` 里批量加载：

```typescript
ConfigModule.forRoot({
  isGlobal: true,
  load: [...Object.values(configs)], // 批量注册所有命名空间
});
```

配置样板以 Redis 为例：

```typescript
// src/config/redis.config.ts
export const RedisConfig = registerAs('redis', () => ({
  host: env('REDIS_HOST', '127.0.0.1'),
  port: envNumber('REDIS_PORT', 6379),
  password: env('REDIS_PASSWORD', ''),
  db: envNumber('REDIS_DB', 0),
}));
```

使用处不再拼字符串：

```typescript
// 用法：拿到的是强类型对象
const redisConfig = configService.get<IRedisConfig>('redis', { infer: true });
// redisConfig.host: string
// redisConfig.port: number
// redisConfig.db:   number
// IDE 会给出字段补全；拼错字段名编译期直接报错
```

### ConfigKeyPaths：点号路径的魔法（进阶）

show-track 还定义了一个递归类型工具，把嵌套配置展平为点号路径联合，让 `configService.get('app.logger.level')` 也有精确类型：

```typescript
export type ConfigKeyPaths = RecordNamePaths<AllConfigType>;
// 'app' | 'app.port' | 'app.logger' | 'app.logger.level' | 'redis' | 'redis.host' | ...
```

| 写法 | 返回类型 |
|------|---------|
| `get('app.port')` | `any`（不推荐） |
| `get('app.port', { infer: true })` | `number`（精确推导） |

> **小结**：③ 让"读配置"变得安全：强类型、能补全、带默认值、可转换。但类型安全不等于值正确——`JWT_SECRET` 配成 `'your-jwt-secret-change-me'` 也是合法字符串，这就引出 ④。

## ④ 校验与敏感信息：生产级可信

类型安全只能保证"读得对类型"，保证不了"配的是有效值"。这一步做三件事：**启动校验**、**构建产物带类型**、**敏感变量拦截**。

### 4.1 启动校验：配错立刻报错，不带着病跑

show-track 在配置加载时直接抛错，让"漏配/弱配置"在启动阶段就暴露，而不是运行到登录接口才炸：

```typescript
// src/config/security.config.ts
export const SecurityConfig = registerAs('security', () => {
  const jwtSecret = env('JWT_SECRET');

  // 启动时校验：JWT 密钥必须配置，且不能用默认值
  if (!jwtSecret || jwtSecret === 'your-jwt-secret-change-me') {
    throw new Error(
      'JWT_SECRET 环境变量未正确配置。生产环境必须使用强随机密钥。',
    );
  }

  return {
    jwtSecret,
    jwtExpire: envNumber('JWT_EXPIRE', 86400),       // 默认 24h
    refreshExpire: envNumber('REFRESH_TOKEN_EXPIRE', 2592000), // 默认 30d
  };
});
```

同理，管理后台账号也是必填项：

```typescript
const adminUsername = env('ADMIN_USERNAME');
const adminPassword = env('ADMIN_PASSWORD');
if (!adminUsername || !adminPassword) {
  throw new Error('ADMIN_USERNAME / ADMIN_PASSWORD 未配置，请检查 .env 文件');
}
```

> **原则**：**宁可启动失败，不可带病运行**。配置错误越早暴露代价越低。

### 4.2 构建产物带类型：扫 .env.example 生成 env.d.ts

show-track 用一个几十行脚本扫描 `.env.example`，自动生成 `types/env.d.ts`，让 `process.env.XXX` 在编辑期就有补全：

```typescript
// scripts/genEnvTypes.ts（核心逻辑节选）
const keys = new Set<string>();
for (const line of content.split('\n')) {
  const trimmed = line.trim();
  if (!trimmed || trimmed.startsWith('#')) continue;
  // 匹配 "KEY=value" 或 "KEY: value"
  const match = trimmed.match(/^([A-Z_][A-Z0-9_]*)\s*[=:]/);
  if (match) keys.add(match[1]);
}

// 生成:
// declare namespace NodeJS {
//   interface ProcessEnv {
//     DB_HOST: string;
//     DB_PORT: string;
//     ...（所有 .env.example 中声明的变量）
//   }
// }
```

生成后：

```typescript
const secret = process.env.JWT_SECRET; // 编辑器自动补全，拼错变量名编译期报错
```

### 4.3 敏感变量拦截：.gitignore 兜底

即使再小心，也可能 `git add .` 把密钥提交上去。`.env*` 的 gitignore 是最后一道防线：

```ini
# 提交真实密钥的灾难性后果：git 历史永久留存，即使删除也能在 commit 记录里找回
.env
.env.local
.env.development
.env.production
!*.env.example    # 模板必须保留在仓库，供他人复制
```

安全配置清单：

| 变量类别 | 处理方式 |
|---------|---------|
| `.env.example` | 提交到 Git，占位符，注释说明每个变量的用途 |
| `.env.development` | 不提交，从 example 复制填真实值 |
| `.env.production` | 不提交，生产服务器上独立配置 |
| `.env.local` | 不提交，个人覆盖（端口、账号差异） |
| 密钥类（JWT_SECRET / DB_PASSWORD / OSS_KEY） | 生产必须强随机，宁可丢弃重配不用弱值 |

> **小结**：④ 收尾。启动校验兜底"弱值"，genEnvTypes 提升开发体验，gitignore 兜底"误提交"。至此环境管理达到生产级。

## 完整示例：怎么加一个新配置（3 步走）

```typescript
// 步骤 1：新建 src/config/smtp.config.ts
export const smtpRegToken = 'smtp';
export const SmtpConfig = registerAs(smtpRegToken, () => ({
  host: env('SMTP_HOST', 'smtp.example.com'),
  port: envNumber('SMTP_PORT', 587),
  user: env('SMTP_USER', ''),
  pass: env('SMTP_PASS', ''),
}));
export type ISmtpConfig = ConfigType<typeof SmtpConfig>;
```

```typescript
// 步骤 2：在 src/config/index.ts 中注册并加入 AllConfigType
export default { SmtpConfig, /* ...已有 */ };
export interface AllConfigType { [smtpRegToken]: ISmtpConfig; /* ... */ }
```

```ini
# 步骤 3：在 .env.example 中添加变量（占位符）+ 相应环境文件中填真实值
SMTP_HOST=smtp.example.com
SMTP_PORT=587
```

> 三个文件各改一处，配置系统自动生效，无需改动业务代码里的读取逻辑。
