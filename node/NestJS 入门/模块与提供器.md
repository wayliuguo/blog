# 模块与提供器


---

## @Module 装饰器

`@Module` 是 NestJS 组织代码的基本单元，每个应用至少有一个根模块。四个字段各管一摊：

> 摘自 `./code/nestjs-basics/src/users/users.module.ts`（运行：`npm start`）

```typescript
@Module({
    imports: [],                                      // 导入其他模块
    controllers: [UsersController, AdminController],  // 该模块下的控制器
    providers: [UsersService],                        // 该模块下的服务/提供器
    exports: [UsersService]                           // 导出给其他模块使用的提供器
})
export class UsersModule {}
```

## 模块化组织代码

业务模块只负责自己那一块，根模块只负责把大家拼起来：

> 摘自 `./code/nestjs-basics/src/app.module.ts`（运行：`npm start`）

```typescript
@Module({
    imports: [
        ConfigModule,                        // @Global 模块，Provider 在所有模块里都能注入
        CacheModule.forRoot({ ttl: 60 }),    // 动态模块：把配置在导入时传进去
        UsersModule,                         // 业务模块
        OrdersModule                        // 业务模块，它自己 imports 了 UsersModule
    ],
    controllers: [AppController],
// …
})
export class AppModule implements NestModule {
```

## 模块共享

通过 `exports` 导出 Provider，其他模块导入后即可使用。**提供方**先注册再导出：

> 摘自 `./code/nestjs-basics/src/config/config.module.ts`（运行：`npm start`）

```typescript
    providers: [
        ConfigService,
        // useValue：注入常量或配置对象，取值要配 @Inject('CONFIG')
        { provide: 'CONFIG', useValue: { port: 3000 } }
    ],
    exports: [ConfigService, 'CONFIG']
```

**使用方**在 `imports` 里引入，之后就能注入对方 `exports` 出来的 Provider：

> 摘自 `./code/nestjs-basics/src/orders/orders.module.ts`（运行：`npm start`）

```typescript
@Module({
    imports: [UsersModule, CacheModule],  // 导入其他模块
    controllers: [OrdersController],      // 该模块下的控制器
    providers: [OrdersService],           // 该模块下的服务/提供器
    exports: [OrdersService]              // 导出给其他模块使用的提供器
})
export class OrdersModule implements NestModule {
```

实测输出（`curl -H "Authorization: Bearer demo-token" http://localhost:3000/orders/stats`，`OrdersService` 直接用到了 `UsersModule` 导出的 `UsersService`——`users: 2` 就是它数出来的）：

```
{"code":0,"data":{"orders":0,"users":2,"port":3000},"message":"success"}
```

## 全局模块

使用 `@Global()` 将模块标记为全局，它的 Provider 在所有模块中可用，无需导入：

> 摘自 `./code/nestjs-basics/src/config/config.module.ts`（运行：`npm start`）

```typescript
@Global()
@Module({
    providers: [
        ConfigService,
        // useValue：注入常量或配置对象，取值要配 @Inject('CONFIG')
        { provide: 'CONFIG', useValue: { port: 3000 } }
    ],
    exports: [ConfigService, 'CONFIG']
})
export class ConfigModule {}
```

> 注意：全局模块只用于真正需要全局共享的模块（如配置、日志），不要滥用。上面 `OrdersModule` 并没有 `import ConfigModule`，却能注入 `'CONFIG'`——`/orders/stats` 里的 `port: 3000` 就是它。

## 动态模块

动态模块允许在导入时传入配置参数，广泛用于库模块。套路是给模块加一个 `static forRoot(options): DynamicModule`：

> 摘自 `./code/nestjs-basics/src/cache/cache.module.ts`（运行：`npm start`）

```typescript
@Module({})
export class CacheModule {
    // forRoot：同步配置，导入时直接把参数传进来
    static forRoot(options: CacheModuleOptions): DynamicModule {
        return {
            module: CacheModule,
            providers: [
                {
                    provide: 'CACHE_OPTIONS',
                    useValue: options
                },
                CacheService
            ],
            exports: [CacheService]
        }
    }
// …
}
```

使用方在 `imports` 里调用它、把配置传进去：

> 摘自 `./code/nestjs-basics/src/app.module.ts`（运行：`npm start`）

```typescript
        CacheModule.forRoot({ ttl: 60 }),    // 动态模块：把配置在导入时传进去
```

实测输出（`curl -H "Authorization: Bearer demo-token" http://localhost:3000/health`，`ttl=60s` 正是导入时传进去的那个值，被 `CacheService` 通过 `@Inject('CACHE_OPTIONS')` 拿到了）：

```
{"code":0,"data":{"status":"ok","dbHost":"localhost","cache":"in-memory cache, ttl=60s, size=0"},"message":"success"}
```

### forRoot vs forRootAsync

同步配置就是上面那种写法；异步配置把 `useValue` 换成 `useFactory` + `inject`，从 `ConfigService` 这类别的 Provider 里读：

> 摘自 `./code/nestjs-basics/src/cache/cache.module.ts`（运行：`npm start`）

```typescript
    // forRoot：同步配置，导入时直接把参数传进来
    static forRoot(options: CacheModuleOptions): DynamicModule {
        return {
            module: CacheModule,
            providers: [
                {
                    provide: 'CACHE_OPTIONS',
                    useValue: options
                },
// …
            ],
            exports: [CacheService]
        }
    }

    // forRootAsync：异步配置，从 ConfigService 里读（ConfigModule 是 @Global，所以这里能直接注入）
    static forRootAsync(): DynamicModule {
        return {
            module: CacheModule,
            providers: [
                {
                    provide: 'CACHE_OPTIONS',
                    useFactory: (config: ConfigService) => ({
                        ttl: Number(config.get('CACHE_TTL') ?? 60)
                    }),
                    inject: [ConfigService]
                },
// …
            ],
            exports: [CacheService]
        }
    }
// …
}
```

## 小结

- **@Module 基本单元**：四个字段 `imports`（导入模块）/ `controllers`（挂控制器）/ `providers`（注册服务）/ `exports`（导出给别处用）；根模块唯一，其余从它的 `imports` 递归挂载，这条链决定模块可见性
- **模块共享链条**：注册 → 导出 → 导入，提供方先 `providers` 注册再 `exports`，使用方 `imports` 引入，三步缺一就报 DI 错
- **@Global() 全局模块**：Provider 在所有模块可注入、免导入，只留给配置/日志这类真正全局的东西，不要滥用
- **动态模块**
  - `forRoot`：`static forRoot(options): DynamicModule` 让库在被导入时接收配置参数
  - `forRoot` 与 `forRootAsync`：同步直接传对象，异步用 `imports + inject + useFactory` 从 ConfigService 读配置
