## 微服务

NestJS 内置微服务支持，可以通过 TCP、Redis、Kafka、RabbitMQ 等方式通信。

> 示意片段（无配套脚本）
```typescript
// 微服务模块
@Module({
    imports: [
        ClientsModule.register([
            {
                name: 'USER_SERVICE',
                transport: Transport.TCP,
                options: { host: 'localhost', port: 3001 }
            }
        ])
    ]
})
export class AppModule {}

// 发送消息
@Injectable()
export class AppService {
    constructor(@Inject('USER_SERVICE') private client: ClientProxy) {}

    async getUser(id: number) {
        return this.client.send({ cmd: 'get_user' }, { id }).toPromise()
    }
}
```

### 微服务拆分原则

| 原则 | 说明 |
|------|------|
| 按业务拆分 | 用户服务、订单服务、商品服务 |
| 独立数据库 | 每个服务有自己的数据库 |
| 独立部署 | 每个服务可以独立部署和扩展 |
| 通信方式 | 同步用 HTTP/gRPC，异步用消息队列 |

## WebSocket

NestJS 内置 WebSocket 支持，使用 `@nestjs/websockets`。

> 示意片段（无配套脚本）
```typescript
@WebSocketGateway({
    namespace: '/chat',
    cors: { origin: '*' }
})
export class ChatGateway implements OnGatewayConnection {
    @WebSocketServer()
    server: Server

    // 处理连接
    handleConnection(client: Socket) {
        console.log('用户连接:', client.id)
    }

    // 处理消息
    @SubscribeMessage('message')
    handleMessage(client: Socket, payload: { content: string }) {
        // 广播消息给所有客户端
        this.server.emit('message', {
            clientId: client.id,
            content: payload.content
        })
    }
}
```

## 高可用设计

| 策略 | 说明 |
|------|------|
| 负载均衡 | 多台服务器分担请求 |
| 冗余部署 | 多实例部署，单点故障不影响 |
| 健康检查 | 定期检查服务状态，自动剔除异常节点 |
| 熔断降级 | 服务不可用时，返回降级响应而非崩溃 |
| 限流 | 保护后端不被突发流量打垮 |

## 小结

- **微服务：先拆得开，再连得上**
  1. **连通方式**：`ClientsModule.register` 声明传输方式（TCP / Redis / Kafka / RabbitMQ），`client.send({ cmd }, payload)` 发消息
  2. **拆分原则**：按业务拆（用户/订单/商品）、每个服务独立数据库、独立部署扩展；同步用 HTTP/gRPC，异步用消息队列
- **WebSocket 网关：连接与广播**
  - **网关声明**：`@WebSocketGateway({ namespace, cors })` 声明命名空间与跨域；`handleConnection(client)` 处理连接建立
  - **消息与广播**：`@SubscribeMessage` 处理消息，`server.emit` 广播给所有客户端
- **高可用的五个策略**
  1. **负载均衡**：多台服务器分担请求
  2. **冗余部署**：多实例部署，单点故障不影响
  3. **健康检查**：定期检查服务状态，自动剔除异常节点
  4. **熔断降级**：服务不可用时返回降级响应而非崩溃
  5. **限流**：保护后端不被突发流量打垮
