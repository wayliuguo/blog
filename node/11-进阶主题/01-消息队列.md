## 什么是消息队列

消息队列（Message Queue）是一种异步通信机制，生产者发送消息到队列，消费者从队列中取消息。

### 为什么需要消息队列

```
同步调用：下单 → 扣库存 → 发短信 → 发邮件 → 积分（用户等待全部完成）
异步调用：下单 → 消息队列 → 扣库存、发短信、发邮件同时进行（用户只等下单）
```

### 核心作用

| 作用 | 说明 | 类比 |
|------|------|------|
| 异步处理 | 非核心操作异步执行 | 餐厅点完餐后，不用等炒菜 |
| 削峰填谷 | 请求高峰时缓冲 | 水库蓄水，防止下游洪灾 |
| 解耦 | 生产者和消费者不直接依赖 | 发布订阅，彼此不需要知道对方 |

## Kafka 核心概念

| 概念 | 说明 |
|------|------|
| Producer | 发送消息的应用程序 |
| Consumer | 消费消息的应用程序 |
| Topic | 消息的分类，类似数据库的表 |
| Partition | Topic 的分区，实现并行处理 |
| Broker | Kafka 集群中的服务器 |
| Consumer Group | 消费者组，组内消费者负载均衡消费 |

```
Topic: orders
├── Partition 0  → Consumer Group A (Consumer 1, Consumer 2)
├── Partition 1  → Consumer Group A
└── Partition 2  → Consumer Group A
```

## 消息队列选型对比

| 特性 | Kafka | RabbitMQ | Redis Stream |
|------|-------|----------|-------------|
| 吞吐量 | 极高（百万级/秒） | 高（万级/秒） | 高（万级/秒） |
| 消息持久化 | 磁盘 | 磁盘 | 内存+磁盘 |
| 消息顺序 | 分区内有序 | 单队列有序 | 有序 |
| 适用场景 | 日志、大数据、流处理 | 业务系统、任务分发 | 简单消息、缓存场景 |
| 学习成本 | 高 | 中 | 低 |

## 小结

- **消息队列的本质：把同步调用拆成异步通信**
  - **什么是消息队列**：生产者发消息到队列、消费者从队列取消息的异步通信机制
  - **同步 vs 异步**：同步是下单后等扣库存、发短信、发邮件、算积分全部完成；异步只让用户等下单，其余由队列驱动
- **队列带来的三大作用**
  1. **异步处理**：非核心操作异步执行，用户不必等全部完成
  2. **削峰填谷**：请求高峰时缓冲，像水库蓄水一样防止下游被冲垮
  3. **解耦**：生产者和消费者不直接依赖，彼此不需要知道对方
- **Kafka 的六个核心概念**
  1. **Producer**：发送消息的应用程序
  2. **Consumer**：消费消息的应用程序
  3. **Topic**：消息的分类，类似数据库的表
  4. **Partition**：Topic 的分区，实现并行处理
  5. **Broker**：Kafka 集群中的服务器
  6. **Consumer Group**：消费者组，组内消费者负载均衡消费
- **选型对比：Kafka / RabbitMQ / Redis Stream**
  1. **Kafka**：吞吐极高（百万级/秒），落磁盘、分区内有序，适合日志、大数据与流处理；学习成本高
  2. **RabbitMQ**：吞吐高（万级/秒），落磁盘、单队列有序，适合业务系统与任务分发；学习成本中
  3. **Redis Stream**：吞吐高（万级/秒），内存+磁盘、有序，轻量，适合简单消息与缓存场景；学习成本低
