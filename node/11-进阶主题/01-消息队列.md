## 什么是消息队列

消息队列（Message Queue）是一种异步通信机制，生产者发送消息到队列，消费者从队列中取消息。

### 为什么需要消息队列

```
同步调用：下单 → 扣库存 → 发短信 → 发邮件 → 积分（用户等待全部完成）
异步调用：下单 → 消息队列 → 扣库存、发短信、发邮件同时进行（用户只等下单）
```

### 核心作用

| 作用 | 说明 | 类比 |
|------|------|------|
| 异步处理 | 非核心操作异步执行 | 餐厅点完餐后，不用等炒菜 |
| 削峰填谷 | 请求高峰时缓冲 | 水库蓄水，防止下游洪灾 |
| 解耦 | 生产者和消费者不直接依赖 | 发布订阅，彼此不需要知道对方 |

## Kafka 核心概念

| 概念 | 说明 |
|------|------|
| Producer | 发送消息的应用程序 |
| Consumer | 消费消息的应用程序 |
| Topic | 消息的分类，类似数据库的表 |
| Partition | Topic 的分区，实现并行处理 |
| Broker | Kafka 集群中的服务器 |
| Consumer Group | 消费者组，组内消费者负载均衡消费 |

```
Topic: orders
├── Partition 0  → Consumer Group A (Consumer 1, Consumer 2)
├── Partition 1  → Consumer Group A
└── Partition 2  → Consumer Group A
```

## 消息队列选型对比

| 特性 | Kafka | RabbitMQ | Redis Stream |
|------|-------|----------|-------------|
| 吞吐量 | 极高（百万级/秒） | 高（万级/秒） | 高（万级/秒） |
| 消息持久化 | 磁盘 | 磁盘 | 内存+磁盘 |
| 消息顺序 | 分区内有序 | 单队列有序 | 有序 |
| 适用场景 | 日志、大数据、流处理 | 业务系统、任务分发 | 简单消息、缓存场景 |
| 学习成本 | 高 | 中 | 低 |
