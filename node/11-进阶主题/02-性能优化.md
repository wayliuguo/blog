## 缓存策略

| 问题 | 现象 | 解决方案 |
|------|------|---------|
| 缓存穿透 | 查询不存在的数据，每次都穿透到数据库 | 缓存空值、布隆过滤器 |
| 缓存击穿 | 热点 key 过期瞬间，大量请求打到数据库 | 互斥锁、热点数据永不过期 |
| 缓存雪崩 | 大量 key 同时过期，数据库压力暴增 | 过期时间加随机值、多级缓存 |

## 并发限流

### 限流算法

| 算法 | 说明 | 特点 |
|------|------|------|
| 计数器 | 固定时间窗口内计数 | 实现简单，有突刺问题 |
| 滑动窗口 | 细粒度时间窗口 | 解决突刺，更平滑 |
| 令牌桶 | 匀速放入令牌，请求消耗令牌 | 允许突发流量 |
| 漏桶 | 匀速处理请求 | 平滑流量，不允许突发 |

### NestJS 限流

```bash
npm install @nestjs/throttler
```

> 示意片段（无配套脚本）
```typescript
@Module({
    imports: [
        ThrottlerModule.forRoot({
            ttl: 60000,     // 时间窗口（60秒）
            limit: 10,      // 窗口内允许的最大请求数
        })
    ]
})
export class AppModule {}

// 使用
@Controller('users')
export class UserController {
    @Throttle(5, 60000)  // 覆盖默认：60秒内最多5次
    @Get('search')
    search(@Query('q') q: string) {}
}
```

## 数据库优化

| 优化手段 | 说明 |
|---------|------|
| 索引优化 | 合理建索引，避免全表扫描 |
| 慢查询日志 | 定位慢 SQL，用 EXPLAIN 分析 |
| 连接池 | 复用数据库连接，避免频繁创建 |
| 读写分离 | 主库写，从库读 |
| 分库分表 | 数据量大时水平拆分 |

## 小结

- **缓存的三种失效场景与对策**
  1. **缓存穿透**：查不存在的数据每次都打到库；对策是缓存空值或上布隆过滤器
  2. **缓存击穿**：热点 key 过期瞬间大量请求涌向数据库；对策是互斥锁或热点数据永不过期
  3. **缓存雪崩**：大量 key 同时过期把数据库压垮；对策是过期时间加随机值、多级缓存
- **限流的四种算法**
  1. **计数器**：固定时间窗口内计数，实现简单但有突刺问题
  2. **滑动窗口**：细粒度时间窗口，解决突刺、更平滑
  3. **令牌桶**：匀速放入令牌、请求消耗令牌，允许突发流量
  4. **漏桶**：匀速处理请求，平滑流量但不允许突发
- **NestJS 限流落地**
  - **全局配置**：`ThrottlerModule.forRoot({ ttl: 60000, limit: 10 })` 定 60 秒窗口、窗口内最多 10 次
  - **按接口覆盖**：`@Throttle(5, 60000)` 让单个路由在 60 秒内最多 5 次
- **数据库优化的五个手段**
  1. **索引优化**：合理建索引，避免全表扫描
  2. **慢查询日志**：定位慢 SQL，用 EXPLAIN 分析
  3. **连接池**：复用数据库连接，避免频繁创建
  4. **读写分离**：主库写，从库读
  5. **分库分表**：数据量大时水平拆分
