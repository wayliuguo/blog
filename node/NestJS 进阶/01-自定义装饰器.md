## 参数装饰器

使用 `createParamDecorator` 创建自定义参数装饰器：

### @CurrentUser() 获取当前用户

> 摘自 `./code/advanced-lab/src/01-decorators.ts`（运行：`npm run 01decorators`）

```typescript
import { createParamDecorator, ExecutionContext } from '@nestjs/common'

// …

// ====== 1) 参数装饰器：@CurrentUser() ======
// createParamDecorator 的回调签名是 (data, ctx)：
//   - data：装饰器使用处传进来的参数，@CurrentUser() 是 undefined，@CurrentUser('id') 是 'id'
//   - ctx：ExecutionContext，用 ctx.switchToHttp().getRequest() 取到原始请求对象
export const CurrentUser = createParamDecorator(
    (data: string | undefined, ctx: ExecutionContext) => {
        const request = ctx.switchToHttp().getRequest()
        const user = request.user // 假设在 Guard 中已经设置了 user

        // 如果传了参数（如 @CurrentUser('id')），返回指定字段
        return data ? user?.[data] : user
    }
)

// …

@Controller('profile')
export class ProfileController {
    @Get('me')
    getProfile(@CurrentUser() user: { id: number; name: string; roles: string[] }) {
        return user
    }

    @Get('id')
    getProfileId(@CurrentUser('id') userId: number) {
        return { userId }
    }

    // …（还有一个 @Post('touch')，同样用 @CurrentUser() 取当前用户）
}
```

实测输出（`npm run 01decorators` 第 1 段；`x-user-*` 三个请求头由脚本里的“造用户守卫”读出来挂到 `request.user`，模拟认证已经跑过）：

```
=== 1) @CurrentUser()：整个 user 对象 vs 指定字段 ===
[LogGuard] type=http 调用: ProfileController.getProfile GET /profile/me
[LogGuard] 这个 handler 的返回码将是 200
  GET    /profile/me      → 200 {"id":1,"name":"boss","roles":["admin","editor"]}
[LogGuard] type=http 调用: ProfileController.getProfileId GET /profile/id
[LogGuard] 这个 handler 的返回码将是 200
  GET    /profile/id      → 200 {"userId":3}
```

`@CurrentUser()` 拿到整个 `user`，`@CurrentUser('id')` 只拿 `id`——差别就是回调里那个 `data` 参数。

## 自定义方法装饰器

使用 `SetMetadata` 和 `Reflector` 实现自定义方法装饰器：

> 摘自 `./code/advanced-lab/src/01-decorators.ts`（运行：`npm run 01decorators`）

```typescript
// ====== 2) 方法装饰器：@Roles() 只负责打标签 ======
// SetMetadata 返回一个装饰器，把 (key, value) 写进类/方法的元数据，本身不做任何判断
export const Roles = (...roles: string[]) => SetMetadata('roles', roles)

// …

@Injectable()
class UserService {
    remove(id: number) {
        return { deleted: id }
    }
}

// …

@Controller('users')
export class UserController {
    constructor(private readonly userService: UserService) {}

    @Roles('admin') // 只有 admin 可以访问
    @Delete(':id')
    remove(@Param('id') id: string) {
        return this.userService.remove(+id)
    }
}
```

实测输出（`npm run 01decorators` 第 2 段；同一个接口换一个身份，结果完全不同）：

```
=== 2) @Roles("admin") + RolesGuard：标签决定放行还是 403 ===
[LogGuard] type=http 调用: UserController.remove DELETE /users/7
[LogGuard] 这个 handler 的返回码将是 200
  DELETE /users/7         → 200 {"deleted":7}
[LogGuard] type=http 调用: UserController.remove DELETE /users/7
[LogGuard] 这个 handler 的返回码将是 200
  DELETE /users/7         → 403 {"message":"Forbidden resource","error":"Forbidden","statusCode":403}
```

`@Roles('admin')` 本身只是往方法上写了一条 `roles` 元数据，真正拦人的是下面这个 Guard。

### 配合 Guard 实现权限控制

> 摘自 `./code/advanced-lab/src/01-decorators.ts`（运行：`npm run 01decorators`）

```typescript
@Injectable()
export class RolesGuard implements CanActivate {
    constructor(private reflector: Reflector) {}

    canActivate(context: ExecutionContext): boolean {
        // 获取方法上的 roles 元数据
        const requiredRoles = this.reflector.getAllAndOverride<string[]>('roles', [
            context.getHandler(),
            context.getClass()
        ])

        if (!requiredRoles) return true // 没有设置角色限制，放行

        const { user } = context.switchToHttp().getRequest()
        return requiredRoles.some(role => user.roles?.includes(role))
    }
}

// …

@Controller('admin')
@UseGuards(RolesGuard)
export class AdminController {
    @Roles('admin')
    @Get('stats')
    getStats() {
        return { visits: 42 }
    }
}
```

实测输出（`npm run 01decorators` 第 3 段，控制器级 `@UseGuards` + 方法级 `@Roles`）：

```
=== 3) 控制器级 @UseGuards(RolesGuard) + 方法级 @Roles() ===
[LogGuard] type=http 调用: AdminController.getStats GET /admin/stats
[LogGuard] 这个 handler 的返回码将是 200
  GET    /admin/stats     → 200 {"visits":42}
[LogGuard] type=http 调用: AdminController.getStats GET /admin/stats
[LogGuard] 这个 handler 的返回码将是 200
  GET    /admin/stats     → 403 {"message":"Forbidden resource","error":"Forbidden","statusCode":403}
```

## 装饰器组合

使用 `applyDecorators` 组合多个装饰器：

> 摘自 `./code/advanced-lab/src/01-decorators.ts`（运行：`npm run 01decorators`）

```typescript
// ====== 4) 装饰器组合：@Auth() ======
// applyDecorators 把多个装饰器合成一个，声明一次、多处生效
export function Auth(...roles: string[]) {
    return applyDecorators(
        SetMetadata('roles', roles),
        UseGuards(RolesGuard)
        // 真实项目里还会合并 Swagger 装饰器，如 ApiBearerAuth()（来自 @nestjs/swagger）
    )
}

// …

@Controller('documents')
export class DocumentController {
    @Auth('admin', 'editor')
    @Delete(':id')
    remove(@Param('id') id: string) {
        return { deleted: id }
    }
}
```

实测输出（`npm run 01decorators` 第 4 段，`@Auth('admin', 'editor')` 一次声明两个角色）：

```
=== 4) @Auth("admin", "editor")：applyDecorators 一次声明两个角色 ===
[LogGuard] type=http 调用: DocumentController.remove DELETE /documents/9
[LogGuard] 这个 handler 的返回码将是 200
  DELETE /documents/9     → 200 {"deleted":"9"}
[LogGuard] type=http 调用: DocumentController.remove DELETE /documents/9
[LogGuard] 这个 handler 的返回码将是 200
  DELETE /documents/9     → 403 {"message":"Forbidden resource","error":"Forbidden","statusCode":403}
```

## ExecutionContext 详解

`ExecutionContext` 是 NestJS 的核心接口，用于获取当前执行上下文的信息。

> 摘自 `./code/advanced-lab/src/01-decorators.ts`（运行：`npm run 01decorators`）

```typescript
// ====== 5) ExecutionContext：守卫里能拿到什么 ======
@Injectable()
export class LogGuard implements CanActivate {
    canActivate(context: ExecutionContext): boolean {
        // 获取请求类型
        const type = context.getType() // 'http' | 'rpc' | 'ws'

        // HTTP 上下文
        const request = context.switchToHttp().getRequest()
        const response = context.switchToHttp().getResponse()

        // 获取控制器和方法
        const controller = context.getClass() // UserController
        const handler = context.getHandler() // findAll

        console.log(`[LogGuard] type=${type} 调用: ${controller.name}.${handler.name} ${request.method} ${request.url}`)
        console.log(`[LogGuard] 这个 handler 的返回码将是 ${response.statusCode}`)

        return true
    }
}
```

上面三段实测输出里每一行请求前都夹着两行 `[LogGuard]`，就是这段代码打的——`type` 是 `http`，`controller.handler` 正好是被调用的那个类与方法，`request` / `response` 拿到的就是 Express 的原始对象。

## 小结

- **参数装饰器**：`createParamDecorator` 回调是 `(data, ctx)`，用 `ctx.switchToHttp().getRequest()` 取数据；`@CurrentUser()` 返回整个 `user`，`@CurrentUser('id')` 按字段名只返回指定字段
- **方法装饰器：打标签与读标签**：`SetMetadata` 只写标签不干活的（如 `const Roles = (...roles) => SetMetadata('roles', roles)`），权限判断留给 Guard；`Reflector.getAllAndOverride` 方法上的元数据覆盖类上的，参数顺序固定 `[getHandler(), getClass()]`
- **装饰器组合**：`applyDecorators` 把 `SetMetadata` + `UseGuards` + Swagger 装饰器合成一个 `@Auth('admin', 'editor')`，一处声明多处生效
- **ExecutionContext 四种能力**：`getType()` 判断 `http`/`rpc`/`ws`；`switchToHttp()` 取 `getRequest()`/`getResponse()`；`getClass()` 拿控制器类；`getHandler()` 拿被调用方法
