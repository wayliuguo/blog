# 定时任务与队列

## 定时任务（@nestjs/schedule）

### 安装

```bash
npm install @nestjs/schedule
```

### 注册模块

> 摘自 `./code/advanced-lab/src/06-schedule.ts`（运行：`npm run 06schedule`）

```typescript
@Module({
    imports: [ScheduleModule.forRoot()],
    providers: [TasksService, TaskManager]
})
export class AppModule {}
```

少了 `ScheduleModule.forRoot()`，`@Cron` / `@Timeout` / `@Interval` 全都只是死标签，`SchedulerRegistry` 也注入不进来。

### 定义定时任务

> 摘自 `./code/advanced-lab/src/06-schedule.ts`（运行：`npm run 06schedule`）

```typescript
@Injectable()
export class TasksService {
    private readonly logger = new Logger(TasksService.name)

    // 每天凌晨 2 点执行
    @Cron(CronExpression.EVERY_DAY_AT_2AM)
    handleDailyReport() {
        this.logger.log('生成昨日销售报表...')
        // 查询数据库 → 生成报表 → 发送邮件
    }

    // 每 10 分钟执行一次
    @Cron('*/10 * * * *')
    handleHealthCheck() {
        // 检查服务健康状态
    }

    // 延迟执行（相对时间，仅一次）
    @Timeout(5000) // 5 秒后执行
    handleTimeout() {
        console.log('启动后 5 秒执行')
    }

    // 间隔执行
    @Interval(10000) // 每 10 秒执行
    handleInterval() {
        console.log('每 10 秒执行一次')
    }
}
```

实测输出（`npm run 06schedule`，脚本一共跑十几秒：能看到 `@Timeout(5000)` 打一次、`@Interval(10000)` 在 10 秒时打第一条；两个 `@Cron` 的表达式分别是「每天 2 点」和「每 10 分钟」，十几秒内不会触发）：

```
=== 1) 动态加一个「每 2 秒」的任务 ===
[t=0.0s] addCronJob('heartbeat', '*/2 * * * * *') 完成，isActive = true
  等 6 秒，看它自己跑起来...
任务 heartbeat 执行
任务 heartbeat 执行
启动后 5 秒执行
任务 heartbeat 执行

=== 2) 停掉它 ===
[t=6.0s] stopJob('heartbeat') 之后 isActive = false
  再等 4 秒，看上面那种「任务 heartbeat 执行」还有没有继续出现...
每 10 秒执行一次

=== 3) 10 秒过去，回头看注册表里到底有什么 ===
  当前时刻 [t=10.1s]
  getCronJobs()   → ["4bf17062-d9aa-41a5-bf92-6f5dfca34580","43ca0c1f-0aa5-46fa-a857-0b03a2576d66","heartbeat"]
  getIntervals()  → ["f713c538-113f-4661-8c61-9e5ecff419c0"]
  getTimeouts()   → ["1c2e2193-1d3e-441b-a259-afb021be5693"]

=== 4) 收尾 ===
  说明：@Timeout(5000) 打了「启动后 5 秒执行」且只打一次；@Interval(10000) 在 10 秒时打了第一条。
  说明：两个 @Cron 装饰器也进了 getCronJobs()，名字是框架自动生成的 UUID；
  说明：@Timeout / @Interval 不进 getCronJobs()，它们分别在 getTimeouts() / getIntervals() 里。
  说明：@Cron(EVERY_DAY_AT_2AM) 与 @Cron("*/10 * * * *") 在十几秒内不会触发，所以看不到它们。
```

第 3 段那三行把三类任务分得很清楚：装饰器写的 `@Cron` 也用 UUID 名字进了 `getCronJobs()`，而 `@Timeout` / `@Interval` 分别躺在 `getTimeouts()` / `getIntervals()` 里——所以想「列出所有任务」，三张表都得看。

### 动态控制任务

> 摘自 `./code/advanced-lab/src/06-schedule.ts`（运行：`npm run 06schedule`）

```typescript
@Injectable()
export class TaskManager {
    constructor(private schedulerRegistry: SchedulerRegistry) {}

    // 动态添加任务
    addCronJob(name: string, cronTime: string) {
        const job = new CronJob(cronTime, () => {
            console.log(`任务 ${name} 执行`)
        })
        this.schedulerRegistry.addCronJob(name, job)
        job.start()
    }

    // 停止任务
    stopJob(name: string) {
        const job = this.schedulerRegistry.getCronJob(name)
        job.stop()
    }

    // 获取所有任务
    getJobs() {
        return this.schedulerRegistry.getCronJobs()
    }
}
```

实测输出见上面第 1、2 段：`addCronJob('heartbeat', '*/2 * * * * *')` 之后每 2 秒打一行「任务 heartbeat 执行」，`stopJob('heartbeat')` 之后 `isActive` 变成 `false`，再等 4 秒也没有新行——动态注册和动态停止都生效了。这里用的是 6 段的秒级表达式（`秒 分 时 日 月 周`），装饰器上那两个是标准 5 段表达式。

## 消息队列（@nestjs/bull）

### 安装

```bash
npm install @nestjs/bull bull
npm install -D @types/bull
```

下面三段代码来自配套脚本 `./code/advanced-lab/src/06-queue.ts`。Bull 的队列数据**全在 Redis 里**，所以这个文件只做结构与类型演示、不建连接——`npm run typecheck` 能过，`npm run 06queue` 只打印一段说明；本机没起 Redis，所以下面三段**没有实测输出**。想看真实收发，先 `redis-server`（或 `docker run -p 6379:6379 redis`）。

### 注册模块

> 摘自 `./code/advanced-lab/src/06-queue.ts`（运行：`npm run 06queue`，需要本地 Redis）

```typescript
@Module({
    imports: [
        BullModule.forRoot({
            redis: {
                host: 'localhost',
                port: 6379
            }
        }),
        BullModule.registerQueue({
            name: 'email' // 队列名称
        })
    ],
    providers: [EmailProcessor, EmailQueue]
})
export class QueueModule {}
```

`forRoot` 只配一次（Redis 连接），每个队列再用 `registerQueue` 登记；`name: 'email'` 这个字符串就是后面 `@InjectQueue('email')` 和 `@Processor('email')` 对上的凭据。

### 生产者：发送任务

> 摘自 `./code/advanced-lab/src/06-queue.ts`（运行：`npm run 06queue`，需要本地 Redis）

```typescript
@Injectable()
export class EmailQueue {
    constructor(@InjectQueue('email') private emailQueue: Queue) {}

    // 发送验证邮件
    async sendVerification(to: string, code: string) {
        await this.emailQueue.add(
            'verification',
            {
                to,
                code
            },
            {
                attempts: 3, // 最多重试 3 次
                backoff: 5000, // 重试间隔 5 秒
                removeOnComplete: true
            }
        )
    }

    // 延迟发送（预约邮件）
    async scheduleEmail(to: string, content: string, delayMs: number) {
        await this.emailQueue.add(
            'scheduled',
            {
                to,
                content
            },
            {
                delay: delayMs // 延迟执行
            }
        )
    }
}
```

`add(任务名, 数据, 选项)` 三个参数里，任务名决定谁消费（对应下面的 `@Process`），数据是消费者能拿到的 `job.data`，选项管重试与延迟：`attempts: 3` 最多重试 3 次、`backoff: 5000` 每次间隔 5 秒、`removeOnComplete: true` 完成后清理记录、`delay` 让它晚点再被取走（订单超时取消就靠它）。

### 消费者：处理任务

> 摘自 `./code/advanced-lab/src/06-queue.ts`（运行：`npm run 06queue`，需要本地 Redis）

```typescript
@Processor('email')
export class EmailProcessor {
    @Process('verification')
    async handleVerification(job: Job<{ to: string; code: string }>) {
        const { to, code } = job.data
        console.log(`发送验证码 ${code} 到 ${to}`)
        // 调用邮件服务...
    }

    @Process('scheduled')
    async handleScheduled(job: Job<{ to: string; content: string }>) {
        console.log(`发送预约邮件到 ${job.data.to}`)
        // 调用邮件服务...
    }
}
```

`@Processor('email')` 标类、`@Process('verification')` 标方法，两级名字和生产者那边一一对应；方法参数是 `job`，投递时传的数据在 `job.data` 里。`npm run typecheck` 的输出里能看到这三个类都通过了类型校验：

```
06-queue.ts 只做结构演示：Bull 的队列数据全在 Redis 里，没有 Redis 看不到真实收发。
  校验编译：npm run typecheck
  真实运行：先 redis-server（或 docker run -p 6379:6379 redis），再把这个文件挂进 Nest 应用启动。
  本文件定义了：QueueModule / EmailQueue / EmailProcessor
```

## 生产场景对比

| 场景 | 方案 | 原因 |
|------|------|------|
| 每日报表生成 | `@Cron` | 固定时间执行，无需队列 |
| 发送验证码邮件 | Bull 队列 | 异步执行，失败自动重试 |
| 订单超时取消 | Bull 延迟任务 | 30 分钟不支付则取消 |
| 用户注册欢迎邮件 | Bull 队列 | 主流程不阻塞，异步发送 |
| 健康检查 | `@Interval` | 固定间隔，轻量级 |
