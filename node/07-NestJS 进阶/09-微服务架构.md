# 微服务架构

> NestJS 原生支持微服务架构，通过不同的传输层（TCP、Redis、RabbitMQ、Kafka 等）实现服务间通信。

---

## 微服务架构概览

```
                    ┌──────────────┐
                    │  API 网关     │
                    │  (HTTP)       │
                    └──────┬───────┘
                           │
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
    ┌────────────┐  ┌────────────┐  ┌────────────┐
    │ 用户服务    │  │ 订单服务   │  │ 商品服务   │
    │ (TCP:3001)  │  │(TCP:3002)  │  │(TCP:3003)  │
    └────────────┘  └────────────┘  └────────────┘
```

## 创建微服务

```typescript
// microservices/user/src/main.ts
import { NestFactory } from '@nestjs/core'
import { MicroserviceOptions, Transport } from '@nestjs/microservices'
import { UserModule } from './user.module'

async function bootstrap() {
    const app = await NestFactory.createMicroservice<MicroserviceOptions>(
        UserModule,
        {
            transport: Transport.TCP,
            options: {
                host: '0.0.0.0',
                port: 3001,
            },
        },
    )
    await app.listen()
}
```

### 定义微服务控制器

```typescript
import { Controller } from '@nestjs/common'
import { MessagePattern, Payload } from '@nestjs/microservices'

@Controller()
export class UserController {
    @MessagePattern({ cmd: 'get_user' })
    getUser(@Payload() data: { id: number }) {
        // 查询用户信息
        return { id: data.id, name: '张三', email: 'zhangsan@example.com' }
    }

    @MessagePattern({ cmd: 'create_user' })
    createUser(@Payload() data: { name: string; email: string }) {
        // 创建用户
        return { id: 1, ...data }
    }
}
```

## API 网关（TCP 客户端）

```typescript
// api-gateway/src/user/user.controller.ts
import { Controller, Get, Post, Body, Inject } from '@nestjs/common'
import { ClientProxy } from '@nestjs/microservices'

@Controller('users')
export class UserController {
    constructor(
        @Inject('USER_SERVICE') private userClient: ClientProxy,
    ) {}

    @Get(':id')
    async getUser(id: number) {
        // 通过 TCP 调用用户微服务
        return this.userClient.send(
            { cmd: 'get_user' },
            { id },
        )
    }
}
```

### 客户端连接配置

```typescript
// api-gateway/src/app.module.ts
import { Module } from '@nestjs/common'
import { ClientsModule, Transport } from '@nestjs/microservices'

@Module({
    imports: [
        ClientsModule.register([
            {
                name: 'USER_SERVICE',
                transport: Transport.TCP,
                options: { host: 'localhost', port: 3001 },
            },
            {
                name: 'ORDER_SERVICE',
                transport: Transport.TCP,
                options: { host: 'localhost', port: 3002 },
            },
        ]),
    ],
    controllers: [UserController],
})
export class AppModule {}
```

## 传输方式对比

| 传输 | 特点 | 适用场景 |
|------|------|---------|
| **TCP** | 点对点、简单、低延迟 | 内部服务间通信，中小规模 |
| **Redis** | 基于 Pub/Sub，无需额外中间件 | 已有 Redis 的场景 |
| **RabbitMQ** | 消息持久化、路由灵活、ACK 机制 | 需要可靠投递的场景 |
| **Kafka** | 高吞吐、分区、持久化 | 大数据量、日志收集 |

## 生产场景：用户注册流程

```
API 网关 (HTTP)
    │
    ├── TCP ──→ 用户微服务：创建用户
    │
    ├── RMQ ──→ 邮件微服务：发送验证邮件（异步）
    │
    ├── RMQ ──→ 积分微服务：赠送注册积分（异步）
    │
    └── TCP ──→ 日志微服务：记录操作日志
```

## 面试题

### Q1: 微服务间通信有哪几种方式？NestJS 分别如何实现？

同步通信（TCP/RMQ 的 RPC 模式）用 `ClientProxy.send()`，异步通信（RMQ 的消息队列）用 `ClientProxy.emit()`。NestJS 通过 `@MessagePattern()` 和 `@EventPattern()` 区分。

### Q2: 微服务如何保证数据一致性？

分布式事务通常用 Saga 模式（编排/ choreography）或 TCC（Try-Confirm-Cancel）。NestJS 推荐结合消息队列实现最终一致性：先执行业务，再发消息，下游消费失败通过重试机制补偿。
