# 环境变量与常用内置模块

## 环境变量：`process.env` 与 `.env` 文件
`process.env` 是启动时注入的环境变量对象，常用于区分环境、存放敏感配置：

> 摘自 `./code/环境变量与常用内置模块/src/env/env.js`（运行：`npm run env`）

```js
// 1) process.env 是启动时注入的环境变量对象，值一律是字符串
console.log('NODE_ENV =', process.env.NODE_ENV)
console.log('DB_HOST =', process.env.DB_HOST)

// 2) 未设置的变量是 undefined，读取时给默认值是常见写法
const port = Number(process.env.PORT) || 3000
console.log('PORT =', process.env.PORT, '，缺省回退后 =', port)
```

实测输出（`npm run env`，通过 `node --env-file=src/env/.env src/env/env.js` 启动）：

```
NODE_ENV = development
DB_HOST = localhost
PORT = 3000 ，缺省回退后 = 3000
```

环境变量通常不直接写在启动命令里，而是放进 `.env` 文件：

```bash
# .env（真实项目里不要提交 Git！可能含数据库密码、API Key）
NODE_ENV=development
PORT=3000
DB_HOST=localhost
DB_PASSWORD=mysecret
```

加载用 Node 20.6+ 内置的 `--env-file` 启动参数，**无需第三方依赖**：

```bash
node --env-file=.env app.js
```

**为何不提交 `.env`？** 它常含密钥，提交等于公开密码；正确做法是 `.env.example` 进仓库、真实 `.env` 进 `.gitignore`。`NODE_ENV` 的通行用法：`development` 开调试、`production` 关调试走优化，很多库都读它决定行为。

## os 模块：机器信息与并行度决策
`os` 模块提供机器信息，是多进程 / 多 Worker 数量决策的依据：

- `os.cpus()`：CPU 核心数组（看核数）
- `os.totalmem()` / `os.freemem()`：总内存 / 空闲内存（字节）
- `os.availableParallelism()`：Node 推荐的并行 Worker 数，比硬编码 `os.cpus().length` 更贴合调度建议——`cluster` 决定开几个 Worker 就用它
- `os.homedir()` / `os.tmpdir()`：用户主目录 / 系统临时目录（临时文件别自己造路径，用它）

> 摘自 `./code/环境变量与常用内置模块/src/os/os.js`（运行：`npm run os`）

```js
const os = require('node:os')

console.log('CPU 核数（os.cpus().length）:', os.cpus().length)
console.log('可用并行度（os.availableParallelism）:', os.availableParallelism())
console.log('总内存:', (os.totalmem() / 1024 / 1024 / 1024).toFixed(1), 'GB')
console.log('用户主目录:', os.homedir())
console.log('系统临时目录:', os.tmpdir())
```

实测输出（`npm run os`，数值随机器而异）：

```
CPU 核数（os.cpus().length）: 8
可用并行度（os.availableParallelism）: 8
总内存: 15.9 GB
空闲内存: 4.1 GB
用户主目录: C:\Users\10855
系统临时目录: C:\Users\10855\AppData\Local\Temp
平台: win32 ，主机名: DESKTOP-NJ6MMM0
```

## path 模块：拼路径、取片段与绝对路径解析
写代码时"路径从哪来"是个高频问题。两个答案：

- **引用自己模块里的文件**：用 CommonJS 模块自带的 `__dirname`（当前文件所在目录绝对路径）/ `__filename`（当前文件绝对路径），它们**不依赖命令执行位置**——从哪个目录启动 node，值都不变
- **基于命令执行位置**：`path.resolve(...)` 从右往左解析、遇绝对路径即停，得到基于 `cwd` 的绝对路径

其余核心 API：`path.join(...)` 按段拼接、跨平台（Windows `\`、Linux `/` 自动处理，**永远不手写分隔符**）；`basename` / `dirname` / `extname` 取文件名 / 目录 / 扩展名；`path.parse` 把路径拆成结构化对象。

> 摘自 `./code/环境变量与常用内置模块/src/path/path.js`（运行：`npm run path`）

```js
// path 核心用法：__dirname 定位、拼接、取片段、解析成绝对路径
const path = require('node:path')

// 1) __dirname / __filename：CommonJS 模块自带的绝对路径，不用自己拼、不依赖 cwd
console.log('__dirname  =', __dirname)
console.log('__filename =', __filename)

// 2) path.join：按段拼接，跨平台（Windows '\'、Linux '/' 自动处理），永远不手写分隔符
console.log('path.join     =', path.join(__dirname, 'output', 'hello.txt'))

// 3) 取片段：basename 文件名 / dirname 目录部分 / extname 扩展名
console.log('path.basename =', path.basename('/users/docs/file.txt')) // file.txt
console.log('path.dirname  =', path.dirname('/users/docs/file.txt')) // /users/docs
console.log('path.extname  =', path.extname('report.pdf')) // .pdf

// 4) path.resolve：从右往左解析、遇绝对路径即停，得到基于 cwd（命令执行位置）的绝对路径
console.log('path.resolve  =', path.resolve('output'))

// 5) 结构化拆解：path.parse 拆成对象；path.sep 是当前系统的分隔符
console.log('path.parse    =', path.parse('/users/docs/file.txt'))
console.log('path.sep      =', JSON.stringify(path.sep))
```

实测输出（`npm run path`，绝对路径随机器与执行位置而异）：

```
__dirname  = E:\working\blog\node\运行环境\code\环境变量与常用内置模块\src\path
__filename = E:\working\blog\node\运行环境\code\环境变量与常用内置模块\src\path\path.js
path.join     = E:\working\blog\node\运行环境\code\环境变量与常用内置模块\src\path\output\hello.txt
path.basename = file.txt
path.dirname  = /users/docs
path.extname  = .pdf
path.resolve  = E:\working\blog\node\运行环境\code\环境变量与常用内置模块\output
path.parse    = {
  root: '/',
  dir: '/users/docs',
  base: 'file.txt',
  ext: '.txt',
  name: 'file'
}
path.sep      = "\\"
```

经验法则：引用模块内文件用 `path.join(__dirname, ...)`；要得到"从命令执行位置出发的绝对路径"才用 `path.resolve`。

## fs 模块：读、写、目录与遍历
fs 有三种风格：回调版（易嵌套）、`fs/promises`（配 async/await，**主流**，可 try/catch 兜底）、`*Sync`（**阻塞事件循环**，只适合启动初始化、CLI，绝不上高并发请求热路径）。日常直接用 `fs/promises`：

> 摘自 `./code/环境变量与常用内置模块/src/fs/fs.js`（运行：`npm run fs`）

```js
// fs 关键操作：读、写、追加、目录遍历与清理（fs/promises 主流用法）
const fs = require('node:fs/promises')
const path = require('node:path')

async function main() {
    // 1) 写文件：mkdir recursive 等价 mkdir -p，writeFile 整体写入
    const dir = path.join(__dirname, 'output')
    await fs.mkdir(dir, { recursive: true })
    await fs.writeFile(path.join(dir, 'hello.txt'), '你好，fs！\n第二行\n', 'utf8')
    console.log('[写] hello.txt 已写入')

    // 2) 读文件：readFile 整体读出，传 'utf8' 得到字符串（不传则得到 Buffer）
    const content = await fs.readFile(path.join(dir, 'hello.txt'), 'utf8')
    console.log('[读] 内容:', JSON.stringify(content))

    // 3) 追加：appendFile 不存在则创建、存在则追加
    await fs.appendFile(path.join(dir, 'hello.txt'), '第三行（追加）\n')
    console.log('[追加] appendFile 完成')

    // 4) 目录遍历：readdir + withFileTypes 拿 Dirent，isFile/isDirectory 判断类型，避免反复 stat
    await fs.writeFile(path.join(dir, 'data.json'), '{"ok":true}')
    const entries = await fs.readdir(dir, { withFileTypes: true })
    for (const ent of entries) {
        console.log(`[遍历] ${ent.isDirectory() ? '[目录] ' : '[文件] '}${ent.name}`)
    }

    // 5) 清理：rm recursive + force
    await fs.rm(dir, { recursive: true, force: true })
    console.log('[清理] output/ 已删除')
}

main()
```

实测输出（`npm run fs`）：

```
[写] hello.txt 已写入
[读] 内容: "你好，fs！\n第二行\n"
[追加] appendFile 完成
[遍历] [文件] data.json
[遍历] [文件] hello.txt
[清理] output/ 已删除
```

一个要点：`readFile` / `writeFile` 是**整体读写**，适合配置、小文件这类常规场景；文件大到内存装不下时才需要升级手段。
