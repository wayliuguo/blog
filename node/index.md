# Node.js 后端知识体系

> 从零开始，系统学习 Node.js + TypeScript + NestJS 后端开发。
> 六个模块按**依赖关系**串成一条链，每一篇都在回答上一篇留下的问题。

---

## 阅读顺序

```
模块一 运行环境  →  模块二 网络底层  →  模块三 Web 框架基础
       ↓
模块四 数据与缓存  →  模块五 后端架构  →  模块六 工程化与拓展
```

这条顺序的依据是**依赖关系**，不是难易程度：

- **先有运行环境，才有"一次请求是怎么被处理的"** —— 模块一讲清 Node.js 怎么跑，模块二才能讲清请求怎么进来
- **先懂网络，才看得清框架封了什么** —— 模块二里用 `node:http` 手写最小服务器，模块三再看 Express/Koa 的封装才有落点
- **框架原理懂了，再补数据层** —— 模块四的 MySQL / Redis 是独立能力，模块五的 NestJS 数据库集成才有基础
- **架构落地之后，才谈工程化** —— 模块六的部署、脚手架、进阶主题属于"把系统跑在线上"的范畴

## 模块一 · 运行环境

> **前置依赖**：无，从这里开始。
> **学完你能做什么**：说清一个请求从浏览器到后端经历了什么；用一组真实耗时数字解释 Node.js 为什么适合 I/O 密集型服务；能手推事件循环输出顺序，并用 Stream 处理大文件、为 CPU 密集任务选对并发方式。

这一模块是一条**有顺序的链**，不是并列的知识点，整条链回答的是同一个问题——**Node 为什么能用少量线程扛住大量 I/O**：

模块系统解决"代码怎么组织" → 事件循环解决"为什么不会卡" → 异步编程解决"怎么写才不卡" → Buffer/Stream 解决"数据长什么样、怎么流动" → 进程与线程解决"单线程不够用怎么办" → 错误兜底与优雅退出解决"出错了怎么安全收场" → 最后一篇把前六篇收成一张图与一张决策表。

## 怎么读这套文档

- **每篇顶部有两行导航**：`> 承上：` 接住上一篇留下的问题，`> 启下：` 预告下一篇要回答什么。整条链就是靠这两行咬合的
- **每篇底部有 `## 配套代码`**：文档里给代码片段，`code/node/` 里给可直接 `node xxx.js` 运行的完整脚本。代码路径以文本形式给出（不是可点击链接），到仓库里按路径打开即可
- **正文不做难度分级**，只按模块顺序渐进；`[初级] / [中级] / [高级]` 只出现在附录的面试题库里
- **目录编号只作文档 ID 使用**，真实阅读顺序以本页的模块划分与侧边栏为准

## 学习建议

1. 按模块顺序学习，不要跳步；模块二的网络底层尤其不要跳过
2. 每篇读完后，把 `## 配套代码` 里的脚本跑一遍，对着"预期输出"自检
3. 遇到不懂的，先继续往下看，回头再理解；模块一的第 7 篇《运行机制收束》适合当作回顾与自测
4. 附录中的 `学习路径图` 和 `面试自测题` 可辅助巩固
