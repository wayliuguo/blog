## 一个常见的困惑

很多人的学习路径是这样的：

```
Node.js 基础  →  Express  →  NestJS  →  数据库  →  部署
```

看起来顺理成章，但几乎每个人都会在同一个地方卡住：

- 面试问 "`req` 为什么是可读流"，只能背"因为 Node.js 是流式的"
- 看 `Express 源码分析` 里的"最小实现"，知道代码在做什么，但不知道为什么 `res.end()` 能结束响应
- 用 NestJS 的 `@Sse()` 做流式接口，能跑通，但说不清它和 WebSocket 到底差在哪
- 线上出现 `ECONNRESET`、连接假死、并发上不去，只能重启了事

这些问题的根源是同一个：**跳过了"网络"这一层，直接学了"框架"。**

框架是对网络的封装。不懂被封装的东西，就只能记住封装的结果。

## 全景图：一次请求的完整路径

当你在浏览器里访问一个 NestJS 接口，数据要穿过多层抽象才能到达你的 Controller：

```txt
浏览器 (Chrome / 微信 WebView)
  │  HTTP 请求（GET /api/user）
  ▼
HTTP（应用层：方法 / 路径 / 头部 / 正文）
  ▼
TCP（传输层：面向连接、可靠、字节流，三次握手后建立的管道）
  ▼
IP（网络层：寻址与路由，找到目标服务器）
  ▼
网卡（网络接口层：把比特流变成电信号 / 光信号）
  ▼
操作系统内核（Kernel）：TCP/IP 协议栈、Socket 缓冲区
  ▼
epoll / kqueue / IOCP（内核告诉你"这个 socket 有数据了"）
  ▼
libuv（跨平台异步 I/O 抽象层）
  ▼
Event Loop（poll 阶段拿到就绪事件）
  ▼
Node.js HTTP 模块（解析 HTTP 报文）
  ▼
Express / Koa（路由、中间件、洋葱模型）
  ▼
NestJS（Controller / Service / 装饰器）
  ▼
你的 Controller
```

> 心智模型：越往上越"像人话"（Controller、`@Get`），越往下越"像机器"（字节流、epoll）。NestJS 把下面这几层全部替你包好了，你只写业务逻辑。但一旦线上出现诡异问题（连接假死、数据错乱、并发上不去），不懂下面这几层，你就只能干瞪眼。

每一层出问题时的典型现象：

| 层 | 出问题的典型现象 |
| --- | --- |
| DNS | 域名解析不了 / 解析到旧 IP |
| TCP | 连接超时、ECONNREFUSED、端口不通 |
| TLS | 证书过期、握手失败、HTTPS 报错 |
| HTTP | 头部过大、请求体读不到、Content-Length 不符 |
| Keep-Alive | ECONNRESET、502 / 504 |
| 内核 / epoll | 连接数打满、文件描述符耗尽 |
| libuv / Event Loop | 并发上不去、CPU 打满但 QPS 低 |
| 框架 | 中间件顺序错、Guard 拦截、DTO 校验失败 |

## 怎么读这几篇

### 不要只读，要跑

前四篇里都有可以直接运行的代码。**至少跑一遍下面这三个**：

1. `node:net` 起一个 TCP Server，用 `nc` 或另一个 Node 脚本连上去，故意连续 `write` 两次，观察 `data` 事件收到几段
2. `node:http` 手写一个只有路由和 JSON 响应的 Server，**不加任何框架**，感受一下"框架之前的世界"
3. 用 SSE 推一个每秒一次的计时器，用 `curl -N` 看输出如何一行行冒出来

跑过之后，再回头看 Express 的 `app.use()` 和 NestJS 的 `@Get()`，你会明显感觉到"它替我做了什么"。

### 什么时候可以跳过

如果你已经能准确回答下面三个问题，这几篇可以只当作复习：

- TCP 是"字节流"协议，那应用层怎么知道一条消息在哪结束？
- 为什么网络 I/O 通常不占用 libuv 的线程池？那 Node.js 凭什么能用单线程管理上万个连接？
- 一个"AI 流式输出"的接口，为什么用 SSE 而不是 WebSocket？

答不上来，就老老实实按顺序读完。

## 记住这条主线

> 越往上越"像人话"（`@Get()`、`@Body()`），越往下越"像机器"（字节流、epoll、Socket）。

日常写业务，你永远待在最上面一层。但线上出问题时，问题往往在最下面几层：

- 连接假死 → NAT 超时 / 缺心跳（第 3 篇）
- 请求体读不到 → 忘了 `req` 是流，需要 `Buffer.concat`（第 2 篇）
- 并发上不去 → 某个同步阻塞操作占住了事件循环（模块一）
- 502 / 504 → Keep-Alive 与上游超时配置打架（第 2 篇、模块六的 Nginx）

掌握这一层，不是为了炫技，而是为了**出问题时知道往哪看**。
