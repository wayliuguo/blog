## 〇、已确认决策（用户拍板）

| # | 决策 |
|---|---|
| 1 | 侧边栏**各自平铺**：渲染架构 / 微前端体系 / 跨端与桌面深化 三个平铺板块，顺序渲染架构 → 微前端 → 跨端 |
| 2 | Flutter 不配环境：**留环境配置章节** + 完整代码讲解，标注未实跑 |
| 3 | 研发平台与效能工程**彻底删除**（不并入任何板块） |
| 4 | 微前端统一工程**宿主用 Vue**，子应用 Vue + React 各一（双框架覆盖） |
| 5 | 旧篇目**允许删除/重命名**，同步改侧边栏与全站链接 |
| 6 | 文件组织：每板块 = 全景（精简）→ 各技术选型一篇 → 原理深化 → 总结/面试题 |
| 7 | 每个框架/选型章必须覆盖四层：**入门、进阶、实战、最小实现** |
| 8 | **原理最小实现按选型各自承担**：不同技术选型需要不同的最小实现（Next 的 mini-next 与 Nuxt 的 mini-nuxt 是两套独立实现），板块不再设统一原理篇 |

## 一、统一章节模板（每个框架/选型章）

```markdown
# Next.js
## X.1 定位与心智模型迁移          【入门】从已会栈映射（Vue→Next：路由/数据获取/样式逐项对照），不含 Hello World
## X.2 上手：最小可跑应用          【入门收尾】cmd 可复制跑通的最小工程，30 分钟内见效
## X.3 核心机制                    【进阶】路由/渲染范式/数据流/缓存/插件机制，三层钻取体例
## X.4 实战：统一业务场景完整应用   【实战】板块统一业务场景，非官方 demo 照抄
## X.5 最小实现                    【最小实现】原理级落地或指向板块统一原理篇
## X.6 对比与适用边界              【收尾】与其他选型横向对比表 + 选型判据
```

> 四层是**完备性检查清单**而非等长配额：薄章节允许合并层（如 iframe 的入门并入实战），但必须显式覆盖或写明省略理由。

## 三、对抗性验证（四层结构 vs 进阶定位）

逐条自我质疑与修正结论：

| # | 质疑 | 结论/修正 |
|---|---|---|
| V1 | **"最小实现"二义**：若各章从零实现一遍公共轮子（如通用 SSR），必然重复劳动；但若统一成一篇，又丢失了"不同选型原理差异"这个最有价值的部分 | 已修正（2026-10-13 二次确认）：**最小实现按选型各自承担，且各不相同**——Next.js 章做 mini-next（React renderToString + 文件路由 + hydration，esbuild 构建链），Nuxt 章做 mini-nuxt（Vue createSSRApp + compiler-sfc esbuild 插件），qiankun 章做 mini 沙箱+注册中心，wujie 章做 mini iframe 代理……它们实现的是**各自选型的独有机制**，天然不重复；禁令只针对"同一原理被多章重复实现" |
| V2 | **入门层与基础板块/官方教程重复**：进阶读者已会 Vue/React，教 Next 安装启动是降智 | 已修正：入门层定位为**心智模型迁移**（已会栈 → 新框架逐项映射对照表），不含 Hello World；验收判据：读者 30 分钟内跑通并说出"它和我会的 XX 的本质差异" |
| V3 | **四层等长会注水**：iframe 方案的"入门"本身就三行代码，硬凑四层是灾难 | 已修正：四层=完备性清单，允许薄章合并层并显式声明；进阶的判定标准是**是否贯穿"先判断→再上手→深机制→能自造"的闭环**，不是层数 |
| V4 | **"实操"承诺与环境现实冲突**：本机无 Android/iOS/Dart 环境，全承诺"真机跑通"会烂尾 | 已修正：**实跑分级**并落进每篇文内标注——Electron/Next/Nuxt/微前端五方案/低代码/可视化全实跑；RN 代码完整+Metro 实跑，设备层写明环境要求；Flutter 仅环境配置章节+代码讲解、明确标注未实跑。与"运行时事实必须实跑"定规的例外逐条登记在文内，不留暗坑 |
| V5 | **实战层退化为官方 demo 照抄**：四层里最容易失守的是"实战" | 已修正：每板块规定**统一业务场景**（微前端=订单列表+详情、低代码=同一 schema 演进到底），实战必须绑定该场景且 code 工程可跑，禁止照抄官方 starter |
| V6 | **平铺后板块割裂**：渲染架构/微前端/跨端平行后，读者看不到三者的上下游关系 | 已修正：渲染架构全景篇末尾放"板块地图"小节，显式链接微前端/跨端板块并说明依赖关系（微前端的沙箱原理依赖渲染架构的运行时知识等） |
| V7 | **单篇过长失控**：一个框架一篇四层，预计 600~800 行 | 接受（先例：性能优化体系篇更长），设拆分阈值：超 1000 行拆两篇（如 Next.js 上/下），拆分时侧边栏同步两级 |
| V8 | **验证兜底**：四层齐≠质量齐 | 每批收尾仍走既有三校验（check-code-sync 成对传参 / vitepress build / dist grep 新字符串），四层覆盖情况写入该批交付说明 |

**验证结论**：四层结构符合进阶思路，前提是执行上述 V1~V5 的修正——"最小实现"不重复造轮子、"入门"做迁移映射不做扫盲、四层允许伸缩、"实战"绑统一场景、环境边界如实标注。按修正后口径，结构成立。
