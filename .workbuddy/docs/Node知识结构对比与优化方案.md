## 二、三篇合起来是一条什么链

三篇不是三个独立主题，而是**同一条主干的"骨架 → 下潜 → 外延"**：

```
        └───────────────────────────────────────────────────────────┘
                                   │
                                   ▼
                          上层框架（Express / NestJS）
```

**关键：每一层都在回答"上一层没解决什么"。**

```
TCP 解决     →  可靠、有序的字节流          （但不知道消息边界 → 粘包）
Socket 解决  →  应用使用网络能力的接口抽象   （但大量 socket 轮询低效 → epoll）
epoll 解决   →  内核帮你盯住 fd，有数据才通知 （但各 OS 机制不同 → libuv）
libuv 解决   →  跨平台抽象 epoll/kqueue/IOCP （但回调怎么调度 → Event Loop）
EventLoop    →  单线程调度就绪事件           （但 CPU 密集会卡主线程 → Worker）
Worker 解决  →  把重计算挪出主线程           （但每请求 new Worker 会拖垮 → Worker Pool）
```

这就是"连贯性"的真实来源：**不是章节排得整齐，而是每一节都在接力。**

## 三、这套写法的 7 条范式（"连贯性 + 原理性"的配方）

| # | 范式             | 具体做法                                | 参考链接中的例子                                                                       |
| - | -------------- | ----------------------------------- | ------------------------------------------------------------------------------ |
| 1 | **先锚后链**       | 整条线开篇先回答"为什么是这一串"，用**真实耗时数字**把主轴立起来 | Day2 §0′ 的 30/100/2000/5/30ms 论证                                               |
| 2 | **首尾各一张图**     | 开篇全景图/疑问清单，结尾"把这些串起来"总图；首尾呼应形成闭环    | Day2 §8、Day3 §56、网络篇 §1 + §31                                                  |
| 3 | **标题即问题**      | 小节标题写成问句，读者是带着问题往下读                 | "TCP 到底解决了什么问题"、"epoll 为什么存在"、"既然 NestJS 都封装了为什么还要学"                           |
| 4 | **递进追问**       | 每引入一层，先答"上一层没解决什么"，再答"这一层补上什么"      | 第二节的接力链                                                                        |
| 5 | **挂 Agent 语境** | 每个知识点都回答"这对 Agent 有什么用"             | Promise.all→取记忆、Stream→LLM 流式、Buffer→多模态、fs→RAG Loader、网络分层→线上排障               |

| 7 | **决策模型收尾**     | 结尾不给 API 清单，给"见 X → 想 Y"的判断规则       | Day3 §57、网络篇 §27 决策表                                                           |

> 附加第 8 条：**版本时效标注**。明确标出 Node 20 / libuv 1.45 的 Event Loop 行为变化，把它当作"教你查证"的教学点，而不是默默写一个可能过期的结论。

## 六、差距诊断（5 条）

### 差距 1｜"锚"缺失：没有一篇回答"这条链为什么必须这么串"

- **参考**：Day2 用一整节、真实耗时数字（30+100+2000+5+30ms）证明"CPU 只算几毫秒，其余全在等 I/O"，把 **EventLoop / 非阻塞 I/O** 立成整条线的主轴。
- **现状**：`01-认识后端` 两篇共 182 行，是"是什么 / 能做啥 / 安装 / 第一个程序"的百科式入门。"I/O 密集型"只作为**结论**出现在 `index.md` 和附录里。
- **后果**：读者从模块一走到模块六，知道"学什么"，但不知道"这条链为什么必须这么排"。这是连贯性断掉的第一处。

### 差距 2｜"串联"缺失：篇与篇之间没有一张跨篇总图

- **参考**：三篇各有一个收尾串联（Day2 §8 知识关系图、Day3 §56-57 架构图 + 决策模型、网络篇 §31 的 31 步）。
- **现状**：只有 `node/index.md` 一张模块级流程图 + `90-附录/02-学习路径图`。**模块内部的 5 篇 / 3 篇之间没有收束章节。**
