## 11:0x Vite 篇：钩子全景（六·四）+ 调试小节（九）落地

### 实测结论（Vite 8.3.0 + Rolldown 1.2.9）
- **一次 build 触发 21 个钩子，一次 dev + 请求触发 13 个**。主干四段：配置期 `config → configResolved → options` / 构建期 `buildStart → resolveId → load → transform → resolveDynamicImport → moduleParsed → buildEnd` / 输出期 `renderStart → banner·intro·outro·footer → renderChunk → augmentChunkHash → generateBundle → transformIndexHtml → writeBundle` / 收尾 `closeBundle`。
- **dev 也走打包器管线**（Vite 6 起 Environment API）：`buildStart` / `buildEnd` / `options` 在 dev 侧同样触发，"dev 只是裸 ESM 服务"不成立。
- **`transformIndexHtml` 两侧位置不同**：build 在 `generateBundle` 之后（ctx 带 `bundle`），dev 在 `load` 之前；dev 的 ctx = `{ path, filename, server, originalUrl }`。
- **`handleHotUpdate` 在 8.x 彻底失效**（`--legacy-hmr` 只注册老钩子 → 0 次触发），由 `hotUpdate` 取代；`hotUpdate` 的 ctx 有 6 个键 `{ type, file, timestamp, read, server, modules }`，`ctx.server.moduleGraph` 可查 / 失效模块，`ctx.server.environments` = client + ssr。
- **注册了不等于会被调用**：27 个待测钩子里 3 个全程未触发——`handleHotUpdate`、`configurePreviewServer`（只在 `vite preview` 下）、`renderDynamicImport`（Rolldown 管线不再调用）。
- **`vite:resolve-builtin` 用 `Object.keys()` 扫不到任何钩子**（自身只有 `name` + `applyToEnvironment`，是 Environment API 壳插件），真正的解析在 `vite:resolve-dev`。总结里的内置插件归类不能再写它。
- **dev 严格按请求驱动**（实测）：请求 `/` → `transform` **0 次**；请求 `/src/main.js` → 1 次。模块图里已有 `lazy.js`（`import()` 被静态分析出来），但只要不请求就不转译。
- 插件链长度 29（serve）/ 38（build）；`enforce:'pre'` 的用户插件落在索引 4（前面还有 4 个内置插件），`'post'` 之后仍压着 3 个 → `enforce` 不是"排到最前 / 最后"。
