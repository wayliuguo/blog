## agent-nest 启动报错修复（篇1 配套工程）

现象：`Missing credentials. Please pass an apiKey, or set the OPENAI_API_KEY environment variable.`
at new OpenAI → at new LlmService。

两个真因（都不是 Key 的问题）：

1. **`.env` 没被加载。** NestJS 不读 `.env`，tsx/node 也不读，`process.env.DEEPSEEK_API_KEY` 恒为 undefined。
   修：`src/main.ts` 顶部 `import 'dotenv/config'`（必须在 Nest 启动前，否则启动自检读不到），
   `src/app.module.ts` 加 `ConfigModule.forRoot({ isGlobal: true })`（@nestjs/config@^3.2.3，isGlobal 全应用可见）。
   坑：预检若只放 main.ts 而靠 AppModule 加载 .env，会在 NestFactory.create 之前读到空 env → 误判退出。
2. **tsx 跑 NestJS 会让 DI 静默失效。** tsx 底层 esbuild 不支持 `emitDecoratorMetadata`，
   `design:paramtypes` 缺失 → Nest 解析不出依赖，注入的都是 undefined，**启动期不报错**，
   请求进来才 `Cannot read properties of undefined (reading 'handle')`（agent.controller.ts 注入 AgentService 处）。
   修：scripts 改 `"build": "tsc -p tsconfig.json"`、`"start": "tsc -p tsconfig.json && node dist/main.js"`、
   `"start:dev": "tsc -p tsconfig.json --watch"`（不用 tsx watch）。验证：dist/product 含 `design:paramtypes`。

另外 llm.service.ts：apiKey 改 `DEEPSEEK_API_KEY ?? OPENAI_API_KEY` 回退 + 缺 Key 时抛中文 Error（不再甩英文堆栈）；
main.ts 启动前自检 Key，缺失则打印中文提示 exit 1。

实跑验证（真实 DeepSeek 调用，非 mock）：
- 无 Key → rc=1 + 中文提示；有 Key → `Nest application successfully started`
- `POST /agent/intent` → `{"action":"getWeather","city":"西安","date":"今天"}`
- `POST /agent/chat` → 真实模型回答
