- **三个反直觉结论**：① 骨架屏让 LCP 落在「加载中…」上，指标变绿但用户没看到内容 → 必须配「内容就绪」自定义指标 ② 路由分割几乎不省体积（152.2→149.1KB，Vue 运行时占 131.5KB），省的是关键路径请求数 ③ **SW 比 HTTP 强缓存慢 ~80ms**（冷启动线程 + 每请求过 fetch），价值在离线与按资源分策略，不是「更快的缓存」

- 用户澄清的真实需求：**不是架构分层图**，而是 **API/函数级整体映像**：parser/traverse/types/generator/core 各自暴露哪些函数、parse 产物（AST）格式有哪些字段、怎么判断该用哪个 API。
- 落点约定：先在对话里给图，用户 OK 后再插入 `frontend/进阶/构建体系/编译与 AST.md` 的第九节（插在「八、AST 还能做什么」之后、「## 配套代码」之前）。
- 实测（Babel 7.29.x；探针脚本 `C:/Users/10855/.workbuddy/tmp/babel_api_probe.cjs` 与 `babel_api_probe2.cjs`）：
  - `transformSync` 返回 `{ code, map, ast, metadata, sourceType, options, externalDependencies }`；默认 `ast:null`、`map:null`，要 `ast:true` / `sourceMaps:true` 才有。
  - `generate()` 返回 `{ code, map, rawMappings, decodedMap }`；`map` 仅在 `sourceMaps:true` 时有。
  - `parse()` 产物 `File{ type, program, comments, start, end, loc, errors }`；`tokens` 需 `opts.tokens:true`（示例源码 25 个），`range` 需 `opts.ranges:true`。
  - `Program{ body, directives, sourceType, interpreter, extra, start, end, loc }`；`parseExpression()` 直接返回 Expression，无 Program 层。
  - `@babel/types`：253 种节点类型（NODE_FIELDS）、321 个 isXxx、309 个 assertXxx、1013 个 builder（含别名）；另有 `traverseFast`（只读快遍历，无 Path/Scope）；别名 `Expression` 下覆盖 52 种类型。
  - `@babel/traverse` / `@babel/generator` 都是 ESM 默认导出包装，CJS 下必须取 `.default`；导出还带 `NodePath` / `Scope` / `Hub` / `visitors`。
  - `core.parseSync` 与 `parser.parse` 产物字段完全一致（都是 File）。
  - 插件首参 `babel` 含 `types/template/traverse/parse/tokTypes/assertVersion/...`；visitor 第二参 `state` 字段 `_map, key, file, opts, cwd, filename, isAsync`。
