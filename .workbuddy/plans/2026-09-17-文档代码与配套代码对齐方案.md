## 三、改后长什么样（以 05 篇「背压」节为例）

### 改前（现状）

```javascript
// highWaterMark 决定每次读的块大小，也决定背压触发点
const reader = fs.createReadStream('./big.iso', { highWaterMark: 64 * 1024 });
```

这段代码在 `05-stream-flow-control.js` 里**根本不存在**；读者拿不到「50 字节缓冲、100 条数据刹车 16 次」那些结论的来源。

### 改后

> 摘自 `./code/node-basics/src/05-stream-flow-control.js`（运行：`npm run 05flow`）

```javascript
// 消费很慢的自定义 Writable；highWaterMark 故意调得很小，让背压很快出现
const slow = new Writable({
    highWaterMark: 50,                                  // 写侧内部缓冲上限 50 字节
    write(chunk, encoding, callback) {
        setTimeout(() => callback(), DELAY)             // 10ms 后才通知"这条处理完了"
    }
})

// 规范的生产者写法：write() 返回 false 就停下，等 drain 再继续
function pump() {
    while (i < COUNT) {
        const ok = slow.write(`第${i}条\n`)
        i += 1
        if (!ok) {
            backpressureCount += 1
            slow.once('drain', () => { drainCount += 1; pump() })
            return                                       // 必须 return，否则会继续往满缓冲里硬塞
        }
    }
    slow.end()
}
```

实测输出（`npm run 05flow`）：

```
第 7 条之后 write() 返回 false：
  writableLength=56B ≥ highWaterMark=50B，writableNeedDrain=true
  → 上游应当暂停，否则内存照样被写爆
drain 事件（第 1 次）：缓冲已排空 writableLength=0B，writableNeedDrain=false → 恢复写入

全部写完：共触发背压 16 次、drain 16 次
```

## 四、四条写作规约

1. **出处标注**：代码块正上方一行 `> 摘自 \`<相对路径>\`（运行：\`npm run xxx\`）`；一段代码跨越脚本多个函数时，用 `// …` 标出省略，**保留的每一行与脚本逐字一致**（缩进、注释、变量名都不改）。
2. **贴多少**：只贴「讲这个知识点必须看到的」。2.3 万行不可能全贴，完整代码靠 `## 配套代码` 表 + 仓库文件。
3. **配实测输出**：凡结论涉及数字（占用、耗时、触发次数、报错码），必须在该段代码下方附 `npm run xxx` 的真实输出。
4. **脚本先于文档**：注释里没写、代码里没有的知识点，先补进脚本并**实跑确认输出**，再回填文档——不许先在文档里写完就算。

规则：遍历每篇正文的 JS 代码块 → 按上方出处标注锁定脚本文件（无标注则在该篇 `code/` 全目录里找）→ 去掉空白与注释后要求「代码块内容是脚本内容的子串」→ 不满足即报「文档代码与配套脚本脱节」，并给出 `文件:行号`。

作用：**日后改脚本，校验立刻报出文档哪一段过期了**，不用靠人记得同步。纳入常规校验后变成「四件套」：

```

```
