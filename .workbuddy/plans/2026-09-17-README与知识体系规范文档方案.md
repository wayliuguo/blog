### 内容大纲（9 章，这是本次的核心产出）

**第 1 章 总则 —— 一篇文章的解剖**
```
# <篇标题>
（正文：若干「知识小节」，标题即问题或判断句）
## 小结          ← 两级知识树，位置固定
## 配套代码       ← 表须含「对应小节」列，路径写文本不做链接
## 参考          ← 首两行固定为本模块「总结 / 面试题」链接
```
- 结尾三段顺序**不可变**；正文不写 `> 承上：`/`> 启下：`，不写 `## 开篇`
- 篇内引用别篇写「见第 X 篇」

**第 2 章 篇级小结规范（两级知识树）**
- 第 1 层 = 有信息量的**概念域**（不能是「模块系统」这类空壳），第 2 层 = `- **知识点**：一句话结论`
- 严格并列项改 `1. 2.` 编号；最多三级、每级缩进 2 空格、同层 ≤ 8 条
- 格式基准：`node/运行环境/02-模块系统与包管理.md`
- 不加小结的 3 篇（`01-…/07-运行机制收束`、`03-…/00-导读与全景图`、`03-…/04-一次请求完整经历了什么`）

**第 3 章 模块总结规范（`<模块>/总结.md`）**
- 两部分：`## 知识主线`（ASCII 依赖链图 + 一段「为什么这样排」的话）+ `## 分篇知识点`
- **反向落回原则**：只维护篇级小结，再用脚本重建 `## 分篇知识点`，**禁止两级手工分别维护**
- 6 组元页面：01 · 03 · 04 · 05(跨 06) · 07(跨 08) · 09(跨 10,11)

**第 4 章 面试题规范（`<模块>/面试题.md`）**
- 四段分类：基础概念 / 机制与原理 / 排障与选型 / 场景设计题
- 每题四要素：**结论**（一句能背的判断句，可当复习清单）/ **原理** / **边界** / **场景**（或追问）
- 每题标出处 `（第 03 篇）`；**答案口径必须与新版正文一致**（历史冲突一律按正文校订）

**第 5 章 配套代码规范**
- 位置 `node/<模块目录>/code/<项目名>/`；`srcExclude: ['**/code/**']` 排除出页面集合
- `node-basics` 零依赖，**文件名前缀 = 篇号**（`01-`~`06-`，另有 `02-module-realm/`）
- **新增脚本必须同步三处**：项目 `README.md`（两张表）、`package.json` 的 `scripts`、对应篇正文的 `## 配套代码` 表
- 脚本**先于文档**：先写出能跑通的脚本，再从它摘录进文档

**第 6 章 文档代码呈现规范（本次新增的重点）**
- 代码块标准形态：
  ````
  > 摘自 `./code/xxx/src/05-buffer.js`（运行：`npm run 05buffer`）
  ```js
  …逐字摘录…
  ```
  …真实输出…
  ````
- 三条硬要求：**出处标注存在** / **逐字摘录**（缩进、注释、变量名不改，省略处单独一行 `// …`）/ **实测输出**（涉及数字、顺序、报错码时）
- 逃生口：无对应脚本的纯 API 速查片段标 `> 示意片段（无配套脚本）`，**不留无标注裸块**
- 风格照抄脚本（多数是 CJS `require`）；脚本本身 `.mjs` 或该篇讲 CJS/ESM 差异时才用 `import`

**第 7 章 文档体例细则**
- 缩进 4 空格 / 单引号 / 120 列（沿用 `.prettierrc.js`）
- ASCII 图用**裸** ```` ``` ```` 围栏，禁 ```` ```text ````（beta.6 会刷 100+ 告警）
- 相对链接要能在构建中解析；`## 配套代码` 的路径写成文本不做链接

**第 8 章 质量校验**
- 四件套 + 判定标准（下节详列）
- 每种报错的修法（1 个例子）

**第 9 章 附录：正反例对照**
- 拿模块一的真实前后做样例（改造前 vs 改造后同一段落并排）
