# frontend/基础 知识体系评审与优化方案

> 评审基准：仓库根 `文档组织规范.md` + `node/` 已全量落地的实例（以 `node/运行环境/` 为样板）。
> 评审范围：`frontend/基础`（7 模块 / 45 篇），凡属全板块共性问题的，同步标注 `frontend/进阶` 的现状。
> 评审日期：2026-09-18

## 0. 一句话结论

**内容质量是好的，缺的是「元页面体系」和「体例一致性」**——两条主线（知识主线 + 分篇知识点）已经做到 node 的水平，但总结页少 5 个固定栏目、单篇结尾顺序与 node 相反且缺 `## 参考`、面试题四段有 3 个模块第四段为空且带 23 处失效的「（附录）」标注；广度上**现代 CSS 与 DOM/浏览器 API 是两处成片的空白**，深度上 JS 核心与 CSS 足够、HTML 与小程序偏薄。

## 2. 问题清单（按优先级）

### P0 · 体例硬伤，机械可修

**P0-1 面试题「（附录）」出处失效，共 23 处**
`node/90-附录/` 已删除，但 frontend 的面试题里仍以「（附录）」标出处，指向不存在的章节。分布：

| 文件 | 处数 |
| --- | --- |
| `进阶/工程实践与架构/面试题.md` | 9 |
| `基础/前端框架-React/面试题.md` | 3 |
| `基础/前端框架-Vue/面试题.md` | 3 |
| `基础/HTML 基础/面试题.md` | 2 |
| `基础/JavaScript 核心/面试题.md` | 2 |
| `基础/网络与浏览器/面试题.md` | 2 |
| `进阶/前端工程化与构建/面试题.md` | 2 |

修法：逐题核对内容实际所属篇目，改为「（第 N 篇）」；确属跨篇综合的（如「错误分级」「预取降级」）改标「（场景综合）」或在正文补出处。

**P0-2 面试题编号与所在段落错位**
编号是「全模块唯一」但段落划分打乱了顺序，导致每段内编号跳跃、读者无法顺读：

- `CSS/面试题.md`：一段 Q1→Q4→Q5→Q7→Q13→Q19，二段 Q3→Q6→…→Q21，三段 Q2→Q9→Q12→Q14
- `React/面试题.md`：一段 Q1-Q5→Q15→Q17，二段 Q6→Q7→Q8→Q10→Q11→Q14
- `Vue/面试题.md`：一段 Q1-Q4→Q19→Q20→Q15→Q21
- `网络与浏览器/面试题.md`：一段 Q2-Q4→Q19→Q20→Q21→Q5→Q6
- `HTML 基础/面试题.md`：一段 Q1-Q5，二段 Q6-Q10→Q12-Q16→Q18-Q19，三段 Q11→Q17

只有 `JavaScript 核心`（Q1-Q17 连续跨段）与 `小程序`（Q1-Q12）是顺的——**这两份就是目标形态**：编号按段落顺序连续递增，段落切换即编号推进。

**P0-3 面试题四段中第四段为空**
`CSS/面试题.md`、`HTML 基础/面试题.md`、`小程序/面试题.md` 的 `## 四、场景设计题` 下无任何内容。其他模块该段有关键词来源（金融/表单/列表/监控等真实场景题），这三处可分别补：
- CSS：多端适配 + 主题切换 + 大规模样式治理类场景
- HTML：表单大校验链路、语义化重构、无障碍改造
- 小程序：分包与首屏、跨端选型落地、setData 治理实战

**P0-4 单篇结尾顺序与命名不符规范**
现状 `## 配套代码` → `## 总结`；规范要求 `## 小结` → `## 配套代码` → `## 参考`。三处偏差：
1. 名称应为 `## 小结`（不是 `## 总结`，避免与模块级 `总结.md` 混淆）
2. 位置应在 `## 配套代码` **之前**
3. **缺 `## 参考`**（全 frontend 仅 2 篇有：`进阶/面试方法论.md`、`进阶/交付与质量/代码规范.md`）

`## 参考` 应补齐四行：
```
- 本模块总结：[总结](./总结.md)
- 本模块面试题：[面试题](./面试题.md)
- 上一篇：[xxx](./xxx.md)
- 下一篇：[xxx](./xxx.md)
```
另外现状 `## 总结` 内的知识树是「分类枚举」（如 `position: static / relative / absolute / fixed / sticky`），**只有标签没有结论**；规范要求知识点层写「一句话结论」——可参照 `node/运行环境/模块系统与包管理.md` 的 `## 小结` 改写。

**P0-5 总结.md 缺 5 个固定栏目**
node 的 8 节结构在 frontend 只落了 3 节。缺失栏目与内容来源：

| 缺失栏目 | 内容来源 |
| --- | --- |
| `## 核心速查表` | `知识点 \| 一句话结论 \| 出处`，从分篇知识点里挑高频易忘项（node 运行环境 27 行） |
| `## 见 X 想 Y` | `见到什么 \| 该想到什么 \| 一句话理由`，从各篇的排障类小节提炼 |
| `## 易错点汇总` | 「常见误区 + 为什么错」，node 是 12 条 |
| `## 与相邻模块的接口` | 「前置必须掌握」+「本模块交给下一模块什么」，**并注明上一/下一模块链接** |
| `## 代码与自测入口` | 配套 code 项目路径 + 怎么跑 + 面试题题数 |

**其中「与相邻模块的接口」对 frontend 尤其重要**：CSS↔HTML↔JS 核心↔框架↔网络 之间当前**没有任何跨模块显式指路**，读者不知道从哪进、往哪走。`节点` 的写法是首尾模块都写明「上一模块：无 / 下一模块：[链接]」。

**P0-6 配套代码表缺「对应小节」列**
41/42 篇的表头是 `| 文件 | 演示什么 |`，只有 `基础/HTML 基础/HTML 语义化与结构.md` 是规范的 `| 文件 | 演示什么 | 对应小节 |`。规范要求表须含「对应小节」并列全脚本覆盖的小节名。
另外路径写法不统一：表内只写文件名（`flex-grid.html`），正文里才补全 `frontend/基础/CSS/code/site/`；规范要求写**完整相对路径的纯文本**。

**P0-7 面试题文件头「题目来源」描述失真**
三行固定头部里写「题目来源：各篇正文原有 `## 面试题`……」——各篇正文已无该小节（这是 node 侧的清理成果），描述需改为「由各篇正文知识点整理」。

**P0-8 小程序面试题末尾多出 `## 参考`**
其他模块面试题均无此节（`进阶/前端框架原理/面试题.md`、`进阶/工程实践与架构/面试题.md` 也有）。建议统一：面试题页不放 `## 参考`，入口回到 `总结.md`。
另 `总结.md` 的 `## 参考` 末行写法不统一：React/Vue/网络/小程序 是 `- 模块面试题：[模块面试题](./面试题.md)`（重复词），CSS/JS/HTML 是 `- [模块面试题](./面试题.md)`。

### P1 · 内容广度缺口

**P1-1 现代 CSS 成片空白（最值得补的一块）**
关键词扫描 `frontend/基础/**/*.md` 的命中结果：

| 关键词 | 命中 |
| --- | --- |
| `var(--)` / `--custom` / 自定义属性 | **0** |
| `@layer` | **0** |
| `@container` | **0** |
| `:has()` | **0** |
| `clamp()` | **0** |
| `aspect-ratio` | **0** |
| `subgrid` | **0** |
| `color-mix` / `oklch` | **0** |
| `prefers-reduced-motion` | **0** |

「CSS 变量」四个字在 4 篇里出现过，但**没有一篇给出 `var()` 写法**。对照现状：CSS 模块讲了层叠四层判定、BEM、Sass，却没有讲现代 CSS 自己的「变量 / 层叠层 / 容器查询」——这三样恰好是 BEM 与工程化选型那两篇的现代答案。建议在 `CSS` 模块新增一篇（或在 `BEM 与 CSS 规范.md` 内扩两节）：
- CSS 自定义属性与设计令牌（`--color-primary` + `var(..., fallback)`）
- `@layer` 层叠层：与 BEM/`!important`/优先级战争的关系
- `@container` 容器查询：组件级响应式（媒体查询管页面、容器查询管组件）
- 现代选择器与函数：`:has()` / `:is()` / `:where()` / `clamp()` / `aspect-ratio`
- 动效无障碍：`prefers-reduced-motion`

**P1-2 DOM / 浏览器 API 无系统篇章**
`XMLHttpRequest`、`axios` 0 命中；`fetch(` 只在框架与案例里一带而过；`IntersectionObserver` 0 命中；`querySelector` 散在 5 篇。JS 核心模块从「数据类型」直接跳到「手写实现」，中间少了**「怎么操作页面」这一层**——而 DOM 事件流/事件委托被放在了 `网络与浏览器/浏览器渲染原理.md` 里（归到「浏览器」勉强成立，但读者在学 JS 时找不到）。
建议：在 `JavaScript 核心` 增一篇《DOM 与浏览器 API》（节点增删改查、样式与类名、事件与委托、观察者三件套 IntersectionObserver / MutationObserver / ResizeObserver、rAF），或在 `网络与浏览器` 独立成篇并把事件流从渲染篇拆出来。
配套补：`fetch` 与 `XHR` 对比、取消（AbortController）、并发与竞态——`手写实现与源码.md` 已有防抖/EventBus，可衔接。

**P1-3 CORS / 跨域无正文**
`CORS` 只在 `面试题.md` 与两篇正文零星出现，`HTTP 与 HTTPS.md` 的 9 节里没有跨域。**同源策略与 CORS 是前端最高频考点之一**，建议在 `网络与浏览器` 补一节（同源三要素、简单请求 vs 预检、`credentials` 与 `Allow-Origin: *` 的互斥、`SameSite` 与跨域的联动、Nginx 反代与网关两种工程解法）。

**P1-4 无障碍（A11Y）只有零散提及**
`aria-` 命中 2 篇、`WCAG` 1 篇，无系统篇章。现状里 A11Y 只在「语义化对 SEO 的价值」和面试题 Q17（`user-scalable=0` 的可访问性代价）出现。建议在 `HTML 基础` 增设 A11Y 一节或独立篇：语义与 ARIA（`role`/`aria-label`/`aria-live`）、键盘可达与焦点管理、`prefers-reduced-motion`、表单 `label` 绑定、审计工具（Lighthouse / axe）。

**P1-5 小程序模块缺基础语法，且无配套代码**
`rpx` **0 命中**——讲小程序却不讲自己的尺寸单位；`WXML`/`WXSS` 只在架构篇作为名词出现，无模板语法、数据绑定、`wx:for`/`wx:if` 的正文；`getUserProfile`/订阅消息 0 命中。且 `小程序/code/` **完全缺失**（基础模块中唯一没有 code 的）。
建议：新增《WXML/WXSS 与基础语法》一篇（含 rpx 与适配）+ 一个可运行 demo（至少在 `code/` 里放一份 WXML/WXSS 布局对照的静态站点，说明如何本地看效果）。

**P1-6 篇幅不均衡**
- **React 6 篇 vs Vue 3 篇**：Vue 三篇分别 573/662/636 行，密度已高，实际要覆盖 Vue2→Vue3 差异、组合式 API、路由、Pinia。Vue 缺独立讲「Vue 生态与工程实践」的位置（无需再补 vs React 对称，但可考虑把 `Vue 路由与状态.md` 拆分）。
- **HTML 基础仅 2 篇**（362 + 321 行）：语义化与表单，缺 Web Components、A11Y、资源与性能（`preload`/`prefetch` 在面试题里讲了但正文没有）。
- **`网络与浏览器/HTTP 与 HTTPS.md` 9 节 520 行**：把 HTTP 缓存、版本演进、HTTPS、DNS、TCP/UDP、WebSocket 全塞一篇，是基础模块里最重的单篇，可考虑拆成「HTTP 与缓存」「HTTPS 与传输层」。

### P2 · 结构一致性与可用性

**P2-1 小节标题风格统一**
33 篇带「一、二、」中文序号（如 `JavaScript 核心/作用域与闭包.md` 十节全带、`网络与浏览器/浏览器渲染原理.md` 十二节全带），另 12 篇不带（`React/*`、`Vue/*`、`HTML 基础/HTML 语义化与结构.md`）。**同一模块内部也不统一**：`CSS/布局.md` 不带序号，`CSS/动画与变换.md` 带。规范要求小节标题写成问题或判断句，建议统一去序号 + 改为判断句（也可保留序号但全板块一致）。

**P2-2 校验脚本扩展不到 frontend**
`check-links.cjs` 的 `DOC_ROOT = path.join(ROOT, 'node')`、`check-code-sync.cjs` 的 `NODE_DIR = path.join(ROOT, 'node')` 都硬编码了模块。frontend 目前**没有守门**——这也是上面 P0-4/5/6 这类偏差能长期存在的原因。
建议：把两个脚本改为支持多板块（`--board node|frontend|ai|interview` 或遍历顶层板块目录），`check-sidebar-coverage.cjs` 同步。改完后跑一遍 frontend，可一次性验证上面所有体例修复。

**P2-3 `frontend/基础` 无模块级「学习路径」说明**
导航直达 `基础/HTML 基础/HTML 语义化与结构`，读者无「我该按什么顺序学」的入口。node 的做法是每模块 `总结.md` 的「知识主线」+「与相邻模块的接口」承担这个职责——补齐 P0-5 后即可解决。
另：`进阶/面试方法论.md` 被 7 处面试题引用（`[「面试方法论」](../../进阶/面试方法论.md)`），但**基础模块的读者未必知道它的存在**。建议在 `总结.md` 的「代码与自测入口」或 `参考` 里补一条入口。

## 3. 深度评估

**达标的部分**
- `JavaScript 核心`：`手写实现与源码.md` 903 行是基础模块最长篇，覆盖 call/apply/bind、new、深拷贝、instanceof、Promise、防抖节流、EventBus、柯里化；`异步编程与事件循环.md` 643 行含经典输出题推演。深度足够面试。
- `CSS`：布局篇 506 行覆盖圣杯/双飞翼/Grid 现代简化版 + 居中方案性能排序，动画篇 573 行讲清合成层与 `will-change` 取舍。达到「原理 + 结论 + 代码」三层。
- 面试题答案质量好：「边界」与「追问」不是复述结论，而是给了反例与选型（如 `Q6 flex: 1 的 min-width: 0 陷阱`、`Q15 fixed 在 transform 祖先下为何变成 absolute`）。

**偏浅的部分**
- `## 总结`（篇级小结）退化为分类清单，无一句话结论，作为「复习清单」价值低。
- 面试题题量偏少：基础 7 模块共 118 题（17~22 题/模块），node 单模块 54 题。题型集中在概念与原理，**场景设计题只有 5 题**且集中在金融业务。
- `小程序` 四篇 477 行，是基础模块最薄的一块（`原生与跨端框架差异.md` 仅 70 行），且缺基础语法与代码，目前更接近「架构科普」而非可上手知识。
- 代码验证强度低于 node：node 要求「涉及数字/顺序/报错码时贴真实输出」，frontend 的配套代码是浏览器 demo（`code/site/*.html` + `server.js`），正文多数只列文件不贴实测现象。若要把结论做实，可对可量化的（回流耗时、合成层数量、`localStorage` 同步阻塞、事件循环输出顺序）补实测输出。
